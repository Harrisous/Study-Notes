M10 · 算力算术：FLOPs、带宽、roofline 与通信

一块 H100 级别的 GPU 每秒能做近千万亿次浮点运算，DeepSeek-V3 训练时却只用上了其中不到四成。这一课教你用纸笔回答三个问题：一件事要做多少次运算？要搬多少字节、走哪条路？这两件事谁先把时间用完？学会这三问，你就能自己核对 V3“每万亿 token 18 万 GPU 小时”的账，也能看懂它为什么不用张量并行、为什么要千方百计把通信藏进计算里。

这一课回答什么问题

DeepSeek-V3 的技术报告里有一句很硬的话：每训练一万亿个 token，只需要 18 万个 H800 GPU 小时，也就是在他们 2048 块 H800 的集群上跑 3.7 天 1。这个数是真的吗？不必相信，也不必怀疑，可以算。要算它，得回答三个问题：每个 token 要做多少次运算？一块 GPU 每秒实际能做多少次？是什么让“实际”低于“峰值”？

第一个问题是数数，§1 解决。第二、三个问题要先认识 GPU 的另一半：数据住在哪里、搬过来要多久（§2）；一段计算是被算力卡住还是被搬运卡住（§3 的算术强度与 §4 的屋顶线模型）。模型大到一块卡装不下时，还要把它切到成千上万块卡上，于是有了第三笔账：卡与卡之间的通信（§5 的四种并行、§6 的集合通信）。§7 把三笔账放在一起，逐项对上 V3 一天的训练记录。

读完这一课，下面这些问题你都能自己回答：

  • 一次矩阵乘法、一次前向、一次训练各要多少次运算？为什么训练约是“6 × 参数 × token”，什么时候这个近似不够准？
  • 从寄存器到 InfiniBand，数据每往外走一层，带宽掉多少？
  • 为什么同一个权重矩阵，乘一批 4096 个 token 时能跑满算力，乘一个向量时连 1% 都用不上？
  • 屋顶线模型怎样一眼看出一段计算受算力限制还是受带宽限制？
  • 一个模型放不进一块卡时有哪四种切法？各自省下什么显存、付出什么通信？
  • 环形 all-reduce 为什么在 1024 块卡上几乎和在 8 块卡上一样快？MoE 的 all-to-all 和流水线的气泡又各要多少时间？

本课的记号
  • \(F\)：一块卡的峰值算力，单位 FLOP/s（每秒浮点运算次数）。\(\mathrm{BW}\)：某一条数据通路的带宽，单位字节/秒。\(I\)：算术强度，单位 FLOP/字节。\(I^\star=F/\mathrm{BW}\)：脊点。
  • \(s\)：每个数占的字节数。BF16 \(s=2\)，FP8 \(s=1\)，FP32 \(s=4\)（这些格式见 M08）。
  • \(N\)：参数量；MoE 模型每个 token 实际参与计算的参数写 \(N_{act}\)。\(D\)：训练 token 数。\(T\)：序列长度。\(d\)：隐藏维（V3 为 7168）。\(l\)：层数。
  • §3、§4 的 \(m,n,k\) 是矩阵的三个维度（与 M01 一致，\(m\) 是 token 数）；§5 起的 \(m\) 是 micro-batch 的个数（与第 12 课一致），\(P\) 是流水线段数。§4 的 \(P(I)\) 是可达算力（FLOP/s），§1 一处的 \(P\) 是注意力权重矩阵，都只在那一页出现。同一个字母的两种用法不会出现在同一段推导或同一道题里。
  • 通信：\(p\) 是参与的卡数，\(\alpha\) 是每条消息的固定延迟（秒），\(\beta=1/\mathrm{BW}\) 是每字节的传输时间（与 GRPO 的 KL 系数 \(\beta\) 无关），\(S\) 是一条消息（或一张卡要处理的整份数据）的字节数，注意与每个数的字节数 \(s\) 区分大小写；\(\gamma_{\mathrm{red}}\) 是做归约（相加）时每字节的计算时间。\(\lg p=\log_2p\)。
  • 时间：一般写 \(t\)；带下标的 \(T_F\)、\(T_B\)、\(T_{\text{ring}}\) 等是某一段操作的耗时（沿用第 12 课与 Thakur 等人的写法），与序列长度 \(T\) 无关。
  • 单位：1 GB \(=10^9\) 字节，1 GiB \(=2^{30}\) 字节；1 TFLOP/s \(=10^{12}\) 次/秒。厂商用哪种就照抄哪种，并注明。

数 FLOPs

先把要验证的数摆出来。V3 报告说：预训练 14.8 万亿（14.8T）个 token 用了 266.4 万 GPU 小时，平均每万亿 token 18 万 GPU 小时 1。要判断这个数合不合理，第一步是知道每个 token 要做多少次运算。这一页从最小的单位数起：一次乘法、一次矩阵乘法、一个线性层的前向与反向、一层 Transformer，最后是整次训练；再用一个叫 MFU 的比值，把“运算次数”换算成“GPU 小时”。

FLOP 与 FLOP/s

含义。 一次浮点运算（floating-point operation，FLOP）是两个浮点数之间的一次加法或一次乘法。数一段计算一共做多少次，得到的叫 FLOPs（运算次数，是一个量）；硬件每秒能做多少次，写作 FLOP/s（是一个速度）。

理解。 前者像“这趟路要走多少步”，后者像“每秒走几步”。两者相除才是时间。英文里常把两者都写成 FLOPS，读数字时先看清是哪一个；本课程一律写 FLOPs 表示次数、FLOP/s 表示速度。

矩阵乘法为什么是 2mnk读过 M01 §5 的可以跳过

\(C=AB\)，\(A\) 是 \([m,k]\)，\(B\) 是 \([k,n]\)。\(C\) 有 \(mn\) 格，每格是一个长度为 \(k\) 的点积：\(k\) 次乘法、\(k-1\) 次加法。硬件的基本指令是乘加（fused multiply-add，一条指令算 \(a\times b+c\)），记作 2 次运算，从 0 开始累加 \(k\) 个乘积正好 \(k\) 次乘加，所以统一记 \(2mnk\)。有些工具报告 MACs（乘加次数），数值是 FLOPs 的一半。详见 M01 §5。

矩阵乘法的运算量\[\mathrm{FLOPs}\big([m,k]\times[k,n]\big)=2mnk\]一个权重矩阵 \(W\in\R^{d_{in}\times d_{out}}\) 作用在一个 token 上，是 \(2d_{in}d_{out}\) 次：每个参数、每个 token，2 次运算。(M10.1)

一个线性层：前向 2 次，反向 4 次

问题。 训练不只做前向，还要反向传播。反向要多少次运算？答案是前向的两倍，原因要从链式法则里读出来。

形式化。 一个线性层 \(Y=XW\)：\(X\in\R^{T\times d_{in}}\) 是 \(T\) 个 token 的输入（每行一个 token），\(W\in\R^{d_{in}\times d_{out}}\) 是权重，\(Y\in\R^{T\times d_{out}}\) 是输出。反向传播到这一层时，手里有上游传来的 \(\partial\mathcal L/\partial Y\)（简写 \(\mathrm dY\)，形状同 \(Y\)），这一层要交出两样东西：传给前一层的 \(\mathrm dX\)，交给优化器的 \(\mathrm dW\)（反向传播的记号见 M06）。

一个线性层的三次矩阵乘法
(1)\(\displaystyle Y=XW:\quad[T,d_{in}]\times[d_{in},d_{out}]\ \Rightarrow\ 2Td_{in}d_{out}\)前向，(M10.1)
(2)\(\displaystyle \mathrm dX=\mathrm dY\,W^\top:\quad[T,d_{out}]\times[d_{out},d_{in}]\ \Rightarrow\ 2Td_{in}d_{out}\)链式法则：\(Y_{tj}=\sum_{i'}X_{ti'}W_{i'j}\)，所以 \(\partial Y_{tj}/\partial X_{ti}=W_{ij}\)；\(X_{ti}\) 经所有 \(Y_{tj}\) 影响损失，\(\mathrm dX_{ti}=\sum_j\mathrm dY_{tj}W_{ij}\)
(3)\(\displaystyle \mathrm dW=X^\top\mathrm dY:\quad[d_{in},T]\times[T,d_{out}]\ \Rightarrow\ 2Td_{in}d_{out}\)同理 \(\partial Y_{tj}/\partial W_{ij}=X_{ti}\)，\(\mathrm dW_{ij}=\sum_tX_{ti}\,\mathrm dY_{tj}\)：权重对每个 token 都有贡献，所以要对 \(t\) 求和
(4)\(\displaystyle \text{合计}\ 6\,Td_{in}d_{out}=6\times(\text{参数})\times(\text{token})\)三次乘法的三个维度都是 \(T,d_{in},d_{out}\)，只是求和的那一维不同
每个参数、每个 token 的训练运算\[\underbrace{2}_{\text{前向}}+\underbrace{2}_{\mathrm dX}+\underbrace{2}_{\mathrm dW}=6\quad\text{FLOPs /（参数·token）}\]这是只算矩阵乘法的计数；逐元素运算（激活函数、归一化、加残差）相对很少，忽略。第 2 课 §6 的图 2.9 画了这三次乘法的形状。(M10.2)

一层 Transformer，再乘以层数

一个 token 经过一层 Transformer，要过两类运算。一类是带参数的矩阵乘法：注意力的各个投影、FFN（或 MoE 的专家），按 (M10.2) 每个参数 2 次（前向）。另一类是不带参数的矩阵乘法：注意力的打分 \(QK^\top\)（查询与键逐个做点积）与加权求和 \(PV\)（\(P\) 是 softmax 之后的注意力权重，\(V\) 是值），两边都是激活乘激活，没有权重，运算量取决于这个 token 要看多少个历史位置。

先交代要用的符号：\(n_h\) 是注意力头数；\(d_{qk}\) 是每个头的查询、键向量的长度，\(d_v\) 是每个头的值向量的长度（标准 Transformer 里两者都等于 \(d_h\)，V3 的 MLA 里前者是 192、后者是 128）；\(\bar t\) 是一个 token 平均要看的历史位置数。

一个 token 在一层注意力里的打分与加权求和（前向）
(1)\(\displaystyle \text{打分}:\ n_h\ \text{个头}\times\bar t\ \text{个点积}\times2d_{qk}=2n_hd_{qk}\bar t\)\(\bar t\)：这个 token 平均看到的位置数；长 \(d_{qk}\) 的点积要 \(2d_{qk}\) 次运算
(2)\(\displaystyle \text{加权求和}:\ n_h\ \text{个头}\times\bar t\ \text{个值向量}\times2d_v=2n_hd_v\bar t\)每个值向量乘一个权重再累加
(3)\(\displaystyle \bar t=\tfrac{1}{T}(1+2+\dots+T)=\tfrac{T+1}{2}\approx\tfrac T2\)因果掩码：位置 \(t\) 只看前 \(t\) 个位置

把两类加起来，前向乘 3 就是训练（反向对两类运算都是两次同样大的乘法）：

每 token 的训练运算量\[C_{\text{token}}\approx6N_{act}+6\,l\,n_h\,(d_{qk}+d_v)\,\bar t\]\(N_{act}\)：每个 token 实际参与矩阵乘法的参数（MoE 只算被选中的专家；嵌入层只是查表，不算）。第二项是注意力打分与加权求和，\(l\) 是层数。(M10.3)
整次训练的运算量\[C\approx C_{\text{token}}\cdot D\ \approx\ 6N_{act}D\quad(\text{注意力项可以忽略时})\]\(D\) 是训练 token 数。\(6ND\) 的推导与它在 GPT-3 上的核对见第 2 课 §6。(M10.4)

PaLM 论文在定义 MFU 时写的是同一个式子的非因果版本：每 token \(6N+12LHQT\)（\(L\) 层、\(H\) 头、每头 \(Q\) 维、序列长 \(T\)）2。把 \(d_{qk}=d_v=Q\)、\(\bar t=T\)（不省掉被掩掉的那一半）代入 (M10.3) 的第二项，正好是 \(12LHQT\)。两种算法在注意力项上差一个 2 倍，本页末尾的“三个常见的混淆”会看到它在真实报告里的样子。

DeepSeek-V3 每个训练 token 要多少次运算

第 12 课的研究笔记按 V3 发布的配置逐项数出了每个 token 激活的矩阵参数 3：61 层、每层 MLA 注意力的投影共 187,105,280 个参数；前 3 层是稠密 FFN，各 396,361,728 个；后 58 层是 MoE，每 token 激活 8 个路由专家加 1 个共享专家，每个专家 44,040,192 个参数，外加门控 1,835,008 个；输出头 926,679,040 个。合计 \(N_{act}=36.62\)B（加上只查表的嵌入层是 37.55B，也就是报告说的“37B 激活参数”）。

  • 矩阵部分：\(6\times36.62\times10^9=219.75\) GFLOPs。
  • 注意力部分：\(l=61\)，\(n_h=128\)，\(d_{qk}=192\)（128 维内容 + 64 维 RoPE），\(d_v=128\)，序列长 4096、因果掩码下 \(\bar t=2048\)：\(6\times61\times128\times320\times2048=30.70\) GFLOPs。
  • 合计 \(250.45\) GFLOPs/token。Insights 论文的表 2 给出的 V3 训练成本正是约 250 GFLOPs/token 4。

预训练 14.8T token 的总运算量：\(250.45\times10^9\times14.8\times10^{12}\approx3.71\times10^{24}\)。若只用 \(6N_{act}D\)、并把 \(N_{act}\) 取成 37B，得 \(3.29\times10^{24}\)，少了 11%：V3 的注意力有 128 个头、每头 320 维（打分 192 + 值 128），上下文 4K，注意力这一项已经占到 12%，不能再忽略。

从运算次数到 GPU 小时：MFU

问题。 知道了每 token 250 GFLOPs，还差一个数：一块卡实际每秒做了多少次有用的运算。峰值只是上限，实际能跑到几成，由后面几页讲的带宽、通信、气泡共同决定。业界用一个比值来报告这件事。

含义。 模型算力利用率（model FLOPs utilization，MFU）= 实际训练吞吐（每秒处理的 token 数）÷ 这套系统以峰值算力运行时的理论最大吞吐。

理解。 PaLM 论文提出这个指标时特意规定：理论最大值只算“前向 + 反向本来就需要的运算”，不算为省显存而做的重算（rematerialization，反向时把前向的某些中间结果再算一遍）2。重算的运算是真的在做，却不推进训练，把它算进去会让利用率虚高；PaLM 把包含重算的那个比值叫硬件算力利用率（HFU）。

数学。 \(n_{gpu}\) 块卡、每块峰值 \(F\)，每秒处理 \(R\) 个 token：

MFU\[\mathrm{MFU}=\frac{R\cdot C_{\text{token}}}{n_{gpu}\cdot F}\]分子是每秒完成的“有用运算”，分母是这些卡每秒最多能做的运算。PaLM 540B 在 6144 块 TPU v4 上的 MFU 是 46.2% 2。(M10.5)

把它倒过来，就得到一次训练要多少 GPU 小时：

GPU 小时\[\text{GPU 小时}=\frac{C_{\text{token}}\cdot D}{F\cdot\mathrm{MFU}\cdot3600}\]分子是总运算量 (M10.4)；分母是每块卡每小时实际完成的运算。(M10.6)
复核“每万亿 token 18 万 GPU 小时”

Insights 论文的表 4 记录了 V3 在 2048 块 H800 上的实测：每天处理 272.80B 个 token，每步 19.926 秒；按 BF16 峰值计算的 MFU 为 38.94%（因果计法）4。

（a）每块卡实际做的运算：\(R\cdot C_{\text{token}}/n_{gpu}=\dfrac{272.80\times10^9}{86400}\times250.45\times10^9\div2048=3.861\times10^{14}\)，即 386 TFLOP/s。

（b）反推峰值：MFU = 实际 ÷ 峰值，所以峰值 = 实际 ÷ MFU。Insights 同一张表给出的每卡因果吞吐是 385 TFLOP/s，\(385/0.3894\approx988.7\) TFLOP/s；用（a）自己数出的 386.1 反推是 \(386.1/0.3894\approx991.5\)，两者差 0.3%，来自每 token 运算量取 250.45 还是论文表 2 的“约 250”。DeepSeek 在 FlashMLA 的技术博客里写的 H800 SXM5 峰值是 990 TFLOP/s 5，H100 SXM 的稠密峰值是 989 6，几个数都在 1% 以内。（NVIDIA 的 H800 规格表本课没有读到，990 是 DeepSeek 的说法。）

（c）每万亿 token 的 GPU 小时：\(\dfrac{10^{12}}{272.80\times10^9}\times2048\times24=180{,}176\)。报告写的是 18 万 1。再乘 14.8，得 \(266.7\) 万，与报告成本表里预训练的 266.4 万一致。

三本账（报告的 GPU 小时、Insights 的吞吐、按配置数出来的 FLOPs）互相对得上：V3 的训练在 39% 左右的 MFU 下跑完，这笔账在物理上是说得通的。

三个常见的混淆

FLOPs 不等于时间。 同样的运算量，搬数据多、通信多、流水线空转多，时间就长。这正是 MFU 只有 39% 的原因，后面几页逐项拆开。

峰值要对口径。 厂商常同时印“稠密”和“稀疏”两个峰值，稀疏值是稠密的 2 倍，普通矩阵乘法用不上；不同精度的峰值也不同。V3 用 FP8 做矩阵乘法，Insights 却按 BF16 的峰值算 MFU 4，换成 FP8 的峰值，这个比例会更低。

因果还是非因果。 同一张表里，V3 的每卡吞吐按非因果计是 432 TFLOP/s，按因果计是 385 TFLOP/s 4。两者的差别只在注意力项是否把被掩掉的一半也算进去：\(432/385\approx1.12\)。按配置算也是这个比例：非因果时 \(\bar t\) 从 2048 换成 4096，注意力项从 30.70 翻倍成 61.40 GFLOPs，每 token 合计 \(219.75+61.40=281.15\)，而 \(281.15/250.45\approx1.12\)。

小练习：一个稠密模型的训练账

一个 7B 参数的稠密模型（忽略注意力项）训练 2T 个 token，用 1024 块峰值 989 TFLOP/s 的卡、MFU 40%。（1）总运算量是多少？（2）要多少 GPU 小时、多少天？

看答案

（1）\(6\times7\times10^9\times2\times10^{12}=8.4\times10^{22}\) FLOPs。

（2）每块卡每小时实际完成 \(989\times10^{12}\times0.4\times3600=1.424\times10^{18}\) 次运算，所以要 \(8.4\times10^{22}/1.424\times10^{18}\approx5.90\times10^4\) GPU 小时；除以 1024 块卡是 57.6 小时，约 2.4 天。

数据住在哪里

第 4 课 §4 算过一个让人意外的例子：Llama-2-7B 在一块 A100 上生成一个 token，运算只要 0.049 毫秒，把权重和 KV cache 从显存读一遍却要 7.53 毫秒。只数 FLOPs，会把时间低估 150 倍。所以第二笔账是字节：数据住在哪里，搬到计算单元要走多远、有多快。这一页把 GPU 的存储层级从里到外走一遍，每一层给出厂商或论文公布的数字。

带宽与延迟

含义。 带宽（bandwidth）是一条数据通路每秒最多能送多少字节；延迟（latency）是发起一次传输、到第一个字节到达之间的固定开销，与传多少字节无关。

理解。 把数据通路想成一根水管：带宽是管子的粗细，决定灌满一桶要多久；延迟是拧开龙头到水流出来的那一小段时间，无论接一杯还是接一桶都要等。传大块数据时粗细说了算，传很多小块时，每块都要付一次“拧龙头”的时间。这个比喻在一处不准：水管里的水是连续的，真实的传输要把数据切成包、经过交换机，延迟本身也随距离和拥塞变化，下面的公式只是一阶近似。

数学。 传 \(S\) 个字节的时间：

一次传输的时间\[t=\alpha+\frac{S}{\mathrm{BW}}=\alpha+S\beta\]\(\alpha\)：每条消息的固定延迟；\(\beta=1/\mathrm{BW}\)：每个字节的传输时间。这就是 §6 集合通信代价模型的基本单元 7。搬运显存里的大块数据时 \(\alpha\) 可以忽略，只剩 \(S/\mathrm{BW}\)。(M10.7)

从寄存器到 InfiniBand

GPU 的计算单元叫流式多处理器（streaming multiprocessor，SM）。H100 SXM5 有 132 个 SM，A100 有 108 个 6,8。数据离 SM 越近，存得越少、送得越快。FlashAttention-3 的论文给出了 H100 SXM5 的一张层级表 6，由内向外：

层级 在哪里 容量 带宽
寄存器（RMEM） 每个 SM 内部，每个线程私有 每 SM 256 KiB 表中未给
共享内存（SMEM，即片上 SRAM） 每个 SM 内部，由程序员管理 每 SM 228 KiB 全卡 31 TB/s
L2 缓存 芯片上，所有 SM 共用 50 MiB 12 TB/s
显存（HBM，论文称 GMEM） 芯片外的 DRAM，所有 SM 都能访问 80 GiB 3.35 TB/s

31 TB/s 这个数是论文自己算的：每个 SM 每个时钟周期 128 字节，乘以 132 个 SM，再乘以 1830 MHz 的加速频率 6。上一代 A100 的数字同一量级：108 个 SM 各有 192 KB 片上 SRAM，带宽约 19 TB/s；HBM 40–80 GB，带宽 1.5–2.0 TB/s 8；A100 数据表上 80GB SXM 版本的显存带宽是 2,039 GB/s，卡间 NVLink 600 GB/s，PCIe Gen4 64 GB/s 9。

再往外就出了这块卡。一台服务器叫一个节点（node）。V3 的集群每个节点 8 块 H800，节点内用 NVLink 与 NVSwitch 互连，节点之间用 InfiniBand（IB）1。报告给出的带宽是 NVLink 约 160 GB/s，大约是 IB（50 GB/s）的 3.2 倍 1；Insights 论文补充了背景：出于合规要求，H800 的 NVLink 带宽从 H100 的 900 GB/s 降到 400 GB/s，名义可用 200 GB/s、实际约能跑到 160 GB/s 4。

每一层都有自己的“脊点”

图 M10.2 右列的数字是这一页最重要的东西，值得单独推一遍。

数据从某一层来时，计算单元不干等的条件
(1)\(\displaystyle t_{\text{算}}=\dfrac{\text{FLOPs}}{F},\qquad t_{\text{搬}}=\dfrac{\text{字节}}{\mathrm{BW}}\)算完、搬完各自的最短时间；(M10.7) 忽略 \(\alpha\)
(2)\(\displaystyle t_{\text{搬}}\le t_{\text{算}}\iff\dfrac{\text{FLOPs}}{\text{字节}}\ge\dfrac{F}{\mathrm{BW}}\)搬运不拖后腿；两边同乘 \(F/\text{字节}\)
(3)\(\displaystyle \dfrac{F}{\mathrm{BW}_{\text{HBM}}}=\dfrac{989\times10^{12}}{3.35\times10^{12}}\approx295\)以 HBM 为例代入

对其余各层做同样的除法：SMEM \(989/31=31.9\)，L2 \(989/12=82.4\)，NVLink \(989/0.16=6181\)，IB \(989/0.05=19{,}780\)（单位都是 FLOP/字节），这就是图 M10.2 的右列。

左边的比值“每字节做几次运算”就是 §3 要正式定义的算术强度。这一串数字说明了高性能程序的共同形状：数据一旦从慢的层搬进快的层，就要在快的层里被反复使用。矩阵乘法把小块矩阵放进 SMEM、在里面做完尽可能多的乘加再写回，FlashAttention 不把 \(T\times T\) 的注意力矩阵写回 HBM 8，都是这个道理。越往外走，要求越苛刻：跨节点的每一个字节，要摊上近两万次运算才“不亏”。§5 会看到，这决定了哪种并行可以跨节点、哪种只能待在节点内。

同样的字节，放在不同的层

（a）搬 1 GB（\(10^9\) 字节）：SMEM 32 µs，L2 83 µs，HBM 0.30 ms，NVLink 6.25 ms，IB 20 ms。同一件事，快慢相差 620 倍。

（b）V3 的 KV cache 每个 token 70,272 字节（第 9 课的 MLA 只缓存 \(512+64\) 维的压缩向量，61 层，BF16）。一条 32K token 的序列：\(70{,}272\times32{,}768=2.30\times10^9\) 字节。decode 每一步都要把它从 HBM 读一遍，按 H800 的 3.35 TB/s 至少 0.69 ms 5；如果这份缓存不在本卡、要经 IB 从别的节点取，就是 46 ms，是 §6 里 Insights 估算的每 token 通信时间（理想情况下约 15 ms）的 3 倍。

（c）延迟：Insights 论文实测 64 字节小消息的端到端延迟，IB 同一交换机下 2.8 µs，NVLink 3.33 µs 4。1 GB 的消息里 µs 级的 \(\alpha\) 无关紧要；但如果把它切成一百万份 1 KB 的小消息，光是延迟就要几秒。

读硬件数字的三个陷阱

GB 还是 GiB。 FlashAttention-3 的表写 80 GiB，NVIDIA 的产品页写 80GB 6,10。二者差 7.4%。

单向还是双向、名义还是可达。 同一块 H800 的 NVLink，出现过 400、200、160 GB/s 三个数 4,1；论文没有逐一说明哪个是双向合计、哪个是单向。本课做计算时一律用 V3 报告给的可达值 160 GB/s。

同名不同卡。 H100 有 SXM 与 NVL 两种版本，带宽分别是 3.35 TB/s 与 3.9 TB/s 10；A100 80GB 的 SXM 与 PCIe 版本分别是 2,039 与 1,935 GB/s 9。H800 的数字本课没有读到 NVIDIA 的规格表，用的是 DeepSeek 在 FlashMLA 技术博客里给出的：显存带宽 3.35 TB/s、峰值 990 TFLOP/s，因降频（约 1600 MHz）实际约 865 TFLOP/s 5。这两个数与 H100 SXM 的 3.35 TB/s、989 TFLOP/s 相同或只差 0.1%；本课用到的数字里，两块卡只在 NVLink 上不同。

小练习：多大的消息才算“大”

按 (M10.7)，一条 \(S\) 字节的消息实际跑出的带宽是 \(S/t=S/(\alpha+S\beta)\)。（1）\(S\) 多大时，它恰好是链路带宽 \(\mathrm{BW}\) 的一半？（2）把上面实测的小消息延迟当作 \(\alpha\)，代入 IB（\(\alpha=2.8\) µs、50 GB/s）与 NVLink（\(\alpha=3.33\) µs、160 GB/s）。（3）V3 训练时，一个 token 在一层里发往一张卡的 dispatch 只有约 7392 字节（§6 的图 M10.11 按示意格式算出的数）。如果每个 token 单独发一条 IB 消息，有效带宽还剩多少？

看答案

（1）令 \(\dfrac{S}{\alpha+S\beta}=\dfrac{1}{2\beta}\)，两边交叉相乘得 \(2S\beta=\alpha+S\beta\)，所以 \(S_{1/2}=\alpha/\beta=\alpha\cdot\mathrm{BW}\)：它就是“等延迟的这段时间里，链路本来能传的字节数”。比它小的消息，一半以上的时间花在等延迟上。

（2）IB：\(2.8\times10^{-6}\times50\times10^9=1.4\times10^5\) 字节，约 140 KB。NVLink：\(3.33\times10^{-6}\times160\times10^9=5.3\times10^5\) 字节，约 533 KB。链路越快，要把延迟“摊薄”所需的消息就越大。

（3）\(t=\alpha+S\beta=2.8\ \mu\text{s}+\dfrac{7392}{50\times10^9}\ \text{s}=2.8\ \mu\text{s}+0.148\ \mu\text{s}=2.95\ \mu\text{s}\)，有效带宽 \(7392/2.95\ \mu\text{s}\approx2.5\) GB/s，只有 50 GB/s 的 5%。所以通信库要把发往同一张卡的许多 token 攒成一条大消息再发。（这是只按 α–β 模型的推算；DeepEP 实际怎样打包，本课没有核对。）

算术强度

取一个 \(7168\times7168\) 的权重矩阵（7168 是 V3 的隐藏维。V3 里真实的投影形状各不相同，例如注意力的输出投影是 \(16384\times7168\)；这里用方阵只是为了算得干净）。prefill 时它一次乘 4096 个 token，decode 时一次只乘 1 个。运算量差 4096 倍，时间却远没有差这么多：两种情况都要把这 \(7168^2\) 个权重从显存读一遍，decode 读完之后只做了 prefill 的 1/4096 的事。上一页的推导已经指出，决定“会不会干等数据”的是运算与字节之比。这一页把这个比值正式定义出来，并对矩阵乘法把它算到底。

定义

含义。 一段计算的算术强度（arithmetic intensity）是它的运算次数除以它在显存与芯片之间搬运的字节数。

理解。 它衡量的是一个字节被“嚼”了几口。强度高，搬来一个字节能用很久；强度低，搬来的东西一口吃完就得等下一口。它只取决于算法和数据形状，与硬件无关；硬件那一边的数是上一页的脊点 \(F/\mathrm{BW}\)。两者一比，就知道这段计算在这块硬件上会不会干等。

数学。

算术强度\[I=\frac{\text{FLOPs}}{\text{HBM 流量（字节）}}\qquad(\text{单位：FLOP/字节})\]分母默认是显存流量。也可以对其他层级定义（例如 SMEM 与寄存器之间），那时要和那一层的带宽比较。(M10.8)
名字的来历

提出屋顶线模型的 Williams 等人管这个量叫 operational intensity，定义为“每字节 DRAM 流量对应的运算数”，并特意不用 arithmetic intensity：在他们的用法里，后者量的是处理器与缓存之间的流量 11。机器学习系统的文献（包括 FlashAttention）普遍叫它 arithmetic intensity 8。本课程沿用“算术强度”这个名字，但分母始终写明是哪一层的流量。

推导：矩阵乘法的强度

问题。 对 \([m,k]\times[k,n]\)，强度是多少？它怎样随三个维度变化？

形式化。 \(A\in\R^{m\times k}\) 是 \(m\) 个 token 的输入，\(B\in\R^{k\times n}\) 是权重，\(C=AB\in\R^{m\times n}\) 是输出，每个数 \(s\) 字节。先做一个理想化假设：每个矩阵只在显存与芯片之间走一趟，\(A\)、\(B\) 各读一次，\(C\) 写一次。这等于假设片上存储足够让每个读进来的数被充分复用；它给出的是流量的下限，也就是强度的上限。

矩阵乘法的算术强度
(1)\(\displaystyle \text{FLOPs}=2mnk\)(M10.1)
(2)\(\displaystyle \text{字节}=s\,(mk+kn+mn)\)读 \(A\)（\(mk\) 个数）、读 \(B\)（\(kn\) 个）、写 \(C\)（\(mn\) 个），每个 \(s\) 字节
(3)\(\displaystyle I=\dfrac{2mnk}{s\,(mk+kn+mn)}\)两者相除
(4)\(\displaystyle I=\dfrac{2}{s}\cdot\dfrac{1}{\frac1n+\frac1m+\frac1k}\)分子分母同除以 \(mnk\)：\(mk/mnk=1/n\)，\(kn/mnk=1/m\)，\(mn/mnk=1/k\)
矩阵乘法的算术强度\[I(m,n,k)=\frac{2mnk}{s\,(mk+kn+mn)}=\frac{2}{s}\left(\frac1m+\frac1n+\frac1k\right)^{-1}\]三个倒数里最大的来自最短的一维，它主导了和，所以强度由最短的那一维决定。(M10.9)

最后一行值得停下来看。\(\frac1m+\frac1n+\frac1k\) 里，最小的维度贡献最大的倒数。把它夹在两个界之间：

强度被最短的一维夹住
(1)\(\displaystyle \text{设}\ \mu=\min(m,n,k)\)记最短的一维
(2)\(\displaystyle \dfrac1\mu\ \le\ \dfrac1m+\dfrac1n+\dfrac1k\ \le\ \dfrac3\mu\)左边：三项之和不小于其中最大的一项 \(1/\mu\)；右边：每一项都不超过 \(1/\mu\)
(3)\(\displaystyle \dfrac{2}{3s}\,\mu\ \le\ I\ \le\ \dfrac2s\,\mu\)取倒数（不等号反向）再乘 \(\frac2s\)
强度的上下界\[\frac{2}{3s}\min(m,n,k)\ \le\ I(m,n,k)\ \le\ \frac{2}{s}\min(m,n,k)\]BF16（\(s=2\)）时就是 \(\tfrac13\min\le I\le\min\)。无论另外两维多大，强度都不会超过最短那一维。(M10.10)

把三种典型形状代入 (M10.9)，强度可以直接读出来（BF16）：

  • 矩阵乘向量（GEMV，\(m=1\)）：\(I=1/(1+\frac1n+\frac1k)\approx1\) FLOP/字节。每个权重读进来只用一次：一次乘、一次加，共 2 次运算，而它占 2 个字节。decode 时 batch 为 1 的每一个线性层都是这种情形。
  • 一批 token 乘一个大权重（\(m\ll n,k\)）：\(I\approx m\)。token 数就是强度，这就是第 4 课式 (4.18) 说的“batch 就是强度”。
  • 方阵（\(m=n=k\)）：\(I=\frac{2n}{3s}=\frac n3\)。\(n=4096\) 时 1365，远在任何一块卡的脊点之上。

前两种情形的差别只有一处：同一份权重被几个 token 共用。权重从显存读一次的字节数两边一样，运算却差 \(m\) 倍。图 M10.3 把这件事画了出来。

手算四个强度

（a）prefill 的一个专家上投影：\(m=4096\) 个 token、\(k=7168\)、\(n=2048\)。运算 \(2\times4096\times2048\times7168=1.203\times10^{11}\)；字节 \(2\times(4096\times7168+7168\times2048+4096\times2048)=2\times52{,}428{,}800=1.049\times10^8\)；\(I=1146.9\)。

（b）decode 的 \(7168\times7168\) 投影，\(m=1\)：\(I=1/(1+2/7168)=0.9997\approx1.0\)。

（c）同一个投影，\(m=64\)：\(I=1/(\frac1{64}+\frac2{7168})=62.9\)，比“\(I\approx m\)”少一点，因为 \(\frac2{7168}\) 并非可以完全忽略。

（d）\(4096^3\) 的方阵乘法：\(I=4096/3=1365.3\)。

MoE 专家的强度：细粒度切分解决不了的事

V3 报告写道：decode 阶段每个专家处理的 batch 通常不超过 256 个 token，瓶颈在访存而不在计算 1。用 (M10.9) 验证：专家上投影 \(k=7168\)、\(n=2048\)，\(m=256\) 时 \(I=1/(\frac1{256}+\frac1{2048}+\frac1{7168})=220.6\) FLOP/字节，低于 H800 的脊点 295.5，确实受带宽限制。

注意 \(m=256\) 时最短的一维是 \(m\)。第 7 课 §5的细粒度专家把 \(n\) 切小，它降低的是曲线右端的上限（图 M10.4 里 \(n\) 从 7168 变成 2048，上限从 3584 降到 1593），对左半边几乎没有影响：强度的瓶颈是“每个专家分到多少个 token”。所以 decode 部署要把尽可能多的 token 汇到同一个专家上，这正是第 12 课 §8里 decode 实例用 320 块卡、每卡只放一个专家的一个理由（笔者的解读）。

不是矩阵乘法的运算

Transformer 里还有许多逐元素运算：加残差、RMSNorm、激活函数、softmax。它们的强度低得多。

加一次残差

\(\mathbf y=\mathbf x+\mathbf z\)，BF16，每个元素：读 \(x_i\)、\(z_i\) 共 4 字节，写 \(y_i\) 2 字节，只做 1 次加法。\(I=1/6\approx0.17\) FLOP/字节，比 decode 的矩阵乘向量还低 6 倍。任何一块卡上它都受带宽限制，时间完全由“读两遍、写一遍”决定。

这类运算的对策不是提高强度（每个元素本来就只有这么点事），而是减少往返 HBM 的次数。GPU 上的一段程序叫一个内核（kernel），每个内核通常从 HBM 读输入、把结果写回 HBM；把几个相邻的逐元素运算合进同一个内核，叫内核融合（kernel fusion），数据读进片上后连续做完再写回，中间结果不再往返显存。另一个上限也要知道：H100 SXM5 的矩阵乘峰值是 989 TFLOP/s，指数这类“特殊函数”却只有 3.9 TFLOP/s 6，softmax 里的 \(e^x\) 走的是后者。FlashAttention 系列把 softmax 与两次矩阵乘法融合在片上完成，同时处理了这两件事 8,6。

注意力在 decode 时的强度

decode 时，每条序列的新 token 要和自己缓存里的所有键做点积，再对所有值加权求和。这里的数据是 KV cache，不是权重，而每条序列只读自己的那一份，所以 batch 帮不上忙。强度由“一份缓存被几个查询头共用”决定。记 \(n_h\) 为查询头数，\(n_g\) 为 KV 头数（分组查询注意力 GQA 把 \(n_h\) 个查询头分成 \(n_g\) 组，每组共用一对键、值头；MHA 是 \(n_g=n_h\) 的特例），\(d_h\) 为每头维度：

MHA / GQA 解码注意力的强度（BF16 缓存，一个查询 token）
(1)\(\displaystyle \text{每个缓存 token、每个 KV 头：读}\ 2d_h\times2=4d_h\ \text{字节}\)键、值各 \(d_h\) 个数，BF16 每个 2 字节
(2)\(\displaystyle \text{每个查询头：打分}\ 2d_h\ +\ \text{加权求和}\ 2d_h=4d_h\)与这个键点积一次，给这个值加权累加一次
(3)\(\displaystyle \text{共用这对键值的查询头有}\ n_h/n_g\ \text{个}\)同一组的查询头读的是同一份缓存
(4)\(\displaystyle I=\dfrac{(n_h/n_g)\cdot4d_h}{4d_h}=\dfrac{n_h}{n_g}\)\(d_h\) 约掉，强度与 batch、上下文长度都无关

这与第 4 课 §4 的结论相同：MHA 为 1；64 个查询头、8 个 KV 头的 GQA-8 为 8。第 9 课 §7 把 MLA 吸收后的解码写成“所有头共用一份缓存”的 MQA 形式，相当于 \(n_g=1\)，强度一下子跳到两百多。注意不是上式给出的 \(n_h/n_g=128\)：上面的推导假设键和值是两份不同的数据，而 MLA 缓存的压缩向量同时充当键和值，下面逐项算。

MLA 解码注意力的强度（V3 维度，BF16 缓存，一个查询 token）
(1)\(\displaystyle \text{每个缓存 token 读}\ (512+64)\times2=1152\ \text{字节}\)缓存的是 512 维压缩向量与 64 维 RoPE 键，所有头共用 3,5
(2)\(\displaystyle \text{每个头：打分}\ 2\times576\ +\ \text{加权求和}\ 2\times512=2176\)吸收后，查询与 576 维缓存向量点积；输出对 512 维压缩向量加权求和
(3)\(\displaystyle \text{128 个头}:\ 128\times2176=278{,}528\ \text{FLOPs}\)V3 有 128 个查询头，共用同一份缓存
(4)\(\displaystyle I=278{,}528/1152=241.8\)与第 9 课式 (9.21) 相同；FlashMLA 的博客近似写成 \(2h_q\)（\(h_q\) 即查询头数 \(n_h\)，\(2\times128=256\)）5

同样读一份缓存，MHA 每个头各读各的，一份数据只服务一个头；MLA 让 128 个头共用一份，而且那 512 维的压缩向量吸收之后既当键又当值，每个头要用它两次（打分一次、加权求和一次），只有 64 维的 RoPE 键每个头只用一次。平均下来，每个缓存的数被用了 \((512\times2\times128+64\times128)/576\approx241.8\) 次（BF16 下每个数 2 字节、每用一次是一次乘加共 2 次运算，所以“用了几次”正好等于强度），这就是强度约为 \(2n_h\)、而不是 \(n_h\) 的原因。这就是“强度”在注意力上的全部含义：一份读进来的数据，被多少次运算用到。

算强度时容易出错的三处

理想化假设。 (M10.9) 假设每个矩阵只走一趟显存。真实的内核把矩阵切成小块放进 SMEM，块不够大时同一块数据会被读好几遍，实际强度低于公式；反过来，L2 缓存可能替你挡掉一部分重复读取。公式给的是一个好内核能接近的上限。

精度要前后一致。 FP8 权重让 \(s\) 减半、强度翻倍，但 FP8 矩阵乘的峰值也不同于 BF16，脊点随之移动。比较时强度与脊点必须用同一种精度。本课的数字一律按 BF16。

不同层级的强度不同。 同一段计算，对 HBM 的强度与对 SMEM 的强度不是一个数。说“强度”时要说清楚分母是哪一层的流量；本课默认是 HBM。

小练习：强度与批量

一个 \([k,n]=[4096,11008]\) 的 BF16 权重。（1）\(m=1\)、\(m=32\) 时强度各是多少？（2）要让强度达到 H800 的脊点 295.5，\(m\) 大约要多大？（用 \(I\approx1/(\frac1m+\frac1n+\frac1k)\) 估算。）

看答案

（1）\(\frac1n+\frac1k=\frac1{11008}+\frac1{4096}=9.08\times10^{-5}+2.44\times10^{-4}=3.35\times10^{-4}\)。\(m=1\)：\(I=1/(1+0.000335)\approx1.0\)。\(m=32\)：\(I=1/(0.03125+0.000335)=31.7\)。

（2）令 \(\frac1m+3.35\times10^{-4}=\frac1{295.5}=3.384\times10^{-3}\)，得 \(\frac1m=3.049\times10^{-3}\)，\(m\approx328\)。

本页要点
  • 算术强度 = 运算 ÷ 显存字节；它只取决于算法与形状，与硬件无关。
  • 矩阵乘法 \(I=\frac2s\big(\frac1m+\frac1n+\frac1k\big)^{-1}\)，被最短的一维夹住：\(\frac{2}{3s}\min\le I\le\frac2s\min\)。GEMV 约 1，一批 \(m\) 个 token 约 \(m\)，方阵约 \(n/3\)（BF16）。

屋顶线模型

上一页算出了强度，上上页给出了硬件的两个上限。把两者放进一张图，就是屋顶线模型（roofline model）：给定一段计算的强度，它在一块卡上最快能跑多快，受的是哪一个上限。这一页先从“时间至少要多久”把它推出来，再把 V3 的几种计算放到 A100 与 H800 的屋顶下。

图景：一间厨房

把 GPU 想成一间厨房（第 4 课用过同一个比喻）。映射：灶台每秒最多炒 \(F\) 份菜（峰值算力）；传菜口每秒最多送进 \(\mathrm{BW}\) 份原料（显存带宽）；一份原料能炒出几份菜，是这道菜的“强度” \(I\)。收益：原料送得再快，每秒也最多炒 \(F\) 份；灶台再快，每秒也最多炒 \(\mathrm{BW}\times I\) 份。实际速度是两者中较小的那个，于是一眼能看出该加灶台还是该拓宽传菜口。失效的地方：真实的 GPU 有好几级“传菜口”（上一页的层级），还能一边送一边炒；另外“一份原料炒几份菜”本身取决于厨师怎么安排（内核怎么分块），并不是菜谱写死的。所以下面的公式是上限，实测只能接近。

从时间下界推出屋顶

屋顶线
(1)\(\displaystyle t\ \ge\ \dfrac{\text{FLOPs}}{F}\)每秒至多做 \(F\) 次运算
(2)\(\displaystyle t\ \ge\ \dfrac{\text{字节}}{\mathrm{BW}}\)每秒至多搬 \(\mathrm{BW}\) 个字节，(M10.7) 忽略延迟
(3)\(\displaystyle t\ \ge\ \max\!\Big(\dfrac{\text{FLOPs}}{F},\ \dfrac{\text{字节}}{\mathrm{BW}}\Big)\)两个条件都要满足
(4)\(\displaystyle P=\dfrac{\text{FLOPs}}{t}\ \le\ \min\!\Big(F,\ \mathrm{BW}\cdot\dfrac{\text{FLOPs}}{\text{字节}}\Big)=\min(F,\ \mathrm{BW}\cdot I)\)可达算力 \(P\) 是运算量除以时间；对 max 取倒数变成 min
屋顶线：可达算力\[P(I)=\min\big(F,\ \mathrm{BW}\cdot I\big)\]Williams 等人的原式：可达 GFlops/s = min(峰值浮点性能, 峰值显存带宽 × operational intensity) 11。(M10.11)

在双对数坐标上，\(\mathrm{BW}\cdot I\) 是一条斜率为 1 的斜线（\(\log P=\log\mathrm{BW}+\log I\)），\(F\) 是一条水平线，合起来像一个屋顶。两条线的交点叫脊点（ridge point），它的横坐标是跑满算力所需的最小强度 11：

脊点\[I^\star=\frac{F}{\mathrm{BW}}\]强度在脊点左边（\(I<I^\star\)）叫受带宽限制（memory-bound），\(P=\mathrm{BW}\cdot I\)；在右边叫受算力限制（compute-bound），\(P=F\)。(M10.12)
对数坐标熟悉双对数图的可以跳过

对数刻度上，相邻两条网格线之间差 10 倍而不是差 10。好处是横跨很多个数量级的数能画在同一张图上：强度从 0.1 到 10,000，算力从 0.1 到 1000 TFLOP/s。代价是直线的含义变了：\(y=cx\) 取对数后是 \(\log y=\log c+\log x\)，在双对数图上是一条斜率为 1 的直线，\(c\) 只决定它上下平移。屋顶的斜线就是这样来的：不同的带宽是互相平行的斜线。

脊点有一个很实用的读法：它把“这块卡算得多快”和“喂得多快”压成一个数。本课用到的几块卡：

硬件 \(F\)（稠密 BF16） \(\mathrm{BW}\)（HBM） 脊点 \(I^\star\) 来源
A100 80GB SXM 312 TFLOP/s 2.039 TB/s 153 NVIDIA 数据表 9
H100 SXM 989 TFLOP/s 3.35 TB/s 295.2 FlashAttention-3 6
H800 SXM5 990（降频后约 865） 3.35 TB/s 295.5（258.2） DeepSeek 的 FlashMLA 博客 5

从 A100 到 H100，算力涨了 \(989/312\approx3.17\) 倍，带宽只涨了 \(3.35/2.039\approx1.64\) 倍，脊点从 153 右移到 295：新一代卡要求更高的强度才能喂饱，强度低的计算反而更“饿”。

一次专家矩阵乘法要多久（H800，BF16）

专家上投影 \(k=7168\)、\(n=2048\)，分到 \(m\) 个 token。

\(m=256\)：运算 \(2\times256\times2048\times7168=7.516\times10^9\)；字节 \(2\times(256\times7168+7168\times2048+256\times2048)=3.408\times10^7\)。\(t_{\text{算}}=7.516\times10^9/990\times10^{12}=7.59\) µs，\(t_{\text{搬}}=3.408\times10^7/3.35\times10^{12}=10.17\) µs。搬运更慢，下界是 10.17 µs，可达 \(7.516\times10^9/10.17\,\mu\text{s}=739\) TFLOP/s，是峰值的 75%。

\(m=1\)：字节几乎不变（\(2.938\times10^7\)，基本就是权重本身），\(t_{\text{搬}}=8.77\) µs；运算只有 \(2.936\times10^7\)，\(t_{\text{算}}=0.030\) µs。可达 3.35 TFLOP/s，是峰值的 0.34%。

两者读的字节差不多，做的事差 256 倍。这就是 decode 的矩阵乘法“把时间花在读权重上”的精确含义。

重叠与不重叠：最多差 2 倍

(M10.11) 默认搬运与计算可以完全重叠（overlap）：一边搬下一块数据，一边算已经到手的那一块。回到厨房的比喻，重叠是“边送原料边炒”，总时间由较慢的那一边决定；不重叠是“等原料全部送到再开火”，时间是两段之和。好在这两种情况差得不多：

重叠的价值有多大
(1)\(\displaystyle \max(a,b)\ \le\ a+b\ \le\ 2\max(a,b)\)\(a,b\ge0\)：和不小于较大者；两项都不超过较大者
(2)\(\displaystyle a=\dfrac{\text{FLOPs}}{F},\ b=\dfrac{\text{字节}}{\mathrm{BW}}\)代入计算时间与搬运时间
(3)\(\displaystyle \text{不重叠时的速度}\ \ge\ \tfrac12\min(F,\mathrm{BW}\cdot I)\)时间至多是理想下界的 2 倍，速度至少是屋顶的一半
一段计算的时间范围\[\max\!\Big(\frac{\text{FLOPs}}{F},\frac{\text{字节}}{\mathrm{BW}}\Big)\ \le\ t\ \le\ \frac{\text{FLOPs}}{F}+\frac{\text{字节}}{\mathrm{BW}}\]右边的上界只在“除了搬运和计算，没有别的开销”时成立。两端之比在 \(a=b\)（强度恰好等于脊点）时最大，为 2；远离脊点时两端几乎相等。(M10.13)

所以离脊点远的计算，重叠与否无关紧要：decode 的矩阵乘向量几乎全是搬运时间，算得再快也没用。离脊点近的计算，重叠最多能省一半。这个“最多一半”在 §6、§7 还会出现：把通信藏进计算里，最好情况也是省掉通信与计算中较短的那一段。

MLA 解码：搬运与计算几乎一样长

V3 的一条 32K token 的序列，decode 一步，所有 61 层的注意力部分：读缓存 \(70{,}272\times32{,}768=2.303\times10^9\) 字节，\(t_{\text{搬}}=0.687\) ms（3.35 TB/s）；运算 \(278{,}528\times32{,}768\times61=5.567\times10^{11}\) 次，\(t_{\text{算}}=0.562\) ms（990 TFLOP/s），降频到 865 时是 0.644 ms。降频后两者差不到 7%：这正是强度 241.8 贴着脊点的样子。按 990 TFLOP/s 算，重叠与否会让时间在 0.69 ms 与 1.25 ms 之间变化，也就是 (M10.13) 的两端，差了近一倍。

屋顶线不告诉你的事

它只是上限。 DeepSeek 报告的 FlashMLA 新内核在 H800 上最高达到降频后峰值的约 80%，受带宽限制的设置下带宽约 3 TB/s（3.35 的 90%）5。这已经是很好的内核，仍在屋顶之下。

它忽略了延迟与并行度。 一次很小的矩阵乘法，数据少、运算少，时间却可能被启动内核、同步的固定开销占满；它也可能太小，填不满 132 个 SM。屋顶线对这些情况给出的下界会过于乐观。

非矩阵运算有自己更低的上限。 指数运算的上限是 3.9 TFLOP/s 而不是 989 6；对 softmax 这类运算，平顶应当画得低得多。

小练习：画出一块卡的屋顶

某卡 \(F=400\) TFLOP/s，\(\mathrm{BW}=1.6\) TB/s。（1）脊点在哪？（2）强度 8、250、1000 的三段计算各能跑多快？（3）一段计算有 \(10^{12}\) 次运算、\(2\times10^{9}\) 字节，时间下界是多少？不重叠时的上界呢？

看答案

（1）\(I^\star=400/1.6=250\) FLOP/字节。

（2）\(I=8\)：\(1.6\times8=12.8\) TFLOP/s（受带宽限制，峰值的 3.2%）；\(I=250\)：恰好 400；\(I=1000\)：400（受算力限制）。

（3）\(t_{\text{算}}=10^{12}/4\times10^{14}=2.5\) ms，\(t_{\text{搬}}=2\times10^9/1.6\times10^{12}=1.25\) ms。下界 \(\max=2.5\) ms；不重叠 \(2.5+1.25=3.75\) ms。强度是 500，在脊点右边，所以下界由计算决定。

本页要点
  • 时间下界 \(t\ge\max(\text{FLOPs}/F,\ \text{字节}/\mathrm{BW})\)，等价于屋顶线 \(P(I)=\min(F,\mathrm{BW}\cdot I)\)，脊点 \(I^\star=F/\mathrm{BW}\)。

四种并行

前四页都在一块卡上算账。V3 放不进一块卡：按 ZeRO 论文的算法，混合精度 Adam 每个参数要 16 字节（半精度的参数与梯度各 2，FP32 的参数副本、动量、方差各 4；论文写的是 fp16，换成 BF16 字节数一样）12，671B 个参数就是 10.7 TB，而一块 H100 只有 80 GB 显存 10。模型必须切开。切法有四种，每一种都是把计算里的某个张量沿某一维切开；切开以后，卡与卡之间就要交换数据。这一页比较它们各自切什么、省下什么显存、付出什么通信；通信的具体代价留给 §6。

数据并行：切数据

含义。 每张卡放一份完整的模型，一个 batch 切成 \(n_{dp}\) 份，各算各的梯度；反向结束后把梯度加起来平均，所有卡做同样的更新，于是模型永远保持一致。

数学。 为什么“各算各的再平均”与“一张卡算整个 batch”完全相同？因为损失是样本损失的平均，求导是线性的：

数据并行的梯度\[\nabla_\theta\mathcal L=\frac1B\sum_{i=1}^{B}\nabla_\theta\ell_i=\frac{1}{n_{dp}}\sum_{g=1}^{n_{dp}}\underbrace{\frac{n_{dp}}{B}\sum_{i\in\text{第 }g\text{ 份}}\nabla_\theta\ell_i}_{\text{第 }g\text{ 张卡的平均梯度}}\]\(\theta\) 是模型参数，\(\ell_i\) 是第 \(i\) 个样本的损失，\(\mathcal L\) 是整个 batch 的平均损失；\(B\) 个样本平均分成 \(n_{dp}\) 份。把各卡的平均梯度求和再除以 \(n_{dp}\)，这个“求和”就是一次 all-reduce。(M10.14)

显存。 每张卡都存全部 16 字节/参数：\(n_{dp}\) 张卡存着 \(n_{dp}\) 份一模一样的参数、梯度和优化器状态，这是数据并行的浪费所在。

ZeRO 的含义。 ZeRO（Zero Redundancy Optimizer，零冗余优化器）让数据并行的每张卡只保管 \(1/n_{dp}\) 的模型状态，要用别人保管的那部分时再通信取来 12。

理解。 像一个学习小组合用一套多卷的参考书：每人只把其中一卷带回家，要用哪卷就找保管它的人借。优化器状态（FP32 的参数副本、动量、方差，共 12 字节/参数）只在更新参数时用一次，最适合先切；梯度与参数在前向、反向里一直要用，切开它们就要多“借”几次。这个比喻在一处不准：借书要等人送来，而 ZeRO 的“借”是集合通信，可以提前发起、和计算重叠。

数学。 设参数量为 \(N\)（ZeRO 论文记作 \(\Psi\)），数据并行的卡数为 \(n_{dp}\)（论文记作 \(N_d\)）。论文把三级切法记作 \(P_{os}\)、\(P_{os+g}\)、\(P_{os+g+p}\) 12，工程上常叫 ZeRO-1、2、3（V3 报告写的就是“ZeRO-1”1）：

级别 切开什么 每卡模型状态（字节） 每步通信（元素）
标准数据并行 不切 \(16N\) \(2N\)
ZeRO-1 优化器状态 \(4N+12N/n_{dp}\) \(2N\)
ZeRO-2 再切梯度 \(2N+14N/n_{dp}\) \(2N\)
ZeRO-3 再切参数 \(16N/n_{dp}\) \(3N\)

前两级不增加通信，原因在 §6 的 (M10.18)：标准的梯度 all-reduce 本来就分成 reduce-scatter 与 all-gather 两半，各搬 \(N\) 个元素。ZeRO 在 reduce-scatter 之后让每张卡只拿自己那一块梯度去更新自己保管的那一块参数，再 all-gather 更新后的参数，两步合起来仍是 \(2N\) 12。ZeRO-3 连参数也只保管一块，前向时要边算边 all-gather 各层参数（\(N\)），反向时按相反顺序再收集一遍（\(N\)），加上梯度的 reduce-scatter（\(N\)），共 \(3N\) 12。V3 用的是 ZeRO-1 1。

7B 模型的数据并行

（a）不切：\(7\times10^9\times16=112\) GB/卡，一块 80 GB 的卡放不下。（b）ZeRO-1、64 张卡：\(4\times7+12\times7/64=28+1.31=29.3\) GB/卡。（c）通信：BF16 梯度 \(2\times7\times10^9=14\) GB，环形 all-reduce 每卡发出约 \(2\times14=28\) GB（§6）。

这个通信贵不贵？用算术强度的眼光看：每张卡每步处理 \(b\) 个 token，做 \(6Nb\) 次运算，发出约 \(2\times2N\) 字节，所以“每字节网络流量摊到的运算”约为 \(6Nb/4N=1.5\,b\)，与模型大小无关（笔者推导）。这里有两个假设：每个参数都参与每个 token 的计算（稠密模型），以及卡数足够多、\(\frac{2(p-1)}{p}\approx2\)。一个每卡每步 \(b=30{,}720\) 个 token 的稠密模型（这正是 V3 每张卡每步平均分到的 token 数：预训练的绝大部分时间里 batch 是 15,360 条 4K 序列，每步 62,914,560 个 token 1，分到 2048 张卡上），强度约 46,000，比 IB 的“脊点” 19,780（§2）还高。

V3 本身是 MoE，不能直接套 \(1.5b\)：若真让每张卡放一份完整的 671B 模型，梯度按 671B 个参数算，运算却只按 37B 个激活参数算，比值会掉到 \(1.5b\times37/671\approx2500\)。好在 V3 不是这样切的，按它的实际配置算（笔者推算）：16 段流水线让每张卡只同步自己那约 \(1/16\) 层的梯度，而流过这些层的是 \(2048/16=128\) 路数据并行中一路的 \(62{,}914{,}560/128=491{,}520\) 个 token，注意力等每个 token 都要用的部分，比值约 \(1.5\times491{,}520\approx74\) 万；路由专家被专家并行切开，同一个专家在全集群只有 \(2048/(16\times64)=2\) 份，梯度只需在这 2 份之间同步，比值更高。数据并行的通信每步只有一次、又能和反向重叠，所以它是四种切法里最容易跨节点的。

张量并行：切矩阵

含义。 把一层里的每个大矩阵切成几块放在不同的卡上，每张卡只算一部分。

理解。 像两个会计合算一张大表。第一步按列分工，各算一半的列，彼此不用对账：下一步的 GeLU 逐个元素作用，拿到自己那一半就能往下算。第二步按行分工，每人只能算出最终结果的一份“部分和”，两人的结果加起来才是总账，这一次对账就是 all-reduce。这个比喻在一处不准：会计对一次账就能收工，张量并行却是每一层、每一批 token 都要对账，对账的数据量还随 token 数增长，所以它对链路带宽的要求远高于数据并行。

数学。 这正是 M01 §4 的分块矩阵乘法。以 FFN 为例，\(Z=\mathrm{GeLU}(XA)\,B\)：\(X\in\R^{T\times d}\) 是 \(T\) 个 token 的输入，\(A\in\R^{d\times4d}\) 与 \(B\in\R^{4d\times d}\) 是 FFN 的两个权重矩阵（GPT 式 FFN 的中间维是 \(4d\)；\(A\)、\(B\) 沿用 Megatron-LM 论文的记号，这里的 \(B\) 与上面的 batch 大小无关），GeLU 是逐元素作用的激活函数，\(Z\in\R^{T\times d}\) 是输出。切成 \(p\) 份时第 \(g\) 份记作 \(A_g\in\R^{d\times4d/p}\)（\(A\) 的第 \(g\) 组列）、\(B_g\in\R^{4d/p\times d}\)（\(B\) 的第 \(g\) 组行），下面以 \(p=2\) 为例：

列切 + 行切，只需一次求和
(1)\(\displaystyle A=[A_1\ A_2]\ \Rightarrow\ XA=[XA_1\ \ XA_2]\)按列切 \(A\)：\(XA_g\) 是 \([T,d]\times[d,2d]=[T,2d]\)，两张卡各自算出一半的列，不用通信
(2)\(\displaystyle \mathrm{GeLU}(XA)=[\mathrm{GeLU}(XA_1)\ \ \mathrm{GeLU}(XA_2)]\)GeLU 逐元素作用，可以各算各的；若按行切 \(A\)，每张卡只有 \(XA\) 的部分和，得先求和才能过 GeLU
(3)\(\displaystyle B=\begin{bmatrix}B_1\\B_2\end{bmatrix}\ \Rightarrow\ Z=\mathrm{GeLU}(XA_1)B_1+\mathrm{GeLU}(XA_2)B_2\)按行切 \(B\)：分块乘法 (M1.12)；\([T,2d]\times[2d,d]\)，每张卡得到一个 \([T,d]\) 的部分和 \(Z_g=\mathrm{GeLU}(XA_g)B_g\)
(4)\(\displaystyle Z=\textstyle\sum_{g=1}^{p}Z_g\ \ \text{需要一次 all-reduce}\)部分和必须加起来，每张卡才有完整的 \(Z\)
张量并行的 FFN\[Z=\sum_{g=1}^{p}\mathrm{GeLU}(XA_g)\,B_g\]Megatron-LM 用这种“先列后行”的切法，让 MLP 前向只需一次 all-reduce、反向一次；注意力按头切 Q、K、V，输出投影按行切，也是前向、反向各一次。合起来，一层 Transformer 前向两次 all-reduce、反向两次 13。(M10.15)

代价。 通信发生在每一层，而且传的是激活，大小与 token 数成正比。它贵不贵，用与数据并行同样的办法估算。

张量并行的“通信强度”（笔者推导）
(1)\(\displaystyle \text{参数}=4d^2+8d^2=12d^2\)注意力的 \(W^Q,W^K,W^V,W^O\) 各 \(d\times d\)；FFN 的 \(A\)、\(B\) 各 \(4d^2\)
(2)\(\displaystyle \text{运算}=\dfrac{6\times12d^2}{p}=\dfrac{72d^2}{p}\ \text{/（token·卡）}\)训练每参数 6 次 (M10.2)，平分到 \(p\) 张卡
(3)\(\displaystyle \text{发送}=4\times\dfrac{2(p-1)}{p}\times2d\ \text{字节 /（token·卡）}\)前向 2 次、反向 2 次 all-reduce，每次 \(d\) 个 BF16 数；环形 all-reduce 每卡发 \(\frac{2(p-1)}{p}\) 倍（§6）
(4)\(\displaystyle I_{\text{TP}}=\dfrac{72d^2/p}{16d(p-1)/p}=\dfrac{4.5\,d}{p-1}\)两者相除，\(1/p\) 约掉
张量并行的通信强度\[I_{\text{TP}}=\frac{4.5\,d}{p-1}\quad\text{FLOP / 字节}\]适用条件：BF16 激活、稠密层、环形 all-reduce、不做激活重算（重算时前向的两次 all-reduce 要再做一遍）。与链路的脊点 \(F/\mathrm{BW}_{\text{link}}\) 比较：低于它，通信时间就超过计算时间。运算只数了带参数的矩阵乘法；注意力打分与加权求和没有计入，计入会让强度略高一些。(M10.16)
V3 为什么不用张量并行

V3 的隐藏维 \(d=7168\)，节点内 8 张卡：\(I_{\text{TP}}=4.5\times7168/7=4608\)。（V3 的一层并不是标准的 \(12d^2\)：MLA 的投影 187.1M 个参数，加上每 token 激活的 9 个专家与门控 398.2M，合计约 \(11.4d^2\)，按它算是 4374，下面的结论不变。）H800 的 NVLink 可达约 160 GB/s，链路脊点 \(990/0.16\approx6190\)（§2 用 H100 的 989 算得 6181，差别可以忽略）；\(4608<6190\)，所以张量并行的通信比计算还慢约 34%，只能靠重叠去藏。跨节点走 IB（50 GB/s，脊点 19,800）就完全不可行。Insights 论文的说法是：训练时不用张量并行，因为在受限的 NVLink 带宽下它效率太低 4。

对照（笔者推算）：H100 的 NVLink 是 900 GB/s，H800 被降到 400 GB/s 4。如果可达带宽也按这 2.25 倍的比例，H100 上的链路脊点约为 2750，低于 4608，张量并行就划算了。这个例子说明，同一个设计在两块“算力一样”的卡上可以得出相反的结论。

流水线并行：切层

含义。 把 \(l\) 层按顺序切成 \(P\) 段，每段放在一组卡上；一个 batch 再切成 \(m\) 个 micro-batch 依次送进去（本页的 \(m\) 是 micro-batch 个数）。段与段之间只传激活（前向）和激活的梯度（反向），而且是点对点，所以通信很少。

图景。 它像一条装配线：\(P\) 个工位按顺序排开，每个工位只装自己那几层；一件产品（micro-batch）做完一道工序就传给下一个工位，于是不同工位可以同时在做不同的产品。失效的地方：装配线只往一个方向走，训练却还要把梯度从最后一个工位倒着传回来，而且每个工位都得把前向时的激活留到这件产品倒着传回来为止，这份激活就是流水线额外的显存负担。

代价是空等。 开工时后面的段没活干，收工时前面的段没活干。这和图 M10.6 里露在外面的那条尾巴是同一回事：流水线要先填满、最后要排空，这两段时间里总有人闲着。设每个 micro-batch 在每段上前向耗时 \(T_F\)、反向耗时 \(T_B\)，先不计通信，看最简单的调度（先做完全部前向，再做全部反向）。段的编号记作 \(i\)，micro-batch 的编号记作 \(j\)，都从 0 数：

流水线气泡的占比
(1)\(\displaystyle t_{i,j}=(i+j)\,T_F\)第 \(i\) 段第 \(j\) 个前向的开始时刻：要等上一段做完第 \(j\) 个、自己做完第 \(j-1\) 个；对 \(i+j\) 归纳，这两件事都在 \((i+j)T_F\) 做完
(2)\(\displaystyle t_{\text{前向完}}=(P-1+m)\,T_F\)最后一段（\(i=P-1\)）做完最后一个（\(j=m-1\)）
(3)\(\displaystyle t_{\text{总}}=(m+P-1)(T_F+T_B)\)最后一段做完前向后接着连做 \(m\) 个反向，到 \((P-1+m)T_F+mT_B\)；反向每往回传一段晚 \(T_B\)，与前向同理，第 0 段再晚 \((P-1)T_B\) 做完
(4)\(\displaystyle t_{\text{空}}=t_{\text{总}}-m(T_F+T_B)=(P-1)(T_F+T_B)\)每段真正在算的时间是 \(m(T_F+T_B)\)
流水线气泡\[\frac{\text{气泡}}{\text{总时长}}=\frac{(P-1)(T_F+T_B)}{(m+P-1)(T_F+T_B)}=\frac{P-1}{m+P-1}\]气泡的绝对大小 \((P-1)(T_F+T_B)\) 与 \(m\) 无关，只由段数和一个 micro-batch 的耗时决定；micro-batch 越多，它占的比例越小。GPipe 论文写作 \(O(\frac{K-1}{M+K-1})\)（\(K\) 段、\(M\) 个 micro-batch），并发现 \(M\ge4K\) 时气泡开销可以忽略 14。注意按 (M10.17)，\(m=4P\) 时占比是 \(\frac{P-1}{5P-1}\)，\(P\) 大时接近 20%，并不小；GPipe 自己的解释是，反向时的重算可以提前开始、填进一部分空档，所以“可以忽略”是它实验里的观察，不是这个公式的推论 14。(M10.17)
V3 的 16 段流水线

\(P=16\)：要让 (M10.17) 低于 10%，需要 \(15/(m+15)<0.1\)，即 \(m>135\)；按 GPipe 的 \(m=4P=64\)，气泡是 \(15/79=19\%\)。micro-batch 多了，每段就要同时存很多份激活；1F1B 调度（one forward, one backward：热身之后每段交替做一个前向、一个反向，一个 micro-batch 的反向做完就释放它的激活）把这份显存从 \(m\) 份降到约 \(P\) 份，但不改变气泡，Zero Bubble 与 V3 的 DualPipe 才进一步压缩气泡（第 12 课 §5–§6）。V3 用 16 段流水线 1；Insights 表 4 里标为 bubble 的一行是 2.06 秒，占一步的 10.3% 4（论文没有另行定义这一行，按字面读作气泡）。

专家并行：切专家

含义。 MoE 层有很多专家，把它们分到不同的卡上；每个 token 被送到它选中的专家所在的卡上计算（dispatch），算完再送回原来的卡（combine）。这一去一回各是一次 all-to-all。

类比：MoE = 医院，专家并行 = 科室分在不同的楼

映射。 token = 病人；专家 = 专科医生；一张卡 = 一栋楼；dispatch = 病人从大厅走到各科所在的楼；combine = 看完病带着结果回到大厅；节点 = 园区，跨园区要坐车（IB），园区内步行（NVLink）。

收益。 通信量取决于“每个病人要去几栋楼、要不要跨园区”，与医生多厉害无关。所以 V3 限制每个 token 至多去 4 个节点（第 11 课 §5的节点受限路由）：少坐几趟车，比什么都省。

失效的地方。 病人不能分身，token 却会被复制成 8 份同时去 8 个专家；而且“走路”的代价按字节算，隐藏状态用 FP8 还是 BF16 传，直接决定路费。

V3 训练时把每层 256 个路由专家放在 8 个节点、64 张卡上，每卡 4 个 1。

省下的显存。 对 MoE 模型，这一刀切下的是参数的大头。按 §1 的参数计数，一个路由专家有 44,040,192 个参数，一层 256 个就是 \(1.127\times10^{10}\) 个，58 层 MoE 合计约 654B，占 V3 全部 671B 参数的 97%（笔者按配置计算）。专家并行把每层的 256 个专家分到 64 张卡上，每张卡只存其中 4 个，这部分显存降到 1/64。

付出的通信。 token 要去找专家：每个 token 每过一层 MoE，都要把隐藏状态送到它选中的 8 个路由专家所在的卡上（至多 8 张），算完再送回来。这两次 all-to-all 要花多少时间，留给 §6 的 (M10.20) 和那里的两道例题。

集合通信的代价

先看一个会让人吓一跳的数。一个 7B 模型的 BF16 梯度是 14 GB。数据并行要把 1024 张卡上的梯度加起来。最直白的做法是“都发给 0 号卡，它加完再发回去”：0 号卡要收 1023 份、发 1023 份，经 50 GB/s 的网卡要 \(2\times1023\times14/50\approx573\) 秒，而一步计算可能只有几秒。实际系统用的环形 all-reduce 只要约 0.57 秒，而且卡数从 8 加到 1024，时间几乎不变。这一页推出它为什么这么快、为什么不可能更快，以及 MoE 的 all-to-all 又是什么代价。

代价模型与六种集合操作

α–β 模型。 沿用 (M10.7)：一条 \(S\) 字节的消息要 \(\alpha+S\beta\) 秒。Thakur 等人的分析还假设：时间与同时在通信的卡对数、与两卡之间的距离都无关；链路是双向的；每张卡的网卡“单端口”，同一时刻最多发一条、收一条；做归约时每字节另有计算代价 \(\gamma_{\mathrm{red}}\) 7。

集合操作（collective）是一组卡一起完成的通信。训练里用到的六种：

环形 all-gather 与 all-reduce

类比：围成一圈对账

映射。 \(p\) 个会计各有一本 \(p\) 页的账（每张卡的梯度，切成 \(p\) 块），目标是每人都拿到“所有人的账逐页相加”的总账。朴素做法是全交给组长，组长加完再复印 \(p\) 份发回去；环形做法是大家围成一圈，每一轮每人只把一页递给右手边的人，右边的人把它加到自己的同一页上，下一轮再往下递。

收益。 每一轮所有人同时在递、同时在收，没有人闲着，也没有哪一张桌子（网卡）堆成瓶颈。\(p-1\) 轮之后每人手里各有一页是全和（reduce-scatter），再转一圈把各自的全和页传给所有人（all-gather），每人一共只递出不到 2 本账的纸。

失效的地方。 真人递一页纸的时间几乎与纸上写了多少字无关，网卡传一块数据的时间却与字节数成正比，所以页切得越薄、每轮越快。反过来，轮数 \(2(p-1)\) 随人数线性增长：人很多、每页很薄时，“递”这个动作本身的固定开销 \(\alpha\) 就成了主角，这是本页后面“延迟项”一节要说的事。

把 \(p\) 张卡排成一个环，每张卡只和右邻发、和左邻收。消息共 \(S\) 字节，切成 \(p\) 块，每块 \(S/p\)。

环形 all-gather
(1)\(\displaystyle \text{第 1 步：卡 }i\text{ 把自己那块发给卡 }i+1\)同时从卡 \(i-1\) 收一块；每张卡发、收各 \(S/p\)
(2)\(\displaystyle \text{第 }k\text{ 步：把上一步收到的那块转发给右邻}\)每一步环上流动的都是“还没到过右邻的那一块”
(3)\(\displaystyle p-1\ \text{步后每张卡收齐 }p-1\text{ 块}\)自己那块本来就有
(4)\(\displaystyle T_{\text{AG}}=(p-1)\Big(\alpha+\dfrac{S}{p}\beta\Big)=(p-1)\alpha+\dfrac{p-1}{p}S\beta\)每步每张卡发一条 \(S/p\) 字节的消息，所有卡同时进行

它的带宽项不可能更小：每张卡都必须从别人那里收到 \(\frac{p-1}{p}S\) 字节，而网卡每秒最多收 \(1/\beta\) 字节 7。reduce-scatter 用同样的环，只是收到的块要加到自己那块上再传，所以多一项计算。把两步相加：

环形 all-reduce
(1)\(\displaystyle T_{\text{RS}}=(p-1)\alpha+\dfrac{p-1}{p}S\beta+\dfrac{p-1}{p}S\gamma_{\mathrm{red}}\)reduce-scatter：\(p-1\) 步，每步发 \(S/p\)、加 \(S/p\)；结束时每张卡有一块完整的和
(2)\(\displaystyle T_{\text{AG}}=(p-1)\alpha+\dfrac{p-1}{p}S\beta\)all-gather：把加好的块沿环传一圈
(3)\(\displaystyle T_{\text{ring}}=T_{\text{RS}}+T_{\text{AG}}\)(M10.18)
环形 all-reduce 的代价\[T_{\text{ring}}=2(p-1)\,\alpha+\frac{2(p-1)}{p}\,S\beta+\frac{p-1}{p}\,S\gamma_{\mathrm{red}}\]Thakur 等人 §5.3 给出同一个代价（他们的实现在 reduce-scatter 一步用成对交换、在 all-gather 一步走环，代价与纯环相同）7。每张卡一共发出 \(\frac{2(p-1)}{p}S\) 字节：\(p=2\) 时 \(S\)，\(p=8\) 时 \(1.75S\)，\(p\to\infty\) 时趋于 \(2S\)。(M10.19)

为什么不可能更省：带宽下界

环形算法让每张卡发 \(\frac{2(p-1)}{p}S\)。Patarasuk 与 Yuan 证明了这已经是下界：在“不压缩、各元素相互独立”的条件下，对单个元素做 all-reduce 至少要通信 \(2(p-1)\) 次部分结果（引理 3）；对 \(X\) 个元素，至少有一张卡要通信 \(\lceil\frac{2(p-1)}{p}X\rceil\) 个元素的字节（引理 4；原文把卡数记作 \(N\)，这里换成本课的 \(p\)，以免与参数量混淆）15。下面是笔者给的直观版本：

带宽下界的直观论证
(1)\(\displaystyle \text{一个元素的全和要汇集 }p\text{ 份贡献}\)每张卡的那一份都不同，缺一不可
(2)\(\displaystyle \text{传输按时间排成一列}\)同时发生的传输任意定个先后；每次传输只改变接收方这一张卡的内容
(3)\(\displaystyle \text{第一张卡拿到全和时：已}\ \ge p-1\ \text{次}\)每次传输在收发两张卡之间连一条线。贡献只能沿这些线流动，所以某张卡含全部 \(p\) 份贡献时，\(p\) 张卡已连成一片；一开始是 \(p\) 片，一条线最多把两片连成一片，至少要 \(p-1\) 条
(4)\(\displaystyle \text{此后：再}\ \ge p-1\ \text{次}\)那一刻只有这一张卡有全和（那次传输只改变了它）；其余 \(p-1\) 张卡各自至少还要收一次，每次传输最多让一张新卡拿到全和
(5)\(\displaystyle X\text{ 个元素共 }\ge2(p-1)X\text{ 次，摊到 }p\text{ 张卡的出口}\)不压缩、元素相互独立：每个元素各自至少传 \(2(p-1)\) 次部分结果，每传一次占一个元素的字节。平均每张卡发出 \(\ge\frac{2(p-1)}{p}X\) 个元素的字节，所以至少有一张卡不少于这个数

注意引理说的是“至少有一张卡”，不是“每张卡”；环形算法让每一张卡都恰好发这么多，负载完全均衡，所以它在带宽意义下是最优的。

延迟项：卡多了之后的另一面

(M10.19) 的带宽项几乎与 \(p\) 无关，延迟项 \(2(p-1)\alpha\) 却随 \(p\) 线性增长：1024 张卡要走 2046 步。递归减半–倍增（recursive halving and doubling）换了一种配对方式：reduce-scatter 阶段第 1 步两两配对（0 号与 1 号、2 号与 3 号……），每对互相发送自己缓冲区的一半（0 号发后一半、收前一半），收到的那一半加到自己没发出去的那一半上；之后每一步配对的距离加倍、交换的数据减半，\(\lg p\) 步后每张卡得到一块全和；all-gather 阶段按相反的顺序走，每步数据量加倍 16。它只要 \(2\lg p\) 步，带宽项不变（为什么不变，见 §8 练习 12），代价是 \(2\lg p\,\alpha+\frac{2(p-1)}{p}S\beta+\frac{p-1}{p}S\gamma_{\mathrm{red}}\)（\(p\) 为 2 的幂）7。Goyal 等人报告，缓冲区在约一百万个元素以内时（服务器多时这个界限更高）减半–倍增明显优于环；在 32 台服务器（256 张 GPU）上，它比环快 3 倍 16。

14 GB 梯度的 all-reduce

（a）一个节点内 8 张卡，NVLink 160 GB/s：带宽项 \(1.75\times14/160=0.153\) s，延迟项 \(14\times5\ \mu\text{s}=70\ \mu\text{s}\)，可以忽略。

（b）1024 张卡，IB 50 GB/s：带宽项 \(1.998\times14/50=0.560\) s，延迟项 \(2046\times5\,\mu\text{s}=10.2\) ms，合计约 0.57 s。

（c）对照朴素做法：\(p=8\) 时 0 号卡要先收 \(7S\) 字节、加完才能再发 \(7S\) 字节，两段只能先后进行，传输时间是 \(2\times7\times S\beta=14S\beta\)；环形算法每卡同时发、收各 \(1.75S\)，时间 \(1.75S\beta\)，快 8 倍。

“环形 all-reduce 的时间与卡数无关”

只有带宽项趋于常数 \(2S\beta\)；延迟项 \(2(p-1)\alpha\) 随卡数线性增长。消息大时前者主导，所以大模型的梯度同步“看起来”与卡数无关；消息小（例如张量并行里每层的激活、MoE 里每个专家的一小批 token）时，延迟会变成主角。

all-to-all

含义。 每张卡手里都有发给其余每张卡的一块各不相同的数据，all-to-all 之后每张卡收齐发给自己的各块。把第 \(i\) 张卡发给第 \(j\) 张卡的块记作 \((i\to j)\)，排成 \(p\times p\) 的块矩阵，all-to-all 就是把它转置。

数学。 成对交换的代价是

all-to-all 的代价\[T_{\text{a2a}}=(p-1)\,\alpha+S\beta\]\(S\) 是每张卡要发给其余所有卡的字节总数 7。它与 all-reduce 的根本区别：没有可以合并的东西，每个字节都得原样送到，\(S\) 由任务本身决定（多少 token、复制几份、每份几字节）。要送走的每个字节至少离开本卡一次，所以任何算法都不能把带宽项压到 \(S\beta\) 以下，只能在延迟项上做取舍：短消息用的 Bruck 算法只要 \(\lg p\) 步，代价是带宽项涨到 \(\frac S2\lg p\,\beta\)（\(p\) 为 2 的幂时）7。(M10.20)
V3 解码速度的上界：all-to-all 至少要多久

Insights 论文按“字节 ÷ 带宽”给 V3 的解码速度估了一个上界，这正是 (M10.20) 的带宽项，论文注明不计网络延迟 4：每张卡只放一个专家、一次约处理 32 个 token，每个 token 发往 9 个专家（8 个路由 + 1 个共享），隐藏维约 7K；dispatch 用 FP8（1 字节）、combine 用 BF16（2 字节），经 50 GB/s 的 IB，dispatch 与 combine 两次 all-to-all 合计：

\[\frac{(1+2)\ \text{字节}\times32\times9\times7000}{50\ \text{GB/s}}=120.96\ \mu\text{s}.\]

在“两个 micro-batch 互相重叠、计算完全藏在通信后面”的理想假设下，每层是两轮通信 241.92 µs，61 层共 14.76 ms，也就是每条请求每秒最多生成约 67 个 token；换成 GB200 NVL72 的 900 GB/s，同一式子是 6.72 µs、0.82 ms、每秒约 1200 个 token 4。论文把 7K 按 7000 代入；用实际的 7168，第一个数是 123.86 µs。

专家并行的“通信强度”（笔者估算）

训练时一个 token 过一层 MoE（前向），计算约是 \(2\times(9\times44.04+187.1+1.8)\times10^6\approx1.17\) GFLOPs（9 个专家、MLA 的投影与门控，参数见 §1；不计注意力打分）。节点受限时跨 IB 的字节至多 \(4\times(7392+14{,}336)=86{,}912\)（dispatch 的 7392 字节含 56 个 FP32 缩放因子，见图 M10.11；第 12 课 §7 的算例不计缩放因子，得 86,016，差 1%）。两者之比约 13,500 FLOP/字节，低于 IB 的链路脊点 19,800：不重叠的话，这一层的 IB 通信时间约是计算时间的 1.5 倍（\(19{,}800/13{,}500\approx1.47\)）。这里只算了前向；反向的运算约是前向的 2 倍，梯度也要沿同样的路线送去、送回一遍，整个训练步的比值会高一些，但仍在 IB 脊点的同一量级。V3 报告自己的说法是，跨节点专家并行让计算与通信之比约为 1:1 1，两者在同一量级。所以 V3 必须把 all-to-all 藏进另一个 micro-batch 的计算里，这就是 DualPipe 的出发点（第 12 课 §6）。

概念题

练习 1 · batch 能救什么

decode 时把 batch 从 1 加到 64，线性层的强度与 MHA 注意力的强度各怎么变？为什么？

看答案

线性层：64 条序列共用一次读进来的权重，相当于 \(m=64\) 的矩阵乘法，由 (M10.9) 强度约从 1 升到 63（BF16）。注意力：每条序列只读自己的 KV cache，多一条序列就多一份运算、也多一份字节，比值不变，MHA 始终约为 1。batch 摊薄的只是共享的数据。

练习 2 · MFU 与 HFU

（a）同一次训练，打开激活重算后，MFU 与 HFU 哪个会变？哪个更大？（b）V3 用 FP8 做矩阵乘法，Insights 却按 BF16 峰值报告 38.94% 的 MFU。若改按 FP8 峰值计算，这个数会变大还是变小？

看答案

（a）MFU 的公式里没有重算这一项：分母是峰值，分子是“吞吐 × 每 token 本来就需要的运算”。在 batch 等其他设置不变时，重算让硬件多做一部分前向，却不会让吞吐（token/s）提高，通常还会拖慢一点，所以 MFU 不变或略降，不会因此变大。（重算省下的显存若被拿去加大 batch、换来更高的吞吐，MFU 可能上升，但那已经换了配置。）HFU 的分子把重算的运算也算进去，所以打开重算后 HFU 大于 MFU。PaLM 540B 就是 MFU 46.2%、HFU 57.8% 2。（b）变小：分子（按公式数出的有用运算）不变，分母换成更高的 FP8 峰值。

练习 3 · 哪种并行能跨节点

用 (M10.16) 和 §5 的数据并行强度 \(1.5b\) 解释：为什么张量并行一般只放在节点内，而数据并行可以跨节点？

看答案

张量并行每 token 的通信强度 \(4.5d/(p-1)\) 与 batch 无关，\(d=7168\)、\(p=8\) 时只有 4608，已低于 NVLink 的链路脊点（约 6190），跨 IB（约 19,800）差得更远。数据并行的强度 \(1.5b\) 随每卡每步的 token 数 \(b\) 增长，\(b\) 取几万时就超过 IB 的脊点，而且每步只通信一次、可以和反向重叠。

计算题

练习 4 · GPT-2 small 的训练账

GPT-2 small：12 层，\(d=768\)，12 个头（\(d_h=64\)），FFN 中间维 \(4d\)，词表 50,257（输出头与嵌入共享权重，但输出头的矩阵乘法照样要算），序列长 1024。按 (M10.3) 求每个训练 token 的运算量，以及注意力项所占的比例。

看答案

每层矩阵参数 \(12d^2=7{,}077{,}888\)，12 层共 84,934,656；输出头 \(768\times50{,}257=38{,}597{,}376\)。\(N_{act}=123{,}532{,}032\)，\(6N_{act}=741.2\) MFLOPs。

注意力项：\(6\times12\times12\times(64+64)\times512=56{,}623{,}104\approx56.6\) MFLOPs（因果掩码下 \(\bar t\approx512\)）。

合计约 797.8 MFLOPs/token，注意力占 7.1%。

练习 5 · 屋顶线上的专家

V3 的专家上投影（\(k=7168\)，\(n=2048\)）每次分到 \(m=128\) 个 token，BF16。（a）强度是多少？（b）在 A100 与 H800 上各能跑多快、占峰值多少？（c）在 H800 上这次乘法的时间下界是多少？

看答案

（a）\(I=1/(\frac1{128}+\frac1{2048}+\frac1{7168})=1/0.0084403=118.5\) FLOP/字节。

（b）A100：\(2.039\times118.5=241.6\) TFLOP/s，受带宽限制，为峰值的 77%；H800：\(3.35\times118.5=396.9\) TFLOP/s，为峰值的 40%。同一个强度，脊点越高的卡越“吃亏”。

（c）字节 \(2\times(128\times7168+7168\times2048+128\times2048)=31{,}719{,}424\)，\(t_{\text{搬}}=9.47\) µs；运算 \(2\times128\times2048\times7168=3.758\times10^9\)，\(t_{\text{算}}=3.80\) µs。下界 9.47 µs。

练习 6 · ZeRO 的通信

一个 7B 模型（BF16 梯度 14 GB）在 64 张卡上做数据并行，全部经 IB（50 GB/s），用环形算法，忽略延迟。（a）标准数据并行每步梯度同步要多久？（b）换成连参数也切开的 ZeRO-3 呢？

看答案

（a）每卡发 \(\frac{2\times63}{64}\times14=27.56\) GB，\(27.56/50=0.551\) s。

（b）ZeRO-3 的通信量是 \(3N\)，为标准的 1.5 倍 12：约 \(0.551\times1.5=0.827\) s。换来的是每卡的模型状态从 112 GB 降到 \(112/64=1.75\) GB。

练习 7 · 16 段流水线

\(P=16\)，按 (M10.17)：（a）\(m=32\)、64、128 时气泡各占多少？（b）要压到 5% 以下，至少要多少个 micro-batch？

看答案

（a）\(15/47=31.9\%\)，\(15/79=19.0\%\)，\(15/143=10.5\%\)。

练习 9 · GQA 与 MQA 的解码注意力

一个模型的注意力有 \(n_h=32\) 个查询头、\(d_h=128\)，KV cache 用 BF16。decode 时某条序列已有 8192 个 token。（a）若用 GQA，\(n_g=8\)：生成一个新 token 时，一层注意力要读多少字节、做多少次运算、强度是多少？（b）在 H800 上它受什么限制？这一层注意力至少要多久？（c）改成 MQA（\(n_g=1\)）呢？

看答案

（a）每个缓存 token、每个 KV 头读 \(4d_h=512\) 字节，共 \(8192\times8\times512=33{,}554{,}432\) 字节（约 33.6 MB）。每个查询头对每个缓存 token 做 \(4d_h=512\) 次运算，共 \(8192\times32\times512=1.342\times10^8\) 次。强度 \(I=1.342\times10^8/3.355\times10^7=4=n_h/n_g\)。

（b）\(4\ll295.5\)，受带宽限制。\(t_{\text{搬}}=3.355\times10^7/3.35\times10^{12}=10.0\) µs，\(t_{\text{算}}=1.342\times10^8/990\times10^{12}=0.14\) µs，下界约 10 µs，算力只用上了约 1.4%。

（c）MQA：字节降到 \(8192\times1\times512=4{,}194{,}304\)（约 4.2 MB），运算不变，强度 32，时间下界约 1.25 µs，快 8 倍；仍在脊点左边，所以仍受带宽限制。要接近脊点，得像 V3 的 MLA 那样让一份缓存被全部 128 个头共用：§3 算出它的强度是 241.8，已贴近 295.5，但仍在脊点左边。

练习 10 · 数据并行什么时候能把通信藏起来

每张卡每步处理 \(b\) 个 token，稠密模型 \(N\) 个参数（每个参数都参与每个 token 的计算），BF16 梯度用环形 all-reduce 同步。（a）推导“每字节通信对应的运算” \(\approx1.5b\)。（b）若要梯度同步的时间不超过这一步的计算时间，\(b\) 至少要多大？代入 \(F=990\) TFLOP/s、IB 50 GB/s。

看答案

（a）运算：由 (M10.2)，每 token \(6N\) 次，共 \(6Nb\)。通信：梯度 \(2N\) 字节，环形 all-reduce 每卡发 \(\frac{2(p-1)}{p}\times2N\approx4N\) 字节。比值 \(6Nb/4N=1.5b\)。

（b）要 \(\frac{4N}{\mathrm{BW}}\le\frac{6Nb}{F}\)，即 \(1.5b\ge F/\mathrm{BW}\)，\(b\ge\frac{F}{1.5\,\mathrm{BW}}=\frac{990\times10^{12}}{1.5\times50\times10^9}=13{,}200\) 个 token。每卡每步 30,720 个 token（V3 的平均数）的稠密模型满足这个条件。这是只看带宽项、并按稠密模型（每个参数都参与每个 token 的计算，全部参数都走数据并行）的粗算；V3 是 MoE，又有流水线并行与专家并行，要按它的实际切法算，结果比这里宽松得多（见 §5 的例题）。

练习 11 · 为什么不用“树”做 all-reduce

一种直观的 all-reduce：先用二项树把 \(p\) 份 \(S\) 字节的梯度归约到 0 号卡（每一轮配对的两张卡中一张把整份 \(S\) 发给另一张，\(\lg p\) 轮），再用二项树把结果广播回去（同样 \(\lg p\) 轮）。（a）推导它的带宽项。（b）与环形算法比，\(p=1024\) 时差几倍？

看答案

（a）每一轮都要传完整的 \(S\) 字节，归约与广播各 \(\lg p\) 轮，带宽项 \(2\lg p\cdot S\beta\)。Thakur 等人给出的二项树归约正是 \(\lceil\lg p\rceil(\alpha+S\beta+S\gamma_{\mathrm{red}})\) 7。

（b）\(p=1024\)：树 \(2\times10\times S\beta=20S\beta\)，环 \(\frac{2\times1023}{1024}S\beta\approx2S\beta\)，差约 10 倍。树的每一轮至多一半的卡在发数据（第一轮一半，以后逐轮减半），而且每次都发完整的一份；环让每张卡在每一步都只发 \(S/p\)、而且所有卡同时在发。树的优点在延迟项（\(2\lg p\) 步），所以它适合小消息。

练习 12 · 减半–倍增的带宽项

§6 的递归减半–倍增：reduce-scatter 阶段第 1 步每张卡与相邻编号的卡交换 \(S/2\) 字节并相加，第 2 步与相距 2 的卡交换 \(S/4\)，第 3 步与相距 4 的卡交换 \(S/8\)，……共 \(\lg p\) 步；all-gather 阶段倒过来，每步交换的量依次是 \(S/p,\ 2S/p,\ \dots,\ S/2\)。（a）推导每张卡一共发出多少字节，说明带宽项与环形算法相同。（b）取 \(p=1024\)、\(S=1\) MB（\(10^6\) 字节）、\(\alpha=5\) µs、50 GB/s，两种算法各要多久？

看答案

（a）reduce-scatter 阶段发出 \(\frac S2+\frac S4+\dots+\frac Sp\)。这是首项 \(\frac S2\)、公比 \(\frac12\) 的等比数列，共 \(\lg p\) 项，和为 \(\frac S2\cdot\frac{1-(1/2)^{\lg p}}{1-1/2}=S\big(1-\frac1p\big)=\frac{p-1}{p}S\)。all-gather 阶段是同样几项倒过来相加，也是 \(\frac{p-1}{p}S\)。合计 \(\frac{2(p-1)}{p}S\)，与 (M10.19) 的带宽项相同，Goyal 等人也写明两种算法每台服务器收发的字节数相同 16。步数是 \(2\lg p\)，所以延迟项是 \(2\lg p\,\alpha\) 7。

（b）两者的带宽项都是 \(\frac{2\times1023}{1024}\times10^6/(50\times10^9)\) 秒，约 40 µs。环：延迟 \(2\times1023\times5=10{,}230\) µs，合计约 10.27 ms。减半–倍增：延迟 \(2\times10\times5=100\) µs，合计约 0.14 ms。这就是图 M10.10 右图 1024 张卡处的两个数。
