第 7 课 · DeepSeekMoE：细粒度专家与共享专家

一个 7B 稠密模型里，接近六成的参数在前馈层（FFN），而且每个 token 都要把它们从头算到尾。混合专家（MoE）让每个 token 只动用其中一小部分：参数可以很多，计算却不跟着涨。DeepSeekMoE 在这个老想法上改了两处：把专家切得更细，再隔离出几个每个 token 都要经过的共享专家。这一课从门控公式讲起，逐项推导负载均衡损失，把“切细”换来了什么、又花掉了什么算清楚。

这一课回答什么问题

第 6 课的 DeepSeek LLM 是稠密（dense）模型：每生成一个 token，67B 个参数全部参与计算。想让模型记住更多知识，就得加参数；加了参数，每个 token 的计算量就同比例上涨。这一课要回答的问题是：能不能让参数总量和每个 token 的计算量脱钩？ 如果能，代价是什么？

答案是混合专家（mixture of experts, MoE）：把前馈层换成许多个小前馈网络（“专家”），再用一个路由器（router）为每个 token 挑出其中几个来算。2024 年 1 月，DeepSeek 发表 DeepSeekMoE 1，在传统 MoE 上做了两处改动，后来的 DeepSeek-V2、V3、V4 的 MoE 层都沿用这套结构。读完这一课，下面这些问题你都能自己回答：

  • 一个稠密模型的参数为什么大半在 FFN？MoE 省的究竟是什么，不省什么？
  • 路由器怎样给专家打分？“先 softmax 再取 top-k”和“先取 top-k 再 softmax”有什么区别？
  • 为什么 MoE 训练会“坍缩”到少数几个专家？负载均衡损失 \(\alpha N\sum_i f_iP_i\) 为什么长这样，它的梯度往哪个方向推？
  • 把 16 个专家切成 64 个、每次激活 8 个，参数和计算都没变，那到底变了什么？4,426,165,368 这个数是怎么来的？
  • 共享专家解决什么问题？专家级和设备级两种均衡损失各管什么？
  • DeepSeekMoE 16B 用约 40% 的计算追平 7B 稠密模型，这个“40%”是哪两个数之比？

这一课在科技树上的位置

这是主线 B “前馈层的稀疏化”的第一课。上一课（第 6 课）用规模化规律回答了“给定算力，模型该多大、数据该多少”，但它默认了一件事：模型越大，每个 token 就越贵。本课打破这个默认。后面三课接着这条线往下走：第 10 课讲 DeepSeek-V2 怎样把 DeepSeekMoE 放大到 160 个路由专家，并用设备受限路由和通信均衡损失控制跨卡通信；第 11 课讲 DeepSeek-V3 如何主要靠一个只管路由的偏置、而不是辅助损失来做负载均衡；第 18 课讲 V4。本课的公式、记号和两个核心设计，是这三课的共同地基。

FFN 的账单与条件计算

先看一张账单。上一课的 DeepSeek LLM 7B 有 30 层、隐藏维度 \(d=4096\)、FFN 中间维度 \(d_{ff}=11008\)、词表 102,400 2,3。它的 69 亿个参数分别放在哪里？每生成一个 token，哪些参数要参与计算？这两个问题的答案决定了 MoE 值不值得做。

FFN 占了多少参数

SwiGLU 前馈层读过第 5 课的可以跳过

第 1 课的 GPT 前馈层是“升维、激活、降维”两个矩阵。LLaMA 式模型（包括 DeepSeek 全系）用的是 SwiGLU（第 5 课）：三个矩阵 \(W_1,W_3\in\R^{d_{ff}\times d}\) 与 \(W_2\in\R^{d\times d_{ff}}\)，

\[\FFN(\mathbf u)=W_2\big(\mathrm{SiLU}(W_1\mathbf u)\odot W_3\mathbf u\big),\]

其中 \(\odot\) 是逐元素乘法，\(\mathrm{SiLU}(x)=x\cdot\sigma(x)\)。本课只需要记住两件事：它有 \(3dd_{ff}\) 个参数；它的计算可以按中间维度的 \(d_{ff}\) 个“神经元”拆开来看（§5 会用到）。第 5 课 §5 讲了为什么是三个矩阵、为什么中间维取 \(\tfrac83d\) 左右。

一层 Transformer 块的参数几乎全在两处：注意力的四个投影矩阵 \(W^Q,W^K,W^V,W^O\)（多头注意力下每个都是 \(d\times d\)），以及 FFN 的三个矩阵。归一化层的参数只有几千个，可以忽略。

一层的参数：FFN 与注意力\[\underbrace{3\,d\,d_{ff}}_{\text{FFN（SwiGLU）}}\qquad\text{vs.}\qquad\underbrace{4\,d^2}_{\text{注意力（MHA）}}\]两者之比是 \(3d_{ff}/(4d)\)。LLaMA 式模型的 \(d_{ff}\approx\tfrac83d\)，代进去得到约 \(2\)：FFN 的参数是注意力的两倍。(7.1)
DeepSeek LLM 7B 每层的参数
(1)\(\displaystyle 4d^2=4\times4096^2=67{,}108{,}864\)注意力：\(W^Q,W^K,W^V,W^O\) 各 \(4096\times4096\)（7B 是标准多头注意力，没有分组）
(2)\(\displaystyle 3dd_{ff}=3\times4096\times11008=135{,}266{,}304\)FFN：\(W_1,W_3\) 各 \(11008\times4096\)，\(W_2\) 是 \(4096\times11008\)
(3)\(\displaystyle \dfrac{135{,}266{,}304}{135{,}266{,}304+67{,}108{,}864}=0.668\)FFN 占每层参数的 66.8%
(4)\(\displaystyle 30\times(67.1\text{M}+135.3\text{M})=6.071\text{B}\)30 层合计；再加输入嵌入与输出头各 \(102400\times4096=0.419\)B，总数 6.910B，与论文的 6.9B 一致

稠密模型的两难

问题。 第 1 课推导过：一个稠密模型前向处理一个 token，大约要做 \(2N\) 次浮点运算，\(N\) 是参数量（每个参数一次乘法、一次加法）；第 2 课由此得到训练总算力 \(C\approx6ND\)。这条关系把两件本该分开的事绑在了一起：

  • 容量：模型能记住多少知识，大致随参数量增长。第 1 课介绍过把 FFN 看成“键值记忆”的观点：模型记住的事实性知识，很大一部分存在 FFN 的参数里。
  • 成本：每个 token 的计算量，同样随参数量增长。

想要十倍的知识容量，就得付十倍的单 token 计算。更糟的是这份计算大部分是浪费：一个关于 Python 语法的 token，也要把存着法律条文、化学方程式的那些 FFN 参数原样乘一遍。

图景。 能不能让每个 token 只“查阅”和它有关的那部分参数？这就是条件计算（conditional computation）的想法。

含义。 条件计算：网络的哪一部分参与计算，取决于输入本身。不同的输入走不同的子网络。

理解。 稠密网络像一本每次都要从头读到尾的书；条件计算像一本带目录的百科全书：先查目录，只翻开相关的几页。书可以很厚（总参数多），每次阅读的页数却固定（激活参数少）。

数学。 把每个 token 实际参与计算的参数量记作 \(N_{act}\)（激活参数），总参数量记作 \(N_{total}\)：

条件计算的账单\[\text{每 token 前向 FLOPs}\approx 2N_{act},\qquad \text{知识容量}\sim N_{total},\qquad N_{act}\ll N_{total}\]稠密模型 \(N_{act}=N_{total}\)。“知识容量随 \(N_{total}\) 增长”是经验规律，不是定理；§8 会看到它在 DeepSeekMoE 上的实测证据。第 6 课用每 token 非嵌入 FLOPs \(M\) 做更精确的记账，这里粗略的 \(2N_{act}\) 就够用。(7.2)
同样约 3B 的计算，存得下多少参数

DeepSeekMoE 16B 由它的配置复算得总参数 16,375,728,128、每 token 激活参数 2,828,650,496（含输入嵌入和输出头）6。按 (7.2)，它每个 token 的前向计算约 \(2\times2.83\text{B}=5.66\) GFLOPs，和一个 2.8B 的稠密模型相当（严格说，输入嵌入只是查表、不做乘加，去掉它的 0.21B 是 \(2\times2.62\text{B}\approx5.24\) GFLOPs；同样口径下稠密模型也要去掉嵌入，比较结论不变），存着的参数却是 16.4B，是 5.8 倍。

Mixtral 8x7B 由配置复算得总参数 46.70B、激活参数 12.88B 5（论文写作 47B 与 13B 8），激活比例 27.6%。它的名字容易让人以为有 \(8\times7=56\)B 参数，但注意力层和嵌入是所有专家共用的，只有 FFN 被复制了 8 份。

MoE 省的是计算，不是显存

(7.2) 里的 \(N_{act}\) 只决定计算量。推理时所有专家的参数都必须放在显存（或至少是能快速取到的地方）里，因为下一个 token 可能用到任何一个专家。16.4B 的模型用 BF16 存储要 \(16{,}375{,}728{,}128\times2\approx32.75\) GB，这个账一分都不会少。MoE 把“计算墙”往后推了，“显存墙”原地不动。

一段简短的历史

MoE 不是新想法，但它最初想解决的问题并不是省算力。

1991 年：为了减少干扰。 Jacobs、Jordan、Nowlan 与 Hinton 的出发点是：用一个网络同时学好几个子任务，这些任务会互相干扰，学得慢、泛化差 9。他们让几个“专家”网络并列，由一个门控网络（gating network）用 softmax 给出每个专家的混合比例 \(p_i\)。这时所有专家都要计算，是稠密的混合。论文真正的贡献在误差函数，它先后比较了三种写法（\(\mathbf d\) 是目标输出，\(\mathbf o_i\) 是专家 \(i\) 的输出）：

  1. 先混合再算误差 \(\norm{\mathbf d-\sum_ip_i\mathbf o_i}^2\)（论文式 (1.1)）：每个专家只需补上别人留下的残差，专家之间“合作”，结果每个样本由好几个专家分摊。
  2. 随机挑一个专家，算期望误差 \(\sum_ip_i\norm{\mathbf d-\mathbf o_i}^2\)（式 (1.2)）：想象门控每次只随机选一个专家、由它独自给出完整输出，专家之间转为“竞争”，系统倾向于把每个样本交给一个专家。
  3. 负对数混合高斯似然 \(-\log\sum_ip_i\,e^{-\frac12\norm{\mathbf d-\mathbf o_i}^2}\)（式 (1.3)）：论文实际使用的写法，它让最合适的专家学得最快，下面的例题说明为什么。
1991 年的“专精”是怎样发生的

两个专家，门控给出相等的比例 \(p=(0.5,0.5)\)。对某个训练样本，专家 1 的输出离目标的距离是 \(\norm{\mathbf d-\mathbf o_1}=1.5\)，专家 2 是 \(3.0\)。

按写法 2，误差对专家 \(i\) 输出的梯度是 \(-2p_i(\mathbf d-\mathbf o_i)\)（论文式 (1.4)），大小 \(2p_i\norm{\mathbf d-\mathbf o_i}\)，即 \((1.5,\ 3.0)\)：差的专家被推得更狠，两个专家都向这个样本靠拢，谁也不会退出。

按写法 3，梯度是 \(-r_i(\mathbf d-\mathbf o_i)\)（式 (1.5)），其中的“后验责任”

\[r_i=\frac{p_i\,e^{-\frac12\norm{\mathbf d-\mathbf o_i}^2}}{\sum_jp_j\,e^{-\frac12\norm{\mathbf d-\mathbf o_j}^2}}\]

表示“这个样本有多大可能是专家 \(i\) 生成的”。代入得 \(r_1=1/(1+e^{-(4.5-1.125)})=0.9669\)、\(r_2=0.0331\)，梯度大小变成 \((0.9669\times1.5,\ 0.0331\times3.0)=(1.4504,\ 0.0993)\) 9。现在是好的专家学得快，差的那个几乎不动，于是这个样本逐渐“归”专家 1 所有。论文的说法是：在门控初始给各专家相等权重、且各专家误差都大于 1 的前提下，式 (1.4) 让最合适的专家学得最慢，式 (1.5) 让它学得最快。“误差大于 1”这个前提从哪里来，可以自己验证：记 \(\epsilon_i=\norm{\mathbf d-\mathbf o_i}\)，等权时 \(r_i\) 的分母对所有专家相同，所以 (1.5) 的梯度大小正比于 \(\epsilon_ie^{-\epsilon_i^2/2}\)；它对 \(\epsilon_i\) 的导数是 \((1-\epsilon_i^2)e^{-\epsilon_i^2/2}\)，只有在 \(\epsilon_i>1\) 时为负，也就是只有这时“误差越小、梯度越大”。(1.4) 的梯度大小 \(2p_i\epsilon_i\) 则对任何误差都随 \(\epsilon_i\) 增大。在他们的元音分类实验里，4 个或 8 个专家的混合达到误差标准所需的轮数，约为普通反向传播网络的一半（1124、1083 轮 vs 2209、2435 轮）。

2017 年：稀疏门控，为了容量。 Shazeer 等人把 MoE 改成稀疏的：门控只保留得分最高的 \(k\) 个专家，其余专家根本不算 10。这样专家可以多到数千个（最大的实验用层级门控做到 131,072 个），模型容量扩大一千倍以上而计算几乎不变。他们的 MoE 层插在堆叠的 LSTM 层之间（还不是 Transformer），最大的 MoE 层有 1370 亿参数。

2020–2022 年：进入 Transformer。 GShard 把 Transformer 里每隔一层的 FFN 换成 top-2 MoE，训练出 6000 亿参数的翻译模型 11；Switch Transformer 证明每个 token 只选 1 个专家也行，做到 1.6 万亿参数 12。

2024 年 1 月：两条路线。 两篇开源 MoE 的论文在同一周挂上 arXiv：Mixtral 在 1 月 8 日，DeepSeekMoE 在 1 月 11 日（Mixtral 8x7B 的权重更早，2023 年 12 月 11 日就以 Apache 2.0 许可公开了 13）。Mixtral 8x7B 沿用“少而大”的专家：每层 8 个大专家选 2 个 8。DeepSeekMoE 走了另一条路：更多、更小的专家，外加共享专家 1。本课的后半部分就是在解释这条路为什么这样走。

类比：MoE = 医院

映射。 一个 token = 一位病人；FFN 专家 = 专科医生；路由器 = 分诊台，看一眼病人就决定挂哪几个科；top-\(k\) = 每位病人最多挂 \(k\) 个号；门控值 = 各科医生意见的权重（最后的诊断是这几位意见的加权综合）；稠密 FFN = 一位什么病都看的全能大夫，每位病人都要从头问到尾。本课后面还会用到三处：细粒度切分 = 把“内科”拆成心内、消化、呼吸……；共享专家 = 每位病人都要先看的全科医生；负载均衡 = 别让所有病人都挤到同一个科室。

收益。 它让条件计算的账一目了然：医院可以养很多医生（总参数），每位病人只占用少数几位的时间（激活参数）；它也预告了 MoE 的两个麻烦：分诊台会不会偏心（负载不均），科室分得太粗会不会什么病都得看（知识混杂）。

失效的地方。 分诊是按 token 进行的：同一句话里的每个词都单独分诊，可能去完全不同的科室，而真实医院里一位病人是一个整体。另外，医院的科室是人为规定的，MoE 的“专科”是训练中自发形成的，没有人告诉专家 3 该管什么，训练完也未必能说出它管的是什么。

本页要点
  • 稠密 LLaMA 式模型的每一层里，FFN 参数（\(3dd_{ff}\)）约是注意力（\(4d^2\)）的 2 倍；DeepSeek LLM 7B 有 58.7% 的参数在 FFN。
  • 稠密模型每 token 计算 \(\approx2N\)，容量和成本被绑在一起。条件计算让每 token 只用 \(N_{act}\) 个参数，二者脱钩；但显存仍要装下全部 \(N_{total}\)。
  • MoE 的起源（1991）是减少干扰、促成专精；稀疏门控（2017）才把它变成扩大容量的工具。DeepSeekMoE 的论文标题 “Towards Ultimate Expert Specialization” 又回到了“专精”这个起点。

MoE 层：路由、top-k 与容量

上一页说“让每个 token 只用一部分参数”。这一页把它落到公式上：一个 MoE 层由哪些零件组成，一个 token 进来后经过哪几步计算，路由器怎样学习，以及把专家分到多张 GPU 上以后会冒出什么新问题。从这一页到 §5，\(N\) 表示一层里专家的个数，\(K\) 表示每个 token 激活的专家个数。

零件：专家、路由器、门控值

专家（expert）。含义：一个普通的前馈网络。理解：MoE 层就是把一个大 FFN 换成 \(N\) 个并列的 FFN，每个都和原来的 FFN 结构相同（传统做法里大小也相同）。数学：第 \(i\) 个专家 \(\FFN_i:\R^d\to\R^d\)，有自己的一套 \(W_{1,i},W_{2,i},W_{3,i}\)。

路由器（router，也叫门控网络 gating network）。含义：决定每个 token 交给哪几个专家的小网络。理解：它就是分诊台，结构极简单：每个专家配一个 \(d\) 维的中心向量 \(\mathbf e_i\)，token 与哪个中心向量的点积大，就更倾向于哪个专家。数学：\(\mathbf e_1,\dots,\mathbf e_N\in\R^d\) 按行堆起来是一个 \(N\times d\) 的矩阵，路由器的全部参数就是它。

亲和度（affinity score）\(s_{i,t}\)。含义：token \(t\) 与专家 \(i\) 的匹配程度。理解：分诊台先给每个科室打一个“对口分”（点积），再把这些分换算成百分比，所有科室的百分比加起来是 100%。数学：点积之后做 softmax，得到 \(N\) 个非负、和为 1 的数。

门控值（gating value）\(g_{i,t}\)。含义：专家 \(i\) 的输出在最终结果里占多大权重。理解：只有被选中的 \(K\) 个专家有非零门控值，其余为 0，而门控值为 0 的专家根本不用计算。数学见下面的定义。

top-K 混合专家层（DeepSeekMoE 论文的写法）

设一层有 \(N\) 个专家，每个 token 激活 \(K\) 个。对第 \(t\) 个 token 的输入 \(\mathbf u_t\in\R^d\)：

\[\mathbf h_t'=\sum_{i=1}^{N}g_{i,t}\,\FFN_i(\mathbf u_t)+\mathbf u_t,\]
\[g_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}\in\TopK\big(\{s_{j,t}\mid 1\le j\le N\},\,K\big),\\ 0, & \text{否则},\end{cases}\qquad s_{i,t}=\softmax_i\big(\mathbf u_t^{\top}\mathbf e_i\big).\]

\(\TopK(\cdot,K)\) 表示集合里最大的 \(K\) 个数组成的集合。最后的 \(+\mathbf u_t\) 是残差连接。这三行是 DeepSeekMoE 论文的式 (3)–(5) 1，只把层号上标省掉了。

把三行拆开编号，后面推导时要分别引用：

MoE 层的输出\[\mathbf h_t'=\mathbf u_t+\sum_{i=1}^{N}g_{i,t}\,\FFN_i(\mathbf u_t)\]求和写的是全部 \(N\) 个专家，但只有 \(K\) 项非零，所以只需计算 \(K\) 个专家。(7.3)
亲和度\[s_{i,t}=\frac{\exp(\mathbf u_t^\top\mathbf e_i)}{\sum_{j=1}^{N}\exp(\mathbf u_t^\top\mathbf e_j)}\]\(\mathbf u_t^\top\mathbf e_i\) 叫路由 logit。softmax 让 \(s_{i,t}\ge0\)、\(\sum_is_{i,t}=1\)。(7.4)
门控值（top-K 截断）\[g_{i,t}=s_{i,t}\cdot\mathbb 1\big[s_{i,t}\in\TopK(\{s_{j,t}\}_{j=1}^{N},K)\big]\]\(\mathbb 1[\cdot]\) 是指示函数（条件成立取 1，否则取 0）。注意这里没有把选中的 \(K\) 个门控值重新归一化，所以它们的和小于 1：被截掉的那些专家的亲和度就这样丢掉了。(7.5)
手算一个 token 的路由

8 个专家，\(K=2\)。某个 token 的 8 个路由 logit \(\mathbf u_t^\top\mathbf e_i\) 是

\[(0.2,\ 2,\ 0,\ -0.5,\ 1,\ 0.5,\ -0.3,\ -1).\]

第一步，softmax。 先算 \(e^{z_i}\)：\(1.2214,\ 7.3891,\ 1,\ 0.6065,\ 2.7183,\ 1.6487,\ 0.7408,\ 0.3679\)，总和 \(15.6927\)。逐个相除得到亲和度

\[s_{\cdot,t}=(0.0778,\ 0.4709,\ 0.0637,\ 0.0387,\ 0.1732,\ 0.1051,\ 0.0472,\ 0.0234).\]

第二步，top-2。 最大的两个是专家 2（0.4709）和专家 5（0.1732）。

第三步，门控值。 按 (7.5)，\(g_{2,t}=0.4709\)，\(g_{5,t}=0.1732\)，其余 6 个为 0。两者之和只有 \(0.6441\)。

第四步，输出。 \(\mathbf h_t'=\mathbf u_t+0.4709\,\FFN_2(\mathbf u_t)+0.1732\,\FFN_5(\mathbf u_t)\)。只有两个专家被计算。

三种门控顺序

上面的例题是“先对全部专家做 softmax，再截取 top-\(K\)，不重新归一化”。这不是唯一的写法，不同论文的顺序不一样，而且顺序会影响路由器能不能学。

Shazeer 等人 2017 年的原始写法是先截断、再 softmax 10：

先取 top-k 再 softmax（Shazeer 2017、Mixtral）\[G(\mathbf u)=\softmax\big(\mathrm{KeepTopK}(\mathbf z,k)\big)\]\(\mathbf z\) 是路由 logit 向量；\(\mathrm{KeepTopK}\) 把前 \(k\) 大的分量原样保留，其余分量改成 \(-\infty\)。\(-\infty\) 经过指数变成 0，所以没选中的专家门控值为 0，选中的 \(k\) 个门控值之和为 1。Shazeer 的 \(\mathbf z\) 里还加了可训练的高斯噪声，用来帮助负载均衡；Mixtral 沿用同样的“top-k logits 上的 softmax”，不加噪声 8。(7.6)

GShard 则是先对全部专家 softmax、取 top-2，再把这两个门控值重新归一化（除以它们的和）11。它和 (7.6) 的结果其实完全一样：

截断后 softmax = softmax 后截断再归一化
(1)\(\displaystyle \dfrac{e^{z_i}}{\sum_{j\in\mathcal T}e^{z_j}}\)(7.6) 对选中集合 \(\mathcal T\) 里的专家 \(i\) 给出的门控值（其余项是 \(e^{-\infty}=0\)）
(2)\(\displaystyle =\dfrac{e^{z_i}/Z}{\sum_{j\in\mathcal T}e^{z_j}/Z},\quad Z=\sum_{j=1}^{N}e^{z_j}\)分子分母同除以全体专家的配分和 \(Z\)，值不变
(3)\(\displaystyle =\dfrac{s_i}{\sum_{j\in\mathcal T}s_j}\)\(e^{z_i}/Z\) 正是全体 softmax 的 \(s_i\)；这就是“先 softmax、截断、再归一化”

所以本质上只有两种门控：归一化的（Shazeer、GShard、Mixtral，门控值之和为 1）和不归一化的（Switch Transformer、DeepSeekMoE、DeepSeek-V2，门控值就是原始的 softmax 概率）12,1。DeepSeekMoE 16B 的开源代码里有一个开关 norm_topk_prob，发布的配置把它设为 false 6，与论文的式 (4)（加上共享专家后是式 (10)）一致：门控值直接取 \(s_{i,t}\)，不再除以选中者之和。

常见误解：DeepSeekMoE 的门控值加起来是 1

不是。DeepSeekMoE 与 DeepSeek-V2 先对全部路由专家做 softmax，再截取 top-\(K\)，不再归一化；§7 的例题里四个 token 的路由门控值之和分别只有 0.65、0.69、0.59、0.49。到了 DeepSeek-V3，亲和度改成 sigmoid，再在选中的专家之间归一化 15，那是第 11 课的内容。另外 GShard 的“重新归一化”也有一个细节：第二个专家只以概率 \(2g_2\) 被真正派发（\(g_2\) 是重新归一化后较小的那个门控值，\(g_2\le\tfrac12\)，所以 \(2g_2\le1\)），没派发时只剩第一个门控值，和并不总是 1 11。

路由器怎样学习

问题。 top-\(K\) 是一个“选或不选”的离散操作，没有导数。路由器的参数 \(\mathbf e_i\) 靠什么得到梯度？

推导。 梯度走的是门控值这条路，不走“选谁”那条路。把“选中了哪 \(K\) 个专家”（记作集合 \(\mathcal T_t\)）当作已经定下的事实，只对门控值的大小求导。这一步是精确的，不是近似：只要第 \(K\) 大与第 \(K+1\) 大的 logit 不相等，把 logit 挪动足够小的一步不会改变排序，\(\mathcal T_t\) 在这个小邻域里是常数，对导数没有贡献；导数只在两者恰好相等的点上不存在，而这样的点构成一个测度为零的集合。对一个被选中的专家 \(i\)，由 (7.3)，

\[\frac{\partial\mathbf h_t'}{\partial g_{i,t}}=\FFN_i(\mathbf u_t).\]

再记一个数

\[a_{i,t}=\Big(\frac{\partial\mathcal L}{\partial\mathbf h_t'}\Big)^{\!\top}\FFN_i(\mathbf u_t)\in\R,\]

它回答：把专家 \(i\) 的门控值调大一点，损失会涨多少（负数表示损失会降，也就是专家 \(i\) 的输出方向对这个 token 有用）。而 \(g_{i,t}=s_{i,t}\) 是路由 logit \(z_{j,t}=\mathbf u_t^\top\mathbf e_j\) 的光滑函数，所以梯度可以沿“损失 → \(\mathbf h_t'\) → \(g_{i,t}\) → \(s_{i,t}\) → \(z_{j,t}\) → \(\mathbf e_j\)”一路传回去。中间要用到 softmax 的导数：

softmax 的导数会求 softmax 雅可比的可以跳过

\(s_i=e^{z_i}/Z\)，\(Z=\sum_ke^{z_k}\)。对 \(z_j\) 求导用商的求导法则：分子 \(e^{z_i}\) 只在 \(i=j\) 时含 \(z_j\)（导数为 \(\delta_{ij}e^{z_i}\)，\(\delta_{ij}\) 在 \(i=j\) 时为 1、否则为 0），分母 \(Z\) 对 \(z_j\) 的导数是 \(e^{z_j}\)。于是

\[\frac{\partial s_i}{\partial z_j}=\frac{\delta_{ij}e^{z_i}Z-e^{z_i}e^{z_j}}{Z^2}=s_i(\delta_{ij}-s_j).\]

\(i=j\) 时是 \(s_i(1-s_i)>0\)：自己的 logit 变大，自己的概率变大；\(i\ne j\) 时是 \(-s_is_j<0\)：别人的 logit 变大，自己的概率被挤小。反向传播与雅可比的一般做法见 M06。

损失对路由 logit 的梯度（先 softmax、不归一化的门控）
(1)\(\displaystyle \dfrac{\partial\mathcal L}{\partial g_{i,t}}=a_{i,t}\)链式法则：上游梯度与 \(\partial\mathbf h_t'/\partial g_{i,t}=\FFN_i(\mathbf u_t)\) 的内积，即 \(a_{i,t}\) 的定义
(2)\(\displaystyle \dfrac{\partial\mathcal L}{\partial z_{j,t}}=\sum_{i\in\mathcal T_t}a_{i,t}\,\dfrac{\partial s_{i,t}}{\partial z_{j,t}}\)只有选中的 \(i\in\mathcal T_t\) 满足 \(g_{i,t}=s_{i,t}\)；其余门控值恒为 0，与 logit 无关
(3)\(\displaystyle =\sum_{i\in\mathcal T_t}a_{i,t}\,s_{i,t}\big(\delta_{ij}-s_{j,t}\big)\)softmax 的雅可比 \(\partial s_i/\partial z_j=s_i(\delta_{ij}-s_j)\)，\(\delta_{ij}\) 在 \(i=j\) 时为 1、否则为 0（M06）
(4)\(\displaystyle =s_{j,t}\Big(a_{j,t}\,\mathbb 1[j\in\mathcal T_t]-S_t\Big)\)第一部分只剩 \(i=j\) 一项，且只在 \(j\) 被选中时存在；第二部分提出公因子 \(s_{j,t}\)，记 \(S_t=\sum_{i\in\mathcal T_t}s_{i,t}a_{i,t}\)
(5)\(\displaystyle \dfrac{\partial\mathcal L}{\partial\mathbf e_j}=\sum_t\dfrac{\partial\mathcal L}{\partial z_{j,t}}\,\mathbf u_t\)\(z_{j,t}=\mathbf u_t^\top\mathbf e_j\) 对 \(\mathbf e_j\) 的导数是 \(\mathbf u_t\)；一个 batch 里各 token 的贡献相加

读这个结果分两种情况。被选中的专家 \(j\)：梯度是 \(s_{j,t}(a_{j,t}-S_t)\)。它比“选中的几位按亲和度加权的总和” \(S_t\) 更有用（\(a_{j,t}<S_t\)）时梯度为负，梯度下降抬高 \(z_{j,t}\)，也就是让 \(\mathbf e_j\) 沿 \(\mathbf u_t\) 的方向挪一点，下次与这类 token 的点积更大；反之推远。没被选中的专家：只剩 \(-s_{j,t}S_t\) 一项，与它自己的输出无关（它本来就没算），只取决于被选中的那几位整体有没有用，这就是“只能通过 softmax 的分母间接受到影响”。在先截断再 softmax 的写法 (7.6) 里，没被选中的专家连这一项也没有：它们的 logit 已被换成 \(-\infty\)，根本不在分母里。

路由梯度的一个数值例子

沿用上面手算的 token：选中专家 2 和 5，\(s_{2,t}=0.4709\)、\(s_{5,t}=0.1732\)。假设这一步反向传播得到 \(a_{2,t}=-0.5\)（专家 2 的输出有助于降低损失）、\(a_{5,t}=+0.2\)（专家 5 帮了倒忙）。这两个数是为演示设的，不来自真实模型。

  • \(S_t=0.4709\times(-0.5)+0.1732\times0.2=-0.2008\)。
  • 专家 2：\(0.4709\times(-0.5+0.2008)=-0.1409\)，负的，梯度下降抬高 \(z_{2,t}\)。
  • 专家 5：\(0.1732\times(0.2+0.2008)=+0.0694\)，正的，\(z_{5,t}\) 被压低。
  • 没选中的专家 1：\(0.0778\times0.2008=+0.0156\)；专家 6：\(0.1051\times0.2008=+0.0211\)。它们的 logit 被轻轻压低：选中的两位整体上有用（\(S_t<0\)），压低其余 logit 等于把 softmax 概率往选中的专家那边挪。

可以用有限差分核对：把 \(\mathcal L\) 看成 \(a_{2,t}s_{2,t}+a_{5,t}s_{5,t}\)，给某个 \(z_{j,t}\) 加 \(10^{-6}\)，损失的变化除以 \(10^{-6}\)，得到的正是上面这几个数。如果专家 5 的 logit 一步步下降、最终被专家 6 反超，这个 token 就会换一位专家：选择集合 \(\mathcal T_t\) 就是这样随训练慢慢改变的，虽然“选谁”这一步本身从来没有梯度。

这就解释了图 7.4 最后一行。Shazeer 等人指出，只有 \(k>1\) 时，被选中专家的门控值才对门控网络的权重有非零导数 10。在“先截断再 softmax”的写法下这是对的：\(k=1\) 时唯一被选中的专家门控值恒等于 \(e^{z}/e^{z}=1\)，与 logit 无关，梯度为零。Switch Transformer 的门控值是对全部 \(N\) 个专家 softmax 之后的概率 \(p_i(x)\)，即使 \(k=1\) 也小于 1、随 logit 变化；论文指出这个门控值“permits differentiability of the router”，并报告只路由到 1 个专家能保持模型质量，在较低的容量因子下甚至比 top-2 更好 12。

参数与计算的账

有了公式，可以精确记账。设每个专家是中间维 \(d_{ff}\) 的 SwiGLU。

一个 MoE 层的参数与每 token 计算\[\underbrace{N\cdot3dd_{ff}+Nd}_{\text{总参数}},\qquad\underbrace{K\cdot3dd_{ff}+Nd}_{\text{每 token 用到的参数}},\qquad \text{FFN 部分的 FLOPs}\approx2K\cdot3dd_{ff}\]\(Nd\) 是路由器；打分要和全部 \(N\) 个中心向量做点积，所以路由器每次都算满。它与一个专家的参数之比是 \(Nd/(3dd_{ff})=N/(3d_{ff})\)：Mixtral（\(N=8\)、\(d_{ff}=14336\)）约 1/5400，差三个多数量级；但专家又多又小时这个比值会变大，DeepSeekMoE 16B（64 个路由专家、中间维 1408）约 1/66。与全部专家参数相比，路由器只占 \(1/(3d_{ff})\)，总是可以忽略。(7.7)
Mixtral 8x7B 的一层

\(d=4096\)、\(d_{ff}=14336\)、\(N=8\)、\(K=2\) 5。每个专家 \(3\times4096\times14336=176{,}160{,}768\) 个参数；一层 8 个专家共 1,409,286,144 个；路由器 \(8\times4096=32{,}768\) 个。每个 token 在这一层用到的专家参数是 \(2\times176{,}160{,}768=352{,}321{,}536\)，只有专家总量的 1/4。32 层合计，专家参数 45.1B，占全模型 46.70B 的 96.6%。

专家分到多张卡上：专家并行与容量

MoE 模型大，一张 GPU 放不下全部专家，常见做法是专家并行（expert parallelism, EP）：不同的专家放在不同的设备上。

含义。 专家并行：一层的 \(N\) 个专家分散在若干设备上，每个 token 被送到它选中的专家所在的设备去计算，算完再送回来。

理解。 就像一家医院的科室分布在不同的楼里。一批病人（一个 batch 的 token）在分诊台挂完号，要走到各自的楼去看病，看完再回到大厅。这一来一回在 GPU 之间是两次全对全通信（all-to-all），代价见 M10 §6 与 第 12 课 §7。

问题。 各设备要同步前进：一层的计算要等最忙的那台设备算完才能进入下一层。GPU 程序喜欢固定形状的矩阵，于是每个专家事先只开固定数量的“槽位”。一个专家收到的 token 多于槽位怎么办？

数学。 Switch Transformer 把每个专家的槽位数叫专家容量（expert capacity）12：

专家容量\[\text{capacity}=\frac{\text{一个 batch 里的 token 数}}{\text{专家数 }N}\times\text{CF}\]CF 是容量因子（capacity factor）。CF \(=1\) 表示“恰好够平均分”；CF \(>1\) 留出余量，但空着的槽位也要参与矩阵计算（补零），白白耗费算力。(7.8)

超出容量的 token 怎么办？GShard 与 Switch 的做法都是丢弃（token dropping）：这个 token 在这一层不经过任何专家，只通过残差连接原样传到下一层 11,12。用 (7.3) 的话说，它的所有门控值被强行置零，\(\mathbf h_t'=\mathbf u_t\)。

容量因子的两难

一个 batch 有 1024 个 token、8 个专家，top-1 路由后各专家收到的 token 数是 \((200,150,130,120,120,110,100,94)\)。

  • CF \(=1.0\)：容量 \(1024/8\times1=128\)。专家 1、2、3 分别超出 72、22、2 个，共丢弃 96 个 token（9.4%）。
  • CF \(=1.25\)：容量 160，只有专家 1 超出 40 个，丢弃 3.9%。
  • CF \(=2.0\)：容量 256，一个不丢；但 8 个专家共 2048 个槽位只用了 1024 个，一半的专家计算在处理补零。

Switch Transformer 报告，在他们的实验里被丢弃的 token 通常不到 1%，并且在容量因子 1.0–1.25 这样的低值上 Switch 的效果更好 12。

DeepSeekMoE 不丢 token

DeepSeekMoE 的 2B 验证模型和 16B 模型训练时都不丢弃任何 token；16B 训练时每一层的全部专家都放在同一台设备上，所以不存在跨设备的负载瓶颈 1。容量与丢弃在 DeepSeek-V2 的大规模训练里重新出现，见第 10 课。

负载不均的代价还不止于丢 token。只要某个专家长期比别人忙，它所在的设备就是整层的瓶颈；更坏的情况是路由器干脆只用少数几个专家。下一页专门处理这个问题。

本页要点
  • MoE 层 = \(N\) 个专家 + 一个路由器（\(N\) 个中心向量）。亲和度 \(s_{i,t}=\softmax_i(\mathbf u_t^\top\mathbf e_i)\)，只保留 top-\(K\) 的门控值，输出是被选中专家的加权和再加残差（(7.3)–(7.5)）。
  • 门控只有两种本质不同的写法：归一化（Shazeer、GShard、Mixtral）与不归一化（Switch、DeepSeekMoE、V2）。先截断再 softmax 在 \(k=1\) 时让路由器失去梯度。
  • 每 token 只算 \(K\) 个专家，但路由器要和全部 \(N\) 个中心向量打分；专家分到多张卡上后，负载不均会造成等待、丢 token 或空转。

负载均衡：路由坍缩与辅助损失

上一页结尾说到负载不均。这一页先看它最极端的形式“路由坍缩”，再推导两代负载均衡损失：Shazeer 2017 的变异系数损失，以及 GShard 与 Switch Transformer 的 \(f\cdot P\) 形式。DeepSeekMoE 的专家级均衡损失（§7）是后者的直接推广，所以这一页的推导要做扎实。

路由坍缩：一个自我强化的回路

问题。 训练开始时路由器的参数是随机的，总有几个专家的打分碰巧略高。接下来会发生什么？Shazeer 等人观察到，门控网络倾向于收敛到“总是给同样几个专家大权重”的状态；而且这种不平衡会自我强化：受偏爱的专家训练得更快，于是被门控网络选得更多 10。

含义。 路由坍缩（routing collapse）：路由器几乎总把 token 送给同一小撮专家，其余专家很少被选中，也就几乎得不到训练。

理解。 回到医院：某个科室口碑碰巧好一点，分诊台就多往那里送病人；那里的医生见的病例多、经验涨得快，口碑更好，分诊台送得更多……最后别的科室门可罗雀，那里的医生手艺荒废。医院养了很多医生，实际只有几位在干活。

数学。 用“每个专家分到的 token 比例”衡量：均匀时每个专家约 \(K/N\) 的 token 选中它；坍缩时少数几个专家的比例接近 1，其余接近 0。下面的两代损失都在惩罚这种集中。

DeepSeekMoE 论文把负载不均的危害归成两条 1：一是路由坍缩，其他专家得不到充分训练，相当于花了参数却没学到东西；二是专家分布在多台设备上时，负载不均会加剧计算瓶颈，也就是 §2 说的“等最慢的那台卡”。

第一代：变异系数损失（Shazeer 2017）

变异系数知道 CV 的可以跳过

一组数 \(x_1,\dots,x_n\)，均值 \(\mu=\frac1n\sum_ix_i\)，标准差 \(\sigma=\sqrt{\frac1n\sum_i(x_i-\mu)^2}\)。变异系数（coefficient of variation）\(\mathrm{CV}=\sigma/\mu\)，是“相对于平均值的离散程度”，没有单位：把所有数同乘 10，CV 不变。所有数相等时 \(\mathrm{CV}=0\)；越不均匀，CV 越大。方差与标准差的基础见 M04。

Shazeer 等人先定义一个专家的重要性（importance）：一个 batch 里所有 token 分给它的门控值之和。然后惩罚各专家重要性的不均匀 10：

importance 损失（Shazeer 2017）\[\begin{aligned}\mathrm{Importance}(X)&=\sum_{\mathbf x\in X}G(\mathbf x),\\ \mathcal L_{importance}(X)&=w_{importance}\cdot\mathrm{CV}\big(\mathrm{Importance}(X)\big)^2\end{aligned}\]\(X\) 是一个 batch 的输入；\(G(\mathbf x)\in\R^N\) 是 (7.6) 给出的门控值向量，所以 \(\mathrm{Importance}(X)\in\R^N\) 是各专家的门控值总和；\(w_{importance}\) 是手调的系数（语言模型实验取 0.1，翻译实验取 0.01）。(7.9)
算几个 CV²

4 个专家的重要性分别是：

  • \((1,1,1,1)\)：完全均匀，\(\sigma=0\)，\(\mathrm{CV}^2=0\)。
  • \((2,1,0.5,0.5)\)：均值 1，偏差 \((1,0,-0.5,-0.5)\)，方差 \((1+0+0.25+0.25)/4=0.375\)，\(\mathrm{CV}^2=0.375\)。
  • \((4,0,0,0)\)：全部压在一个专家上。均值 1，偏差 \((3,-1,-1,-1)\)，方差 \((9+1+1+1)/4=3\)，\(\mathrm{CV}^2=3\)。

论文没有说明用的是总体标准差（除以 \(n\)）还是样本标准差（除以 \(n-1\)）；若用后者，后两个数分别是 0.5 和 4.0。两种写法只差一个常数倍，不影响“越不均越大”。

只有 importance 还不够：一个专家可能收到少数几个门控值很大的 token，另一个收到许多门控值很小的 token，两者重要性相同，负载却差很多 10。所以 Shazeer 等人又加了一个 load 损失，同样是变异系数平方，惩罚的是“每个专家被选中的次数”。次数是离散的，没法求导；他们借助门控里的随机噪声，把“被选中”换成“在噪声重新抽样时仍留在 top-\(k\) 的概率”，得到一个光滑的估计。表 6 显示，只要两种损失至少用上一种，模型质量就很接近（困惑度 35.6–35.7），完全不用则差得多（39.8）。

第二代：\(f\cdot P\) 损失（GShard、Switch Transformer）

问题。 我们真正想要的是“每个专家分到的 token 比例相等”。能不能直接写出这个目标？

记 \(f_i\) 为一个 batch 里首选专家 \(i\) 的 token 比例，\(\sum_if_i=1\)。一个自然的惩罚是平方和 \(\sum_if_i^2\)：越集中越大。它在均匀时最小：

均匀分配让 \(\sum_i f_i^2\) 最小
(1)\(\displaystyle \sum_{i=1}^{N}f_i=1\)每个 token 恰有一个首选专家，比例加起来是 1
(2)\(\displaystyle 1=\Big(\sum_i1\cdot f_i\Big)^2\le\Big(\sum_i1^2\Big)\Big(\sum_if_i^2\Big)=N\sum_if_i^2\)柯西–施瓦茨不等式 \((\mathbf a\cdot\mathbf b)^2\le\norm{\mathbf a}^2\norm{\mathbf b}^2\)，取 \(\mathbf a\) 为全 1 向量（证明见 M01 练习 7）
(3)\(\displaystyle N\sum_if_i^2\ge1,\quad\text{等号当且仅当 }f_i=\tfrac1N\)柯西–施瓦茨取等号当且仅当两向量成比例，即所有 \(f_i\) 相等

麻烦。 \(f_i\) 是计数，对路由器参数不可导。GShard 的办法是把平方里的一个 \(f_i\) 换成可导的替身：专家 \(i\) 在这个 batch 上的平均门控概率。论文原话是用平均门值作为可导的近似，把 \((c_e/S)^2\) 换成 \(m_e(c_e/S)\) 11。GShard 的记号是：\(E\) 个专家（即本课的 \(N\)），一组 \(S\) 个 token，\(c_e\) 是首选专家 \(e\) 的 token 数，\(m_e\) 是专家 \(e\) 在这组 token 上的平均 softmax 门值；所以 \(c_e/S\) 就是 \(f_i\)，\(m_e\) 就是下面的 \(P_i\)。Switch Transformer 沿用这一形式，乘上专家数 \(N\) 和系数 \(\alpha\) 12：

Switch Transformer 的负载均衡损失\[\mathcal L_{bal}=\alpha\cdot N\cdot\sum_{i=1}^{N}f_i\,P_i\]这是一个加在语言模型损失上的辅助损失（auxiliary loss）。Switch 取 \(\alpha=10^{-2}\)：他们在 \(10^{-1}\) 到 \(10^{-5}\) 之间按 10 的幂扫过，这个值既能保证均衡，又不至于压过主要的交叉熵目标。(7.10)
两个统计量\[f_i=\frac1T\sum_{\mathbf x\in\mathcal B}\mathbb 1\Big\{\argmax_j\,p_j(\mathbf x)=i\Big\},\qquad P_i=\frac1T\sum_{\mathbf x\in\mathcal B}p_i(\mathbf x)\]\(\mathcal B\) 是一个 batch，含 \(T\) 个 token（注意：这里的 \(T\) 是 batch 里的 token 数，不是序列长度）；\(p_i(\mathbf x)\) 是对全部 \(N\) 个专家做 softmax 后的概率，即本课的 \(s_{i,t}\)。\(f_i\) 是实际分到的比例，不可导，求梯度时当作常数；\(P_i\) 是路由器“愿意”给专家 \(i\) 的平均概率，可导。(7.11)

为什么乘 \(N\)。 均匀路由时 \(f_i=P_i=1/N\)，\(\sum_if_iP_i=N\cdot\frac1{N^2}=\frac1N\)，乘上 \(N\) 正好是 1，损失等于 \(\alpha\)，与专家数无关。这样同一个 \(\alpha\) 可以用在不同专家数的模型上。另一个极端：全部 token 都去专家 1，而且路由器也把概率全给它，\(f_1=P_1=1\)，损失是 \(\alpha N\)；\(N=128\) 时是均匀时的 128 倍。GShard 的写法 \(\frac1E\sum_e\frac{c_e}{S}m_e\) 前面是 \(1/E\) 而不是 \(N\)（\(E=N\)），均匀时等于 \(\frac1E\cdot E\cdot\frac1E\cdot\frac1E=1/E^2\)，两篇论文的系数因此不能直接比较大小。

一个 8 token 的小批次

\(N=4\) 个专家，一个 batch 有 \(T=8\) 个 token。首选专家的计数是 \((5,1,1,1)\)，路由器给四个专家的平均概率是 \(P=(0.55,0.15,0.15,0.15)\)。

  • \(f=(5,1,1,1)/8=(0.625,\ 0.125,\ 0.125,\ 0.125)\)。
  • \(\sum_if_iP_i=0.625\times0.55+3\times0.125\times0.15=0.34375+0.05625=0.4\)。
  • \(\mathcal L_{bal}=\alpha\times4\times0.4=1.6\alpha\)，比均匀时的 \(\alpha\) 高 60%。
  • 对 \(P\) 的梯度 \(\partial\mathcal L_{bal}/\partial P_i=\alpha Nf_i=\alpha\,(2.5,\ 0.5,\ 0.5,\ 0.5)\)：最忙的专家 1，平均概率被往下压的力度是其他专家的 5 倍。

梯度往哪个方向推

对 \(P_i\) 的梯度只说了“压谁”。路由器的参数 \(\mathbf e_j\) 要通过 logit 才起作用，所以把梯度推到单个 token 的 logit \(z_{j,t}=\mathbf u_t^\top\mathbf e_j\) 上：

均衡损失对一个 token 的路由 logit 求导
(1)\(\displaystyle \dfrac{\partial\mathcal L_{bal}}{\partial z_{j,t}}=\alpha N\sum_{i}f_i\,\dfrac{\partial P_i}{\partial z_{j,t}}\)\(f_i\) 不可导，当作常数；只有 \(P_i\) 依赖 logit
(2)\(\displaystyle =\dfrac{\alpha N}{T}\sum_{i}f_i\,\dfrac{\partial s_{i,t}}{\partial z_{j,t}}\)\(P_i=\frac1T\sum_t s_{i,t}\)，只有第 \(t\) 项含 \(z_{j,t}\)
(3)\(\displaystyle =\dfrac{\alpha N}{T}\sum_{i}f_i\,s_{i,t}\big(\delta_{ij}-s_{j,t}\big)\)softmax 的雅可比 \(\partial s_i/\partial z_j=s_i(\delta_{ij}-s_j)\)，\(\delta_{ij}\) 在 \(i=j\) 时为 1、否则为 0（M06）
(4)\(\displaystyle =\dfrac{\alpha N}{T}\,s_{j,t}\Big(f_j-\sum_{i}s_{i,t}f_i\Big)\)\(\delta_{ij}\) 只留下 \(i=j\) 那一项；第二部分提出公因子 \(s_{j,t}\)
均衡损失对路由 logit 的梯度\[\frac{\partial\mathcal L_{bal}}{\partial z_{j,t}}=\frac{\alpha N}{T}\,s_{j,t}\,\big(f_j-\bar f_t\big),\qquad \bar f_t=\sum_{i=1}^{N}s_{i,t}\,f_i\]\(\bar f_t\) 是“按 token \(t\) 自己的路由分布加权的平均负载”。梯度下降让 \(z_{j,t}\) 沿 \(-\partial\mathcal L/\partial z_{j,t}\) 移动：负载高于这个平均的专家（\(f_j>\bar f_t\)），logit 被压低；低于平均的被抬高。严格说，真正被更新的是 \(\mathbf e_j\)：学习率为 \(\eta\) 时，token \(t\) 这一项贡献 \(-\eta\,\frac{\partial\mathcal L}{\partial z_{j,t}}\mathbf u_t\)，使 \(z_{j,t}\) 变化 \(-\eta\frac{\partial\mathcal L}{\partial z_{j,t}}\norm{\mathbf u_t}^2\)，方向与上面一致；一步更新把 batch 里所有 token 的项加在一起，某个 \(z_{j,t}\) 的实际变化还会受其他 token 的 \(\mathbf u_{t'}^\top\mathbf u_t\) 影响。(7.12)

这个式子把回路图里的绿色箭头说准确了：一个专家越忙，每个 token 把它的 logit 往下压得越狠；压的力度还按 \(s_{j,t}\) 加权，路由器越想把 token \(t\) 送给专家 \(j\)，这一压就越重。§7 会用一个 4 个 token 的例子把这个梯度逐项算出来。

还有一个容易忽略的性质（笔者的推导）：如果把 \(f\) 固定，只对 \(P\) 最小化 \(\sum_if_iP_i\)，最优解是把全部概率压到当前最空闲的那个专家上，而不是让 \(P\) 也均匀。理由是：\(P\) 落在概率单纯形 \(\{P_i\ge0,\ \sum_iP_i=1\}\) 上，\(\sum_if_iP_i\) 是 \(P\) 的线性函数，它在单纯形上的最小值 \(\min_if_i\) 取在顶点，也就是 \(P\) 全部集中在 \(f_i\) 最小的专家上。（由 softmax 平均出来的 \(P_i\) 都严格大于 0，这个顶点只能无限逼近、取不到，但方向不变。）同一件事也说明，均匀路由并不是 \(\sum_if_iP_i\) 的最小点：§7 会给出一个比均匀值更低的例子。所以这项损失不是一个“目标”，而是一股“往空闲专家那边推”的压力；\(f\) 随之改变后压力方向也随之改变，与语言模型损失的拉力一起达成平衡。这也是 \(\alpha\) 必须小的原因之一。

类比延伸：分诊台的考核

映射。 \(f_i\) = 科室 \(i\) 今天实际接诊的比例；\(P_i\) = 分诊台对科室 \(i\) 的平均“推荐意愿”；\(N\sum_if_iP_i\) = 给分诊台的考核分，越低越好；梯度 (7.12) = 考核要求分诊台把推荐意愿从拥挤的科室挪到清闲的科室。

收益。 它说明了为什么只要 \(P_i\) 可导就够了：考核改变的是分诊台的“意愿”，意愿变了，下一批病人的实际去向 \(f_i\) 自然跟着变。

失效的地方。 这项考核只看人数，不看疗效：权重 \(\alpha\) 定得太高，分诊台会为了凑人数把病人送到不对口的科室，这就是均衡损失伤害模型质量的方式。另外，这个“考核”按一个 batch 统计，不保证每一时刻、每一台设备都均衡。

常见误解：\(f\cdot P\) 形式的损失是 Shazeer 2017 提出的

不对。Shazeer 2017 首创了用辅助损失做负载均衡，但它用的是 importance 与 load 两个变异系数平方损失 (7.9)；\(f\cdot P\) 形式来自 GShard 与 Switch Transformer，Switch 明确说它简化了 Shazeer 原来“两个损失”的设计 12。ST-MoE 的附录把 \(\alpha N\sum f_iP_i\) 说成来自 Shazeer 2017 14，这是一处出处误记。

选讲：router z-loss

负载均衡之外，大规模稀疏模型的路由器还有训练稳定性问题。ST-MoE 加了一项 router z-loss，惩罚进入门控网络的过大 logit 14：

\[\mathcal L_z=\frac1B\sum_{i=1}^{B}\Big(\log\sum_{j=1}^{N}e^{x_j^{(i)}}\Big)^2,\]

\(B\) 是 token 数，\(x^{(i)}\) 是第 \(i\) 个 token 的路由 logit，系数取 \(c_z=0.001\)。在他们的稳定性实验里，基线 6 次训练有 4 次稳定，加 z-loss 后 3 次全部稳定，质量也略好。它和负载均衡无关，DeepSeekMoE 没有使用，这里只是让读者知道路由器的麻烦不止一种。

失败模式
  • \(\alpha\) 太小：压不住回路，退回路由坍缩。
  • \(\alpha\) 太大：均衡了，但 token 被推到不合适的专家，语言模型损失变差。DeepSeekMoE 论文明确说，过强的负载均衡约束会损害模型性能 1。
  • 统计口径：\(f_i\)、\(P_i\) 是在一批 token 上平均的；批内均衡不等于每台设备在每一步都均衡，也不等于每条序列内部均衡。
  • 均衡不等于专精：所有专家都一样忙，并不说明它们学到的东西各不相同。下一页讨论的正是这个问题。
本页要点
  • 路由坍缩是自我强化的：被偏爱的专家学得更快、被选得更多。Shazeer 表 6：不加均衡损失时最忙专家负载是平均的 17.8 倍，困惑度 39.8；加上后 1.14 倍、35.6。
  • 理想目标 \(\sum f_i^2\) 在均匀时最小（柯西–施瓦茨），但 \(f_i\) 不可导；把一个 \(f_i\) 换成可导的平均概率 \(P_i\)，得到 \(\alpha N\sum_if_iP_i\)。乘 \(N\) 让均匀时的值恒为 \(\alpha\)。
  • 梯度 (7.12)：\(\propto s_{j,t}(f_j-\bar f_t)\)，忙的专家 logit 被压低、闲的被抬高。\(\alpha\) 要小：均衡是约束，不是目标。

两个病根：知识混杂与知识冗余

到这里，传统 MoE 的全部零件都已齐备：门控、容量、均衡损失。GShard 式的 MoE 已经能训练到上千亿参数。DeepSeekMoE 的论文换了一个角度发问：这些专家真的“专”吗？

专家专精（expert specialization）。含义：论文给的定义是每个专家学到互不重叠、各自集中的知识 1。理解：好医院里心内科医生只管心脏，而且医院里不需要十个人都在研究同一种常见病。数学：论文没有给出专精程度的公式化度量，只用间接的实验来检验（§8），所以下面两个“病根”应当读作假说。

病根一：知识混杂

含义。 知识混杂（knowledge hybridity）：一个专家被迫在同一组参数里装下多种互不相干的知识。

理解。 论文的论证是这样的：现有的 MoE 通常只有不多的专家（例如 8 个或 16 个），于是分给某个专家的 token 很可能覆盖五花八门的知识；这个专家就得在自己的参数里汇集差异很大的知识，而这些知识很难被同时用好 1。医院只设 8 个大科室时，“内科”既要看心脏病，又要看胃病、肺病，内科医生什么都懂一点，却很难样样精通。

数学（笔者的简化说法）。 设一个 token 同时要用到 \(r\) 个互不相干的知识“面”，而它只能激活 \(K\) 个专家。例如 §5 开头那个 token 需要 Python 语法、数值计算、英文注释三样，\(r=3\)。把 \(r\) 个面分给 \(K\) 个专家，由抽屉原理，至少有一个专家要同时承担 \(\lceil r/K\rceil\) 个面：\(K=2\) 时，这个专家在处理这一个 token 时就得身兼两职。整个训练集里这样的 token 很多，每次凑在一起的面又各不相同，所以一个大专家在同一组参数里混装的知识面就多了。这不是论文里的公式，只是把“专家少而大 → 混杂”这句话翻译成数量关系；真实的知识没有这么整齐的分面。

另一种粗算为什么解释不了细粒度切分

常见的另一种说法是：“知识分成 \(Q\) 类、每个 token 用其中一类，\(N\) 个专家、每 token 选 \(K\) 个，平均每个专家管 \(QK/N\) 类。”它能说明“专家越少越混杂”，但对细粒度切分不敏感：\(N\to mN\)、\(K\to mK\) 之后 \(Q\cdot mK/(mN)=QK/N\)，一点没变。细粒度切分的好处要从上面“一个 token 同时用到几个面”的角度看：激活名额从 \(K\) 变成 \(mK\)，\(\lceil r/(mK)\rceil\) 可以降到 1，每个面都能分到自己的小专家（\(m=4\)、\(K=2\)、\(r=3\) 时，8 个名额分给 3 个面，每个面 2–3 个小专家）。

病根二：知识冗余

含义。 知识冗余（knowledge redundancy）：同一份知识被多个专家各自重复学了一遍。

理解。 分给不同专家的 token 可能都需要某些公共知识，于是好几个专家会各自在参数里学到这份公共知识，专家参数因此冗余 1。医院里每个专科都得会量血压、问病史；如果每个科室都要单独培养这项本领，就等于同一件事培养了很多遍。语言模型里的“公共知识”可以想成语法、常见搭配、基本常识这类几乎每个 token 都用得上的东西。

这是假说，证据是间接的

论文没有直接检查“专家 3 存了哪些知识”，而是做了几类间接实验：禁用排名靠前的专家时损失上升得多快、去掉共享专家会怎样、少激活几个专家行不行（§8）。同月发布的 Mixtral 论文分析了自己的路由，发现专家分配没有明显的按主题分工，更像是句法层面的规律 8。这个观察和“知识混杂”的说法方向一致，但它来自另一个模型、另一种分析方法，不能当作 DeepSeekMoE 假说的直接证据。

两个对策一览

DeepSeekMoE 针对两个病根各开了一剂药，两剂药都不改变总参数和每 token 的计算量：

  1. 细粒度专家切分（fine-grained expert segmentation），针对混杂：把每个专家切成 \(m\) 个更小的专家，同时每个 token 激活的专家数也乘 \(m\)。专家更小、更多，每一类知识可以落进更窄的专家里，一个 token 再从中挑出更精确的组合（§5）。
  2. 共享专家隔离（shared expert isolation），针对冗余：拿出少数几个专家，每个 token 都必然经过它们，专门承载公共知识；其余专家照常路由（§6）。
类比延伸：医院改组

映射。 细粒度切分 = 把“内科”拆成心内、消化、呼吸……，每位病人由原来挂 2 个大科室，改成挂 4 个更对口的小科室，看病总时长不变；共享专家 = 设一位每位病人都要先看的全科医生，量血压、问病史这些事由他统一做，专科医生不必各自重复。

收益。 它把两剂药分别对准两个病根：拆科室对付“什么都得看”（混杂），全科医生对付“人人都得会”（冗余）。

失效的地方。 真实医院拆科室要多雇人、多占诊室；MoE 的细粒度切分参数总量不变，“多出来的”是调度与通信成本（§5 的失败模式）。另外，全科医生看什么是医院规定的，共享专家学什么是训练自发决定的，论文只能事后间接检验它确实承载了难以替代的东西。

本页要点
  • DeepSeekMoE 的目标是专家专精：每个专家的知识互不重叠、各自集中。
  • 两个病根（论文的假说）：专家太少太大 → 知识混杂；公共知识被各专家重复学习 → 知识冗余。证据是间接的。
  • 两个对策：细粒度切分（对付混杂）、共享专家隔离（对付冗余），两者都保持总参数与每 token 计算量不变。

细粒度专家切分

问题。 传统 top-2 MoE 里，一个 token 用到的全部“专门知识”必须装进它选中的 2 个大专家里。16 个专家选 2 个，一共只有 \(\binom{16}{2}=120\) 种搭配。如果一个 token 需要“Python 语法 + 数值计算 + 英文注释”三种知识，而没有哪两个专家恰好覆盖这三样，就只能凑合。能不能在不增加参数、不增加计算的前提下，让搭配多得多？

图景。 医院不增加医生总工时，只是把“内科”拆成心内、消化、呼吸、内分泌四个小科室，每位病人原来挂 2 个大科室，现在挂 8 个小科室。每个小科室更专一，病人的组合也灵活得多。

定义

含义。 细粒度专家切分（fine-grained expert segmentation）：把每个专家沿中间维度切成 \(m\) 个小专家，同时把每个 token 激活的专家数也乘以 \(m\)。

理解。 专家数从 \(N\) 变成 \(mN\)，每个专家的中间维从 \(d_{ff}\) 变成 \(d_{ff}/m\)，每个 token 激活 \(mK\) 个。总参数和每 token 的计算都不变，变的是“颗粒度”。

数学。 这是 DeepSeekMoE 论文的式 (6)–(8) 1：

细粒度切分后的 MoE 层\[\mathbf h_t'=\mathbf u_t+\sum_{i=1}^{mN}g_{i,t}\,\FFN_i(\mathbf u_t),\qquad g_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}\in\TopK\big(\{s_{j,t}\}_{j=1}^{mN},\,mK\big),\\ 0, & \text{否则},\end{cases}\]\(s_{i,t}=\softmax_i(\mathbf u_t^\top\mathbf e_i)\) 现在对 \(mN\) 个专家做 softmax；每个 \(\FFN_i\) 的中间维是 \(d_{ff}/m\)。和 (7.3)–(7.5) 相比，只有专家个数、专家大小和 top 的个数变了。(7.13)

为什么可以这样切

切分不是任意的：一个 FFN 本来就是它每个中间神经元贡献之和。把 SwiGLU 按中间维的下标 \(j\) 展开：

FFN 是中间神经元的贡献之和\[\FFN(\mathbf u)=W_2\big(\mathrm{SiLU}(W_1\mathbf u)\odot W_3\mathbf u\big)=\sum_{j=1}^{d_{ff}}\mathbf w_{2,j}\;\mathrm{SiLU}\big(\mathbf w_{1,j}^\top\mathbf u\big)\,\big(\mathbf w_{3,j}^\top\mathbf u\big)\]\(\mathbf w_{1,j}^\top,\mathbf w_{3,j}^\top\) 是 \(W_1,W_3\) 的第 \(j\) 行，\(\mathbf w_{2,j}\) 是 \(W_2\) 的第 \(j\) 列，都在 \(\R^{d}\) 里。每一项只用到第 \(j\) 个神经元自己的三组权重（矩阵乘向量 = 列的加权和，见 M01）。(7.14)

所以把 \(d_{ff}\) 个神经元分成 \(m\) 组，每组就是一个中间维为 \(d_{ff}/m\) 的完整 SwiGLU，\(m\) 组输出之和恰好等于原来的 FFN。细粒度切分做的事是：让路由器分别决定每一组用不用、用多大权重。第 1 课把 FFN 看成键值记忆，在那个视角下，每个神经元就是一条“键 \(\mathbf w_{1,j}\)、值 \(\mathbf w_{2,j}\)”的记忆，切分就是把记忆条目分成更小的抽屉。

切分前后的参数与计算
(1)\(\displaystyle \text{每个小专家的参数}=3\cdot d\cdot\dfrac{d_{ff}}{m}\)SwiGLU 三个矩阵，中间维缩小为 \(1/m\)
(2)\(\displaystyle \text{专家参数合计}=mN\cdot3d\dfrac{d_{ff}}{m}=N\cdot3dd_{ff}\)\(m\) 约掉：总参数与切分前相同
(3)\(\displaystyle \text{每 token 激活的专家参数}=mK\cdot3d\dfrac{d_{ff}}{m}=K\cdot3dd_{ff}\)激活个数乘 \(m\)、每个缩小为 \(1/m\)，再次约掉：计算量不变
(4)\(\displaystyle \text{路由器参数}=mN\cdot d\)唯一变化：中心向量多了 \(m\) 倍，打分的计算也多了 \(m\) 倍
细粒度切分的账\[\underbrace{N\cdot3dd_{ff}}_{\text{专家参数：不变}},\qquad \underbrace{K\cdot3dd_{ff}}_{\text{激活参数：不变}},\qquad \underbrace{mNd}_{\text{路由器：}\times m}\](7.15)
\(d=2048\) 的 16 个专家切成 4 份

标准 FFN 中间维 5632。切分前：每个专家 \(3\times2048\times5632=34{,}603{,}008\) 个参数，16 个共 553,648,128；路由器 \(16\times2048=32{,}768\)。

\(m=4\) 之后：64 个专家，每个中间维 1408，参数 \(3\times2048\times1408=8{,}650{,}752\)；64 个共 \(553{,}648{,}128\)，一个不差；每 token 激活 \(2\times4=8\) 个，激活参数 \(8\times8{,}650{,}752=69{,}206{,}016=2\times34{,}603{,}008\)，也一个不差。路由器变成 \(64\times2048=131{,}072\)，是专家参数合计的 0.024%。

组合数：从 120 到 4,426,165,368

组合数会算 \(\binom{n}{k}\) 的可以跳过

从 \(n\) 个不同的东西里不计顺序地选出 \(k\) 个，方法数是 \(\binom{n}{k}=\dfrac{n!}{k!\,(n-k)!}\)。例如 \(\binom{16}{2}=\dfrac{16\times15}{2}=120\)：先选第一个有 16 种、再选第二个有 15 种，但“先 A 后 B”和“先 B 后 A”是同一种，所以除以 2。

DeepSeekMoE 论文用组合数说明细粒度切分的好处 1：\(N=16\) 时，传统 top-2 路由有

论文的组合数例子\[\binom{16}{2}=120\qquad\longrightarrow\qquad\binom{64}{8}=4{,}426{,}165{,}368\quad(m=4)\]参数与计算不变，可选的专家组合多了约 \(3.7\times10^{7}\) 倍。论文的原话是，这让被激活专家的组合更灵活、更有适应性，知识可以被更精确地分解到不同专家里。(7.16)

\(\binom{64}{8}\) 可以自己验算：\(\dfrac{64\cdot63\cdot62\cdot61\cdot60\cdot59\cdot58\cdot57}{8!}=\dfrac{178{,}462{,}987{,}637{,}760}{40{,}320}=4{,}426{,}165{,}368\)。

增长有多快？ 随 \(m\) 增大，组合数以指数速度增长，指数的斜率由二元熵决定。二元熵的定义与性质见 M05，这里只需要它的公式 \(H(p)=-p\log_2p-(1-p)\log_2(1-p)\)。

组合数的熵上界与下界（取 \(p=k/n\)）
(1)\(\displaystyle 1=\big(p+(1-p)\big)^n=\sum_{j=0}^{n}\binom{n}{j}p^j(1-p)^{n-j}\)二项式定理
(2)\(\displaystyle 1\ge\binom{n}{k}p^k(1-p)^{n-k}\)求和的每一项都非负，只留 \(j=k\) 这一项，和不会变大
(3)\(\displaystyle \binom{n}{k}\le p^{-k}(1-p)^{-(n-k)}=2^{-k\log_2p-(n-k)\log_2(1-p)}=2^{nH(p)}\)移项；代入 \(k=np\)、\(n-k=n(1-p)\)，指数恰好是 \(n\) 倍二元熵
(4)\(\displaystyle \binom{n}{k}p^k(1-p)^{n-k}\ge\dfrac1{n+1}\)\(p=k/n\) 时，二项分布 \(n+1\) 项里第 \(k\) 项最大，至少是平均值 \(\tfrac1{n+1}\)
(5)\(\displaystyle \dfrac{2^{nH(p)}}{n+1}\le\binom{n}{k}\le2^{nH(p)}\)合并第 (3)(4) 行

第 (4) 行说“第 \(k\) 项最大”，理由如下。记第 \(j\) 项 \(b_j=\binom nj p^j(1-p)^{n-j}\)，相邻两项之比

\[\frac{b_{j+1}}{b_j}=\frac{n-j}{j+1}\cdot\frac{p}{1-p}.\]

它不小于 1，当且仅当 \((n-j)p\ge(j+1)(1-p)\)；展开后两边的 \(-jp\) 抵消，整理得 \(j\le np-(1-p)=k-1+p\)。\(j\) 是整数、\(0<p<1\)，所以 \(j\le k-1\) 时后一项不小于前一项，\(j\ge k\) 时后一项更小：各项一路增到 \(j=k\) 再一路减小，第 \(k\) 项最大。\(n+1\) 项加起来是 1，最大的一项不会小于它们的平均值 \(\frac1{n+1}\)。

组合数随切分粒度的增长\[\log_{10}\binom{mN}{mK}=mN\,H\!\left(\tfrac KN\right)\log_{10}2-O(\log m)\]\(K/N\) 不随 \(m\) 变，所以 \(\log\) 组合数的主项随 \(m\) 线性增长，修正项只有 \(O(\log m)\)（由上一个推导，它介于 \(0\) 与 \(\log_{10}(mN+1)\) 之间）：组合数本身按 \(m\) 的指数速度增长。\(N=16,K=2\) 时 \(H(1/8)=0.5436\) 比特，斜率是每增加 1 个 \(m\) 上升 \(16\times0.5436\times0.30103=2.62\) 个数量级。(7.17)
真实模型的组合数
  • Mixtral 8x7B：8 个专家选 2 个，\(\binom82=28\)。
  • DeepSeekMoE 2B：1 个共享专家不参与选择，63 个路由专家选 7 个，\(\binom{63}{7}=553{,}270{,}671\)。
  • DeepSeekMoE 16B：2 个共享，64 个路由选 6 个，\(\binom{64}{6}=74{,}974{,}368\)。比论文示意的 \(\binom{64}{8}\) 小得多，因为共享专家占掉了 2 个激活名额。
  • DeepSeekMoE 145B（arXiv v1 初步实验）：4 个共享，128 个路由选 12 个，\(\binom{128}{12}\approx2.37\times10^{16}\)。
组合数是动机，不是证明

“组合多了，所以专精了”是论文给出的直觉，不是被证明的机制。三个理由要记住：

  1. 组合数只数无序集合。 门控值是连续的，即使只有 2 个专家，两个门控值的比例也能连续变化；组合数忽略了这一点。
  2. 反例就在同一篇论文里。 消融实验中，从 GShard（16 选 2，120 种组合）加上 1 个共享专家（15 选 1，只剩 15 种组合），组合数降了 8 倍，多数基准却变好了（§8）。共享专家的收益与组合数无关。
  3. 论文没有直接测量专家学到了什么（§4），只能从下游指标间接推断。

切细的隐藏成本

(7.15) 说参数和 FLOPs 都不变，但“计算量相同”不等于“一样快”。

  • 小矩阵的硬件效率低。 一个专家的矩阵乘法从 \([\,\cdot\,,2048]\times[2048,5632]\) 变成 \([\,\cdot\,,2048]\times[2048,1408]\)。GPU 在小矩阵上更难把计算单元喂饱。论文明确说，16B 没有用更细的切分，就是因为专家过小可能降低计算效率 1。
  • 每个专家分到的 token 数不变，但每次矩阵乘法变小了。 一个 batch 有 \(T\) 个 token 时，每个专家平均分到 \(T\cdot mK/(mN)=TK/N\) 个 token，与切分前相同（Shazeer 所说的“每个专家的批量缩小”问题 10 既没变好也没变坏）。所以每读一遍专家权重所做的计算，即算术强度，也与 \(m\) 无关（练习 12，算术强度见 M10）。变的是矩阵的形状：一次要做 \(mN\) 个更窄的小矩阵乘法，而不是 \(N\) 个宽的，调度开销更大、单个矩阵更难跑满硬件（笔者的分析）。
  • 通信变多。 每个 token 要派发到 \(mK\) 个专家，当专家分布在不同设备上时，派发目的地更多、通信更多。ACL 正式版的“局限”一节承认了这一点 1。第 10 课的设备受限路由正是为此设计的。
  • 路由器变大，打分计算按 \(m\) 倍增长，不过量很小（上例是专家参数的 0.024%）。

DeepSeekMoE 实际选的粒度：2B 与 16B 的专家是标准 FFN 的 0.25 倍（\(m=4\)），145B 是 0.125 倍（\(m=8\)）1。

本页要点
  • 细粒度切分：\(N\) 个专家切成 \(mN\) 个、激活 \(mK\) 个。FFN 是中间神经元贡献之和 (7.14)，所以切分合法；专家参数与激活参数都不变，只有路由器 \(\times m\) (7.15)。
  • 组合数 \(\binom{16}{2}=120\to\binom{64}{8}=4{,}426{,}165{,}368\)；\(\log\) 组合数随 \(m\) 线性增长，斜率 \(N\,H(K/N)\log_{10}2\)（\(N=16,K=2\) 时 2.62 个数量级）。
  • 组合数是动机，不是证明。代价：矩阵变窄变多、硬件效率下降，路由器变大，每个 token 的派发目的地变多（通信），后者是后来设备受限路由的起因。

共享专家隔离

问题。 细粒度切分对付的是混杂。冗余还在：公共知识（语法、常用搭配……）每个 token 都需要，路由专家各自都得学一份。能不能把这部分知识从路由专家里“抽”出来，单独存一份？

图景。 医院设一位全科医生，每位病人都先由他看一遍：量血压、问病史、看常见问题。专科医生就不必各自重复这些事，可以把精力全花在自己的专长上。

定义

含义。 共享专家（shared expert）：不经过路由器、每个 token 都必然激活的专家。共享专家隔离（shared expert isolation）：从细粒度专家里拿出 \(K_s\) 个作为共享专家，同时把路由激活的个数减少 \(K_s\) 个，保持计算量不变 1。

理解。 共享专家是“永远在线”的那一小块 FFN，相当于在 MoE 旁边并联了一个小的稠密 FFN；路由专家则只负责每个 token 特有的那部分知识。

数学。 DeepSeekMoE 论文的式 (9)–(11) 用 \(K_s\) 记共享专家数；DeepSeek-V2 把它改写成下面这套记号 7，本课从这里起统一使用：

  • \(N_s\)：共享专家的个数（论文里的 \(K_s\)）；
  • \(N_r\)：路由专家的个数，\(N_r=mN-N_s\)；
  • \(K_r\)：每个 token 激活的路由专家个数，\(K_r=mK-N_s\)。
DeepSeekMoE 层（V2 记号）\[\mathbf h_t'=\mathbf u_t+\sum_{i=1}^{N_s}\FFN_i^{(s)}(\mathbf u_t)+\sum_{i=1}^{N_r}g_{i,t}\,\FFN_i^{(r)}(\mathbf u_t)\]\(\FFN^{(s)}_i\) 是第 \(i\) 个共享专家，\(\FFN^{(r)}_i\) 是第 \(i\) 个路由专家。共享专家前面没有门控值，相当于权重恒为 1。(7.18)
路由专家的门控\[g_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}\in\TopK\big(\{s_{j,t}\mid1\le j\le N_r\},\,K_r\big),\\ 0, & \text{否则},\end{cases}\qquad s_{i,t}=\softmax_i\big(\mathbf u_t^\top\mathbf e_i\big)\]softmax 只在 \(N_r\) 个路由专家之间做：论文式 (11) 没有写明下标范围，开源代码里路由器的权重形状是（路由专家数, 隐藏维），即只为路由专家打分 6。\(\mathbf e_i\) 是第 \(i\) 个路由专家的中心向量。(7.19)
计算量守恒的记账\[\underbrace{N_s+K_r}_{\text{每 token 激活的专家数}}=mK,\qquad \underbrace{N_s+N_r}_{\text{专家总数}}=mN\]共享专家占掉 \(N_s\) 个激活名额，所以路由只再选 \(K_r=mK-N_s\) 个。(7.20)

回到 §4 的图 7.8，看它的 (c) 行：紫色方块 S 在路由器那条紫色横条的外面，没有被“选”，它总是计算；路由器只在其余 15 个里挑 3 个。紫色加蓝色的总宽度仍是 2 份，与上面几行相同。那一行就是 \(m=2\)、\(N=8\)、\(N_s=1\) 时的 (7.18)–(7.20)：\(N_r=16-1=15\)，\(K_r=2\times2-1=3\)。

两个共享专家 = 一个加宽的 FFN

16B 有 2 个共享专家。它们都不经路由、权重都是 1，那么“两个共享专家”和“一个中间维加倍的共享专家”有区别吗？

两个 SwiGLU 专家之和等于一个中间维相加的 SwiGLU
(1)\(\displaystyle \FFN_a(\mathbf u)+\FFN_b(\mathbf u)=\sum_{j\in\mathcal J_a}\phi_j(\mathbf u)+\sum_{j\in\mathcal J_b}\phi_j(\mathbf u)\)按 (7.14) 展开；\(\phi_j(\mathbf u)=\mathbf w_{2,j}\mathrm{SiLU}(\mathbf w_{1,j}^\top\mathbf u)(\mathbf w_{3,j}^\top\mathbf u)\) 是神经元 \(j\) 的贡献，\(\mathcal J_a,\mathcal J_b\) 是两个专家各自的神经元
(2)\(\displaystyle =\sum_{j\in\mathcal J_a\cup\mathcal J_b}\phi_j(\mathbf u)\)两个有限和合并；逐元素运算不跨神经元，所以没有交叉项
(3)\(\displaystyle =\FFN_{a\cup b}(\mathbf u)\)把 \(W_1,W_3\) 按行、\(W_2\) 按列拼接，得到中间维 \(\lvert\mathcal J_a\rvert+\lvert\mathcal J_b\rvert\) 的一个 SwiGLU
共享专家的等价实现\[\sum_{i=1}^{N_s}\FFN_i^{(s)}(\mathbf u)=\FFN^{(s)}_{\text{宽}}(\mathbf u),\qquad \text{中间维}=N_s\cdot\frac{d_{ff}}{m}\]16B：\(2\times1408=2816\)，参数 \(3\times2048\times2816=17{,}301{,}504=2\times8{,}650{,}752\)。(7.21)

开源代码正是这样实现的：共享专家是一个中间维为 moe_intermediate_size * n_shared_experts \(=2816\) 的 MLP 6。这和论文说的“2 个共享专家”在数学上完全等价，读代码时不要误以为“共享专家比路由专家大一倍”。由此也可以看出，共享专家的个数 \(N_s\) 本身没有独立的意义，有意义的是它们的总宽度。论文为什么用“个数”来描述，原文没有解释；笔者的理解是，这样可以和细粒度专家用同一个单位记账。

这个想法从哪里来

共享专家不是 DeepSeek 首创。DeepSeekMoE 论文自己指出，共享专家隔离的原型可以归功于 DeepSpeed-MoE 的 Rajbhandari 等人，区别在于他们是从工程角度得出这个策略，而 DeepSeekMoE 是从算法角度 1；ACL 正式版还补充致谢了 Elbayad 等人 2023 年的工作。DeepSpeed-MoE 的 Residual-MoE 让每个 token 固定经过一个稠密 MLP，再加一个被选中的专家，把专家看成对稠密 MLP 的“误差修正项” 16。DeepSeekMoE 的贡献是从“知识冗余”的角度重新论证它，把它和细粒度切分组合起来，并做了规模化验证。

常见误解：共享专家是 DeepSeek 发明的

不对，原型是 DeepSpeed-MoE 的 Residual-MoE（ICML 2022）16，DeepSeekMoE 论文明确承认了这一点 1。准确的说法是：DeepSeekMoE 提出了“共享专家承载公共知识、减少路由专家冗余”这个算法解释，并把它和细粒度切分一起做成了后来 DeepSeek 全系沿用的结构。

证据：去掉共享专家会怎样

实测（2B 规模，Pile 验证集损失，越低越好）1：

  • 共享专家不可替代。 把训练好的 DeepSeekMoE 2B 的共享专家禁用，同时多激活 1 个路由专家，保持计算量不变：Pile 损失从 1.808 升到 2.414，上升 0.606（33.5%）。换句话说，路由专家里没有谁能顶替共享专家学到的东西。
  • 共享与路由的比例影响不大。 保持 64 个专家、每 token 激活 8 个不变，用 1 个、2 个、4 个共享专家（即激活的共享 : 路由为 1:7、2:6、4:4）时，Pile 损失分别是 1.808、1.806、1.811。2 个共享专家（1:3）略好，所以放大规模时论文保持共享 : 激活路由 \(=1:3\)：16B 是 2 + 6，145B 是 4 + 12。
算一算“1:3”

64 个专家、激活 8 个的前提下：1 个共享 + 7 个路由是 1:7；2 个共享 + 6 个路由是 2:6 = 1:3；4 个共享 + 4 个路由是 1:1。所以“1:3”对应的是 Pile 损失 1.806 的那一档，而不是 2B 主模型（1 共享 + 7 路由，1.808）。差距只有 0.002–0.005，论文自己也说是“略好”，这个比例更像一个合理的默认值，而不是被精确优化出来的最优点。

一个值得注意的细节：共享专家的“声音”更大

由 (7.18) 与 (7.19)，共享专家的输出以权重 1 加进来，而路由专家的门控值是未归一化的 softmax 概率，加起来小于 1（§7 例题中四个 token 分别是 0.65、0.69、0.59、0.49）。这是论文公式与发布配置的直接推论（norm_topk_prob: false）6；至于它对训练有什么影响，论文没有讨论，这里不下结论。DeepSeek-V3 改用 sigmoid 亲和度并在选中的专家间归一化 15，按论文公式，路由部分的总权重就变成了 1。这笔账只对论文公式成立：V2 与 V3 发布的代码还会给路由门控值再乘一个论文没写的常数，V2 是不归一化再乘 16（第 10 课 §1），V3 是归一化之后乘 2.5（第 11 课 §2），所以在代码里，V3 路由部分的总权重恒为 2.5，V2 的是选中概率之和的 16 倍，都不能再简单地说“比共享专家的 1 小”。

失败模式：共享专家不是越多越好
  • 共享份额过大，路由就没东西可选。 激活名额固定为 \(mK\) 时，每多一个共享专家，路由就少选一个。2B 消融里 4 共享 + 4 路由（1.811）已经略差于 2 + 6（1.806）。推到极端（笔者的推理）：8 个名额全给共享专家，这一层就退回一个中间维为 2 个标准 FFN 的稠密 FFN，其余 56 个路由专家永远不会被选中，参数白白占着显存。
  • 共享专家的计算每个 token 都要付。 16B 里共享专家占每 token 激活参数的 16.5%（图 7.14），这一块不会因为路由而省下来。
  • “承载公共知识”是解释，不是测量。 1.808 → 2.414 说明共享专家难以替代；至于它装的是不是“语法与常识”，论文没有直接检查（§4 的警告同样适用）。
类比回顾：全科医生

映射。 共享专家 = 每位病人都要看的全科医生；路由专家 = 专科医生；“1 个共享专家禁用、多挂 1 个专科号”= 取消全科医生，让病人多看一位专科医生。

收益。 损失从 1.808 跳到 2.414 这个实验，用类比说就是：多看一位专科医生补不回全科医生的那部分工作，因为专科医生们都默认“基础的事有人做了”，没有人再学它。

失效的地方。 真实的全科医生先看、专科医生后看，是串行的；共享专家和路由专家是并联的，同时读同一个 \(\mathbf u_t\)，输出直接相加。另外全科医生的职责是规定好的，共享专家学什么完全由训练决定。

本页要点
  • 共享专家不经路由、每个 token 必经，权重恒为 1；路由再选 \(K_r=mK-N_s\) 个，计算量不变 (7.18)–(7.20)。本课起使用 V2 记号 \(N_s,N_r,K_r\)。
  • 多个共享专家等价于一个加宽的 FFN (7.21)，代码就是这样实现的。
  • 原型是 DeepSpeed-MoE 的 Residual-MoE。实测：去掉共享专家（多激活一个路由专家补足计算）Pile 损失 1.808 → 2.414；共享 : 激活路由的比例影响很小，取 1:3。

专家级与设备级均衡损失

共享专家不经路由，不存在负载问题；需要均衡的是 \(N_r\) 个路由专家。DeepSeekMoE 的 arXiv v1 在 §3 给出两项均衡损失 1：专家级（expert-level）损失防止路由坍缩，设备级（device-level）损失防止设备之间计算不均。这一页把两者的每个符号拆开，用一个 4 个 token 的小批次逐项算一遍，最后说清楚三个规模的模型各用了哪一项、系数是多少。

先说版本差异

设备级损失只出现在 arXiv v1 里。ACL 2024 正式版正文只保留了一项 \(\mathcal L_{Bal}=\alpha\sum_{i}f_iP_i\)，与下面的专家级损失同形，全文没有设备级损失 1。而且即使在 arXiv v1 里，2B 与 16B 模型也没有使用设备级损失（本页最后一节）。

专家级均衡损失

含义。 一项加在语言模型损失上的小惩罚，路由专家之间的负载越不均，它越大。

理解。 它就是 §3 的 Switch 损失 \(\alpha N\sum f_iP_i\)，推广到“每个 token 选 \(K_r\) 个专家”的情形，并把 \(f_i\) 换了一种归一化，让均匀时每个 \(f_i\) 都等于 1。

数学。 论文式 (12)–(14)，换成本课记号 1：

专家级均衡损失\[\mathcal L_{\mathrm{ExpBal}}=\alpha_1\sum_{i=1}^{N_r}f_i\,P_i\](7.22)
归一化负载\[f_i=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb 1\big(\text{token }t\text{ 选中专家 }i\big)\](7.23)
平均亲和度\[P_i=\frac1T\sum_{t=1}^{T}s_{i,t}\](7.24)

逐个符号：

  • \(\alpha_1\)：专家级均衡因子，一个手调的超参数，决定这项损失有多大分量。
  • \(N_r\)：路由专家数，论文写作 \(N'=mN-K_s\)。求和只跑路由专家，共享专家不参与。
  • \(K_r\)：每个 token 激活的路由专家数，论文写作 \(K'=mK-K_s\)。
  • \(T\)：参与统计的 token 数。DeepSeekMoE 论文在 §2 把 \(T\) 定义为序列长度；开源代码默认 seq_aux=True，即每条序列单独算 \(f_i\)、\(P_i\) 和损失，再对 batch 求平均 6。这和 Switch 在整个 batch 上统计不同。注意：论文的训练是在自研框架 HAI-LLM 上做的 1，Hugging Face 上的代码是随模型发布的实现，并不是训练代码本身；两者只能在公式层面对照，代码的默认值不能直接当作论文训练时的设置。
  • \(\mathbb 1(\cdot)\)：指示函数。注意这里数的是全部 \(K_r\) 次选择，而不只是首选（GShard 的 \(c_e\) 只数首选）。
  • \(s_{i,t}\)：(7.19) 的亲和度，对 \(N_r\) 个路由专家做 softmax 的结果，可导。
  • \(f_i\)：专家 \(i\) 的归一化负载，不可导，求梯度时当作常数；均匀时为 1。
  • \(P_i\)：专家 \(i\) 的平均亲和度，可导，梯度经由它回到路由器；均匀时为 \(1/N_r\)。
专家级损失的两个参照值
(1)\(\displaystyle \sum_{i}f_i=\dfrac{N_r}{K_rT}\sum_{t}\sum_{i}\mathbb 1(t\text{ 选中 }i)\)代入 (7.23)，交换两个求和的次序
(2)\(\displaystyle =\dfrac{N_r}{K_rT}\cdot K_rT=N_r\)每个 token 恰好选中 \(K_r\) 个专家，内层和等于 \(K_r\)
(3)\(\displaystyle \text{均匀：}\ \sum_if_iP_i=\sum_i1\cdot\tfrac{1}{N_r}=1\)每个专家被 \(K_rT/N_r\) 个 token 选中，\(f_i=1\)；亲和度平均分配，\(P_i=1/N_r\)
(4)\(\displaystyle \text{坍缩：}\ \sum_if_iP_i=K_r\cdot\tfrac{N_r}{K_r}\cdot\tfrac{1}{K_r}=\tfrac{N_r}{K_r}\)全部 token 都选同一组 \(K_r\) 个专家并平分亲和度：这些专家 \(f_i=N_r/K_r\)、\(P_i=1/K_r\)，其余 \(f_i=0\)
专家级损失的尺度\[\underbrace{\alpha_1}_{\text{均匀路由}}\qquad\longleftrightarrow\qquad\underbrace{\alpha_1\,\frac{N_r}{K_r}}_{\text{全部坍缩到 }K_r\text{ 个专家}}\]16B（\(N_r=64,K_r=6\)）：从 \(\alpha_1\) 到 \(10.67\alpha_1\)；2B（\(63,7\)）：到 \(9\alpha_1\)。(7.25)

右端是一个上界，而且是紧的：一个专家最多被全部 \(T\) 个 token 选中，所以每个 \(f_i\le N_r/K_r\)；又 \(\sum_iP_i=1\)，于是 \(\sum_if_iP_i\le\max_if_i\cdot\sum_iP_i\le N_r/K_r\)。严格说，softmax 给每个专家的概率都大于 0，其余专家的 \(P_i\) 不可能恰好为 0，所以这个上界只能无限逼近、不能恰好取到；上面“坍缩”一行写的是这个极限情形。左端不是下界：若 \(f\) 不均，而忙专家的 token 都是“勉强选中”、空闲专家的 token 都是“很有把握地选中”，损失可以低于 \(\alpha_1\)。例如 \(N_r=2\)、\(K_r=1\)：3/4 的 token 以 \(s\approx(0.5,0.5)\) 勉强选专家 1，1/4 的 token 以 \(s\approx(0,1)\) 选专家 2，则 \(f=(1.5,0.5)\)、\(P\approx(0.375,0.625)\)，\(\sum_if_iP_i\approx0.5625+0.3125=0.875<1\)。这正是 §3 说的“往空闲专家推”的方向。

与 Switch 的关系。 令 \(K_r=1\)，(7.23) 变成 \(f_i=N_r\cdot\frac{\text{次数}_i}{T}=N_r\tilde f_i\)，其中 \(\tilde f_i\) 是 Switch 意义下的比例；代入 (7.22) 得 \(\alpha_1N_r\sum_i\tilde f_iP_i\)，正是 (7.10)。所以 (7.23) 里的 \(1/K_r\) 只是把“每个 token 被数了 \(K_r\) 次”抵消掉，让均匀值仍然是 \(\alpha_1\)。

一个 4 token 的批次，逐项算专家级损失

\(N_r=8\)、\(K_r=2\)、\(T=4\)。四个 token 的路由 logit 分别是

\[\begin{aligned}&(2,\ 1.5,\ 0.5,\ 0,\ 0,\ 0,\ 0,\ -0.5),\quad(2,\ 0.2,\ 1.8,\ 0,\ 0,\ 0,\ -0.3,\ 0),\\&(1.6,\ 1.4,\ 0,\ 0.2,\ 0,\ 0,\ 0,\ 0),\quad(0,\ 0,\ 0.1,\ 1.2,\ 1.1,\ 0.3,\ 0,\ 0).\end{aligned}\]

亲和度与选择。 逐行 softmax（图 7.11 ①）。token 1 选专家 {1, 2}（0.408、0.247），token 2 选 {1, 3}，token 3 选 {1, 2}，token 4 选 {4, 5}。

\(f_i\)。 被选次数 \((3,2,1,1,1,0,0,0)\)，乘以 \(\frac{N_r}{K_rT}=\frac{8}{2\times4}=1\)，所以 \(f=(3,2,1,1,1,0,0,0)\)；和为 8 \(=N_r\)，与推导一致。

\(P_i\)。 各列平均：\(P=(0.2980,\ 0.1637,\ 0.1387,\ 0.1117,\ 0.1019,\ 0.0695,\ 0.0593,\ 0.0572)\)。

损失。 把 \(P\) 多保留一位小数：\(P_{1..5}=(0.29800,\ 0.16368,\ 0.13873,\ 0.11168,\ 0.10186)\)。于是 \(\sum_if_iP_i=3P_1+2P_2+(P_3+P_4+P_5)=0.89400+0.32736+0.35227=1.57363\approx1.5736\)。（直接用上面 4 位小数的 \(P\) 会得到 1.5737，差在最后一位的舍入。）即 \(\mathcal L_{\mathrm{ExpBal}}=1.5736\,\alpha_1\)，介于均匀的 \(\alpha_1\) 与坍缩的 \(4\alpha_1\) 之间。

梯度往哪推：token 1 的路由 logit

和 (7.12) 同样的推导（这里 \(f\) 已归一化，前面没有 \(N\)）给出 \(\partial\mathcal L_{\mathrm{ExpBal}}/\partial z_{j,t}=\frac{\alpha_1}{T}s_{j,t}(f_j-\bar f_t)\)，\(\bar f_t=\sum_is_{i,t}f_i\)。

token 1：\(\bar f_1=0.4076\times3+0.2473\times2+0.0910\times1+0.0552\times1+0.0552\times1=1.9188\)。于是

  • 专家 1：\(\frac{1}{4}\times0.4076\times(3-1.9188)=0.1102\)（单位 \(\alpha_1\)），正的梯度，梯度下降压低它的 logit；
  • 专家 2：\(\frac14\times0.2473\times(2-1.9188)=0.0050\)，几乎不动；
  • 专家 3：\(\frac14\times0.0910\times(1-1.9188)=-0.0209\)，负的梯度，logit 被抬高；专家 6、7（\(f=0\)）各 \(-0.0265\)，也被抬高。

最忙的专家 1 被压，空闲的专家被抬，力度按亲和度 \(s_{j,1}\) 加权，与 §3 的结论一致。

设备级均衡损失

问题。 把专家分布到多台设备上时，真正拖慢训练的是最忙的那台设备。专家级损失要求每个专家都均衡，但同一台设备上的几个专家之间忙闲不均，其实不影响这台设备的总工作量。论文的判断是：为了缓解计算瓶颈，没必要在专家级强加严格的均衡，因为过强的均衡约束会损害模型性能；主要目标应当是设备之间计算均衡 1。

含义。 设备级均衡损失：以“设备”为单位统计负载与亲和度，只惩罚设备之间的不均。

理解。 回到医院：一栋楼（设备）里有几个科室（专家）。院方关心的是每栋楼的电梯和走廊别堵死，至于同一栋楼里心内科比消化科忙一点，可以不管。

数学。 把 \(N_r\) 个路由专家分成 \(D\) 组 \(\{\mathcal E_1,\dots,\mathcal E_D\}\)，每组放在一台设备上。论文式 (15)–(17) 1：

设备级均衡损失\[\mathcal L_{\mathrm{DevBal}}=\alpha_2\sum_{i=1}^{D}f_i'\,P_i'\]\(\alpha_2\) 是设备级均衡因子，\(D\) 是设备数。(7.26)
设备的负载与亲和度\[f_i'=\frac{1}{\lvert\mathcal E_i\rvert}\sum_{j\in\mathcal E_i}f_j,\qquad P_i'=\sum_{j\in\mathcal E_i}P_j\]\(\mathcal E_i\) 是第 \(i\) 台设备上的路由专家集合，\(\lvert\mathcal E_i\rvert\) 是其中的专家个数。\(f'\) 取组内平均（\(f_j\) 已经归一化，均匀时为 1，取平均后仍是 1）；\(P'\) 取组内求和（\(P_j\) 是概率，求和得到这台设备分到的总概率，均匀时为 \(\lvert\mathcal E_i\rvert/N_r\)，各组大小相同时就是 \(1/D\)）。无论各组大小是否相同，均匀路由时都有 \(\sum_if_i'P_i'=\sum_i1\cdot\lvert\mathcal E_i\rvert/N_r=1\)。(7.27)
各组大小相同时，设备级损失就是“以设备为专家”的 Switch 损失
(1)\(\displaystyle f_i'=\dfrac{1}{\lvert\mathcal E_i\rvert}\sum_{j\in\mathcal E_i}\dfrac{N_r}{K_rT}\,\text{次数}_j\)代入 (7.23)
(2)\(\displaystyle =\dfrac{N_r}{\lvert\mathcal E_i\rvert}\cdot\dfrac{\sum_{j\in\mathcal E_i}\text{次数}_j}{K_rT}=D\,F_i\)设 \(\lvert\mathcal E_i\rvert=N_r/D\)；\(F_i\) 是设备 \(i\) 承接的选择次数占全部 \(K_rT\) 次的比例
(3)\(\displaystyle \mathcal L_{\mathrm{DevBal}}=\alpha_2\,D\sum_{i=1}^{D}F_i\,P_i'\)代回 (7.26)：与 (7.10) 同形，“专家数”换成设备数 \(D\)
(4)\(\displaystyle \text{均匀：}\ \mathcal L_{\mathrm{DevBal}}=\alpha_2\)均匀时 \(F_i=P_i'=\tfrac1D\)，代入上一行得 \(\alpha_2\cdot D\cdot D\cdot\tfrac1{D^2}\)；与专家级损失一样，均衡时等于系数本身
同一个批次的设备级损失

专家 1–4 放在设备 A，5–8 放在设备 B（\(D=2\)，每组 4 个）。

  • \(f'_A=(3+2+1+1)/4=1.75\)，\(f'_B=(1+0+0+0)/4=0.25\)。换成比例：设备 A 承接了 \(F_A=1.75/2=87.5\%\) 的选择。
  • \(P'_A=0.2980+0.1637+0.1387+0.1117=0.7121\)，\(P'_B=0.2879\)。
  • \(\mathcal L_{\mathrm{DevBal}}=\alpha_2(1.75\times0.71209+0.25\times0.28791)=\alpha_2(1.24616+0.07198)=1.3181\,\alpha_2\)。

对照专家级的 1.5736：设备 A 内部专家 1 与专家 3 的忙闲之差，在设备级损失里完全看不见。这正是设计意图：只管设备之间，不管设备之内。

笔者的一个推论：放在同一台设备上时，设备级损失失去作用

若一层的全部路由专家都在同一台设备上（\(D=1\)），则 \(f_1'\) 是全部 \(f_j\) 的平均 \(=1\)，\(P_1'=\sum_jP_j=1\)，\(\mathcal L_{\mathrm{DevBal}}\equiv\alpha_2\)，是个常数，梯度为零。这和 16B 的做法吻合：16B 训练时每层的全部专家放在同一台设备上，也就没有使用设备级损失（见下一节）。

三个规模实际怎么用

总的训练目标是语言模型损失加上辅助损失：

DeepSeekMoE 的训练损失\[\mathcal L=\mathcal L_{\mathrm{LM}}+\mathcal L_{\mathrm{ExpBal}}+\mathcal L_{\mathrm{DevBal}}\]\(\mathcal L_{\mathrm{LM}}\) 是下一词预测的交叉熵（第 2 课）。两项辅助损失的分量由 \(\alpha_1\)、\(\alpha_2\) 控制；不用某一项时，就是把它的系数设为 0。(7.28)

论文的实际设置 1：

规模 \(\alpha_1\)（专家级） \(\alpha_2\)（设备级） 专家放置 丢 token
2B（验证） 0.01 不用 — 不丢
16B 0.001 不用 每层全部专家在同一台设备 不丢
145B（arXiv v1，初步） 0.003 0.05 路由专家均匀放在 4 台设备 未说明

几点解读：

  • 原则写在论文里：用一个小的专家级因子防止路由坍缩，再用一个较大的设备级因子促进设备间的计算均衡。145B 的 \(\alpha_2=0.05\) 比 \(\alpha_1=0.003\) 大约 17 倍，符合这个原则。
  • 16B 的 \(\alpha_1\) 特别小（0.001）。论文给的理由是：在他们的并行策略下，更大的专家级因子不能提高计算效率，反而损害模型性能。发布的配置与代码默认值也是 0.001 6；后来的 DeepSeek-V2-Lite 同样只用了 \(\alpha_1=0.001\) 的专家级损失 7,17。
  • 16B 的损失有多小：由图 7.12，即使完全坍缩，专家级损失也只有 \(10.67\times0.001\approx0.0107\)，相比语言模型损失（本课引用的各个训练完成的模型，Pile 损失都在 1.8–2.1 之间）微不足道。它的作用靠的是梯度方向，而不是数值大小。
类比延伸：按楼平衡，而不是按科室平衡

映射。 设备 = 一栋门诊楼；专家 = 楼里的科室；专家级损失 = 考核每个科室的接诊量；设备级损失 = 只考核每栋楼的总接诊量。

收益。 它解释了为什么设备级损失可以用大系数而专家级只用小系数：按楼考核给分诊台留下了在同一栋楼内自由选择最对口科室的余地，损害小；按科室严格考核则会逼着分诊台把病人送到不对口的科室。

失效的地方。 真实的楼是固定的，MoE 里“哪些专家放在一起”由工程师决定，放置方式本身就会改变设备级损失的含义；另外设备之间的瓶颈除了计算还有通信，DeepSeek-V2 为此又加了第三项通信均衡损失（第 10 课）。

常见误解：DeepSeekMoE 16B 用专家级 + 设备级两个损失训练

不对。设备级损失只在 arXiv v1 的 145B 初步实验里用过（\(\alpha_2=0.05\)）；2B（\(\alpha_1=0.01\)）和 16B（\(\alpha_1=0.001\)）都只用专家级损失，也都不丢 token 1。ACL 正式版里根本没有设备级损失。另一个容易混淆的地方：DeepSeek-V3 也有一个“序列级辅助损失”。它的公式和统计范围与这里 seq_aux=True 时的专家级损失同形（都按一条序列统计 \(f_i\)、\(P_i\)），不同在三处：亲和度换成 sigmoid 后再在全部路由专家上归一化，系数小到 \(10^{-4}\)，而且它不再是主要的均衡手段，只是配合无辅助损失偏置的护栏（第 11 课 §5）。

本页要点
  • 专家级损失 \(\alpha_1\sum_if_iP_i\)，\(f_i=\frac{N_r}{K_rT}\cdot\)次数（均匀为 1，\(\sum f_i=N_r\)），\(P_i\) 为平均亲和度；均匀时为 \(\alpha_1\)，全坍缩时为 \(\alpha_1N_r/K_r\)（这也是它的上界）；\(K_r=1\) 时退化为 Switch 损失。
  • 设备级损失 \(\alpha_2\sum_if_i'P_i'\)，\(f'\) 取组内平均、\(P'\) 取组内求和；等组时就是“以设备为专家”的 Switch 损失，只管设备之间。
  • 实际用法：2B 与 16B 只用小的专家级损失（0.01、0.001）；只有 145B 初步实验用了设备级（0.05）；ACL 正式版只保留一项。

专精的间接证据

论文用三类实验支持“DeepSeekMoE 的专家更专精”（实测，2B 规模）1：

  1. 路由专家更不可替代。 逐步禁用排名最靠前的路由专家（按比例），DeepSeekMoE 的 Pile 损失上升得比 GShard×1.5 更快（两者不禁用时 Pile 损失相同）。论文的解读是：每个路由专家更难被替代，说明参数冗余更低。
  2. 共享专家不可替代。 禁用共享专家、多激活一个路由专家：1.808 → 2.414（§6）。
  3. 少激活几个专家也够。 只激活 4 个路由专家时，DeepSeekMoE 的 Pile 损失就与 GShard 相当；从头训练一个 1 共享 + 63 路由只选 3 个的模型（激活的专家参数只有一半），仍然优于 GShard。

这些都是间接证据：它们说明 DeepSeekMoE 的专家“更难互相替代”“用得更经济”，但没有直接看专家里存了什么（§4 的警告仍然成立）。

强项。 论文指出，16B 相对 DeepSeek 7B 的优势集中在语言建模与知识密集型任务上（Pile、HellaSwag、TriviaQA、NaturalQuestions），并把这一点和“Transformer 的 FFN 负责记忆知识”的观点联系起来：MoE 模型里 FFN 的参数远多于注意力 1。这与 §1 的“知识容量随 \(N_{total}\) 增长”方向一致，但仍是相关性的观察，不是因果证明。

弱项。 16B 在多项选择题式的考试上落后于 DeepSeek 7B：MMLU 45.0 vs 48.2，CEval 40.6 vs 45.0，CMMLU 42.5 vs 47.2。论文把原因归于 16B 的注意力参数少。按配置复算，16B 的注意力参数是 \(28\times4\times2048^2\approx0.47\)B，DeepSeek 7B 是 \(30\times4\times4096^2\approx2.01\)B（笔者复算）；arXiv v1 写的是约 0.5B 和 2.5B，后一个数与复算不符，ACL 正式版删去了这两个数字，只保留定性说法 1。这个弱项也提醒我们：MoE 只稀疏化了 FFN，注意力那一侧的账要另算。

部署。 论文与仓库说明 16B 可以在单张 40GB 显存的 GPU 上不经量化直接部署 1,19。复算：BF16 权重 \(16{,}375{,}728{,}128\times2=32.75\) GB，剩下约 7 GB 给 KV cache 和激活。它用的是标准多头注意力，每个 token 的 KV cache 是 \(2\times16\times128\times28\times2=229{,}376\) 字节（224 KiB），4K 上下文每条序列约 0.94 GB。论文还说经过适当的算子优化后，推理速度接近 7B 稠密模型的 2.5 倍，但没有给出测量设置，这个数字本课未能核实。

往后看：同样的 MoE，换一种注意力

DeepSeek-V2-Lite（2024 年 5 月）的 FFN 部分与 16B 完全相同：2 个共享 + 64 个路由专家选 6 个、专家中间维 1408、首层稠密、\(\alpha_1=0.001\)；它换掉的是注意力，用 MLA 把每 token 的 KV cache 降到 \((512+64)\times27\times2=31{,}104\) 字节，是 16B 的 1/7.37 7,17。这是第 9 课的主题。

145B：只在 arXiv v1 里的初步结果

arXiv v1 的最后一节标题就叫 “DeepSeekMoE 145B Ongoing”：62 层、隐藏维 4096、32 头，4 个共享 + 128 个路由专家选 12 个，专家是标准 FFN 的 0.125 倍；只训练了 245B token；路由专家均匀放在 4 台设备上，\(\alpha_1=0.003\)、\(\alpha_2=0.05\) 1。论文表 6 的结果（实测，初步）：

概念题

练习 1 · MoE 省的是什么

（a）一个 MoE 模型总参数 16.4B、激活参数 2.8B。推理时它的显存需求更接近哪个数？每 token 的计算量更接近哪个数？（b）为什么说 MoE 的“知识容量随总参数增长”是经验规律而不是定理？（c）16B 在 MMLU 上落后于 DeepSeek 7B，这与 MoE“只稀疏化了哪一部分”有什么关系？

看答案

（a）显存更接近 16.4B：所有专家都必须随时可用，BF16 权重约 32.75 GB。计算量更接近 2.8B：每 token 前向约 \(2\times2.83\text{B}\approx5.7\) GFLOPs（(7.2)，激活参数取复算值 2,828,650,496）。

（b）“容量”没有一个被严格定义并证明与参数量成正比的量；我们看到的是实验现象：同样的激活参数下，总参数更多的 MoE 模型损失更低（例如 §8 的 2B 实验）。它可能在某些规模、某些数据上不成立。

（c）MoE 只把 FFN 换成了专家，注意力仍是稠密的、而且变小了（16B 的注意力约 0.47B，DeepSeek 7B 约 2.01B，按配置复算）。论文把多选题上的落后归因于注意力参数少，也就是说，MoE 省下的计算并没有补到注意力那一侧。

练习 2 · 组合数下降，效果却提高

消融实验中，从 GShard（16 选 2）改成“1 个共享专家 + 15 选 1”，路由组合数从 120 降到 15，多数基准却变好了。这说明什么？细粒度切分的收益能不能完全用“组合数变大”来解释？

看答案

说明组合数不是性能的充分解释。共享专家的收益来自“公共知识不必在每个路由专家里重复存”（冗余论点），与组合数无关，甚至在组合数减少 8 倍时依然成立。细粒度切分的收益同样不能只归功于组合数：组合数只数无序集合，不计门控值的连续变化，而且论文没有直接测量专家学到了什么。组合数是一个有启发性的动机，不是被证明的机制。

练习 3 · 门控顺序与梯度

路由 logit 为 \((2,\ 1,\ 0.5,\ 0.2,\ 0,\ -0.3,\ -0.5,\ -1)\)，\(k=2\)。（a）分别按 DeepSeekMoE（softmax 后取 top-2、不归一化）、Mixtral（top-2 logit 上 softmax）、GShard（softmax、top-2、再归一化）算出两个门控值。（b）若 \(k=1\)，Mixtral 式门控对路由器参数的梯度是多少？Switch 式呢？

看答案

（a）\(e^{z}\)：\(7.3891,\ 2.7183,\ 1.6487,\ 1.2214,\ 1,\ 0.7408,\ 0.6065,\ 0.3679\)，和 \(15.6927\)。DeepSeekMoE：\((0.4709,\ 0.1732)\)，和 \(0.6441\)。Mixtral：\(e^2/(e^2+e^1)=1/(1+e^{-1})=0.7311\) 与 \(0.2689\)。GShard：\(0.4709/0.6441=0.7311\)、\(0.1732/0.6441=0.2689\)，与 Mixtral 完全相同（§2 的推导）。

（b）\(k=1\) 时 Mixtral 式门控值恒为 \(e^{z_1}/e^{z_1}=1\)，与路由器参数无关，梯度为 0；这与 Shazeer 所说“\(k>1\) 才有非零导数”一致。Switch 式门控值是对全部专家 softmax 后的 \(p_1=0.4709\)，随 logit 连续变化，路由器有梯度。

计算题

练习 4 · 数组合

（a）16 个专家选 2 个有多少种组合？切成 4 份后 64 个选 8 个呢？（b）DeepSeekMoE 16B（64 个路由专家选 6 个）呢？为什么比（a）的第二问少得多？（c）Mixtral 呢？

看答案

（a）\(\binom{16}{2}=120\)；\(\binom{64}{8}=4{,}426{,}165{,}368\)。

（b）\(\binom{64}{6}=74{,}974{,}368\)，约为 \(\binom{64}{8}\) 的 1/59。因为 16B 的 8 个激活名额里有 2 个给了共享专家，路由只从 64 个里选 6 个；在 \(k\ll n\) 时组合数随 \(k\) 增长很快，少选 2 个就少了一个多数量级。

（c）\(\binom82=28\)。

练习 5 · 参数守恒

\(d=2048\)，标准 SwiGLU FFN 的中间维 5632，一层有 16 个这样的专家、每 token 激活 2 个。切分粒度 \(m=8\)。（a）每个小专家多少参数？专家参数总量变不变？（b）每 token 激活多少个小专家、多少专家参数？（c）路由器参数从多少变成多少？

看答案

（a）中间维 \(5632/8=704\)，每个 \(3\times2048\times704=4{,}325{,}376\)；128 个共 \(553{,}648{,}128\)，与切分前 \(16\times34{,}603{,}008\) 相同。

（b）\(2\times8=16\) 个，\(16\times4{,}325{,}376=69{,}206{,}016=2\times34{,}603{,}008\)，不变。

（c）\(16\times2048=32{,}768\) 变为 \(128\times2048=262{,}144\)，乘了 8；占专家参数的 \(0.047\%\)。

用配置（28 层，\(d=2048\)，词表 102,400，首层稠密 FFN 中间维 10944，其余 27 层为 2 共享 + 64 路由选 6、专家中间维 1408，多头注意力，嵌入与输出头不共享，忽略偏置）复算总参数与激活参数。激活参数去掉输入嵌入和输出头后是多少？

专家 \(e=3\times2048\times1408=8{,}650{,}752\)。MoE 层总 \(66e+64\times2048=571{,}080{,}704\)，激活 \(8e+64\times2048=69{,}337{,}088\)。公共部分：嵌入与输出头 \(2\times102400\times2048=419{,}430{,}400\)；注意力 \(28\times4\times2048^2=469{,}762{,}048\)；首层 FFN \(3\times2048\times10944=67{,}239{,}936\)；归一化 \(116{,}736\)。

练习 7 · 容量因子

1024 个 token、8 个专家、top-1 路由，负载为 \((200,150,130,120,120,110,100,94)\)。（a）容量因子 1.0、1.25、2.0 时各丢弃多少 token？（b）容量因子 2.0 时有多少“空槽”？这意味着什么？（c）如果负载完全均匀，容量因子 1.0 会丢 token 吗？

看答案

（a）容量 \(1024/8\times\text{CF}\) = 128、160、256。CF 1.0：超出 \(72+22+2=96\) 个（9.4%）；CF 1.25：只有专家 1 超出 40 个（3.9%）；CF 2.0：0 个。

（b）\(8\times256=2048\) 个槽位只用了 1024 个，空 1024 个：一半的专家矩阵计算在处理补零，算力白花。

（c）不会：每个专家恰好 128 个，正好装满。但真实路由从不完全均匀，这正是需要负载均衡损失的原因之一。

练习 8 · 均衡损失与专家放置

沿用 §7 的 4 个 token、8 个路由专家的例子：\(f=(3,2,1,1,1,0,0,0)\)，\(P=(0.2980,\ 0.1637,\ 0.1387,\ 0.1117,\ 0.1019,\ 0.0695,\ 0.0593,\ 0.0572)\)。（a）复核 \(\mathcal L_{\mathrm{ExpBal}}/\alpha_1=1.5736\)。（b）如果把专家 \(\{1,6,7,8\}\) 放在设备 A、\(\{2,3,4,5\}\) 放在设备 B，设备级损失 \(\mathcal L_{\mathrm{DevBal}}/\alpha_2\) 是多少？和 §7 的放法（1–4 / 5–8）比较，说明什么？

看答案

（a）用 5 位小数的 \(P\)：\(3(0.29800)+2(0.16368)+(0.13873+0.11168+0.10186)=0.89400+0.32736+0.35227=1.57363\approx1.5736\)。只用题目给的 4 位小数会得到 1.5737，差别来自舍入。

（b）\(f'_A=(3+0+0+0)/4=0.75\)，\(f'_B=(2+1+1+1)/4=1.25\)；\(P'_A=0.2980+0.0695+0.0593+0.0572=0.4840\)，\(P'_B=0.5160\)。\(\mathcal L_{\mathrm{DevBal}}/\alpha_2=0.75\times0.4840+1.25\times0.5160=0.3630+0.6450=1.0080\)，几乎等于完全均衡时的 1；§7 的放法是 1.3181。

同一组路由结果，换一种专家放置，设备间的负载就从“设备 A 承接 87.5% 的选择”变成“A 37.5%、B 62.5%”。设备级损失衡量的是“路由 + 放置”的组合：除了调整路由，把常被一起选中的忙专家分散到不同设备，也能缓解设备间的不均。第 12 课讲推理部署时还会遇到按负载安排专家的问题。

推导题

练习 9 · 专家级损失的两端与坍缩曲线

（a）由 (7.23) 证明 \(\sum_if_i=N_r\)。（b）证明均匀路由时 \(\mathcal L_{\mathrm{ExpBal}}=\alpha_1\)，全部 token 坍缩到同一组 \(K_r\) 个专家（并平分亲和度）时 \(\mathcal L_{\mathrm{ExpBal}}=\alpha_1N_r/K_r\)。（c）若比例 \(\lambda\) 的 token 坍缩到这 \(K_r\) 个专家、其余均匀路由，推导图 7.12 的曲线公式并尽量化简，算出 16B（\(N_r=64,K_r=6\)）在 \(\lambda=0.5\) 时的值。

看答案

（a）\(\sum_if_i=\frac{N_r}{K_rT}\sum_t\sum_i\mathbb 1(t\text{ 选 }i)=\frac{N_r}{K_rT}\cdot K_rT=N_r\)，因为每个 token 恰好选 \(K_r\) 个专家。

（b）均匀：每个专家被 \(K_rT/N_r\) 个 token 选中，\(f_i=1\)；\(P_i=1/N_r\)；\(\sum_if_iP_i=N_r\cdot\frac1{N_r}=1\)。坍缩：\(K_r\) 个专家各被全部 \(T\) 个 token 选中，\(f_i=\frac{N_r}{K_rT}\cdot T=\frac{N_r}{K_r}\)，\(P_i=\frac1{K_r}\)；其余 \(f_i=0\)；\(\sum_if_iP_i=K_r\cdot\frac{N_r}{K_r}\cdot\frac1{K_r}=\frac{N_r}{K_r}\)。

（c）对坍缩组里的专家：坍缩 token 贡献 \(\lambda T\) 次选择，均匀 token 贡献 \((1-\lambda)T\cdot K_r/N_r\) 次，于是 \(f=\frac{N_r}{K_rT}\big[\lambda T+(1-\lambda)T\frac{K_r}{N_r}\big]=(1-\lambda)+\lambda\frac{N_r}{K_r}\)，\(P=\frac{1-\lambda}{N_r}+\frac{\lambda}{K_r}\)。其余 \(N_r-K_r\) 个专家：\(f=1-\lambda\)，\(P=\frac{1-\lambda}{N_r}\)。所以

\[\frac{\mathcal L_{\mathrm{ExpBal}}}{\alpha_1}=K_r\Big[(1-\lambda)+\lambda\tfrac{N_r}{K_r}\Big]\Big[\tfrac{1-\lambda}{N_r}+\tfrac{\lambda}{K_r}\Big]+(N_r-K_r)\frac{(1-\lambda)^2}{N_r}.\]

\(N_r=64,K_r=6,\lambda=0.5\)：第一项 \(6\times(0.5+5.3333)\times(0.0078125+0.0833333)=6\times5.8333\times0.0911458=3.1901\)；第二项 \(58\times0.25/64=0.2266\)；合计 \(3.4167\)。

这个式子还能化简。记 \(\rho=N_r/K_r\)，注意坍缩组里的 \(P=\big[(1-\lambda)+\lambda\rho\big]/N_r\) 恰好是 \(f/N_r\)：

坍缩曲线化简为抛物线
(1)\(\displaystyle K_r\cdot f\cdot P=\dfrac{K_r}{N_r}\big[1+\lambda(\rho-1)\big]^2=\dfrac{1}{\rho}\big[1+\lambda(\rho-1)\big]^2\)坍缩组：\(f=(1-\lambda)+\lambda\rho=1+\lambda(\rho-1)\)，\(P=f/N_r\)
(2)\(\displaystyle (N_r-K_r)\dfrac{(1-\lambda)^2}{N_r}=\dfrac{\rho-1}{\rho}(1-\lambda)^2\)其余专家：\((N_r-K_r)/N_r=1-1/\rho\)
(3)\(\displaystyle \dfrac{1}{\rho}\Big[1+2\lambda(\rho-1)+\lambda^2(\rho-1)^2+(\rho-1)(1-2\lambda+\lambda^2)\Big]\)两项相加，提出 \(1/\rho\) 并展开平方
(4)\(\displaystyle =\dfrac{1}{\rho}\Big[\rho+\lambda^2(\rho-1)\rho\Big]=1+(\rho-1)\lambda^2\)一次项正负抵消；常数项合成 \(\rho\)；二次项系数 \((\rho-1)^2+(\rho-1)=(\rho-1)\rho\)

所以 \(\mathcal L_{\mathrm{ExpBal}}/\alpha_1=1+\big(\tfrac{N_r}{K_r}-1\big)\lambda^2\)：16B 在 \(\lambda=0.5\) 时是 \(1+\tfrac{58}{6}\times0.25=3.4167\)，与上面一致。它是 \(\lambda\) 的抛物线，\(\lambda=0\) 处导数为 0：刚开始坍缩时，损失值的变化只是 \(\lambda\) 的二次小量。梯度却是一次量：(7.12) 式（§7 的版本前面没有 \(N\)）的梯度正比于 \(f_j-\bar f_t\)；对一个均匀路由的 token，\(s_{i,t}=1/N_r\)，所以 \(\bar f_t=\frac1{N_r}\sum_if_i=1\)（用到 (a) 的 \(\sum_if_i=N_r\)），于是 \(f_j-\bar f_t=f_j-1\)，坍缩组专家是 \(\lambda(\rho-1)\)、其余专家是 \(-\lambda\)，都与 \(\lambda\) 成正比。所以轻微坍缩时，起作用的是梯度的方向，而不是损失值的大小。（对那些已经坍缩的 token，按本题的理想化设定，亲和度平分在坍缩组上、其余专家为 0：坍缩组专家有 \(\bar f_t=f_j\)，其余专家有 \(s_{j,t}=0\)，梯度全为零。把路由拉回均匀的，主要是均匀路由那部分 token 上的梯度。）

练习 10 · 退化为 Switch

（a）证明 \(K_r=1\) 时，专家级损失 (7.22)–(7.24) 就是 Switch 损失 (7.10)–(7.11)。（b）Switch 例子：\(N=4\)，8 个 token 的首选计数 \((5,1,1,1)\)，\(P=(0.55,0.15,0.15,0.15)\)，损失是 \(\alpha\) 的几倍？（c）如果路由器“诚实”，\(P_i=f_i\)，损失是多少？与 (b) 比较说明什么？

看答案

（a）\(K_r=1\) 时每个 token 只选一个专家，\(f_i=\frac{N_r}{T}\cdot\text{次数}_i=N_r\tilde f_i\)，\(\tilde f_i\) 是 Switch 的比例；代入 (7.22) 得 \(\alpha_1N_r\sum_i\tilde f_iP_i\)，即 (7.10)。

（b）\(\tilde f=(0.625,0.125,0.125,0.125)\)，\(\sum\tilde f_iP_i=0.34375+0.05625=0.4\)，损失 \(=4\times0.4\,\alpha=1.6\alpha\)。

（c）\(4\sum\tilde f_i^2=4(0.390625+3\times0.015625)=4\times0.4375=1.75\)，即 \(1.75\alpha\)。(b) 的 \(P\) 比实际负载更“平”（给专家 1 的概率 0.55 小于它实际拿到的 0.625），所以损失略低；这也说明 \(\sum f_iP_i\) 衡量的是“实际负载”与“路由意愿”的配合，而 \(N\sum f_i^2\ge1\) 的下界只在 \(P=f\) 时直接适用（§3 的推导）。

练习 11 · 共享专家的等价实现

（a）证明两个 SwiGLU 共享专家之和等于一个中间维相加的 SwiGLU。（b）用 16B 的数字检查参数量。（c）既然如此，说“16B 有 2 个共享专家”和“16B 有 1 个中间维 2816 的共享专家”有区别吗？

看答案

（a）按 (7.14) 把两个专家都展开成中间神经元之和；SwiGLU 的逐元素运算不跨神经元，两个有限和可以合并成对 \(\mathcal J_a\cup\mathcal J_b\) 的一个和；把 \(W_1,W_3\) 按行、\(W_2\) 按列拼接，就是中间维 \(\lvert\mathcal J_a\rvert+\lvert\mathcal J_b\rvert\) 的一个 SwiGLU（§6 的推导）。

（b）\(3\times2048\times2816=17{,}301{,}504=2\times8{,}650{,}752\)。

（c）前向计算上没有区别，开源代码就是用一个中间维 2816 的 MLP 实现的。区别只在记账方式：用“个数”描述，可以和 0.25 倍大小的细粒度专家用同一单位，说成“激活 2 + 6 = 8 个专家、共 2 个标准 FFN”（这是笔者的理解，论文没有解释为什么这样记）。

练习 12 · 组合数的熵估计

（a）用 (7.17) 前的上下界 \(\frac{2^{nH(p)}}{n+1}\le\binom nk\le2^{nH(p)}\) 估计 \(\binom{64}{8}\)，并与精确值 4,426,165,368 比较。（b）细粒度切分时，每个专家平均分到的 token 数随 \(m\) 怎样变化？每个 token 在一个专家上的计算量呢？这对硬件效率意味着什么？

看答案

（a）\(p=8/64=1/8\)，\(H(1/8)=\frac18\log_28+\frac78\log_2\frac87=0.375+0.1686=0.5436\) 比特；\(nH=64\times0.5436=34.79\)；上界 \(2^{34.79}\approx2.97\times10^{10}\)；下界 \(2.97\times10^{10}/65\approx4.56\times10^{8}\)。精确值 \(4.43\times10^9\) 落在两者之间，约为上界的 15%。上下界相差 \(n+1=65\) 倍，但指数部分（每增加 1 个 \(m\) 约 2.62 个数量级）是准确的。

（b）一个 batch 有 \(T\) 个 token，每个 token 选 \(mK\) 个专家，共 \(mN\) 个专家，平均每个专家分到 \(T\cdot mK/(mN)=TK/N\) 个 token，与 \(m\) 无关。但每个专家的中间维是 \(d_{ff}/m\)，一个 token 在它那里的计算只有原来的 \(1/m\)。每读一遍专家权重（\(3d\,d_{ff}/m\) 个参数）所做的计算是 \(2\cdot TK/N\cdot3d\,d_{ff}/m\) FLOPs，二者之比是每个参数 \(2TK/N\) 次浮点运算（BF16 权重每个参数 2 字节，按字节计的算术强度就是 \(TK/N\)），与 \(m\) 无关；可是矩阵变窄后单个矩阵乘法变小，GPU 更难达到峰值效率，每个 token 要分发到的专家数又乘了 \(m\)，调度与通信开销上升。这与论文不再继续切细的理由一致（以上是笔者的分析，论文只说了“过小的专家可能降低计算效率”）。
