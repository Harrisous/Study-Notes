第 18 课 · DeepSeek-V4：百万 token 上下文

DeepSeek-V3.2 把每个查询要精读的 token 限制在 2048 个，但它的打分器仍要把前文逐个扫一遍，缓存也仍然每个 token 存一份。把上下文从 128K 拉到 100 万 token，这两笔账都会膨胀 8 倍。V4 的办法是先沿序列方向压缩，再决定怎么读：一半的层把每 4 个 token 压成一个条目、再从中挑出 1024 个（V4-Pro；Flash 为 512 个）精读（CSA），另一半的层把每 128 个 token 压成一个条目、然后全部读一遍（HCA）。这一课从公式讲到字节，最后亲手复算论文里那两个头条数字：1M 上下文下，V4-Pro 的单 token 计算量约为 V3.2 的 27%，KV cache 约为 10%。

这一课回答什么问题

一本 30 万字的长篇小说大约是几十万个 token；一个大型代码仓库、一整年的会议记录、一个跑了几百步的智能体的全部工具输出，都可能超过 100 万个 token。要让模型“一眼看完”这么长的上下文，每生成一个新 token，它都要回头面对前面的 100 万个 token。这一课回答五个问题：

  • 如果把 DeepSeek-V3.2 原样拉到 100 万 token，它的 KV cache 有多大？每生成一个 token 要做多少计算？账单里最大的一项是什么？
  • V4 的 CSA（压缩稀疏注意力）怎样把每 4 个 token 的键值“合成”一个条目？为什么它的压缩不是简单平均，而是两路重叠、逐通道的 softmax 加权？压缩之后又怎样挑出该精读的条目？
  • HCA（重压缩注意力）把每 128 个 token 压成一个条目、却不做任何选择，这样做图什么？两种层怎样交错排布？滑动窗口、attention sink、部分 RoPE 的“逆旋转”各补了哪个漏洞？
  • V4 怎样把第 16 课的 mHC 接进每一层？为什么大部分参数改用 Muon 优化器？牛顿–舒尔茨迭代对一个矩阵到底做了什么，为什么 V4 要把它拆成“8 步快 + 2 步准”？
  • V4 用什么数据、什么日程训练到 1M 上下文？后训练为什么把强化学习阶段整个换成了“在线蒸馏”？“Non-think / High / Max”三档推理强度是怎么来的？论文说的“27% 的计算、10% 的 KV cache”，自己能不能算出来？

这一课在科技树上的位置

这一课是五条主线的交汇点。主线 A（注意力与 KV cache 经济学）：第 9 课的 MLA 沿特征方向把每个 token 的条目压到 576 个数；第 14 课的 DSA 让每个查询只精读 2048 个 token，但第 14 课的结尾算出了它的软肋——打分器（lightning indexer）自己仍然是 \(O(T^2)\)，而且 KV cache 一个字节也没省。V4 第一次沿序列方向压缩：不是让每个条目更短，而是让条目更少。主线 E（残差流与记忆）：第 16 课的 mHC 在这里第一次进入 DeepSeek 的旗舰模型；第 17 课留下的问题是“不是所有上下文都需要以完整 KV 的形式记住”，Engram 和 OCR 在注意力之外回答它，V4 则在注意力之内回答：旧的上下文以 4 倍或 128 倍压缩的形式记住。主线 F（优化器）：第 2 课的 AdamW 让位于 Muon。主线 B 与 D：第 11 课的无辅助损失均衡与 MTP 原样沿用，第 13 课、第 15 课的 GRPO 只留在“专家培养”阶段，最后一步换成了在线蒸馏。

下一课的 V4.1-Flash 在本课的 CSA/HCA 之上继续压 KV：相邻的层共用全局 KV、主 KV 存成 FP4、滑动窗口状态不再进入持久化缓存（丢了只回放 128 个 token）。本课 §7 算出的 V4-Flash“每 token 约 3.5 KB”正是它的起点。

百万 token 的账单

先算账，再看设计。这一页做三件事：把 DeepSeek-V3.2 按它的真实维度外推到 100 万 token，看 KV cache 与计算量各变成多少、最大的一项是什么；然后概览 V4 的回答和两款模型的规格；最后把论文的两个头条数字连同它们的限定一起摆出来，留到 §7 亲手复算。

V3.2 的缓存：每个 token 48,068 字节

含义。 KV cache 是模型为已经读过的每个 token 保存的“键和值”，后来的 token 只需翻它，不必重算（第 4 课）。

理解。 用会议纪要本的类比：每位发言者（token）说完，秘书在本子上记一条“标签 + 要点”。本子的厚度与发言人数成正比。MLA（第 9 课）把每一条写成速记，让每条更短；DSA（第 14 课）让读者每次只翻其中 2048 条，但每位发言者仍然各占一条，而且为了知道该翻哪 2048 条，还要另外维护一份“目录”（lightning indexer 的键），同样每人一行。

数学。 V3.2 每层为每个 token 存两样东西 4,5,6：一个 MLA 条目（512 维的潜向量以 FP8 存放、每 128 个数一个 FP32 缩放因子，外加 64 维 BF16 的 RoPE 键），一个 lightning indexer 键（128 维 FP8 加 1 个 FP32 缩放因子）。61 层合计：

V3.2 每 token 的 KV 字节\[b_{3.2}=61\times\big(\underbrace{512+4\times4+64\times2}_{656\ \text{MLA 条目}}+\underbrace{128+4}_{132\ \text{indexer 键}}\big)=61\times788=48{,}068\ \text{字节}\]FP8 每个数 1 字节，BF16 每个数 2 字节，FP32 缩放因子每个 4 字节。(18.1)
一个 100 万 token 的请求要多少缓存

本课的“1M”取 \(2^{20}=1{,}048{,}576\) 个 token（论文图 1 的横轴以 1024 为 K，§7 的拟合也支持这一点）。\(48{,}068\times2^{20}=5.040\times10^{10}\) 字节 \(\approx50.40\) GB（\(=46.94\) GiB）。这还只是一个请求的缓存，不含模型权重。128K（\(131{,}072\) 个 token，V3.2 官方的最大上下文）时是 \(6.30\) GB。

V3.2 的计算：扫目录的钱压倒了一切

含义。 “单 token FLOPs”指处理位置 \(t\) 上的一个 token 要做的浮点运算次数：解码时就是生成这一个 token 的代价，预填充时是这一行的代价。一次乘加算 2 次运算（M01）。

理解。 这笔账分三块。第一块是所有投影与专家的矩阵乘法：每个激活参数对每个 token 做一次乘加，约 \(2N_{\text{act}}\)，与位置无关。第二块是核心注意力：每个头对每个被选中的条目做一次打分（点积）和一次取值（加权），DSA 只选 2048 个，所以位置超过 2048 之后它就不再增长。第三块是 lightning indexer：为了选出那 2048 个，它要给前文的每一个 token 打分，与 \(t\) 成正比。

数学。 用 V3.2 的维度：主干与 V3 相同，激活参数 \(N_{\text{act}}=37\)B、61 层、128 个头 7；MLA 在解码时用 MQA 模式 4，键 576 维、值 512 维 5，每个头每个条目 \(2\times576+2\times512=2176\) 次运算；indexer 64 个头、每头 128 维（V3.2 论文只说“少量头”，这两个数来自开源的 config.json，见第 14 课 §4），每个头每个前文 token \(2\times128=256\) 次：

V3.2 的单 token FLOPs（原始计数）\[F_{3.2}(t)=\underbrace{2N_{\text{act}}}_{7.4\times10^{10}}+\underbrace{61\cdot128\cdot2176\cdot\min(t,2048)}_{\text{核心注意力，}t\ge2048\text{ 时 }3.48\times10^{10}}+\underbrace{61\cdot64\cdot256\cdot t}_{\text{indexer，}=999{,}424\,t}\]只数主要项：投影、\(QK^\top\) 与 \(PV\)、indexer 的点积；softmax、归一化、ReLU 等逐元素运算相对很小，忽略。§7 会在此基础上换成论文用的“等效 FP8”口径。(18.2)
1M 处的三块

\(t=2^{20}\)：投影 \(0.074\) TFLOPs；核心注意力 \(61\times128\times2176\times2048=3.48\times10^{10}\)，即 \(0.035\) T；indexer \(999{,}424\times2^{20}=1.048\times10^{12}\)，即 \(1.048\) T。合计 \(1.157\) T，indexer 占 \(90.6\%\)。

再看读的字节：每解码一步，indexer 要把 61 层、\(2^{20}\) 个 token 的键全部读一遍，\(132\times61\times2^{20}=8.44\times10^{9}\) 字节；核心注意力只读 \(2048\times656\times61=8.2\times10^{7}\) 字节，是前者的 1%。目录比书本身还重。

第 14 课在结尾已经预告了这件事：indexer 每键的计算只有核心注意力的 1/17，但它要扫全部前文，所以长度超过 34,816 之后，“扫目录”就比“精读”更贵（第 14 课 §7）。到 1M，目录是精读的 30 倍。继续用 DSA 的思路是走不到 1M 的：要么让目录更短，要么让每一页更“厚”，也就是让每个条目概括多个 token。V4 两件事都做了。

V4 的回答：先沿序列压缩，再决定怎么读

V4 的注意力有两种层，交错堆叠 1：

  • CSA（Compressed Sparse Attention，压缩稀疏注意力）：沿序列方向把每 \(m=4\) 个 token 的 KV 合成一个条目，再在这些条目上做 DSA 式的选择，每个查询只精读 \(k_{\text{sel}}\) 个条目（Pro 1024 个，Flash 512 个）。indexer 的键也同样压缩，所以目录缩短到原来的 1/4。
  • HCA（Heavily Compressed Attention，重压缩注意力）：每 \(m'=128\) 个 token 合成一个条目，然后不做选择，对全部条目做稠密注意力。1M 时只有 8192 个条目。
  • 两种层都附带一个滑动窗口分支：最近的 \(n_{\text{win}}=128\) 个 token 以未压缩的形式直接参与注意力，补上“还没凑满一块、尚未被压缩”的那部分近邻。

注意力之外，V4 还有两项主要升级：mHC（第 16 课的流形约束超连接）把残差流扩成 4 条；Muon 优化器取代了大部分参数上的 AdamW。其余部分沿用 V3：DeepSeekMoE、无辅助损失的负载均衡、深度为 1 的 MTP，论文明说“未说明的细节沿用 V3 的设定” 1,7。

数一数 Flash 的专家参数

一个路由专家是 SwiGLU 的三个矩阵：gate、up 各 \(d\times d_{ff}\)，down \(d_{ff}\times d\)，共 \(3\times4096\times2048=25{,}165{,}824\approx25.17\)M 个参数。每层 256 个路由专家，43 层：\(25.17\text{M}\times256\times43=277.0\)B。总参数 284.3B 里 97.4% 是路由专家，而每个 token 只激活其中 6 个：这就是 13B 激活、284B 总量的来历。Pro 同理：\(3\times7168\times3072=66.06\)M，\(\times384\times61=1{,}547\)B，占不含 MTP 的总参数（1,573.0B）的 98.4%。

MoE 的几处改动

V4 的 MoE 沿用 V3 的 DeepSeekMoE（第 7 课、第 11 课），论文逐项交代了四点：三处改动，一处照旧 1。

第一处：亲和度函数从 sigmoid 换成 \(\sqrt{\operatorname{softplus}(\cdot)}\)。第 \(t\) 个 token 对第 \(i\) 个专家的亲和度是

V4 的亲和度\[s_{i,t}=\sqrt{\operatorname{softplus}\big(\mathbf x_t^\top\mathbf e_i\big)},\qquad \operatorname{softplus}(x)=\ln(1+e^{x})\]\(\mathbf x_t\in\R^{d}\)：进入 MoE 子层的隐藏状态（第 11 课写作 \(\mathbf u_t\)，本课把 \(\mathbf u\) 留给 §3 的滑动窗口条目）；\(\mathbf e_i\in\R^{d}\)：专家 \(i\) 的中心向量（第 11 课记号，与 §2 的压缩条目 \(\mathbf e_s\) 无关）。选专家时仍用 \(s_{i,t}+b_i\) 取前 6 名（\(b_i\) 是无辅助损失均衡的偏置），门控值用不加偏置的 \(s_{i,t}\) 在选中的 6 个里归一化。(18.3)

两个函数的差别在形状上。sigmoid 的输出被夹在 \((0,1)\) 里；\(\sqrt{\operatorname{softplus}}\) 在 \(x\) 很大时像 \(\sqrt x\) 一样继续增长，在 \(x\) 很负时像 \(e^{x/2}\) 一样趋于 0（因为 \(x\to-\infty\) 时 \(\ln(1+e^x)\approx e^x\)）。取三个打分对照：\(x=-4\) 时 sigmoid 为 0.018、\(\sqrt{\operatorname{softplus}}\) 为 0.135；\(x=0\) 时分别为 0.5 与 \(\sqrt{\ln2}=0.833\)；\(x=4\) 时分别为 0.982 与 2.005。sigmoid 在 \(x=4\) 附近已经饱和，两位打分 4 和 8 的专家几乎拿到一样的亲和度；\(\sqrt{\operatorname{softplus}}\) 仍能把它们分开（2.005 对 2.828；sigmoid 是 0.982 对 0.9997）。这只是函数形状上的对比，论文没有解释为什么换，本课也不猜动机。开源代码在归一化之后还乘了一个常数（Pro 2.5、Flash 1.5；V3 的代码是 2.5，见第 11 课 §2），论文未提 8。

照旧的一处：负载均衡仍是无辅助损失的偏置法，偏置更新速度 0.001，外加权重 0.0001 的序列级均衡损失，两个数都与 V3 相同。第二处：去掉了“每个 token 最多发往 \(M\) 个节点”的限制（V3 的 \(M=4\)，第 11 课），改为重新设计并行策略。第三处：开头的稠密层换成 Hash 路由的 MoE 层：V3 的前 3 层是稠密 FFN，V4 的前 3 层也是 MoE，但选哪 6 个专家不看打分，而是按输入 token 的编号查一张预先固定的表（开源代码里形状为词表大小 × 6），门控值仍来自打分 8。这种按 token 哈希分配专家的路由来自 Hash Layers 9。

“Hash 层就是稠密层”

不是。V4 没有稠密 FFN 层了：前 3 层同样有 1 个共享专家和 6 个路由专家，只是路由由 token 编号决定，不由隐藏状态决定。这让最浅的几层也能用上 MoE 的参数容量，又不必在隐藏状态还很“生”的时候学路由。后半句是笔者对动机的解读，论文只给了做法。

两个头条数字，连同它们的限定

论文摘要说：在 1M 上下文下，V4-Pro 的单 token 推理 FLOPs 只有 V3.2 的 27%，KV cache 只有 10%；§1 补充 V4-Flash 分别是 10% 和 7% 1。这两个数字会被反复转述，所以在讲机制之前，先把它们的三个限定写清楚：

  1. 只在 1M、只比 V3.2。 而 V3.2 官方只支持 128K 4，1M 处的 V3.2 是按架构外推的假想点。§7 会算出：128K 时 V4-Pro 的单 token FLOPs 约为 V3.2 的一半，而不是 27%。
  2. FLOPs 是“等效 FP8 FLOPs”，而且是估算。 论文 §1 明说曲线是估算值、口径是等效 FP8。不同数值精度的运算按某种比例折算，论文没给折算规则；§7 用一种与图 1 吻合的折算（笔者推测）复算。
  3. KV cache 只算随长度增长的部分。 每个请求还有一块固定大小的“滑动窗口状态”（V4-Pro 约 4.56 MB），短上下文时它会让比例高一些（§7）。

CSA（上）：沿序列方向压缩 KV

上一页的结论是：要走到 1M，条目必须变少。这一页讲 CSA 的前一半，压缩：怎样把每 \(m=4\) 个 token 的键值合成一个条目。下一页讲后一半，选择：怎样在这些条目上做 DSA 式的 top-\(k\)。HCA 的压缩是同一个公式的简化版，放到 §4。

两个方向的压缩

问题。 一层注意力的 KV cache 是一张表：每行一个 token，每行 \(c\) 个数。要让这张表变小，只有两个方向可以压：让每一行变短，或者让行数变少。

图景。 MLA（第 9 课）压的是列：每个 token 的键和值被压成一个 512 维的潜向量（再加 64 维 RoPE 键），行数不变。CSA 压的是行：每 \(m\) 个相邻 token 合成一行，行数变成 \(T/m\)，每行仍然是 \(c=512\) 维。前者是“每条纪要写得更短”，后者是“几位发言者合写一条纪要”。两者可以叠加，V4 的条目本身也不宽（512 维，与 MLA 的潜向量同宽）。

类比：会议纪要本，从“一人一条”到“四人一条”

映射。 发言者 = token；纪要本上的一条 = 一个 KV 条目；秘书 = 压缩器。V3.2 的秘书为每位发言者记一条速记（MLA）。CSA 的秘书每听完 4 位发言者，就合写一条联合纪要：这条纪要的每一个栏目（通道），由秘书单独决定主要采信哪位发言者（逐通道 softmax）；为了不让恰好跨在两组交界处的讨论被切断，每条联合纪要除了本组 4 人，还会参考上一组的 4 人（重叠窗口）。

收益。 本子的厚度变成 1/4；后来的人翻本子时，要看的条数也变成 1/4。它还解释了为什么权重要“按栏目”分：一位发言者也许只在某个话题上有要点，别的栏目应该听别人的。

失效的地方。 真秘书会理解内容再总结；压缩器只是学出来的线性投影加 softmax 加权，一旦合写，就再也拆不回 4 条原话。所以最近的 128 个 token 仍以“一人一条”的原样保留在手边（滑动窗口分支，§3），以免刚说完的话被合并掉细节。另外，这条纪要同时充当“标签”和“内容”（键和值是同一个向量），真纪要本没有这种一身二任。

压缩公式

含义。 压缩条目 \(\mathbf e_s\in\R^{c}\) 是一个 512 维的向量，概括第 \(s\) 块的 \(m\) 个 token（并参考前一块的 \(m\) 个 token），在注意力里同时当键和值。

理解。 做法分三步：先给每个 token 算两份“候选内容”和两份“打分”；再在一个窗口的 \(2m\) 个 token 上，对每个通道分别做 softmax，得到每个 token 在这个通道上的权重；最后按权重把候选内容加起来。两份候选叫 \(a\) 路和 \(b\) 路：一个 token 在自己所在的块里贡献 \(a\) 路，在下一块的条目里贡献 \(b\) 路。

数学。 对每个 token \(\tau\) 的隐藏状态 \(\mathbf h_\tau\in\R^{d}\)，用四个矩阵算出四个 \(c\) 维向量 1：

候选内容与打分\[\mathbf c^a_\tau=W^{aKV}\mathbf h_\tau,\quad \mathbf c^b_\tau=W^{bKV}\mathbf h_\tau,\qquad \mathbf z^a_\tau=W^{aZ}\mathbf h_\tau,\quad \mathbf z^b_\tau=W^{bZ}\mathbf h_\tau\]四个矩阵都是 \(c\times d\)（Pro：\(512\times7168\)）。\(\mathbf c^{a},\mathbf c^b\) 是候选的条目内容，\(\mathbf z^a,\mathbf z^b\) 是每个通道上的打分（logit）。注意 \(\mathbf c^a_\tau\) 与查询潜向量 \(\mathbf c^Q_t\) 只是字母相同，是两回事。(18.4)

第 \(s\) 个条目的窗口由两块组成：本块 \(\mathcal B_s=\{ms,\dots,m(s+1)-1\}\)，取 \(a\) 路；前一块 \(\mathcal B_{s-1}=\{m(s-1),\dots,ms-1\}\)，取 \(b\) 路。另有两个可学习的块内位置偏置 \(P^a,P^b\in\R^{m\times c}\)：块内第 \(\rho\) 个位置（\(\rho=0,\dots,m-1\)）的 token 在打分上加一行 \(\mathbf p^a_\rho\) 或 \(\mathbf p^b_\rho\)。对每个通道 \(r=1,\dots,c\)，在这 \(2m\) 个 token 上做 softmax：

逐通道 softmax 权重\[\begin{aligned}[\mathbf w^a_\tau]_r&=\frac{\exp\big([\mathbf z^a_\tau+\mathbf p^a_{\tau-ms}]_r\big)}{Z_{s,r}}, && \tau\in\mathcal B_s\\[4pt] [\mathbf w^b_\tau]_r&=\frac{\exp\big([\mathbf z^b_\tau+\mathbf p^b_{\tau-m(s-1)}]_r\big)}{Z_{s,r}}, && \tau\in\mathcal B_{s-1}\end{aligned}\]\(Z_{s,r}\) 是这 \(2m\) 个指数在通道 \(r\) 上的和，所以每个通道上的 \(2m\) 个权重非负、和为 1。\(s=0\) 时没有前一块，\(b\) 路的打分按 \(-\infty\)、内容按 0 填充，相当于只有本块的 \(m\) 个 token。(18.5)
压缩条目\[\mathbf e_s=\sum_{\tau\in\mathcal B_s}\mathbf w^a_\tau\odot\mathbf c^a_\tau+\sum_{\tau\in\mathcal B_{s-1}}\mathbf w^b_\tau\odot\mathbf c^b_\tau\ \in\R^{c}\]\(\odot\) 是逐元素乘积（Hadamard 积）。这是 V4 论文式 (9)–(12) 改写成列向量后的形式；论文把整段序列按行堆成矩阵 \(H\in\R^{n\times d}\)，写 \(C^a=H\cdot W^{aKV}\) 等 1。(18.6)

开源代码与这组公式一致：压缩器一次输出 \(2c=1024\) 维，后一半当本块的 \(a\) 路、前一半留给下一个条目当 \(b\) 路；位置偏置 ape 的形状是 \(m\times2c\)；softmax 沿 token 轴、在 \(2m\) 个元素上做，每个通道独立 8。压缩在 FP32 里算，算完再做一次 RMSNorm。

三个性质

性质一：每个通道都是一个凸组合。 这是 (18.5) 的直接推论，也是它“不会把数值放大”的保证。

条目的每个分量落在候选值的范围内
(1)\(\displaystyle [\mathbf e_s]_r=\sum_{\tau\in\mathcal W_s}[\mathbf w_\tau]_r\,[\mathbf c_\tau]_r\)(18.6) 的第 \(r\) 个分量；\(\mathcal W_s=\mathcal B_{s-1}\cup\mathcal B_s\)，\(\mathbf c_\tau,\mathbf w_\tau\) 按所在块取 \(a\) 路或 \(b\) 路
(2)\(\displaystyle [\mathbf w_\tau]_r\ge0,\quad \sum_{\tau\in\mathcal W_s}[\mathbf w_\tau]_r=1\)(18.5)：指数为正，除以它们的和
(3)\(\displaystyle \min_{\tau}[\mathbf c_\tau]_r\le[\mathbf e_s]_r\le\max_{\tau}[\mathbf c_\tau]_r\)非负、和为 1 的加权平均不会超出被平均的数的范围

性质二：窗口重叠，但条目数仍是 \(T/m\)。 条目 \(s\) 读 \(2m=8\) 个 token（\(\tau\) 从 \(m(s-1)\) 到 \(m(s+1)-1\)），相邻条目的步长是 \(m=4\)，所以相邻两个条目的窗口重叠 4 个 token。每个 token 恰好出现在两个条目的窗口里（自己那块的 \(a\) 路、下一块的 \(b\) 路），但条目的个数只由步长决定：长度 \(T\) 的序列有 \(T/m\) 个条目。存储与后续注意力的开销都按条目数算，所以压缩率仍是 \(1/m\)。

性质三：权重依输入而变，而且逐通道不同。 打分 \(\mathbf z_\tau\) 是 \(\mathbf h_\tau\) 的函数，所以哪个 token 在条目里占主导，是每段文字各不相同的；而且 512 个通道各有一套权重，一个条目可以在通道 17 上主要记住第 2 个 token、在通道 300 上主要记住第 7 个 token。下面的例子把这一点算出来。

手算一个条目（为了好算，取 \(m=2\)、\(c=2\)）

4 个 token：块 0 是 token 0、1，块 1 是 token 2、3。条目 1 读块 0 的 \(b\) 路和块 1 的 \(a\) 路。设投影之后（已加上位置偏置）的数是：

token 所在路 候选内容 \(\mathbf c_\tau\) 打分 \(\mathbf z_\tau+\mathbf p\) 两个通道的 \(\exp\)
0 \(b\) \((1,\ 0)\) \((0,\ 0)\) \((1,\ 1)\)
1 \(b\) \((0,\ 2)\) \((0,\ \ln3)\) \((1,\ 3)\)
2 \(a\) \((2,\ 1)\) \((\ln2,\ 0)\) \((2,\ 1)\)
3 \(a\) \((-1,\ 3)\) \((0,\ \ln4)\) \((1,\ 4)\)

通道 1：指数之和 \(1+1+2+1=5\)，权重 \((0.2,\ 0.2,\ 0.4,\ 0.2)\)；分量 \(0.2\times1+0.2\times0+0.4\times2+0.2\times(-1)=0.8\)。 通道 2：指数之和 \(1+3+1+4=9\)，权重 \((\tfrac19,\ \tfrac39,\ \tfrac19,\ \tfrac49)\)；分量 \(\tfrac{0\cdot1+2\cdot3+1\cdot1+3\cdot4}{9}=\tfrac{19}{9}\approx2.111\)。

所以 \(\mathbf e_1=(0.8,\ 2.111)\)。通道 1 最信 token 2（权重 0.4），通道 2 最信 token 3（权重 0.444）：同一个条目的两个分量“听了不同的人”。如果只允许每个 token 一个标量权重（所有通道共用），这种分工就做不到。作为对照，4 个候选的简单平均是 \((0.5,\ 1.5)\)。两个分量都落在各自候选值的范围里：通道 1 在 \([-1,2]\)，通道 2 在 \([0,3]\)，与性质一相符。

“CSA 就是每 4 个 token 取个平均”

不对，差了四处：权重是 softmax 算出来的、随输入变化；是逐通道的 softmax，不是每个 token 一个标量；每个条目读 8 个 token（本块 + 前一块，两套投影），步长才是 4；打分上还有可学习的块内位置偏置。唯一对的是压缩率：条目数确实是 \(T/4\) 1,8。

压缩丢掉了什么

合写是多对一的：条目只记住每个通道上的加权和，记不住“这个数是谁贡献的”。在上面的例题里，把 token 0 与 token 1 在通道 1 上的候选对调（1 和 0 互换），两者在通道 1 上的权重都是 0.2，于是 \([\mathbf e_1]_1=0.2\times0+0.2\times1+0.4\times2+0.2\times(-1)=0.8\)，与对调前相同：输入变了，条目却一模一样。按个数算，一个 CSA 条目把 8 个 token 的候选（\(8\times512=4096\) 个数）合成 512 个数；HCA 的条目把 \(128\times512=65{,}536\) 个数合成 512 个。块内谁先谁后，只能靠位置偏置 \(P^a,P^b\) 写进权重；条目的 RoPE 位置也只记块的第一个 token（§4）。所以一个必须逐字精确的细节（一个数字、一个变量名）离开最近 128 个 token 的窗口之后，模型只能从合写过的条目里去读它。这是结构本身带来的限制；它在基准上造成多大损失，研究笔记里没有可引用的消融数据，本课不做定量推断。

因果：条目什么时候才能被看见

条目 \(s\) 用到了 token \(m(s+1)-1\)，所以只有位置 \(t\ge m(s+1)-1\) 的查询才能看它，否则就偷看了未来。开源代码（\(t\) 从 0 计）的可见条件是

压缩条目的可见范围\[s<\Big\lfloor\frac{t+1}{m}\Big\rfloor\]等价于 \(m(s+1)-1\le t\)：条目读到的最后一个 token 不晚于查询本身。论文写的是 \(s<\lfloor t/m\rfloor\)，两者只在 \((t+1)\) 恰为 \(m\) 的倍数时差一个条目（“以当前 token 结尾的那一块”算不算已完成），都满足因果，可能只是 \(t\) 从 0 还是从 1 计的差别 1,8。(18.7)

这带来一个空洞：查询 \(t\) 所在的那一块如果还没凑满 \(m\) 个 token，这几个 token 就还没进入任何条目。\(m=4\) 时最多空 3 个 token；HCA 的 \(m'=128\) 时最多空 127 个。这个空洞由滑动窗口分支补上（§4 会证明窗口恰好够用）。

一个条目占多少字节

KV cache 里存的就是这些条目。V4 用混合精度存储：512 维里，最后 64 维带 RoPE（位置信息，§4），以 BF16 保存；前 448 维以 FP8 保存，每 64 个数配一个缩放因子 1,5。

FP8、FP4 与 UE8M0 缩放因子读过第 12 课或 M08 的可以跳过

FP8（E4M3）用 8 个比特存一个数，只有 3 位尾数，所以要先把一组数除以一个缩放因子，让它们落在可表示的范围里，用时再乘回去（“短尺子 + 分段放大镜”）。UE8M0 是一种只有 8 位指数、没有尾数和符号位的缩放因子格式：它只能表示 2 的整数次幂，占 1 个字节。FP4（E2M1）只有 4 个比特，能表示的非零绝对值只有 0.5、1、1.5、2、3、4、6 七个；MXFP4 是“每 32 个 FP4 数共享一个 UE8M0 缩放因子”的格式，平均每个数 \(4+8/32=4.25\) 比特。各格式的位布局见 M08 §3，UE8M0 与 MXFP4 见 M08 §7。

一个 V4 条目为什么是 584 字节
(1)\(\displaystyle 448\times1=448\)前 448 维 FP8，每个数 1 字节
(2)\(\displaystyle 64\times2=128\)最后 64 维（RoPE 部分）BF16，每个数 2 字节
(3)\(\displaystyle 448/64=7,\quad 7\times1+1=8\)每 64 个 FP8 数一个 UE8M0 缩放因子（1 字节），再补 1 字节对齐
(4)\(\displaystyle 448+128+8=584\)FlashMLA 规定的 V4 条目格式
(5)\(\displaystyle 584/(512\times2)=57.0\%\)纯 BF16 要 1024 字节，省了 43%，即论文说的“小了近一半”

indexer 的键也按同样的方式压缩（维度 \(d^I=128\)，也是 \(m=4\) 且重叠，有自己的一套压缩矩阵），以 FP4 保存：\(128/2=64\) 字节，外加每 32 个数一个 UE8M0 缩放因子共 4 字节，合计 68 字节。这是参考代码的格式；生产系统里的实际布局（有没有额外填充）研究笔记没能核实。

每个 CSA 层，每个 token 摊到多少字节

每 \(m=4\) 个 token 存一个 584 字节的条目和一个 68 字节的 indexer 键：\((584+68)/4=163\) 字节/token/层。V3.2 每层每 token 是 \(656+132=788\) 字节，CSA 层是它的 \(1/4.83\)。压缩贡献了 4 倍，条目格式（584 对 656、68 对 132）贡献了剩下的一点。真正的大头在 HCA 层：每 128 个 token 才存一个条目，\(584/128=4.56\) 字节/token/层（§4）。

小练习：第 1000 号条目

CSA，\(m=4\)。（a）条目 \(s=1000\) 的 \(a\) 路和 \(b\) 路各读哪些 token？（b）按 (18.7)，位置最早为多少的查询能看到它？（c）1M（\(2^{20}\)）个 token 的序列，每个 CSA 层有多少个条目？

看答案

（a）\(a\) 路读本块 \(\{4000,4001,4002,4003\}\)，\(b\) 路读前一块 \(\{3996,3997,3998,3999\}\)。（b）需要 \(1000<\lfloor(t+1)/4\rfloor\)，即 \(\lfloor(t+1)/4\rfloor\ge1001\)，\(t+1\ge4004\)，\(t\ge4003\)：正是条目读到的最后一个 token 本身。（c）\(2^{20}/4=262{,}144\) 个。

本页要点
  • CSA 沿序列方向压缩：每 \(m=4\) 个 token 合成一个 \(c=512\) 维的条目 \(\mathbf e_s\)，条目数 \(T/4\)；MLA 沿特征方向压缩，两者方向不同、可以叠加。
  • 压缩 (18.4)–(18.6)：每个 token 两份候选（\(a\)、\(b\) 路）与两份打分；条目读本块 \(a\) 路 + 前一块 \(b\) 路共 8 个 token，按逐通道 softmax 加权求和，另有块内位置偏置。每个分量是候选值的凸组合。
  • 合写是多对一的：条目记不住某个数是哪个 token 贡献的，块内先后只能靠位置偏置写进权重；逐字精确的细节要靠最近 128 个 token 的窗口。
  • 因果：条目 \(s\) 对位置 \(t\) 可见当且仅当 \(s<\lfloor(t+1)/m\rfloor\)；尚未凑满的尾部由滑动窗口补。
  • 条目 584 字节（448 FP8 + 64 BF16 + 8 字节缩放），indexer 键 68 字节（FP4）；每个 CSA 层每 token 摊 163 字节，V3.2 是 788 字节。

CSA（下）：在压缩条目上做稀疏选择

压缩之后，1M 的序列在每个 CSA 层还有 \(2^{20}/4=262{,}144\) 个条目。如果每个查询都对它们做稠密注意力，Pro 的一层就要 \(128\times2048\times262{,}144=6.87\times10^{10}\) 次运算，比 V3.2 整层还贵。所以 CSA 的后一半是在条目上再做一次 DSA：用 lightning indexer 给条目打分，只精读前 \(k_{\text{sel}}\) 名。这一页按数据流的顺序走一遍：查询怎么来、indexer 怎么打分、核心注意力怎么算、输出怎么投回 \(d\) 维。

查询：一个潜向量，两种用途

含义。 查询潜向量 \(\mathbf c^Q_t\) 是当前 token 的隐藏状态先压到 \(d_c'\) 维的“中间表示”，主注意力的查询和 indexer 的查询都从它展开。

理解。 这是 MLA 留下来的做法（第 9 课的“查询低秩压缩”）：先降维再升维，比直接从 \(d\) 维投到 \(n_hc\) 维便宜。V4 让 indexer 也复用它，所以 indexer 的查询几乎不花额外的投影钱。

数学。 论文 §2.3.1 的式 (13)–(15)、(18) 改写成列向量 1：

查询侧\[\begin{aligned}\mathbf c^Q_t&=W^{DQ}\mathbf h_t\in\R^{d_c'}, & \mathbf q_{t,i}&=W^{UQ}_i\,\mathbf c^Q_t\in\R^{c}\quad(i=1,\dots,n_h),\\ \mathbf q^I_{t,j}&=W^{IUQ}_j\,\mathbf c^Q_t\in\R^{d^I}, & w^I_{t,j}&=\big(W^{w}\mathbf h_t\big)_j\in\R\quad(j=1,\dots,H^I)\end{aligned}\]Pro：\(W^{DQ}\in\R^{1536\times7168}\)；\(W^{UQ}\) 把 1536 维升到 \(n_hc=128\times512=65{,}536\) 维，切成 128 个头；\(W^{IUQ}\) 升到 \(64\times128\)，切成 64 个 indexer 头；\(W^w\in\R^{64\times7168}\) 给出 64 个头权重。代码里两种查询都从归一化后的 \(\operatorname{RMSNorm}(\mathbf c^Q_t)\) 展开 8。(18.8)

lightning indexer：给条目打分

和第 14 课的公式形式完全相同，只有一处结构差别：键是压缩后的 indexer 键 \(\mathbf k^I_s\)，每 4 个 token 一个。

CSA 的 indexer 分数与选择\[I_{t,s}=\sum_{j=1}^{H^I}w^I_{t,j}\,\operatorname{ReLU}\!\big(\mathbf q^{I}_{t,j}\cdot\mathbf k^I_s\big),\qquad \mathcal S_t=\operatorname{Top\text{-}k_{sel}}\big\{I_{t,s}:\ s<\lfloor(t+1)/m\rfloor\big\}\]\(H^I=64\)，\(d^I=128\)。可见条目不足 \(k_{\text{sel}}\) 个时全部选中。代码在打分前还对查询和键做了 Hadamard 旋转、按 32 个数一块量化成 FP4，并给头权重乘了常数 \(1/\sqrt{d^I H^I}\)；论文只说“FP4”，没提旋转与常数 8。(18.9)
indexer 每个查询、每层要花多少
(1)\(\displaystyle \text{V3.2}:\ 2H^Id^I\cdot t=16{,}384\,t\)64 头 × 每头 256 次，对每个 token 打分（第 14 课）
(2)\(\displaystyle \text{V4 的 CSA}:\ 2H^Id^I\cdot\frac{t}{4}=4{,}096\,t\)只对每 4 个 token 一个的压缩键打分，次数变成 1/4
(3)\(\displaystyle t=2^{20}:\ 4096\times2^{20}=4.29\times10^{9}\)1M 处每个 CSA 层每个查询的原始 FLOPs
(4)\(\displaystyle \text{FP4 对 FP8：再折半（等效口径）}\)§7 的“等效 FP8”把 FP4 运算记 0.5 份（笔者推测的折算）

压缩让目录缩短到 1/4，FP4 又让每一行更便宜。后训练阶段，DeepSeek 还把 index score 从 FP32 量化到 BF16，让 top-\(k\) 选择提速 2 倍，而被选中条目的召回率保持在 99.7% 1。

1M 时选了多少、覆盖多大跨度

Pro 选 \(k_{\text{sel}}=1024\) 个条目，占可见的 262,144 个的 \(0.39\%\)（Flash 选 512 个，\(0.20\%\)）。每个条目概括 4 个 token，所以被精读的“原文跨度”约 \(1024\times4=4096\) 个 token，再加 128 个滑动窗口 token，共 4,224 个；Flash 是 \(512\times4+128=2{,}176\) 个。V3.2 精读 2048 个 token。论文把“top-\(k\) 比 V3.2 小”列为 V4 在中短文本上也更省的原因之一 1：条目数 1024 比 2048 少，但每条覆盖 4 个 token。

核心注意力：共享 KV 的 MQA

含义。 每个被选中的条目 \(\mathbf e_s\) 同时当键和值；128 个查询头共用这同一批条目。这叫“共享键值的多查询注意力”（shared-KV MQA）。

理解。 V3 的 MLA 在解码时也是 MQA 形态（第 14 课 §5）：576 维的缓存条目被 128 个头共用，键用 576 维、值用前 512 维。V4 更进一步：没有上投影、没有“矩阵吸收”，512 维的条目本身就是键，也本身就是值，头维就是 512。所以每个头每个条目的运算是 \(2\times512\)（打分）\(+2\times512\)（取值）\(=2048\) 次。

数学。 把被选中的压缩条目和滑动窗口的条目合成一个集合，在上面做带 sink 的 softmax 1：

一个 CSA 查询要看的条目\[\mathcal K_t=\underbrace{\{\tilde{\mathbf e}_s:\ s\in\mathcal S_t\}}_{\le k_{\text{sel}}\text{ 个压缩条目}}\ \cup\ \underbrace{\{\tilde{\mathbf u}_\tau:\ t-n_{\text{win}}<\tau\le t\}}_{n_{\text{win}}=128\text{ 个未压缩条目}}\]\(\mathbf u_\tau=\operatorname{RMSNorm}(W^{\text{win}}\mathbf h_\tau)\in\R^{c}\) 是滑动窗口分支自己的条目（\(W^{\text{win}}\in\R^{c\times d}\) 是一个单独的投影，代码里叫 wkv；本课不写成 \(W^{KV}\)，免得与 §4 HCA 压缩器的 \(W^{KV}\) 混淆），不是压缩器的输出。波浪号表示“做过 RMSNorm、最后 64 维按自己的位置加了 RoPE”（§4）。(18.10)
带 attention sink 的共享 KV 注意力\[a_{t,i,\mathbf x}=\frac{\exp\!\big(\tilde{\mathbf q}_{t,i}^\top\mathbf x/\sqrt c\big)}{\sum_{\mathbf y\in\mathcal K_t}\exp\!\big(\tilde{\mathbf q}_{t,i}^\top\mathbf y/\sqrt c\big)+\exp(z'_i)},\qquad \mathbf o_{t,i}=\sum_{\mathbf x\in\mathcal K_t}a_{t,i,\mathbf x}\,\mathbf x\ \in\R^{c}\]\(\tilde{\mathbf q}_{t,i}\)：第 \(i\) 个头的查询（RMSNorm + RoPE）；\(\mathbf x,\mathbf y\)：求和变量，泛指 \(\mathcal K_t\) 里的某个条目，它同时是键和值（与 MoE 的输入 \(\mathbf x_t\) 无关）；\(a_{t,i,\mathbf x}\in[0,1)\)：第 \(i\) 个头分给条目 \(\mathbf x\) 的注意力权重；\(z'_i\in\R\)：第 \(i\) 个头的可学习 sink logit，只出现在分母里。\(\mathbf o_{t,i}\) 的最后 64 维随后还要做一次“逆旋转”（§4）。这是研究笔记把论文式 (19)、(27) 与 §2.3.3 的附加部件合在一起写成的总公式。(18.11)

滑动窗口：补上最近的 128 个 token

压缩条目只覆盖已经凑满的块（(18.7)），而且即使凑满了，4 个 token 也被合成了一个向量。可语言里最要紧的信息往往就在最近几个 token：刚打开的括号、上一个词的词性、句子的主语。V4 因此给 CSA 和 HCA 都加了一个滑动窗口分支：最近 \(n_{\text{win}}=128\) 个 token 以未压缩的条目（每个 token 一个 \(\mathbf u_\tau\)）直接进入同一个 softmax 1。它和压缩条目共用一个分母，模型自己决定“看近处原文”还是“看远处摘要”。这 128 个条目的缓存大小固定，与上下文长度无关（§7 的“状态缓存”）。

attention sink：允许一个头“什么都不看”

问题。 普通 softmax 的权重和必为 1：即使一个头在当前位置找不到任何有用的条目，它也必须把全部注意力分出去。StreamingLLM 的研究发现，训练好的模型会把这种“无处安放”的注意力大量堆到开头几个 token 上，哪怕它们语义上并不重要 10。

图景。 回到图书馆检索的类比：softmax 把一段固定的阅读时间按匹配度分给书架上的每一本书，一分钟都不许剩下。sink 相当于在书架上放一本“空白书”：它有自己的匹配分 \(z'_i\)，分给它的时间就是“这次不读”，读书笔记（输出）里不会因此多出任何内容。边界：空白书的分数每个头只有一个，训练完就固定，不随查询变化；一个头这一步“读多少、空多少”，取决于它对真实条目的打分比 \(z'_i\) 高多少。

做法。 给每个头一个可学习的 \(z'_i\)，它的指数加进分母，却不对应任何值向量 (18.11)。于是权重和

\[\sum_{\mathbf x\in\mathcal K_t}a_{t,i,\mathbf x}=1-\frac{e^{z'_i}}{\sum_{\mathbf y}e^{\tilde{\mathbf q}^\top\mathbf y/\sqrt c}+e^{z'_i}}<1,\]

一个头可以把一部分“注意力预算”交给这个虚拟的“空位”。gpt-oss 用了同样的设计，V4 引用了它 11。对压缩注意力来说这件事尤其自然：条目是合成的，并不存在一个“永远在开头、可以当垃圾桶”的真实 token（这是笔者的解读）。

一个 sink 让权重和变成 0.80

某个头对三个条目的打分（已除以 \(\sqrt c\)）为 \((2,\ 1,\ 0)\)，sink logit \(z'=1\)。指数：\(e^2=7.389\)，\(e^1=2.718\)，\(e^0=1\)，sink \(e^1=2.718\)；分母 \(7.389+2.718+1+2.718=13.825\)。权重 \((0.534,\ 0.197,\ 0.072)\)，和为 \(0.803\)；剩下的 \(0.197\) 交给了 sink。三个真实条目的权重都乘上了同一个因子 \(11.107/13.825=0.803\)，所以输出向量方向不变、长度恰好是没有 sink 时的 0.803 倍。若 \(z'=-\infty\)（没有 sink），权重是 \((0.665,\ 0.245,\ 0.090)\)，和为 1。

反过来看它的代价：若 \(z'=5\)，分母变成 \(11.107+e^5=159.5\)，三个真实条目的权重和只剩 \(11.107/159.5=0.070\)，这个头的输出被压到没有 sink 时的约 7%，在这个位置几乎被关掉了。sink 给了头“不看”的自由，也就给了它“学成一个常年不看的死头”的可能；这是公式的直接推论，论文没有报告 V4 里是否出现过这种情况。

为什么注意力 logit 不会爆炸

在送进核心注意力之前，查询的每个头和每个 KV 条目都各做一次 RMSNorm（论文称“条目归一化”）。代码里查询的 RMSNorm 不带可学习权重，KV 条目的带权重 1,8。这给注意力打分装了一个硬上限：

RMSNorm 之后，打分有界
(1)\(\displaystyle \operatorname{RMSNorm}(\mathbf x)=\mathbf x\big/\sqrt{\tfrac1c\sum_r x_r^2}\)不带权重的 RMSNorm（忽略 \(\epsilon\)）
(2)\(\displaystyle \norm{\operatorname{RMSNorm}(\mathbf x)}^2=\sum_r x_r^2\Big/\tfrac1c\sum_r x_r^2=c\)所以归一化后的长度恰为 \(\sqrt c\)
(3)\(\displaystyle \norm{\boldsymbol\gamma\odot\operatorname{RMSNorm}(\mathbf e)}\le\max_r\abs{\gamma_r}\sqrt c\)KV 条目带可学习权重 \(\boldsymbol\gamma\)
(4)\(\displaystyle \abs{\tilde{\mathbf q}^\top\tilde{\mathbf e}}/\sqrt c\le\sqrt c\cdot\sqrt c\max_r\abs{\gamma_r}/\sqrt c=\sqrt c\max_r\abs{\gamma_r}\)柯西–施瓦茨不等式 \(\abs{\mathbf a^\top\mathbf b}\le\norm{\mathbf a}\norm{\mathbf b}\)

\(c=512\) 时 \(\sqrt c\approx22.6\)：只要 \(\boldsymbol\gamma\) 不失控，logit 就被钉在一个固定的范围里，无论投影矩阵在训练中长得多大。§5 会看到，这正是 V4 说自己不需要 QK-Clip 的理由。（RoPE 是旋转，不改变长度，所以加 RoPE 不影响这个上界。）

分组输出投影：65,536 维怎样回到 7168 维

问题。 头维是 512、头数是 128，拼起来的输出 \(\mathbf o_t\in\R^{n_hc}\) 有 65,536 维，是隐藏维 7168 的 9.1 倍。直接用一个 \(7168\times65{,}536\) 的矩阵投回去，每层就是 4.70 亿个参数。对照：V3 的 MLA 是 128 头 × 128 维 = 16,384 维，输出矩阵只有 1.17 亿参数。

做法。 把 \(n_h\) 个头分成 \(g\) 组，每组先投到一个较小的 \(d_g\) 维，拼起来再投到 \(d\) 1：

分组输出投影\[\mathbf o^{G}_{t,\kappa}=W^{O1}_{\kappa}\big[\mathbf o_{t,i}\big]_{i\in\text{组}\,\kappa}\in\R^{d_g},\qquad \hat{\mathbf o}_t=W^{O2}\big[\mathbf o^G_{t,1};\dots;\mathbf o^G_{t,g}\big]\in\R^{d}\]\(\kappa=1,\dots,g\) 是组编号（不用 \(\gamma\)，免得与上面 RMSNorm 的权重 \(\boldsymbol\gamma\) 混淆）；\([\cdot]_{i\in\text{组}\,\kappa}\) 表示把这一组的 \(n_h/g\) 个头输出上下拼成一个 \(c\,n_h/g\) 维的列向量；\(W^{O1}_\kappa\in\R^{d_g\times c n_h/g}\)，\(W^{O2}\in\R^{d\times gd_g}\)，要求 \(d_g<c\,n_h/g\)。\(\hat{\mathbf o}_t\in\R^{d}\) 是注意力子层的最终输出，交给 mHC 的 \(H^{post}\)（§5）。Pro：\(g=16\)，每组 8 个头 = 4096 维，\(d_g=1024\)；Flash：\(g=8\)，\(d_g=1024\)。(18.12)
Pro 的一层省了多少参数
(1)\(\displaystyle 7168\times65{,}536=469.8\text{M}\)直接投影
(2)\(\displaystyle 16\times(1024\times4096)=67.1\text{M}\)第一步：16 个组各自一个 \(1024\times4096\)，等价于一个块对角矩阵
(3)\(\displaystyle 7168\times(16\times1024)=7168\times16{,}384=117.4\text{M}\)第二步：拼成 16,384 维后投到 7168
(4)\(\displaystyle (67.1+117.4)/469.8=184.5/469.8=39.3\%\)Flash 同理为 50.0%

第一步是块对角的：一组内的 8 个头可以互相混合，组与组之间要到第二步才混合。这是一种“先局部、后全局”的低秩近似，和 MLA 的查询压缩是同一类思路（低秩分解的参数账见 M02 §2）。

“V4 的注意力还是 MLA”

不是 V2/V3 意义上的 MLA。V4 没有 \(W^{UK}\)、\(W^{UV}\) 上投影，没有矩阵吸收，也没有单独的解耦 RoPE 键：512 维条目本身同时当键和值，RoPE 放在同一个向量的最后 64 维。与 MLA 相同的只有两点：查询的低秩压缩，以及“所有头共用一个 KV 条目”的 MQA 形态。开源代码的类注释仍写着 “Multi-head Latent Attention (MLA)”，那是沿用的旧名 8；FlashMLA 把 V4 归为 MQA 模式、键维度 512，而 V3 系列是 576 5。

把“先查目录再精读”套到 CSA 上

映射。 书 = 全部上下文；每 4 页装订成一“折”，每折写一段合并摘要（压缩条目）；目录的每一行对应一折而不是一页（压缩的 indexer 键）；64 位审稿人按自己的角度给每一行打分，\(w^I\) 决定这次更听谁的；top-\(k\) = 翻开得分最高的 1024 折的摘要；手边另外摊着最近 128 页的原文（滑动窗口）。

收益。 它说明了 CSA 的两处节省从哪里来：目录短了 4 倍，所以“扫目录”便宜了 4 倍；每次翻开的是折而不是页，1024 折就覆盖约 4096 页。

失效的地方。 摘要是合成的：翻开一折，拿到的是 4 页按通道混合后的一个向量，没法只读其中一页（除非它恰好在最近 128 页里）。目录仍要逐行扫完，只是行数少了 4 倍，在 1M 处仍有 262,144 行。

小练习：一个 CSA 层每个查询的核心注意力

V4-Pro，\(t=2^{20}\)。（a）一个查询在一个 CSA 层要和多少个条目做注意力？（b）核心注意力（\(QK^\top\) 与 \(PV\)）要多少原始 FLOPs？（c）如果不做选择、对全部压缩条目做稠密注意力呢？

看答案

（a）\(1024+128=1152\) 个（1024 个被选中的压缩条目 + 128 个窗口条目）。（b）每头每条目 \(2\times512+2\times512=2048\) 次，128 个头：\(1152\times128\times2048=3.02\times10^8\)。（c）\((262{,}144+128)\times128\times2048=6.88\times10^{10}\)，是（b）的 228 倍。

本页要点
  • 查询 \(\mathbf c^Q_t\)（Pro 1536 维）同时展开成 128 个 512 维主查询和 64 个 128 维 indexer 查询 (18.8)。
  • indexer 对压缩后的键打分，次数是 V3.2 的 1/4，再用 FP4 计算；选出 \(k_{\text{sel}}\) 个条目（Pro 1024，Flash 512）(18.9)，覆盖约 4096 个 token 的原文跨度。
  • 核心注意力是共享 KV 的 MQA：512 维条目同时当键和值，128 个头共用；再并入 128 个未压缩的滑动窗口条目；每个头有一个 sink logit，让权重和可以小于 1 (18.10)–(18.11)。
  • Q 与 KV 条目各做 RMSNorm，logit 被限制在 \(\sqrt c\max\abs{\gamma_r}\) 以内；分组输出投影把 65,536 维先分 16 组各投到 1024 维，参数只有直接投影的 39.3% (18.12)。

HCA 与层间交错

CSA 的每个条目只概括 4 个 token，所以到 1M 仍有 26 万个条目，必须靠 indexer 挑。V4 的另一种层走相反的路线：压得狠一点（每 128 个 token 一个条目），条目少到可以全部读一遍，于是连 indexer 都省了。这一页讲 HCA、两种层的排布、三种分支拼起来的“视野”，最后讲一个容易被忽略却必不可少的细节：条目既当键又当值，位置编码该怎么放。

HCA：每 128 个 token 一个条目，全部读

问题。 CSA 的选择有两个代价：indexer 仍要扫 \(t/4\) 行目录；而 top-\(k\) 是硬选择，没被选中的条目在这一层就完全看不见。有没有一种层，能让每个查询总能看到全部历史的某种概括，又不太贵？

图景。 在会议纪要本的类比里，HCA 的秘书每 128 位发言者才写一条“阶段纪要”，但读者每次都把所有阶段纪要从头到尾读一遍，不查目录、不挑。100 万个 token 只有 8192 条阶段纪要，全读一遍的钱比 CSA 查目录还少。代价是分辨率：一条纪要概括 128 个 token，细节必然大量丢失。

数学。 压缩与 CSA 相同，只是 \(m'=128\)、不重叠（只有一路投影）1：

HCA 的压缩\[\mathbf e'_s=\sum_{\tau\in\mathcal B'_s}\mathbf w_\tau\odot\mathbf c_\tau,\qquad [\mathbf w_\tau]_r=\frac{\exp\big([\mathbf z_\tau+\mathbf p_{\tau-m's}]_r\big)}{\sum_{\tau'\in\mathcal B'_s}\exp\big([\mathbf z_{\tau'}+\mathbf p_{\tau'-m's}]_r\big)}\]\(\mathcal B'_s=\{m's,\dots,m'(s+1)-1\}\)；\(\mathbf c_\tau=W^{KV}\mathbf h_\tau\)，\(\mathbf z_\tau=W^{Z}\mathbf h_\tau\)，\(W^{KV},W^Z\in\R^{c\times d}\)；位置偏置 \(P\in\R^{m'\times c}\)。论文式 (20)–(23)。(18.13)
HCA 的核心注意力\[\mathcal K'_t=\big\{\tilde{\mathbf e}'_s:\ s<\lfloor(t+1)/m'\rfloor\big\}\ \cup\ \big\{\tilde{\mathbf u}_\tau:\ t-n_{\text{win}}<\tau\le t\big\}\]然后在 \(\mathcal K'_t\) 上做与 (18.11) 完全相同的共享 KV 注意力（带 sink），再做分组输出投影。没有 indexer，没有 top-\(k\)：全部已完成的压缩块都参与。论文式 (24)–(26)。(18.14)
1M 处一个 HCA 层的账

条目数 \(2^{20}/128=8192\)，加 128 个窗口条目共 8320 个。Pro 的一个 HCA 层、一个查询：\(8320\times128\times2048=2.18\times10^9\) 次运算（原始计数）。对照同一位置的一个 CSA 层：核心注意力 \(1152\times128\times2048=3.0\times10^8\)，indexer \(4.29\times10^9\)。所以按原始计数，HCA 层比 CSA 层便宜一半；§7 会看到，换成“等效 FP8”口径后排序会反过来。存储：每 128 个 token 一个 584 字节的条目，每 token 每层 \(584/128=4.56\) 字节，是 CSA 层（163 字节）的 1/36。

三种分辨率，三种读法

把滑动窗口、CSA、HCA 放在一起看，它们是同一段历史的三种分辨率：

分支 一个条目概括 能看到哪里 1M 处每个查询读几个条目（Pro） 怎么挑
滑动窗口 1 个 token 最近 128 个 token 128 不挑，全读
CSA 4 个 token（读 8 个） 全部已完成的块 1024 indexer 打分，top-\(k\)
HCA 128 个 token 全部已完成的块 8192 不挑，全读

滑动窗口负责“刚说过的话，一字不差”；CSA 负责“远处某几段特别相关的话，看得比较细”；HCA 负责“整个历史的大意，一段不漏”。前两者每层都有；后两者按层交替，每层只有其中一种。

地图的三种比例尺（本页专用的一个图景）

映射。 滑动窗口 = 你脚下这条街的街景照片；CSA = 按需调出的几张 1:5000 街区图，由搜索框（indexer）决定调哪几张；HCA = 一张 1:1,000,000 的全国地图，每次都整张展开。

收益。 它说明为什么三者缺一不可：只有全国地图，找不到具体的门牌；只有街区图，搜索框漏掉的地方就是盲区；只有街景，走不出这条街。

失效的地方。 地图的比例尺是固定的几何缩放，而条目的“缩放”是学出来的逐通道加权，不同内容被保留的程度不同；而且在注意力里三种比例尺共用一个 softmax，模型每一步都在它们之间重新分配权重，真看地图的人不会这样同时看三张。

层间交错：两种层怎样排

V4 的每一层只用 CSA 或 HCA 中的一种，按层交替 1。开源 config.json 的 compress_ratios 列表逐层写出了压缩率（0 = 纯滑动窗口，4 = CSA，128 = HCA）8：

  • V4-Pro（61 层）：第 0、1 层是 HCA，之后偶数层 CSA、奇数层 HCA。数一数：第 2、4、…、60 层共 30 层 CSA；第 3、5、…、59 层共 29 层 HCA，加上开头 2 层，共 31 层 HCA。
  • V4-Flash（43 层）：第 0、1 层是纯滑动窗口注意力（没有任何压缩分支），之后偶数层 CSA、奇数层 HCA：21 层 CSA、20 层 HCA。
  • 两款模型的 MTP 层都是纯滑动窗口。

论文没有解释为什么 Pro 以 HCA 开头、Flash 以纯滑动窗口开头，本课不猜。交替排布的一个直接后果是：从第 2 层起，任何相邻两层里，都有一层能看到全部历史的概括（HCA），另一层能精读挑出来的片段（CSA），信息可以借残差流在两种视野之间来回传递。

一个查询到底看见了什么

用一个具体位置把三种分支的视野拼起来。查询位置 \(t=1000\)（从 0 计）：

\(t=1000\) 时三种分支各看得见哪些 token
(1)\(\displaystyle \text{滑动窗口}:\ \tau\in(1000-128,\ 1000]=\{873,\dots,1000\}\)最近 128 个 token，未压缩
(2)\(\displaystyle \text{CSA}:\ s<\lfloor1001/4\rfloor=250\)条目 0–249，到 token 999
(3)\(\displaystyle \text{CSA 选择}:\ \min(1024,250)=250\)\(k_{\text{sel}}\) 比可见条目多，全选
(4)\(\displaystyle \text{HCA}:\ s<\lfloor1001/128\rfloor=7\)块 0–6，到 token 895
(5)\(\displaystyle 896\ \text{到}\ 1000\ \text{由窗口覆盖}:\ 873\le896\)空洞 896–1000 全在窗口里

最后一行不是巧合。一般地，HCA 在位置 \(t\) 尚未压缩的 token 个数是 \((t+1)\bmod m'\)，最多 \(m'-1=127\) 个；窗口有 \(n_{\text{win}}=128\) 个，所以窗口总能盖住 HCA 的空洞；CSA 的空洞最多 3 个，更不在话下。\(n_{\text{win}}=m'=128\) 恰好让三种分支无缝衔接（这是笔者从两个数值看出的关系，论文没有这样表述）。

同一个查询到了 1M

\(t=2^{20}-1\)：窗口 128 个；CSA 可见 \(2^{20}/4=262{,}144\) 个条目，选 1024 个（0.39%）；HCA 可见 8192 个块，全读。于是一个 Pro 查询在一对相邻的 CSA/HCA 层里，一共读 \(1152+8320=9472\) 个条目，而它面对的历史有 1,048,576 个 token。V3.2 在一层里要读 2048 个条目，外加扫 1,048,576 行目录。

部分 RoPE 与输出逆旋转

问题。 RoPE（第 5 课）把位置写进查询和键：位置 \(t\) 的查询与位置 \(p\) 的键各转一个角度，点积只依赖角度之差，也就是相对位置 \(p-t\)。但在 V4 里，条目同时是值。如果条目带着“转过 \(p\) 角度”的分量被加权求和进输出，输出就带上了绝对位置 \(p\)：同一段话出现在上下文的开头还是结尾，注意力输出会不一样。

做法。 V4 只对查询和条目的最后 64 维加 RoPE（其余 448 维不带位置）；并对每个头输出 \(\mathbf o_{t,i}\) 的最后 64 维，再转一个 \(-t\) 的角度 1。下面证明这样输出就只含相对位置。为什么是 64 维而不是全部 512 维，论文没有解释。两个可以核对的旁证是：V2/V3 的解耦 RoPE 键也是 64 维（第 9 课）；而 §2 的条目格式里，只有这 64 维以 BF16 存放、其余以 FP8 存放，带位置的维度越少，这部分存储越省（这是笔者从格式上看到的关联，不是论文给的理由）。

旋转矩阵的两条性质读过第 5 课或 M03 的可以跳过

把 64 维按两两一对分成 32 个平面，RoPE 在每个平面里转一个角度，角度与位置成正比：位置 \(p\) 在第 \(k\) 个平面里转 \(p\,\theta_k\)。记整块的旋转为 \(R_p\)。它有两条性质：转置等于反转，\(R_p^\top=R_{-p}\)（旋转矩阵是正交矩阵）；连转等于相加，\(R_aR_b=R_{a+b}\)（同一平面里先转 \(b\) 再转 \(a\)，一共转了 \(a+b\)）。两条性质的推导见 M03 §5，64 维的块对角旋转见 M03 §6。

设查询的 RoPE 部分为 \(\mathbf q^r\)，条目 \(s\) 的 RoPE 部分为 \(\mathbf e^r_s\)，条目的位置为 \(p_s\)。代码把条目的位置取为它所概括的块的第一个 token：CSA 条目 \(s\) 取 \(4s\)，HCA 条目取 \(128s\)，窗口条目就是它自己的位置 8。

打分只依赖相对位置
(1)\(\displaystyle \tilde{\mathbf q}^r=R_t\,\mathbf q^r,\qquad \tilde{\mathbf e}^r_s=R_{p_s}\mathbf e^r_s\)查询转 \(t\)，条目转 \(p_s\)
(2)\(\displaystyle (\tilde{\mathbf q}^r)^\top\tilde{\mathbf e}^r_s=(\mathbf q^r)^\top R_t^\top R_{p_s}\,\mathbf e^r_s\)转置的“穿脱法则” \((AB)^\top=B^\top A^\top\)
(3)\(\displaystyle =(\mathbf q^r)^\top R_{-t}R_{p_s}\,\mathbf e^r_s=(\mathbf q^r)^\top R_{p_s-t}\,\mathbf e^r_s\)\(R_t^\top=R_{-t}\)，\(R_{-t}R_{p_s}=R_{p_s-t}\)
逆旋转之后，输出也只依赖相对位置
(1)\(\displaystyle \mathbf o^r=\sum_s a_s\,\tilde{\mathbf e}^r_s=\sum_s a_s R_{p_s}\mathbf e^r_s\)(18.11) 的输出，只看 RoPE 那 64 维；由上一个推导，\(a_s\) 对位置的依赖只经过 \(p_s-t\)
(2)\(\displaystyle R_{-t}\,\mathbf o^r=\sum_s a_s R_{-t}R_{p_s}\mathbf e^r_s\)对输出的最后 64 维施加位置 \(-t\) 的旋转；旋转是线性的，可以移进求和
(3)\(\displaystyle =\sum_s a_s R_{p_s-t}\,\mathbf e^r_s\)连转等于相加
部分 RoPE 的两个结论\[\tilde{\mathbf q}^{r\top}\tilde{\mathbf e}^r_s=\mathbf q^{r\top}R_{p_s-t}\,\mathbf e^r_s,\qquad R_{-t}\sum_s a_s\tilde{\mathbf e}^r_s=\sum_s a_sR_{p_s-t}\,\mathbf e^r_s\]打分和输出里出现的都只有 \(p_s-t\)。前 448 维不带旋转，本来就与位置无关。(18.15)

这两个结论是对一组给定的条目说的：条目内容 \(\mathbf e_s\) 相同，输出就只随相对位置变。压缩的块边界却钉在绝对位置上（4 和 128 的整数倍），把整段上下文平移 \(\Delta\) 个 token 时，只有 \(\Delta\) 是 128 的倍数（HCA）或 4 的倍数（CSA），每个条目概括的那几个 token 才保持不变；否则分块方式变了，条目本身就不同。所以对同一段内容，“输出只随相对位置变”严格地说只在平移 128 的倍数时成立；对任意平移，能保证的是 RoPE 这一路不再把绝对位置带进输出（这是笔者从公式推出的限定，论文没有讨论）。

用一个二维平面验证

只看一个平面，每个位置转 \(\theta=0.1\) 弧度。取 \(\mathbf q^r=\mathbf e^r=(1,0)\)。情形 A：\(t=10\)，\(p=4\)。情形 B：\(t=110\)，\(p=104\)。两种情形的相对位置都是 \(-6\)。

打分：A 为 \(\cos(0.4-1.0)=\cos(-0.6)=0.825\)；B 为 \(\cos(10.4-11.0)=0.825\)。相同。

输出（这一个条目的贡献）：不做逆旋转时，A 是 \(R_{0.4}(1,0)=(\cos0.4,\sin0.4)=(0.921,\ 0.389)\)，B 是 \((\cos10.4,\sin10.4)=(-0.561,\ -0.828)\)，完全不同——输出泄露了绝对位置。做了逆旋转，两者都是 \(R_{-0.6}(1,0)=(0.825,\ -0.565)\)。

论文写的是“位置 \(-i\)”

V4 论文 §2.3.3 说对每个头的输出施加“位置 \(-i\)”的 RoPE，而 \(i\) 在论文式 (19) 里是头的编号；同一小节的式 (27) 又用 \(i\) 表示查询 token。开源代码用的是查询 token 的位置（freqs_cis 取当前位置、做共轭旋转），FlashMLA 把这一步叫 “O-RoPE (conjugate)” 8,5。按上面的推导，只有转 \(-t\) 才得到相对位置。所以这里应理解为记号混用，本课统一写 \(R_{-t}\)。

RoPE 的基数与 YaRN。 论文没写，代码里有：带压缩的层（CSA、HCA）用基数 \(\theta_{\text{base}}=160{,}000\)，并加 YaRN（第 5 课）把原长 65,536 放大 16 倍，\(16\times65{,}536=1{,}048{,}576\)，正好是 1M 上下文的 token 数；纯滑动窗口的层（Flash 的前两层和 MTP 层）用基数 10,000、不加 YaRN 8。笔者推测其理由是：纯窗口层只会看到 127 以内的相对距离，用不着为长距离设计的频率。

本页要点
  • HCA (18.13)–(18.14)：每 \(m'=128\) 个 token 一个条目、不重叠、只有一路投影；不做选择，对全部已完成的条目加 128 个窗口条目做共享 KV 注意力。1M 时 8192 个条目，每 token 每层只存 4.56 字节。
  • 三种分辨率：窗口（1 token，最近 128 个）、CSA（4 token，挑 1024 个）、HCA（128 token，全读）。Pro 30 CSA + 31 HCA，前两层 HCA；Flash 21 CSA + 20 HCA，前两层纯窗口；之后逐层交替。
  • HCA 尚未压缩的尾部最多 127 个 token，窗口 128 个，恰好盖住；\(t=1000\) 时窗口 873–1000，HCA 只到 895。
  • RoPE 只加在最后 64 维；因为条目也是值，输出最后 64 维再转 \(-t\)，于是对给定的条目，打分和输出都只依赖相对位置 \(p_s-t\) (18.15)；块边界钉在 4 与 128 的倍数上，所以整段平移只在平移量是 128 的倍数时才完全不改变输出。

mHC 与 Muon

注意力之外，V4 还有两项升级，一项改结构，一项改训练。mHC 把残差流从 1 条扩成 4 条，数学已经在第 16 课讲过，这里只讲它怎样接进 V4、花了多少。Muon 是一个新的优化器：它不再逐个元素地决定每个参数走多远，而是把整个更新矩阵“正交化”。这一页的大半篇幅给 Muon，因为它的核心运算——牛顿–舒尔茨迭代——完全可以在纸上算一遍。

mHC 在 V4 里的样子

问题（回顾第 16 课）。 标准残差 \(\mathbf x_{l+1}=\mathbf x_l+\mathcal F_l(\mathbf x_l)\) 只有一条“传送带”。Hyper-Connections 把它扩成 \(n_{hc}\) 条，并让层与层之间学习怎样在带与带之间调度，表达力更强；但 V4 的作者也观察到，朴素的 HC 叠很多层时训练常常数值不稳定 1。mHC 的办法是把带与带之间的调度矩阵约束成双随机矩阵：每行、每列的和都是 1，元素非负 12。双随机矩阵为什么不放大信号、Sinkhorn 迭代怎样把任意正矩阵变成双随机矩阵，见 M11 §2–§5。

数学。 把 4 条残差流按行堆成 \(X_l\in\R^{4\times d}\)（Pro：\(4\times7168\)）。V4 论文式 (1) 用课程记号写成 1：

V4 的一个 mHC 子层\[X_{l+1}=H^{res}_l\,X_l+(H^{post}_l)^\top\,\mathcal F_l\big(H^{pre}_l X_l\big),\qquad H^{pre}_l\in\R^{1\times4},\ \ H^{res}_l\in\R^{4\times4},\ \ H^{post}_l\in\R^{1\times4}\]\(H^{pre}_l\) 把 4 条流加权汇成 1 条（\(1\times d\)）送进子层 \(\mathcal F_l\)（CSA/HCA 注意力或 MoE，输入输出都是 \(d\) 维）；\(H^{post}_l\) 把子层输出按 4 个权重分发回 4 条流（\((H^{post}_l)^\top\) 是 \(4\times1\)，乘 \(1\times d\) 的输出得 \(4\times d\)）；\(H^{res}_l\) 在 4 条流之间做双随机的混合。V4 论文写作 \(A_l=H^{pre}_l\)、\(B_l=H^{res}_l\)、\(C_l=(H^{post}_l)^\top\)：与第 16 课一样，写入映射记成 \(1\times4\) 的行，所以式中带转置。(18.16)

三个映射都不是固定参数，而是由当前的残差流动态生成（论文式 (3)–(8)）：

动态生成三个映射\[\begin{aligned}\hat{\mathbf x}_l&=\operatorname{RMSNorm}\big(\operatorname{vec}(X_l)\big)\in\R^{4d}\\ H^{pre}_l&=\sigma\big(\alpha^{pre}_l\,(W^{pre}_l\hat{\mathbf x}_l)^\top+S^{pre}_l\big),\qquad H^{post}_l=2\,\sigma\big(\alpha^{post}_l\,(W^{post}_l\hat{\mathbf x}_l)^\top+S^{post}_l\big)\\ H^{res}_l&=\operatorname{Sinkhorn}_{20}\Big(\exp\big(\alpha^{res}_l\operatorname{Mat}(W^{res}_l\hat{\mathbf x}_l)+S^{res}_l\big)\Big)\end{aligned}\]\(\operatorname{vec}(X_l)\) 把 \(4\times d\) 的矩阵按行拉成一个 \(4d\) 维向量；\(\operatorname{Mat}(\cdot)\) 把 16 个数排回 \(4\times4\) 矩阵。\(W^{pre}_l,W^{post}_l\in\R^{4\times4d}\)，\(W^{res}_l\in\R^{16\times4d}\)（第 16 课 (16.26) 把 \(\hat{\mathbf x}_l\) 写成 \(1\times4d\) 的行向量、投影写成 \(4d\times4\)，与这里只差一个转置）；\(S\) 是静态偏置（形状与对应的 \(H\) 相同）；\(\alpha\) 是三个标量门控因子，初始化为小值，所以训练开始时映射主要由静态偏置决定；\(\sigma(\cdot)\) 是 sigmoid，\(H^{post}\) 的取值范围因此是 \((0,2)\)（与第 16 课相同；本页后面带下标的 \(\sigma_i\) 和 (18.20) 里的自变量 \(\sigma\) 指奇异值，与 sigmoid 无关）。\(\operatorname{Sinkhorn}_{20}\)：交替做列归一化、行归一化共 20 轮（\(t_{\max}=20\)）。(18.17)
V4 的 mHC 有多少参数、多少个数

每个子层的动态部分一共要生成 \(4+4+16=24\) 个数（\(H^{pre}\) 4 个、\(H^{post}\) 4 个、\(H^{res}\) 16 个）。开源代码用一个线性层一次产出这 24 个数，权重形状 \(24\times4d\) 8。Pro：\(24\times28{,}672=688{,}128\) 个参数；每层有注意力和 MoE 两个子层，各一套，共 \(1{,}376{,}256\)；61 层合计约 \(8.4\times10^7\)，占 1.6T 的 0.005%。论文 §3.3 提到的“输出维只有 24 的矩阵乘”指的就是它：输出太窄，GPU 上要专门写确定性的分块归约 1。

一个标量玩具：双随机矩阵在守恒什么

设 \(d=1\)，4 条流的当前值 \(X_l=(1,2,3,4)^\top\)，总和 10。取 \(H^{res}=\tfrac14\mathbf 1\mathbf 1^\top\)（每个元素 0.25，行和、列和都是 1），\(H^{pre}=(0.5,0.5,0.5,0.5)\)，子层 \(\mathcal F(x)=0.2x\)，\(H^{post}=(1,1,1,1)\)。

Muon：问题从哪里来

含义。 Muon 是一种针对矩阵形参数的优化器：它先像普通动量法那样累积梯度，然后把累积出来的矩阵“正交化”——保留它的方向结构，把所有奇异值都换成 1——再用这个矩阵做更新。

理解。 AdamW（第 2 课，M07 §4）把一个 \(1536\times7168\) 的权重矩阵（例如 Pro 的 \(W^{DQ}\)）当成 1,100 万个互不相干的数，每个数按自己的梯度历史决定步长。可这个矩阵是一个线性映射：它把输入空间的某些方向拉长、某些方向压短。如果动量矩阵在少数几个方向上特别“强”（奇异值很大），而在其余方向上很弱，那么直接用它更新，参数几乎只沿那几个强方向移动。正交化把所有方向的步长拉平：强方向不再独占更新，弱方向也得到同样大小的一步。

奇异值分解与“正交因子”读过第 9 课或 M02 的可以跳过

任何 \(p\times q\) 矩阵都能写成 \(M=U\Sigma V^\top\)：\(U\) 的各列是输出空间里一组互相垂直的单位向量，\(V\) 的各列是输入空间里的一组，\(\Sigma\) 是对角线上的非负数 \(\sigma_1\ge\sigma_2\ge\dots\)，叫奇异值。读法：\(M\) 把输入方向 \(\mathbf v_i\) 送到输出方向 \(\mathbf u_i\)，并乘上 \(\sigma_i\)。把所有 \(\sigma_i\) 换成 1，得到 \(UV^\top\)，叫 \(M\) 的正交因子（极分解里的那个正交部分）：方向对应关系不变，但每个方向的“放大倍数”都是 1。谱范数 \(\norm{M}_2=\sigma_1\) 是最大的放大倍数，Frobenius 范数 \(\norm{M}_F=\sqrt{\sum_i\sigma_i^2}\) 是所有元素平方和的平方根。SVD 见 M02 §3，两种范数见 M02 §4；Muon 的正交化与牛顿–舒尔茨迭代在 M07 §6–§7 有更完整的讲解。

类比：调音台上的推子（本页专用的一个图景）

映射。 把动量矩阵 \(M\) 想成一台调音台。每一对奇异向量 \((\mathbf v_i,\mathbf u_i)\) 是一条通道：信号从输入端口 \(\mathbf v_i\) 接进来，从输出端口 \(\mathbf u_i\) 送出去；奇异值 \(\sigma_i\) 是这条通道的推子位置。AdamW 像是逐个旋钮地调（每个矩阵元素按自己的历史各调各的）；Muon 保留所有通道的接线（\(U\)、\(V\) 不变），把每一个推子都推到同一格（所有 \(\sigma_i\) 换成 1）。

收益。 它说清了正交化改了什么、没改什么：更新的方向结构原样保留，只有“哪条通道声音大”被抹平。平时被几条强通道盖住的弱通道，这一步也能走出同样大小的一步。

失效的地方。 真调音台的通道是固定的，这里的“通道”每一步都从新的动量矩阵重新算出来。推子也并不能真的全部推平：下面会讲到，正交化实际是用 10 步多项式迭代 (18.19) 近似的，太小的奇异值来不及被拉起来。笔者按 (18.20) 用 Python 迭代：相对 \(\norm{M}_F\) 的起点 \(\sigma_0=10^{-5}\) 最后到 0.686，\(10^{-6}\) 只到 0.079，\(10^{-7}\) 只到 0.0079。比 \(\norm{M}_F\) 小五个数量级以上的方向，基本还保持“静音”。

为什么偏偏是 \(UV^\top\)？ 下面这个线性代数事实给出一种解读（这是笔者按数学给出的理解，不是 Muon 作者原话）：如果只允许更新矩阵 \(O\) 的谱范数（最大奇异值）不超过 1，那么让损失一阶下降最多的方向恰好是 \(UV^\top\)。

在谱范数预算下，\(UV^\top\) 是最陡的方向
(1)\(\displaystyle \langle M,O\rangle=\tr(M^\top O)=\tr(V\Sigma U^\top O)=\sum_i\sigma_i\,\mathbf u_i^\top O\,\mathbf v_i\)内积 = 一阶下降量；代入 SVD，\(\tr(AB)=\tr(BA)\)
(2)\(\displaystyle \abs{\mathbf u_i^\top O\mathbf v_i}\le\norm{\mathbf u_i}\,\norm{O\mathbf v_i}\le\norm{O}_2\)柯西–施瓦茨；谱范数定义；\(\mathbf u_i,\mathbf v_i\) 是单位向量
(3)\(\displaystyle \langle M,O\rangle\le\sum_i\sigma_i\quad(\norm{O}_2\le1)\)逐项放大后相加
(4)\(\displaystyle O=UV^\top:\ \mathbf u_i^\top UV^\top\mathbf v_i=1\Rightarrow\langle M,UV^\top\rangle=\sum_i\sigma_i\)\(U^\top\mathbf u_i\)、\(V^\top\mathbf v_i\) 都是第 \(i\) 个坐标向量，上界取到

对照 AdamW：如果只允许每个元素的绝对值不超过 1，最陡的方向是逐元素取符号 \(\operatorname{sign}(M)\)——这是理解 Adam 类方法的一个常见角度。两者的差别在于“步长预算”按什么量：按每个数，还是按整个矩阵作为线性映射的放大倍数。

Muon 的算法

V4 的算法 1（改写成课程记号）对每个“逻辑上独立”的矩阵 \(W\in\R^{p\times q}\) 执行 1：

V4 的 Muon 更新\[\begin{aligned}G_t&=\nabla_W\mathcal L_t(W_{t-1}) && \text{梯度}\\ M_t&=\mu M_{t-1}+G_t && \text{动量，}\mu=0.95\\ O'_t&=\operatorname{HybridNS}\big(\mu M_t+G_t\big) && \text{Nesterov 技巧 + 正交化}\\ O_t&=O'_t\cdot\sqrt{\max(p,q)}\cdot\gamma_{\text{rms}} && \gamma_{\text{rms}}=0.18\\ W_t&=W_{t-1}(1-\eta\lambda)-\eta\,O_t && \text{权重衰减 }\lambda=0.1\end{aligned}\]\(t\) 在这里是训练步数（不是 token 位置）；\(\eta\) 是学习率；\(\mathcal L_t\) 是第 \(t\) 步那个 batch 上的损失。Nesterov 技巧：送进正交化的不是 \(M_t\)，而是“往前再看一步”的 \(\mu M_t+G_t\)。权重衰减、Nesterov 和 RMS 缩放三件事沿用 Liu 等人的做法 13；与他们不同的是正交化用“混合牛顿–舒尔茨迭代”，缩放常数用 0.18 而不是 0.2。(18.18)

正交化本来要做一次 SVD，对大矩阵太贵，也不适合 GPU 上的低精度运算。Muon 用一个只含矩阵乘法的迭代来近似它，叫牛顿–舒尔茨迭代（Newton–Schulz iteration）14：

牛顿–舒尔茨迭代\[X_0=\frac{M}{\norm{M}_F},\qquad X_k=a\,X_{k-1}+b\,(X_{k-1}X_{k-1}^\top)X_{k-1}+c\,(X_{k-1}X_{k-1}^\top)^2X_{k-1}\]\(\norm{M}_F=\sqrt{\sum_{ij}M_{ij}^2}\) 是 Frobenius 范数；\(a,b,c\) 是多项式的三个系数（这里的 \(c\) 与条目维度 \(c=512\) 无关，沿用 Muon 文献的写法）。V4 用 10 步：前 8 步 \((a,b,c)=(3.4445,\,-4.7750,\,2.0315)\)，后 2 步 \((2,\,-1.5,\,0.5)\)（论文式 (28)）。(18.19)

这个迭代只动奇异值

(18.19) 看上去是一堆矩阵乘法，其实它对矩阵的“方向”一点都不碰，只对奇异值做一个一元多项式。推导如下：

奇次矩阵多项式作用在奇异值上
(1)\(\displaystyle XX^\top=U\Sigma V^\top V\Sigma U^\top=U\Sigma^2U^\top\)\(V^\top V=I\)（\(V\) 的列是正交单位向量）
(2)\(\displaystyle (XX^\top)X=U\Sigma^2U^\top U\Sigma V^\top=U\Sigma^3V^\top\)\(U^\top U=I\)
(3)\(\displaystyle (XX^\top)^2X=U\Sigma^5V^\top\)同理再乘一次
(4)\(\displaystyle aX+b(XX^\top)X+c(XX^\top)^2X=U\big(a\Sigma+b\Sigma^3+c\Sigma^5\big)V^\top\)三项有相同的 \(U\) 和 \(V^\top\)，可以合并
迭代等价于对每个奇异值做一元迭代\[\begin{aligned}\sigma\ \mapsto\ \varphi(\sigma)&=a\sigma+b\sigma^3+c\sigma^5\\ \varphi_A(\sigma)&=3.4445\,\sigma-4.7750\,\sigma^3+2.0315\,\sigma^5\qquad(\text{前 8 步})\\ \varphi_B(\sigma)&=2\,\sigma-1.5\,\sigma^3+0.5\,\sigma^5\qquad(\text{后 2 步})\end{aligned}\]\(U\)、\(V\) 在整个迭代中保持不变。所以问题化成了一个一元问题：找一个奇次多项式，反复作用后能把 \((0,1]\) 里的每个数都推到 1。先除以 \(\norm{M}_F\) 是为了保证起点都在 \((0,1]\) 里：最大奇异值不超过 Frobenius 范数。(18.20)

两组系数分工明确：

  • \(\varphi_A\) 负责“快”。 它在 0 处的斜率是 \(a=3.4445\)：很小的奇异值每步放大约 3.4 倍，从 \(10^{-3}\) 出发，第 6 步就被拉到 1 附近（1.17）。代价是它不收敛到 1：\(\varphi_A(1)=0.701\)，最大值 \(1.2024\)（在 \(\sigma=0.554\) 处），它的正不动点是 0.868 与 1.264。反复迭代时，奇异值会在区间 \([0.682,\ 1.134]\) 里来回振荡——这个区间在 \(\varphi_A\) 下映回自身：\(\varphi_A\) 在区间内的最小值是它在 \(\sigma=1.050\) 处的局部极小 0.682，最大值在左端点，\(\varphi_A(0.682)=1.134\)，恰好是区间的两端。所以一旦进入就出不来；而区间里的不动点 0.868 处斜率 \(\varphi_A'(0.868)=-1.58\)，绝对值大于 1，是排斥的，迭代也收敛不到它。Jordan 的原版 Muon 只用 5 步 \(\varphi_A\)，设计目标本来就只是“落在约 \([0.7,1.3]\)”，近似正交即可 14。
  • \(\varphi_B\) 负责“准”。 它满足 \(\varphi_B(1)=1\)、\(\varphi_B'(1)=0\)：1 是不动点，而且在 1 处切线水平，误差会被平方地消灭。
为什么 \(\varphi_B\) 两步就够
(1)\(\displaystyle \varphi_B'(\sigma)=2-4.5\sigma^2+2.5\sigma^4,\quad \varphi_B'(1)=0\)求导
(2)\(\displaystyle \varphi_B(1+\varepsilon)=1+0.5\varepsilon^2+3.5\varepsilon^3+2.5\varepsilon^4+0.5\varepsilon^5\)按二项式展开，一次项系数 \(2-4.5+2.5=0\)

(4)\(\displaystyle 1.134\to1.018\to1.0002,\qquad 0.682\to0.962\to1.0005\)8 步 \(\varphi_A\) 之后的两个最坏端点，各再做两步 \(\varphi_B\)（第二步已进入二阶区）

更新的大小：为什么乘 \(\sqrt{\max(p,q)}\cdot0.18\)

问题。 正交因子的“大小”取决于形状：一个 \(1536\times7168\) 的矩阵和一个 \(65{,}536\times1536\) 的矩阵，正交化后元素的典型大小差好几倍。如果所有矩阵共用一个学习率，形状不同的层实际走的步长就不同。

满秩正交因子的 RMS 只由形状决定
(1)\(\displaystyle \norm{UV^\top}_F^2=\tr\big(VU^\top UV^\top\big)=\tr(V^\top V)=\min(p,q)\)\(U^\top U=I\)；\(V\) 有 \(\min(p,q)\) 列单位正交向量
(2)\(\displaystyle \operatorname{RMS}(UV^\top)=\sqrt{\norm{UV^\top}_F^2/(pq)}=\sqrt{\min(p,q)/(pq)}\)RMS = 元素平方的平均再开方
(3)\(\displaystyle =1/\sqrt{\max(p,q)}\)\(pq=\min(p,q)\max(p,q)\)
(4)\(\displaystyle \operatorname{RMS}\big(UV^\top\cdot\sqrt{\max(p,q)}\cdot\gamma_{\text{rms}}\big)=\gamma_{\text{rms}}\)乘上缩放因子，形状的影响被抵消

这就是 Liu 等人论文的 Lemma 1 与“对齐 AdamW 的 update RMS”：他们观察到 AdamW 的更新 RMS 经验上在 0.2–0.4，于是把 Muon 的更新也缩放到这个量级，就能直接复用 AdamW 的学习率和权重衰减 13。V4 把常数从 0.2 换成 0.18 1。

两个形状

\(1536\times7168\)（Pro 的 \(W^{DQ}\)，输出 × 输入）：正交化后 RMS \(=1/\sqrt{7168}=0.01181\)，乘 \(\sqrt{7168}\times0.18\) 后是 0.18。\(65{,}536\times1536\)（Pro 的 \(W^{UQ}\)）：RMS \(=1/\sqrt{65{,}536}=0.00391\)，乘 \(\sqrt{65{,}536}\times0.18=46.08\) 后也是 0.18。

工程。 Muon 与 ZeRO 天生冲突（ZeRO 见 M10 §5）：ZeRO 把每个参数矩阵切碎分给不同的卡，而正交化需要完整的矩阵。V4 的解法 1：稠密参数限制 ZeRO 的并行规模，用背包算法把整块矩阵分给各个 rank（每个 rank 不超过 5 个矩阵，填充带来的显存开销小于 10%）；MoE 的参数按专家各自独立正交化；形状相同的矩阵合并成一批做牛顿–舒尔茨；并且发现迭代用 BF16 矩阵乘法仍然稳定，于是把 MoE 梯度用随机舍入量化成 BF16 再同步，通信量减半。

牛顿–舒尔茨本身贵不贵

对 \(p\times q\)（\(q\le p\)；否则先转置）的矩阵，一步迭代约 \(2(2pq^2+q^3)\) 次运算 14。\(W^{DQ}\) 转置后是 \(7168\times1536\)：\(2\times(2\times7168\times1536^2+1536^3)=7.49\times10^{10}\)，10 步 \(7.49\times10^{11}\)。同一个矩阵在一个训练步里的前向加反向是每 token \(6\times7168\times1536=6.6\times10^7\) 次，乘以 Pro 的 batch 94.4M token，约 \(6.2\times10^{15}\)。牛顿–舒尔茨只占它的约 0.012%（笔者复算）。贵的不是算，而是上面说的“要完整矩阵”带来的通信与分片问题。

本页要点
  • mHC (18.16)–(18.17)：4 条残差流 \(X_l\in\R^{4\times d}\)；每个子层动态生成 \(H^{pre}\)（σ，1×4）、\(H^{post}\)（2σ，1×4）、\(H^{res}\)（Sinkhorn 20 轮，4×4 双随机），共 24 个数；每层两套；墙钟开销 6.7%。
  • Muon (18.18)：动量 → Nesterov → 正交化 → 乘 \(\sqrt{\max(p,q)}\times0.18\) → 乘法式权重衰减。\(UV^\top\) 是谱范数预算下的最陡方向。
  • 牛顿–舒尔茨 (18.19)–(18.20) 只改奇异值：\(\varphi_A\)（8 步）把小奇异值快速拉大但只能振荡在 \([0.68,1.13]\)；\(\varphi_B\)（2 步）以二阶收敛把它们钉到 1，起点 \(\sigma_0\in[10^{-3},1]\) 时误差 \(<6\times10^{-4}\)（更小的起点来不及拉满）。
  • AdamW 只留给 embedding、预测头、RMSNorm 权重与 mHC 的静态偏置、门控因子；V4 不用 QK-Clip，靠 Q/KV 的 RMSNorm 防 logit 爆炸。

训练与后训练

架构讲完了，这一页讲模型是怎样被“养”出来的：用什么数据、按什么日程把上下文从 4K 拉到 1M、训练中遇到的不稳定怎样压住；后训练怎样先培养一批各有所长的专家，再把它们合成一个模型；以及 V4 对外提供的三档“推理强度”是怎么来的。凡是论文没有给出的数字（训练成本、GPU 小时、各阶段的 token 数），本页一律不写。

预训练数据

V4 的预训练语料在 V3 的基础上扩充，总量超过 32T token：Flash 训练 32T，Pro 训练 33T 1。论文列出的改动有五条：加强多样性与长文档；过滤成批自动生成、模板化的网页，以防“模型坍塌”（在模型生成的数据上反复训练导致分布退化）；中期训练加入智能体（agentic）数据以增强编码能力；更大的多语言语料；专门整理科学论文、技术报告这类长文档。

分词器沿用 V3，只新增了少量用于构造上下文的特殊 token，词表仍是“128K”（config.json 里是 129,280 个条目）；沿用 V3 的 token-splitting 与 FIM（填空式训练，第 6 课）；文档按来源打包，以减少截断。与 V3 不同的一点是样本级注意力掩码。

含义。 一条训练序列里往往拼着好几篇文档。样本级掩码让每个 token 只能看同一篇文档里、在它之前的 token。理解。 没有它，第二篇文档的开头会“看到”第一篇文档的结尾，学到并不存在的跨文档关联；序列越长（V4 训练到 1M），一条序列里拼进的文档越多，这个问题越重。数学。 掩码 \(\mathcal M_{t,\tau}=0\) 当且仅当 \(\tau\le t\) 且 \(\operatorname{doc}(\tau)=\operatorname{doc}(t)\)，否则为 \(-\infty\)，加在注意力打分上。对压缩注意力还多一层含义：上下文并行的实现里，每篇拼进来的文档各自独立压缩，末尾凑不满 \(m\) 个的 token 直接丢弃，不和下一篇文档合成一个条目 1。

训练日程：从 4K 到 1M，从稠密到稀疏

长度。 训练序列从 4K 起，逐步扩到 16K、64K，最后到 1M；预训练结束时就原生支持 1M 上下文 1。

稠密到稀疏。 Flash 的前 1T token 用稠密注意力预热（论文没说这一阶段压缩分支是否已经启用；笔者的读法是 CSA 的压缩条目全部参与、不做 top-\(k\)），在 64K 长度的阶段才引入稀疏选择，之后一直保持稀疏；引入时先短暂预热 lightning indexer。Pro 的稠密阶段更长，引入方式相同。这正是第 14 课 DSA 的“两阶段”思路：先让 indexer 学会模仿稠密注意力，再让整个模型适应只读被选中的条目（第 14 课 §6）。各长度阶段各训多少 token、Pro 的稠密阶段有多长，论文没有给。

训练不稳定：两招，以及作者的坦白

问题。 论文报告：训练中的 loss 尖峰总与 MoE 层里的离群值（数值特别大的激活）同时出现，而路由机制会把离群值放大；遇到尖峰就回滚到之前的检查点，只能治标 1。V4 用了两招。

第一招：Anticipatory Routing（预判路由）。 第 \(t\) 步用当前参数 \(\theta_t\) 计算特征，但每个 token 去哪几个专家，用的是更早的参数 \(\theta_{t-\Delta t}\) 算出的路由：

Anticipatory Routing\[\mathcal E_t(\mathbf x)=\operatorname{TopK}_6\Big(\big\{s_{i}(\mathbf x;\theta_{t-\Delta t})+b_i\big\}_{i}\Big),\qquad \text{专家的计算与门控值仍用 }\theta_t\]\(\mathcal E_t(\mathbf x)\)：第 \(t\) 步 token \(\mathbf x\) 被分到的 6 个路由专家。这是笔者按论文的文字描述写成的公式，论文没有给式子。实现上，在第 \(t-\Delta t\) 步就提前取出第 \(t\) 步的数据、预先算好并缓存路由。\(\Delta t\) 取多少，论文没有给。(18.21)

它有约 20% 的墙钟开销，所以不是一直开着：系统检测到 loss 尖峰时自动做一次短回滚、打开它，训练一段时间后恢复常规路由，摊下来的总开销可以忽略 1。一种理解（笔者的解读，论文没有这样解释）：离群值 → 路由突变 → 专家收到陌生的输入 → 更大的离群值，这是一个正反馈环；让路由决定落后几步，相当于在环上加了延迟，打断了“参数一变、路由立刻跟着变”的放大。

第二招：SwiGLU Clamping（截断）。 两款模型从头到尾都把 SwiGLU 的线性分量截断到 \([-10,10]\)、门分量的上限截断到 10 1，做法来自 gpt-oss 11：

带截断的 SwiGLU 专家\[\operatorname{FFN}(\mathbf x)=W^{down}\Big[\operatorname{SiLU}\big(\min(W^{gate}\mathbf x,\ 10)\big)\odot\operatorname{clip}\big(W^{up}\mathbf x,\ -10,\ 10\big)\Big]\]\(\min\) 与 \(\operatorname{clip}\) 逐元素作用。门分量只截上界：SiLU 在负半轴本来就趋于 0，不会爆。开源代码的 swiglu_limit 为 10.0 8。(18.22)
作者自己也说不清为什么有效

论文在结论里承认，这两招的原理尚不清楚，是经验上有效的做法 1。所以上面对 Anticipatory Routing 的“正反馈环”解释只是一个合理的猜测，不是论文的结论；读者复现时，应把它们当作“需要自己验证的工程经验”，而不是“已知机制”。

后训练：先培养专家，再在线蒸馏

V4 的后训练大体沿用 V3.2（第 15 课），但做了一个关键替换：V3.2 最后那个“混合 RL 阶段”被整体换成了在线策略蒸馏（On-Policy Distillation，OPD）1。整个流程分两段。

第一段：专家培养。 每个领域（数学、代码、智能体、指令遵循等）从 V4-Base 出发，先做 SFT，再用该领域的提示与奖励做 GRPO（第 8 课），超参数与此前的工作接近 1。两点新东西：

  • 生成式奖励模型（GRM）。 对难以用规则验证的任务，不再训练一个输出标量分数的奖励模型，而是准备带评分细则（rubric）的 RL 数据，让一个会“写评语再给分”的生成式模型来评判；而且 actor 本身就充当这个 GRM，评判能力和生成能力在同一次 RL 里一起训练，只需要少量人工标注 1。
  • 按推理强度分别培养。 同一个领域，用不同的 RL 配置（不同的长度惩罚、不同的上下文窗口）训练出面向不同推理量的专家，这就是后面三档推理强度的来源。

第二段：多教师在线蒸馏。 把十几个专家（论文说“十个以上”）合成一个学生模型。目标是学生对各个教师的反向 KL 的加权和 1：

在线策略蒸馏的目标\[\mathcal L_{\text{OPD}}(\theta)=\sum_{i=1}^{N_E}w_i\ \mathbb E_{y\sim\pi_\theta(\cdot\mid x)}\Big[\sum_t \KL\big(\pi_\theta(\cdot\mid x,y_{<t})\ \big\|\ \pi_{E_i}(\cdot\mid x,y_{<t})\big)\Big]\]\(\pi_\theta\)：学生；\(\pi_{E_i}\)：第 \(i\) 个专家（教师）；\(N_E\)：教师个数（论文只说十个以上；不是参数量 \(N\)）；\(w_i\)：按相对重要性给的权重（取值论文未给）；\(x\)：提示（prompt），\(y\)：学生写出的回答，\(y_t\) 是它的第 \(t\) 个 token，\(y_{<t}\) 是它前面的部分；\(y\sim\pi_\theta\)：轨迹由学生自己采样（on-policy）。论文式 (29) 写作 \(\sum_iw_i\,\mathrm D_{\mathrm{KL}}(\pi_\theta\|\pi_{E_i})\)，这里把“在学生轨迹上逐位置求和”展开写出。(18.23)
前向 KL 与反向 KL读过 M05 的可以跳过

\(\KL(p\|q)=\sum_vp(v)\log\frac{p(v)}{q(v)}\) 不对称。前向 \(\KL(\pi_E\|\pi_\theta)\) 按教师的分布加权：教师认为可能的词，学生必须都给概率，否则代价很大，所以学生会“摊开”去覆盖教师的所有可能（mass-covering）。反向 \(\KL(\pi_\theta\|\pi_E)\) 按学生自己的分布加权：学生只要在自己选择放概率的地方与教师一致就行，于是倾向于集中到教师的某一个主要模式上（mode-seeking）。把普通知识蒸馏的前向 KL 换成反向 KL、并在学生自己的采样上优化，是 MiniLLM 的做法 16。详见 M05 §5：那里的图 M5.7 用一个高斯分布去拟合双峰分布，前向 KL 的解罩住两个峰，反向 KL 的解只贴住其中一个。

小练习：两个学生，两种 KL

某个位置只有 3 个候选词，教师 \(\pi_E=(0.49,\ 0.02,\ 0.49)\)：词 1 和词 3 都好，词 2 几乎不可能。学生 A 押定词 1，\(\pi_A=(0.96,\ 0.02,\ 0.02)\)；学生 B 三个词都给，\(\pi_B=(0.34,\ 0.32,\ 0.34)\)。（a）分别算两位学生的反向 KL \(\KL(\pi_{\text{学生}}\|\pi_E)\) 与前向 KL \(\KL(\pi_E\|\pi_{\text{学生}})\)。（b）OPD 用的反向 KL 更偏爱谁？为什么？

看答案

（a）反向 KL，A：\(0.96\ln\frac{0.96}{0.49}+0.02\ln1+0.02\ln\frac{0.02}{0.49}=0.6456+0-0.0640=0.582\)；B：\(0.34\ln\frac{0.34}{0.49}\times2+0.32\ln\frac{0.32}{0.02}=-0.2486+0.8872=0.639\)。前向 KL，A：\(0.49\ln\frac{0.49}{0.96}+0.02\ln1+0.49\ln\frac{0.49}{0.02}=-0.3295+0+1.5673=1.238\)；B：\(0.49\ln\frac{0.49}{0.34}\times2+0.02\ln\frac{0.02}{0.32}=0.3582-0.0555=0.303\)。（b）反向 KL 偏爱 A（0.582 < 0.639）：它按学生的分布加权，B 把 0.32 的概率放在教师几乎不写的词 2 上，这一项 \(0.32\ln16=0.887\) 是它最大的代价；A 几乎不写词 3（只给 0.02），反向 KL 只按 A 自己在词 3 上的 0.02 计价，这一项是 \(0.02\ln\frac{0.02}{0.49}=-0.064\)，几乎不罚。前向 KL 正好相反，偏爱 B（0.303 < 1.238）：它按教师的分布加权，A 在教师给了 0.49 的词 3 上只给 0.02，代价 \(0.49\ln24.5=1.567\)。这就是“挑峰”与“覆盖”：OPD 的学生宁可押定教师的一种写法，也不在教师不会写的地方放概率。

全词表，而不是单个 token。 一种省资源的常见简化是：只看学生实际采到的那个 token \(y_t\)，用 \(\log\frac{\pi_\theta(y_t)}{\pi_{E}(y_t)}\) 当作这一位置 KL 的估计，再当作优势塞进策略梯度（第 8 课的 \(k_1\) 估计器，三种单样本估计器的比较见 M05 §6）。论文认为它方差大、训练不稳定，改为在每个位置用完整的 logits 精确计算 KL 1：

每个位置的精确反向 KL\[\KL\big(\pi_\theta(\cdot\mid s_t)\,\big\|\,\pi_E(\cdot\mid s_t)\big)=\sum_{v\in\mathcal V}\pi_\theta(v\mid s_t)\,\log\frac{\pi_\theta(v\mid s_t)}{\pi_E(v\mid s_t)},\qquad s_t=(x,y_{<t})\]对词表里全部 129,280 个词求和。这就要求在每个位置都拿到教师的完整分布。(18.24)
单样本估计到底有多“吵”

设词表只有 3 个词，某个位置学生分布 \(\pi_\theta=(0.7,\,0.2,\,0.1)\)，教师 \(\pi_E=(0.5,\,0.4,\,0.1)\)。精确的反向 KL：\(0.7\ln\frac{0.7}{0.5}+0.2\ln\frac{0.2}{0.4}+0.1\ln1=0.2355-0.1386+0=0.0969\) nat。

单样本估计 \(\log\frac{\pi_\theta(y)}{\pi_E(y)}\)：采到词 1（概率 0.7）得 \(\ln1.4=0.336\)；采到词 2（概率 0.2）得 \(\ln0.5=-0.693\)；采到词 3 得 0。它的期望确实是 \(0.7\times0.336+0.2\times(-0.693)=0.0969\)（无偏），但方差是 \(0.7\times0.336^2+0.2\times0.693^2-0.0969^2=0.166\)，标准差 0.41，是均值的 4 倍多。全词表的算法一次就得到 0.0969，没有这份噪声；代价是每个位置都要教师的 129,280 个概率。

这个代价在工程上并不小。V4 的做法 1：教师权重放在集中式的分布式存储里，按需以 ZeRO 的方式分片加载；不缓存教师的 logits（太大），只缓存教师最后一层的隐藏状态，训练时再过一遍预测头重建 logits；把样本按教师编号排序，保证每个教师的预测头在每个 mini-batch 里只加载一次、显存里同时最多一个；精确的 KL 用专门写的 TileLang 内核计算。

“V4 的最后一步是强化学习”

不是。GRPO 只出现在第一段的专家培养里；把专家合成最终模型的是 OPD，它的损失是蒸馏损失 (18.23)，没有奖励。这与 R1、V3.2 “最后一段是 RL”的流程不同（第 13 课、第 15 课）。

为什么最后一步换成了蒸馏

论文只写了“混合 RL 阶段被整体换成 OPD”，没有写理由。把它和 V3.2 的流程并排看，能看出这一步替换了什么；下面的解读是笔者的，不是论文的结论。

V3.2 做了两件事，V4 用一件事代替。 V3.2 先让专家写出大量回答，学生用普通的下一词交叉熵去模仿这些文字（离线蒸馏，第 15 课 §4），再用一个混合 RL 阶段补上“只比专家略差”的那点差距。离线蒸馏的学生只读过专家写的文字，从没在自己写错的地方得到过纠正；混合 RL 让学生自己写，却只按整篇回答给一个分数。OPD 把两者合在一步里：回答由学生自己写（on-policy），纠正来自教师在每一个位置给出的完整分布。

监督信号的个数差了好几个数量级。 GRPO 的优势 (15.11) 是一个回答一个数，这个回答里的所有 token 共享它。设一个回答长 \(10{,}000\) 个 token：GRPO 给它 1 个标量；OPD 在 \(10{,}000\) 个位置上各给一个 129,280 维的教师分布，一共约 \(10^4\times1.29\times10^5=1.29\times10^9\) 个数。这只是按定义数出来的个数，不代表“信息量”同比例更多，但它说明了为什么 OPD 不需要奖励、也能在每一步告诉学生哪里偏了。

专家可以各自按自己的配置去练。 混合 RL 要在一个阶段里同时平衡“长度与正确率”“语言一致性与正确率”等互相拉扯的目标（第 15 课 §4）。V4 把这些拉扯留在专家阶段：同一领域的专家按 Non-think / High / Max 用不同的长度惩罚和上下文窗口各练一个，最后由 OPD 统一合并。

类比：从“读题解、看总分”到“自己做题、逐步批注”

映射。 沿用第 15 课的学校图景：各科尖子生（专家）先各自刷题（SFT + GRPO）。V3.2 的通才学生先读尖子生写的题解（离线蒸馏），再去考试，只拿到每张卷子的总分（混合 RL）。V4 的通才学生直接自己做题，每写一步，负责这门课的尖子生就在旁边写下“换我在这一步会怎么写、各有几成把握”（完整的下一词分布）；学生只需在自己下笔的地方与批注一致（反向 KL）。

收益。 它说明了 OPD 的两个要点从哪里来：批注写在学生自己的草稿上，所以纠正的正是学生真会犯的错（on-policy）；批注逐步给出，所以不需要等到交卷才知道对错（稠密信号）。

失效的地方。 批注者本身也是模型，它的“把握”可能是错的。(18.23) 在学生与教师完全一致时取到最小值 0，所以在一个领域里，学生最多学到和那位专家一样好；能力的提升发生在专家阶段的 SFT 与 GRPO 里，OPD 负责的是“合并时少丢一点”。另外，真老师会解释为什么，这里的批注只有一张概率表。

FP4 量化感知训练

发布的 V4 指令模型里，路由专家的权重是 FP4（MXFP4），其余大多是 FP8；而 Base 模型的专家是 FP8 8。FP4 是在后训练阶段通过量化感知训练（quantization-aware training，QAT）得到的：对 MoE 专家权重和 CSA indexer 的 QK 路径做 MXFP4 量化，训练时前向用量化后的值，反向相当于直通估计（STE：把量化当作恒等映射传梯度）；推理和 RL 的采样直接用原生 FP4 权重 1。indexer 的 index score 也从 FP32 降到 BF16：top-\(k\) 选择提速 2 倍，被选条目的召回率保持 99.7%。

这样做不需要新的训练框架：论文说整条 QAT 流水线原封不动地复用“现有的 FP8 训练框架”（论文没有明说它就是 V3 的那一套，只是 V4 声明未说明的细节沿用 V3）。FP32 主权重先量化成 FP4，再无损地反量化成 FP8 参与计算。论文说，只要同一个 \(128\times128\) 的 FP8 块里，各个 \(1\times32\) 的 FP4 子块的缩放因子之比不超过某个阈值，FP8（E4M3）多出来的指数位就能吸收这些细粒度缩放；作者实测当前权重满足条件 1。阈值论文没给，可以自己推出来：

反量化无损的阈值（笔者推导）

FP4（E2M1）的非零绝对值是 \(\{0.5,1,1.5,2,3,4,6\}\)。子块的缩放因子都是 2 的整数次幂（UE8M0），把 FP8 块的缩放因子也取成 2 的幂，子块相对块的缩放差就是一个因子 \(2^e\)（\(e\) 为整数）。要求这 7 个值乘 \(2^e\) 后都能被 E4M3 精确表示（E4M3 最大 448，最小的次正规数 \(2^{-9}\)，尾数 3 位）。上界：\(6\times2^6=384\le448\)，而 \(6\times2^7=768>448\)，所以 \(e\le6\)。下界：\(0.5\times2^{-8}=2^{-9}\) 恰好是最小次正规数，\(1.5\times2^{-8}=3\times2^{-9}\) 也可表示，而 \(e=-9\) 时 \(0.5\times2^{-9}=2^{-10}\) 下溢，所以 \(e\ge-8\)。\(e\in[-8,6]\) 共跨 14 个二进制数量级：同一块里子块缩放因子的最大/最小比不超过 \(2^{14}=16{,}384\) 时，反量化无损。

面向智能体的三处格式改动

最后简单记下三处与智能体使用相关的改动 1。工具调用格式：用一个专门的特殊 token 加 XML 风格的标签来写工具调用，减少 JSON 转义出错。交错思考：在有工具调用的对话里，之前各轮的思考内容跨用户轮次完整保留（V3.2 在新的用户消息到来时会丢弃它们）；普通对话仍然丢弃旧的思考。API 的对应规则是：请求带 tools 参数时，之前各轮的 reasoning_content 都要回传并拼进上下文 17。Quick Instruction：把“要不要搜索”“起标题”“生成搜索词”等辅助小任务做成专用的特殊 token，直接接在已有的输入后面，复用已经算好的 KV cache，免得另起一个小模型把整段输入再 prefill 一遍。

KV cache：每 token 多少字节

模型。 只数随长度增长的部分（压缩条目与 indexer 键）；滑动窗口与未凑满的尾部是每个请求一块固定大小的状态，单独算。记 \(L_C,L_H\) 为 CSA 层与 HCA 层的层数（Pro 30、31，Flash 21、20；不用 \(\mathcal L\)，它在本课是损失），\(b_e=584\) 字节是一个条目，\(b_I=68\) 字节是一个 indexer 键：

状态缓存与块布局

(18.25) 没有计入的那部分，是每个请求一块固定大小的“状态缓存”：每一层最近 128 个 token 的滑动窗口条目，加上每个压缩层尚未凑满一块的尾部 1。

状态缓存有多大，什么时候它不能忽略

Pro 的滑动窗口部分：\(61\times128\times584=4{,}559{,}872\) 字节 \(\approx4.56\) MB；Flash：\(43\times128\times584\approx3.21\) MB。把它加进 Pro 对 V3.2 的比值：\(\frac{5031.44\,t+4{,}559{,}872}{48{,}068\,t}\)，\(t=4096\) 时是 12.8%，32K 时 10.8%，128K 以上约 10.5%。所以“10% 的 KV”在短上下文时会略高一些，1M 时它可以忽略。

这种“一部分按块增长、一部分每请求固定”的结构，不符合 PagedAttention（第 4 课 §3介绍过它）的基本假设。论文列了两个障碍：各层的缓存策略不同（例如滑动窗口只留最近的条目），以及高性能注意力内核的对齐要求 1。V4 把滑动窗口与尾部当成类似状态空间模型的定长“状态”来管理；增长部分按块存放，每块覆盖 \(\operatorname{lcm}(4,128)=128\) 个原始 token，于是每块里每个 CSA 层有 32 个条目和 32 个 indexer 键，每个 HCA 层有 1 个条目 1。

持久化到磁盘的前缀缓存（多轮对话、重复前缀复用）也分两类处理 1。压缩条目全部落盘，命中时复用到最后一个完整的块。滑动窗口条目则麻烦得多。按每个 token 算：每个 token 在每一层都有一个未压缩的窗口条目，Pro 每 token \(61\times584=35{,}624\) 字节，而压缩条目每 token 只有 \(30\times146+31\times4.5625=4{,}521\) 字节（不含 indexer 键），前者约是后者的 7.9 倍，与论文说的“约 8 倍”相符。论文比较的对象是“压缩后的 CSA 与 HCA KV 条目”，没提 indexer 键；若把 indexer 键也算进去（每 token 5,031 字节），比值是 7.1 倍，所以这里按不含 indexer 键的口径（研究笔记的推测）。窗口条目这么大，论文为它提供了三种策略：全部落盘、每隔 \(p\) 个 token 存一个检查点、完全不存。完全不存时，命中后重算最后 \(n_{\text{win}}\times\) 层数个 token 即可恢复，Pro 是 \(128\times61=7808\) 个：最后 128 个位置在第 \(\ell\) 层的窗口条目，取决于这些位置进入第 \(\ell\) 层的隐藏状态，而它们又要用到第 \(\ell-1\) 层再往前 127 个位置的窗口条目；这种依赖每往下一层就向前多伸 127 个 token，61 层叠起来是 \(128+127\times60=7748\) 个，不超过 7808。这部分正是下一课 V4.1-Flash 继续开刀的地方（第 19 课 §6）。

模型。 与 (18.2) 相同，只数投影、核心注意力（\(QK^\top\) 与 \(PV\)）和 indexer 打分。V4 每个头每个条目 \(4c=2048\) 次运算：

V4 的单 token FLOPs\[\begin{aligned}F_{\text{V4}}(t)=\ &2N_{\text{act}}\\ &+w_{\text{BF16}}\,n_h\,4c\,\Big[L_C\big(\min(k_{\text{sel}},\tfrac tm)+n_{\text{win}}\big)\\ &\qquad\qquad+L_H\big(\tfrac{t}{m'}+n_{\text{win}}\big)+L_S\,n_{\text{win}}\Big]\\ &+w_{\text{FP4}}\,L_C\cdot2H^Id^I\cdot\tfrac tm\end{aligned}\]\(L_S\)：纯滑动窗口层的层数（Flash 2，Pro 0）。可见条目数 \(\lfloor(t+1)/m\rfloor\) 近似成 \(t/m\)，窗口按满 128 个计（\(t<127\) 时略多算）。\(w_{\text{BF16}},w_{\text{FP8}},w_{\text{FP4}}\)：把某种精度的一次运算折算成几次“等效 FP8 运算”的权重，取值见下一段；全取 1 就是原始计数。V3.2 的对应式是 (18.2)，其中核心注意力乘 \(w_{\text{BF16}}\)、indexer 乘 \(w_{\text{FP8}}\)。(18.26)

四个值得记住的观察：

  1. 短上下文时 V4-Pro 反而更贵。 常数项 \(2N_{\text{act}}\)：Pro 是 0.098 T，V3.2 是 0.074 T（激活参数 49B 对 37B）。在这个模型里，\(t<911\) 时 Pro 的单 token FLOPs 高于 V3.2。
  2. FLOPs 的优势随长度增长，KV 的优势与长度无关。 128K 处 Pro 的单 token FLOPs 是 V3.2 的 52.0%（1.92 倍），Flash 是 15.0%（V3.2 在 128K 是 0.275 T；按原始次数是 0.240 T，就是第 14 课 §7 的 74 + 166 GFLOPs）；1M 处才到 26.5% 与 9.9%。KV 的比值则处处是 10.5% 与 7.3%，因为两边都是过原点的直线。
  3. 口径决定结论。 不加精度权重（全部按原始次数），1M 处 Pro 是 26.2%，Flash 却是 12.1%（8.27 倍），离论文的 10% 较远——这正是推断“等效 FP8”折算的主要证据。
  4. 重压缩的层成了主要的注意力开销。 等效 FP8 口径下，1M 处 Pro 的 31 层 HCA 稠密注意力合计 0.135 T，超过 30 层 CSA 的 indexer（0.064 T）；按原始次数则反过来（indexer 0.129 T 对 HCA 0.068 T）。“哪一项最大”依赖口径，所以别脱离口径说“V4 的瓶颈是某某”。

1M 装得下，不等于 1M 都用得好

KV 和 FLOPs 回答的是“能不能装下、算不算得起”。模型在 1M 上下文里找东西的能力是另一回事。论文用 OpenAI 的 MRCR 测了不同长度 1。按 OpenAI 的数据集说明，MRCR 是一段很长的合成多轮对话，里面混着 2、4 或 8 个相同的请求（例如“写一首关于貘的诗”），模型要找回其中指定的第 \(k\) 个的回答，按与标准答案的字符串相似度打分 18；论文图 9 用的是 8 根“针”的版本，也就是最难的一档。

两点提醒。第一，论文表格里的“MRCR 1M = 83.5”（Pro-Max）不是“在 1M 长度上得 83.5 分”：图 9 在 1024K 处只有 0.59；83.5 也不等于图 9 八个点的简单平均（0.8225）。它是论文没有定义的另一种汇总口径，引用时要连口径一起说清。第二，横向比较时，Pro-Max 在 MRCR 上高于 Gemini-3.1-Pro（83.5 对 76.3），低于 Claude Opus 4.6（92.9）1。“支持 1M”首先是一个工程能力；1M 处的检索质量，仍在明显衰减。

练习与答案

概念题

练习 1　为什么 KV 的比值与长度无关，而 FLOPs 的比值随长度变好

论文图 1 里，V4-Pro 对 V3.2 的 KV 比值在任何长度都约为 9.5 倍，而 FLOPs 的比值从短上下文的“不到 1 倍”一路变到 1M 处的 3.7 倍。用 (18.1)、(18.2)、(18.25)、(18.26) 的结构解释原因。

看答案

两者的 KV 都与 \(t\) 成正比、没有常数项（只计增长部分）：\(48{,}068\,t\) 对 \(5031.44\,t\)，比值恒为 9.55。FLOPs 则是“常数项 + 线性项”：常数项是投影 \(2N_{\text{act}}\)（Pro 0.098 T 比 V3.2 的 0.074 T 还大），线性项的斜率 V3.2 主要来自 indexer（等效 FP8 口径每个上下文 token 约 \(1.0\times10^6\) 次），Pro 主要来自 HCA 稠密注意力与压缩后的 indexer（合计约 \(1.9\times10^5\) 次）。\(t\) 小时常数项占主导，比值接近 \(0.074/0.098\)（Pro 反而更贵，\(t<911\)）；\(t\) 大时线性项占主导，比值趋向两个斜率之比。所以 128K 时只省到 52%，1M 时省到 26.5%。

练习 2　CSA 与 HCA 各自解决什么，窗口为什么恰好够

（a）CSA 需要 indexer 而 HCA 不需要，为什么？（b）证明：在任何位置 \(t\)，HCA 尚未压缩的 token 都落在 128 个 token 的滑动窗口里。（c）如果把 \(m'\) 改成 256、窗口仍是 128，会出什么问题？

看答案

（a）1M 时 CSA 每层有 262,144 个条目，全部做稠密注意力每个查询要 \(6.9\times10^{10}\) 次运算，必须挑；HCA 只有 8192 个条目，全读的代价（\(2.2\times10^9\)）可以接受，于是省掉 indexer 与 top-\(k\)，也避免了“漏选”。（b）HCA 在位置 \(t\) 已完成的块是 \(s<\lfloor(t+1)/m'\rfloor\)，它们覆盖 token \(0\) 到 \(m'\lfloor(t+1)/m'\rfloor-1\)；未压缩的 token 从 \(m'\lfloor(t+1)/m'\rfloor\) 到 \(t\)，个数为 \((t+1)\bmod m'\le m'-1=127\)。窗口覆盖 \(t-127\) 到 \(t\) 共 128 个，而 \(m'\lfloor(t+1)/m'\rfloor\ge t+1-127=t-126>t-128\)，所以未压缩的部分全部在窗口里。（c）未压缩尾部最多 255 个 token，窗口只有 128 个，最坏时中间有 127 个 token 在 HCA 层里既不在任何条目、也不在窗口里，这一层完全看不见它们（CSA 层仍看得见，但要靠 indexer 选中）。

练习 3　被中断的 rollout 为什么不能从头重来

RL 采样（rollout）经常被抢占而中断。论文 §5.2.3 说：把没完成的请求丢掉、从头重新生成，在数学上是错的，因为短回答更容易在中断之前完成。请解释这为什么会带来偏差，偏向哪一边；V4 的做法是什么？

看答案

每条回答的生成时间与长度成正比。一段时间内发生中断时，已经完成的多是短回答，被打断的多是长回答。如果只保留“幸存”的回答、把被打断的丢掉重来，新一轮里长回答又更容易被打断……最终进入训练的样本系统性地偏短，相当于按长度做了一次有偏的拒绝采样，策略梯度的估计因此偏向“写短一点”。V4 的做法是逐 token 写预写日志（WAL）并保存 KV，被中断的请求从断点接着生成，而不是重来 1。

计算题

练习 4　V4-Pro 的 KV cache

已知 V4-Pro 有 30 个 CSA 层、31 个 HCA 层，条目 584 B，indexer 键 68 B，\(m=4\)，\(m'=128\)。（a）每 token 的增长部分是多少字节？（b）1M（\(2^{20}\)）个 token 共多少 GB？（c）加上 4.56 MB 的滑动窗口状态后，4K 上下文时与 V3.2（48,068 B/token）的比值是多少？

看答案

（a）\(30\times(584+68)/4+31\times584/128=4890+141.44=5031.44\) B。（b）\(5031.44\times2^{20}=5.276\times10^{9}\) B \(\approx5.28\) GB。（c）\((5031.44\times4096+4{,}559{,}872)/(48{,}068\times4096)=(20{,}608{,}768+4{,}559{,}872)/196{,}886{,}528=12.8\%\)，高于 1M 处的 10.5%。

练习 5　“约为 GQA8 的 2%”

以 BF16、8 个 KV 组、头维 128 的 GQA 为基线。（a）43 层的基线每 token 多少字节？（b）V4-Flash（3,514.25 B）是它的百分之几？（c）V4-Flash 相对 V3.2 小多少倍？

看答案

（a）\(2\times8\times128\times2\times43=176{,}128\) B（2 表示 K 与 V，末尾的 2 表示 BF16 每数 2 字节）。（b）\(3514.25/176{,}128=2.00\%\)。（c）\(48{,}068/3514.25=13.68\) 倍，即 7.31%，对上论文图 1 的“13.7 倍”和正文的“7%”。

练习 6　手算一个压缩条目（\(m=2\)，\(c=1\)）

4 个 token，块 0 = token 0、1，块 1 = token 2、3。条目 1 读块 0 的 \(b\) 路与块 1 的 \(a\) 路。已知（已含位置偏置）：\(b\) 路候选 \(c^b_0=2\)、\(c^b_1=-1\)，打分 \(0\)、\(\ln3\)；\(a\) 路候选 \(c^a_2=4\)、\(c^a_3=1\)，打分 \(\ln2\)、\(\ln2\)。（a）求 4 个权重与 \(e_1\)。（b）位置最早为几的查询能看到条目 1？（c）若把 \(c^a_2\) 换成 400，\(e_1\) 会变成多少？这说明了什么？

看答案

（a）指数为 \((1,3,2,2)\)，和为 8，权重 \((0.125,\ 0.375,\ 0.25,\ 0.25)\)；\(e_1=0.125\times2+0.375\times(-1)+0.25\times4+0.25\times1=0.25-0.375+1+0.25=1.125\)。（b）按 (18.7)，\(1<\lfloor(t+1)/2\rfloor\) 要求 \(t+1\ge4\)，\(t\ge3\)：条目读到的最后一个 token 是 3。（c）\(e_1=0.25-0.375+100+0.25=100.125\)。权重只由打分决定，与候选值的大小无关，所以一个很大的候选值会直接主导条目（凸组合不会超出候选值的范围，但范围本身被这个大数撑大了）。压缩之后的那次 RMSNorm（即 §3 的条目归一化）正好把这种尺度上的失控压回去；这是笔者对它作用的一种解读，论文没有这样解释。

练习 7　HCA 的稠密注意力贵不贵

V4-Pro，\(t=2^{20}\)。（a）31 个 HCA 层合计的核心注意力是多少原始 FLOPs？（b）30 个 CSA 层的 indexer 合计多少原始 FLOPs？（c）按等效 FP8 口径（BF16×2、FP4×0.5），两者各是多少？哪个大？

看答案

（a）每层每头每条目 2048 次，条目 \(2^{20}/128+128=8320\) 个：\(31\times128\times2048\times8320=6.76\times10^{10}\)。（b）\(30\times64\times256\times2^{20}/4=1.29\times10^{11}\)。原始口径下 indexer 更大。（c）HCA \(\times2=0.135\) T，indexer \(\times0.5=0.064\) T，HCA 更大。结论随口径翻转，这是引用“最大开销在哪里”时必须带上口径的原因。

练习 8　Muon 的更新缩放

（a）V4-Pro 一个路由专家的 up 矩阵是 \(3072\times7168\)（输出 × 输入）。正交化后更新的 RMS 是多少？V4 要乘的缩放因子是多少？（b）V4-Flash 的 indexer 头权重矩阵 \(W^w\) 是 \(64\times4096\)，同样的问题。（c）为什么缩放后可以让不同形状的矩阵共用一个学习率？

看答案

（a）\(1/\sqrt{\max(3072,7168)}=1/\sqrt{7168}=0.01181\)；缩放因子 \(\sqrt{7168}\times0.18=15.24\)，缩放后 RMS 为 0.18。（b）秩为 64（满秩），RMS \(=\sqrt{64/(64\times4096)}=1/\sqrt{4096}=0.0156\)；缩放因子 \(\sqrt{4096}\times0.18=11.52\)，缩放后仍为 0.18。（c）缩放后每个矩阵的更新 RMS 都等于 \(\gamma_{\text{rms}}=0.18\)，与形状无关；学习率 \(\eta\) 于是对所有矩阵意味着同样大小的“元素级”步长，并且与 AdamW 更新的 RMS 量级（经验上 0.2–0.4）对齐，可以复用 AdamW 的学习率与权重衰减。

练习 9　对一个对角矩阵做牛顿–舒尔茨

\(M=\begin{pmatrix}3&0\\0&4\end{pmatrix}\)。（a）\(X_0=M/\norm{M}_F\) 是什么？（b）做一步 \(\varphi_A\) 之后是什么？（c）如果接着直接做一步 \(\varphi_B\) 呢？（d）标准答案 \(UV^\top\) 是什么？

看答案

（a）\(\norm{M}_F=5\)，\(X_0=\operatorname{diag}(0.6,\ 0.8)\)。对角矩阵的奇异值就是对角元，\(U=V=I\)。（b）\(\varphi_A(0.6)=3.4445\times0.6-4.775\times0.216+2.0315\times0.07776=1.1933\)；\(\varphi_A(0.8)=2.7556-2.4448+0.6657=0.9765\)。\(X_1=\operatorname{diag}(1.1933,\ 0.9765)\)：小的被推过了头，大的被压到 1 以下。（c）\(\varphi_B(1.1933)=2.3865-2.5486+1.2097=1.0476\)，\(\varphi_B(0.9765)=1.9530-1.3966+0.4439=1.0002\)：离 1 近的那个一步就几乎精确（误差从 0.0235 降到 0.0002，二阶收敛），离得远的还差 0.05，再来一步是 \(\varphi_B(1.0476)=1.0015\)。（d）\(UV^\top=I\)。

练习 10　专家并行的带宽平衡点

论文 §3.1 分析专家并行的通信能否被计算掩盖：每个“token–专家”对要做 SwiGLU 的三次矩阵乘，共 \(6\,d\,d_{ff}\) 次运算（\(d\) 隐藏维，\(d_{ff}\) 专家中间维），要通信 \(3d\) 字节（FP8 发送 \(d\) 字节，BF16 收回 \(2d\) 字节）。当峰值算力 \(C_{\text{peak}}\)（FLOP/s）与互联带宽 \(B_{\text{net}}\)（字节/秒）满足 \(C_{\text{peak}}/B_{\text{net}}\le6dd_{ff}/(3d)\) 时，通信可以完全被计算掩盖（加下标是为了不与本课程的 batch size \(B\)、训练算力 \(C\) 混淆）。（a）化简这个条件，代入 V4-Pro（\(d_{ff}=3072\)）与 V4-Flash（\(d_{ff}=2048\)）。（b）某加速卡的 FP8 峰值为 1000 TFLOP/s（假设值），跑 Pro 与 Flash 各至少需要多少互联带宽？

看答案

（a）\(6dd_{ff}/(3d)=2d_{ff}\) FLOPs/字节：Pro 为 6144，Flash 为 4096 1。注意论文此处用 \(d\) 表示专家中间维、\(h\) 表示隐藏维，与前文的记号不同。条件的来历：一对的计算时间是 \(6dd_{ff}/C_{\text{peak}}\)，通信时间是 \(3d/B_{\text{net}}\)，要求后者不超过前者。（b）\(B_{\text{net}}\ge C_{\text{peak}}/(2d_{ff})\)：Pro \(10^{15}/6144=1.63\times10^{11}\) 字节/秒 ≈ 163 GB/s；Flash \(10^{15}/4096\approx244\) GB/s。专家越“瘦”（\(d_{ff}\) 越小），每字节通信配的计算越少，越吃带宽。超过平衡点之后再加带宽，收益递减——这是论文给硬件厂商的建议之一。

推导题

练习 11　不做逆旋转，平移整段上下文会怎样

设一个头在位置 \(t\) 的输出（RoPE 那 64 维）为 \(\mathbf o^r(t)=\sum_s a_s R_{p_s}\mathbf e^r_s\)，其中 \(a_s\) 只依赖 \(p_s-t\)。把整段上下文整体向后平移 \(\Delta\) 个位置（所有 \(p_s\) 与 \(t\) 都加 \(\Delta\)，内容不变；设 \(\Delta\) 是 128 的倍数，于是每个条目概括的 token 不变，见 (18.15) 后的说明）。（a）证明不做逆旋转时 \(\mathbf o^r\) 变成 \(R_\Delta\,\mathbf o^r\)。（b）证明做了逆旋转之后 \(R_{-t}\mathbf o^r\) 不变。

看答案

（a）平移后权重不变：\(a_s\) 只依赖 \((p_s+\Delta)-(t+\Delta)=p_s-t\)。所以 \(\mathbf o^r_{\text{新}}=\sum_s a_sR_{p_s+\Delta}\mathbf e^r_s=\sum_s a_sR_\Delta R_{p_s}\mathbf e^r_s=R_\Delta\sum_s a_sR_{p_s}\mathbf e^r_s=R_\Delta\,\mathbf o^r\)（用了 \(R_{a+b}=R_aR_b\) 与线性）。同样的内容放到不同位置，输出被转了一个角度：输出携带了绝对位置。（b）\(R_{-(t+\Delta)}\mathbf o^r_{\text{新}}=R_{-t-\Delta}R_\Delta\mathbf o^r=R_{-t}\mathbf o^r\)，与平移前相同。这就是 (18.15) 的另一种说法：逆旋转之后，输出只依赖相对位置。

练习 12　为什么迭代之前要除以 Frobenius 范数

（a）证明对任意矩阵，最大奇异值 \(\sigma_1\le\norm{M}_F\)，因此 \(X_0=M/\norm{M}_F\) 的奇异值都在 \((0,1]\) 里。（b）如果不归一化，某个奇异值是 2，做一步 \(\varphi_A\) 会得到什么？（c）改成除以谱范数 \(\sigma_1\)（精确值）会有什么好处？为什么实际不这么做？

看答案

（a）\(\norm{M}_F^2=\tr(M^\top M)=\tr(V\Sigma^2V^\top)=\sum_i\sigma_i^2\ge\sigma_1^2\)，所以 \(\sigma_1\le\norm{M}_F\)，归一化后最大的奇异值不超过 1；非零奇异值为正，所以都在 \((0,1]\)。（b）\(\varphi_A(2)=3.4445\times2-4.775\times8+2.0315\times32=6.889-38.2+65.008=33.70\)，再迭代会迅速发散：\(\varphi_A(\sigma)-\sigma=\sigma(2.4445-4.775\sigma^2+2.0315\sigma^4)\) 在 \(\sigma\) 超过正不动点 1.264 之后恒为正，而 \(\varphi_A\) 在 \(\sigma>1.050\) 上单调递增，所以一旦越过 1.264，每一步都更大，越走越远（下一步已是 \(\varphi_A(33.7)\approx8.8\times10^7\)）。（c）除以 \(\sigma_1\) 能让最大奇异值恰为 1、其余更大一些，离目标更近；但精确求 \(\sigma_1\) 需要幂迭代或 SVD，本身就是额外的迭代计算，而 Frobenius 范数只需一次求平方和。代价是：若矩阵的奇异值很分散，除以 \(\norm{M}_F\) 后最小的那些会非常小，需要 \(\varphi_A\) 的大斜率（3.4445）多花几步把它们拉起来——这正是前 8 步的任务。
