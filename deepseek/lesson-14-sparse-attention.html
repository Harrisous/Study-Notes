第 14 课 · 稀疏注意力：从 NSA 到 DSA

MLA 把每个 token 的 KV cache 压到了 576 个数，但每生成一个 token，注意力仍要把前面所有 token 读一遍、算一遍。上下文到 128K 时，这笔账是其余全部计算的近 9 倍。这一课讲 DeepSeek 怎样让每个查询只看一小部分 token：先是 NSA 用“压缩 + 选块 + 滑窗”从头训练出稀疏注意力，再是 DSA 用一个极便宜的打分器（lightning indexer）为每个查询挑出 2048 个 token，只改一处架构、续训不到一万亿 token，就把 V3.1 变成了 V3.2。

这一课回答什么问题

注意力的本意是让每个 token 回头看全部前文，再决定从哪里取信息。上下文短的时候，这是它最大的优点；上下文长到十几万 token 时，它变成了最大的账单：第 \(T\) 个 token 要和前面 \(T\) 个 token 各打一次分、各取一次值，整段 \(T\) 个 token 加起来就是约 \(T^2/2\) 对。这一课要回答四个问题：

  • 这笔账到底有多大？以 DeepSeek-V3 的真实维度，一个 token 在位置 128K 时，注意力要花多少 FLOPs、读多少字节？它从哪个长度开始超过模型其余部分的全部计算？
  • 如果每个查询只看一小部分 token（稀疏注意力），这一小部分由谁来挑？挑的成本是多少？怎样挑才能让 GPU 真的变快，而不只是纸面上少算？
  • NSA 为什么要三个分支（压缩、选择、滑动窗口）？它的“硬件对齐”具体对齐了什么？
  • DSA 的 lightning indexer 为什么用 ReLU、为什么能用 FP8、为什么必须在 MLA 的“MQA 模式”上实现？它的两阶段续训里，那个 KL 散度损失在教打分器学什么？

这一课在科技树上的位置

这一课在主线 A（注意力与 KV cache 经济学）上。第 4 课推导了 KV cache，并指出解码受显存带宽限制（第 4 课 §4）；第 9 课用 MLA 把每个 token 的缓存从“每头一对键值”压成一个 576 维的条目。但 MLA 只改变了每个条目有多大，没有改变每一步要读、要算多少个条目：位置 \(T\) 的查询仍然要面对全部 \(T\) 个条目。第 13 课的推理模型把回答越写越长，第 15 课的智能体要在一个上下文里塞进大量工具调用结果，长上下文从“偶尔用到”变成了常态，这笔 \(O(T)\)/查询、\(O(T^2)\)/序列的账就成了下一个要打折的对象。

本课之后，第 15 课讲在 DSA 架构之上做规模化强化学习与智能体的 V3.2；第 18 课的 V4 先沿序列方向压缩 KV，再在压缩后的条目上做 DSA 式选择（CSA）。压缩之后，打分器要打分的条目也少了几倍，这正好缓解了本课最后会算出来的一个问题：打分器自己的 \(O(T^2)\)（V4 论文给出的动机是超长上下文下注意力整体成为瓶颈，把两者联系起来是本课的读法）。

长上下文的平方账单

先把账算清楚，再谈怎么省。这一页只做一件事：用 DeepSeek-V3 的真实维度，数出注意力在不同上下文长度下要花多少计算、读多少字节，并看它在哪个长度开始压倒模型的其余部分。数完之后，“为什么要稀疏”就不再需要说服，数字自己会说话。

一个查询要做多少事

含义。 注意力层里，位置 \(t\) 的 token 发出一个查询，和前面每一个 token 的键打分，把分数变成权重，再按权重把这些 token 的值加起来。

理解。 用第 1 课的图书馆类比：查询是你的检索问题，每个键是一本书的书脊标签，值是书的内容。稠密注意力的规则是：每一本书都要看一眼标签，每一本书都要按权重读一点。书架上有 \(T\) 本书，工作量就和 \(T\) 成正比。

数学。 DeepSeek-V3 这一代的 MLA 在训练和预填充（prefill）时按“MHA 模式”计算：先把缓存的压缩向量展开成每个头的键和值，再做普通的多头注意力（V3.2 论文附录以同一架构的 V3.1-Terminus 为例说明了这一点）1,2。第 \(i\) 个头的输出是

位置 t 的一个头（MLA 的 MHA 模式）\[\mathbf o_{t,i}=\sum_{s=1}^{t}\softmax_s\!\left(\frac{\mathbf q_{t,i}^\top\mathbf k_{s,i}}{\sqrt{d_h+d_h^R}}\right)\mathbf v^C_{s,i},\qquad \mathbf u_t=W^O\big[\mathbf o_{t,1};\dots;\mathbf o_{t,n_h}\big]\]\(\mathbf q_{t,i},\mathbf k_{s,i}\in\R^{d_h+d_h^R}=\R^{192}\)：第 \(i\) 个头的查询与键，前 128 维是内容部分、后 64 维带 RoPE；\(\mathbf v^C_{s,i}\in\R^{d_h}=\R^{128}\)：值；\(\softmax_s\) 表示对 \(s=1,\dots,t\) 归一化；\([\mathbf o_{t,1};\dots;\mathbf o_{t,n_h}]\in\R^{n_hd_h}=\R^{16384}\) 是 128 个头的输出拼起来，\(W^O\in\R^{d\times n_hd_h}=\R^{7168\times16384}\)，\(\mathbf u_t\in\R^{7168}\)：注意力层输出。(14.1)

数 FLOPs 只需要一条规则：长度为 \(m\) 的点积要做 \(m\) 次乘加，记作 \(2m\) 次浮点运算（FLOPs）。

数 FLOPs 的约定读过 M01 §5 的可以跳过

一次乘法或一次加法算 1 次浮点运算（FLOP）。硬件的基本指令是乘加 \(a\times b+c\)，所以业界把“一次乘加”记作 2 FLOPs。长度为 \(m\) 的点积是 \(m\) 次乘加，即 \(2m\) FLOPs；\([m,k]\times[k,n]\) 的矩阵乘法约 \(2mnk\) FLOPs；一个参数对一个 token 贡献 2 FLOPs，所以激活参数为 \(N\) 的模型每个 token 约 \(2N\) FLOPs。推导见 M01 §5。

位置 T 的一个查询，每个键要花多少 FLOPs（每层）
(1)\(\displaystyle \mathbf q_{t,i}^\top\mathbf k_{s,i}:\ 2\times192=384\)打分：长度 \(d_h+d_h^R=192\) 的点积
(2)\(\displaystyle p_{t,i,s}\,\mathbf v^C_{s,i}:\ 2\times128=256\)加权求和：一个权重乘一个 128 维的值，再累加
(3)\(\displaystyle \text{每头每键}:\ 384+256=640\)softmax 本身每个分数只做几次运算，相对可忽略
(4)\(\displaystyle \text{每键}:\ 128\times640=81{,}920\)\(n_h=128\) 个头，各算各的
(5)\(\displaystyle F_{\text{MHA}}(T)=81{,}920\,T\)位置 \(T\) 的查询要面对 \(T\) 个键
稠密注意力：一个查询、一层\[F_{\text{MHA}}(T)=2\,n_h\big[(d_h+d_h^R)+d_h\big]\,T=2\cdot128\cdot(192+128)\cdot T=81{,}920\,T\ \text{FLOPs}\]只数 \(QK^\top\) 与 \(PV\) 两个矩阵乘；投影矩阵的计算与 \(T\) 无关，算在“其余部分”里。(14.2)
位置 128K 的一个 token

\(T=131{,}072\)（DeepSeek 文档里的“128K”就是 \(2^{17}\)，§6 会用训练 token 数复核这一点）。一层：\(81{,}920\times131{,}072=1.074\times10^{10}\)，约 10.7 GFLOPs。61 层：\(655\) GFLOPs。

模型其余部分呢？V3 每个 token 激活 37B 参数 1，按“每参数 2 FLOPs”约 \(2\times37\times10^9=74\) GFLOPs，与位置无关。于是位置 128K 的这个 token，注意力的 \(QK^\top\) 与 \(PV\) 就占了 \(655/(655+74)=89.8\%\)。同样算法：位置 4K 占 21.7%，位置 32K 占 68.9%。两者相等的位置是 \(T=74\times10^9/(61\times81{,}920)\approx14{,}808\)。

整段的账：平方

上面是一个 token 的账。预填充一段长 \(T\) 的提示时，位置 \(1,2,\dots,T\) 的查询都要算一遍。

整段 T 个 token 的注意力 FLOPs（每层，因果）
(1)\(\displaystyle \sum_{t=1}^{T}F_{\text{MHA}}(t)=81{,}920\sum_{t=1}^{T}t\)位置 \(t\) 的查询面对 \(t\) 个键，由 (14.2)
(2)\(\displaystyle =81{,}920\cdot\frac{T(T+1)}{2}\)等差数列求和
(3)\(\displaystyle \approx40{,}960\,T^2\)\(T\gg1\)；因果掩码让上三角那一半不用算
整段预填充的注意力账单\[F^{\text{seq}}_{\text{MHA}}(T)=81{,}920\cdot\frac{T(T+1)}{2}=O(T^2)\](14.3)
大 O 记号熟悉 \(O(\cdot)\) 的可以跳过

\(O(T^2)\) 读作“至多按 \(T^2\) 的量级增长”：\(T\) 翻一倍，量约变成 4 倍，常数因子（这里的 40,960）被省略。\(O(Tk)\) 表示和 \(T\) 与 \(k\) 的乘积成正比；若 \(k\) 固定，它就是 \(T\) 的线性函数。大 O 只说增长的形状，不说绝对大小：两个都是 \(O(T^2)\) 的东西，常数可以差 100 倍，本课后面会反复遇到这种情况。

一段 128K 的提示

每层 \(81{,}920\times131{,}072\times131{,}073/2=7.04\times10^{14}\) FLOPs，61 层合计 \(4.29\times10^{16}\)。其余部分是 \(74\times10^9\times131{,}072=9.70\times10^{15}\)。整段来看，注意力是其余全部计算的 4.4 倍。把长度减半到 64K，注意力变成约 \(1/4\)，其余部分只减半：平方项正是长上下文贵的根源。

解码时的账：读字节

解码（decode）每步只生成一个 token，计算量不大，瓶颈在读：第 4 课 §4 讲过，这一步要把 KV cache 从显存（HBM）里完整读一遍，读的时间远大于算的时间。MLA 让每个 token 每层只缓存 \(d_c+d_h^R=576\) 个数，BF16 下是 \(576\times2=1152\) 字节；DeepSeek 开源的 FlashMLA 稠密解码核读的正是 BF16/FP16 格式的缓存 3。

位置 128K 的一步解码要读多少

每层 \(1152\times131{,}072=1.51\times10^8\) 字节，约 151 MB；61 层合计约 9.2 GB。也就是说，一个请求在 128K 位置每生成一个 token，要从显存里读 9.2 GB 的缓存。缓存再小，只要每一步都要全部读一遍，读取量就随位置线性增长。

这两笔账的形状完全一样：一个查询 \(O(T)\)，一段序列 \(O(T^2)\)。MLA 把每个条目变小，减的是常数；要改变形状，只能让一个查询不再面对全部 \(T\) 个条目。

为什么不直接引用论文里的“70–80%”

NSA 论文的引言说，按“理论估计”，解码 64K 上下文时 softmax 注意力占总延迟的 70–80% 4。论文没有给出这个估计的模型、硬件或推导，本课无法复算，所以不用它；上面的数字都是按 V3 维度自己数出来的，你可以逐个复核。

真的需要看全部吗？

注意力权重通常并不均匀。NSA 论文可视化了一个预训练好的 27B 全注意力模型的注意力图，发现注意力分数往往成块聚集，相邻的键常常有相近的分数 4。如果大部分权重集中在少数位置上，那么只看这些位置、把其余位置的权重直接设为零，输出不会差太多。这就是稀疏注意力的出发点。

含义。 稀疏注意力（sparse attention）：每个查询只在前文的一个小子集上做注意力。

理解。 稠密注意力是“每本书都读一点”；稀疏注意力是“先挑出几本，只读这几本”。被挑中的书之间照常按匹配度分配阅读时间，没被挑中的书一个字也不读。

数学。 给每个查询位置 \(t\) 一个被选集合 \(\mathcal S_t\subseteq\{1,\dots,t\}\)，大小 \(\abs{\mathcal S_t}\ll t\)：

稀疏注意力的一般形式\[\mathbf o_{t,i}=\sum_{s\in\mathcal S_t}\frac{\exp\!\big(\mathbf q_{t,i}^\top\mathbf k_{s,i}/\sqrt{d_h+d_h^R}\big)}{\sum_{s'\in\mathcal S_t}\exp\!\big(\mathbf q_{t,i}^\top\mathbf k_{s',i}/\sqrt{d_h+d_h^R}\big)}\,\mathbf v^C_{s,i}\]softmax 只在 \(\mathcal S_t\) 内部归一化；\(\mathcal S_t=\{1,\dots,t\}\) 时退化为 (14.1)。若 \(\abs{\mathcal S_t}=k\) 固定，一个查询的核心注意力是 \(O(k)\)，整段是 \(O(Tk)\)。(14.4)

稀疏会让输出偏多少？ 上面说“输出不会差太多”，这句话可以写成一个不等式。只看一个头，省略下标 \(t,i\)：\(z_s\in\R\) 是查询对位置 \(s\) 的打分（(14.4) 里 exp 括号中的那一项），\(a_s=\softmax_s(z)\) 是稠密注意力在位置 \(s\) 上的权重，\(\mathbf v_s\in\R^{128}\) 是值（即 \(\mathbf v^C_{s,i}\)），\(\mathbf o=\sum_{s\le t}a_s\mathbf v_s\) 是稠密输出 (14.1)，\(\tilde{\mathbf o}\) 是稀疏输出 (14.4)。再记被选集合拿走的权重 \(m=\sum_{s\in\mathcal S_t}a_s\)，丢掉的权重 \(\varepsilon=1-m\)（一个 0 到 1 之间的数，与 PPO/GRPO 的裁剪系数无关）。

丢掉权重 ε，输出最多偏离 2ε 倍的最长值向量
(1)\(\displaystyle \tilde a_s=\frac{e^{z_s}}{\sum_{s'\in\mathcal S_t}e^{z_{s'}}}=\frac{e^{z_s}/Z}{\sum_{s'\in\mathcal S_t}e^{z_{s'}}/Z}=\frac{a_s}{m}\)(14.4) 里选中位置 \(s\) 的权重；分子分母同除以稠密的分母 \(Z=\sum_{s'\le t}e^{z_{s'}}\)
(2)\(\displaystyle \mathbf o-\tilde{\mathbf o}=\sum_{s\notin\mathcal S_t}a_s\mathbf v_s+\sum_{s\in\mathcal S_t}\Big(a_s-\frac{a_s}{m}\Big)\mathbf v_s\)稠密输出减稀疏输出，按“没选中”“选中”两部分写
(3)\(\displaystyle =\sum_{s\notin\mathcal S_t}a_s\mathbf v_s-\frac{\varepsilon}{m}\sum_{s\in\mathcal S_t}a_s\mathbf v_s\)\(a_s-a_s/m=-a_s(1-m)/m\)，而 \(1-m=\varepsilon\)
(4)\(\displaystyle \norm{\mathbf o-\tilde{\mathbf o}}\le\varepsilon\,v_{\max}+\frac{\varepsilon}{m}\cdot m\,v_{\max}=2\varepsilon\,v_{\max}\)三角不等式，\(v_{\max}=\max_s\norm{\mathbf v_s}\)；两个和里的权重分别合计 \(\varepsilon\) 与 \(m\)

这个不等式把“稀疏好不好”变成了一个可以度量的问题：被选集合拿走了多少注意力权重。\(\varepsilon\) 越小，误差的上界越小。\(k\) 固定时，让 \(m\) 最大的集合就是权重最大的 \(k\) 个位置，所以“按分数取前 \(k\) 名”在这个意义下是最好的选法，前提是知道真实的权重 \(a_s\)。可是 \(a_s\) 要做完一遍稠密注意力才知道，打分器只能事先去估计它；§6 会看到，DSA 训练打分器时用的目标正是这些权重（多个头的平均）。

同样选 2048 个，集中与弥散差在哪里

位置 \(t=131{,}072\)，选 \(k=2048\) 个 token（1.56%）。集中的情形（为说明而假设的数字）：某个头的权重大多落在少数位置上，被选的 2048 个拿走了 95%，\(\varepsilon=0.05\)，输出误差不超过 \(2\times0.05\,v_{\max}=0.1\,v_{\max}\)，即最长值向量长度的十分之一。弥散的情形：权重完全均匀，每个位置 \(1/131{,}072\)，被选的 2048 个只拿走 \(2048/131{,}072=1.56\%\)，\(\varepsilon=0.984\)，上界是 \(1.97\,v_{\max}\)，几乎没有保证。

这就是稀疏注意力的失败模式：它押注“注意力是集中的”。需要把大量位置平均起来的任务，注意力天然是弥散的，押注就会输（例如数一整篇文档里某个词出现了多少次，这是笔者举的例子）。另有两点：这只是上界，值向量方向各异、互相抵消时，真实误差可以小得多；而且实际系统里多个头共用同一个 \(\mathcal S_t\)（NSA 是一个 GQA 组的 16 个头，DSA 是一个查询 token 的全部 128 个头），同一批位置不可能让每个头的 \(m\) 都最大，这是“共享选择”要付的代价。

(14.4) 把问题转移到了 \(\mathcal S_t\) 身上。设计一个稀疏注意力，要回答三个问题。NSA 论文第 2 节分析了现有方法为什么没能兑现推理加速（2.1 节）、为什么难以训练（2.2 节）4，那些论点可以归到下面三处（这个三分法是本课的归纳，不是论文的原话）：

  1. 选谁。 \(\mathcal S_t\) 按位置定（只看最近 \(w\) 个、固定间隔），还是按内容定（给每个位置打分，取最高的）？按内容定就需要一个打分器，而打分器要给全部 \(t\) 个位置打分，它自己不能贵。
  2. 怎么读。 GPU 从显存成块地连续读取远快于零散的按下标读取。另外，若同一组共享 KV 的多个查询头各选各的，显存要读的是它们选择的并集：原文的说法是，在 GQA 下 KV cache 的访存量对应同一组内全部查询头所选集合的并集。选得再少，并集一大，读取量照样大。
  3. 怎么训。 只在推理时才稀疏（事后稀疏，post-hoc），模型在训练时从没见过稀疏的注意力，行为会偏离；而“取最高的 \(k\) 个”是离散操作，梯度传不过去。
类比：稀疏注意力 = 先查目录再精读

映射。 前文 \(T\) 个 token = 一本 \(T\) 页的书；每个 token 的键和值 = 一页的标题与正文；稠密注意力 = 每回答一个问题都把整本书从头读到尾；打分器 = 目录，快速给每一页和当前问题的相关度打个粗分；\(\mathcal S_t\) = 按目录挑出的 \(k\) 页；(14.4) = 只精读这 \(k\) 页，并在它们之间分配注意力。

收益。 它把成本拆成两部分：“扫目录”的成本随页数增长，但每页只花很少的力气；“精读”的成本只随 \(k\) 增长。只要扫一条目录远比精读一页便宜，整体就划算。它也说明了为什么打分器必须便宜：目录要是和正文一样厚，查目录就没有意义了。

失效的地方。 第一，目录仍然要逐条扫一遍：打分器对一个查询仍是 \(O(T)\)，对整段仍是 \(O(T^2)\)，只是常数小得多（§7 会算出，128K 时这一项已经比精读还贵）。第二，真书的目录是作者写好、固定不变的；这里的“目录”对每个问题都重新打分，而且是训练出来的，可能漏掉关键的一页，漏掉的那页对答案的贡献是精确的零，而不是“略读”。第三，真人可以边读边回头翻目录；(14.4) 里选页只发生一次，读的过程中不再改选。

两种常见的省法，以及它们坏在哪里

只看最近的窗口（图 14.2(b)）最便宜，但窗口外的 token 不管多重要都看不见：让模型在 100K token 的文档里找第 3 页的一句话，它就无能为力。事后稀疏（训练用稠密，推理时截掉低分位置）不需要重训，但模型的每一层都是在稠密注意力下学会协作的，推理时突然少看一大片，误差会逐层累积。NSA 与 DSA 都属于第三条路：让模型在训练时就用稀疏注意力，用训练把损失降回来。

本页要点
  • 以 V3 维度，稠密注意力每个键 81,920 FLOPs/层（MHA 模式）。位置 128K 时一个 token 的注意力是 655 GFLOPs，占全模型计算的 89.8%；位置约 14.8K 起超过其余全部计算。
  • 一个查询 \(O(T)\)，整段 \(O(T^2)\)；解码在 128K 处每步要读约 9.2 GB 缓存。MLA 只改常数，不改形状。
  • 稀疏注意力 (14.4)：只在 \(\mathcal S_t\) 上做 softmax。输出误差不超过 \(2\varepsilon\,v_{\max}\)，\(\varepsilon\) 是被丢掉的注意力权重：注意力越集中越安全，弥散的注意力是它的失败模式。
  • 要回答三个问题：选谁（打分器要便宜）、怎么读（成块、共享）、怎么训（训练时就稀疏）。

NSA（上）：三个分支与门控

2025 年 2 月，DeepSeek 与北京大学等单位的 Yuan 等人发表了 NSA（Native Sparse Attention，原生稀疏注意力）4。这篇论文后来获得 ACL 2025 最佳论文奖（当年共四篇）5。标题里的两个词就是它对上一页三个问题的回答：native，从预训练开始就用稀疏注意力，而不是事后截断；hardware-aligned，选择方式按 GPU 的读写习惯设计。这一页讲它的整体结构和其中两个分支，下一页讲最关键的选择分支和硬件设计。

论文的实验骨干是一个 27B 总参数、3B 激活的 GQA + MoE 模型：30 层，隐藏维 2560，GQA 分 4 组共 64 个头（每组 16 个查询头共享一对键值头），每头查询/键维 192、值维 128 4。下面凡是“组内 16 个头”，都来自这个配置。

总框架：为每个查询重新造一套小键值

问题。 (14.4) 只说“选一个子集”。但子集里的元素一定要是原始的 token 吗？NSA 的回答是不一定：可以是原始 token，也可以是把一段 token 压缩成的一个“摘要 token”。于是它把稀疏注意力写成更一般的形式：对每个查询 \(\mathbf q_t\)，用前文的键值造出一套小得多的键值 \(\tilde K_t,\tilde V_t\)，再在这套小键值上做普通注意力。

数学。 设 \(\mathbf k_{:t},\mathbf v_{:t}\) 表示位置 \(1,\dots,t\) 的全部键和值。NSA 用三种“造法”\(c\in\mathcal C=\{\text{cmp},\text{slc},\text{win}\}\)（压缩 compression、选择 selection、滑动窗口 sliding window），各造一套，再加权相加：

NSA 的输出：三个分支的门控和\[\mathbf o^*_t=\sum_{c\in\mathcal C}g_t^{c}\cdot\Attn\!\big(\mathbf q_t,\tilde K_t^{c},\tilde V_t^{c}\big),\qquad \tilde K_t^c=f_K^c(\mathbf q_t,\mathbf k_{:t},\mathbf v_{:t}),\quad g_t^c\in[0,1]\]每个查询实际面对的键数 \(N_t=\sum_c\operatorname{size}[\tilde K_t^c]\)（各分支键的个数之和），设计要求 \(N_t\ll t\)。原文式 (3)–(6)。(14.5)

门控 \(g_t^c\)。 含义：每个分支输出的“音量旋钮”。理解：模型可以根据当前 token 决定更相信哪个分支，比如需要精确回忆远处某句话时调高选择分支，只需要局部语法时调高窗口分支。数学：\(g_t^c\) 由输入特征经一个 MLP 再过 sigmoid 得到，三个分支各自独立地落在 \([0,1]\) 里 4。它们不是 softmax，三者之和不必为 1；它也和 MoE 里的门控值 \(g_{i,t}\) 毫无关系，只是字母相同。门控 MLP 的具体结构论文没有给出。

分支一：压缩

含义。 把一段连续的键压成一个“摘要键”，值同理。

理解。 像给书的每一小节写一句摘要。读摘要比读全文便宜得多，而且每一节都有摘要，所以不会漏掉任何一节的存在，只是细节模糊了。

数学。 块长 \(\ell_c\)、步长 \(\delta_c\)，把第 \(b\) 块 \(\mathbf k_{b\delta_c+1:\,b\delta_c+\ell_c}\) 送进一个可学习的函数 \(\varphi\)：

压缩分支的键\[\tilde K_t^{\text{cmp}}=\Big\{\varphi\big(\mathbf k_{b\delta_c+1:\,b\delta_c+\ell_c}\big)\ \Big|\ 0\le b\le\Big\lfloor\frac{t-\ell_c}{\delta_c}\Big\rfloor\Big\},\qquad \ell_c=32,\ \delta_c=16\]\(\varphi\)：带块内位置编码的可学习 MLP，把 32 个键压成 1 个键；\(\tilde V_t^{\text{cmp}}\) 同理。个数为 \(\lfloor(t-\ell_c)/\delta_c\rfloor+1\)（\(t\ge\ell_c\) 时；更早的位置还凑不满一块，没有压缩键）。原文式 (7)，符号按本课改写。(14.6)

为什么 \(\delta_c<\ell_c\)，让相邻两块重叠一半？论文的理由是减轻“信息碎片化”：一句话如果恰好跨在两块的边界上，不重叠时它被劈成两半、分别压进两个摘要；重叠时，只要这句话不超过 \(\delta_c+1=17\) 个 token，就总有一块把它完整包住 4。（17 这个界是笔者算的：块 \(b\) 覆盖 \([16b+1,\,16b+32]\)，从 \(a\) 开始的一段取 \(b=\lfloor(a-1)/16\rfloor\)，最坏的起点 \(a=16b+16\) 离块尾还剩 17 个位置；更长的句子仍可能被劈开。）

压缩分支在 8K 和 64K 各有多少个键

\(t=8192\)：\(\lfloor(8192-32)/16\rfloor+1=\lfloor510\rfloor+1=511\) 个压缩键，约为原长的 \(1/16\)。\(t=65{,}536\)：\(\lfloor65{,}504/16\rfloor+1=4095\) 个。

注意这个数随 \(t\) 线性增长。所以压缩分支对一个查询仍是 \(O(t/16)\)，对整段仍是 \(O(T^2/16)\)：它是一个缩小了 16 倍的稠密注意力，并没有摆脱平方。（按大 O 的定义，\(O(T^2/16)\) 就是 \(O(T^2)\)；本课写出 1/16 只是为了提醒这个常数。）§3 的实测会看到，64K 的前向计算里，压缩与窗口两个分支合计的耗时已经超过了选择分支。

分支三：滑动窗口

含义。 每个查询固定看最近的 \(w\) 个原始 token。

理解。 读书时刚读过的那几页总是记得最清楚，也最常用到。

数学。

滑动窗口分支\[\tilde K_t^{\text{win}}=\mathbf k_{t-w+1:t},\qquad \tilde V_t^{\text{win}}=\mathbf v_{t-w+1:t},\qquad w=512\]下标两端都含（与 (14.6) 相同的约定），所以正好是位置 \(t-w+1,\dots,t\) 这 \(w\) 个 token；\(t<w\) 时就是全部 \(t\) 个。原文写作 \(\mathbf k_{t-w:t}\)，按这个约定会多出一个，本课按 \(w\) 个计。(14.7)

窗口看起来和“省计算”无关，NSA 专门给它一个分支，是为了保护另外两个分支的学习。论文的观察是：局部模式适应得更快，会主导学习过程，让模型懒得去学压缩和选择这两条长程通路 4。这是一种捷径学习（shortcut learning）：如果最近的上下文就能把损失降下来，梯度就不会费力去优化更难的路径。把局部模式单独交给窗口分支，另两个分支就只能靠长程信息赚到损失的下降。为了让三个分支互不干扰，NSA 给三个分支各自独立的键和值，而不是共用同一份投影 4；这会带来多少额外的 KV cache，论文没有量化。

分支二：选择（预告）

选择分支从原始 token 里挑出 \(n_s=16\) 个长 \(\ell_s=64\) 的块，一共 \(16\times64=1024\) 个原始 token，精读它们。16 块里有 3 块是固定的：开头 1 块和最近 2 块（本地块），真正按分数动态选出的是 13 块 4。分数从哪里来、为什么按块选、为什么一组的头要选同一批块，是下一页的主题。

每个查询到底看多少个键

把三个分支的键数加起来，就得到 NSA 每个查询的预算。解码时论文按访存量给出了同样形式的上界（原文的压缩项写作 \(\lfloor(t-\ell_c)/\delta_c\rfloor\)，比 (14.6) 的个数少 1，见 §3 的警告框）4：

NSA 每个查询面对的键数\[N_t\ \le\ \underbrace{\Big\lfloor\frac{t-\ell_c}{\delta_c}\Big\rfloor+1}_{\text{压缩}\ \approx\ t/16}\ +\ \underbrace{n_s\ell_s}_{\text{选择}\ =\ 1024}\ +\ \underbrace{w}_{\text{窗口}\ =\ 512}\ \approx\ \frac{t}{16}+1536\]是上界而不是等号：本地块与窗口有重叠，开头处 \(t\) 还不够长时各项都取不满。(14.8)

复核论文的“2560 个 token”预算

NSA 在 LongBench 上和其他稀疏方法比较时，为了公平，把所有基线的 token 预算都设为 2560，理由是这“对应 NSA 处理 32K 序列时平均激活的 token 数” 4。可以自己复核：对 \(t=32,\dots,32{,}768\) 逐个计算 \(\lfloor(t-32)/16\rfloor+1+\min(1024,t)+\min(512,t)\) 再取平均，得 2540.96，与 2560 差 0.7%。心算版：压缩项的平均约是 \(32{,}768/2/16=1024\)，加上选择 1024 与窗口 512，正好 2560。

这张表揭示了 NSA 的一个性质：它的预算随 \(t\) 线性增长，斜率是 \(1/16\)，来自压缩分支。它把 \(O(t)\) 的常数从 1 降到了约 \(1/16\)，再加一个固定的 1536。§4 会看到 DSA 的选择是固定的 \(k=2048\)，但它的打分器同样随 \(t\) 线性增长。两者都没有真正摆脱“对每个查询扫一遍全部前文”，只是扫得便宜。

小练习：16K 处的精确预算

用 (14.8) 的精确形式（压缩项取 \(\lfloor(t-\ell_c)/\delta_c\rfloor+1\)），算 \(t=16{,}384\) 时 NSA 每个查询最多面对多少个键，与表中的 2560 差多少？占稠密的百分之几？

看答案

压缩：\(\lfloor(16{,}384-32)/16\rfloor+1=1022+1=1023\)；选择 1024；窗口 512。合计 2559，比表中按 \(t/16\) 估的 2560 少 1。占稠密的 \(2559/16{,}384=15.6\%\)。这是上界：本地块与窗口重叠的部分实际只读一次。

把“目录”类比套到 NSA 上

映射。 压缩分支 = 每一节的摘要，全部读一遍（便宜但模糊）；选择分支 = 根据摘要的相关度，把最相关的 16 节翻开读原文（其中第一节和最近两节无论如何都读）；窗口 = 刚读过的最后 512 个字总是记在脑子里；门控 = 决定这三种信息各听多少。

收益。 它解释了为什么选择分支的打分不需要额外参数：读摘要时顺手就知道了哪一节最相关（下一页的“分数复用”）。

失效的地方。 这里的“摘要”不是一句人能读懂的话，而是 \(\varphi\) 学出来的一个向量；而且摘要本身也参与回答（压缩分支有自己的输出），不只是用来挑章节。

本页要点
  • NSA 把稀疏注意力写成“为每个查询造一套小键值”(14.5)：压缩、选择、窗口三个分支，各自独立的键值，由各自独立的 sigmoid 门加权相加。
  • 压缩分支 (14.6)：长 32、步长 16 的重叠块压成摘要键，每 16 个 token 一个；它本身是缩小 16 倍的稠密注意力，仍是 \(O(T^2/16)\)。
  • 窗口分支 (14.7) 看最近 512 个 token，主要作用是吸收局部模式，逼另两个分支学长程依赖。
  • 每个查询约看 \(t/16+1536\) 个键 (14.8)：8K 时 2048，64K 时 5632。

NSA（下）：硬件对齐的块选择

三个分支里，只有选择分支读的是原始 token 的精确内容：压缩分支读的是模糊的摘要，窗口分支只看附近。NSA 能不能在长上下文里“找到第 3 页的那句话”，全靠它。这一页回答选择分支的三个设计问题：块的分数从哪里来（不能太贵）；为什么按 64 个 token 的块来选，而不是逐个 token 选；同一个 GQA 组里的 16 个头怎样协调。最后看 NSA 的实测速度与质量，以及它试过又放弃的两条路。

为什么按块选

含义。 选择的最小单位是一个块：\(\ell_s=64\) 个连续的 token。第 \(j\) 个选择块（\(j=0,1,2,\dots\)）包含键 \(\mathbf k_{j\ell_s+1:(j+1)\ell_s}\)，要么整块被选中，要么整块不选。本页用 \(j\) 数选择块、用 \(b\) 数压缩块，两者不要混。

理解。 理由有两条，一条来自硬件，一条来自注意力本身 4。硬件上，现代 GPU 成块连续读取的吞吐量远高于按下标零散读取；张量核（tensor core）也需要把一批键拼成矩阵才能高效计算。注意力本身呢？前面提到的注意力图显示，高分位置往往成片出现：一个重要 token 的邻居通常也重要。既然如此，按块选并不会多浪费多少预算。

GPU 为什么偏爱连续读取了解显存访问粒度的可以跳过

显存（HBM）不是一个字节一个字节地交付数据，而是一段一段地搬：程序要一个数，硬件也会把它所在的一整段搬进片上缓存。数据在内存里连续存放时，搬来的整段都有用；如果要的数东一个西一个（比如逐 token 选出的 2048 个位置分散在十几万个位置里），每次搬来的整段里只有一小部分有用，带宽就被浪费了。另外，GPU 上做矩阵乘法最快的硬件单元要求输入是成块的小矩阵。这两件事合起来，就是“硬件对齐”的意思：让算法的访问模式长成硬件擅长的样子。

分数从哪里来：复用压缩分支

给每一块打分，最直接的办法是再造一个打分网络，但它要对每个查询、每一块都算一遍，本身又是一笔账。NSA 的做法是不另外打分：压缩分支本来就要算查询对每个压缩键的注意力权重，这组权重就是一份现成的“哪一段更相关”的评估 4。

压缩分支的注意力分数\[\mathbf p_t^{\text{cmp}}=\softmax\!\big(\mathbf q_t^\top\tilde K_t^{\text{cmp}}\big)\in\R^{\lfloor(t-\ell_c)/\delta_c\rfloor+1}\]第 \(b\) 个分量 \(\mathbf p_t^{\text{cmp}}[b]\) 是查询 \(\mathbf q_t\) 对第 \(b\) 个压缩块的注意力权重。原文式 (8)。(14.9)

如果选择块和压缩块的切法完全一样（\(\ell_s=\ell_c=\delta_c\)），第 \(b\) 个选择块的分数就是 \(\mathbf p_t^{\text{cmp}}[b]\)。NSA 实际用的是 \(\ell_c=32\)、\(\delta_c=16\)、\(\ell_s=64\)，一个选择块和好几个压缩块部分重叠，于是按重叠程度把压缩块的分数加起来。

一个选择块收集哪些压缩块的分数（\(\ell_c=32,\ \delta_c=16,\ \ell_s=64\)）
(1)\(\displaystyle B^{\text{slc}}_j=[64j+1,\ 64j+64]\)选择块 \(j\)：按 (14.12) 的切法，第 \(64j+1\) 到第 \(64j+64\) 个键
(2)\(\displaystyle B^{\text{cmp}}_b=[16b+1,\ 16b+32]\)压缩块 \(b\)：按 (14.6)，块长 32、步长 16
(3)\(\displaystyle o_{j,b}=\abs{B^{\text{cmp}}_b\cap B^{\text{slc}}_j}\)重叠长度 = 两个区间交集里的键数
(4)\(\displaystyle b=4j,\,4j+1,\,4j+2:\ \text{重叠}\ 32\)这三块完整落在选择块里
(5)\(\displaystyle b=4j-1,\ 4j+3:\ \text{重叠}\ 16\)这两块一半在里、一半在外
(6)\(\displaystyle \text{权重}=\text{重叠}/\delta_c=(1,2,2,2,1)\)以 16 个 token 为单位计数；其余压缩块不重叠，权重为 0
选择块的分数：按重叠加权求和\[\mathbf p_t^{\text{slc}}[j]=\sum_{b}\omega_{j,b}\,\mathbf p_t^{\text{cmp}}[b],\qquad \omega_{j,b}=\frac{o_{j,b}}{\delta_c}=\frac{\abs{B^{\text{cmp}}_b\cap B^{\text{slc}}_j}}{\delta_c}\in\{0,1,2\}\]原文式 (9) 用二重求和写出同样的 \((1,2,2,2,1)\) 计数，见下面的警告框。(14.10)
原文公式的下标对不上

按原文式 (7) 与式 (12) 的下标约定逐块核对，完整落在选择块 \(j\) 里的压缩块是 \(4j,4j+1,4j+2\)，而原文式 (9) \(\mathbf p_t^{\text{slc}}[j]=\sum_{m=0}^{\ell_s/\delta_c-1}\sum_{n=0}^{\ell_c/\delta_c-1}\mathbf p_t^{\text{cmp}}\big[\tfrac{\ell_s}{\delta_c}j-m-n\big]\) 取的是 \(4j-4,\dots,4j\)（\(m+n\) 取 0 到 4 的次数正是 1、2、2、2、1）；arXiv v1 版的式 (9) 写的是 \(+m+n\)，v2 改成了 \(-m-n\)，两版都对不齐。原文还称 \(\tilde K_t^{\text{cmp}}\) 有 \(\lfloor(t-\ell_c)/\delta_c\rfloor\) 列，比式 (7) 的元素个数少 1。这些都是记号上的小毛病，不影响“按重叠加权”这个机制，所以本课讲机制，不逐下标照抄原文。

算一个块分数

设某个查询对压缩块 3 到 7 的注意力权重是 \((0.02,\ 0.10,\ 0.30,\ 0.05,\ 0.01)\)。选择块 1 的分数是 \(1\times0.02+2\times0.10+2\times0.30+2\times0.05+1\times0.01=0.93\)。如果另一个选择块覆盖的压缩块权重都在 0.01 左右，它的分数只有约 \(8\times0.01=0.08\)。块分数不必归一化，只用来排序。每个块的分数只是 5 个数的加权和，几乎是免费的：打分的主要成本（\(\mathbf q_t\) 与全部压缩键的点积）已经算在压缩分支里了。

一组头必须选同一批块

问题。 NSA 的骨干用 GQA：64 个查询头分成 4 组，每组 16 个查询头共用一对键值头。按 (14.10)，每个头都有自己的 \(\mathbf p_t^{\text{slc}}\)，如果各选各的 16 块，会怎样？

GQA 与访存读过第 4 课的可以跳过

分组查询注意力（GQA）把 \(n_h\) 个查询头分成 \(n_g\) 组，同一组的查询头共用同一个键头和值头，缓存里只存 \(n_g\) 份键值。解码时，读进片上的一份键值会被组内所有查询头用到：读一次，算好几次。这正是 GQA 在解码时省带宽的原因（第 4 课 §5）。

组内 16 个头读的是同一份键值缓存。若头 1 要块 \(\{3,7,\dots\}\)、头 2 要块 \(\{5,9,\dots\}\)，这一组就要把所有头要的块都读进来，读取量是它们的并集。所以 NSA 要求组内的选择一致：先把组内各头的分数加起来，再统一取前 \(n_s\) 名 4。

组内共享的块选择\[\mathbf p_t^{\text{slc}\,\prime}=\sum_{h=1}^{16}\mathbf p_t^{\text{slc},(h)},\qquad \mathcal I_t=\Big\{j\ \Big|\ \operatorname{rank}\big(\mathbf p_t^{\text{slc}\,\prime}[j]\big)\le n_s\Big\},\qquad n_s=16\]\(h\) 是组内的头编号，求和对一个 GQA 组内的 16 个查询头进行；\(\operatorname{rank}(\cdot)\) 是降序名次；\(\mathcal I_t\) 是被选中的选择块编号的集合。开头 1 块与本地 2 块总是在 \(\mathcal I_t\) 里。原文式 (10)(11)；原文式 (11)(12) 用 \(i\) 数选择块、式 (9) 用 \(j\)，本课统一写 \(j\)。(14.11)
选择分支的键：把被选块拼起来\[\tilde K_t^{\text{slc}}=\operatorname{Cat}\Big[\big\{\mathbf k_{j\ell_s+1:(j+1)\ell_s}\ \big|\ j\in\mathcal I_t\big\}\Big]\in\R^{d_k\times n_s\ell_s}=\R^{192\times1024}\]\(d_k=192\) 是 NSA 骨干每头键的维度；\(\tilde V_t^{\text{slc}}\) 同理。拼接的是原始的键和值，不是压缩后的；原文式 (12)。(14.12)
各选各的，要多读多少

64K 的上下文有 \(65{,}536/64=1024\) 个选择块。开头块与 2 个本地块对所有头都一样，只有动态选的 13 块会因头而异。若组内 16 个头各自动态选 13 块、且互不重叠，并集是 \(3+16\times13=211\) 块，即 \(211\times64=13{,}504\) 个 token，占上下文的 20.6%；共享选择时只有 16 块、1024 个 token。最坏情况下，各选各的要多读约 13 倍。各头的选择实际会有重叠，倍数介于 1 和 13 之间，但“稀疏”的收益会被大幅吃掉，而且读进来的很多块只被一个头用到。

组中心的核：一次读，16 个头用

有了组内一致的 \(\mathcal I_t\)，NSA 为选择分支写了专门的 Triton 核（压缩分支与窗口分支直接用 FlashAttention-2 的核）4。它的组织方式与 FlashAttention 恰好相反：FlashAttention 让一段连续的查询共用 KV 块；NSA 的选择分支里不同位置的查询选的块各不相同，于是改为让同一位置、同一组的 16 个头共用 KV 块。论文把这概括为三点：

  1. 以组为中心装入数据：外层对每个查询位置 \(t\) 和每个 GQA 组启动一个程序，把这一组 16 个头的查询 \(Q_t\in\R^{16\times192}\) 和共享的索引 \(\mathcal I_t\) 装进片上 SRAM。
  2. 共享的 KV 读取：内层按 \(\mathcal I_t\) 依次把被选块装进 SRAM，每次装 \(B_k\) 行（\(B_k\) 整除 64，论文没有给出具体值）；每装一块就算出这一块的分数，用在线 softmax累加进输出。
  3. 外层循环交给网格：查询位置的循环交给 Triton 的 grid 调度器并行执行。
共享让每个字节多做 16 倍的事（解码，按 BF16 计）

一个查询位置、一个组，装入一个 64 token 的块：键 \(64\times192\)、值 \(64\times128\)，共 20,480 个数，按 BF16 是 40,960 字节。16 个头每头对每个键做 \(2\times192+2\times128=640\) 次运算，共 \(16\times64\times640=655{,}360\) FLOPs。算术强度（arithmetic intensity）是运算次数除以从显存搬运的字节数（第 4 课 §4、M10 §3），这里是 \(655{,}360/40{,}960=16\) FLOPs/字节。如果每个头单独读自己的键值，只有 1 FLOP/字节。解码受带宽限制（第 4 课），算术强度越高，同样的带宽能喂饱越多的计算。NSA 的实际数值精度论文没有说明，这里的 BF16 是为了算例而取的假设。

论文明确说这个核针对 GQA 与 MQA 设计；对每个头各有键值的 MHA，解码本来就是访存密集、效率低的，不在它的考虑范围内 4。这一点在 §5 会变得关键：DSA 所在的 MLA，解码时正是以“MQA 模式”运行的。

账单与实测

解码。 解码每一步读的 token 数就是 (14.8) 的 \(N_t\)。解码受带宽限制时，时间大致与读取量成正比，于是论文用读取量之比估计加速 4：

训练。 前向和反向用的是完整序列，瓶颈变成计算。论文在 8 张 A100 上比较了 NSA 的 Triton 核与 Triton 版 FlashAttention-2：64K 时前向快 9.0 倍、反向快 6.0 倍 4。这是注意力核的耗时之比，不是端到端的训练吞吐：模型里还有 MoE、投影等大量与注意力无关的计算。

NSA 试过又放弃的两条路

论文第 6.1 节记录了两种没有采用的选择策略，它们在 3B 模型上的训练损失都比 NSA 差 4：

  1. 用辅助损失训练一个可学习的打分器：给每个 token 加一个额外的查询、给每个块加一个代表键，用块内注意力分数的平均（mean-pooling）作监督信号，并用 KL 散度监督块重要性的预测。放弃的理由是它依赖辅助损失，增加算子开销，而且常常损害模型性能。
  2. 无参数的启发式选择（类似 Quest 的做法），并试过“先用全注意力训练 1000 步，再切换到启发式块选择”的冷启动。

请记住这两条。§6 会看到，DSA 的训练方法恰好是“用 KL 散度监督一个独立的打分器 + 先稠密预热 1000 步”：这两样 NSA 当年都试过（分别用在上面两条路里）、都放弃了，在另一套工程条件下（token 级选择、ReLU + FP8 的打分器、打分器与主模型的梯度分离）重新成了主角。这个“翻盘”是笔者的解读，两篇论文都没有这样表述。

本页要点
  • 选择分支按 64 token 的块选，理由是 GPU 偏爱连续读取、注意力分数成片出现。
  • 块分数不另外计算：复用压缩分支的注意力权重 (14.9)，按重叠加权 (14.10)，权重 \((1,2,2,2,1)\)。
  • GQA 组内 16 个头把分数相加、统一取前 16 块 (14.11)，否则读取量是并集；组中心核让一次读取服务 16 个头。
  • 64K 时解码的期望加速 11.6 倍（访存量之比，上限 16 倍），注意力核前向 9.0 倍、反向 6.0 倍；27B 模型上质量不低于全注意力。
  • NSA 放弃了“KL 监督的独立打分器”和“稠密预热后切换”，DSA 后来把两者捡了回来。

DSA（上）：lightning indexer 与 top-k

2025 年 9 月 22 日，DeepSeek 发布了 V3.1-Terminus 6；一周后的 9 月 29 日，发布了 V3.2-Exp，并附上一份 6 页的技术报告 7。报告开宗明义：V3.2-Exp 唯一的架构改动，是通过续训引入 DeepSeek 稀疏注意力（DeepSeek Sparse Attention，DSA）。同年 12 月的正式版 V3.2 使用与 V3.2-Exp 完全相同的架构，论文中 DSA 的描述逐字沿用 2。所以这一课讲的 DSA，就是 V3.2 系列的 DSA，没有“改进版”。

报告说 DSA 的原型主要由两部分组成：lightning indexer（闪电索引器）与细粒度的 token 选择机制。和 NSA 对照，DSA 对 §1 那三个问题给出了完全不同的回答：

问题 NSA DSA

怎么读 一个 GQA 组的 16 个头共享同一批块 一个查询 token 的全部 128 个头共享同一批 token（MLA 的 MQA 模式）

lightning indexer：打分公式

问题。 要逐 token 地选，就要给前文每一个 token 打分。对位置 \(t\) 的查询，这是 \(t\) 个分数；整段是 \(O(T^2)\) 个。打分器因此必须比主注意力便宜得多，否则省下的全被它吃掉。

数学。 DSA 报告的式 (1) 7：

lightning indexer 的打分\[I_{t,s}=\sum_{j=1}^{H^I}w^I_{t,j}\cdot\operatorname{ReLU}\!\big(\mathbf q^I_{t,j}\cdot\mathbf k^I_s\big)\]\(I_{t,s}\in\R\)：查询 token \(t\) 对前文 token \(s\) 的索引分数；\(H^I\)：indexer 的头数；\(\mathbf q^I_{t,j}\in\R^{d^I}\) 与 \(w^I_{t,j}\in\R\) 由查询 token 的 \(\mathbf h_t\) 算出；\(\mathbf k^I_s\in\R^{d^I}\) 由前文 token 的 \(\mathbf h_s\) 算出。(14.14)

逐项展开：

  • 索引分数 \(I_{t,s}\)。 含义：查询 \(t\) 认为 token \(s\)“值不值得看”。理解：目录上给每一页打的相关度粗分，只用来排序，不用来加权，所以它不需要归一化，也不经过 softmax。数学：一个实数，对每一对 \((t,s)\) 各算一个，\(s\le t\)。
  • 头数 \(H^I\) 与维度 \(d^I\)。 论文只说 indexer 有“少量的头”，没有给数值；公开的 config.json 里是 index_n_heads = 64、index_head_dim = 128 8。64 个头并不算“少”（主注意力是 128 个头），它便宜的原因在下面。
  • 查询 \(\mathbf q^I_{t,j}\) 与头权重 \(w^I_{t,j}\)。 含义：第 \(j\) 个 indexer 头的“检索问题”，以及这个查询对第 \(j\) 个头的信任程度。理解：64 个头从 64 个角度评价前文，\(w^I_{t,j}\) 决定当前 token 更听哪几个头的。\(w^I_{t,j}\) 是线性投影的输出，可正可负：一个头可以投“反对票”。
  • 键 \(\mathbf k^I_s\)。 每个前文 token 只有一个 indexer 键，被 64 个 indexer 头共用：indexer 自己就是一个 MQA 结构。这是它便宜的第一个原因：缓存和读取的都只是每 token 一个 128 维的键。
  • ReLU。 报告的原话是：选 ReLU 作为激活函数是出于吞吐量的考虑 7。可以这样理解（笔者的解读，报告没有展开）：ReLU 只是一次比较，不需要 softmax 那样的指数运算和跨位置的求和，每个 \((t,s)\) 的分数独立算完即可；负的点积被截成 0，表示“这个头认为 \(s\) 与当前查询无关”。

报告说，由于 indexer 头数少、又能用 FP8 实现，它的计算效率非常高 7。把“便宜”换成数字：

indexer 每个键要花多少 FLOPs（每层、一个查询）
(1)\(\displaystyle \mathbf q^I_{t,j}\cdot\mathbf k^I_s:\ 2d^I=256\)一个 indexer 头的点积，\(d^I=128\)
(2)\(\displaystyle \text{ReLU 与乘 }w^I_{t,j}\text{：每头几次}\)相对点积可忽略
(3)\(\displaystyle \text{每键}:\ 2H^Id^I=2\times64\times128=16{,}384\)64 个头
(4)\(\displaystyle \frac{16{,}384}{278{,}528}=\frac{1}{17}\)与下一页的 MQA 模式核心注意力每键相比

没有值、没有 softmax、单个共享键，每键的计算量只有主注意力（MQA 模式）的 \(1/17\)。而且这些运算在 FP8 上做：在支持 FP8 的 GPU 上，FP8 矩阵乘法的峰值吞吐通常高于 BF16，实际耗时之比可能还要更小。后半句是笔者按硬件常识的推测，报告没有给出 indexer 的实测耗时。

手算 lightning indexer

\(H^I=2\)，\(d^I=2\)。查询 token \(t\) 的两个 indexer 查询 \(\mathbf q^I_{t,1}=(1,0)\)、\(\mathbf q^I_{t,2}=(0,1)\)，头权重 \(w=(0.5,\ 1.0)\)。前文四个 token 的 indexer 键：\(\mathbf k^I_1=(2,-1)\)，\(\mathbf k^I_2=(-1,3)\)，\(\mathbf k^I_3=(1,1)\)，\(\mathbf k^I_4=(-2,-2)\)。

头 1 的点积：\((2,\,-1,\,1,\,-2)\)，ReLU 后 \((2,0,1,0)\)，乘 0.5 得 \((1,\,0,\,0.5,\,0)\)。头 2 的点积：\((-1,\,3,\,1,\,-2)\)，ReLU 后 \((0,3,1,0)\)，乘 1.0 不变。相加：\(I_{t,:}=(1.0,\ 3.0,\ 1.5,\ 0)\)。若 \(k=2\)，选中 \(\{2,3\}\)。

注意 token 1：头 1 很看好它（点积 2），头 2 对它是负的（点积 −1）。ReLU 让头 2 的意见变成“不表态”（0），而不是“扣分”。这就是 ReLU 丢掉的信息：在单个头上，“无关”和“强烈相反”被合并了；模型只能靠 \(w\) 的符号和其他头来表达反对。

top-k：逐 token 的选择

有了分数，选择就是取前 \(k\) 名 7：

细粒度的 token 选择\[\begin{aligned}\mathcal S_t&=\big\{s\ \big|\ I_{t,s}\in\operatorname{Top\text{-}k}(I_{t,:})\big\},\qquad k=2048\\ \mathbf u_t&=\Attn\!\Big(\mathbf h_t,\ \big\{[\mathbf c^{KV}_s;\mathbf k^R_s]\ \big|\ s\in\mathcal S_t\big\}\Big)\end{aligned}\]\(\mathcal S_t\)：被选中的 \(k\) 个位置；\([\mathbf c^{KV}_s;\mathbf k^R_s]\in\R^{576}\) 是 MLA 缓存里的完整条目（报告写作 \(\mathbf c_s\)，指的是整个 576 维的条目，不只是 512 维的 \(\mathbf c^{KV}_s\)）。\(k\) 的数值写在训练小节里，config.json 的 index_topk 也是 2048。(14.15)

三个细节决定了 (14.15) 的含义：

  1. 一个查询 token 选一组，128 个头共用。 被选的 2048 个 token 不是每个头各选一套，而是整个查询 token 的全部注意力头共用同一组。下一页会看到，这正是 MLA 的 MQA 模式要求的。
  2. \(t\le2048\) 时就是稠密注意力。 推理代码取的是 \(\min(k,\ \text{当前长度})\) 个 8，前文不到 2048 个 token 时全部选中，(14.15) 与 (14.1) 在数学上完全相同，只是多付了 indexer 的钱。所以 DSA 在短上下文任务上的质量变化，不可能来自“少看了 token”，只可能来自续训与后训练。
  3. 选择是离散的，梯度过不去。 在 (14.15) 里，分数 \(I\) 只通过集合 \(\mathcal S_t\) 影响输出。把某个 \(I_{t,s}\) 改动一点点，只要排名不变，\(\mathcal S_t\) 就不变，输出也一点不变，所以导数是 0；排名恰好交换的那一刻，\(\mathcal S_t\) 突然换掉一个成员，输出跳变，导数不存在。于是主模型的语言模型损失没有办法告诉 indexer“你漏选了一个重要 token”。indexer 必须另有自己的训练信号，这是 §6 的内容。
128K 时选了多少

\(k/T=2048/131{,}072=1.5625\%\)。每个查询只精读 1.56% 的前文。和 NSA 在 64K 时每个查询约 5632 个键（8.6%）相比，DSA 的预算是固定的 2048，不随 \(T\) 增长；随 \(T\) 增长的只有 indexer 的打分。

两个常见的误读

“每个头各选 2048 个 token。” 错。是每个查询 token 选一组 2048 个，被它的全部 128 个头共享。“DSA 首次实现了细粒度稀疏注意力。” 这是模型仓库 README 里的宣传语 8，技术报告正文没有这个说法；逐 token 的选择在推理期方法里早已有之（NSA 论文比较过的 Exact-Top 基线，就是先算出全部注意力分数、再为每个查询取分数最高的若干个键）4。比较稳妥的说法是：DSA 是一种在前沿规模的模型上端到端续训、并实际部署了的 token 级稀疏注意力；至于它是不是“第一个”，只有 DeepSeek 自己的说法。

FP8 与缩放因子读过第 12 课或 M08 的可以跳过

FP8 E4M3 用 8 个比特表示一个数（1 位符号、4 位指数、3 位尾数），能表示的最大值是 448，而且只有 3 位尾数：在正规数范围里，相邻两个可表示的数之间相对差距在 6.25% 到 12.5% 之间，舍入的相对误差不超过 \(2^{-4}=6.25\%\)。为了把一组数装进这个范围，要先除以一个缩放因子，让这组数里最大的那个刚好落在 448 附近。代价落在最小的那些数上：E4M3 的正规数只覆盖 \(2^{-6}\) 到 448 这一段，跨 \(448/2^{-6}=28{,}672\) 倍；比这组最大值小 28,672 倍以上的数会落进次正规区，相对误差迅速变大，再小就被舍入成 0。所以一个离群值要比其余的数大上万倍，才会让 FP8 把成片的小数冲成 0。对 INT8 这种等间距的格式，伤害要直接得多：步长等于最大绝对值除以 127，离群值越大，其余的数分到的刻度越少。详见 M08 §6。

Hadamard 矩阵。 含义：元素只有 \(+1\) 和 \(-1\)、各行两两正交的方阵。理解：最小的一个是下式左边的 \(H_2\)，它把 \((x_1,x_2)\) 变成“和”与“差” \((x_1+x_2,\ x_1-x_2)\)；除以 \(\sqrt2\) 之后是一个正交变换（几何上是一次镜面反射），不改变向量长度。例如 \((40,\ 0)\) 经 \(H_2/\sqrt2\) 变成 \((28.3,\ 28.3)\)：一个大分量被平分给了两个分量。数学：更大的按下式右边递推（Sylvester 构造），\(128=2^7\)，从 \(H_2\) 起再递推 6 次就是 \(H_{128}\)；这样构造出的矩阵是对称的，并且 \(H_nH_n^\top=nI\)。

\[H_2=\begin{pmatrix}1&1\\1&-1\end{pmatrix},\qquad H_{2n}=\begin{pmatrix}H_n&H_n\\H_n&-H_n\end{pmatrix}\]

Hadamard 旋转为什么不改变打分，又可能有什么用？ 先证明它不改变点积，再看它对离群值做了什么。

正交旋转不改变点积
(1)\(\displaystyle H_{128}H_{128}^\top=128\,I\)Hadamard 矩阵的定义：元素为 \(\pm1\)，各行两两正交
(2)\(\displaystyle \mathcal H^\top\mathcal H=\frac{1}{128}H_{128}^\top H_{128}=I\)\(\mathcal H=H_{128}/\sqrt{128}\)；\(H_{128}\) 对称
(3)\(\displaystyle (\mathcal H\mathbf q)\cdot(\mathcal H\mathbf k)=\mathbf q^\top\mathcal H^\top\mathcal H\,\mathbf k\)点积写成矩阵乘法，用转置的“穿脱法则”
(4)\(\displaystyle =\mathbf q^\top\mathbf k=\mathbf q\cdot\mathbf k\)代入第 (2) 行
一个离群值被摊平

设一个 128 维向量只有一个分量是 40，其余都是 0。旋转后，每个分量都是 \(\pm40/\sqrt{128}=\pm3.54\)：一个巨大的离群值被均匀地摊到 128 个分量上，最大绝对值从 40 降到 3.54，而向量长度（40）不变。更真实的情形：一个 128 维标准正态向量把其中一个分量改成 40，旋转后每个分量是 \(\pm3.54\) 加上一个近似标准正态的数，最大绝对值约为 5 到 8（笔者 1000 次随机抽样：5.2–7.8，均值约 6.1）。

这对量化有多大好处，取决于格式，而且比较必须在同一套坐标里做：旋转后量化的结果要先乘回 \(\mathcal H^\top\)、回到原来的坐标，才能和原向量逐个分量比。（旋转后的 128 个坐标每个都混进了离群值，数值在 3.5 左右，已经不是“其余 127 个分量”了；拿它们的相对误差和原来那些绝对值 1 左右的分量比，是在比两样东西。）按每 128 个数一个缩放因子量化这个向量，看其余 127 个普通分量的相对误差中位数（笔者用 Python 复算，1000 次抽样）：

  • INT8（等间距）：不旋转时步长 \(40/127=0.315\)，约 1/8 的分量被舍入成 0，误差中位数约 11%；旋转后最大绝对值只有约 6，步长缩小到约 1/6.5，转回原坐标后误差约 1.4%。旋转明显有用。
  • FP8 E4M3（浮点）：不旋转时约 2.2%，没有分量变成 0，因为 40 倍的悬殊远没有超出 E4M3 的正规范围（见上面的前置框）。旋转后反而约 10%。原因是浮点数的误差与每个数自身的大小成正比：不旋转时，离群值的误差只落在它自己身上（这里 40 恰好映到 448，误差为 0），小分量只承担自己那份小误差；旋转后每个坐标都在 3.5 左右，各带约 0.08 的舍入误差，乘回 \(\mathcal H^\top\) 后全部摊到那些绝对值只有 1 左右的分量上。

FP8 要到离群值是典型分量的上万倍时，才会有成片的分量被冲成 0：离群值取 \(10^5\) 时，不旋转约有 17% 的分量变成 0。旋转也救不回它们：旋转后每个坐标都约为 \(\pm8840\)，FP8 在这个量级上相邻两个可表示数相差约 630，普通分量带来的 \(\pm1\) 左右的差别被整个舍掉，转回原坐标后同样丢失。所以在这些例子里，旋转只对等间距的格式有好处。代码里没有注释说明为什么要旋转，“为了在低精度量化前摊平离群值”是笔者的推测；indexer 的真实激活里离群值有多悬殊、落在哪些通道，公开材料没有给出。

把“目录”类比套到 DSA 上

映射。 KV cache = 整本书；indexer 键 \(\mathbf k^I_s\) = 目录里每一页的一行索引（只有 128 个数，而且是 FP8）；indexer 的 64 个头 = 64 位审稿人，各自从一个角度给每页打分，\(w^I_{t,j}\) 决定这次更听谁的；top-k = 按总分翻开 2048 页；主注意力 = 精读这 2048 页。

收益。 它说明了 DSA 与 NSA 的根本区别：NSA 的“目录”是书的章节摘要（压缩分支），本身也参与回答；DSA 的目录是一份独立编写的索引，只用来挑页，不参与回答。

失效的地方。 目录仍要逐行扫完：128K 时，一个查询要对 131,072 行索引各打一次分。§7 会算出，在 34,816 以上的长度，扫目录（indexer）的 FLOPs 已经超过精读（核心注意力）。另外，这份目录是训练出来的“模仿品”：它学的是稠密注意力会看哪里（§6），模仿不到的地方就会漏页。

小练习：indexer 自己要缓存多少

看答案

（a）\(128\times1+4=132\) 字节/层，\(132\times61=8{,}052\) 字节。（b）\(132/656=20.1\%\)。（c）每个新的查询都要对全部前文打分（(14.14) 对所有 \(s\le t\) 求值），一个 token 这次没被选中，下一个查询可能就要选它；打分时缺了它的键，它就永远没有机会被选中。

DSA（中）：在 MLA 的 MQA 模式上实现

选出了 2048 个 token，还要把它们真的读进来、算出注意力，而且要算得快。这一页回答“怎么读”：DSA 报告说，出于计算效率，在核的层面每个 KV 条目必须被多个查询共享，并直接引用 NSA 作为这一原则的出处，所以 DSA 基于 MLA 的 MQA 模式实现，每个潜向量（MLA 的 KV 条目）被这个查询 token 的全部查询头共享 7。要理解这句话，先回到第 9 课的 MLA，看它的两种算法（第 9 课 §7 有更完整的讲法）。

MLA 的两种算法

第 9 课讲过，MLA 的缓存里每个 token 只存两样东西：压缩潜向量 \(\mathbf c^{KV}_s\in\R^{512}\) 与带 RoPE 的共享键 \(\mathbf k^R_s\in\R^{64}\) 9,1。第 \(i\) 个头的键和值由它们展开：\(\mathbf k_{s,i}=[W^{UK}_i\mathbf c^{KV}_s;\ \mathbf k^R_s]\in\R^{192}\)，\(\mathbf v^C_{s,i}=W^{UV}_i\mathbf c^{KV}_s\in\R^{128}\)（即 (14.1) 里的值），其中 \(W^{UK}_i,W^{UV}_i\in\R^{128\times512}\) 是第 \(i\) 个头的上投影。查询也分成同样的两段：\(\mathbf q_{t,i}=[\mathbf q^C_{t,i};\mathbf q^R_{t,i}]\)，\(\mathbf q^C_{t,i}\in\R^{128}\) 是内容部分，\(\mathbf q^R_{t,i}\in\R^{64}\) 是带 RoPE 的部分。同一个注意力有两种算法 2：

  • MHA 模式：先把每个缓存条目按 128 个头展开成键和值，再做普通的多头注意力，也就是 (14.1)。V3.1-Terminus 用它来训练和预填充。
  • MQA 模式：不展开缓存，而是把 \(W^{UK}_i\) 挪到查询那一侧（第 9 课 §3 的“矩阵吸收”），让缓存条目原样充当所有头的键和值。V3.1-Terminus 用它来解码。

为什么这两种算法给出同一个结果？推导只用结合律和转置。

MQA 模式与 MHA 模式等价（第 \(i\) 个头）
(1)\(\displaystyle \mathbf q_{t,i}^\top\mathbf k_{s,i}=(\mathbf q^C_{t,i})^\top W^{UK}_i\mathbf c^{KV}_s+(\mathbf q^R_{t,i})^\top\mathbf k^R_s\)查询与键都分成内容部分（128 维）和 RoPE 部分（64 维），拼接向量的点积是两段点积之和
(2)\(\displaystyle =\big((W^{UK}_i)^\top\mathbf q^C_{t,i}\big)^\top\mathbf c^{KV}_s+(\mathbf q^R_{t,i})^\top\mathbf k^R_s\)结合律与 \((AB)^\top=B^\top A^\top\)；记 \(\mathbf q^A_{t,i}=(W^{UK}_i)^\top\mathbf q^C_{t,i}\in\R^{512}\)
(3)\(\displaystyle =\big[\mathbf q^A_{t,i};\mathbf q^R_{t,i}\big]^\top\big[\mathbf c^{KV}_s;\mathbf k^R_s\big]\)两段点积合成一个 576 维的点积：缓存条目本身成了“键”
(4)\(\displaystyle \sum_sp_{t,i,s}W^{UV}_i\mathbf c^{KV}_s=W^{UV}_i\sum_sp_{t,i,s}\,\mathbf c^{KV}_s\)值那一侧：矩阵乘法对加法可分配，\(W^{UV}_i\) 提到求和外面，缓存条目的前 512 维成了“值”
MQA 模式下的稀疏注意力（第 \(i\) 个头）\[\mathbf o_{t,i}=W^{UV}_i\sum_{s\in\mathcal S_t}\softmax_s\!\left(\frac{[\mathbf q^A_{t,i};\mathbf q^R_{t,i}]^\top[\mathbf c^{KV}_s;\mathbf k^R_s]}{\sqrt{d_h+d_h^R}}\right)\mathbf c^{KV}_s\]缩放仍是 \(1/\sqrt{192}\)：吸收只是换了乘法的顺序，点积的数值一个不变。所有 128 个头面对的是同一组条目 \(\{[\mathbf c^{KV}_s;\mathbf k^R_s]\}_{s\in\mathcal S_t}\)，这就是“多查询”（MQA）的意思。研究笔记按 V3.2 附录图与推理代码写出，不是论文编号公式。(14.17)

两种模式的账：算得多，还是读得多

MQA 模式每个键要花多少 FLOPs（每层、一个查询）
(1)\(\displaystyle [\mathbf q^A;\mathbf q^R]^\top[\mathbf c^{KV};\mathbf k^R]:\ 2\times576=1152\)每个头的打分点积长 \(d_c+d_h^R=576\)
(2)\(\displaystyle p\,\mathbf c^{KV}:\ 2\times512=1024\)加权求和的“值”是 512 维
(3)\(\displaystyle \text{每键}:\ 128\times(1152+1024)=278{,}528\)128 个头
(4)\(\displaystyle \frac{278{,}528}{81{,}920}=3.4\)对比 (14.2) 的 MHA 模式
三种“每键”成本（每层、一个查询）\[\begin{aligned}F^{\text{key}}_{\text{MHA}}&=2n_h\big[(d_h+d_h^R)+d_h\big]=81{,}920\\ F^{\text{key}}_{\text{MQA}}&=2n_h\big[(d_c+d_h^R)+d_c\big]=278{,}528\\ F^{\text{key}}_{\text{idx}}&=2H^Id^I=16{,}384\end{aligned}\]与 \(T\) 无关的常数项不计：MQA 模式吸收 \(W^{UK}\) 与乘 \(W^{UV}\) 每 token 每层各约 16.8M FLOPs。(14.18)

MQA 模式每键多算 3.4 倍，为什么解码还要用它？因为解码的瓶颈是读，不是算。用算术强度（每读一个字节做多少次运算）来比较：

解码时两种模式的算术强度（一个查询，按 BF16 计）

MHA 模式：每个头读自己的键（192 个数）和值（128 个数），共 640 字节；做 \(2\times192+2\times128=640\) 次运算。算术强度 1 FLOP/字节。而且这些展开后的键值要么提前存下来（每 token 每层 40,960 个数，MLA 的缓存优势就没了），要么每步临时展开（又是一大笔计算）。

MQA 模式：读一个 576 维的条目，BF16 是 1152 字节，被 128 个头共用，做 278,528 次运算。算术强度 \(278{,}528/1152\approx242\) FLOPs/字节；按 V3.2 的 FP8 缓存格式（656 字节，见 §7）约 425 FLOPs/字节。

同样读一个字节，MQA 模式做的事是 MHA 模式的两百多倍。解码受带宽限制时，前者几乎是白算。这就是“KV 条目必须被多个查询共享”的定量含义。

对 DSA 来说，这个理由更加充分。被选中的 2048 个 token 对每个查询都不一样，散落在整个上下文里；如果用 MHA 模式，要么为全部历史 token 存好展开后的键值，要么每一步为 2048 个被选 token 临时展开。MQA 模式让“按下标取出 2048 个 576 维条目、交给 128 个头一起用”成为可能。FlashMLA 公开的稀疏核，无论预填充还是解码，都是 MQA 模式（键 576 维、值 512 维），在 H800 上预填充可达 640 TFLOPS、解码可达 410 TFLOPS 3。

短序列怎么办：用掩码的 MHA 模式

MQA 模式的代价在预填充时暴露出来。预填充不是带宽受限，而是计算受限，每键多算 3.4 倍是实打实的损失。DSA 报告专门说明：对短序列的预填充，他们专门实现了一个带掩码的 MHA 模式来模拟 DSA，在短上下文下效率更高 7。所谓“模拟”，就是仍用 MHA 模式算全部分数，再把没被选中的位置用 \(-\infty\) 掩掉，数学上与 (14.17) 相同。

多短算“短”？用 (14.18) 可以算出交叉点（笔者的计算）：

稀疏 MQA 模式何时比稠密 MHA 模式便宜（只算核心注意力）
(1)\(\displaystyle F_{\text{DSA,core}}(T)=278{,}528\cdot\min(T,2048)\)稀疏：每个查询最多看 2048 个键，每键按 MQA 模式计价
(2)\(\displaystyle F_{\text{MHA}}(T)=81{,}920\,T\)稠密 MHA 模式，(14.2)
(3)\(\displaystyle 81{,}920\,T^*=278{,}528\times2048\ \Rightarrow\ T^*=6{,}963\)令两者相等

位置不到约 7K 时，稠密的 MHA 模式比稀疏的 MQA 模式还便宜，这时用 MHA 模式加掩码最划算。§7 会看到，论文成本曲线里 V3.2 的预填充成本恰好在约 6.6K 处出现一个拐点；把两者联系起来是笔者的推测，论文没有说明拐点的来源。

开源推理代码并不稀疏

V3.2-Exp 仓库里的推理 demo 实现了 DSA 的数学：预填充走 MHA 模式加掩码，解码走 MQA 模式。但两个分支都是先对全部可见位置算稠密分数，再把未选中的位置加上 \(-\infty\)，结果与稀疏注意力相同，速度却没有任何提升 8。仓库的 README 也把高性能实现指向了另外两个仓库：真正只读、只算被选位置的，是 FlashMLA 里的稀疏注意力核 3；indexer 的打分（它本来就要对全部位置算）则由 DeepGEMM 里的 indexer logits 核加速。读代码时不要以为 demo 能复现论文的速度。demo 的 KV cache 也以 BF16 存放、只“模拟”FP8 精度，部署时用的是 §7 将要看到的 656 字节 FP8 格式。

本页要点
  • MLA 有两种等价算法：MHA 模式先展开再算（每键 81,920 FLOPs），MQA 模式把 \(W^{UK}\) 吸收进查询、让 576 维缓存条目原样当键值（每键 278,528 FLOPs，多 3.4 倍）(14.17)(14.18)。
  • MQA 模式让一个条目被 128 个头共用，解码时算术强度约 242（BF16）到 425（FP8）FLOPs/字节，MHA 模式只有 1。DSA 的稀疏核因此都跑在 MQA 模式上。
  • 短序列预填充反而用带掩码的 MHA 模式：只算核心注意力，稀疏 MQA 模式在位置约 7K 以上才比稠密 MHA 模式便宜。
  • 开源 demo 数学正确但并不稀疏；速度来自 FlashMLA 与 DeepGEMM 的专用核。

DSA（下）：两阶段续训与 KL 对齐

NSA 从预训练的第一步起就是稀疏的。DSA 不是：它从一个已经训练好的稠密模型出发，用续训（continued training）把稀疏注意力“装”进去。起点是 V3.1-Terminus 的基座检查点，上下文已扩到 128K；两个续训阶段的数据分布，与 V3.1-Terminus 做 128K 长上下文扩展时用的数据完全对齐 7。这一页回答“怎么训”：为什么要分两个阶段，那个 KL 散度损失到底在教 indexer 学什么，以及为什么 indexer 和主模型的梯度要彼此隔开。

问题。 刚加上去的 indexer 还什么都没学过（报告没有说明它怎样初始化；新加的模块通常是随机初始化，下面按这个情形来想）。如果立刻切换到稀疏注意力，每个查询选出来的 2048 个 token 近乎随机，模型会突然看不到它依赖的大部分上下文，续训等于从一个被严重破坏的模型开始。反过来，想用语言模型的损失去训练 indexer 也行不通：top-k 是离散的选择，梯度传不到打分上（§4）。所以 indexer 需要一个独立的、在它上岗之前就能学的信号。DSA 的答案是：让它先模仿稠密注意力。

第一阶段：稠密预热

做法。 注意力保持稠密，冻结除 indexer 以外的全部参数，只训练 indexer 7。主模型照常用稠密注意力前向，它的注意力分布此时就是 indexer 的“标准答案”。

目标分布。 报告的做法是：对第 \(t\) 个查询，把主注意力的分数在所有头上求和，再沿序列维做 L1 归一化，得到目标分布 \(p_{t,:}\in\R^t\) 7。这个“求和再归一化”其实就是求平均：

“按头求和再 L1 归一化”就是 128 个头注意力的平均
(1)\(\displaystyle a_{t,i,s}\ge0,\quad \sum_{s=1}^{t}a_{t,i,s}=1\)\(a_{t,i,s}\)：第 \(i\) 个头里查询 \(t\) 对位置 \(s\) 的注意力权重（softmax 的输出），每个头的一行和为 1
(2)\(\displaystyle \sum_{s}\sum_{i=1}^{n_h}a_{t,i,s}=\sum_{i=1}^{n_h}\sum_{s}a_{t,i,s}=n_h\)交换有限求和的次序，每个头贡献 1
(3)\(\displaystyle p_{t,s}=\frac{\sum_ia_{t,i,s}}{\sum_{s'}\sum_ia_{t,i,s'}}=\frac1{n_h}\sum_{i=1}^{n_h}a_{t,i,s}\)L1 归一化 = 除以全部元素之和，即除以 \(n_h=128\)
预热阶段的目标分布\[p_{t,s}=\frac{1}{n_h}\sum_{i=1}^{n_h}a_{t,i,s},\qquad s=1,\dots,t\]\(p_{t,:}\) 是一个合法的概率分布：非负、和为 1。它回答的问题是：“把 128 个头的意见平均起来，查询 \(t\) 在位置 \(s\) 上花了多少注意力？”这一形式是研究笔记由报告的文字描述推出的，报告本身没有写成公式。(14.19)

为什么用所有头的平均，而不是每个头各训一个 indexer？因为 (14.15) 的选择是 128 个头共用的：一个 token 只要有某几个头很需要它，就应当进入被选集合。平均正好反映“全体头加起来对它的需求”。（如果改成对头取最大值再归一化，会更偏向“被某一个头强烈关注”的 token；这是练习 9 的开放问题。）

损失。 用 KL 散度衡量 indexer 的分布和目标分布差多远 7：

预热阶段的 indexer 损失\[\mathcal L^I=\sum_t\KL\!\Big(p_{t,:}\ \Big\Vert\ \softmax\big(I_{t,:}\big)\Big)\]\(\softmax(I_{t,:})\)：把 indexer 对位置 \(1,\dots,t\) 的分数变成分布；求和对批里的全部查询位置进行。报告式 (3)。(14.20)
KL 散度读过 M05 的可以跳过

两个分布 \(p\)、\(q\) 之间的 KL 散度 \(\KL(p\Vert q)=\sum_sp_s\log\frac{p_s}{q_s}\)，读作“用 \(q\) 去近似 \(p\) 要付出的代价”。它总是 \(\ge0\)，当且仅当 \(p=q\) 时为 0（由 Jensen 不等式，证明见 M05 §4）。它不对称：\(\KL(p\Vert q)\ne\KL(q\Vert p)\)。前向 KL（\(p\) 在前）在 \(p_s\) 大而 \(q_s\) 小的地方罚得最重，因为 \(\log(p_s/q_s)\) 会变得很大、又被 \(p_s\) 加权。展开可得 \(\KL(p\Vert q)=\underbrace{-\sum_sp_s\log q_s}_{\text{交叉熵}}-\underbrace{\big(-\sum_sp_s\log p_s\big)}_{p\text{ 的熵}}\)；目标 \(p\) 固定时，最小化 KL 与最小化交叉熵等价。

\(I_{t,:}\) 本身只是一串没有归一化的分数（经过 ReLU 与加权求和），要和概率分布比较，先用 softmax 把它变成分布。这里有一个论文与代码之间的细节：代码里的分数多乘了 \(1/\sqrt{H^Id^I}\)（§4），这个常数不改变 top-k 的排序，却改变 softmax 的“温度”，从而改变 (14.20) 的数值。训练时用的是哪种缩放，论文没有说，训练代码也没有公开。

这个损失在教 indexer 什么？ 看它对分数的梯度最清楚。

KL 损失对 indexer 分数的梯度（一个查询 \(t\)，记 \(q=\softmax(I_{t,:})\)）
(1)\(\displaystyle \KL(p\Vert q)=\sum_sp_s\log p_s-\sum_sp_s\log q_s\)KL 的定义拆成两项；第一项与 \(I\) 无关
(2)\(\displaystyle \log q_s=I_{t,s}-\log\sum_{s'}e^{I_{t,s'}}\)softmax 取对数
(3)\(\displaystyle -\sum_sp_s\log q_s=-\sum_sp_sI_{t,s}+\log\sum_{s'}e^{I_{t,s'}}\)代入，并用 \(\sum_sp_s=1\)
(4)\(\displaystyle \frac{\partial}{\partial I_{t,u}}\Big(\log\sum_{s'}e^{I_{t,s'}}\Big)=\frac{e^{I_{t,u}}}{\sum_{s'}e^{I_{t,s'}}}=q_u\)log-sum-exp 的导数就是 softmax
(5)\(\displaystyle \frac{\partial\,\KL(p\Vert q)}{\partial I_{t,u}}=q_u-p_u\)两项相加
KL 对齐的梯度\[\frac{\partial\mathcal L^I}{\partial I_{t,u}}=\softmax(I_{t,:})_u-p_{t,u}\]与交叉熵对 logits 的梯度“预测减目标”形式相同（M06 §5）。梯度下降会抬高 indexer 低估了的位置（\(q_u<p_u\)），压低高估了的位置。(14.21)
算一次 KL 与梯度

接 §4 的手算例：indexer 分数 \(I=(1,\ 3,\ 1.5,\ 0)\)，\(\softmax(I)=(0.0961,\ 0.7101,\ 0.1584,\ 0.0354)\)。设主注意力有两个头，\(a_1=(0.10,0.70,0.15,0.05)\)，\(a_2=(0.20,0.40,0.35,0.05)\)，由 (14.19)，\(p=(0.15,\ 0.55,\ 0.25,\ 0.05)\)。

KL：\(0.15\ln\frac{0.15}{0.0961}+0.55\ln\frac{0.55}{0.7101}+0.25\ln\frac{0.25}{0.1584}+0.05\ln\frac{0.05}{0.0354}=0.0668-0.1405+0.1140+0.0173=0.0576\)。

梯度 \(\softmax(I)-p=(-0.054,\ +0.160,\ -0.092,\ -0.015)\)：indexer 把 token 2 看得太重（它给了 71%，平均注意力只有 55%），把 token 3 看得太轻。一步梯度下降会压低 \(I_2\)、抬高 \(I_3\) 与其余两个。注意中间那一项是负的：KL 的单项可以为负，只有总和保证非负。

前向 KL 与“漏选”。 (14.20) 是 \(p\) 在前的前向 KL。按上面的前置框，它在“主注意力很看重、indexer 却给低分”的位置罚得最重。对 DSA，这恰好是代价最大的错误：没被选进 \(\mathcal S_t\) 的 token，主注意力一个字也看不到，而且（下面会看到）第二阶段没有任何机制能把它捡回来。反方向的错误，即 indexer 高估了一个不太重要的 token，只是浪费了 2048 个名额中的一个。所以前向 KL 的偏好与 top-k 的风险是一致的：它逼 indexer 的分布“铺开”去盖住目标分布的每一处质量，而不是只盯住最高的那个峰（两个方向的对比见 M05 §5）。这是笔者的解读，报告没有解释为什么选这个方向。

超参数。 学习率 \(10^{-3}\)；只训 1000 步，每步 16 条 128K token 的序列，共 2.1B token 7。学习率是下一阶段的 137 倍。报告没有解释为什么；一个自然的理解（笔者推测）是：这时只有 0.87B 参数的 indexer 在动、主模型是冻结的，大学习率只影响一个从零学起的小网络，不会破坏已经训好的主模型。

第二阶段：稀疏训练

做法。 打开 top-k 选择，优化全部参数，让模型适应 DSA 的稀疏模式 7。indexer 继续用 KL 对齐，但只在被选中的集合上：

稀疏阶段的 indexer 损失\[\mathcal L^I=\sum_t\KL\!\Big(p_{t,\mathcal S_t}\ \Big\Vert\ \softmax\big(I_{t,\mathcal S_t}\big)\Big),\qquad \mathcal S_t=\big\{s\ \big|\ I_{t,s}\in\operatorname{Top\text{-}k}(I_{t,:})\big\}\]\(p_{t,\mathcal S_t}\)：主注意力（此时本来就只在 \(\mathcal S_t\) 上计算）的头平均分布；\(I_{t,\mathcal S_t}\)：indexer 在被选位置上的分数。报告式 (4)。\(p_{t,\mathcal S_t}\) 是否在 \(\mathcal S_t\) 上重新归一化，报告没有写明；稀疏阶段主注意力本来只在 \(\mathcal S_t\) 上做 softmax，天然归一，本课按归一化理解，即 \(p_{t,s}=\frac1{n_h}\sum_i\tilde a_{t,i,s}\)，\(\tilde a_{t,i,s}=a_{t,i,s}/m_{t,i}\) 是第 \(i\) 个头在 \(\mathcal S_t\) 内的 softmax 权重（§1 的推导），\(m_{t,i}\) 是这个头落在 \(\mathcal S_t\) 内的稠密权重。它一般不等于把 (14.19) 的稠密平均截到 \(\mathcal S_t\) 再归一化：后者等于 \(\sum_i\frac{m_{t,i}}{\sum_{i'}m_{t,i'}}\tilde a_{t,i,s}\)，相当于按 \(m_{t,i}\) 给各头加权；除非各头的 \(m_{t,i}\) 相同（或各头的 \(\tilde a_{t,i,:}\) 恰好一样），两者不相等（图 14.11 有一个数例）。(14.22)

梯度分离。 报告写道：把 indexer 的输入从计算图中分离（detach），单独优化；indexer 的训练信号只来自 \(\mathcal L^I\)，主模型的优化只依据语言模型损失 7。这句话有两层意思：

  1. 语言模型损失不训练 indexer。 这本来也做不到：top-k 不可导，语言模型损失对 \(I\) 没有梯度。
  2. \(\mathcal L^I\) 不训练主模型。 如果不 detach，\(\mathcal L^I\) 的梯度会穿过 indexer 的输入（\(\mathbf h_t\)、\(\mathbf c^Q_t\)）流进主模型，主模型会被推着去改变自己的表示，好让 indexer 更容易模仿。那样主模型就在同时优化两个目标。分离之后，主模型只管语言建模，indexer 只管模仿。至于为什么要这样设计，报告只陈述了做法，“避免主模型被辅助目标拉偏”是笔者的解读；它恰好对应 NSA 放弃辅助损失路线时给出的理由：辅助损失常常损害模型性能（§3）。

只在 \(\mathcal S_t\) 上对齐意味着什么？ 由 (14.21)，softmax 只在 \(\mathcal S_t\) 内计算时，梯度也只落在 \(\mathcal S_t\) 内的分数上，而且这些分量之和是 \(\sum_{u\in\mathcal S_t}(q_u-p_u)=1-1=0\)：把 \(\mathcal S_t\) 内的分数同时加上一个常数，损失一点不变。于是第二阶段的 KL 只能调整已选中的 2048 个 token 之间的相对大小，既不会把它们整体抬到未选 token 之上，也没有任何一项去抬高一个落在 \(\mathcal S_t\) 之外、却本该被选中的 token：主注意力看不到它，\(p\) 里也就没有它。（indexer 的参数是所有位置共用的，更新参数会顺带改变未选 token 的分数，但没有哪一项损失专门朝“找回漏选”的方向推。）第二阶段能不能选对，很大程度上依赖第一阶段在全部位置上学到的“召回”能力，以及主模型在稀疏训练中学会把重要信息放在 indexer 容易找到的地方。这是笔者由公式得出的分析，报告没有讨论。

超参数。 学习率 \(7.3\times10^{-6}\)，每个查询选 2048 个键值 token；主模型与 indexer 一起训练 15000 步，每步 480 条 128K token 的序列，共 943.7B token 7。

用 token 数反推“128K”到底是多少
(1)\(\displaystyle 15{,}000\times480\times131{,}072=943{,}718{,}400{,}000\approx943.7\text{B}\)取 \(128\text{K}=2^{17}=131{,}072\)，与报告一致

算总账

前面五页把 NSA 与 DSA 的每个零件拆开讲了。这一页把它们装回去，用 DeepSeek-V3 的真实维度算四笔账：计算（FLOPs）、存储与读取（字节）、论文公布的服务成本、模型质量。每一笔都要回答同一个问题：DSA 在哪里省了、省多少，在哪里没省甚至更贵。

计算：一个查询的 FLOPs

把 (14.18) 的三种每键成本组合起来。稠密注意力每个查询面对 \(T\) 个键；DSA 的核心注意力最多面对 \(k=2048\) 个键（MQA 模式计价），indexer 面对全部 \(T\) 个键：

DSA 每个查询的注意力 FLOPs（每层）\[F_{\text{DSA}}(T)=\underbrace{278{,}528\cdot\min(T,k)}_{\text{核心注意力},\ O(k)}+\underbrace{16{,}384\cdot T}_{\text{indexer},\ O(T)},\qquad k=2048\]对比稠密：预填充按 MHA 模式 \(81{,}920\,T\)，解码按 MQA 模式 \(278{,}528\,T\)。与 \(T\) 无关的项都不计入：MHA 模式把每个 token 展开成键值（乘 \(W^{UK}\)、\(W^{UV}\)）与 MQA 模式的吸收乘法，每 token 每层都是 \(2\times16.8\)M FLOPs，两边一样多；DSA 另有 indexer 的三个投影，每 token 每层约 \(2\times13.96\text{M}=27.9\)M FLOPs，只相当于稠密 MHA 模式约 341 个键的成本，这里也略去。(14.23)

交叉点。令 (14.23) 与稠密成本相等（\(T>k\) 时核心项是常数）：

DSA 从哪个长度开始比稠密省
(1)\(\displaystyle F^{\text{key}}_{\text{dense}}\,T^*=278{,}528\,k+16{,}384\,T^*\)\(T^*>k\) 时 DSA 核心项是常数
(2)\(\displaystyle T^*=\frac{278{,}528\,k}{F^{\text{key}}_{\text{dense}}-16{,}384}\)移项
(3)\(\displaystyle T^*_{\text{decode}}=\frac{278{,}528\times2048}{278{,}528-16{,}384}=2{,}176\)解码：稠密也用 MQA 模式，代入 \(F^{\text{key}}_{\text{dense}}=278{,}528\)
(4)\(\displaystyle T^*_{\text{prefill}}=\frac{278{,}528\times2048}{81{,}920-16{,}384}=8{,}704\)预填充：稠密用 MHA 模式，代入 \(F^{\text{key}}_{\text{dense}}=81{,}920\)
(5)\(\displaystyle 16{,}384\,T=278{,}528\times2048\ \Rightarrow\ T=34{,}816\)indexer 追上核心注意力：此后打分比精读还贵
交叉点的一般式\[T^*=\frac{F^{\text{key}}_{\text{MQA}}\cdot k}{F^{\text{key}}_{\text{dense}}-F^{\text{key}}_{\text{idx}}}\]分母说明了 indexer 为什么必须便宜：若 \(F^{\text{key}}_{\text{idx}}\) 接近稠密注意力的每键成本，交叉点会跑到无穷远，稀疏永远不划算。式子成立有两个前提：\(F^{\text{key}}_{\text{dense}}>F^{\text{key}}_{\text{idx}}\)（否则 DSA 在任何长度都更贵），以及算出的 \(T^*>k\)（推导用了“核心项已封顶”）。本课两种口径都满足：\(2176>2048\)，\(8704>2048\)。(14.24)
整段预填充与全模型占比

整段。 对位置 \(1,\dots,T\) 逐个把 (14.23) 加起来（核心项在 \(t\le2048\) 时按 \(278{,}528\,t\) 计，indexer 项 \(16{,}384\,t\) 对每个位置都计）：每层 4K 时稠密 MHA 0.687 TFLOPs，DSA 1.890 TFLOPs，DSA 贵 2.75 倍；32K 时 43.98 对 26.90，DSA 省 1.63 倍；128K 时 703.7 对 214.9，省 3.27 倍。短序列预填充改用带掩码的 MHA 模式（§5），就是为了不吃 4K 那一栏的亏。

全模型占比。 仍以 74 GFLOPs 作为“其余部分”：稠密时注意力在 4K、32K、128K 占 21.7%、68.9%、89.8%；DSA（含 indexer）占 34.4%、47.7%、69.1%。4K 时 DSA 反而占比更高；128K 时每 token 的注意力从 655 GFLOPs 降到 166 GFLOPs，但仍是大头，其中 131 GFLOPs 是 indexer。

字节：存的变多，读的变少

存储。DSA 不能丢掉任何一个 MLA 条目：今天没被选中的 token，下一个查询可能就要选它。它还要为每个 token 额外存一个 indexer 键。V3.2 部署时的 KV cache 格式是每 token 每层 656 字节：512 个 FP8（内容部分）+ 4 个 FP32 缩放因子（每 128 个值一个）+ 64 个 BF16（RoPE 部分，为了精度不量化）3；indexer 键是 128 个 FP8 加 1 个 FP32 缩放，132 字节 8。

读取。解码一步，稠密注意力要读全部 \(T\) 个条目；DSA 读全部 \(T\) 个 indexer 键，再读被选中的 2048 个条目：

解码一步、每层要读的字节\[\text{Bytes}_{\text{dense}}(T)=656\,T,\qquad \text{Bytes}_{\text{DSA}}(T)=656\cdot\min(T,k)+132\,T\]若稠密核读 BF16 缓存，则 \(\text{Bytes}_{\text{dense}}=1152\,T\)。只计 KV 与索引键，不计权重。（本课的 \(B\) 已用来记区间 \(B^{\text{cmp}}_b\) 与核的块行数 \(B_k\)，这里写全称以免混淆。）(14.25)
128K 请求的字节账

存。 61 层、131,072 个 token：FP8 格式 \(656\times61\times131{,}072\) 字节 \(=4.88\) GiB；加上 indexer 键 \((656+132)\times61\times131{,}072=5.87\) GiB，多 20.1%。作为对照，BF16 的 MLA 缓存是 8.58 GiB。FlashMLA 的博客给出的 128K 单请求 KV 大小是 \(576\times2\times62\times128\times1024\) 字节 \(=8.72\) GiB 3，那是按 62 层、每数 2 字节算的（把 62 理解为 61 层加 1 个 MTP 层、把 2 理解为 BF16，是笔者的解读，博客只给了算式）。

读。 位置 128K 解码一步、每层：稠密 FP8 读 \(656\times131{,}072=86.0\) MB，DSA 读 \(656\times2048+132\times131{,}072=18.6\) MB，降到 1/4.6；若与读 BF16 的稠密核相比（151.0 MB），降到 1/8.1。位置 32K 时分别是 3.8 倍与 6.7 倍。

短序列。 令 \(656\,T=656\times2048+132\,T\)，得 \(T\approx2564\)：短于此，DSA 读得比稠密（FP8）还多，因为它多读了 indexer 键。FlashMLA 博客报告，他们的 FP8 稀疏解码核在长度约 3000 时耗时与稠密解码核相当 3。这个 3000 不能用来验证 2564：博客比较的只是两个注意力核（不含 indexer），稠密核读的是 BF16 缓存，而且稀疏核受反量化限制而不是带宽限制（见下文）。两个数只是量级相同。

FlashMLA 的博客还解释了稀疏解码核为什么不是算力受限：一个线程块处理 64 个头时，每个 KV token 的矩阵乘在 H800 的一个 SM 上约需 34 个时钟周期，而把它从 FP8 反量化约需 50 个周期，核实际上被反量化卡住了（dequantization-bound）；他们用两个线程块协作分摊反量化，把性能从 250 TFLOPS 提到 410 TFLOPS 3。省下了读取，瓶颈就搬到了下一个地方，这是本课反复出现的模式。

练习 1 · MLA 为什么没有改变平方，稀疏又会偏多少

（a）第 9 课的 MLA 把每个 token 每层的缓存从“128 个头各一对键值”压成 576 个数。为什么它没有把长上下文注意力的 \(O(T^2)\) 变成别的形状？DSA 改变的是什么？（b）位置 \(t=32{,}768\) 的某个头，被选中的 2048 个 token 拿走了它 80% 的注意力权重。按 §1 的误差上界，稀疏输出与稠密输出最多相差多少（用最长值向量的长度 \(v_{\max}\) 表示）？如果这个头的权重完全均匀呢？

看答案

（a）注意力的账是“条目数 × 每个条目的成本”。MLA 减小的是每个条目的大小（字节）和读取成本，条目数仍是 \(T\)：位置 \(T\) 的查询仍要与全部 \(T\) 个条目打分、加权，一个查询 \(O(T)\)、整段 \(O(T^2)\)。DSA 改变的是核心注意力面对的条目数：从 \(T\) 降到固定的 \(k=2048\)，核心注意力变成一个查询 \(O(k)\)、整段 \(O(Tk)\)。但它新增的 indexer 仍对全部 \(T\) 个位置打分，所以严格说整段仍有一个 \(O(T^2)\) 项，只是每键常数是核心注意力的 1/17。

（b）丢掉的权重 \(\varepsilon=1-0.80=0.20\)，上界 \(2\varepsilon\,v_{\max}=0.40\,v_{\max}\)。权重完全均匀时，2048 个位置只拿走 \(2048/32{,}768=6.25\%\)，\(\varepsilon=0.9375\)，上界 \(1.875\,v_{\max}\)：几乎没有保证。上界只取决于被丢掉的权重，与 \(t\) 本身无关；长上下文之所以危险，是因为同样的 \(k\) 在更长的前文里更容易只拿到一小部分权重。

练习 2 · 短上下文上的 DSA

（a）前文不到 2048 个 token 时，DSA 的输出与稠密注意力有什么关系？（b）有人发现 V3.2-Exp 在一个只有 1000 token 的任务上分数变了，这个变化可能来自哪里？（c）为什么短序列预填充要用“带掩码的 MHA 模式”？

看答案

（a）推理代码取 \(\min(k,\text{当前长度})\) 个 token，\(t\le2048\) 时全部选中，(14.15) 与稠密注意力 (14.1) 在数学上完全相同，只是多算了一遍 indexer。

（b）不可能来自“少看了 token”。只能来自续训（943.7B token 的稀疏训练同样更新了主模型的全部参数）与后训练，以及数值实现的差别（例如 FP8 缓存格式）。

（c）预填充是计算受限的。MQA 模式每键 278,528 FLOPs，MHA 模式 81,920；只算核心注意力，稀疏 MQA 模式要到 \(T>6{,}963\) 才比稠密 MHA 模式便宜，计入 indexer 要到 8,704。更短的序列用 MHA 模式把全部分数算出来、再用 \(-\infty\) 掩掉未选位置，数学上等价、算得更少。

练习 3 · 共享与梯度分离

（a）NSA 和 DSA 都要求“一组查询头共享同一批被选的 KV”。分别说出两者的“一组”是什么，并解释若不共享，解码时的读取量会怎样。（b）DSA 为什么要把 indexer 的输入 detach？分别说明“语言模型损失不训练 indexer”与“\(\mathcal L^I\) 不训练主模型”两层含义。

看答案

（a）NSA：一个 GQA 组内的 16 个查询头（它们本来就共用一份键值缓存），做法是把 16 个头的块分数相加再统一取前 16 块 (14.11)。DSA：一个查询 token 的全部 128 个头，做法是 indexer 为每个查询 token 只产生一组 top-2048，并在 MLA 的 MQA 模式下让 576 维条目同时充当 128 个头的键和值。若不共享，同一份缓存要按各头选择的并集读取：NSA 在 64K 时最坏从 16 块涨到 \(3+16\times13=211\) 块（1024 → 13,504 个 token）；各头独有的块只被一个头使用，这部分读取的算术强度从约 16 降到约 1 FLOP/字节。

（b）第一层：top-k 是离散选择，语言模型损失对 indexer 分数本来就没有梯度，indexer 只能靠 \(\mathcal L^I\) 学习。第二层：如果不 detach，\(\mathcal L^I\) 的梯度会流进 indexer 的输入 \(\mathbf h_t\)、\(\mathbf c^Q_t\)，推动主模型改变表示来迎合 indexer，相当于给主模型加了一个辅助目标；detach 后主模型只按语言模型损失优化。NSA 放弃辅助损失路线的理由正是辅助损失常常损害模型性能。

计算题

练习 4 · NSA 的解码读取量

用 \(\ell_c=32\)、\(\delta_c=16\)、\(\ell_s=64\)、\(n_s=16\)、\(w=512\)。（a）64K 上下文解码一步，NSA 最多读多少个 token？期望加速和稀疏率各是多少？（b）为什么论文把它叫“期望加速”？（c）复核 LongBench 的 2560 预算：对 \(t=32,\dots,32{,}768\)，\(N_t\) 的平均约是多少？给出心算版本。

看答案

（a）压缩按表 4 取 \(65{,}536/16=4096\)（论文 §5.2 的上界写作 \(\lfloor(65{,}536-32)/16\rfloor=4094\)；按 (14.6) 数元素个数是 \(4094+1=4095\)），选择 \(16\times64=1024\)，窗口 512，合计约 5632。期望加速 \(65{,}536/5632=11.6\)；稀疏率 \(5632/65{,}536=8.6\%\)。

（b）它是按访存量之比推出来的：解码受带宽限制时，时间大致与读取量成正比。它没有计入核的启动开销、选择本身的计算、访存效率的差别等，论文表 4 的行名就是 “Expected Speedup”，不是计时结果。

（c）精确平均约 2541（2540.96）。心算：压缩项 \(\approx t/16\)，在 \(t\) 均匀分布于 0 到 32K 时平均 \(\approx16{,}384/16=1024\)；选择 1024、窗口 512 几乎对所有 \(t\) 都取满；合计 \(\approx2560\)。精确值略小，是因为开头处选择与窗口取不满、压缩项是向下取整。

练习 5 · 128K 到底是多少

DSA 的稀疏训练是 15000 步、每步 480 条 128K 的序列，报告写共 943.7B token。（a）分别按 128K = 131,072 与 128,000 计算总 token 数，判断报告用的是哪一个。（b）预热阶段 1000 步 × 16 条 × 128K 是多少？两阶段 token 数之比、学习率之比各是多少？

看答案

（a）\(15{,}000\times480\times131{,}072=943{,}718{,}400{,}000\approx943.7\)B，与报告一致；\(15{,}000\times480\times128{,}000=921.6\)B，不一致。报告的 128K 是 \(2^{17}=131{,}072\)。

（b）\(1000\times16\times131{,}072=2{,}097{,}152{,}000\approx2.1\)B。token 数之比 \(943.7/2.097=450\)；学习率之比 \(10^{-3}/(7.3\times10^{-6})\approx137\)。预热只占两阶段合计的 0.22%。

练习 6 · 每个查询的 FLOPs 与交叉点

（a）推导 MHA 模式与 MQA 模式每个键的 FLOPs，以及 indexer 每个键的 FLOPs。（b）位置 \(T=65{,}536\)：分别求稠密 MHA 模式、稠密 MQA 模式、DSA 合计每层每查询的 FLOPs，以及两个比值。（c）求 indexer 的 FLOPs 超过 DSA 核心注意力的位置。

看答案

（a）MHA 模式：每头打分 \(2\times192\)、加权 \(2\times128\)，共 640；128 头 81,920。MQA 模式：每头打分 \(2\times576\)、加权 \(2\times512\)，共 2176；128 头 278,528。indexer：\(2\times64\times128=16{,}384\)。

（b）稠密 MHA：\(81{,}920\times65{,}536=5.369\times10^9\)。稠密 MQA：\(278{,}528\times65{,}536=1.825\times10^{10}\)。DSA：\(278{,}528\times2048+16{,}384\times65{,}536=5.704\times10^8+1.074\times10^9=1.644\times10^9\)。MHA/DSA = 3.27，MQA/DSA = 11.10。

（c）\(16{,}384\,T=278{,}528\times2048\Rightarrow T=34{,}816\)。

练习 7 · DSA 的缓存变大还是变小

（a）每 token 每层，V3.2 的 FP8 KV 条目与 indexer 键各多少字节？DSA 比不带 indexer 多存百分之几？（b）一个 128K 的请求（61 层）总共存多少 GiB？（c）位置 128K 解码一步，每层读多少字节？和稠密（FP8）相比呢？

看答案

（a）KV 条目 \(512\times1+4\times4+64\times2=656\) 字节；indexer 键 \(128\times1+4=132\) 字节；多 \(132/656=20.1\%\)。

（b）\(656\times61\times131{,}072=5.245\times10^9\) 字节 \(=4.88\) GiB；加 indexer 键 \(788\times61\times131{,}072=6.300\times10^9\) 字节 \(=5.87\) GiB。

（c）DSA：\(656\times2048+132\times131{,}072=1{,}343{,}488+17{,}301{,}504=18{,}644{,}992\) 字节 \(\approx18.6\) MB。稠密 FP8：\(656\times131{,}072=85{,}983{,}232\approx86.0\) MB。比值 4.61。结论：DSA 省读取、不省存储。

练习 8 · 读成本曲线

用图 14.15 的顶点：预填充 Terminus \((0,0.0529)\to(128,0.6658)\)，V3.2 \((0,0.0611)\to(6.589,0.0999)\to(128,0.1871)\)；解码 Terminus \((0,0.0705)\to(128,2.1543)\)，V3.2 \((0,0.0952)\to(2.056,0.1457)\to(101.607,0.2274)\to(128,0.2491)\)（横轴单位 K，纵轴美元/百万 token）。（a）128K 处的两个倍数。（b）预填充的交叉点。（c）为什么 0–128K 的平均倍数（预填充 2.56）比 128K 处（3.56）小？

看答案

（a）预填充 \(0.6658/0.1871=3.56\)；解码 \(2.1543/0.2491=8.65\)。

（b）Terminus：\(0.0529+0.004788x\)（斜率 \((0.6658-0.0529)/128\)）。V3.2 在 6.589K 之后：\(0.0999+0.000718(x-6.589)=0.0952+0.000718x\)（斜率 \((0.1871-0.0999)/121.411\)）。令两者相等：\(0.0529+0.004788x=0.0952+0.000718x\)，\(0.004070x=0.0423\)，\(x\approx10.4\)K。它大于 6.589，确实落在 V3.2 的第二段上。第一段不会有交点：在 \(x=0\) 与 \(x=6.589\) 两端，V3.2 都比 Terminus 贵（\(0.0611>0.0529\)，\(0.0999>0.0529+0.004788\times6.589=0.0844\)），两条都是直线，所以整段上都更贵。

（c）平均要把所有位置都算进去；位置越靠前两者越接近，10.4K 以前 V3.2 甚至更贵。平均值被前段拉低了。实际请求的长度分布决定了真实的节省幅度。

推导题

练习 9 · 目标分布与“取最大”

（a）证明“把各头注意力按头求和、再沿序列维 L1 归一化”等于各头注意力的算术平均。（b）如果改成“按头取最大值、再归一化”，目标分布会偏向哪类 token？对 top-k 选择可能有什么利弊？（开放题）

看答案

（a）每个头的一行满足 \(\sum_sa_{t,i,s}=1\)。按头求和后行和为 \(\sum_s\sum_ia_{t,i,s}=\sum_i1=n_h\)。L1 归一化即除以 \(n_h\)，得 \(p_{t,s}=\frac1{n_h}\sum_ia_{t,i,s}\)。

（b）取最大会偏向“被某一个头强烈关注”的 token：只要有一个头给它很高的权重，即使其余 127 个头都不看它，它的目标值也高。利：DSA 的 top-k 被 128 个头共用，一个 token 只要有一个头真正需要，就应该被选进来，取最大更贴近“别漏掉任何一个头的需要”。弊：对单个头的噪声更敏感，也不再是一个自然的概率混合（各头的最大值加起来不等于 1，只能靠事后归一化）。两种目标的差别可以很大：一个只被某一个头强烈关注的 token，在平均法里至多分到约 \(1/n_h=1/128\) 的份量，在取最大法里却可能排在最前面；反过来，被所有头中等程度关注的 token，在取最大法里相对变弱。报告选择了平均法，没有讨论其他做法。

练习 10 · KL 的梯度与方向

（a）推导 \(\partial\KL\big(p\,\Vert\,\softmax(I)\big)/\partial I_u=\softmax(I)_u-p_u\)。（b）对 §6 的例子 \(p=(0.15,0.55,0.25,0.05)\)、\(I=(1,3,1.5,0)\)，计算反向 KL \(\KL(\softmax(I)\Vert p)\)，与前向 KL 0.0576 比较。（c）说明为什么对 top-k 选择来说前向 KL 更合适。

看答案

（a）见 §6 的推导：\(\KL=\sum p\log p-\sum_sp_sI_s+\log\sum_se^{I_s}\)，第一项与 \(I\) 无关，第二项对 \(I_u\) 的导数是 \(-p_u\)，第三项是 \(\softmax(I)_u\)。

（b）\(q=(0.0961,0.7101,0.1584,0.0354)\)。\(\KL(q\Vert p)=0.0961\ln\frac{0.0961}{0.15}+0.7101\ln\frac{0.7101}{0.55}+0.1584\ln\frac{0.1584}{0.25}+0.0354\ln\frac{0.0354}{0.05}\) \(=-0.04279+0.18142-0.07226-0.01225=0.05412\approx0.0541\)（多保留一位，是为了让各项相加与总和对得上）。两个方向的数值接近，但对不同错误的惩罚方式不同。

（c）前向 KL 以 \(p\) 加权：\(p_s\) 大而 \(q_s\) 小的位置（indexer 漏看了主注意力看重的 token）罚得最重，对应 top-k 里代价最大、而且事后无法挽回的“漏选”。反向 KL 以 \(q\) 加权，更罚“indexer 看重、主注意力不看”的位置，那只是浪费一个名额。这是笔者的解读，报告没有解释方向的选择。

练习 11 · 重叠权重的一般式

设 \(\ell_c=2\delta_c\)、\(\ell_s=4\delta_c\)（NSA 的取值），选择块 \(j\) 覆盖键 \([4\delta_cj+1,\ 4\delta_c(j+1)]\)，压缩块 \(b\) 覆盖 \([\delta_cb+1,\ \delta_cb+2\delta_c]\)。（a）哪些压缩块与选择块 \(j\) 重叠？权重（重叠长度 / \(\delta_c\)）各是多少？（b）设 \(j\ge1\)，且选择块 \(j\) 后面至少已有 \(\delta_c\) 个键（压缩块 \(4j+3\) 已经凑满）。证明所有权重之和等于 \(\frac{\ell_s}{\delta_c}\cdot\frac{\ell_c}{\delta_c}=8\)，并给出一个不用逐块计算的理由；再说明这两个条件不满足时会怎样。

看答案

（a）完整落在里面的是 \(b=4j,4j+1,4j+2\)（区间 \([4\delta_cj+1,\,4\delta_cj+2\delta_c]\) 等），权重 2；一半在里面的是 \(b=4j-1\)（右半）和 \(b=4j+3\)（左半），权重 1。其余不重叠。权重 \((1,2,2,2,1)\)，和为 8。

（b）交换求和次序：\(\sum_b\abs{B^{\text{cmp}}_b\cap B^{\text{slc}}_j}=\sum_{x\in B^{\text{slc}}_j}\#\{b:\ x\in B^{\text{cmp}}_b\}\)，也就是把“每个键被几个压缩块覆盖”加起来。键 \(x\) 属于压缩块 \(b\) 当且仅当 \(\delta_cb<x\le\delta_cb+2\delta_c\)，即 \(\frac{x}{\delta_c}-2\le b<\frac{x}{\delta_c}\)；长为 2 的半开区间里恰好有 2 个整数。两个条件保证这 2 个块都存在：\(j\ge1\) 使 \(x>\delta_c\)，较小的那个 \(b\ge0\)；选择块后面已有 \(\delta_c\) 个键，使最大的 \(b=4j+3\) 已经凑满。于是重叠长度之和 \(=\ell_s\times2\)，除以 \(\delta_c\) 得 \(\frac{\ell_s}{\delta_c}\cdot\frac{\ell_c}{\delta_c}=4\times2=8\)。一般地（\(\delta_c\) 整除 \(\ell_c\)），每个键被 \(\ell_c/\delta_c\) 个压缩块覆盖，和就是 \(\frac{\ell_s}{\delta_c}\cdot\frac{\ell_c}{\delta_c}\)；原文式 (9) 的二重求和正好有这么多项，与此一致。

条件不满足时：\(j=0\) 时开头 16 个键只被压缩块 0 覆盖（没有块 \(-1\)），权重和是 7；选择块紧挨当前位置、压缩块 \(4j+3\) 还没凑满 32 个键时，它还不存在，权重和少 1，离当前位置更近时还会更少。

练习 12 · Hadamard 旋转

设 \(\mathcal H=H_{128}/\sqrt{128}\)，\(H_{128}\) 是元素为 \(\pm1\) 的对称 Hadamard 矩阵，\(H_{128}H_{128}^\top=128I\)。（a）证明 \((\mathcal H\mathbf q)\cdot(\mathcal H\mathbf k)=\mathbf q\cdot\mathbf k\)，从而 indexer 的分数不因旋转而改变。（b）一个向量只有一个分量为 40、其余为 0，旋转后每个分量是多少？一块里的最大绝对值从多少变成多少？再换一个真实些的向量：128 个标准正态数，其中一个改成 40。按“每 128 个数共用一个缩放因子”量化时，比较旋转前后的误差要注意什么？为什么旋转对 INT8（等间距，步长 = 最大绝对值 ÷ 127）帮助很大，对 FP8 E4M3 却没有帮助、甚至更差？（c）旋转后的向量长度是多少？

看答案

（a）\(\mathcal H^\top\mathcal H=\frac1{128}H_{128}^\top H_{128}=\frac1{128}H_{128}H_{128}^\top=I\)（对称）。于是 \((\mathcal H\mathbf q)^\top(\mathcal H\mathbf k)=\mathbf q^\top\mathcal H^\top\mathcal H\mathbf k=\mathbf q^\top\mathbf k\)。

（b）设非零分量在第 \(c\) 个位置，则 \(\mathcal H\mathbf x\) 的第 \(r\) 个分量是 \(\frac{1}{\sqrt{128}}H_{r,c}\cdot40=\pm3.54\)，128 个分量绝对值全相等；最大绝对值从 40 降到 3.54。这个特例本身在两种格式下都没有误差（旋转前后，缩放后的数都恰好落在格点上），区别出现在真实向量上。

先说比较的口径：旋转后量化的误差要乘回 \(\mathcal H^\top\)、在原坐标里和原向量比。旋转后的每个坐标都混进了离群值，数值在 3.5 左右，拿它们的相对误差去和原来那些绝对值 1 左右的分量比，是在比两样东西。下面的百分数都是“其余 127 个普通分量在原坐标里的相对误差中位数”（笔者用 Python 复算，1000 次抽样，见 §4 的例子）。

INT8 的步长是最大绝对值 ÷ 127。离群值 40 让步长变成 \(40/127=0.315\)，而标准正态分量的绝对值中位数只有 0.67，只分到两三个刻度：相对误差的中位数约 11%，绝对值小于半个步长（0.157）的约 1/8 直接变成 0。旋转后最大值约 6，步长约 0.05，缩小到约 1/6.5；误差转回原坐标后约 1.4%。

FP8 E4M3 是浮点格式，正规区跨 28,672 倍，40 倍的悬殊不会把任何分量挤出正规区；每个数的相对误差不超过 6.25%，不旋转时中位数约 2.2%。浮点数的误差与每个数自身的大小成正比：不旋转时，离群值的误差只落在它自己身上（40 恰好映到 448，误差为 0），小分量只承担自己那份小误差；旋转后每个坐标都在 3.5 左右，各带约 0.08 的舍入误差，乘回 \(\mathcal H^\top\) 后摊到所有分量上，中位数反而升到约 10%。所以在这个例子里，旋转只对等间距的格式有好处。DeepSeek 为什么在 FP8 打分前旋转，代码没有注释，“为了量化”只是笔者的推测。

（c）正交变换保长度：\(\norm{\mathcal H\mathbf x}^2=\mathbf x^\top\mathcal H^\top\mathcal H\mathbf x=\norm{\mathbf x}^2\)，长度仍是 40；验算 \(128\times3.54^2\approx1600=40^2\)。

DeepSeek-V3 Technical Report
DeepSeek-AI (2024). arXiv:2412.19437（读的是 v2）
发现　给出 MLA 的公式与 V3 维度：61 层、\(d=7168\)、128 头、\(d_h=128\)、\(d_h^R=64\)、\(d_c=512\)、\(d_c'=1536\)，每 token 激活 37B 参数。

https://arxiv.org/abs/2512.02556

FlashMLA（GitHub 仓库 README）与博客 “A Deep Dive Into The Flash MLA FP8 Decoding Kernel on Hopper” · 制品
DeepSeek-AI (2025). GitHub 仓库与文档，稀疏核发布于 2025-09-29
发现　稀疏 prefill 与稀疏 decode 核都在 MQA 模式下运行（键 576 维、值 512 维）；V3.2 的 FP8 KV cache 每 token 656 字节；稀疏解码核在 H800 上达 410 TFLOPS，在长度约 3000 时与稠密解码核耗时相当。
本课为何引用　它把“省多少”落到真实内核与字节格式上，是本课 KV 字节账与“短序列稀疏不划算”讨论的依据。

https://github.com/deepseek-ai/FlashMLA

Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention
Yuan, J., Gao, H., Dai, D., Luo, J., Zhao, L., Zhang, Z., Xie, Z., Wei, Y. X., Wang, L., Xiao, Z., Wang, Y., Ruan, C., Zhang, M., Liang, W., Zeng, W. (2025). ACL 2025 (Long Papers), pp. 23078–23097; arXiv:2502.11089（读的是 v2，节号、式号、图号按 arXiv v2）
发现　提出压缩、块选择、滑动窗口三分支加门控的原生可训练稀疏注意力；27B 模型上通用基准与 LongBench 的平均分不低于全注意力；64K 时注意力核前向 9.0 倍、反向 6.0 倍，解码按访存量推算的期望加速 11.6 倍。
本课为何引用　它确立了“KV 条目必须被多个查询头共享、按硬件友好的方式选择”的原则，DSA 直接引用它来论证为什么在 MLA 的 MQA 模式上实现；它试过又放弃的“KL 监督的打分器”与“稠密预热后切换”，后来在 DSA 里以另一种形式回归。

https://aclanthology.org/2025.acl-long.1126/

DeepSeek-AI (2025). Hugging Face 仓库 deepseek-ai/DeepSeek-V3.2-Exp（README 与 GitHub 同名仓库相同）；indexer RoPE 布局修复提交于 2025-11-17

本课为何引用　论文没有给出 indexer 的头数与维度，本课的规格、参数核对与“论文与代码的差别”都依赖这份代码；“首次实现细粒度稀疏注意力”的说法也只出现在它的 README 里。

https://huggingface.co/deepseek-ai/DeepSeek-V3.2-Exp
