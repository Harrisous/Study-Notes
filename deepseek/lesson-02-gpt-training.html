这一课回答什么问题

上课之前，先问大家一件事。你用手机打字的时候，有没有留意过输入法的“联想”：刚打出“今天天气”，候选栏里就冒出“很好”“怎么样”“真热”。它并没有读懂你的心思，它只是见过很多人打过的字，知道“今天天气”后面最常跟着什么。

GPT 做的是同一件事：读了前文，猜下一个 token。区别在规模：它读过几千亿个 token，猜的时候看的是前面整整几千个 token。第 1 课我们把这台机器拆开了：token 进去，logits 出来。可机器里那一亿多个参数，一开始全是随机数，对下一个 token 几乎没有偏好；训练结束后，同一台机器却能续写文章、做翻译、在提示里看几个例子就学会一个新任务。中间发生了什么？

今天这一课，我们就把这件事彻底讲清楚。它可以拆成五个问题：

  • 要优化的那个数是什么？为什么“预测下一个 token”加上“交叉熵”就等于“学会语言的概率分布”？困惑度又是什么？
  • 一条 2048 个 token 的序列，为什么一次前向传播就能得到 2048 个损失？梯度从哪里开始往回流？
  • 训练数据从哪里来，怎样过滤、去重、打包？
  • 每一步参数怎么改？AdamW 的每个符号是什么意思，学习率为什么要先升后降，为什么要裁剪梯度、为什么用 BF16？
  • 一次训练要多少次浮点运算？给定算力预算，参数量 \(N\) 与训练 token 数 \(D\) 应该怎么分？Kaplan 与 Chinchilla 为什么给出不同的答案？

每个问题都先在黑板上用能手算的小例子走一遍（三个词的小词表、一个参数的两步 AdamW、6 个参数的线性层……），再换成 GPT-3 的真数字。

这一课在科技树上的位置

这一课是主线 D（训练目标与后训练）和主线 F（规模化规律与优化器）的起点。第 1 课留下的问题是：前向传播讲清楚了，可参数从哪里来？这一课回答它，并建立整门课反复使用的几件工具：交叉熵损失（第 3 课的 SFT、第 8 课的 GRPO 都在它上面加东西）、AdamW 与学习率调度（第 6 课的多步调度、第 18 课的 Muon 都是对它的修改）、训练算力 \(6ND\)（第 6 课改成 \(MD\)，第 7 课起 MoE 只把“激活参数”算进去）、BF16 混合精度（第 12 课降到 FP8），以及 Chinchilla 的算力最优分配（第 6 课 DeepSeek LLM 在它之上拟合超参数的规模化规律）。说白了，后面几乎每一课都要回来翻这一课的账本。

本课的记号
  • \(x_1,\dots,x_T\)：一条长为 \(T\) 的 token 序列，\(x_t\in\{0,1,\dots,V-1\}\) 是整数 id；\(x_{<t}\) 是前缀 \(x_1,\dots,x_{t-1}\)，\(x_{\le t}\) 含 \(x_t\)。\(V=\lvert\mathcal V\rvert\) 是词表大小（GPT-2/3 为 50,257）。
  • \(\theta\)：模型的全部参数，拉成一个很长的向量；\(p_\theta(\cdot\mid x_{<t})\) 是模型在位置 \(t\) 给出的、定义在整个词表上的概率分布。
  • \(\mathbf z_t\in\R^{V}\)：位置 \(t\) 的 logits；\(\mathbf p_t=\softmax(\mathbf z_t)\)；\(\mathbf y_t\in\{0,1\}^V\) 是真实下一个 token 的独热向量。
  • \(\ell_t\)：位置 \(t\) 的损失；\(\mathcal L\)：平均损失，单位 nats/token（自然对数）。
  • \(N\) 参数量、\(D\) 训练 token 数、\(C\) 训练算力（FLOPs）、\(\eta\) 学习率、\(B\) 每步的 batch（本课按 token 计）。
  • \(s\)：优化步的编号，\(\theta_s\) 是第 \(s\) 步的参数。§5 讲 Adam 时沿用 Adam 论文的写法，把步数记作 \(t\)，那里会再提醒一次。
  • 黑板上的小例子（“黑板上”开头的例题框）用的是为了手算而随手取的小数字，不是任何真实模型的参数；真实模型的数字都注明了来源。

问题：从一堆随机数到一个语言模型

大家上学时都做过完形填空：一篇短文挖掉几个词，让你根据上下文填回去。出题的人得先有一篇完整的文章，再决定挖哪里，答案就是原文。

GPT 的预训练，做的就是一种最简单的完形填空：永远只挖“下一个词”，而且一段文字的每一个位置都挖一遍。那么问题来了：一个刚造好的模型做这种题，是什么水平？要做多少道题、花多少算力，才能做得像样？这一页先把这两件事算清楚，再画一张全流程图，把后面七页要讲的东西先摆上黑板。

刚造好的模型：在五万个选项里瞎猜

第 1 课结束时，我们手里有一台完整的机器：GPT-2 small 读入一串 token id，经过 12 层注意力和前馈网络，在每个位置吐出 50,257 个 logits。这台机器有 124,439,808 个参数 1。刚造好时，这些参数全是随机数：GPT-1 的报告和 GPT-2 的代码都把权重初始化成均值 0、标准差约 0.02 的正态分布 2,3,1。

这样的模型做填空题，是什么水平？大家想一想。它对下一个 token 几乎没有偏好，接近于在 50,257 个选项里均匀地瞎猜，给真实下一个 token 的概率只有约 \(1/50{,}257\approx2\times10^{-5}\)，十万分之二。训练就是把这一亿多个数一点点调好，让模型给真实文本里每一个“下一个 token”分配尽可能高的概率。

预训练是什么：文本自带答案

我们先在黑板上写一句话，数一数里面藏着几道题。

黑板上 · 一句话里藏着几道填空题

黑板上写 5 个 token：“我 / 爱 / 吃 / 苹果 / 。”。从左往右，每到一个位置就把下一个 token 盖住：

  • 看到“我”，猜下一个（答案：爱）；
  • 看到“我爱”，猜下一个（答案：吃）；
  • 看到“我爱吃”，猜下一个（答案：苹果）；
  • 看到“我爱吃苹果”，猜下一个（答案：。）。

5 个 token，4 道题，每道题的答案都写在原文里，不需要任何人来批改。（第一个 token 前面没有前文，在 §3 的训练写法里它只当输入、不当答案。）

好，现在把 5 换成任意长度：一段 \(T+1\) 个 token 的文字，自带 \(T\) 道“填下一个 token”的题；一本 10 万 token 的书，就是约 10 万道题。这件事有一个正式的名字。

含义。 预训练（pre-training）：在大量没有人工标注的文本上，让模型反复练习“根据前文预测下一个 token”，把参数从随机数调成有用的值。叫“预”训练，是因为 GPT-1 的设想是先这样训练，再针对具体任务做一次“微调”（§8）2。

理解。 这种练习不需要人来出题：文本本身就是答案。所以预训练能用上几乎整个互联网的文本，而这正是它能做大的原因。

数学。 给定语料（很多条 token 序列），找参数 \(\theta\)，使平均损失 \(\mathcal L(\theta)\)（§2 定义）尽量小。做法是把“取一批数据 → 算损失 → 算梯度 → 改参数”重复几万到几十万次。

账单有多大

题目是现成的，做完这些题要花多少力气？GPT-3 175B 训练了 300B（3,000 亿）个 token 4。§6 会推导：训练一个稠密 Transformer，每个参数、每个 token 大约要 6 次浮点运算，所以总算力约为 \(6ND\)。

大家先猜一猜：GPT-3 这一次训练，一共做了多少次浮点运算？交给一台每秒做 \(10^{15}\) 次运算的机器，要算多久？几天？几个月？

GPT-3 的算力账单

GPT-3 论文表 D.1 用的参数量是 \(N=174{,}600\)M，训练 token 数 \(D=300\)B 4：

\[C\approx6ND=6\times1.746\times10^{11}\times3\times10^{11}=3.14\times10^{23}\ \text{FLOPs}.\]

论文惯用的单位是 PF-day：\(1\ \text{PF-day}=10^{15}\times86{,}400=8.64\times10^{19}\) FLOPs。于是 \(C=3.14\times10^{23}/8.64\times10^{19}\approx3{,}640\) PF-days，与表 D.1 印的 3,640 一致。换成人话：一台每秒做 \(10^{15}\) 次运算、一刻不停满负荷运转的机器，要算 3,640 天，将近 10 年。

将近十年。这张账单上的每一项都可以被设计改变：每个 token 花多少次运算（§6，以及第 7 课起的 MoE），每个数用几位存（§6 的 BF16，第 12 课的 FP8），在固定算力下选多大的模型、喂多少数据（§7）。这门课后面几乎每一个 DeepSeek 的创新，都是在给这张账单或者推理的账单打折。

一个优化步（optimizer step）

设第 \(s\) 步的参数为 \(\theta_s\)。一步做六件事：

  1. 从打包好的数据里取一个 batch：\(B\) 个 token，排成若干条长为 \(T\) 的序列。
  2. 前向传播，得到每个位置的 logits \(\mathbf z_t\in\R^V\)。
  3. 每个位置算损失 \(\ell_t=-\log p_\theta(x_{t+1}\mid x_{\le t})\)，对全部 \(B\) 个位置取平均得 \(\mathcal L\)。
  4. 反向传播，得到梯度 \(\mathbf g_s=\nabla_\theta\mathcal L(\theta_s)\)，和 \(\theta\) 一样长。
  5. 若 \(\norm{\mathbf g_s}\) 超过阈值，就把它等比例缩短。
  6. 用 AdamW 和当前学习率 \(\eta_s\) 算出 \(\theta_{s+1}\)。
一步里有多少道“填空题”

黑板上那句话是 4 道题。GPT-3 175B 的 batch 是 3.2M 个 token（表 2.1）4，每个 token 位置都贡献一个损失项，所以一步平均了约 320 万个损失。总共 300B 个 token，忽略训练初期 batch 从小到大的渐增，步数约为 \(3\times10^{11}/3.2\times10^{6}=93{,}750\)。作为对照，GPT-1 每步只有 \(64\times512=32{,}768\) 个 token 2，是 GPT-3 的约百分之一。

这一页讲了三件事
  • 第一，预训练就是做填空题，而且题目自带答案。 在无标注文本上反复做“预测下一个 token”，一段 \(T+1\) 个 token 的文字就是 \(T\) 道题（黑板上 5 个 token、4 道题）。刚初始化的模型相当于在 50,257 个选项里瞎猜，猜中的概率约 \(2\times10^{-5}\)。
  • 第二，训练分两部分。 一次性的数据管线（过滤、去重、分词、打包）和每步重复的循环（前向 → 损失 → 反向 → 裁剪 → AdamW → 调度）。
  • 第三，账单很大。 GPT-3 175B：300B token，约 \(6ND=3.14\times10^{23}\) FLOPs = 3,640 PF-days，约 9.4 万步，每步平均约 320 万个损失。

训练目标：自回归分解、最大似然与交叉熵

大家每天都看天气预报。一位预报员说“明天下雨的概率是 80%”，第二天真下雨了；另一位说“明天下雨的概率只有 1%”，结果也下了大雨。你会怎么给这两位打分？

直觉上，第二位错得离谱：他几乎打了包票说不会下，偏偏下了。第一位说得不错。那么问题来了：能不能给“说得不错”和“错得离谱”各打一个分数，而且这个分数能比较、能相加、能求导？

这正是训练的第一步。梯度下降只会把一个标量往下推，所以得先把“学会一门语言”翻译成一个标量，而且它要对每一个参数可导。GPT 的回答分三步：先把“一段文本出现的概率”拆成一连串“下一个 token 的概率”；再说“好的模型应该让真实文本的概率尽量大”（最大似然）；最后把它改写成对每个位置都一样的一个损失（交叉熵）。天气预报员的分数，会在第二步的末尾揭晓。

自回归分解：把一段文本的概率拆成一串条件概率

问题。 我们想让模型给整段文本一个概率 \(p(x_1,\dots,x_T)\)。可是长为 \(T\) 的序列有 \(V^T\) 种可能，\(V=50{,}257\)、\(T=2048\) 时这是一个有近一万位的数字，不可能直接列表。需要一个把大问题拆成小问题的办法。

图景。 回想一下输入法：它从左往右读，每读到一个位置，都对“下一个词是什么”有一个预期。整句话出现的概率，就是这些“下一个词猜中的概率”连乘起来。我们先在黑板上乘一次。

黑板上 · 一句话的概率

第 1 课里 “The unbelievable tokenization” 被 GPT-2 分成 4 个 token：The、Ġunbelievable、Ġtoken、ization 1。假设某个模型从左往右，给这 4 个位置的条件概率依次是 \(0.5\)、\(0.25\)、\(0.1\)、\(0.8\)（为了手算方便而取的数）：

\[p(\text{整句})=0.5\times0.25\times0.1\times0.8=0.01.\]

大家看第三个因子：只要有一个位置猜得很差（这里是 \(0.1\)），整句的概率就被拉低一个数量级。

好，现在把 4 换成 \(T\)。只用条件概率的定义 \(p(a,b)=p(a)\,p(b\mid a)\)，一次拆出一个变量：

概率的链式法则
(1)\(\displaystyle p(x_1,\dots,x_T)=p(x_1)\,p(x_2,\dots,x_T\mid x_1)\)条件概率的定义，把 \(x_1\) 单独拿出来
(2)\(\displaystyle =p(x_1)\,p(x_2\mid x_1)\,p(x_3,\dots,x_T\mid x_1,x_2)\)对剩下的部分再用一次，这次在已知 \(x_1\) 的条件下拿出 \(x_2\)
(3)\(\displaystyle =p(x_1)\,p(x_2\mid x_1)\cdots p(x_T\mid x_1,\dots,x_{T-1})\)重复 \(T-1\) 次
(4)\(\displaystyle =\prod_{t=1}^{T}p(x_t\mid x_{<t})\)约定 \(x_{<1}\) 是空前缀
自回归分解\[p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta\big(x_t\mid x_{<t}\big)\]\(p_\theta(\cdot\mid x_{<t})\) 是模型读完前缀 \(x_{<t}\) 之后在整个词表上给出的分布，也就是第 1 课里那个位置的 \(\softmax(\mathbf z)\)(2.1)

我们代回黑板：\(T=4\) 时右边是 \(p(x_1)\,p(x_2\mid x_1)\,p(x_3\mid x_{\le2})\,p(x_4\mid x_{\le3})\)，正是那四个数的连乘，\(0.01\)。对，一模一样。

这个分解是恒等式，没有做任何近似：任何一个序列上的分布都能这样写。模型要学的只是每一个条件分布。它也不是唯一的拆法（也可以从右往左拆），“从左往右”是一个选择，理由是语言有自然的先后顺序，GPT-2 的式 (1) 正是这样说的 5。GPT-1 的写法多了一个限制：只看最近 \(k\) 个 token，\(\log P(u_i\mid u_{i-k},\dots,u_{i-1})\)，\(k\) 是上下文窗口 2。这才是近似：窗口之外的历史被丢掉了，实际模型的窗口就是它的上下文长度（GPT-1 为 512，GPT-3 为 2048）。

论文原式里的一个笔误

GPT-2 报告的式 (1) 印的是 \(p(x)=\prod_{i=1}^{n}p(s_n\mid s_1,\dots,s_{n-1})\)：连乘的下标是 \(i\)，因子里却写成了 \(s_n\) 5。应读作 \(p(s_i\mid s_1,\dots,s_{i-1})\)。读论文时遇到下标对不上，先按上面的链式法则自己推一遍。

最大似然：让真实文本的概率尽量大

含义。 最大似然估计（maximum likelihood estimation，MLE）：在所有可能的参数里，挑那个让“已经观察到的数据”出现概率最大的。

理解。 训练语料是真实世界写下来的文本。一个好的语言模型应该觉得这些文本“很可能出现”。如果模型给某篇真实文章的概率很低，说明它在某些位置的预期和真实写法不一致，就该调参数。

数学。 把语料看成 \(n\) 条相互独立的序列 \(x^{(1)},\dots,x^{(n)}\)，总 token 数为 \(D\)（这里的 \(n\) 只是序列条数；\(M\) 这个字母留给第 6 课 DeepSeek LLM 的“每 token FLOPs”）。它们同时出现的概率叫似然（likelihood），是 \(\theta\) 的函数：

最大似然估计\[\theta^\star=\argmax_\theta\ \prod_{m=1}^{n}p_\theta\big(x^{(m)}\big)=\argmax_\theta\ \sum_{m=1}^{n}\sum_{t}\log p_\theta\big(x^{(m)}_t\mid x^{(m)}_{<t}\big)\]第二个等号用了 (2.1)，以及“对数是单调递增函数，不改变最大值出现的位置”。(2.2)
从最大似然到平均负对数似然
(1)\(\displaystyle \argmax_\theta\prod_m p_\theta(x^{(m)})\)目标：让语料的概率最大
(2)\(\displaystyle =\argmax_\theta\sum_m\log p_\theta(x^{(m)})\)\(\log\) 严格递增，最大值点不变；乘积变成求和
(3)\(\displaystyle =\argmax_\theta\sum_m\sum_t\log p_\theta(x^{(m)}_t\mid x^{(m)}_{<t})\)代入 (2.1)，对数把连乘拆成逐位置求和
(4)\(\displaystyle =\argmin_\theta\ -\frac1D\sum_m\sum_t\log p_\theta(x^{(m)}_t\mid x^{(m)}_{<t})\)乘以负常数 \(-1/D\)，最大化变成最小化，最优点不变

最后一行的量，就是训练时真正盯着看的损失：

平均负对数似然（训练损失）\[\mathcal L(\theta)=-\frac1D\sum_{\text{所有位置}}\log p_\theta\big(x_t\mid x_{<t}\big)=\frac1D\sum_{\text{所有位置}}\ell_t,\qquad \ell_t=-\log p_\theta\big(x_t\mid x_{<t}\big)\]每个位置一个非负的 \(\ell_t\)：真实 token 的概率越高，\(\ell_t\) 越小；概率为 1 时 \(\ell_t=0\)。(2.3)

为什么不直接最大化乘积本身，非要取对数？三个理由，第一个最要命。大家先猜一猜：2048 个位置、每个概率都是 \(0.1\)，用 FP32 一个一个乘下去，乘到第几个就变成 0 了？

答案是第 46 个。FP32 能表示的最小正数约为 \(1.4\times10^{-45}\)，而 \(0.1^{46}=10^{-46}\) 连它的一半都不到，只能存成 0；整条序列的 \(0.1^{2048}=10^{-2048}\) 更不用说，梯度也跟着没了。这是数值下溢。取对数后是 \(2048\times\ln0.1\approx-4716\)，一个普通大小的数。第二个理由是可分解：求和让每个位置的贡献各自独立，梯度就是各位置梯度之和（§3）。第三个是可比较：除以 \(D\) 之后，不同长度的语料、不同大小的 batch 上的损失可以直接比较。

黑板上 · 手算平均损失

接着黑板上那句话，4 个位置的概率 \(0.5,0.25,0.1,0.8\)：

\[\begin{aligned}\ell_1&=-\ln0.5=0.693, &\ell_2&=-\ln0.25=1.386,\\ \ell_3&=-\ln0.1=2.303, &\ell_4&=-\ln0.8=0.223,\end{aligned}\]
\[\mathcal L=\frac{0.693+1.386+2.303+0.223}{4}=1.151\ \text{nats/token}.\]

核对：\(-\ln0.01/4=4.605/4=1.151\)，和“整句概率取对数再平均”一致。损失最大的是第 3 个位置，它一个就贡献了一半的总损失。

现在可以回答开头那个问题了：预报员的罚分就是 \(-\ln p\)，\(p\) 是他给“真实发生的那件事”的概率。说 80%、真下了，罚 \(-\ln0.8=0.223\)；说 1%、真下了，罚 \(-\ln0.01=4.605\)，是前者的 20 倍多。错得越笃定，罚得越重；给真实结果的概率是 1，就一分不罚。\(\ell_t\) 就是给语言模型每个位置打的这种分。

交叉熵：同一个损失的信息论名字

熵、交叉熵与 KL 散度学过信息论的可以跳过；完整讲法见 M05 §1（熵）、§2（交叉熵）、§4（KL 与它非负的证明）

设 \(q\)、\(p\) 是同一组结果（这里是词表里的 \(V\) 个 token）上的两个概率分布。本课 \(q\) 是真实分布、\(p\) 是模型；M05 把两个字母反过来用（\(p\) 是目标、\(q\) 是模型），读的时候按含义对应。

一个概率为 \(q_i\) 的结果真的发生了，它带来的意外程度（信息量，surprisal）定义为 \(-\log q_i\)：必然发生（\(q_i=1\)）时为 0，越罕见越大（\(q_i=0.01\) 时是 \(-\ln0.01=4.6\) nats）。选对数的理由是：两件独立的事同时发生，概率相乘，意外程度正好相加。下面三个量都是“意外程度”的平均。

  • 熵 \(H(q)=-\sum_iq_i\log q_i\)：按 \(q\) 出结果时，平均每个结果的“意外程度”。完全确定（某个 \(q_i=1\)）时为 0；\(V\) 个结果等可能时为 \(\log V\)，最大。
  • 交叉熵 \(H(q,p)=-\sum_iq_i\log p_i\)：结果按 \(q\) 出现，你却按 \(p\) 去预期时，平均的意外程度。
  • KL 散度 \(\KL(q\,\|\,p)=\sum_iq_i\log\frac{q_i}{p_i}\)：两者之差，衡量 \(p\) 离 \(q\) 有多远。它总是 \(\ge0\)，只在 \(p=q\) 时等于 0（吉布斯不等式，证明用 Jensen 不等式，见 M05）。

我们还是先上黑板，把预报员换成一个小小的语言模型。

黑板上 · 三个词的小词表

词表只有三个词：{好, 热, 冷}。前文是“今天天气很”，模型给出 \(\mathbf p=(0.5,\ 0.25,\ 0.25)\)。这一次，原文写的是“热”。

  • 按 \(\ell_t\) 的定义：\(\ell=-\ln0.25=1.386\) nats。
  • 按交叉熵的定义：真实分布是独热向量 \(\mathbf q=(0,\ 1,\ 0)\)，\(H(\mathbf q,\mathbf p)=-(0\times\ln0.5+1\times\ln0.25+0\times\ln0.25)=1.386\)。

两个数一模一样：三项求和里，只有真 token 那一项的系数不是 0。如果原文写的是“好”，罚分就只有 \(-\ln0.5=0.693\)。

含义。 交叉熵（cross-entropy）：用模型的分布 \(p_\theta\) 去预期真实分布 \(q\) 产生的结果时，平均付出的“意外”。

理解。 黑板上已经看到了：在一个训练位置上，真实的下一个 token 是确定的，“真实分布” \(q\) 是一个独热向量，代进定义，求和只剩一项，交叉熵就是 \(-\log p_\theta(\text{真 token})\)，恰好是 (2.3) 里的 \(\ell_t\)。所以“负对数似然”和“交叉熵损失”是同一个东西的两个名字，Kaplan 等人写的就是 “autoregressive log-likelihood (i.e. cross-entropy loss)” 6。

数学。 把所有训练位置放在一起看：同一个前缀 \(c\) 后面，真实文本的下一个 token 服从某个分布 \(q(\cdot\mid c)\)。在这些位置上平均 \(\ell_t\)，得到的是 \(H\big(q(\cdot\mid c),\,p_\theta(\cdot\mid c)\big)\) 对各种前缀的平均。它可以拆成两块：

交叉熵 = 熵 + KL
(1)\(\displaystyle H(q,p)=-\sum_iq_i\log p_i\)定义
(2)\(\displaystyle =-\sum_iq_i\log q_i+\sum_iq_i\log q_i-\sum_iq_i\log p_i\)加一项、减一项同样的东西
(3)\(\displaystyle =-\sum_iq_i\log q_i+\sum_iq_i\log\frac{q_i}{p_i}\)后两项合并成一个对数
(4)\(\displaystyle =H(q)+\KL(q\,\|\,p)\)按定义认出两项
交叉熵的分解\[H\big(q,\,p_\theta\big)=\underbrace{H(q)}_{\text{与 }\theta\text{ 无关}}+\underbrace{\KL\big(q\,\|\,p_\theta\big)}_{\ge0,\ \text{只在 }p_\theta=q\text{ 时为 }0}\]\(q\) 是文本本身的分布，\(p_\theta\) 是模型。(2.4)

这个式子到底在说什么？我们找一个“真的说不准”的位置代进去看看。

一个有真实不确定性的位置

设语料里“今天天气很”后面只出现两种写法，“好”和“热”各占一半：\(q=(0.5,\,0.5)\)（为了好算，这里没有“冷”）。模型 A 学得不准，给 \(p_A=(0.8,\,0.2)\)；模型 B 学对了，给 \(p_B=(0.5,\,0.5)\)。在这个前缀出现的所有位置上平均 \(\ell_t\)：

\[\begin{aligned}H(q,p_A)&=-0.5\ln0.8-0.5\ln0.2=0.5\times0.223+0.5\times1.609=0.916\ \text{nats},\\ H(q,p_B)&=-0.5\ln0.5-0.5\ln0.5=0.693\ \text{nats}=H(q).\end{aligned}\]

按 (2.4) 拆开：模型 A 的 \(0.916=0.693+0.223\)，其中 \(0.693=\ln2\) 是文本自己的熵，\(0.223\) 是 \(\KL(q\,\|\,p_A)=0.5\ln\frac{0.5}{0.8}+0.5\ln\frac{0.5}{0.2}=-0.235+0.458=0.223\)。模型 B 的 KL 为 0，损失停在 \(0.693\)，再也降不下去：它已经完美，剩下的是“好”与“热”本身的五五开。这就是下面说的“损失的底”。

(2.4) 说了两件重要的事。第一，最小化交叉熵 = 最小化模型与真实分布的 KL 散度，因为第一项与参数无关。所以“预测下一个 token”不是一个随便挑的练习，它的最优解就是真实的语言分布本身。第二，损失有一个降不下去的底：即使模型完美，\(\mathcal L\) 也只能降到文本自身的熵 \(H(q)\)。自然语言本来就有不确定性（“今天天气很___”后面可以是好、热、冷……），这部分谁也预测不了。§7 的 Chinchilla 拟合公式里那个常数项 \(E\)，作者就解释为这一项 7。

很多人以为：训练得足够久，损失就能降到 0

很多人以为：交叉熵是“猜错的程度”，模型足够大、训练足够久，总能一个不错，把损失降到 0。

其实：由 (2.4)，损失的下限是文本自身的熵 \(H(q)\)，不是 0。上面的模型 B 已经完美，损失仍然停在 \(\ln2=0.693\)，因为原文本身就是一半写“好”、一半写“热”。损失降到某个值不再动，未必是模型不行，也可能是碰到了语言本身的不确定性。

单位。 用自然对数时单位是 nats，以 2 为底时是 bits，两者差一个常数：\(\mathcal L_{\text{bits}}=\mathcal L_{\text{nats}}/\ln2\)。本课和 Kaplan 的论文一样用 nats 6。Chinchilla 的论文没有写明损失的单位；本课按惯常的自然对数来读它的损失数字，这是笔者的假设。黑板上那句话的 1.151 nats 等于 \(1.151/0.693=1.661\) bits：平均每个 token 的不确定性，相当于抛 1.66 枚硬币。

困惑度：把损失翻译成“在几个选项里犹豫”

大家考试时都碰到过完全不会的四选一吧？只能蒙，猜对的概率是 \(1/4\)。

那么问题来了：“损失 2.9 nats”到底好不好？这个数不直观，“相当于四选一瞎蒙”却一听就懂。困惑度就是把前者翻译成后者。

黑板上 · 四选一瞎蒙的损失

一个“学生”每道题都在 4 个选项里均匀地蒙，正确答案总在其中：每道题给正确答案的概率都是 \(1/4\)，每道题的罚分 \(-\ln\frac14=\ln4=1.386\) nats，平均损失也是 \(1.386\)。

反过来，拿到一个平均损失 \(1.386\)，怎么知道它“相当于几选一”？取指数：\(e^{1.386}=4\)。

含义。 困惑度（perplexity，PPL）：模型平均相当于在多少个等可能的选项里犹豫。

困惑度\[\mathrm{PPL}=e^{\mathcal L}=\Big(\prod_{t=1}^{T}\frac{1}{p_\theta(x_t\mid x_{<t})}\Big)^{1/T}\]第二种写法说明它是“每个位置概率倒数”的几何平均。以 bits 计的损失则用 \(2^{\mathcal L_{\text{bits}}}\)，结果相同。(2.5)

推导它为什么是“选项数”。 把黑板上的 4 换成 \(k\)：设模型在每个位置都恰好在 \(k\) 个 token 之间均匀犹豫，而真 token 就在其中，那么每个位置 \(p=1/k\)，\(\mathcal L=-\ln(1/k)=\ln k\)，\(\mathrm{PPL}=e^{\ln k}=k\)。反过来，任何困惑度为 \(k\) 的模型，其平均意外程度都和“在 \(k\) 个选项里均匀瞎猜”相同。这是等效的选项数，不是说模型真的只考虑 \(k\) 个候选。

三个困惑度
  • 黑板上那句话：\(\mathcal L=1.151\)，\(\mathrm{PPL}=e^{1.151}=3.16\)。核对第二种写法：\((1/0.01)^{1/4}=100^{0.25}=3.16\)。
  • GPT-1 在 BooksCorpus 上报告了 18.4 的 token 级困惑度 2，对应 \(\mathcal L=\ln18.4=2.912\) nats/token。
  • 刚初始化、在 50,257 个 token 上均匀瞎猜的模型：\(\mathcal L=\ln50{,}257=10.825\) nats，\(\mathrm{PPL}=50{,}257\)。从 10.8 降到 3 以下，就是预训练做的事。
失败模式：跨分词器比较困惑度

困惑度是“每个 token”的平均，而“token”的定义取决于分词器。同一段文字，分词器 A 切成 100 个 token，分词器 B 切成 130 个：即使两个模型给整段文字的总负对数概率相同，B 的每 token 损失也只有 A 的 \(1/1.3\)，困惑度看起来好得多。所以 Transformer 原论文特意注明它的困惑度是按 wordpiece 计的，不能和按词计的直接比 8；GPT-2 报告在各基准上也把结果换算回数据集规定的单位（字符、字节或词）再比 5。本课后面引用的损失数字（Kaplan、Chinchilla）也各自依赖自己的分词器，不能跨论文直接比较。

这一页讲了三件事
  • 第一，整句的概率拆成一串“下一个 token”的概率。 链式法则给出恒等式 \(p(x_{1:T})=\prod_tp(x_t\mid x_{<t})\) (2.1)，GPT 只学每一个条件分布（黑板上 \(0.5\times0.25\times0.1\times0.8=0.01\)）。
  • 第二，损失就是给每个位置打的“预报员分数”。 最大似然 ⇔ 最小化平均负对数似然 \(\mathcal L=\frac1D\sum\ell_t\)，\(\ell_t=-\log p\)；取对数避免下溢，并把损失拆成逐位置之和。\(\ell_t\) 就是独热分布与模型分布的交叉熵；\(H(q,p)=H(q)+\KL(q\|p)\)，所以最优解是真实分布，损失的底是文本自身的熵，不是 0。
  • 第三，困惑度是等效的选项数。 \(\mathrm{PPL}=e^{\mathcal L}\)（四选一瞎蒙是 4）；它依赖分词器，跨分词器不可比。

Teacher forcing：一次前向，T 个损失

大家做练习册的时候，有没有用过这种办法：做一道，马上翻到书后面对答案；错了就把正确答案改上，再接着做下一道。这样做有个好处：前面一道做错了，不会把后面一连串题都带歪。

GPT 训练时用的就是这种“做一道、对一道”的办法，而且比练习册更狠：它把所有题同时做完、同时对答案。(2.3) 要求对每个位置算一个 \(\ell_t\)，一条 2048 个 token 的序列就有 2048 个位置。最笨的做法是：把前缀 \(x_1\) 喂给模型算一次，再把 \(x_1x_2\) 喂进去算一次……一共 2048 次前向传播。这一页说明为什么一次就够，以及梯度从损失出发时的第一步长什么样。

什么是 teacher forcing

含义。 教师强制（teacher forcing）：训练时，每个位置的输入前缀都用真实文本，而不是模型自己前面生成的 token。

理解。 生成文本时，模型每一步吃进去的是自己上一步的输出；训练时却不这样做。即使模型在位置 3 猜错了，位置 4 看到的仍然是正确的第 3 个 token。这样，每个位置的练习题都是“给定正确前文，猜下一个”，互不牵连。

类比：做一道、对一道答案的练习册

映射。 学生做一本带答案的练习册：每做一道之前先猜，猜完立刻翻到后面对答案，把正确答案写上，再做下一道。前缀 = 已经对过答案、改正过的前面各题；每次的“猜”= \(p_\theta(\cdot\mid x_{\le t})\)；猜得多离谱 = \(\ell_t\)。

收益。 它说明了为什么一处猜错不会连累后面：后面的题都建立在正确答案上。也说明了每道题的难度只取决于原文本身。

但是这个比方有两个地方不对。 第一，练习册是一道一道依次做的，模型却是同时做完所有题（下一节）。第二，到了真正生成的时候，没有答案可对，前面写错的字会一直留在前缀里。后一点是 teacher forcing 带来的训练与生成之间的不一致（常被称为 exposure bias），它不影响本课的预训练，但会是后面对齐与强化学习要处理的问题之一。

数学。 一条训练序列取 \(T+1\) 个 token \(x_1,\dots,x_{T+1}\)：前 \(T\) 个作为输入，后 \(T\) 个（整体左移一位）作为目标。先在黑板上摆一次。

黑板上 · 输入与目标，错开一位

还是 §1 那句话，5 个 token（\(T+1=5\)，\(T=4\)）：

位置 \(t\) 1 2 3 4
输入 \(x_t\) 我 爱 吃 苹果
目标 \(x_{t+1}\) 爱 吃 苹果 。

目标这一行，就是输入这一行整体左移一位。位置 \(t\) 的输出负责预测第 \(t+1\) 个 token；4 个位置，4 个损失 \(\ell_1,\dots,\ell_4\)，这条序列的损失是它们的平均。

好，把一条序列换成 \(B_{seq}\) 条，一个 batch 共 \(B=B_{seq}T\) 个位置：

一个 batch 的训练损失\[\begin{gathered}\mathcal L_{\text{batch}}(\theta)=\frac{1}{B_{seq}T}\sum_{b=1}^{B_{seq}}\sum_{t=1}^{T}\ell_{b,t}\\ \ell_{b,t}=-\log p_\theta\big(x_{b,t+1}\mid x_{b,1},\dots,x_{b,t}\big)\end{gathered}\]输入是 \(x_{b,1:T}\)，目标是 \(x_{b,2:T+1}\)。与 (2.3) 相比只是下标平移了一位：位置 \(t\) 的输出负责预测第 \(t+1\) 个 token。(2.6)

代回黑板：\(B_{seq}=1\)、\(T=4\)，\(\mathcal L_{\text{batch}}=(\ell_1+\ell_2+\ell_3+\ell_4)/4\)，正是那条序列的平均损失。

为什么一次前向就能得到全部 \(T\) 个损失

先看笨办法到底笨在哪里。

黑板上 · 笨办法要处理多少个位置

还是那 4 道题。笨办法每道题单独喂一次前缀：

  • 第 1 题喂“我”：1 个位置；
  • 第 2 题喂“我爱”：2 个位置；
  • 第 3 题喂“我爱吃”：3 个位置；
  • 第 4 题喂“我爱吃苹果”：4 个位置。

合计 \(1+2+3+4=10\) 个“位置 × 前向”。可第 4 次前向里，位置 1、2、3 的计算和前三次一模一样：只要位置 \(t\) 看不见它后面的 token，一次喂进整条“我爱吃苹果”，4 个位置的输出就已经是 4 道题各自的答卷。一次前向只处理 4 个位置，省了 \(10/4=2.5\) 倍。

“只要位置 \(t\) 看不见它后面的 token”，靠的正是第 1 课的因果掩码：注意力里位置 \(t\) 对位置 \(j>t\) 的权重被强制为 0。它保证了一件事：一次前向时位置 \(t\) 的输出，和“只把前缀 \(x_{1:t}\) 单独喂给模型”时的输出完全相同。 所以一次前向里的 \(T\) 个输出，就是 \(T\) 次单独前向的结果。我们对层数归纳，一行一行写：

位置 t 的输出只依赖前缀 x≤t
(1)\(\displaystyle \mathbf h^{(0)}_t=\mathrm{Emb}(x_t)+\mathrm{Pos}(t)\)第 0 层是查表，只依赖 \(x_t\)
(2)\(\displaystyle \mathbf h^{(l-1)}_j=f(x_{\le j})\ \ \text{对所有}\ j\)归纳假设：第 \(l-1\) 层的每个位置只依赖自己及之前的 token
(3)\(\displaystyle \mathbf u_t=\sum_{j\le t}a_{tj}\,\mathbf v_j\)因果掩码让 \(j>t\) 的注意力权重为 0，只剩 \(j\le t\) 的项
(4)\(\displaystyle \mathbf q_t,\ \mathbf k_j,\ \mathbf v_j\ (j\le t)\ \text{只依赖}\ x_{\le t}\)它们由 \(\mathbf h^{(l-1)}_t\)、\(\mathbf h^{(l-1)}_j\) 逐位置算出（Pre-LN 下先过 LayerNorm 再做线性投影），由假设只依赖 \(x_{\le j}\subseteq x_{\le t}\)，所以权重 \(a_{tj}\) 也是
(5)\(\displaystyle \mathbf h^{(l)}_t=g\big(\mathbf h^{(l-1)}_t,\mathbf u_t\big)\)多头的拼接与输出投影 \(W^O\)、LayerNorm、FFN、残差都逐位置计算，不在位置之间混合信息
(6)\(\displaystyle \mathbf h^{(l)}_t,\ \dots,\ \mathbf z_t\ \text{只依赖}\ x_{\le t}\)归纳完成，逐层直到 logits
一次前向省了多少

笨办法：对 \(t=1,\dots,T\) 分别把长为 \(t\) 的前缀喂进去，一共处理 \(\sum_{t=1}^{T}t=T(T+1)/2\) 个“位置”。一次前向只处理 \(T\) 个。比值 \((T+1)/2\)：代回黑板，\(T=4\) 时是 2.5，对得上；\(T=2048\) 时是 1,024.5 倍（这还没算注意力的平方项）。GPT-3 一步 3.2M 个 token，正因为有因果掩码，它们只需要一次前向、一次反向。这也是 Transformer 能在训练中高效利用 GPU 的根本原因之一：循环神经网络在训练时也用 teacher forcing，但它的隐藏状态必须一个位置一个位置地往下传，无法在序列维度上并行。

很多人以为：输入里明明就有答案，模型抄一下就行

很多人以为：teacher forcing 把整句真实文本都喂了进去，位置 \(t\) 的答案 \(x_{t+1}\) 就躺在输入里（它是位置 \(t+1\) 的输入），模型只要学会“抄右边那一格”，损失就能降到 0。

其实：因果掩码把位置 \(t\) 对所有 \(j>t\) 的注意力权重强制为 0，其余运算又都逐位置，所以 \(x_{t+1}\) 的信息到不了位置 \(t\) 的输出（上面归纳的结论）。答案在输入里，却在位置 \(t\) 看不见的那一边。去掉掩码，训练就成了抄答案，损失低得不真实，生成时右边却根本没有答案可抄（笔者的推理）。

打包：不浪费任何一个位置

真实文档长短不一。如果每篇文档单独占一条长 2048 的序列，短的用填充符（padding）补齐，填充位置的计算就白做了。GPT-3 的做法是：序列总是填满 \(n_{ctx}=2048\)；比这短的文档首尾相接，文档之间放一个 <|endoftext|>（GPT-2 词表里 id 为 50256 的 token），并且不做任何特殊掩码 4,1。模型需要自己学会“看到 <|endoftext|> 之后，前面的内容基本无关”。

填充与打包的利用率

三篇文档，长 700、1500、900 个 token，共 3,100 个。各占一条长 2048 的序列时，要 3 条、6,144 个位置，只有 3,100 个是真 token，利用率 \(3100/6144=50.5\%\)。首尾相接（加上 3 个分隔符共 3,103 个 token）只需要约 1.5 条序列，利用率接近 100%。代价是：同一条序列里的第二篇文档能“看到”第一篇，这些跨文档的注意力对预测大多无用。

梯度的起点：交叉熵对 logits 的导数是 p − y

损失算出来以后，反向传播从 \(\ell_t\) 出发往回走。第一站是 logits \(\mathbf z_t\)。这一步的结果极简单，也是整个反向传播里被计算次数最多的一个公式。我们不急着推，先在黑板上一格一格地“试”出来。

黑板上 · 把三个 logit 各推一下，看损失怎么变

还是三个词的小词表 {好, 热, 冷}。为了手算，我故意挑了这样一组 logits：\(\mathbf z=(\ln4,\ \ln2,\ \ln2)\approx(1.386,\ 0.693,\ 0.693)\)。于是 \(e^{\mathbf z}=(4,\ 2,\ 2)\)，和为 8，\(\mathbf p=(0.5,\ 0.25,\ 0.25)\)，正是 §2 黑板上那个分布。真 token 是“热”，损失 \(\ell=-\ln0.25=1.3863\)。

现在把每个 logit 单独加 0.01，重新算损失：

推哪一格 新的损失 变化 变化 ÷ 0.01
\(z_{\text{好}}+0.01\) 1.3913 +0.0050 +0.50
\(z_{\text{热}}+0.01\) 1.3788 −0.0075 −0.75
\(z_{\text{冷}}+0.01\) 1.3888 +0.0025 +0.25

最后一列就是损失对三个 logit 的（近似）导数：\((0.50,\ -0.75,\ 0.25)\)。大家对照一下 \(\mathbf p=(0.5,\ 0.25,\ 0.25)\)，看出什么关系了吗？

对，除了真 token 那一格少了 1，其余一模一样。是不是巧合？我们推一下。

softmax 与链式法则会对 log-sum-exp 求导的可以跳过；系统讲法见 M06 §5

\(\softmax\) 把任意实数向量变成概率分布：

\[p_k=\frac{e^{z_k}}{\sum_{j=1}^{V}e^{z_j}},\qquad p_k>0,\quad\sum_kp_k=1.\]

需要的只有一个求导事实：\(\frac{\partial}{\partial z_k}\log\sum_je^{z_j}=\frac{e^{z_k}}{\sum_je^{z_j}}=p_k\)（对数的导数是 \(1/(\cdot)\)，再乘上里面对 \(z_k\) 的导数 \(e^{z_k}\)）。

交叉熵对 logits 的梯度
(1)\(\displaystyle \ell=-\log p_y=-\log\frac{e^{z_y}}{\sum_je^{z_j}}\)\(y\) 是真实 token 的编号，\(\ell\) 是这个位置的损失
(2)\(\displaystyle =-z_y+\log\sum_{j}e^{z_j}\)对数把商拆成差
(3)\(\displaystyle \frac{\partial\ell}{\partial z_k}=-[k=y]+\frac{e^{z_k}}{\sum_je^{z_j}}\)第一项只在 \(k=y\) 时对 \(z_k\) 有导数 \(-1\)；第二项用上面框里的求导事实
(4)\(\displaystyle =p_k-y_k\)\([k=y]\) 正是独热向量 \(\mathbf y\) 的第 \(k\) 格
交叉熵对 logits 的梯度\[\frac{\partial\ell_t}{\partial\mathbf z_t}=\mathbf p_t-\mathbf y_t\ \in\R^{V},\qquad \mathbf p_t=\softmax(\mathbf z_t)\]预测分布减去真实的独热分布。因为 (2.6) 是各位置损失的平均，整个 batch 对 \(\theta\) 的梯度是各位置梯度的平均；对某一个位置的 logits 求导，则是 \(\partial\mathcal L_{\text{batch}}/\partial\mathbf z_{b,t}=(\mathbf p_{b,t}-\mathbf y_{b,t})/(B_{seq}T)\)。(2.7)

代回黑板：\(\mathbf p-\mathbf y=(0.5,\ 0.25,\ 0.25)-(0,\ 1,\ 0)=(0.5,\ -0.75,\ 0.25)\)，和刚才一格一格试出来的一样。不是巧合。

读这个结果有三个角度。方向：真 token 那一格的梯度是 \(p_y-1<0\)，沿负梯度走会把它的 logit 往上推；其他格是 \(p_k>0\)，被往下压，而且原来概率越大的错误答案被压得越狠（黑板上“好”的 0.5 是“冷”的 0.25 的两倍）。守恒：\(\sum_k(p_k-y_k)=1-1=0\)，一格涨多少，其余合计跌多少。大小：用 L1 范数（各分量绝对值之和）来量，真 token 那一格贡献 \(1-p_y\)，其余各格合计 \(\sum_{k\ne y}p_k=1-p_y\)，所以 \(\norm{\mathbf p-\mathbf y}_1=2(1-p_y)\)（黑板上 \(0.5+0.75+0.25=1.5=2\times0.75\)）。模型已经很确定地猜对时（\(p_y\to1\)）梯度趋于 0，这个位置不再提供学习信号；很确定地猜错时（\(p_y\to0\)）接近最大值 2。刚初始化时 \(p_y\approx1/V\)，每个位置的梯度都接近这个最大值。

沿负梯度走一步（步长取 1，只为演示），\(\mathbf z'=(0.886,\ 1.443,\ 0.443)\)，“热”的概率从 0.25 升到 0.515，损失从 1.386 降到 0.663 nats。下图是四个词的版本。

手算 p − y：四个词

四个候选 Ġstory、Ġtoken、Ġnews、Ġcat 的 logits 为 \(\mathbf z=(2,1,0,-1)\)，真 token 是 Ġtoken。\(e^{\mathbf z}=(7.389,\,2.718,\,1,\,0.368)\)，和为 \(11.475\)，所以

\[\mathbf p=(0.644,\ 0.237,\ 0.087,\ 0.032),\qquad \mathbf p-\mathbf y=(0.644,\ -0.763,\ 0.087,\ 0.032).\]

核对：四个分量之和为 0；\(\norm{\mathbf p-\mathbf y}_1=1.526=2\times(1-0.237)\)。这个位置的损失 \(\ell=-\ln0.237=1.440\) nats。

失败模式：先算 softmax、再取对数

照着定义写代码，先算 \(e^{z_k}\)、归一化成 \(\mathbf p\)、再取 \(-\log p_y\)，会在两头出事。上溢：FP32 能表示的最大数约 \(3.4\times10^{38}=e^{88.7}\)，只要有一个 logit 超过 88.7，\(e^{z}\) 就变成无穷大，\(\mathbf p\) 里出现 NaN；FP16 的上限 65,504 \(=e^{11.09}\)，logit 超过约 11.09 就溢出。下溢：真 token 的概率小于 FP32 能表示的最小正数（约 \(1.4\times10^{-45}=e^{-103.3}\)）时，\(p_y\) 被存成 0，\(-\log0\) 是无穷大。

办法是在对数里提出最大的 logit \(m=\max_jz_j\)：

\[\begin{aligned}\log\sum_je^{z_j}&=\log\Big(e^{m}\sum_je^{z_j-m}\Big)=m+\log\sum_je^{z_j-m},\\ \ell&=-z_y+m+\log\sum_je^{z_j-m}.\end{aligned}\]

减去 \(m\) 以后每个指数都 \(\le0\)，每一项都在 \((0,1]\) 里，而且最大的那一项正好是 1，所以求和结果至少是 1，对数里既不会出现无穷大，也不会出现 0。例：\(\mathbf z=(1000,\,999,\,998)\)，真 token 是第 2 个。直接算 \(e^{1000}\) 立刻溢出；按上式，\(m=1000\)，\(e^{0}+e^{-1}+e^{-2}=1+0.368+0.135=1.503\)，\(\ell=-999+1000+\ln1.503=1.408\) nats。梯度 \(\mathbf p-\mathbf y\) 也用同一组减过 \(m\) 的指数来算。所以实现里总是把 softmax 和取对数合成一步，直接算 \(\ell\)，不先存下 \(\mathbf p\)。

从 logits 再往回一步，是第 1 课的反嵌入（unembedding）(1.29)：\(\mathbf z_t=E\,\tilde{\mathbf h}_t\)，其中 \(E\in\R^{V\times d}\) 是与输入嵌入共享的词表矩阵，\(\tilde{\mathbf h}_t\in\R^{d}\) 是最终 LayerNorm 的输出。于是 \(\partial\ell_t/\partial\tilde{\mathbf h}_t=E^\top(\mathbf p_t-\mathbf y_t)\)，形状 \([d,V]\times[V]\to[d]\)，一个 \(d\) 维向量，穿过最终 LayerNorm 后沿残差流继续往下传。每一层的反向传播都是这样的矩阵乘法，§6 会数它们的运算量。

这一页讲了三件事
  • 第一，做一道、对一道。 Teacher forcing：训练时每个位置的前缀都是真实文本；目标序列是输入序列左移一位（黑板上“我爱吃苹果”对“爱吃苹果。”）。
  • 第二，一次前向，\(T\) 个损失。 因果掩码保证位置 \(t\) 的输出只依赖 \(x_{\le t}\)，所以一次前向同时给出 \(T\) 个“只看前缀”的预测和 \(T\) 个损失，比逐个前缀计算省 \((T+1)/2\) 倍（黑板上 10 对 4）。文档首尾相接、用 <|endoftext|> 分隔，把序列填满，不浪费位置。
  • 第三，梯度从 \(\mathbf p-\mathbf y\) 出发。 \(\partial\ell/\partial\mathbf z=\mathbf p-\mathbf y\)（黑板上一格一格试出 \((0.5,-0.75,0.25)\)），分量和为 0，L1 范数 \(2(1-p_y)\)，猜对且确定时趋于 0。实现时不要先算 \(\mathbf p\) 再取对数：提出最大 logit \(m\)，直接算 \(\ell=-z_y+m+\log\sum_je^{z_j-m}\)。

数据：从网页到打包好的 batch

大家刷手机的时候一定遇到过：同一个段子、同一篇文章，被不同的号搬来搬去，一天能刷到七八遍；还有些网页，点开全是乱码和广告。

假如一个模型把这些全读进去，会发生什么？(2.4) 说，交叉熵的最优解是“真实分布” \(q\)。可是模型见到的 \(q\) 其实是训练语料的分布。语料里全是垃圾网页，模型就学会写垃圾网页；同一篇文章重复一千遍，模型就会把它当成语言里特别常见的东西。所以“喂什么”和“怎么优化”一样决定结果。这一页看 GPT 三代的数据是怎么做的，重点是 GPT-3 的四道工序：质量过滤、去重、配比、去污染。

三代 GPT 的数据

GPT-1（2018） GPT-2（2019） GPT-3（2020）
语料 BooksCorpus：7,000 多本未出版的书 WebText：Reddit 上获得至少 3 karma 的外链网页 过滤后的 Common Crawl + WebText2 + Books1/2 + 英文维基
规模 报告未给 token 数 800 多万篇文档，40 GB 300B token（训练量）

GPT-1 选书籍，是因为书里有长段连续的文本，能学到长距离的依赖；报告特意对比了 1B Word Benchmark，那个数据集在句子级别被打乱，长程结构被破坏了 2。GPT-2 想要更大、更杂的数据，又不想要网页爬虫里的大量低质内容，办法见下面的小故事。GPT-3 需要的数据多得多（光是过滤后的 Common Crawl 就有 570 GB，是 WebText 的 14 倍），只能用全网爬虫，于是需要系统的过滤。

小故事 · 用 Reddit 的点赞当筛子

2019 年的 GPT-2 没有训练任何质量分类器，而是借了网友的眼光：只收 Reddit 用户分享、并且至少得到 3 个 karma 的外链，把“有人觉得值得看”当成质量信号；只收 2017 年 12 月之前的链接，去重与清洗后得到 800 多万篇文档、40 GB 文本；还删掉了全部维基百科文档，以免与评测集重叠 5。

质量过滤：分类器打分，再按分数抽样

含义。 质量过滤（quality filtering）：给每篇文档一个“像不像高质量文本”的分数，按分数决定留不留。

理解。 GPT-3 训练了一个逻辑回归分类器：正例是 WebText 等精选语料，负例是未经过滤的 Common Crawl。分类器输出一个分数 \(s\in[0,1]\)，越接近 1 越像精选语料 4。但它没有简单地设一个阈值，而是做了一次随机抽样。

数学。 附录 A 的规则写成代码是 np.random.pareto(α) > 1 − document_score，\(\alpha=9\) 4。大家先猜一猜：分类器给一篇文档打了 0.5 分，也就是“一半像精选语料”，它被留下的概率是多少？一半？

要回答它，只需要知道这个随机数的分布。

保留概率的推导
(1)\(\displaystyle X\sim\text{Lomax}(\alpha):\ P(X>x)=(1+x)^{-\alpha},\ x\ge0\)NumPy 的 pareto(α) 抽的是 Lomax（第二类 Pareto）分布，这是它的生存函数
(2)\(\displaystyle P(\text{保留}\mid s)=P(X>1-s)\)附录 A 的保留规则
(3)\(\displaystyle =\big(1+(1-s)\big)^{-\alpha}=(2-s)^{-\alpha}\)代入生存函数，\(1-s\in[0,1]\) 满足 \(x\ge0\)
GPT-3 质量过滤的保留概率\[P(\text{保留}\mid s)=(2-s)^{-9},\qquad s\in[0,1]\]\(s=1\) 时为 1；\(s=0\) 时为 \(2^{-9}=1/512\approx0.2\%\)。用 200 万次随机模拟可以核对这个公式。(2.8)

代进去：\(s=0.5\)，\((2-0.5)^{-9}=1.5^{-9}=0.026\)。只有 2.6%，远不是一半。

三篇文档的命运

分类器给三篇文档打分 0.9、0.5、0.1。保留概率分别是 \(1.1^{-9}=0.424\)、\(1.5^{-9}=0.026\)、\(1.9^{-9}=0.0031\)。也就是说，分数 0.9 的文档有四成机会留下，分数 0.5 的只有 2.6%，分数 0.1 的约千分之三。曲线非常陡：分数从 0.5 升到 0.9，保留概率涨了 16 倍。

去重：MinHash 找“几乎一样”的文档

问题。 开头说的“搬运”：同一篇文章会被转载、镜像、加个页眉页脚再发一遍。完全相同的副本用哈希就能找到，“几乎一样”的却不行。重复的文档等于被悄悄提高了采样权重，还白占了训练算力。

含义。 模糊去重（fuzzy deduplication）：把内容高度重合的文档当成重复，只留一份。

怎么量“几乎一样”？我们在黑板上拿两句话玩一个小游戏。

黑板上 · 两句几乎一样的话

A：“今天天气很好”；B：“今天天气很热”。把每句切成相邻两个字的片段：

  • A 的片段：{今天, 天天, 天气, 气很, 很好}，5 个；
  • B 的片段：{今天, 天天, 天气, 气很, 很热}，5 个。

两边共有的有 4 个（交集），合起来一共 6 个不同的片段（并集）。交集除以并集，\(4/6\approx0.667\)，这就是两句话的 Jaccard 相似度。

现在做个游戏：把这 6 个片段随机排一次队，看 A、B 各自排最前的是谁。如果全队第一是“今天”，它两边都有，A、B 的“领头”相同；如果全队第一是“很好”，A 的领头是它，B 里却没有它，两边不同。6 个片段站第一的机会均等，其中 4 个是共有的，所以“领头相同”的概率正好是 \(4/6\)，等于 Jaccard 相似度。

这个游戏就是 MinHash。理解。 直接两两比较 \(n\) 篇文档要 \(n^2/2\) 次，几亿篇文档做不到。MinHash 给每篇文档算一个很短的“签名”（就是游戏里的“领头”），签名相同的概率恰好等于 Jaccard 相似度，于是只需比较签名，再用局部敏感哈希（LSH）把签名相近的文档分到同一个桶里。GPT-3 用 Spark 的 MinHashLSH、10 个哈希，在每个数据集内部去重，并从 Common Crawl 里去掉与 WebText 重复的文档，数据量平均减少了 10% 4。

数学。 设文档的片段集合为 \(A\)、\(B\)。取一个随机的哈希 \(h\)（把每个片段映射成一个互不相同的数），定义签名 \(m(A)=\min_{a\in A}h(a)\)。下面的推导用理想化的假设：\(h\) 等价于把所有片段均匀随机地排一个次序，没有并列（实际的哈希函数只是近似满足这一点）。

MinHash 的碰撞概率等于 Jaccard 相似度
(1)\(\displaystyle e^\star=\argmin_{e\in A\cup B}h(e)\)并集里哈希值最小的那个元素；\(h\) 是均匀随机的次序，所以它等于并集中任何一个元素的概率都相同，为 \(1/\lvert A\cup B\rvert\)
(2)\(\displaystyle e^\star\in A\cap B\ \Rightarrow\ m(A)=m(B)=h(e^\star)\)\(e^\star\) 同时在两个集合里，是两边共同的最小值
(3)\(\displaystyle e^\star\in A\setminus B\ \Rightarrow\ m(A)=h(e^\star)<m(B)\)它只在 \(A\) 里；\(B\) 的最小值来自别的元素，而且更大（反之亦然）
(4)\(\displaystyle P\big(m(A)=m(B)\big)=\frac{\lvert A\cap B\rvert}{\lvert A\cup B\rvert}\)两个签名相等当且仅当 \(e^\star\) 落在交集里
MinHash 与 Jaccard 相似度\[J(A,B)=\frac{\lvert A\cap B\rvert}{\lvert A\cup B\rvert}=P\big(m(A)=m(B)\big)\]用 \(k\) 个独立的哈希，签名相等的比例就是 \(J\) 的一个无偏估计。(2.9)

代回黑板：\(\lvert A\cap B\rvert=4\)，\(\lvert A\cup B\rvert=6\)，\(P=4/6=0.667\)。我用 20 万次随机排队模拟了一下，领头相同的比例是 0.667。对得上。

两篇转载文章

两篇文章各切成 90 个片段，其中 80 个相同：\(\lvert A\cap B\rvert=80\)，\(\lvert A\cup B\rvert=90+90-80=100\)，\(J=0.8\)。用 10 个哈希，平均会有 8 个签名相等；一篇无关文章与它们共享 2 个片段，\(J=2/178\approx0.011\)，10 个签名里平均只有 0.1 个相等。只看 10 个数，就能把这两种情况分开。

配比：不按大小比例采样

五个数据集并不是按大小混在一起。GPT-3 给每个数据集一个采样权重 \(w_k\)，训练时按这些权重从各数据集抽取文本，高质量的数据集因此被重复采样 4。每个数据集被看了几遍，由权重和它的大小共同决定。还是先上黑板。

黑板上 · 两个数据集的配比

假设只有两个数据集：“书”10B token，“网页”100B token。训练一共读 100B token，采样权重定成书 30%、网页 70%。

  • 书：读了 \(0.3\times100=30\)B token，可书只有 10B，相当于从头到尾读了 \(30/10=3\) 遍；
  • 网页：读了 \(0.7\times100=70\)B token，网页有 100B，只读了 \(70/100=0.7\) 遍。

同一次训练，书被读了 3 遍，网页连一遍都没读完。

把黑板上的“30%、100B、10B”换成字母：

数据集被看的遍数（epoch）\[e_k=\frac{w_k\cdot D}{q_k}\]\(w_k\)：第 \(k\) 个数据集的采样权重；\(D\)：训练总 token 数（GPT-3 为 300B）；\(q_k\)：该数据集的 token 数。\(e_k<1\) 表示没看完，\(e_k>1\) 表示重复看。(2.10)

代回黑板：\(e_{\text{书}}=0.3\times100/10=3\)，\(e_{\text{网页}}=0.7\times100/100=0.7\)。对得上。

很多人以为：GPT-3 把它的数据完整地过了一遍（一个 epoch）

很多人以为：GPT-3 训练了 300B 个 token，就是把它的数据集从头到尾读了一遍。

其实：300B token 是训练量，不是数据量。五个数据集合计 499B token，Common Crawl 只被看了 0.44 遍，维基被看了 3.4 遍（表 2.2）。论文附录 C 也说，模型只在过滤后 Common Crawl 文档的 40% 上训练过 4。就像黑板上的书和网页，“epoch”在大模型预训练里不再是一个统一的数，每个数据源有自己的遍数。

去污染：别让考题混进课本

考前泄题的后果大家都知道：分数再高也说明不了水平。模型也一样。

含义。 去污染（decontamination）：从训练数据里删掉与评测基准重叠的内容，否则模型在“考试”时可能只是在背诵见过的题。

GPT-3 用 13-gram 重叠来找这类文档并删除，但论文承认过滤代码有一个 bug，导致部分重叠没有被删掉，而由于训练成本太高没有重训，只能在附录 C 里逐个基准分析污染的影响 4。这是一个真实的失败模式：数据管线里的一个 bug，可以让一项耗资巨大的训练在评测上留下永久的疑问。

失败模式：数据决定了损失的“意义”

§2 说交叉熵的底是文本自身的熵。换一份语料，这个底、以及整条损失曲线都会变：去重、过滤、配比都会改变“真实分布” \(q\)。所以不同语料上训练的模型，损失数字不能直接比较；§7 的规模化规律拟合出来的常数，也只对它所用的那份数据和那个分词器成立。第 6 课会看到，DeepSeek LLM 发现连“最优的模型/数据分配”都会随数据质量改变：数据越好，越该把算力分给模型 9。

最后两道工序在前两页已经讲过：分词用第 1 课的字节级 BPE（词表 50,257），然后把文档首尾相接、用 <|endoftext|> 分隔，切成长 2048 的序列（§3），再凑成每步 3.2M token 的 batch。

这一页讲了三件事
  • 第一，吃什么就长什么。 语料决定了交叉熵在逼近哪个分布；GPT 三代的数据从书籍（长文本）到“人工点赞筛选的网页”再到“分类器过滤的全网爬虫”。
  • 第二，过滤与去重。 GPT-3 的质量过滤按 \((2-s)^{-9}\) 随机保留文档（0.5 分只留 2.6%）；去重用 MinHash，签名相等的概率等于 Jaccard 相似度（黑板上 \(4/6\)）；数据量平均减少 10%。
  • 第三，配比与去污染。 采样权重不按大小比例，数据集被看的遍数 \(e_k=w_kD/q_k\)：高质量数据看 2–3 遍，Common Crawl 只看 0.44 遍（黑板上书 3 遍、网页 0.7 遍）。去污染用 13-gram 重叠，GPT-3 的过滤有 bug 且未重训。

优化：AdamW、学习率调度与梯度裁剪

大家洗澡调水温都有经验。刚打开热水器，水忽冷忽热，你不敢猛拧；水温快合适了，你越拧越轻；偶尔水温突然一跳，你也不会跟着猛拧一大圈。还有：冷水龙头很灵、热水龙头很钝的话，你对两个龙头自然用两种拧法。

这几个习惯，恰好对应这一页的几样工具。§3 给了我们梯度 \(\mathbf g_s=\nabla_\theta\mathcal L(\theta_s)\)，它指向损失上升最快的方向。最朴素的做法是沿反方向走一小步：

随机梯度下降（SGD）\[\theta_{s+1}=\theta_s-\eta\,\mathbf g_s\]\(\eta>0\) 是学习率（learning rate），一个标量；“随机”是因为 \(\mathbf g_s\) 只来自一个 batch，是全语料梯度的一个带噪声的估计。(2.11)

这一行公式放到一个有 1750 亿参数的模型上，会出什么事？先上黑板。

黑板上 · 一个步长管两个参数

两个参数，一个的梯度是 100（像那个很灵的冷水龙头），一个的梯度是 0.01（像那个很钝的热水龙头）。学习率 \(\eta=0.01\)：

  • 第一个参数一步走 \(0.01\times100=1\)；
  • 第二个参数一步走 \(0.01\times0.01=0.0001\)。

同一个 \(\eta\)，一个被推出去一大截，一个几乎纹丝不动。把 \(\eta\) 调大，第一个会飞；调小，第二个永远走不到地方。

这就是 (2.11) 的第一个毛病，真实模型里一共有四个。第一，一个 \(\eta\) 管所有参数：嵌入表、LayerNorm 的增益、注意力的投影矩阵，梯度的典型大小可以相差很多（罕见 token 的那一行输入嵌入，只要这个 batch 里没出现它，从输入端传回的梯度就是 0；像 GPT-2 那样与反嵌入共享权重时，输出端也只传回一点与它很小的概率 \(p_k\) 成正比的梯度），同一个步长对有的太大、对有的太小。第二，噪声：每步只看 3.2M 个 token，梯度方向会抖。第三，起步不稳：刚初始化时模型和优化器的状态都很“生”，大步长容易把训练带崩。第四，偶发的巨大梯度：一个坏 batch 就能产生一次很长的梯度，一步把参数推飞。这一页的四样工具各治一个：Adam（前两个，每个龙头用自己的拧法）、学习率调度（第三个）、梯度裁剪（第四个），再加上权重衰减做正则。数学的系统讲法见 M07 §4（Adam 与 AdamW）和 M07 §5（调度、batch 与裁剪）。

类比：在雾里下山

映射。 损失曲面是一片山地，参数 \(\theta\) 是你站的位置，损失是海拔。梯度 = 脚下的坡度，而且雾很大，只看得清脚边一小块（每步只用一个 batch 估计）；学习率 = 步长；动量 \(\mathbf m\) = 惯性，沿着一直在下坡的方向继续走，不被一块小石头带偏；Adam 的 \(\sqrt{\hat{\mathbf v}}\) = 按每个方向“地面有多颠簸”调整步子，颠簸的方向小心迈，平缓的方向大胆迈；warmup = 天刚亮、什么都看不清时先小步试探；余弦衰减 = 接近谷底时步子越迈越小，才能停在底上，而不是来回跨过它；梯度裁剪 = 踩到松石猛地一滑时，限制这一下最多滑多远；权重衰减 = 腰上系一根松紧带，一直把你往原点轻轻拉。

收益。 四个毛病各对应一个直观的动作，也说明了这些工具为什么能叠在一起用：它们管的是不同的事（方向、每个方向的尺度、随时间变化的步长、偶发的冲击）。

但是这个比方有两个地方不对。 第一，真实的“山”有上千亿个方向，不是三维的地形；Adam 的“颠簸程度”是逐坐标算的，只沿参数自己的坐标轴调整步子，斜着走向的沟壑它看不出来。第二，这里的“惯性”和“颠簸程度”不是一个人的一种感觉，而是给每个参数各记一份：\(\mathbf m\)、\(\mathbf v\) 都和参数一样大，这就是 Adam 要额外存两份参数量大小的状态的原因（§6 算它占多少字节）。

Adam：给每个参数配一个自己的步长

含义。 Adam（adaptive moment estimation）：对每个参数分别维护“梯度的滑动平均”和“梯度平方的滑动平均”，用前者当方向、用后者的平方根给步长做归一化。

理解。 滑动平均（exponential moving average）就是“新值占一小份、旧的平均占一大份”地不断更新，它把最近若干步的梯度平均起来，抖动被抵消，方向更稳：这叫动量。梯度平方的滑动平均则记录这个参数的梯度“通常有多大”。用平均梯度除以典型大小，得到的是一个“以自己的尺度衡量”的无量纲方向，每个参数于是走大小相近的步子。

好，我们在黑板上跟着一个参数走两步。

黑板上 · 一个参数的两步 Adam

取 GPT-3 的 \(\beta_1=0.9\)、\(\beta_2=0.95\)，学习率 \(\eta=0.01\)（为了数字好看，比 GPT-3 的大），参数初值 \(\theta_0=1\)。第 1 步的梯度是 0.2，第 2 步是 0.1。每一步都做同样的四件事：更新两个滑动平均 \(m\)、\(v\)；除以修正因子；算方向 \(\hat m/\sqrt{\hat v}\)；走一步。

第 1 步（\(g=0.2\)） 第 2 步（\(g=0.1\)）
\(m\leftarrow0.9\,m+0.1\,g\) \(0+0.1\times0.2=0.02\) \(0.9\times0.02+0.1\times0.1=0.028\)
\(v\leftarrow0.95\,v+0.05\,g^2\) \(0+0.05\times0.04=0.002\) \(0.95\times0.002+0.05\times0.01=0.0024\)
\(\hat m=m/(1-0.9^{t})\) \(0.02/0.1=0.2\) \(0.028/0.19=0.1474\)
\(\hat v=v/(1-0.95^{t})\) \(0.002/0.05=0.04\) \(0.0024/0.0975=0.02462\)
方向 \(\hat m/\sqrt{\hat v}\) \(0.2/0.2=1.000\) \(0.1474/0.1569=0.939\)
\(\theta\leftarrow\theta-\eta\times\text{方向}\) \(1-0.01=0.99\) \(0.99-0.00939=0.9806\)

我们停下来看两件事。第一，第 1 步的 \(m=0.02\) 只有真实梯度 0.2 的十分之一：滑动平均从 0 起步，被 0 拉低了；除以 \(1-0.9=0.1\) 之后才回到 0.2。第二，梯度从 0.2 变成 0.1，小了一半，可每步走的距离几乎没变：方向是 1.000 和 0.939，不是 0.2 和 0.1。

现在把黑板上的两步写成一般公式。下面对每个参数逐元素进行（\(\mathbf g_t^2\) 表示逐元素平方）。按 Adam 论文的习惯，本页的下标 \(t\) 表示第 \(t\) 个优化步（就是 (2.11) 里的 \(s\)），不是 §2、§3 里的 token 位置：

Adam 的两个滑动平均\[\mathbf m_t=\beta_1\mathbf m_{t-1}+(1-\beta_1)\,\mathbf g_t,\qquad \mathbf v_t=\beta_2\mathbf v_{t-1}+(1-\beta_2)\,\mathbf g_t^2,\qquad \mathbf m_0=\mathbf v_0=\mathbf 0\]\(\mathbf m_t\)：一阶矩（梯度的平均）；\(\mathbf v_t\)：二阶矩（梯度平方的平均）；\(\beta_1,\beta_2\in[0,1)\) 是衰减率，GPT-3 取 \(\beta_1=0.9\)、\(\beta_2=0.95\) 4。(2.12)

两个平均都从 0 起步，前几步会被 0 拉低，黑板上第 1 步已经看到了。拉低了多少？怎么修正？我们推一下。

偏差修正从哪里来
(1)\(\displaystyle \mathbf m_t=(1-\beta_1)\sum_{k=1}^{t}\beta_1^{\,t-k}\,\mathbf g_k\)把 (2.12) 从 \(\mathbf m_0=\mathbf 0\) 展开 \(t\) 次
(2)\(\displaystyle \E[\mathbf m_t]=(1-\beta_1)\sum_{k=1}^{t}\beta_1^{\,t-k}\,\E[\mathbf g]\)设各步梯度的期望都是同一个 \(\E[\mathbf g]\)（近似平稳）
(3)\(\displaystyle =(1-\beta_1)\,\frac{1-\beta_1^{t}}{1-\beta_1}\,\E[\mathbf g]=(1-\beta_1^{t})\,\E[\mathbf g]\)等比数列求和 \(\sum_{j=0}^{t-1}\beta_1^j=\frac{1-\beta_1^t}{1-\beta_1}\)
(4)\(\displaystyle \hat{\mathbf m}_t=\mathbf m_t/(1-\beta_1^{t})\ \Rightarrow\ \E[\hat{\mathbf m}_t]=\E[\mathbf g]\)除以这个因子就去掉了偏差；\(\mathbf v_t\) 同理，除以 \(1-\beta_2^{t}\)
Adam 的更新\[\hat{\mathbf m}_t=\frac{\mathbf m_t}{1-\beta_1^{t}},\qquad \hat{\mathbf v}_t=\frac{\mathbf v_t}{1-\beta_2^{t}},\qquad \theta_t=\theta_{t-1}-\eta_t\,\frac{\hat{\mathbf m}_t}{\sqrt{\hat{\mathbf v}_t}+\epsilon}\]\(\epsilon\) 是防止除以 0 的小常数，GPT-3 取 \(10^{-8}\) 4；\(\eta_t\) 是第 \(t\) 步的学习率（下文的调度给出）。(2.13)

代回黑板：\(t=1\) 时修正因子是 \(1-0.9=0.1\) 和 \(1-0.95=0.05\)，\(t=2\) 时是 \(1-0.81=0.19\) 和 \(1-0.9025=0.0975\)，正是表里除的那几个数。

Adam 的步长与梯度的尺度无关

取 GPT-3 的 \(\beta_1=0.9\)、\(\beta_2=0.95\)，看一个参数的前三步。

  • 梯度恒为 \(0.01\)：\(\mathbf m_1=0.001\)，\(\mathbf v_1=5\times10^{-6}\)；修正后 \(\hat m_1=0.01\)，\(\hat v_1=10^{-4}\)，\(\hat m_1/\sqrt{\hat v_1}=1.0\)。第 2、3 步也都是 \(1.0\)。
  • 梯度恒为 \(100\)（大一万倍）：\(\hat m_t=100\)，\(\hat v_t=10^4\)，比值仍是 \(1.0\)。两种情况每步都走 \(\eta_t\) 那么远。
  • 梯度正负交替 \(+10^{-3},-10^{-3},+10^{-3}\)：比值依次为 \(1.0\)、\(-0.053\)、\(0.336\)。方向来回翻转时，一阶矩互相抵消，步子自动变小。

如果不做偏差修正，第一步的比值是 \((1-\beta_1)/\sqrt{1-\beta_2}\)：GPT-3 的设置下为 \(0.1/\sqrt{0.05}=0.447\)；用 Adam 的默认值 \(\beta_2=0.999\) 则是 \(0.1/\sqrt{0.001}=3.16\)，第一步就走了三倍多的步长。

回到那两个龙头：梯度 100 和梯度 0.01 的参数，在 Adam 下每步都走约 \(\eta\) 那么远，“一个飞了、一个不动”的毛病就治好了。

权重衰减与 AdamW：为什么要“解耦”

含义。 权重衰减（weight decay）：每一步都把所有权重按一个小比例往 0 拉，防止权重无节制地变大，是一种正则化。最早的写法是 \(\theta_{t+1}=(1-\lambda)\theta_t-\alpha\nabla f_t(\theta_t)\) 10，其中 \(f_t\) 是第 \(t\) 步那个 batch 上的损失（沿用 AdamW 论文的记号），\(\alpha\) 是学习率。

理解。 在普通的 SGD 里，权重衰减和“往损失里加一项 \(\tfrac{\lambda'}{2}\norm{\theta}^2\)”（L2 正则）是一回事：L2 项的梯度是 \(\lambda'\theta\)，走一步就是把 \(\theta\) 乘上 \((1-\alpha\lambda')\)。所以很多代码把权重衰减实现成“往梯度里加 \(\lambda'\theta\)”。

那么问题来了：换成 Adam，还等价吗？大家想一想，\(\lambda'\theta\) 加进梯度以后要经过谁？对，经过两个滑动平均，最后被 \(\sqrt{\hat{\mathbf v}_t}\) 除一次。Loshchilov 与 Hutter 指出：这个等价性在 Adam 里不成立 10。

在 Adam 里，L2 正则不等于权重衰减
(1)\(\displaystyle \mathbf g_t\leftarrow\nabla f_t(\theta)+\lambda'\theta\)“Adam + L2”：把 L2 项的梯度加进梯度
(2)\(\displaystyle \hat{\mathbf m}_t\approx\overline{\nabla f}+\lambda'\theta\)\(\overline{\nabla f}\) 记损失梯度的滑动平均；设 \(\theta\) 变化慢，L2 那一部分在滑动平均里几乎不变
(3)\(\displaystyle \Delta\theta\approx-\eta_t\frac{\overline{\nabla f}}{\sqrt{\hat{\mathbf v}_t}}-\eta_t\frac{\lambda'\theta}{\sqrt{\hat{\mathbf v}_t}}\)代入 (2.13)，忽略 \(\epsilon\)；再设 \(\lambda'\theta\) 比损失的梯度小得多，于是 \(\hat{\mathbf v}_t\) 仍由损失的梯度决定。第二项是 L2 带来的收缩
(4)\(\displaystyle \text{每步收缩比例}\approx\eta_t\lambda'/\sqrt{\hat{\mathbf v}_t}\)与该参数自己的梯度尺度成反比，每个参数都不一样

最后一行就是问题所在：梯度一贯很大的参数（\(\sqrt{\hat v}\) 大），L2 几乎拉不动它；梯度很小的参数反而被拉得很狠。论文的原话是，梯度大的权重 “do not get regularized as much”，并证明了对 Adam 这类自适应方法，不存在任何 L2 系数能等价于解耦的权重衰减（命题 2）10。解决办法是把衰减从梯度里拿出来，直接作用在参数上，这就是 AdamW。

AdamW 的一步（完整写法）\[\theta_t=\theta_{t-1}-\eta_t\left(\frac{\hat{\mathbf m}_t}{\sqrt{\hat{\mathbf v}_t}+\epsilon}+\lambda\,\theta_{t-1}\right)\]\(\hat{\mathbf m}_t,\hat{\mathbf v}_t\) 只用损失的梯度算；衰减项 \(\lambda\theta_{t-1}\) 不经过它们，每个参数按同一比例 \(\eta_t\lambda\) 收缩。(2.14)
黑板上 · 给那两步加上权重衰减

还是黑板上那个参数，取 \(\lambda=0.1\)，按 (2.14) 再走一遍：

  • 第 1 步：方向仍是 1.000，衰减项 \(\lambda\theta_0=0.1\times1=0.1\)，\(\theta_1=1-0.01\times(1.000+0.1)=0.989\)；
  • 第 2 步：方向仍是 0.939（\(\hat m\)、\(\hat v\) 只用损失的梯度算，衰减碰不到它们），衰减项 \(\lambda\theta_1=0.0989\)，\(\theta_2=0.989-0.01\times(0.939+0.0989)=0.9786\)。

和纯 Adam 的 0.99、0.9806 相比，每步多往 0 拉了约 \(\eta\lambda\theta\approx0.001\)。这一拉对每个参数都是同一个比例 \(\eta\lambda\)，与它的梯度多大无关。

很多人以为：往梯度里加一项 λθ，就是权重衰减

很多人以为：L2 正则和权重衰减是一回事，所以在 Adam 里把 \(\lambda\theta\) 加进梯度，就等于做了权重衰减。

其实：只有在 SGD 里两者等价。在 Adam 里，加进梯度的 \(\lambda\theta\) 会被 \(\sqrt{\hat{\mathbf v}_t}\) 除一次，梯度越大的参数被拉得越少，而且没有任何 L2 系数能补回来 10。要按同一比例往 0 拉，衰减就得像 (2.14) 那样放在归一化之外。

AdamW 里的每个符号
  • \(\theta_{t-1}\in\R^{N}\)：更新前的参数；\(\mathbf g_t\in\R^N\)：本步（裁剪后）的梯度。
  • \(\mathbf m_t,\mathbf v_t\in\R^N\)：两个滑动平均，和参数一样大，是优化器的状态（每个参数多存两个数）。
  • \(\beta_1,\beta_2\)：滑动平均的衰减率；\(\beta_1^{t}\) 是 \(\beta_1\) 的 \(t\) 次方（不是上标编号）。
  • \(\epsilon\)：防止除以 0；\(\lambda\)：权重衰减系数；\(\eta_t\)：第 \(t\) 步的实际学习率。
  • 本课采用 PyTorch 的参数化：\(\eta_t\) 已包含调度，衰减项每步收缩 \(\eta_t\lambda\)。
“权重衰减 0.1”是哪一种 0.1？

AdamW 论文的算法 2 写的是 \(\theta_t\leftarrow\theta_{t-1}-\eta_t\big(\alpha\hat m_t/(\sqrt{\hat v_t}+\epsilon)+\lambda\theta_{t-1}\big)\)：\(\alpha\) 是基础学习率，\(\eta_t\) 只是调度的乘子，衰减项不乘 \(\alpha\) 10。PyTorch 的实现却是先 param.mul_(1 - lr * weight_decay)，其中 lr 是含调度的实际学习率 11，也就是 (2.14)。同一个 \(\lambda=0.1\)，在两种约定下每步的收缩量相差一个 \(\alpha\) 的倍数。GPT-3 写的“weight decay of 0.1”属于哪一种，论文没有说 4。读别人的超参数时，先问清约定。

GPT-3 的权重衰减每步收缩多少

按 PyTorch 约定，峰值学习率 \(\eta=6\times10^{-5}\)、\(\lambda=0.1\) 时，每步把每个权重乘以 \(1-\eta\lambda=1-6\times10^{-6}\)。假如学习率一直停在峰值、梯度又恰好为 0，走完 93,750 步后权重变成原来的 \((1-6\times10^{-6})^{93750}=0.570\)。实际学习率会按调度降下来，梯度也不为 0，所以这只是量级：权重衰减是一股很弱、但一直在起作用的力。

小故事 · 一篇论文的两个题目

AdamW 的论文 2017 年 11 月第一次挂上 arXiv 时，题目叫 “Fixing Weight Decay Regularization in Adam”，直译就是“修好 Adam 里的权重衰减”；现在的版本题为 “Decoupled Weight Decay Regularization” 10。GPT-1 在 2018 年用的一种 “modified version of L2 regularization”，引用的正是这第一版，系数 0.01 2。GPT-3 用 Adam 加权重衰减 0.1，同样引用这篇论文 4。Chinchilla 把 Gopher 用的 Adam 换成 AdamW，发现 AdamW 的模型要到余弦周期约 80% 处才超过 Adam 的模型，但最终明显更好 7。

学习率调度：先升温，再慢慢降

问题。 (2.13) 里的 \(\eta_t\) 不是常数。就像刚打开的热水器，训练开始时直接用大学习率，模型常常一上来就发散；训练后期还用大学习率，参数会在最低点附近来回跳，损失降不下去。

含义。 学习率调度（learning-rate schedule）：规定 \(\eta_t\) 随训练进度怎么变。GPT-1 和 GPT-3 都用线性预热（warmup：从 0 线性升到峰值）加余弦衰减（cosine decay：沿半个余弦波降下来）；GPT-2 没有报告它的调度。

为什么要 warmup。 一个直接的证据来自 Xiong 等人：Post-LN 的 Transformer 在 IWSLT14 德英翻译上，不用 warmup 时 Adam 训练出的 BLEU 只有 8.45，用了 warmup 约为 34；他们的分析是，Post-LN 在初始化时靠近输出层的参数梯度很大，一上来就用大学习率会不稳定，而改用第 1 课讲的 Pre-LN 后可以去掉 warmup 12。他们还发现 SGD 同样需要 warmup，所以 warmup 并不只是为了等 Adam 的二阶矩估计变准 12。GPT-3 是 Pre-LN 结构，却仍然用了 warmup；笔者的理解是，它便宜，又能多挡一层训练初期的风险。

第一个公式实例。 Transformer 原论文的学习率是

Transformer 原论文的学习率\[\eta(s)=d^{-0.5}\cdot\min\!\big(s^{-0.5},\ s\cdot s_w^{-1.5}\big)\]\(s\) 是步数，\(s_w\) 是 warmup 步数（原论文 4000），\(d\) 是模型维度（base 模型 512）8。(2.15)
(2.15) 在哪里转弯、峰值多高

GPT 系列用的是另一种形状：先直线升温，再沿半个余弦波降下来。我们先在黑板上画一个只有十几步的小调度，看清它的形状。

黑板上 · 一个十步的调度

峰值 \(\eta_{\max}=1\)（就当是“1 个单位”），最低 \(\eta_{\min}=0.1\)，前 \(s_w=2\) 步升温，余弦段到第 \(s_c=10\) 步结束。

  • 升温段：\(\eta(1)=1\times\frac12=0.5\)，\(\eta(2)=1\)，一条直线爬上去。
  • 余弦段：记 \(\tau=(s-2)/8\)，它从 0 走到 1；\(\eta=0.1+\frac{1-0.1}{2}(1+\cos\pi\tau)=0.1+0.45\,(1+\cos\pi\tau)\)。

    • 第 6 步：\(\tau=0.5\)，\(\cos90^\circ=0\)，\(\eta=0.1+0.45=0.55\)，正好在峰值和最低值的正中间；
    • 第 8 步：\(\tau=0.75\)，\(\cos135^\circ=-0.707\)，\(\eta=0.1+0.45\times0.293=0.232\)；
    • 第 10 步：\(\tau=1\)，\(\cos180^\circ=-1\)，\(\eta=0.1\)。
  • 第 10 步以后：一直停在 0.1。

大家看降的速度：第 2 到第 4 步只降 0.13，第 4 到第 6 步降 0.32，第 8 到第 10 步又只降 0.13。这就是余弦的形状。

好，把 2 换成 \(s_w\)，把 10 换成 \(s_c\)，把 1 和 0.1 换成 \(\eta_{\max}\) 和 \(\eta_{\min}\)：

线性 warmup + 余弦衰减\[\eta(s)=\begin{cases}\eta_{\max}\,\dfrac{s}{s_w}, & s\le s_w\\[2mm]\eta_{\min}+\dfrac{\eta_{\max}-\eta_{\min}}{2}\Big(1+\cos\big(\pi\tau\big)\Big),\ \ \tau=\dfrac{s-s_w}{s_c-s_w}, & s_w<s\le s_c\\[2mm]\eta_{\min}, & s>s_c\end{cases}\]\(\tau\) 从 0 走到 1 时，\(\tfrac12(1+\cos\pi\tau)\) 从 1 平滑地降到 0：开头和结尾降得慢，中间降得快。(2.16)

代回黑板：\(s=6\)，\(\tau=(6-2)/(10-2)=0.5\)，\(\eta=0.1+\tfrac{0.9}{2}(1+0)=0.55\)。对，0.55。

三代 GPT 的取值：GPT-1 用最大学习率 \(2.5\times10^{-4}\)，前 2000 次更新线性升温，再余弦退火到 0 2。Kaplan 等人的实验用 3000 步 warmup 加余弦到 0 6。GPT-3 按 token 数而不是步数计：前 375M token 线性升温，然后余弦降到峰值的 10%，历时 260B token，之后保持 10% 直到 300B；175B 模型的峰值是 \(0.6\times10^{-4}\) 4。论文只给了文字描述，(2.16) 是本课按文字写出的公式（余弦段从 warmup 结束处算起，这一点论文没有明说）。

GPT-3 在第 130B 个 token 时的学习率

\(\tau=(130-0.375)/(260-0.375)=0.49928\)，\(\cos(\pi\times0.49928)=0.0023\)，

\[\eta=6\times10^{-5}\times\Big[0.1+0.9\times\tfrac12(1+0.0023)\Big]=6\times10^{-5}\times0.551=3.31\times10^{-5}.\]

失败模式：步数、token 数与 batch 渐增

GPT-3 的 batch 不是一开始就是 3.2M：它在前 4–12B 个 token 里从 32k token 线性增加到满值（依模型大小而定）4。如果按满 batch 算，375M token 的 warmup 只有 \(375\text{M}/3.2\text{M}\approx117\) 步，可实际上 warmup 全部落在 batch 还很小的阶段，步数要多得多。所以“按 token 计”的调度无法精确换算成步数，论文也没有给出。复现别人的训练时，调度的单位（步还是 token）和 batch 的变化方式都要问清。

梯度裁剪：给步长加一个上限

含义。 梯度裁剪（gradient clipping）：如果整个梯度向量太长，就把它等比例缩短到一个上限。

理解。 偶尔一个 batch 会产生一个异常大的梯度，就像水温突然一跳。对不带归一化的 SGD (2.11)，这是直接的灾难：步长正比于梯度，100 倍的梯度就是 100 倍的一步。Adam 的归一化已经限制了单步的大小，但尖峰会写进两个滑动平均：\(\mathbf v\) 被放大几百倍，要上百步才降回来，这期间正常的更新都被压小；\(\mathbf m\) 在之后十几步里主要由这一个坏 batch 决定方向（本节第二个例题算给你看）。裁剪在梯度进入 \(\mathbf m\)、\(\mathbf v\) 之前就把它等比例缩短，只改长度、不改方向，两个滑动平均都不受污染。

数学。 把所有参数的梯度拼成一个向量，算它的 L2 范数（全局范数）：

按全局范数裁剪\[\norm{\mathbf g}=\sqrt{\sum_{i=1}^{N}g_i^2},\qquad \mathbf g\leftarrow\mathbf g\cdot\min\!\Big(1,\ \frac{c}{\norm{\mathbf g}}\Big)\]\(c\) 是阈值，GPT-3 取 1.0 4。\(\norm{\mathbf g}\le c\) 时不变；超过时整个向量乘以同一个系数 \(c/\norm{\mathbf g}<1\)。(2.17)
黑板上 · 裁剪只改长度

两个参数的梯度 \(\mathbf g=(3,4)\)，\(\norm{\mathbf g}=5>1\)，系数 \(1/5\)，裁剪后 \((0.6,0.8)\)：方向不变，长度为 1。如果改成“每个分量各自截到 \([-1,1]\)”，结果是 \((1,1)\)，方向从 \(53^\circ\) 变成了 \(45^\circ\)。这就是为什么用全局范数：它不扭曲梯度的方向。

一次梯度尖峰：不裁剪与裁剪

取 GPT-3 的 \(\beta_1=0.9\)、\(\beta_2=0.95\)，看一个参数：它每步的梯度都一样大，训练早已走稳。为了好算，把它平时的梯度当作 1 个单位，于是 \(\hat m\approx m=1\)，\(\hat v\approx v=1\)，每步走 \(\eta\)。（它的真实值当然远小于下面的全局范数 0.5，因为全局范数至少和任何一个分量一样大；但前面“Adam 的步长与梯度的尺度无关”那个例题说明，把一个参数的整串梯度同乘一个常数，\(\hat m/\sqrt{\hat v}\) 不变（忽略 \(\epsilon\)），所以用什么单位都不影响结果。）某一步来了一个坏 batch，所有梯度同时放大 100 倍。设平时的全局范数是 0.5，这一步变成 50，超过阈值 \(c=1\)，裁剪把整个梯度乘以 \(1/50\)，这个参数的梯度从 100 个单位变成 2 个单位。按 (2.12)–(2.13) 逐步算 \(\hat m/\sqrt{\hat v}\)，也就是每步走了几个 \(\eta\)：

这一页讲了三件事
  • 第一，Adam 给每个参数配自己的步长。 梯度的滑动平均当方向、梯度平方的滑动平均给步长归一化，偏差修正除以 \(1-\beta^t\)（黑板上第 1 步的 \(m=0.02\) 除以 0.1 才回到 0.2）。GPT-3：\(\beta_1=0.9\)，\(\beta_2=0.95\)，\(\epsilon=10^{-8}\)。
  • 第二，权重衰减要“解耦”。 在 Adam 里 L2 正则会被 \(1/\sqrt{\hat v}\) 缩放，梯度大的参数几乎不被正则；AdamW 把衰减 \(\eta_t\lambda\theta\) 直接作用在参数上（黑板上每步多拉约 0.001）。“权重衰减 0.1”要说明是哪种约定。
  • 第三，步长随时间变，冲击要挡住。 学习率先线性 warmup 再余弦衰减 (2.16)（黑板上走到一半时是峰值的 0.55）；GPT-3 按 token 计：375M 升温、260B 降到 10%。梯度裁剪按全局范数等比例缩短，阈值 1.0；它保护的是 Adam 的两个滑动平均：一次不裁剪的尖峰会把之后上百步的步长压小。

算力与数值：C ≈ 6ND 与 BF16 混合精度

大家装修时，师傅报价一般按平方米算：每平方米多少钱，乘以面积。训练的账也是这么算的：每个参数、每个 token 花几次运算，乘以参数量，再乘以 token 数。

§1 直接用了“每个参数、每个 token 6 次”，得到 \(C\approx6ND\)。这个 6 是怎么来的？这一页先在黑板上把它数出来，再回答同一张账单的另一半：这么多次运算，每个数用几位来存、来算。

前向：每个参数、每个 token，2 次运算

矩阵乘法的运算次数读过 M01 §5 的可以跳过

\([m,k]\times[k,n]\) 的矩阵乘法：结果有 \(mn\) 格，每格是长为 \(k\) 的点积，要 \(k\) 次乘法和约 \(k\) 次加法，合计约 \(2mnk\) 次浮点运算（FLOPs）。硬件的基本指令是“乘加”（一条指令算 \(a\times b+c\)），记作 2 次运算。详见 M01 §5。

我们在黑板上造一个最小的线性层，一格一格数。

黑板上 · 一个 6 参数的线性层，前向数一数

\(W\) 是 \(2\times3\) 的矩阵，一共 6 个参数；一次喂进 4 个 token，\(X\) 是 \(4\times2\)（每行一个 token）。\(Y=XW\) 是 \(4\times3\)，一共 12 格。

每一格 \(Y_{tj}=X_{t1}W_{1j}+X_{t2}W_{2j}\)：2 次乘法，每个乘积加进这一格的累加器，按上面框里的记法就是 2 次乘加。12 格一共 \(12\times2=24\) 次乘法，记作 \(2\times24=48\) 次运算。

换一种数法：\(48=2\times6\times4\)，即 2 × 参数个数 × token 个数。每个参数对每个 token 恰好出场一次：乘一次、加一次。

好，把 6 个参数、4 个 token 换成一般的线性层 \(Y=XW\)：\(X\in\R^{T\times d_{in}}\) 是 \(T\) 个 token 的输入（按行堆叠，每行一个 token 的行向量），\(W\in\R^{d_{in}\times d_{out}}\) 有 \(d_{in}d_{out}\) 个参数。按上面的规则，前向要 \(2\,T\,d_{in}\,d_{out}\) 次运算，也就是每个参数、每个 token 2 次：一次乘、一次加。Transformer 的参数几乎全在这样的矩阵里（第 1 课：每层约 \(12d^2\)），所以

每 token 的前向运算量\[C_{\text{fwd}}\approx2N\quad\text{FLOPs / token}\]\(N\) 是参与矩阵乘法的参数量。Kaplan 等人的原话是 “the factor of two comes from the multiply-accumulate operation” 6。(2.18)

代回黑板：\(N=6\)，4 个 token，\(2\times6\times4=48\)。对得上。

反向：两次同样大小的矩阵乘法，4 次运算

反向传播到这一层时，我们手里有上游传来的 \(\partial\mathcal L/\partial Y\in\R^{T\times d_{out}}\)（简写 \(\partial Y\)）。这一层要交出两样东西：给下一层（更靠近输入的层）的 \(\partial X\)，以及给优化器的 \(\partial W\)。

反向传播为什么是前向的两倍
(1)\(\displaystyle Y=XW\ \Rightarrow\ Y_{tj}=\sum_iX_{ti}W_{ij}\)前向，逐元素写开
(2)\(\displaystyle \partial X_{ti}=\sum_j\partial Y_{tj}\,W_{ij}\ \Rightarrow\ \partial X=\partial Y\,W^\top\)链式法则：\(X_{ti}\) 通过所有 \(Y_{tj}\) 影响损失；形状 \([T,d_{out}]\times[d_{out},d_{in}]\)
(3)\(\displaystyle \partial W_{ij}=\sum_tX_{ti}\,\partial Y_{tj}\ \Rightarrow\ \partial W=X^\top\partial Y\)同理，\(W_{ij}\) 通过所有 token 的 \(Y_{tj}\) 影响损失；形状 \([d_{in},T]\times[T,d_{out}]\)
(4)\(\displaystyle 2Td_{in}d_{out}+2Td_{in}d_{out}=4\times(\text{参数})\times T\)两次矩阵乘法的中间维分别是 \(d_{out}\) 和 \(T\)，运算量都和前向一样

回到黑板，把这两次乘法也数一遍。

黑板上 · 同一个线性层，反向再数一数

上游传来的 \(\partial Y\) 是 \(4\times3\)。

  • \(\partial X=\partial Y\,W^\top\)：\([4,3]\times[3,2]\)，结果 8 格，每格 3 次乘法，共 24 次；
  • \(\partial W=X^\top\partial Y\)：\([2,4]\times[4,3]\)，结果 6 格，每格 4 次乘法，共 24 次。

两次都是 24 次乘法，和前向一模一样。前向加反向一共 \(3\times24=72\) 次乘法，按乘加记是 144 次运算，而 \(144=6\times6\times4\)。

训练算力\[C\approx\underbrace{2ND}_{\text{前向}}+\underbrace{4ND}_{\text{反向}}=6ND\]\(D\) 是训练 token 数。GPT-3 论文表 D.1 逐列写的就是这个逻辑：前向每个激活参数每 token 2 FLOPs，算上反向后总量是前向的 3 倍，合计 6 4。(2.19)

代回黑板：\(6ND=6\times6\times4=144\)，一次不差。

好，现在请大家猜一猜：GPT-3 每训练一个 token，要做多少次运算？一亿次？一百亿次？

答案是 \(6\times174.6\times10^9\approx1.05\times10^{12}\)，一万亿次出头。一个 token。

GPT-3 的 3.14 × 10²³，以及被忽略的部分

\(6\times174.6\times10^9\times300\times10^9=3.1428\times10^{23}\) FLOPs \(=3{,}637.5\) PF-days，表 D.1 印 3.14E+23 与 3,640 4。

被忽略的是注意力里不带参数的两次矩阵乘法（\(QK^\top\) 与 \(PV\)）。Kaplan 的前向计数是 \(2N+2\,n_{layer}\,n_{ctx}\,d\) 6。第二项可以这样对上（笔者的对账，Kaplan 只给了结果）：位置 \(t\) 的查询要和 \(t\) 个键各做一次点积（所有头合计 \(2td\) 次运算），再对 \(t\) 个值加权求和（又是 \(2td\) 次），每层 \(4td\)；只数因果掩码下真正要算的下三角，\(t\) 在 1 到 \(n_{ctx}\) 之间平均约 \(n_{ctx}/2\)，平均每 token 每层就是 \(2n_{ctx}d\)。两项之比为

\[\frac{2\,n_{layer}\,n_{ctx}\,d}{2\times12\,n_{layer}d^2}=\frac{n_{ctx}}{12\,d}=\frac{2048}{12\times12288}=1.4\%.\]

这就是 Kaplan 说“\(d_{model}\gg n_{ctx}/12\) 时上下文相关项可以忽略”的意思。把它加上，GPT-3 的总算力是 \(3.186\times10^{23}\)，只多 1.4%。

\(6ND\) 是近似，但近似得很好。Chinchilla 附录 F 按嵌入、QKV、注意力打分、softmax、输出投影、FFN、logits 逐项精确计数（反向取前向的两倍），与 \(6ND\) 之比在 7300 万到 68 亿参数的六个模型上是 0.99 到 1.10 7。上下文变长、模型变窄时注意力的份额会变大：PaLM 把它写进公式，每 token 训练算力记为 \(6N+12LHQT\)（\(L\) 层数、\(H\) 头数、\(Q\) 每头维度、\(T\) 序列长度）13。把这一项拆开（\(12LHQT=3\times L\times2\times2\,T\,HQ\)），它相当于把 \(QK^\top\) 与 \(PV\) 都按完整的 \(T\times T\) 注意力矩阵计数、不扣掉因果掩码掩掉的一半，所以是上面 Kaplan 口径（\(3\times2n_{layer}n_{ctx}d\)）的 2 倍。第 6 课的 DeepSeek LLM 用的 \(M\) 与此同类（§8）。

6 不是永远的 6

GPT-3 表 D.1 里的 T5-11B 是每参数每 token 3 FLOPs：它是编码器–解码器结构，每个 token 只经过一半参数 4。规律是：\(6N\) 里的 \(N\) 应该是每个 token 实际参与计算的参数。第 7 课起的 MoE 模型总参数很大，每个 token 却只激活一小部分专家，训练算力按“激活参数”算，这正是 MoE 省钱的来源。

混合精度：每个数用几位

问题。 GPT-3 175B 的参数如果全用 32 位浮点数（FP32，每个 4 字节）存，光权重就是 \(174.6\times10^9\times4\approx698\) GB；每次矩阵乘法都要把它们从显存搬进计算单元。位数减半，存储和搬运都减半。代价是精度：少了的位从哪里扣？扣了会出什么事？先在黑板上用十进制演一遍。

黑板上 · 一台只能显示三位有效数字的计算器

假设计算器只能显示三位有效数字。屏幕上是 1.00，我们给它加 0.001：

  • 真实结果是 1.001，可屏幕只有三位，四舍五入回 1.00；
  • 再加一次 0.001，还是 1.00；
  • 加一千次，屏幕上仍然是 1.00，而真实结果早就是 2.00 了。

每一次加的数都不到“最后一位的一半”（0.005），于是每一次都被舍掉，一千次加起来一个也没留下。

训练里的参数更新，就是这种小不点。那么真实的浮点数有几位？

浮点数的构成\[x=(-1)^{s}\times2^{\,e-\text{bias}}\times(1.f)_2\]\(s\)：1 位符号；\(e\)：指数位，决定能表示多大、多小的数（范围）；\(f\)：尾数位，决定相邻两个可表示的数之间隔多远（精度）。\(p\) 位尾数时，\([2^k,2^{k+1})\) 里相邻两数的间隔是 \(2^{k-p}\)。完整讲法见 M08 §2–§4。(2.20)

三种格式的分法不同。FP32 是 1 + 8 + 23 位；FP16 是 1 + 5 + 10 位，精度还行，但最大只能表示 65,504（NumPy 的 finfo 可查）。BF16（bfloat16）是 1 + 8 + 7 位：它就是 FP32 的高 16 位，指数位一位没少，所以范围与 FP32 相同，但尾数只剩 7 位，相对精度约 \(2^{-7}\approx0.0078\)，只有两三位有效数字 14,15，和黑板上那台三位计算器差不多。借整门课“短尺子”的比喻（第 12 课展开）：BF16 是一把量程和 FP32 一样长、刻度却粗得多的尺子。

混合精度（mixed precision）就是把两种格式各用在合适的地方：计算量大、对误差不敏感的矩阵乘法用 BF16；需要细小累加的参数更新用 FP32。Chinchilla 的描述是：前向与反向用 bfloat16，在分布式优化器的状态里保存一份 float32 的权重副本 7。Google 的 TPU 文档也写明：矩阵乘法用 bfloat16 的值，累加用 IEEE float32 15。GPT-3 论文没有写它用的数值精度 4。

为什么参数本身不能也用 BF16 存？回到黑板上那台计算器：§5 的更新太小了。

一次更新被舍掉
(1)\(\displaystyle 0.02\in[2^{-6},2^{-5})=[0.0156,\,0.0313)\)先找 0.02 落在哪个“二进制区间”
(2)\(\displaystyle \text{间隔}=2^{-6}\times2^{-7}=2^{-13}\approx1.22\times10^{-4}\)BF16 有 7 位尾数，按 (2.20) 的规则
(3)\(\displaystyle \Delta\theta\approx\eta=6\times10^{-5}<\tfrac12\times1.22\times10^{-4}=6.1\times10^{-5}\)Adam 的步长约为 \(\eta\)（§5 的例题）；不到半个间隔
(4)\(\displaystyle \mathrm{round}_{\text{BF16}}(\theta+\Delta\theta)=\theta\)就近舍入回到原值，这次更新整个消失
一千步之后

用 NumPy 按位模拟：BF16 里最接近 0.02 的数是 \(0.0200195\)。每步加 \(6\times10^{-5}\)、共 1000 步：用 FP32 累加得到 \(0.0800\)；每步都舍入回 BF16，结果仍是 \(0.0200195\)，一点没动，和黑板上的三位计算器一模一样。所以主权重必须用 FP32 保存，更新在 FP32 上做。

同一套模拟也显示了 FP16 的毛病：\(70{,}000\) 在 FP16 里溢出成无穷大，在 BF16 里是 \(70{,}144\)；\(10^{-8}\) 在 FP16 里下溢成 0，在 BF16 里仍是 \(1.0\times10^{-8}\)。训练中的数值一旦跨越很多个数量级，BF16 的大范围就比 FP16 多出的三位尾数更要紧。

很多人以为：混合精度就是全程都用 16 位

很多人以为：“用 BF16 训练”就是把权重、梯度、优化器状态统统换成 16 位，显存和计算都砍一半。

其实：16 位只用在前向、反向的矩阵乘法上；参数更新要在 FP32 的主权重上做，否则就是黑板上那台三位计算器，训练停在原地。所以下面这笔账里，FP32 的那几份才是大头。

这样做每个参数要几个字节

按上面的做法、再假设梯度也用 BF16 存，数一数（这是笔者的假设与算术，不是论文数字）：BF16 权重 2 字节 + BF16 梯度 2 字节 + FP32 主权重 4 字节 + FP32 的 \(\mathbf m\)、\(\mathbf v\) 各 4 字节 = 16 字节/参数。GPT-3 175B 就是 \(174.6\times10^9\times16\approx2.8\) TB，还不算前向时存下的激活。任何单块加速器都放不下，只能切到很多块上：这是第 12 课“训练基建”要解决的问题，第 12 课还会把矩阵乘法进一步降到 8 位（FP8）。

这一页讲了三件事
  • 第一，6 = 2 + 4。 前向每个参数每个 token 一乘一加，2 次；反向要算 \(\partial X=\partial Y\,W^\top\) 和 \(\partial W=X^\top\partial Y\) 两次同样大的矩阵乘法，4 次；合计 \(C\approx6ND\)（黑板上 6 个参数、4 个 token：\(144=6\times6\times4\)）。
  • 第二，GPT-3 的账。 \(6\times174.6\text{B}\times300\text{B}=3.14\times10^{23}\) FLOPs，每个 token 约 \(1.05\times10^{12}\) 次；注意力打分只占 \(n_{ctx}/(12d)=1.4\%\)。\(N\) 应是每个 token 实际参与计算的参数。
  • 第三，刻度粗的尺子记不下小更新。 BF16 = FP32 的高 16 位：范围不变，精度只有 \(2^{-7}\)。混合精度：矩阵乘法用 BF16，主权重与优化器状态用 FP32，否则小更新会被舍掉（只走 0.49 格的那一步）。

规模化规律：Kaplan 与 Chinchilla

大家攒过电脑吗？预算固定，要分给 CPU 和显卡。钱全砸在显卡上，CPU 拖后腿；全砸在 CPU 上，显卡又带不动。最划算的分法在中间某处，而且没法一台一台买回来试。

训练大模型是同一道题。GPT-3 的一次训练花掉 3,640 PF-days，只能做一次。开训之前必须回答：在 \(C\approx6ND\) 固定的前提下，是训一个更大的模型、少看点数据，还是训一个小一点的模型、多看点数据？在全尺寸上试错是不可能的。唯一的办法是在一系列小模型上做实验，找出损失随 \(N\)、\(D\)、\(C\) 变化的规律，再外推到大模型。这样的经验规律叫规模化规律（scaling law）。

幂律：对数坐标上的一条直线

含义。 幂律（power law）：一个量按另一个量的某个固定次方变化，\(L\propto X^{-\alpha}\)。

先在黑板上画一个指数是 0.5 的幂律。

黑板上 · 每放大 4 倍，损失减半

取 \(L(X)=(64/X)^{0.5}\)，代几个数：

\(X\) 1 4 16 64
\(L\) 8 4 2 1

\(X\) 每放大 4 倍，\(L\) 就减半；不管是从 1 放大到 4，还是从 16 放大到 64，都是减半。可要是看“掉了多少”：从 1 到 4，\(L\) 掉了 4；从 16 到 64，只掉了 1。画在普通坐标上，这是一条越来越平的曲线。如果把横轴、纵轴都换成对数，四个点正好排成一条直线。

理解。 幂律的特点是“按比例”：把 \(X\) 放大同样的倍数，\(L\) 总是缩小同样的比例，不管从哪里开始放大。在两个坐标轴都取对数的图上，它是一条直线。为什么？我们推一下。

幂律在对数坐标上是直线
(1)\(\displaystyle L(X)=\left(X_c/X\right)^{\alpha}\)幂律的一般形式；\(X_c\) 是常数，\(\alpha>0\) 是指数
(2)\(\displaystyle \log L=\alpha\log X_c-\alpha\log X\)两边取对数：对数把乘方变成乘法
(3)\(\displaystyle \frac{L(kX)}{L(X)}=\left(\frac{X_c/kX}{X_c/X}\right)^{\alpha}=k^{-\alpha}\)放大 \(k\) 倍，损失乘 \(k^{-\alpha}\)，与起点 \(X\) 无关
幂律\[L(X)=\left(\frac{X_c}{X}\right)^{\alpha}\quad\Longleftrightarrow\quad\log L=-\alpha\log X+\text{常数}\]在双对数坐标上是斜率为 \(-\alpha\) 的直线；\(X\) 翻倍，\(L\) 乘 \(2^{-\alpha}\)。(2.21)

代回黑板：\(X_c=64\)，\(\alpha=0.5\)，\(k=4\)，\(4^{-0.5}=0.5\)，减半；右图那条直线的斜率是 \(-0.5\)。对得上。

Kaplan 2020：三条幂律与“主要加大模型”

Kaplan 等人在 WebText2 上训练了从不到一千到 15 亿非嵌入参数的大量模型，发现交叉熵损失分别对参数量、数据量和算力呈幂律，跨越了算力的八个数量级 6：

Kaplan 的三条幂律\[\begin{aligned}L(N)&=\left(\frac{8.8\times10^{13}}{N}\right)^{0.076}\\ L(D)&=\left(\frac{5.4\times10^{13}}{D}\right)^{0.095}\\ L(C_{\min})&=\left(\frac{3.1\times10^{8}}{C_{\min}}\right)^{0.050}\end{aligned}\]\(L\)：nats/token；\(N\)：非嵌入参数；\(D\)：token；\(C_{\min}\)：达到这个损失所需的最少算力（对应用远小于“临界 batch”的 batch 训练，临界 batch 见 §8），以 PF-days 计。三条各有前提：\(L(N)\) 是数据足够、训到收敛；\(L(D)\) 是大模型、数据有限、提前停止；\(L(C_{\min})\) 是算力受限、模型大小取最优 6。(2.22)

黑板上的幂律，放大 4 倍损失就减半。那真实的语言模型呢？大家猜一猜：按 \(L(N)\)，参数翻一倍，损失降多少？一半？三成？

翻倍能换来多少

按 (2.21)：参数翻倍，损失乘 \(2^{-0.076}=0.949\)，降 5.1%（论文原文给的就是 0.95）；数据翻倍，乘 \(2^{-0.095}=0.936\)，降 6.4%；算力翻倍，乘 \(2^{-0.050}=0.966\)，只降 3.4%。算力的指数最小，因为多出来的算力要分给模型和数据两边。

只降 5%。黑板上翻 4 倍就能减半，是因为我故意取了 0.5 这么大的指数；真实的指数只有 0.076，每一点进步都要拿成倍的参数去换。

Kaplan 还发现了两件后来影响很大的事。第一，形状几乎无关：参数量固定时，层数与宽度的比例变化 40 倍，损失只轻微变化；6 层、宽 4288 的模型与 GPT-2 的 48 层、宽 1600 相差不到 3% 6。第二，把 \(N\) 与 \(D\) 放进同一个式子，过拟合的程度主要取决于 \(N^{0.74}/D\)（原文 “depends predominantly on”）：模型放大 8 倍，数据只需放大约 5 倍（\(8^{0.738}=4.64\)）6。

Kaplan 的联合式\[\begin{gathered}L(N,D)=\left[\left(\frac{N_c}{N}\right)^{\alpha_N/\alpha_D}+\frac{D_c}{D}\right]^{\alpha_D}\\ \alpha_N=0.076,\quad \alpha_D=0.103,\quad N_c=6.4\times10^{13},\quad D_c=1.8\times10^{13}\end{gathered}\]这是表 2 的联合拟合，常数与 (2.22) 单独拟合的不同；\(\alpha_N/\alpha_D=0.738\)，这才是正文 “\(N^{0.74}\)” 的来源 6。(2.23)

最后是本页的核心问题：算力多了，怎么分？Kaplan 的经验拟合是 6

Kaplan 的算力最优分配\[N_{\text{opt}}\approx1.3\times10^{9}\,C_{\min}^{\,0.73},\qquad D_{\text{opt}}\approx2\times10^{10}\,C_{\min}^{\,0.27}\qquad(C_{\min}\ \text{以 PF-days 计})\]算力放大 10 倍：模型放大 \(10^{0.73}=5.37\) 倍，数据只放大 \(10^{0.27}=1.86\) 倍。(2.24)

Kaplan 的结论是：算力应该主要用来加大模型，并且算力最优的训练是“训练很大的模型，在收敛之前很早就停下” 6。注意，不是“训到收敛”：那只是 (2.22) 里 \(L(N)\) 一条的实验前提。GPT-3 的设计与这个思路一致：175B 参数只训练了 300B token，平均每个参数 1.7 个 token。

Kaplan 等人的论文 2020 年 1 月挂上 arXiv；4 个月后发布的 GPT-3 论文，作者名单里也有 Kaplan 和 Brown 6,4。GPT-3 说它给大模型配更大的 batch、更小的学习率，是参照 Kaplan 等人和梯度噪声尺度的工作选的 4。

Chinchilla 2022：参数与数据应该同比例增长

两年后，Hoffmann 等人（DeepMind）重新做了这个实验，结论不同。他们把问题写成一个带约束的最小化 7：

算力最优分配问题\[N_{\text{opt}}(C),\ D_{\text{opt}}(C)=\argmin_{N,D\ \text{s.t.}\ \mathrm{FLOPs}(N,D)=C}\ L(N,D)\]这里 \(N\) 包含嵌入参数，\(\mathrm{FLOPs}(N,D)\approx6ND\)。(2.25)

他们训练了 400 多个模型（7000 万到 160 多亿参数），用三种独立的方法估计 \(N_{\text{opt}}\propto C^{a}\)、\(D_{\text{opt}}\propto C^{b}\) 中的指数 7：

方法 做法 \(a\)（模型） \(b\)（数据）
1. 训练曲线的下包络 每个规模训 4 种余弦周期长度，在每个算力点取最低损失 0.50 0.50
2. IsoFLOP 曲线 9 个固定算力，各扫一遍模型大小，取谷底 0.49 0.51
3. 拟合参数化损失 用 (2.26) 拟合全部实验，再解析求最优 0.46 0.54
Kaplan 2020 0.73 0.27

三种方法都说 \(a\approx b\approx0.5\)：模型每放大一倍，训练 token 也应该放大一倍 7。方法 3 的参数化损失是

Chinchilla 的参数化损失\[\begin{gathered}\hat L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}\\ E=1.69,\quad A=406.4,\quad B=410.7,\quad \alpha=0.34,\quad \beta=0.28\end{gathered}\]这里沿用论文的字母：\(E\)、\(A\)、\(B\) 是拟合常数（\(E\) 与 §3 的词表矩阵、\(B\) 与 batch 大小都无关），\(\alpha,\beta\) 是指数。三项的意思：\(E\) 是模型再大、数据再多也降不下去的部分，作者把它解释为自然文本的熵（呼应 §2 的 \(H(q)\)）；\(A/N^\alpha\) 是“模型有限”造成的损失；\(B/D^\beta\) 是“数据有限”造成的损失 7。(2.26)

有了 (2.26)，最优分配可以用纸笔解出来。先别急着推，我们在黑板上把“攒电脑的预算”分一次。

黑板上 · 把 100 个单位的预算分给 N 和 D

取一个玩具版的 (2.26)：\(E=0\)，\(A=B=1\)，\(\alpha=\beta=1\)，也就是 \(\hat L=\frac1N+\frac1D\)。预算固定为 \(ND=100\)（相当于 \(C/6=100\)，单位是随手取的）。我们试几种分法：

\(N\) 2 4 5 10 20 25 50
\(D=100/N\) 50 25 20 10 5 4 2
模型有限 \(1/N\) 0.5 0.25 0.2 0.1 0.05 0.04 0.02

再把预算放大 4 倍，\(ND=400\)。大家自己试一试：最好的是 \(N=D=20\)，\(\hat L=0.1\)。预算翻 4 倍，模型和数据各翻 2 倍。

好，把玩具换回 (2.26)。

算力最优前沿
(1)\(\displaystyle D=\frac{C}{6N}\ \Rightarrow\ \hat L(N)=E+AN^{-\alpha}+B\left(\frac{6N}{C}\right)^{\beta}\)用约束 \(6ND=C\) 消去 \(D\)
(2)\(\displaystyle \frac{d\hat L}{dN}=-\alpha AN^{-\alpha-1}+\beta B\left(\frac{6}{C}\right)^{\beta}N^{\beta-1}=0\)对 \(N\) 求导，令其为 0
(3)\(\displaystyle \alpha AN^{-\alpha}=\beta B\left(\frac{6N}{C}\right)^{\beta}=\beta BD^{-\beta}\)两边乘 \(N\)，再把 \(6N/C\) 换回 \(1/D\)：最优点上两项“边际收益”相等
(4)\(\displaystyle N^{\alpha+\beta}=\frac{\alpha A}{\beta B}\left(\frac{C}{6}\right)^{\beta}\)取上一行的前一个等号，把 \((6N/C)^{\beta}\) 拆成 \((C/6)^{-\beta}N^{\beta}\)，两边乘 \(N^{\alpha}(C/6)^{\beta}/(\beta B)\)，\(N\) 的幂合并到左边
(5)\(\displaystyle N_{\text{opt}}=G\left(\frac{C}{6}\right)^{\frac{\beta}{\alpha+\beta}},\quad G=\left(\frac{\alpha A}{\beta B}\right)^{\frac1{\alpha+\beta}}\)两边开 \(\alpha+\beta\) 次方；\(D_{\text{opt}}=C/(6N_{\text{opt}})=G^{-1}(C/6)^{\frac{\alpha}{\alpha+\beta}}\)
方法 3 的最优前沿\[N_{\text{opt}}(C)=G\left(\frac C6\right)^{a},\quad D_{\text{opt}}(C)=G^{-1}\left(\frac C6\right)^{b},\quad a=\frac{\beta}{\alpha+\beta},\ b=\frac{\alpha}{\alpha+\beta}\]把 \(N\) 换成 \(u=\ln N\) 来看，\(\hat L=E+Ae^{-\alpha u}+B(6/C)^{\beta}e^{\beta u}\) 是两个指数函数之和，处处是凸的，所以这个驻点是唯一的最小值。用论文 TeX 源码里未四舍五入的拟合值（\(\alpha=0.3392\)，\(\beta=0.2849\)），\(a=0.4565\)、\(G=1.300\) 7。(2.27)

代回黑板：\(\alpha=\beta=1\)、\(A=B=1\)，所以 \(a=b=\tfrac12\)，\(G=1\)，\(N_{\text{opt}}=(C/6)^{1/2}=\sqrt{100}=10\)，\(D_{\text{opt}}=10\)；预算换成 400，\(\sqrt{400}=20\)。和我们一格一格试出来的一样。推导第三行说最优点上 \(\alpha AN^{-\alpha}=\beta BD^{-\beta}\)，黑板上 \(\alpha=\beta\)，于是两项本身相等，都是 0.1。

为什么两家结论不同？ Chinchilla 自己给出的原因有两条 7。第一，Kaplan 所有模型用同样的训练 token 数和同一个学习率调度（余弦周期约 130B token，即 \(2.5\times10^5\) 步 × \(2^{19}\) token）；拿一次长周期训练的中间检查点当作“训练到那么多 token 的模型”，高估了它的损失，因为 §5 的余弦调度只有在周期与训练长度匹配时才降到最低。第二，Kaplan 的模型大多很小，许多不到 1 亿参数，而前沿在小规模处有一点弯曲。Chinchilla 并没有说 Kaplan 的幂律拟合本身算错了，它说的是实验设计让小数据量的效果被低估了。

类比：一笔固定的学费，分给“脑容量”和“读书量”

映射。 训练一个模型像用一笔固定的学费培养一名学生：\(N\) 是学生的脑容量，\(D\) 是他读过的页数，\(C\approx6ND\) 是总花费。Kaplan 的结论相当于“钱主要花在扩容上，书读个大概就行”；Chinchilla 的结论是“容量和读书量一起涨”。

收益。 它说明了为什么一定存在最优点：容量很大却没读几页，容量闲置（(2.26) 里 \(B/D^\beta\) 大）；读了很多却容量太小，装不下（\(A/N^\alpha\) 大）。练习 12 会证明，最优点上这两项的比例固定为 \(\beta/\alpha\)（黑板上 \(\alpha=\beta\)，比例是 1）。

但是这个比方有两个地方不对。 第一，人读一页书的成本和脑容量无关，模型读一个 token 的成本却正比于 \(N\)，这正是 \(C=6ND\) 写成乘积的原因，也是两者此消彼长的根源。第二，这笔账只算“上学”（训练）的花费，不算“毕业后工作”（推理）的开销。

算一笔：GPT-3 的预算应该怎么分

把 GPT-3 的预算 \(C=3.14\times10^{23}\) FLOPs 按三种规则各分一次，再和 GPT-3 的实际做法比较。第一种规则是“每个参数 20 个 token”，先把它解出来：

每个参数 20 个 token 时的分配
(1)\(\displaystyle D=20N,\quad C=6ND\)经验法则与算力公式
(2)\(\displaystyle C=6N\cdot20N=120N^2\)代入
(3)\(\displaystyle N=\sqrt{C/120},\quad D=20N\)解出

用同一条法则“预言” Chinchilla

Gopher（280B 参数、300B token）的算力是 \(5.76\times10^{23}\) FLOPs 7。按 (2.28)：\(N=\sqrt{5.76\times10^{23}/120}=69.3\)B，\(D=1.39\)T。DeepMind 用同样的算力训练了 70B 参数、1.4T token 的 Chinchilla，它在多项评测上全面超过 Gopher、GPT-3（175B）和 MT-NLG（530B）；MMLU 5-shot 平均 67.5%（摘要的数字，正文表 6 印 67.6%），比 Gopher 的 60.0% 高 7 个百分点以上 7。

很多人以为：Chinchilla 论文证明了每个参数应该训练 20 个 token

很多人以为：“每个参数 20 个 token”是 Chinchilla 论文推出来的一条定律。

其实：论文全文（包括 TeX 源码）没有“20 tokens per parameter”这句话 7。论文说的是“模型大小每翻一倍，训练 token 也翻一倍”。“20”是从 Chinchilla 本身（1.4T ÷ 70B）和方法 1 的投影表（各行 20.0–22.4）总结出的经验法则。反过来，正文给出的参数化拟合 (2.26) 并不推出 20：代入四舍五入的参数，Gopher 算力下是 93；这组参数还被 Besiroglu 等人指出拟合不佳、置信区间窄得不合理，他们重新拟合后才得到与 20 一致的结果 16。引用时要说清楚这个数的来历。

规模化规律没有告诉你的

第一，常数只对它所用的数据和分词器成立。Kaplan 注意到，如果训练数据只像 (2.24) 那样慢慢增长，\(L(C_{\min})\) 迟早会撞上有限数据所能达到的 \(L(D)\)；他们把两条线的交点估为 \(L^{\ast}\approx1.7\) nats，并猜测这个交点标出了 Transformer 语言模型性能的上限，\(L^\ast\) 也许可以粗略地当作自然语言每个 token 的熵。这个 \(L^\ast\) 和 Chinchilla 的 \(E=1.69\) 数值接近纯属巧合，Kaplan 自己也说这组交点的数值很不确定，可能差一个数量级 6。第二，(2.25) 只最小化训练算力下的损失；模型训好后每生成一个 token 的推理成本也随 \(N\) 增长，这一项不在目标里（笔者的说明）。第三，“最优”依赖数据质量：第 6 课会看到，DeepSeek LLM 在不同质量的数据上拟合出了不同的分配指数 9。

这一页讲了三件事
  • 第一，幂律在双对数坐标上是直线。 \(L=(X_c/X)^\alpha\)，放大 \(k\) 倍损失乘 \(k^{-\alpha}\)，与起点无关（黑板上 \(\alpha=0.5\)，每放大 4 倍减半）。真实指数很小：参数翻倍，损失只降 5.1%。
  • 第二，两家的分法不同。 Kaplan：\(N_{\text{opt}}\propto C^{0.73}\)、\(D_{\text{opt}}\propto C^{0.27}\)，主要加大模型、提前停止。Chinchilla：三种方法都给出 \(a\approx b\approx0.5\)，参数与数据同比例增长；方法 3 的 \(\hat L=E+A/N^\alpha+B/D^\beta\) 在 \(6ND=C\) 下解出 \(N_{\text{opt}}=G(C/6)^{\beta/(\alpha+\beta)}\)（黑板上 \(ND=100\) 时 \(N=D=10\)，预算翻 4 倍各翻 2 倍）。
  • 第三，“20”是经验法则。 GPT-3 的预算按“每参数 20 token”应分成 51B 参数、1.0T token；Gopher 的预算正好给出 Chinchilla 的 70B / 1.4T。“20”来自 Chinchilla 本身与方法 1，不是正文参数化拟合的推论。

GPT-1：预训练当作初始化

GPT-1 的主张是：先在无标注文本上做 (2.3) 的预训练，再在每个下游任务（分类、蕴含、问答……）的带标签数据上微调。微调时在最后一层上加一个线性输出头，目标是任务损失 \(L_2\)，并保留语言模型目标作为辅助项 2：

GPT-1 的微调目标\[L_3(\mathcal C)=L_2(\mathcal C)+\lambda\cdot L_1(\mathcal C),\qquad L_2(\mathcal C)=\sum_{(x,y)}\log P(y\mid x^1,\dots,x^m),\qquad \lambda=0.5\]\(\mathcal C\) 是带标签的数据集；\(L_1\) 是 (2.3) 那样的语言模型对数似然（原文写成要最大化的形式）；\(x^1,\dots,x^m\) 是输入 token，\(y\) 是标签。微调学习率 \(6.25\times10^{-5}\)、batch 32，通常 3 个 epoch 就够 2。(2.29)

结果：12 个任务里 9 个超过了当时的最好成绩 2。这时预训练的角色是“一个很好的初始化”，真正的任务能力还要靠每个任务单独微调。

GPT-2：更多、更好的数据，零样本

GPT-2 改了三样东西：数据（§4 的 WebText）、结构（第 1 课的 Pre-LN、上下文 1024、字节级 BPE 词表 50,257）、规模（最大 1.5B）。它的主张是零样本（zero-shot）：不做任何微调，直接把任务写成一段文字让模型续写，在 8 个语言建模数据集里有 7 个达到当时最优 5。报告还有一句很重要的话：最大的模型 “still underfits WebText”，也就是模型越大，在同一份数据上的损失还在降 5。这句话指向了下一代：继续放大。GPT-2 没有报告学习率、步数和训练 token 数，只说各模型的学习率是在 WebText 5% 的保留集上手工调的 5。

GPT-3：放大一百多倍，上下文学习

GPT-3 把参数从 1.5B 放大到 175B，训练 300B token。它的主张是上下文学习（in-context learning）：预训练得到的能力，可以在推理时的前向传播里被调用；给模型看几个例子，它就能照着做，不需要更新任何权重 4。这是什么意思？先上黑板。

黑板上 · 在提示里放两个例子

给模型这样一段英译中的提示（示意）：“apple → 苹果；banana → 香蕉；grape →”。

模型要做的，仍然只是 (2.1) 里那一件事：读了前文，猜下一个 token。可前文里的两个例子已经“告诉”了它这是什么任务，一个学得好的模型，最可能的续写就是“葡萄”（说明用的示意，不是某个模型的实测输出）。从头到尾，参数一个数也没改。

好，把 2 个例子换成 \(K\) 个：

少样本的上下文学习\[\hat y=\argmax_{y}\ p_\theta\big(y\ \big|\ \text{任务描述},\ (x_1,y_1),\dots,(x_K,y_K),\ x\big),\qquad \theta\ \text{固定}\]\((x_k,y_k)\) 是第 \(k\) 个示例的输入与答案，\(x\) 是要回答的新输入，它们都是一段文字（不是单个 token id）；\(\hat y\) 是模型给出的答案。\(K=0\) 是零样本，\(K=1\) 是单样本，\(K\) 一般取 10 到 100，受上下文长度 2048 限制 4。“学习”只发生在条件分布里，没有梯度。实际输出是按 (2.1) 逐 token 生成的。(2.30)

代回黑板：\(K=2\)，\((x_1,y_1)=\)（apple，苹果），\((x_2,y_2)=\)（banana，香蕉），\(x=\) grape，\(\theta\) 固定。

交给第 6 课的三个问题

问题一：batch 和学习率该怎么随规模变？ GPT-3 的八个规模里，batch 从 0.5M 增加到 3.2M token，学习率从 \(6\times10^{-4}\) 降到 \(0.6\times10^{-4}\)（本页上半的表），但这些数是按经验选的。Kaplan 给过一条相关的规律，先把概念讲清楚。

含义。 临界 batch（critical batch size）：batch 大小的一个分界点，在它以下加大 batch 很划算，在它以上加大 batch 基本是浪费 6。

理解。 batch 远小于临界值时，把 batch 翻倍，达到同一损失所需的步数几乎减半，多用的 token 没有白花；batch 远大于临界值时，再加大 batch，步数几乎不再减少，多出来的 token 等于白算。直觉是：batch 越大，梯度里的噪声越小，可一旦噪声已经小到不再拖后腿，再多平均一些样本也帮不上忙。系统的推导见 M07 §5。

数学。 Kaplan 发现这个分界点随损失下降而变大：

临界 batch 随损失的变化\[B_{\text{crit}}(L)=\frac{B_\ast}{L^{1/\alpha_B}},\qquad B_\ast\approx2\times10^{8}\ \text{token},\quad \alpha_B\approx0.21\]\(B_{\text{crit}}\) 以 token 计；\(L\) 是当前的损失（nats）。损失每降 13%，临界 batch 约翻一倍（\((1/0.87)^{1/0.21}=1.94\)）6。(2.31)
临界 batch 的量级

用表 5 的 \(B_\ast=2.1\times10^8\)：损失 3 nats 时 \(B_{\text{crit}}=2.1\times10^8/3^{4.76}=1.12\times10^6\) token；2.5 nats 时 \(2.67\times10^6\)。GPT-3 175B 用的 3.2M token 落在同一个量级。Kaplan 在 §1.1 也说，收敛时最大模型的理想 batch 约为一两百万 token 6。

第 6 课的 DeepSeek LLM 把这件事做成了系统的实验：直接拟合最优 batch 与最优学习率随算力 \(C\) 变化的幂律，而不是靠经验挑。

问题二：“模型规模”该怎么量？ \(6ND\) 里的 \(N\) 是参数量，但 §6 已经看到，它忽略了注意力的运算。DeepSeek LLM 改用每 token 的非嵌入 FLOPs \(M\)，它把注意力算进去、把词表的计算排除在外，于是 \(C=MD\) 9：

DeepSeek LLM 的模型规模表示\[6N_1=72\,n_{layer}d^2,\qquad M=72\,n_{layer}d^2+12\,n_{layer}\,d\,l_{seq}\]\(n_{layer}\) 层数，\(d\) 隐藏维度，\(l_{seq}\) 序列长度；\(6N_1\) 是只数非嵌入参数的 \(6N\)。第二项与 PaLM 的 \(12LHQT\) 相同（\(HQ=d\)）13，是 §6 里 Kaplan 口径训练注意力项 \(3\times2n_{layer}n_{ctx}d\) 的 2 倍（相当于按完整的 \(T\times T\) 计数，不扣掉因果掩码掩掉的一半，见 §6）。(2.32)
差别在小模型上最大

GPT-3 175B（96 层，\(d=12288\)，\(l_{seq}=2048\)）：\(6N_1=1.044\times10^{12}\)，\(M=1.073\times10^{12}\)，只差 2.8%（是 §6 那个 1.4% 的两倍，原因见上式的说明）。GPT-2 small（12 层，\(d=768\)，\(l_{seq}=1024\)）：\(6N_1=5.10\times10^8\)，\(M=6.23\times10^8\)，差 22%；如果把词表的计算也算进 \(6N\)（\(6N_2=6N_1+6n_{vocab}d\)），则是 \(7.41\times10^8\)，比 \(6N_1\) 大 45%，比 \(M\) 大 19%。规模化规律正是在小模型上拟合、再外推到大模型的，量尺在小模型上差 20% 以上，拟合出的指数就可能跟着偏。这是第 6 课改用 \(M\) 的动机（笔者按 (2.32) 计算）。

问题三：最优分配是不是一个普适常数？ Chinchilla 的 \(a\approx b\approx0.5\) 是在它自己的训练数据（MassiveText）上拟合出来的。第 6 课会看到，DeepSeek LLM 在三份质量不同的数据上分别拟合，发现数据质量越高，增加的算力越应该分给模型而不是数据；作者认为，这或许也能解释早先各家规模化研究在分配结论上的明显分歧 9。

全课要点
  • 训练 = 数据管线 + 每步循环：交叉熵损失（一次前向 \(T\) 个）→ 反向（梯度从 \(\mathbf p-\mathbf y\) 开始）→ 裁剪 → AdamW → warmup + 余弦的学习率。
  • 账单：\(C\approx6ND\)；GPT-3 175B 是 \(3.14\times10^{23}\) FLOPs；混合精度用 BF16 算、FP32 存主权重。
  • 规模化规律：Kaplan 说主要加大模型，Chinchilla 说参数与数据同比例，“每参数约 20 token”是经验法则。
  • 第 6 课接着回答：超参数怎么随算力变、模型规模怎么量（\(M\)）、数据质量怎样改变最优分配。

最后给大家留个问题

这一课训练出来的模型，本领只有一个：读了前文，按训练语料的统计规律猜下一个 token。GPT-3 在提示里看几个例子，就能照着做翻译。

可如果你不给例子，直接问它一句：“番茄炒蛋怎么做？”它会怎么接？大家先想一想：在它读过的几千亿个 token 里，一个问题后面最常跟着的是什么？也许是一份菜谱，也许是另一个问题，也许是论坛里的一串跟帖。（这是思想实验，不是某个模型的实测输出。）交叉熵只奖励“像语料”，不奖励“帮上忙”；而且 §3 说过，训练时永远有标准答案可对，真正生成时却没有。

那么，怎样把一个很会续写的模型，变成一个按人的意图办事的助手？还用交叉熵吗？要用什么样的数据？又要提防什么？这就是第 3 课要揭晓的问题。

概念题

练习 1 · 训练能并行，生成为什么不能

§3 说一次前向就能得到一条序列全部 \(T\) 个位置的损失。可大家用聊天机器人时都见过，它的回答是一个 token 一个 token 往外吐的。两者的差别在哪里？因果掩码在两种情形下各起什么作用？

看答案

训练时，所有位置的输入都是已知的真实文本（teacher forcing），因果掩码保证位置 \(t\) 的输出只依赖 \(x_{\le t}\)，所以 \(T\) 个位置可以同时算，结果与逐个前缀计算完全相同（§3 的归纳证明）。生成时，位置 \(t+1\) 的输入是模型在位置 \(t\) 采样出来的 token，在算出位置 \(t\) 的分布之前根本不知道它，所以只能串行。因果掩码在生成时保证“后面的 token 不影响前面的输出”，这使得前面位置算过的东西可以缓存复用，这正是第 4 课 KV cache 的出发点。

练习 2 · 哪个参数被正则得多

两个参数当前的值都是 \(\theta=0.05\)。参数甲的梯度一贯很大，\(\sqrt{\hat v}=10^{-2}\)；参数乙的梯度很小，\(\sqrt{\hat v}=10^{-4}\)。学习率 \(\eta=6\times10^{-5}\)。（a）用 AdamW（\(\lambda=0.1\)，PyTorch 约定），两者每步因衰减各收缩多少？（b）用 Adam + L2，取 \(\lambda'=10^{-4}\)，两者每步因 L2 各收缩多少（用 §5 推导的近似）？（c）这说明了什么？

看答案

（a）AdamW：收缩比例都是 \(\eta\lambda=6\times10^{-6}\)，即每步减少 \(0.05\times6\times10^{-6}=3\times10^{-7}\)，两者相同。

（b）Adam + L2：收缩比例 \(\approx\eta\lambda'/\sqrt{\hat v}\)。甲：\(6\times10^{-5}\times10^{-4}/10^{-2}=6\times10^{-7}\)；乙：\(6\times10^{-5}\times10^{-4}/10^{-4}=6\times10^{-5}\)，是甲的 100 倍。

（c）在 Adam 里，L2 正则被每个参数自己的梯度尺度除了一次：梯度大的参数几乎不被正则，梯度小的被正则得很狠，与“把所有权重按同一比例往 0 拉”的本意不符。AdamW 把衰减从梯度里拿出来，才恢复了这个本意 10。

练习 3 · “20”到底从哪里来

有人这样说：“Chinchilla 用参数化损失 \(\hat L=E+A/N^\alpha+B/D^\beta\) 证明了每个参数应该训练 20 个 token。”这句话里有两处问题，大家把它们找出来。

看答案

第一，论文里没有“每参数 20 token”这句话；论文的结论是 \(N_{\text{opt}}\) 与 \(D_{\text{opt}}\) 都约按 \(C^{0.5}\) 增长，“20”是由 Chinchilla 本身（1.4T ÷ 70B）和方法 1 的投影表总结出的经验法则 7。第二，参数化损失（方法 3）恰恰不给出 20：代入正文四舍五入的参数，在 Gopher 的算力下最优 \(D/N\) 约为 93，用 TeX 源码的原值约为 59；这组拟合后来被指出拟合不佳，重新拟合后才与 20 一致 16。另外，“证明”一词也不对：规模化规律是经验拟合，不是定理。

计算题

练习 4 · 交叉熵、bits 与困惑度

模型在一段 4 个 token 的文本上，给真实 token 的概率依次是 \(0.4,\ 0.2,\ 0.9,\ 0.05\)。像 §2 黑板上那样一个位置一个位置算：平均交叉熵是多少 nats、多少 bits？困惑度呢？哪一个位置贡献的损失最多？

看答案

各位置的损失：\(-\ln0.4=0.916\)，\(-\ln0.2=1.609\)，\(-\ln0.9=0.105\)，\(-\ln0.05=2.996\)，合计 \(5.627\)。

\[\mathcal L=5.627/4=1.407\ \text{nats},\qquad \mathcal L_{\text{bits}}=1.407/0.693=2.03\ \text{bits},\qquad \mathrm{PPL}=e^{1.407}=4.08.\]

核对：\(\big(1/(0.4\times0.2\times0.9\times0.05)\big)^{1/4}=(1/0.0036)^{1/4}=277.8^{0.25}=4.08\)。第 4 个位置（概率 0.05）贡献了 \(2.996/5.627=53\%\) 的损失：一个“很有把握地猜错”的位置，比三个猜得还行的位置加起来还贵。

练习 5 · 手算 p − y

三个候选 token 的 logits 为 \(\mathbf z=(1,3,0)\)，真实 token 是第 2 个。求 \(\mathbf p\)、这个位置的损失，以及 \(\partial\ell/\partial\mathbf z\)。沿负梯度走一小步，三个 logit 各往哪个方向动？（想验算的话，可以像 §3 黑板上那样，把每个 logit 加 0.01 看损失怎么变。）

看答案

\(e^{\mathbf z}=(2.718,\ 20.086,\ 1)\)，和为 \(23.804\)，所以 \(\mathbf p=(0.114,\ 0.844,\ 0.042)\)。损失 \(\ell=-\ln0.844=0.170\) nats。

\[\frac{\partial\ell}{\partial\mathbf z}=\mathbf p-\mathbf y=(0.114,\ -0.156,\ 0.042).\]

三个分量之和为 0。沿负梯度走：\(z_2\) 上升（真 token），\(z_1\)、\(z_3\) 下降，且 \(z_1\) 降得比 \(z_3\) 多（它原来的概率更大）。因为模型已经给真 token 0.844 的概率，梯度的模量 \(\norm{\mathbf p-\mathbf y}_1=2(1-0.844)=0.31\) 比 §3 例题里的 1.53 小得多：猜得越准，学习信号越弱。

练习 6 · GPT-3 的学习率

按 (2.16) 和 GPT-3 175B 的设置（峰值 \(6\times10^{-5}\)，前 375M token 线性升温，余弦在 260B token 降到峰值的 10%），求第 0.1B、10B、200B、280B 个 token 时的学习率。（先拿 §5 黑板上那个十步的调度热热身，形状是一样的。）

看答案
  • 0.1B：还在 warmup，\(\eta=6\times10^{-5}\times0.1/0.375=1.6\times10^{-5}\)。
  • 10B：\(\tau=(10-0.375)/259.625=0.0371\)，\(\cos(\pi\tau)=0.9932\)，\(\eta=6\times10^{-5}\times(0.1+0.45\times1.9932)=5.98\times10^{-5}\)，几乎还是峰值（余弦开头降得慢）。
  • 200B：\(\tau=0.7689\)，\(\cos(\pi\tau)=-0.7478\)，\(\eta=6\times10^{-5}\times(0.1+0.45\times0.2522)=1.28\times10^{-5}\)。
  • 280B：已过 260B，保持 \(6\times10^{-6}\)。
练习 7 · 用 6ND 算账

GPT-3 XL 有 1.32B 参数（表 D.1 的写法），训练 300B token。（a）训练算力是多少 FLOPs、多少 PF-days？（b）假设一个集群能持续提供 \(10^{17}\) FLOP/s，需要多少小时？（c）注意力打分部分约占多少（\(n_{ctx}=2048\)，\(d=2048\)）？

看答案

（a）\(6\times1.32\times10^9\times3\times10^{11}=2.376\times10^{21}\) FLOPs，除以 \(8.64\times10^{19}\) 得 27.5 PF-days，与表 D.1 一致 4。

（b）\(2.376\times10^{21}/10^{17}=23{,}760\) 秒，约 6.6 小时。

（c）按 §6 的比值（注意力项 ÷ 参数项，其中参数项按每层 \(12d^2\) 近似）：\(n_{ctx}/(12d)=2048/(12\times2048)=1/12\approx8.3\%\)。换成占总算力的份额是 \(\frac{1/12}{1+1/12}=1/13\approx7.7\%\)。对这个较窄的模型，注意力已经不能完全忽略；GPT-3 175B 的 \(d\) 大 6 倍，比值就降到了 1.4%（此时比值与份额只差小数点后第二位）。

练习 8 · 给定 10²⁴ FLOPs，怎么分

算力预算 \(C=10^{24}\) FLOPs。（a）按“每参数 20 token”，\(N\)、\(D\) 各是多少？（b）按 Chinchilla 方法 3 的未四舍五入参数（\(G=1.300\)，\(a=0.4565\)），\(N\)、\(D\) 与每参数 token 数各是多少？（c）如果预算变成 \(10^{25}\)，按 (a) 的法则 \(N\) 放大多少倍？按 Kaplan 的指数呢？

看答案

（a）\(N=\sqrt{10^{24}/120}=9.13\times10^{10}\)（91.3B），\(D=20N=1.83\times10^{12}\)（1.83T）。

（b）\(C/6=1.667\times10^{23}\)，\(N=1.300\times(1.667\times10^{23})^{0.4565}=5.19\times10^{10}\)（51.9B），\(D=C/(6N)=3.21\times10^{12}\)（3.21T），每参数约 62 个 token。

（c）按 (a)：\(N\propto C^{0.5}\)，放大 \(10^{0.5}=3.16\) 倍。按 Kaplan：\(10^{0.73}=5.37\) 倍。

练习 9 · 幂律的“价格”

按 Kaplan 的 \(L(N)=(N_c/N)^{0.076}\)：（a）参数放大 10 倍，损失乘多少？（b）要把损失降低 10%，参数要放大多少倍？

看答案

（a）\(10^{-0.076}=0.839\)，降 16%。

（b）要 \(k^{-0.076}=0.9\)，\(k=0.9^{-1/0.076}=e^{0.1054/0.076}=e^{1.386}=4.0\)，参数要放大 4 倍。损失每再降 10%，都要再乘 4 倍：这就是幂律“越往后越贵”的含义。

练习 10 · BF16 会丢掉多小的更新

就像 §6 黑板上那台三位计算器：（a）BF16 有 7 位尾数。一个值为 1.0 的权重，BF16 里与它相邻的下一个数是多少？（b）就近舍入时，小于多少的更新会被整个舍掉？（c）学习率 \(10^{-3}\) 的 Adam 步长约为 \(10^{-3}\)，它能改动这个权重吗？学习率 \(10^{-4}\) 呢？

看答案

（a）\(1.0\) 在 \([2^0,2^1)\) 里，间隔 \(2^{0-7}=2^{-7}=0.0078125\)，下一个数是 \(1.0078125\)。

（b）不到半个间隔，即小于 \(2^{-8}\approx0.0039\) 的向上更新会舍回 1.0。向下要小心：1.0 正好在区间的左端，它下面的数属于 \([2^{-1},2^0)\)，间隔只有 \(2^{-8}\)，所以向下的门槛是 \(2^{-9}\approx0.0020\)。

（c）\(10^{-3}\) 比两个门槛都小：两个学习率下的更新，不论向上还是向下，都会被整个舍掉。直接用 BF16 存这个权重，训练就停在原地；这就是混合精度要保留 FP32 主权重的原因（§6）。

推导题

练习 11 · 最大似然 = 最小化 KL

设真实文本在某个前缀之后的下一 token 分布为 \(q\)，模型为 \(p_\theta\)。证明：最小化期望损失 \(\E_{x\sim q}[-\log p_\theta(x)]\) 等价于最小化 \(\KL(q\,\|\,p_\theta)\)，并说明损失的最小可能值是多少、何时取到。

看答案

\(\E_{x\sim q}[-\log p_\theta(x)]=-\sum_xq(x)\log p_\theta(x)=H(q,p_\theta)\)。按 §2 的推导，

\[H(q,p_\theta)=H(q)+\KL(q\,\|\,p_\theta).\]

\(H(q)\) 与 \(\theta\) 无关，所以两个最小化问题的最优 \(\theta\) 相同。由吉布斯不等式 \(\KL(q\,\|\,p_\theta)\ge0\)，等号当且仅当 \(p_\theta=q\)，所以损失的最小值是 \(H(q)\)，在模型分布与真实分布完全一致时取到。实际训练中我们只能用语料的经验分布代替 \(q\)，这就是“最大似然”。

练习 12 · 最优点上两项损失的比例

在 Chinchilla 的 \(\hat L=E+A/N^\alpha+B/D^\beta\) 与约束 \(6ND=C\) 下，证明在最优点上“模型有限”项与“数据有限”项之比恒为

\[\frac{A/N_{\text{opt}}^{\alpha}}{B/D_{\text{opt}}^{\beta}}=\frac{\beta}{\alpha},\]

与 \(C\) 无关。用 \(C=10^{21}\) 与未四舍五入的参数验证。（§7 黑板上 \(\alpha=\beta\)，两项正好相等，就是这个比例等于 1 的情形。）

看答案

§7 推导的第三行给出最优条件 \(\alpha AN^{-\alpha}=\beta BD^{-\beta}\)。两边同除以 \(\alpha BD^{-\beta}\)，得 \(\frac{AN^{-\alpha}}{BD^{-\beta}}=\frac{\beta}{\alpha}\)，右边是常数。

验证：\(C=10^{21}\) 时 \(N_{\text{opt}}=2.217\times10^9\)，\(D_{\text{opt}}=C/(6N)=7.52\times10^{10}\)。\(A/N^\alpha=406.4/(2.217\times10^9)^{0.3392}=0.275\)，\(B/D^\beta=410.7/(7.52\times10^{10})^{0.2849}=0.327\)，比值 \(0.840\)；而 \(\beta/\alpha=0.2849/0.3392=0.840\)。

含义：沿着最优前沿放大算力时，两项可减少的损失始终按固定比例一起下降，没有哪一项被“单独偏爱”。这是“参数与数据同比例增长”的另一种说法。
