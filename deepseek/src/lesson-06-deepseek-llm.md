## 这一课回答什么问题

[第 5 课](lesson-05-modern-block.html)把一个现代 Transformer 块搭好了：Pre-RMSNorm、SwiGLU、RoPE。积木有了，下一个问题是：**用这些积木盖一栋多大的楼、备多少材料、按什么节奏施工？** 这不是细枝末节。一次 67B 模型的预训练要花大约 $8.65\times10^{23}$ 次浮点运算（§5 会算出这个数），只能跑一遍。batch size 取错一倍、学习率取错一倍、模型大小和数据量配比失当，赔进去的都是整次训练。

DeepSeek 在 2023 年 11 月发布第一代通用大模型 DeepSeek LLM 7B 与 67B，2024 年 1 月发表技术报告 [@dsllm]。它的架构几乎照搬 LLaMA，报告的主要篇幅却花在“怎么花算力”上。读完这一课，下面这些问题你都能自己回答，并且能用计算器复核报告里的数字：

- batch size 和学习率怎样随算力变化？为什么 67B 用 $3.2\times10^{-4}$ 的学习率、每步 4608 条序列？
- “模型有多大”该用什么量来记？为什么 DeepSeek 不用人人都在用的 $6N$，而改用“每 token 非嵌入 FLOPs” $M$？
- 算力多出十倍，该多给模型还是多给数据？为什么 Kaplan 和 Chinchilla 两篇著名论文的答案差这么多？
- 多步学习率调度的最终效果和 cosine 一样，它多出来的好处在哪里？
- 67B 为什么是 95 层？GQA 省下来的参数去了哪里？

## 这一课在科技树上的位置

这一课在主线 F（规模化规律与优化器）上，同时碰到主线 A（GQA 与 KV cache）。它用到三课的积累：[第 2 课](lesson-02-gpt-training.html)的 $C\approx6ND$、学习率调度和 Kaplan/Chinchilla 两套 scaling law；[第 4 课](lesson-04-inference-kv-cache.html)的 KV cache 账单与 GQA；[第 5 课](lesson-05-modern-block.html)的 LLaMA 式块。

上一课留下的问题是：**积木定了，怎么把它放大？** DeepSeek LLM 是后面所有 DeepSeek 模型的起点。它拟合出的超参数规律被同期的 DeepSeek-Coder 直接拿去用（§8），报告的结尾预告了代码和混合专家（MoE）两份报告 [@dsllm]，后者就是[第 7 课](lesson-07-deepseekmoe.html)的 DeepSeekMoE。

# 问题：一次性的大训练，靠小实验下注 | DeepSeek LLM 要回答的三个问题，以及整个配方的全景 | 15

先看账单。DeepSeek LLM 67B 在 2 万亿（$2\times10^{12}$）个 token 上预训练，按 §5 的记账方式，总算力约 $8.65\times10^{23}$ FLOPs；7B 约 $8.49\times10^{22}$ FLOPs。这样的训练只能跑一次。可是开跑之前必须先定下一串数：每一步喂多少 token（batch size），学习率多大，学习率怎样随训练下降，模型做多大，数据喂多少。每一个都影响最终效果，而且都没法在目标规模上反复试。

DeepSeek 的报告把处境说得很直白：早先关于“算力该怎么在模型和数据之间分”的研究结论互不一致，让人怀疑 scaling law 是否普遍适用；这些研究还常常没有完整交代超参数，没法确认各个预算下的模型是否真的训练到了最优 [@dsllm]。所以它决定自己把 scaling 研究重做一遍，而且从超参数做起。

## DeepSeek LLM 是什么

**含义。** DeepSeek LLM 是 DeepSeek 的第一代通用语言模型，有 7B 和 67B 两个尺寸，各有基座（Base）版和对话（Chat）版。

**理解。** 时间上要分清两件事：模型权重在 **2023 年 11 月 29 日**前后发布到 Hugging Face 和 GitHub [@hf-llm-cfg; @gh-llm]，技术报告在 **2024 年 1 月 5 日**才发到 arXiv [@dsllm]，晚了五周多。预训练数据 2T token，以中文和英文为主。报告标题里的 “Longtermism”（长期主义），用报告自己的话说，是把 DeepSeek LLM 当作一个“以长期视角推进开源语言模型的项目” [@dsllm]。落实到技术上，就是先把“怎样可靠地放大”研究清楚，再去放大。

**全景。** 本课的全部内容可以放进一张流程图。

**看紫色虚线框：报告真正下功夫的地方在这里。** 上排的数据管线和下排的模型结构大多沿用前人的做法；报告最用力的部分，是在 $10^{17}$ 到 $3\times10^{20}$ FLOPs 的小预算上做系统实验，拟合出“最优超参数”和“最优模型/数据分配”随算力变化的幂律，再外推到 7B、67B 的真实训练。每个框右上角标着本课讲它的那一页。框内数字取自 DeepSeek LLM 报告 [@dsllm]。

## 三个问题

报告的 scaling 研究依次回答三个问题。先把它们摆清楚，后面每一页都在回答其中之一。

**问题一：超参数。** 给定算力 $C$，最优的 batch size $B$ 和学习率 $\eta$ 是多少？小模型上可以网格搜索，大模型上不行。

**问题二：记账。** 算力 $C$ 和“模型规模”“数据量”是什么关系？第 2 课的惯例是 $C\approx6ND$，$N$ 是参数量。可是 $N$ 算不算嵌入矩阵？注意力里随序列长度增长的那部分计算算不算？DeepSeek 发现，不同的记法在小模型上能差到 50% [@dsllm]，足以把拟合出来的曲线带偏。

**问题三：分配。** 算力固定时，模型做多大、数据喂多少，损失最低？算力增加时，两者各该长多少？前人研究过这个问题，但答案互相矛盾。

::: pre 幂律与双对数坐标 | 熟悉“$y=kx^a$ 在双对数坐标里是直线”的可以跳过
**幂律**（power law）指 $y=k\,x^{a}$ 这种关系，$k>0$ 是系数，$a$ 是指数。两边取对数：

$$y=k\,x^{a}\quad\Longleftrightarrow\quad\log y=\log k+a\log x$$

所以在横轴、纵轴都取对数的**双对数坐标**里，幂律是一条直线，斜率就是 $a$。

它最好用的读法是“倍数”：$x$ 变成 10 倍，$y$ 就变成 $10^{a}$ 倍，与 $x$ 原来多大无关。$a=0.5$ 时，$x$ 乘 10，$y$ 乘 $\sqrt{10}\approx3.16$；$a$ 为负时 $y$ 随 $x$ 变小。scaling law 的研究几乎全部用这种语言说话，[第 2 课 §7](lesson-02-gpt-training.html#p7)已经用过。
:::

::: ex 两篇论文，同一个问题，两个答案
第 2 课讲过两套结论。Kaplan 等人（2020）得到最优参数量 $N_{opt}\propto C^{0.73}$、数据量 $D\propto C^{0.27}$ [@kaplan]；Chinchilla（Hoffmann 等人，2022）用 IsoFLOP 方法得到的指数是 $0.49$ 与 $0.51$ [@chinchilla]。用上面的“倍数”读法，算力从 $10^{21}$ 增到 $10^{24}$，即 1000 倍：

- 按 Kaplan：模型 $\times1000^{0.73}\approx155$ 倍，数据只 $\times1000^{0.27}\approx6.5$ 倍。
- 按 Chinchilla：模型 $\times1000^{0.49}\approx29.5$ 倍，数据 $\times1000^{0.51}\approx33.9$ 倍。

同样是 1000 倍的算力，一个说“大头给模型”（按数量级计 73% 给模型），一个说“模型和数据大致对半分”，得到的模型大小相差 5 倍多。DeepSeek 报告提出的一个可能的解释是：**数据质量不同，最优分配就不同**（§7；报告的措辞是这一发现“也许能解释”前人的分歧）。
:::

## 用小实验给大训练下注

三个问题用的是同一种方法：在便宜的小预算上做大量实验，把结果拟合成幂律，然后外推。图 6.2 把实验所在的位置和真实训练所在的位置画在同一根对数轴上。

::: fig figures/l06-extrapolation.svg | 图 6.2 实验在左边做，赌注下在右边
**看绿色星号与紫色点之间的距离：7B 的训练算力是最大一组 IsoFLOP 实验的 283 倍，67B 是 2885 倍。** 按正文，超参数公式拟合自 $10^{17}$ 到 $2\times10^{19}$ 的实验，外推到 67B 相当于放大约 4.3 万倍。报告说小规模实验可以准确预测“1000 倍算力”的模型表现，这是数量级上的说法。位置由脚本按报告数字计算 [@dsllm]；7B、67B 的算力 $C=MD$ 在 §5 推导。
:::

::: ana 类比：风洞试验
**映射。** 飞机造出来之前，工程师先把缩小的模型放进风洞，测它的升力和阻力，再按相似律换算到真飞机上。在这里，小预算实验 = 风洞里的缩比模型；拟合出来的幂律 = 相似律；7B、67B 的真实训练 = 真飞机的首飞。

**收益。** 它说明这套方法的关键不在“做了多少次实验”，而在“换算规则对不对”：换算规则错了，实验做得再多，外推到几百倍、几千倍以外也会差之千里。§5 讲的记账方式，修的正是换算规则。

**失效的地方。** 风洞的相似律来自流体力学方程，有理论保证；语言模型的 scaling law 是对实验点的经验拟合，没有定理保证它在拟合范围之外仍然成立，只能靠事后验证。报告图 5 里，7B、67B 的实际验证损失落在小实验拟合出的曲线上，报告据此说它们的表现“被 scaling 曲线很好地预测了” [@dsllm]，这一次外推才算得到证实。另外，有些现象在小规模上根本不出现（例如只在大模型上出现的训练不稳定），风洞里测不到。
:::

::: warn 正文与图不完全一致
报告正文说超参数实验的预算是 $10^{17}$ 到 $2\times10^{19}$ [@dsllm]。研究笔记对原图做过像素反解：报告图 3(a)（batch size 拟合图）里代表“近优”的灰点一直延伸到约 $1.6\times10^{20}$，而图 3(b)（学习率拟合图）的灰点只到约 $2.4\times10^{19}$。也许图 3(a) 另外画进了 $10^{20}$ 验证实验的点，报告没有说明。本课引用拟合范围时一律写“正文称”。

# 数据：去重、过滤、重混，以及分词器 | 跨 dump 去重为什么删得更多，MinHash 怎么找近似重复，词表为什么是 102400 | 20

预训练数据决定了模型能学到什么。网页数据有两个天然的毛病：**重复**（同一篇文章被转载，或被不同月份的爬虫反复抓到）和**稀释**（大量信息量很低的文本，如导航栏、广告、模板页）。重复让模型把算力花在背同一段话上，稀释让每个 token 能教给模型的东西变少。DeepSeek LLM 的数据管线用三个阶段应对：去重（deduplication）、过滤（filtering）和重混（remixing）。按报告的说法，去重和重混通过“只采样独一无二的实例”保证多样性，过滤则提高信息密度 [@dsllm]。

## 去重：为什么要跨 dump 一起做

**含义。** Common Crawl 是一个公开的网页爬取项目，隔一段时间把爬到的网页打包发布一次，每一次发布叫一个 **dump**（快照）。**去重**就是在语料里找出内容相同或几乎相同的文档，只留一份。

**理解。** 同一个网页往往出现在很多个 dump 里：只要它还挂在网上，下一次爬取还会再抓到它。如果只在每个 dump 内部去重，一个页面在 91 个 dump 里就各留一份，合起来仍然重复 91 次。所以去重的范围越大，找到的重复越多。

**数学。** 把**去重率**定义为“被删掉的文档数 ÷ 去重前的文档总数”。报告表 1 给出了不同范围下的去重率（图 6.3 下）：只在 1 个 dump 内去重是 22.2%，把 91 个 dump 合在一起去重是 89.8% [@dsllm]。

::: ex 读报告表 1
- 91 个 dump 一起去重，删 89.8%，**留 10.2%**；单个 dump 内去重，删 22.2%，留 77.8%。
- 报告说跨 91 个 dump 去重“删掉的文档是单 dump 方法的四倍”：$89.8/22.2\approx4.05$。
- 换一个角度。表 1 只给了一个 dump 的单独去重率；假设 91 个 dump 各自单独去重时都删掉约 22.2%（笔者的假设），同样一堆原始文档，逐个 dump 去重后剩 77.8%，全局去重后剩 10.2%，相差 $77.8/10.2\approx7.6$ 倍。也就是说，只在单个 dump 内去重的话，留下来的文档里约有 $1-10.2/77.8\approx87\%$ 是多余的副本：同样的内容在别的 dump 里已经留了一份。

表 1 还显示去重率随 dump 数**递增，但增速总体上放缓**：从 1 个到 2 个 dump 跳了 24.5 个百分点，从 41 个到 91 个（多了 50 个 dump）只多了 8.2 个百分点。放缓并不逐段单调：16 到 22 个 dump 只多 0.6 个点，22 到 41 个又多了 5.3 个点。报告没有分析这个形状；一个自然的读法是，新增的 dump 里越来越多的内容已经在前面的 dump 里出现过（笔者的读法）。
:::

## 怎样在几十亿篇文档里找“几乎一样”的两篇：MinHash

**问题。** 完全相同的文档好找：给每篇算一个哈希值，哈希相同就是重复。难的是**近似重复**：同一篇新闻被不同网站转载，页眉页脚不同，正文一样。逐对比较 $n$ 篇文档要 $n(n-1)/2$ 次，$n$ 是几十亿时根本做不完。

DeepSeek 的报告没有写去重算法。GitHub README 说，它的去重系统用 **MinHash LSH**，在文档级和字符串级两个层次去重，最小可行方案以 RefinedWeb 和 CCNet 为起点 [@gh-llm]。下面讲清 MinHash 的原理。它是一个可以当场证明的概率事实，不依赖 DeepSeek 任何未公开的细节。

**含义。** 先定义“两篇文档有多像”。把一篇文档切成许多 **shingle**（片段：连续 $w$ 个词或字），得到片段的集合 $S$。例如按相邻 2 个字切，“小猫坐在垫子上”的片段集合是 {小猫, 猫坐, 坐在, 在垫, 垫子, 子上}。两篇文档的 **Jaccard 相似度**是：

::: eq Jaccard 相似度 | (6.1)
$$J(S_A,S_B)=\frac{\lvert S_A\cap S_B\rvert}{\lvert S_A\cup S_B\rvert}\in[0,1]$$
两篇文档共有的片段数，除以两篇合起来的不同片段数。完全相同为 1，没有任何共同片段为 0。
:::

**理解。** “小猫坐在垫子上”和“小猫坐在毯子上”共有 4 个片段（小猫、猫坐、坐在、子上），合起来有 8 个不同的片段，所以 $J=4/8=0.5$。直接算 (6.1) 要把两个集合摆在一起比，面对几十亿篇文档，这仍是逐对比较。MinHash 的想法是：给每篇文档算一个很短的“指纹”，让两个指纹相同的**概率**恰好等于 $J$。

**数学。** 取一个把所有可能的片段随机打乱顺序的函数 $h$（一个**均匀**随机的排列：每一种顺序出现的概率都相同），定义 $\mathrm{mh}(S)=\min_{s\in S}h(s)$，也就是集合里排得最靠前的那个片段的名次。图 6.4 左边用上面两句话演示了四次这样的排列。

::: deriv 两个 MinHash 相等的概率恰好是 Jaccard 相似度
$\text{考察并集 }S_A\cup S_B\text{ 中名次最靠前的片段 }s^*$ || $h$ 是均匀随机排列，并集里每个元素排在最前的机会相同，所以 $s^*$ 是并集里均匀随机的一个元素
$\mathrm{mh}(S_A)=\mathrm{mh}(S_B)\iff s^*\in S_A\cap S_B$ || 若 $s^*$ 同属两个集合，它同时是两边的最小者；若只属于一边，另一边的最小者名次更靠后，两者不等
$\Pr[\mathrm{mh}(S_A)=\mathrm{mh}(S_B)]=\Pr[s^*\in S_A\cap S_B]$ || 上一行的两个事件是同一个事件
$=\dfrac{\lvert S_A\cap S_B\rvert}{\lvert S_A\cup S_B\rvert}=J(S_A,S_B)$ || 均匀随机的元素落进交集的概率 = 交集大小 ÷ 并集大小
:::

用 $K$ 个彼此独立的随机排列 $h_1,\dots,h_K$，每篇文档得到 $K$ 个 MinHash 值（叫它的**签名**）。两篇文档签名里相同位置的比例

$$\hat J=\frac1K\sum_{k=1}^{K}\mathbf{1}\bigl[\mathrm{mh}_k(S_A)=\mathrm{mh}_k(S_B)\bigr]$$

是 $J$ 的一个无偏估计（$\mathbf 1[\cdot]$ 在括号内条件成立时取 1，否则取 0）：每一项是成功概率为 $J$ 的伯努利变量，均值为 $J$，所以平均值的期望也是 $J$；各项独立，方差为 $J(1-J)/K$，$K$ 越大估计越准。例如 $J=0.5$、$K=100$ 时标准差是 $\sqrt{0.25/100}=0.05$，估计值大约 95% 的时候落在 0.4 到 0.6 之间（均值加减两个标准差）。这还不够快：比较签名仍是逐对的。**LSH**（locality-sensitive hashing，局部敏感哈希）再走一步：把 $K$ 个值分成 $b$ 带、每带 $r$ 个（$K=br$），每一带整体算一个哈希放进桶里；两篇文档只要**有一带**完全相同，就成为“候选对”，只有候选对才做精确比较。

::: eq 分带 LSH：两篇文档成为候选对的概率 | (6.2)
$$P(\text{候选}\mid J)=1-\bigl(1-J^{\,r}\bigr)^{b}$$
一带里 $r$ 个值全相同的概率是 $J^r$（各排列独立）；$b$ 带用的是不同的排列，彼此独立，所以“至少一带全相同”的概率等于 1 减去“每一带都不全同”的概率 $(1-J^r)^b$。这里假设桶哈希不会把两段不同的带内容放进同一个桶（忽略碰撞）。这里的 $b$ 只在本节使用，与 §7 的数据指数 $b$ 无关。
:::

::: ex 一组示意参数（不是 DeepSeek 的参数，报告与 README 都没有公开）
取 $K=100$，分成 $b=20$ 带，每带 $r=5$ 个。

- $J=0.8$ 的近似重复：$0.8^5=0.328$，$P=1-0.672^{20}\approx1-0.0004=0.9996$，几乎必被抓到。
- $J=0.5$：$0.5^5=0.03125$，$P=1-0.96875^{20}\approx0.47$。
- $J=0.2$：$0.2^5=0.00032$，$P=1-0.99968^{20}\approx0.0064$，基本不会成为候选对。

$P$ 随 $J$ 的变化像一个开关。开关大约在 $J^r\approx1/b$ 处拨动：此时每一带命中的概率约 $1/b$，$b$ 带合起来命中的概率约 $1-(1-1/b)^b\approx1-e^{-1}\approx0.63$。对这组参数，$J\approx(1/20)^{1/5}\approx0.55$。每篇文档只和落进同一个桶的文档比较，$n^2$ 次比较就这样避开了。
:::

::: fig figures/l06-minhash-lsh.svg | 图 6.4 MinHash 怎样把“相似度”变成“相等的概率”，分带 LSH 又怎样把它变成开关 | scroll
**先看左图每一行排第一的那个片段：它是绿色（两篇都有）时，A 和 B 的最小名次落在同一格，两个 MinHash 相等；它是蓝色或紫色时，两者不等。** 并集 8 个片段里有 4 个绿色，所以随机排一次，相等的概率是 $4/8=J$，这就是上面推导的第二、四行；四个排列里恰好两次相等，只是这个小例子凑巧，一般要平均很多次才接近 $J$。右图是 (6.2)：只比一个 MinHash 值时，成为候选对的概率就是 $J$ 本身（灰色点线）；分成 $b=20$ 带、每带 $r=5$ 个之后（蓝色实线），$J<0.3$ 几乎不会成为候选对，$J>0.7$ 几乎必被抓到，中间在 $J\approx0.55$ 附近陡升。虚线是练习 10 的 $b=25$、$r=4$，开关左移到约 0.45。例句与排列是笔者构造的示意，参数不是 DeepSeek 的（未公开）；曲线由脚本按 (6.2) 计算。
:::

::: warn 失败模式：MinHash 只认片段，不认意思
MinHash 衡量的是“共有多少片段”，所以同一内容换一种说法（改写、翻译）它认不出来；反过来，两篇不同的网页如果共享大段模板（相同的页眉、页脚、导航栏），片段重合度会虚高，被误判成重复。实践中要先把正文从网页模板里抽出来再算指纹（笔者注：这一步属于 CCNet、RefinedWeb 一类管线的正文抽取环节，DeepSeek 没有公开自己的做法）。
:::

## 过滤与重混：报告只给了方向

过滤阶段，报告说它为文档质量制定了“稳健的评判标准”，结合**语言学**和**语义**两类评估，“从个体和全局两个角度”看数据质量；重混阶段，它调整数据配比以纠正失衡，重点是提高**代表性不足的领域**的占比 [@dsllm]。报告没有给出过滤用的模型或阈值、重混后的领域配比，也没有给出 2T token 里中文、英文、代码、数学各占多少。这些只能写“未公开”。

报告在 §3 的开头另有一句话，把数据质量和本课后半部分连了起来：最优的模型/数据分配策略不同，“也可以作为间接评估数据质量的一种方法” [@dsllm]。§7 会看到，这句话背后是一个可以测量的数：分配指数 $a$。

## 分词器：BBPE、逐位数字与 102400

::: pre BPE 回顾 | 学过第 1 课 BPE 的可以跳过
**BPE**（byte pair encoding，字节对编码）从最小的单位出发，反复把语料里最常见的相邻一对合并成一个新 token，直到词表达到预定大小。**字节级** BPE（byte-level BPE，BBPE）从 256 个字节出发，所以任何文本（包括任何语言、表情符号）都能被编码，不会出现“未知字符”。**预分词**（pre-tokenization）在 BPE 之前先按规则把文本切成小段，BPE 只在段内合并。细节见 [第 1 课 §2](lesson-01-transformer-anatomy.html#p2)。
:::

DeepSeek LLM 的分词器基于 Hugging Face 的 tokenizers 库实现 BBPE。预分词规则防止不同字符类别的 token 合并在一起，例如换行、标点和中日韩（CJK）字符，做法与 GPT-2 类似；此外，**数字被拆成单个数位** [@dsllm]。分词器在约 24 GB 的多语言语料上训练，常规 token 设为 100000 个，再加 15 个特殊 token，共 100015 个；训练时模型的词表大小设为 102400，既为了计算效率，也为将来可能增加的特殊 token 预留位置 [@dsllm]。

::: ex 词表的账
- 已用 id：$100000+15=100015$；嵌入矩阵实际有 $102400$ 行，预留 $102400-100015=2385$ 行。
- $102400=100\times1024=400\times256$，是 256 的整数倍。报告只说是“为了计算效率”；笔者注：矩阵维度取 64、128、256 的倍数，便于 GPU 上的矩阵乘法分块。
- 这 15 个追加 token 里，只有句首（BOS）和句末（EOS）两个在 `tokenizer.json` 里标成特殊符号；另外 13 个是单个的 Latin-1 字符（如 ø、ö、ü），标为非特殊 [@hf-llm-cfg]。它们为什么以追加方式存在，官方没有说明。
- 输入嵌入和输出头**不共享**权重（config 里 `tie_word_embeddings: false`），各占 $Vd$ 个参数。7B：$2\times102400\times4096=838{,}860{,}800$，占总参数 $6{,}910{,}365{,}696$ 的 12.1%；67B：$2\times102400\times8192=1{,}677{,}721{,}600$，只占 2.5% [@hf-llm-cfg]。
:::

**为什么把数字拆成单个数位？** 报告只说这是沿用 LLaMA（Touvron 等人 2023a、2023b）的做法，没有给理由 [@dsllm]。一个常见的考虑是（笔者解释）：不拆的话，BPE 会按出现频率把某些数字串合并成整体，比如 “2023” 可能是一个 token，而 “2123” 被切成两三个，同一种数量关系在模型眼里就有了互不相干的写法；逐位切开后，每个数都用同样的 10 个“字母”拼出来。

::: warn 失败模式：词表越大，小模型越“头重”
7B 有 12.1% 的参数花在嵌入和输出头上，67B 只有 2.5%。这些参数对“每个 token 的思考量”贡献不大（输入嵌入是查表，没有乘法；输出头虽然要做一次矩阵乘，报告认为这部分词表计算对模型能力的贡献较小），却实实在在地占显存。这有两个后果：一是 §3 里 7B 只放了 30 层，而不是 LLaMA-1 6.7B 的 32 层；二是 §5 里 DeepSeek 坚持把词表的计算量排除在模型规模 $M$ 之外。
:::

::: key 本页要点
- 三阶段：去重（保多样）、过滤（提密度）、重混（纠失衡）。跨 91 个 dump 去重删掉 89.8% 的文档，是单 dump 去重的 4.05 倍。
- MinHash：两个签名值相同的概率恰好是 Jaccard 相似度；分带 LSH 把“是否近似重复”变成一个陡峭的概率开关，避开逐对比较。
- 分词器：字节级 BPE，数字逐位切分；100000 + 15 个 token，嵌入矩阵 102400 行。7B 的嵌入与输出头占 12.1% 参数。
- 过滤模型、阈值、领域配比都没有公开；报告把“最优分配指数”当作间接的数据质量指标（§7）。
:::

# 架构：LLaMA 的积木，DeepSeek 的层数 | 参数量逐位复现、67B 的 GQA、“加深而非加宽” | 20

参数预算定下来（“7B 左右”“67B 左右”）之后，还有一串形状上的选择：堆多少层，每层多宽，注意力用几组键值头。同样是 670 亿参数、同样的隐藏维度，可以是 80 层、每层参数多一些的网络，也可以是 95 层、每层参数少一些的网络；注意力省下来的参数，可以加到前馈层的宽度上，也可以加到层数上。这些选择决定了训练效率、推理时的显存和延迟。DeepSeek LLM 的回答分两层：**微观**（一个块里面长什么样）照搬 LLaMA；**宏观**（层数、宽度、注意力类型）自己定 [@dsllm]。

## 参数量：逐位复现“7B”和“67B”

**问题。** 模型卡上写的“7B”“67B”是四舍五入的名字。§5 要精确地数 FLOPs，§7 要判断模型是不是“算力最优”，都需要知道参数量到底是多少、分布在哪里。能逐位复现官方数字，才说明我们对结构的理解没有遗漏。

**数学。** 一层的参数由四部分组成（DeepSeek LLM 的线性层都没有偏置）：

::: eq 一层的参数量 | (6.3)
$$P_{\text{layer}}=\underbrace{2d^2}_{W^Q,\,W^O}+\underbrace{2\,d\,n_gd_h}_{W^K,\,W^V}+\underbrace{3\,d\,d_{ff}}_{\text{SwiGLU 三个矩阵}}+\underbrace{2d}_{\text{两个 RMSNorm}}$$
$W^Q\in\R^{n_hd_h\times d}$、$W^O\in\R^{d\times n_hd_h}$，因为 $n_hd_h=d$，各有 $d^2$ 个参数；$W^K,W^V\in\R^{n_gd_h\times d}$；SwiGLU 有门控 $W_{gate}$、线性 $W_{up}$（都是 $d_{ff}\times d$）和下投影 $W_{down}$（$d\times d_{ff}$）三个矩阵；每个 RMSNorm 有一个长度为 $d$ 的缩放向量。
:::

整个模型再加上最后一个 RMSNorm（$d$ 个参数）、输入嵌入和输出头（各 $Vd$ 个）：

::: eq 总参数量 | (6.4)
$$N_{\text{total}}=L\cdot P_{\text{layer}}+d+2Vd$$
:::

::: deriv 7B 的参数量（$L=30$，$d=4096$，$n_g=32$，$d_h=128$，$d_{ff}=11008$，$V=102400$）
$2d^2=2\times4096^2=33{,}554{,}432$ || $W^Q$、$W^O$ 各 $4096\times4096$
$2\,d\,n_gd_h=2\times4096\times32\times128=33{,}554{,}432$ || MHA：$n_gd_h=4096=d$，所以和上一项相等
$3\,d\,d_{ff}=3\times4096\times11008=135{,}266{,}304$ || SwiGLU 三个矩阵
$P_{\text{layer}}=33{,}554{,}432\times2+135{,}266{,}304+8{,}192=202{,}383{,}360$ || 加上两个 RMSNorm 的 $2d=8192$
$L\cdot P_{\text{layer}}+d=6{,}071{,}500{,}800+4{,}096=6{,}071{,}504{,}896$ || 30 层，加最终 RMSNorm：这是非嵌入参数
$N_{\text{total}}=6{,}071{,}504{,}896+2\times102400\times4096=6{,}910{,}365{,}696$ || 加嵌入与输出头 $838{,}860{,}800$
:::

这个数与官方权重文件记录的总字节数（13,820,731,392 字节，bf16 每个参数 2 字节）除以 2 逐位一致 [@hf-llm-cfg]。所以“7B”其实是 69.1 亿，其中 12.1% 是嵌入与输出头。

::: ex 67B 的参数量
$d=8192$，$n_g=8$，$d_{ff}=22016$，$L=95$。

- 注意力：$2d^2=134{,}217{,}728$；$2\,d\,n_gd_h=2\times8192\times8\times128=16{,}777{,}216$。
- SwiGLU：$3\times8192\times22016=541{,}065{,}216$；RMSNorm：$2\times8192=16{,}384$。
- $P_{\text{layer}}=692{,}076{,}544$；$\times95=65{,}747{,}271{,}680$；加最终 RMSNorm 得非嵌入参数 $65{,}747{,}279{,}872$。
- 加嵌入与输出头 $2\times102400\times8192=1{,}677{,}721{,}600$，总计 $67{,}425{,}001{,}472$，与官方权重的 134,850,002,944 字节除以 2 一致。

注意 FFN 占一层参数的 $541{,}065{,}216/692{,}076{,}544\approx78\%$。FFN 中间维 22016 比 $\tfrac83\times8192\approx21845.3$ 略大，$22016/8192=11008/4096=2.6875$；config 用的是取整后的值，取整规则报告没有写。
:::

## GQA：67B 为推理省下的 KV cache

::: pre MHA、GQA、MQA | 学过第 4 课的可以跳过
自回归解码时，每个已生成的 token 都要把自己的键 $\mathbf k$ 和值 $\mathbf v$ 存进 **KV cache**，后面每一步的查询都要读一遍它（[第 4 课 §2](lesson-04-inference-kv-cache.html#p2)；MQA 与 GQA 见同课 [§5](lesson-04-inference-kv-cache.html#p5)）。多头注意力（MHA）里每个头都有自己的键和值，缓存最大。GQA 的原始定义是：把查询头分成 $n_g$ 组（原论文记作 $G$），每组共享一个键头和一个值头；$n_g=1$ 就是多查询注意力（MQA），$n_g=n_h$ 就是 MHA [@gqa]。所以 GQA 是在 MHA 的质量与 MQA 的缓存之间取一个中间点。
:::

每个 token 在每一层要缓存 $n_g$ 个键向量和 $n_g$ 个值向量，每个长 $d_h$。用 bf16（每个数 2 字节）存：

::: eq 每 token 的 KV cache 字节数 | (6.5)
$$\text{KV 字节/token}=2\times L\times n_g\times d_h\times 2$$
第一个 2 是键和值两份，最后一个 2 是 bf16 的字节数。
:::

::: ex GQA 给 67B 省了多少
- 7B（MHA）：$2\times30\times32\times128\times2=491{,}520$ 字节 $=480$ KiB/token。
- 67B（GQA-8）：$2\times95\times8\times128\times2=389{,}120$ 字节 $=380$ KiB/token。
- 假如 67B 用 MHA（$n_g=64$）：乘以 8，$3{,}112{,}960$ 字节 $\approx2.97$ MiB/token。

一条 4096 token 的满长度序列：7B 要 1.875 GiB，67B 要 1.484 GiB；MHA 版的 67B 要 11.875 GiB。结论有点反直觉：参数多 10 倍的 67B，每个 token 的缓存反而比 7B 小，因为它的 KV 头从 64 个减到了 8 个。
:::

## 加深而非加宽

**问题。** GQA 让每层的 $W^K$、$W^V$ 从 $d\times d$ 缩成 $1024\times d$，参数少了一截。要维持总参数量，省下的参数得有个去处。

报告说：与大多数使用 GQA 的工作不同，67B 把参数扩展在网络**深度**上，而不是按常见做法去加宽 FFN 的中间维度，目的是获得更好的性能 [@dsllm]。“常见做法”在 Llama 2 的论文附录里有原文：为了让 GQA、MQA 与 MHA 的总参数量相近，他们加大前馈层的维度来补偿注意力层的缩减，MQA 乘以 1.33，GQA 乘以 1.3 [@llama2]。

::: deriv GQA 每层省下多少参数（$d=8192$，$n_gd_h=8\times128=1024$）
$\text{MHA 注意力}=4d^2=268{,}435{,}456$ || $W^Q,W^K,W^V,W^O$ 都是 $d\times d$
$\text{GQA 注意力}=2d^2+2\times d\times1024=150{,}994{,}944$ || $W^K,W^V$ 缩成 $1024\times d$
$\text{每层节省}=2d\,(d-1024)=117{,}440{,}512$ || 两式相减，注意力参数少了 43.75%
$\text{95 层共节省}=95\times117{,}440{,}512=11{,}156{,}848{,}640\approx111.6\text{ 亿}$ || 每层都一样
:::

111.6 亿说的是“同样 95 层，MHA 比 GQA-8 多出的参数”。要问“省下的参数花到了哪里”，更合适的起点是 LLaMA-1 65B 那样的 80 层 MHA 网络（$d=8192$、FFN 22016，与 67B 相同，非嵌入参数 $80\times809{,}517{,}056+8192\approx647.6$ 亿）：把它换成 GQA-8，80 层共省 $80\times117{,}440{,}512\approx94.0$ 亿参数。这笔参数可以有两种花法。下面两个数都是笔者按 (6.3) 算的假想方案，报告没有做这样的对照：

- **加宽（Llama 2 的做法）**：保持 80 层、GQA-8，要让非嵌入参数达到 67B 的约 657.5 亿，FFN 中间维要从 22016 加到约 27296，即乘以 1.24。
- **加深（DeepSeek 的做法）**：保持 FFN 22016。一层 MHA 有 $809{,}517{,}056$ 个参数，一层 GQA-8 有 $692{,}076{,}544$ 个，所以 80 层 MHA 的参数量等于 $80\times809{,}517{,}056/692{,}076{,}544\approx93.6$ 层 GQA-8。DeepSeek 用了 95 层。换句话说，**80 层省下的约 94.0 亿参数差不多正好换成了 14 层左右**（$94.0\text{ 亿}\div6.92\text{ 亿}\approx13.6$ 层）；再多出的约 1.4 层，让非嵌入参数从 647.6 亿增到 657.5 亿。

::: fig figures/l06-depth-width.svg | 图 6.6 按比例画出的“深”与“宽”
**看最右边的 DeepSeek 67B：虚线标出的 93.6 层，就是 80 层 MHA 网络的参数量。** 每个长方形的高按层数、宽按隐藏维度 $d$ 等比例绘制。DeepSeek 7B 比 LLaMA-1 的 6.7B 少两层；DeepSeek 67B 与 LLaMA-1 的 65.2B 同宽，但深 15 层。LLaMA-1 的层数与宽度取自其论文表 2 [@llama1]，DeepSeek 的取自报告表 2 [@dsllm]；每层参数由脚本按 (6.3) 计算。
:::

**7B 为什么是 30 层？** 报告只说层数的调整“在与其他开源模型保持参数量一致的同时”，也方便流水线并行时切分模型 [@dsllm]。一个可以复核的解释（笔者解释）：LLaMA 的词表是 32000，DeepSeek 是 102400，嵌入与输出头多出 $(102400-32000)\times4096\times2=576{,}716{,}800$ 个参数，约等于 7B 的 $576{,}716{,}800/202{,}383{,}360\approx2.85$ 层。作为对照，若用同样的块、32 层、32000 的词表来估算，总参数约 $32\times202{,}383{,}360+4096+2\times32000\times4096\approx67.4$ 亿，与 LLaMA-1 的 6.7B 相当；DeepSeek 去掉两层、换上大词表，是 69.1 亿。两者相差不到 3%。

**加深的理由与代价。** 报告给的理由只有一句“为了更好的性能”，没有给出加深与加宽的对照实验，所以“深比宽好”在这里只能算设计者的判断。代价倒是可以算：推理时一个 token 必须依次穿过所有层，层数从 80 增到 95，每步解码要串行执行的层数多了 19%（笔者推算，实际延迟还取决于并行方式）。另外，更深的网络对训练稳定性要求更高，Pre-Norm 结构（[第 5 课](lesson-05-modern-block.html)）是它能这样堆的前提之一。

::: key 本页要点
- 微观照搬 LLaMA：Pre-RMSNorm、SwiGLU（$d_{ff}/d=2.6875$）、RoPE、无偏置、嵌入与输出头不共享。
- (6.3)(6.4) 可以逐位复现官方参数量：7B 是 6,910,365,696，67B 是 67,425,001,472。
- 67B 用 GQA-8，每 token KV cache 380 KiB，是 MHA 版的 1/8，甚至比 7B 的 480 KiB 还小。
- GQA 每层省 1.17 亿参数，95 层共 111.6 亿。DeepSeek 没有加宽 FFN，而是把层数从 80 左右加到 95：80 层 MHA 的参数量约等于 93.6 层 GQA-8。
:::

# 多步学习率调度：为续训留一扇门 | 分段公式、与 cosine 的比较、复用第一阶段能省多少算力 | 20

学习率调度看起来是个小设置，但它藏着一个很实际的约束：**cosine 调度要求你在开跑前就定死训练总量。** 训练到一半想多训一些？cosine 的整条曲线都是按原来的总量画的，中途的检查点（checkpoint）已经处在“降到一半”的位置，没法直接接着用。做 scaling 研究时，这个约束更伤：同一个模型要在很多个数据量上各训一次，每一次都得从头开始。DeepSeek LLM 换成了**多步**（multi-step）调度 [@dsllm]，这一页讲它的定义、它为什么几乎不损失效果，以及它省下了多少算力。

::: pre 学习率调度、warmup 与 cosine | 学过第 2 课与 M07 的可以跳过
**学习率** $\eta$ 是每一步参数更新的步长。**调度**（schedule）让它随训练进度变化。几乎所有大模型训练都先 **warmup**（预热）：从很小的值线性升到峰值 $\eta_{\max}$，避免训练初期梯度方向还很乱时迈出大步。之后逐渐减小。**cosine 调度**按余弦曲线从峰值降到终值 $\eta_{\min}$：

$$\eta(\tau)=\eta_{\min}+\tfrac12(\eta_{\max}-\eta_{\min})\bigl(1+\cos(\pi\tau/D)\bigr)$$

其中 $\tau$ 是已处理的训练量，$D$ 是计划的总量（这里忽略 warmup）。细节见 [第 2 课 §5](lesson-02-gpt-training.html#p5) 与 [M07 §5](../math/m07-optimization.html#p5)。关键是：**$D$ 出现在公式里**，所以每一步的学习率都取决于计划的总量。
:::

::: ex cosine 的检查点为什么不能拿来续训
设 $\eta_{\min}=0.1\,\eta_{\max}$。同样训到 $\tau=1\text{T}$ token：

- 计划总量 $D=2\text{T}$：$\cos(\pi/2)=0$，$\eta=\eta_{\max}(0.1+0.45\times1)=0.55\,\eta_{\max}$。
- 计划总量 $D=4\text{T}$：$\cos(\pi/4)\approx0.707$，$\eta=\eta_{\max}(0.1+0.45\times1.707)\approx0.87\,\eta_{\max}$。

两次训练在 1T 处的学习率不同，走过的轨迹也不同。所以“先按 2T 训，训完觉得不够再续到 4T”，得到的并不是“按 4T 计划训出来的模型”；要得到后者，只能从头再来。
:::

## 定义：三段常数

**含义。** 多步调度是一条台阶形的曲线：warmup 之后先保持峰值不动，到某个位置突然降一截，过一段再降一截。

**理解。** 台阶的平台上学习率与总量无关，只有两个“降档点”的位置依赖总量。所以两次总量不同的训练，在第一个降档点之前完全一样，可以共用。

**数学。** 设计划训练 $D$ 个 token，已处理 $\tau$ 个。DeepSeek LLM 的调度是 [@dsllm]：

::: eq 多步学习率调度 | (6.6)
$$\eta(\tau)=\eta_{\max}\times\begin{cases}\text{从 0 升到 1（warmup）}, & \text{前 2000 步}\\ 1, & \text{warmup 之后},\ \tau<0.8D\\ 10^{-1/2}\approx0.316, & 0.8D\le\tau<0.9D\\ 10^{-1}=0.1, & \tau\ge0.9D\end{cases}$$
报告的原话是：warmup 2000 步后达到峰值，处理完 80% 的训练 token 后降到峰值的 31.6%，90% 之后再降到 10%。切点**按 token 比例**定义，不是按步数。
:::

31.6% 不是随手取的：$0.316\approx10^{-1/2}=\sqrt{1/10}$。两次各乘 $\sqrt{1/10}$，最后恰好是 $1/10$。同期的 DeepSeek-Coder 报告把这句话写明了：每一阶段的学习率缩小为前一阶段的 $\sqrt{1/10}$，这是遵循 DeepSeek LLM 的做法 [@dscoder]。报告没有说 warmup 的形状（是否线性）。

::: ex 7B 与 67B 的真实调度
训练量 $D=2\times10^{12}$ token，序列长 4096。

- **7B**：每步 $2304\times4096=9{,}437{,}184$ token，共 $2\times10^{12}/9{,}437{,}184\approx211{,}928$ 步。warmup 2000 步 $=2000\times9{,}437{,}184\approx1.89\times10^{10}$ token，只占总量的 0.94%。学习率在 1.6T token（第 169,542 步左右）和 1.8T（第 190,735 步左右）各降一档：

$$\eta_{\max}\times\bigl(1,\ 10^{-1/2},\ 10^{-1}\bigr)=\bigl(4.2,\ 1.328,\ 0.42\bigr)\times10^{-4}$$

- **67B**：每步 $4608\times4096=18{,}874{,}368$ token，共约 105,964 步；warmup 约 377 亿 token。学习率：$3.2\times10^{-4}$ → $1.012\times10^{-4}$ → $3.2\times10^{-5}$。

GitHub README 用绝对 token 数写的是同一件事：学习率在 1.6 万亿 token 处降到峰值的 31.6%，在 1.8 万亿处降到 10% [@gh-llm]。
:::

::: fig figures/l06-lr-schedule.svg | 图 6.7 DeepSeek LLM 7B 的多步调度与 cosine 调度
**看蓝色台阶与灰色虚线：warmup 之后直到 80% 处，多步调度的学习率一直高于 cosine；到 1.6T 和 1.8T 才连降两档。** 紫色点线是假想的续训：若计划改成 3T，0–1.6T 这一段与 2T 的那次训练一模一样，可以直接从 1.6T 处（降档之前）的检查点接着训。蓝线的峰值、切点、各档数值来自报告与 README [@dsllm; @gh-llm]；warmup 的线性形状和 cosine 的终值（10%）报告没有给出，这里只是示意。曲线由脚本按 (6.6) 计算。
:::

## 效果：和 cosine 基本一样

多步调度会不会损失效果？报告在 1.6B 参数、100B token 的规模上做了对比（报告图 1）：训练过程中两者的损失曲线走势不同，多步调度在前 80% 一直高一些，在降档处陡降；但**最终表现与 cosine 基本一致**（按研究笔记对原图的目测，两者终点都在约 2.33）[@dsllm]。报告图 1(b) 还比较了 80/10/10、70/15/15、60/20/20 三种阶段比例（三条曲线的终点几乎重合，目测都在约 2.33）。报告的说法是：调整各阶段的比例可以得到略好一点的表现，但为了在“续训时的复用比例”和“模型表现”之间取得平衡，最终用了 80%、10%、10% [@dsllm]。

## 为什么一降档，损失就陡降

**问题。** 报告图 1 里，多步调度的损失在降档处陡降。学习率只是步长，为什么步长一变小，损失会立刻掉一截？报告没有解释。下面用 [M07 §2](../math/m07-optimization.html#p2) 的玩具模型把它算出来（笔者的解读，不是报告的分析）。

**图景。** 随机梯度带着噪声。学习率大时，参数在谷底附近被噪声推着来回晃，晃动让损失比谷底高出一截；把学习率降下来，晃动变小，参数落得更深，损失随之下降。

**形式化。** 设损失只有一个方向，$f(x)=\tfrac12hx^2$：$x$ 是参数离谷底的距离（一个实数），$h>0$ 是这个方向的曲率。每一步拿到的梯度是真梯度 $hx_t$ 加一个噪声 $\xi_t$，各步独立、均值 0、方差 $\sigma^2/B$（$\sigma^2$ 是单个 token 梯度的方差，$B$ 是 batch size；这里还假设一个 batch 内各 token 的噪声相互独立，$B$ 个平均后方差才是 $\sigma^2/B$。§6 的 pre 会再用到这个 $1/B$）。

::: deriv 带噪声的梯度下降停在哪里（学习率 $\eta$ 固定）
$x_{t+1}=(1-\eta h)\,x_t-\eta\,\xi_t$ || 一步更新 $x_{t+1}=x_t-\eta(hx_t+\xi_t)$，整理成“收缩 + 噪声”
$\E[x_{t+1}]=(1-\eta h)\,\E[x_t]$ || 噪声均值为 0：平均位置每步按 $1-\eta h$ 缩向谷底，$\eta$ 越大缩得越快
$v_{t+1}=(1-\eta h)^2\,v_t+\eta^2\sigma^2/B$ || $v_t=\Var[x_t]$；$\xi_t$ 与 $x_t$ 独立，方差相加
$v_\infty=\dfrac{\eta^2\sigma^2/B}{1-(1-\eta h)^2}=\dfrac{\eta\,\sigma^2}{B\,h\,(2-\eta h)}$ || 稳定时 $v_{t+1}=v_t$；分母 $1-(1-\eta h)^2=\eta h(2-\eta h)$。这要求 $\lvert1-\eta h\rvert<1$，即 $0<\eta h<2$，否则方差逐步放大、不存在稳定值
$\E[f]\to\tfrac12h\,v_\infty\approx\dfrac{\eta\,\sigma^2}{4B}$ || 由第二行，平均位置 $\E[x_t]\to0$ 回到谷底，于是 $\E[f]=\tfrac12h\bigl(v_t+\E[x_t]^2\bigr)$ 只剩方差项，损失全来自晃动；$\eta h\ll1$ 时 $2-\eta h\approx2$
:::

最后一行叫**噪声地板**：学习率不变，损失就降到这个高度为止，它**正比于 $\eta$**（也正比于 $1/B$）。第三行还说明地板降下来要多久：方差每步乘 $(1-\eta h)^2\approx1-2\eta h$，大约 $1/(2\eta h)$ 步就走完了大半。

::: ex 7B 的两次降档，把地板压低多少
7B 的峰值学习率 $4.2\times10^{-4}$。按上面的玩具模型：

- 1.6T 处降到 $1.328\times10^{-4}$：地板乘 $10^{-1/2}\approx0.316$，这部分“晃动造成的额外损失”只剩 31.6%。
- 1.8T 处降到 $0.42\times10^{-4}$：再乘 0.316，只剩峰值时的 10%。

地板降到新高度所需的约 $1/(2\eta h)$ 步，在曲率大的方向上很短，远小于一个阶段的几万步，所以曲线在降档处看起来是“陡降”。在 M07 的数值例子里（$h=1$、$\eta$ 从 0.1 降到 0.01），这个时间是 $1/(2\times0.01\times1)=50$ 步。
:::

这个模型同时解释了**为什么不从一开始就用小学习率**：第二行说，平均位置逼近谷底的速度也按 $\eta$ 变慢。大学习率走得快但停得高，小学习率停得低但走得慢，所以调度先用峰值走远（前 80%），最后再降档压低地板。cosine 把这个“落下去”的过程摊到整个训练里，多步调度把它集中在最后 20%。报告图 7 里，7B 的多项基准分数在 1.6T 处（第一次降档）都有一个明显的跳升（目测），是同一件事在下游指标上的反映。

::: warn 玩具模型解释方向，不给跳幅
一维二次函数加独立同分布的噪声，与大模型的损失曲面相差很远：真实的曲率有亿万个方向、大小悬殊，平缓方向上的噪声要很久才消掉；AdamW 还会逐坐标改变步长。所以它能说明“为什么降档会降、为什么先大后小”，却算不出报告图 1 里具体降多少。
:::

## 复用：到底省了多少

**问题。** 同一个模型要在 $D$、$2D$、$4D$ 三个数据量上各训一次（scaling 研究天天做这种事）。cosine 只能各训各的，总共 $D+2D+4D=7D$。多步调度可以共享第一阶段，能省多少？

::: fig figures/l06-reuse.svg | 图 6.8 共用第一阶段：7D 变成 4.6D
**看下半部分那根深蓝色的长条：它只训一次，三个预算都从它身上分叉。** 预算 $kD$ 的训练在 $0.8kD$ 处从主干上取检查点，接一段 $0.2kD$ 长的降档“尾巴”（先 31.6% 再 10% 的学习率）。主干长 $0.8\times4D=3.2D$，三条尾巴共 $0.2D+0.4D+0.8D=1.4D$，合计 $4.6D$。条长按比例由脚本计算。
:::

::: deriv 共用第一阶段的总成本（预算 $D_1<D_2<\cdots<D_k$，第一阶段占比 $p$）
$\text{主干}=p\,D_{\max}$ || 所有预算的第一阶段都是“峰值学习率”，长度 $pD_i$，最长的一条 $pD_{\max}$ 包含了其余各条
$\text{尾巴}=\textstyle\sum_i(1-p)D_i$ || 每个预算各自的降档段，长度 $(1-p)D_i$，互不共享
$\text{多步总成本}=p\,D_{\max}+(1-p)\textstyle\sum_iD_i$ || 两者相加
$\text{节省比例}=1-\dfrac{pD_{\max}+(1-p)\sum_iD_i}{\sum_iD_i}=p\Bigl(1-\dfrac{D_{\max}}{\sum_iD_i}\Bigr)$ || 与 cosine 的 $\sum_iD_i$ 相比，化简
:::

::: eq 多步调度的复用节省 | (6.7)
$$\text{节省}=p\left(1-\frac{D_{\max}}{\sum_iD_i}\right)$$
$p$ 越大（第一阶段越长）、预算越多越分散，省得越多。
:::

::: ex 80/10/10 对 60/20/20
预算 $D,2D,4D$，$\sum_iD_i=7D$，$D_{\max}=4D$，$1-4/7=3/7$。

- $p=0.8$：节省 $0.8\times3/7\approx34.3\%$，总成本 $4.6D$。
- $p=0.6$：节省 $0.6\times3/7\approx25.7\%$，总成本 $0.6\times4D+0.4\times7D=5.2D$。

第一阶段越短，复用越少：60/20/20 比 80/10/10 少省 8.6 个百分点。报告说调整比例能换来略好一点的表现，但没有说哪一种比例最好；“略好”与“多省算力”之间的取舍，就是报告所说的在复用比例和模型表现之间的平衡。
:::

这正是 §6 超参数实验的做法：报告说，它用多步调度“复用第一阶段”，高效地训练了许多个 batch size、学习率、算力预算（正文称 $10^{17}$ 到 $2\times10^{19}$）各不相同的模型 [@dsllm]。每一组 (batch size, 学习率) 只训一根主干，在各个预算处分叉。

::: warn 失败模式：共用的主干只有一组超参数
一根主干只用一个 batch size 和一个峰值学习率。可是 §6 会看到，最优的 batch size 和学习率本身随算力 $C$ 变化。所以从同一根主干分叉出来的 $D$、$2D$、$4D$ 三个模型，至多只有一个用的是“它那个预算下的最优超参数”。在超参数扫描里这恰好是想要的（每个网格点就是一组固定的超参数，看它在不同预算下表现如何）；但如果拿 2T 训练的主干续训到 4T，续训那部分的超参数就不再是为 4T 挑的（笔者推论）。另一个工程细节：要复用，必须保存降档之前的那个检查点。
:::

## 其余训练设置

::: pre AdamW | 学过第 2 课与 M07 的可以跳过
AdamW 为每个参数维护梯度 $\mathbf g_t$ 的两个滑动平均：一阶矩 $\mathbf m_t=\beta_1\mathbf m_{t-1}+(1-\beta_1)\mathbf g_t$ 与二阶矩 $\mathbf v_t=\beta_2\mathbf v_{t-1}+(1-\beta_2)\mathbf g_t^2$（逐元素平方），经偏差修正后得 $\hat{\mathbf m}_t$、$\hat{\mathbf v}_t$，更新为 $\theta\leftarrow\theta-\eta\bigl(\hat{\mathbf m}_t/(\sqrt{\hat{\mathbf v}_t}+\epsilon)+\lambda\theta\bigr)$。$\lambda$ 是**解耦的权重衰减**：直接把参数往 0 拉一点，而不是加进梯度里。推导见 [M07 §4](../math/m07-optimization.html#p4)。
:::

DeepSeek LLM 用标准差 0.006 初始化，用 AdamW 训练，$\beta_1=0.9$，$\beta_2=0.95$，权重衰减 0.1；梯度裁剪阈值 1.0 [@dsllm]。训练框架（报告称 HAI-LLM）集成了 Megatron 式的数据并行、张量并行、序列并行和 1F1B 流水线并行，用 ZeRO-1 把优化器状态分到各数据并行进程上；模型以 bf16 精度训练，梯度在 fp32 中累加；交叉熵“原地”计算：在交叉熵的 CUDA 内核里把 bf16 的 logits 临时转成 fp32（而不是事先在显存里整体转换），算出 bf16 的梯度后直接覆盖掉 logits；模型权重和优化器状态每 5 分钟异步保存一次 [@dsllm]。[第 12 课](lesson-12-v3-infrastructure.html)讲 V3 的训练基建时，还会遇到这里的流水线并行与混合精度。

::: ex 为什么交叉熵要“原地”算
一条 4096 token 的序列，输出层的 logits 是 $4096\times102400$ 个数。bf16 存是 $4096\times102400\times2=838{,}860{,}800$ 字节 $=0.78$ GiB；若先整体转成 fp32 再算交叉熵，还要再占 $4096\times102400\times4=1.5625$ GiB。在内核里逐块转换、算完就丢，这 1.56 GiB 就不必同时存在（算例中的“每次一条序列”是笔者的假设，报告没有给出微批大小）。词表越大，这笔账越重；102400 的词表让它比 LLaMA 的 32000 词表重 3.2 倍。
:::

::: key 本页要点
- cosine 调度的每一步都依赖计划总量 $D$，中途检查点不能直接续训。多步调度 (6.6) 在 80% 与 90% 处各乘 $\sqrt{1/10}$，第一阶段与总量无关。
- 报告在 1.6B/100B token 上验证：最终效果与 cosine 基本一致；调整阶段比例能略好一点，但为了复用选了 80/10/10。
- 降档处损失陡降，可以用带噪声的二次函数理解：噪声地板约 $\eta\sigma^2/(4B)$，正比于学习率，每降一档乘 0.316；小学习率停得低但走得慢，所以先大后小。
- 共用第一阶段的节省 $=p\,(1-D_{\max}/\sum D_i)$：$D,2D,4D$ 三个预算从 $7D$ 降到 $4.6D$，省 34.3%。§6 的超参数扫描正是靠这个做的。
- 其余：AdamW（0.9, 0.95, 0.1）、初始化标准差 0.006、梯度裁剪 1.0、bf16 训练 + fp32 梯度累加。
:::

# 算力记账：6N₁、6N₂ 与 M | 从矩阵乘法数出每个 token 的 FLOPs，看清 6N 偏在哪里、偏多少 | 25

scaling law 是一条“损失（或最优规模）对算力”的曲线。横轴上的算力 $C$ 怎么算，决定了曲线的形状。第 2 课的惯例是 $C\approx6ND$：$N$ 个参数，每个 token 大约 6 次浮点运算，一共 $D$ 个 token。DeepSeek 发现这个惯例有两处毛病 [@dsllm]：它**没算注意力**里随序列长度增长的那部分计算；如果 $N$ 里包括了词表，又**多算了词表**的计算，而词表对模型能力的贡献比较小。两者在某些设置下误差都很大，小模型上能差到 50%，足以把拟合出来的曲线带偏。这一页从矩阵乘法出发，把每一项 FLOPs 数清楚。

::: pre 矩阵乘法的 FLOPs，以及“每参数每 token 6 次” | 学过 M01 §5 与第 2 课的可以跳过
$[m,k]\times[k,n]$ 的矩阵乘法要做 $mnk$ 次乘法和差不多同样多次加法，记作 $2mnk$ 次浮点运算（FLOPs），见 [M01 §5](../math/m01-vectors-matrices.html#p5)。一个 $d_{out}\times d_{in}$ 的权重矩阵作用在一个 token 上，前向是 $2d_{in}d_{out}$ 次，也就是**每个参数 2 次**。反向传播要算两样东西：对输入的梯度（传给前一层）和对权重的梯度（用来更新），各是一次同样规模的矩阵乘法，共**每个参数 4 次**。前向加反向，**每个参数每个 token 约 6 次**，这就是 $6N$ 里的 6（[第 2 课 §6](lesson-02-gpt-training.html#p6)、[M10 §1](../math/m10-compute-arithmetic.html#p1)）。
:::

## 72 L d² 从哪里来

**含义。** $6N_1$ 里的 $N_1$ 是**非嵌入参数量**（non-embedding parameters）：去掉输入嵌入和输出头之后剩下的参数。

**数学。** 按 DeepSeek 报告式 (2) 的约定，每层用 MHA、FFN 中间维取 $\tfrac83d$，忽略 RMSNorm 的少量参数：

::: deriv 非嵌入参数量与 $6N_1$
$\text{注意力}=4d^2$ || $W^Q,W^K,W^V,W^O$ 都是 $d\times d$（MHA 时 $n_hd_h=d$）
$\text{SwiGLU}=3\times d\times\tfrac83d=8d^2$ || 三个矩阵，每个 $d\times\tfrac83d$
$N_1=L\,(4d^2+8d^2)=12Ld^2$ || $L$ 层；这与经典 GPT 的 $4d^2+2\times d\times4d=12d^2$ 相同，$\tfrac83$ 正是为此而取（第 5 课）
$6N_1=72Ld^2$ || 每参数每 token 6 次
:::

## 12 L d T 从哪里来

**问题。** 参数矩阵乘的计算量和序列多长无关。但注意力里还有两次**不涉及参数**的矩阵乘法：查询与所有键打分（$QK^\top$），以及用权重对所有值加权求和（$PV$，$P$ 是 softmax 之后的注意力权重矩阵）。每个头里，$Q,K,V\in\R^{T\times d_h}$（每行一个 token），$QK^\top$ 与 $P$ 的形状是 $T\times T$，$PV$ 又回到 $T\times d_h$。一个 token 要和多少个位置打分，取决于序列长度 $T$。$6N$ 完全没有这一项。

::: deriv 注意力打分与加权求和的 FLOPs（每层、每个 token）
$\text{打分}=\textstyle\sum_{i=1}^{n_h}T\times2d_h=2Td$ || 每个头：与 $T$ 个键各做一次长 $d_h$ 的点积，每次 $2d_h$ 次运算；$n_h$ 个头合计，$n_hd_h=d$
$\text{加权求和}=2Td$ || 每个头：$T$ 个长 $d_h$ 的值向量按权重相加，同样 $2Td_h$，合计 $2Td$
$\text{前向}=2Td+2Td=4Td$ || 打分与加权求和相加
$\text{前向+反向}=3\times4Td=12Td$ || 反向要对两个输入（$Q$ 与 $K$，或权重与 $V$）各求一次梯度，约为前向的 2 倍
$L\text{ 层合计}=12LdT$ || 每层都一样
:::

这里有两个约定要说清楚。第一，它按“每个 token 都和全部 $T$ 个位置打分”计，没有打因果掩码的折扣；实际上因果注意力里第 $t$ 个 token 只看前 $t$ 个位置，平均约 $T/2$，是否真能省下这一半取决于实现（研究笔记未核实具体实现）。第二，Kaplan 等人的算力估计里，前向的上下文项是 $2Ln_{ctx}d$，乘 3 后是 $6Ln_{ctx}d$，只有 DeepSeek 这一项的一半；而且 Kaplan 明确说，因为主要研究 $d_{model}\gg n_{ctx}/12$ 的模型，所以训练算力里**不含**与上下文有关的项，直接取 $C\approx6N$ [@kaplan]。两边都是约定，不是精确 FLOPs。

## 6N₂ 多算了什么

**含义。** $N_2$ 是报告所说的“完整参数”（complete parameters），在 $N_1$ 的基础上加上词表参数。

**数学。** 报告表 3 的数字表明 $N_2=N_1+Vd$（例如第一行 $25.17\text{M}+102400\times512=77.59\text{M}$，表中印作 77.6M），只加了**一份**词表矩阵，尽管 DeepSeek LLM 的输入嵌入和输出头不共享，实际有两份。换成算力：输入嵌入是查表，几乎不花 FLOPs；输出头是一次 $d\times V$ 的矩阵乘，前向 $2Vd$、前向加反向 $6Vd$。所以 $6N_2=72Ld^2+6Vd$，多出来的 $6Vd$ 就是**输出头的计算**，也就是报告说的“词表计算”。

把三种记法写在一起：

::: eq 三种模型规模表示（DeepSeek LLM 式 (2)，改写成本课记号） | (6.8)
$$\begin{aligned}6N_1&=72\,L\,d^{2}\\ 6N_2&=72\,L\,d^{2}+6\,V\,d\\ M&=72\,L\,d^{2}+12\,L\,d\,T\end{aligned}$$
报告原式用 $n_{\mathrm{layer}}$、$d_{\mathrm{model}}$、$n_{\mathrm{vocab}}$、$l_{\mathrm{seq}}$；本课写 $L$、$d$、$V$、$T$。
:::

**含义。** $M$ 叫**每 token 非嵌入 FLOPs**（non-embedding FLOPs/token）：训练时每处理一个 token，模型主体（不含词表）要做的浮点运算次数，**包括**注意力的打分与加权求和，**不包括**输出头。

**理解。** $M$ 是在问“模型每读一个 token 要思考多少”，而不是“模型有多少参数”。两个参数量相同的模型，上下文长的那个每 token 要算得更多；$M$ 能区分它们，$N$ 不能。

**数学。** 有了 $M$，训练总算力可以写得很干净 [@dsllm]：

::: eq 用 M 表示的训练算力 | (6.9)
$$C=M\cdot D$$
$M$ 的单位是 FLOPs/token，$D$ 是 token 数，$C$ 是 FLOPs。
:::

## 两种 6N 各偏多少

用 (6.8) 直接相除：

::: deriv $6N_1$ 与 $M$ 之比
$\dfrac{6N_1}{M}=\dfrac{72Ld^2}{72Ld^2+12LdT}$ || (6.8)
$=\dfrac{6d}{6d+T}$ || 分子分母同除以 $12Ld$；$L$ 约掉了，只剩宽度 $d$ 与序列长度 $T$
$1-\dfrac{6N_1}{M}=\dfrac{T}{6d+T}$ || 这就是注意力打分与加权求和在 $M$ 中所占的比例
:::

::: eq 6N₁ 的低估比例只由 d 和 T 决定 | (6.10)
$$\begin{aligned}\frac{6N_1}{M}&=\frac{6d}{6d+T}\\[4pt] \text{注意力占比}&=\frac{T}{6d+T}\end{aligned}$$
$d$ 越小、$T$ 越长，$6N_1$ 低估得越多；$T=6d$ 时恰好低估一半。
:::

::: fig figures/l06-flops-breakdown.svg | 图 6.9 三种记账方式各自数了哪些 FLOPs
**看最上面的小模型：$6N_1$（只有蓝色）只到 $M$ 的 43%，$6N_2$（蓝色加灰色）却冲到 132%。** 每个模型的三行都以 $M$ 为 100% 归一。蓝色是参数矩阵乘 $72Ld^2$，紫色是注意力的打分与加权求和 $12LdT$，灰色是输出头 $6Vd$。模型变大时蓝色占绝对多数，三种记法趋于一致。三组 $(L,d)$ 取自 DeepSeek LLM 报告表 3，$V=102400$、$T=4096$ [@dsllm]；条长由脚本按 (6.8) 计算。
:::

::: ex 7B：$6N_1$ 少算了什么

- $12LdT=12\times30\times4096\times4096=6.040\times10^{9}$。
- $M=3.624\times10^{10}+6.040\times10^{9}=4.228\times10^{10}$。
- $6N_1/M=6\times4096/(6\times4096+4096)=6/7\approx0.857$：$6N_1$ 少算了 14.3%，少算的正是注意力的 $QK^\top$ 与 $PV$。

同样的式子：67B（$d=8192$）的注意力占比 $4096/(6\times8192+4096)=1/13\approx7.7\%$（这是按 (6.8) 的 MHA 结构算的；67B 实际用 GQA-8，参数矩阵乘少一些，按下一小节的 (6.11) 是 $3.825\times10^{10}/4.3273\times10^{11}\approx8.8\%$）；§8 的 DeepSeek-Coder 6.7B（$d=4096$）若在 16K 序列上训练，占比升到 $16384/(24576+16384)=40\%$。上下文一长，$6N$ 的误差就不能忽略。
:::

## 真实结构下的 M：67B 用的是哪个

(6.8) 对“MHA + $d_{ff}=\tfrac83d$”的结构是精确的。7B 基本符合（只是 $d_{ff}$ 取了 11008），67B 却用了 GQA-8 和 22016。按真实结构逐项计数：

::: eq 按真实结构计算的 M | (6.11)
$$\begin{aligned}M&=6L\,\bigl(2d^2+2\,d\,n_gd_h+3\,d\,d_{ff}\bigr)\\&\quad+12\,L\,d\,T\end{aligned}$$
括号里正是 (6.3) 去掉 RMSNorm 之后的每层矩阵参数；注意力项严格说是 $12\,L\,n_hd_h\,T$，因为 $n_hd_h=d$ 才写成 $12LdT$。它与 KV 头数 $n_g$ 无关：67B 的 $64$ 个查询头仍然各自和所有位置打分。
:::

::: ex 7B 与 67B 的 M 和 C
- 7B：括号内 $=2\times4096^2\times2+3\times4096\times11008=202{,}375{,}168$；$6\times30\times202{,}375{,}168=3.643\times10^{10}$；加 $12LdT=6.040\times10^9$，得 $M=4.2467\times10^{10}$。$C=MD=4.2467\times10^{10}\times2\times10^{12}=8.49\times10^{22}$。
- 67B：括号内 $=134{,}217{,}728+16{,}777{,}216+541{,}065{,}216=692{,}060{,}160$；$6\times95\times692{,}060{,}160=3.945\times10^{11}$；加 $12\times95\times8192\times4096=3.825\times10^{10}$，得 $M=4.3273\times10^{11}$。$C=8.65\times10^{23}$。
- 若直接把 67B 代进 (6.8)：$M=72\times95\times8192^2+12\times95\times8192\times4096=4.97\times10^{11}$，比真实结构多 15%。

报告图 4(b) 在 67B 旁标注的正是 “4.3e11 FLOPs/Token”；§6 会看到，报告图 3 里 67B 的 batch size “19.7M” 也只有用 $4.33\times10^{11}$ 才能复现。研究笔记还从图 3(a) 的像素位置反解了 67B 星号的横坐标，$\log_{10}C=23.937$，与真实结构的预测一致，与 (6.8) 版的 23.998 不符。所以报告实际用的是 (6.11)。这是从图上的数字反推出来的，报告正文没有写明。
:::

::: warn 这些记法都不是“精确 FLOPs”
$M$ 比 $6N$ 更贴近真实计算，但它仍是约定：注意力不打因果折扣；softmax、RMSNorm、激活函数、残差加法等逐元素运算都没算；前向加反向按整齐的“3 倍”计。它的价值不在绝对精确，而在于**用同一条规则把 $6N$ 漏掉的注意力项算了进去**：这一项随形状变化最大（在最小的实验模型上占 $M$ 的 57%），$6N_1$ 把它整个丢掉，拟合就会被系统地扭曲（下一小节）。剩下的约定也会随形状带来偏差，不能说 $M$ 对所有形状“误差相同”。例如，若实现真的利用因果掩码省下一半的打分与加权求和，实际 FLOPs 是 $72Ld^2+6LdT$，$M$ 多算的比例是 $\dfrac{6LdT}{72Ld^2+6LdT}=\dfrac{T}{12d+T}$：$d=512$ 时 40%，$d=8192$ 时 4%（笔者算例，$T=4096$）。报告附录 A.2 的实测是：三种记法里用 $M$ 拟合的预测最准。
:::

## 记账误差为什么会扭曲拟合

**问题。** 如果横轴每个点都乘上同一个常数，双对数坐标里只是整体平移，拟合出的指数不变。麻烦在于 $6N_1/M$ **随模型形状变化**：小模型约 0.43，大模型约 0.92。

::: ex 同一批实验点，在横轴上各挪多远
用 $6N_1D$ 代替 $MD$ 作横轴，每个点向左平移 $\log_{10}(6N_1/M)$ 个数量级：

- $L=8$、$d=512$ 的小模型：$\log_{10}0.43\approx-0.37$，左移 0.37 个数量级。
- $L=80$、$d=8192$ 的大模型：$\log_{10}0.92\approx-0.035$，几乎不动。

小模型的点整体被挪得比大模型远，点与点之间的横向距离被拉开，拟合出来的斜率和截距都会变，外推到几百倍以外，这点差别被放大。$6N_2$ 的问题方向相反：小模型的点被挪向右边（$\log_{10}1.32\approx+0.12$）。
:::

报告附录 A.2 用同一批实验、三种横轴各拟合了一次：在较大的预算上三种表示给出的最优分配差别不大，在较小的预算上差别明显；用 $6N_1$ 时，拟合出的性能曲线**高估**大模型的表现，用 $6N_2$ 时**低估**，用 $M$ 时预测最准 [@dsllm]。报告图 6 把这三条曲线并排画出。这是实测结果；“高估还是低估”取决于点怎样被挪动、IsoFLOP 实验怎样按各自的记法分配预算，报告没有给出更细的分析。

::: key 本页要点
- $6N_1=72Ld^2$ 漏了注意力的打分与加权求和 $12LdT$；$6N_2=72Ld^2+6Vd$ 还多算了输出头。$M=72Ld^2+12LdT$，训练算力 $C=MD$。
- $6N_1/M=6d/(6d+T)$：7B 是 0.857，67B 约 0.92，最小的实验模型只有 0.43；$6N_2$ 在最小模型上高估 32%。
- 67B 用 GQA-8 与 22016 维 FFN，报告实际使用的是按真实结构算的 $M=4.33\times10^{11}$（由图 3、图 4 的数字反推），不是 (6.8) 给出的 $4.97\times10^{11}$。
- 记账误差随模型形状变化，所以会扭曲拟合；报告实测 $M$ 的预测最准。
:::

# 超参数的 scaling law：batch size 与学习率 | 1e17 上的网格、“近优”的定义、两条幂律及其对 7B/67B 的预测 | 25

有了算力的记账方式，就可以回答问题一：给定算力 $C$，batch size 和学习率取多少？报告先说明为什么只研究这两个：经验上，大多数超参数的最优值不随算力预算变化，所以沿用即可；但对效果影响最大的两个超参数，batch size 和学习率，需要重新考察 [@dsllm]。报告还指出，早先的 scaling 研究对超参数交代不全，没法确认各预算下的模型是否训到了最优（§1）；如果每个预算下的超参数都没调好，拟合出来的“最优分配”也就无从谈起。所以超参数的规律要最先定。

::: pre batch size、梯度噪声与步数 | 学过 M04 方差与 M07 的可以跳过
**batch size** $B$ 是每一步更新用多少个 token 的梯度求平均（本课按 token 计）。每个 token 的梯度都是真实梯度加上噪声；$B$ 个独立噪声取平均，方差变成原来的 $1/B$（[M04 §3](../math/m04-probability.html#p3)）。所以 $B$ 越大，每一步的方向越准。代价是：数据总量 $D$ 固定时，步数 $S=D/B$ 越少。学习率 $\eta$ 决定沿这个方向走多远。§4 的玩具模型里，噪声地板约为 $\eta\sigma^2/(4B)$，只依赖 $\eta/B$ 这个比值，所以 batch size 和学习率要一起考虑。两者的配合是 [M07 §5](../math/m07-optimization.html#p5) 的主题；这里只需要记住“大 batch = 准但步数少，小 batch = 步数多但每步更吵”。
:::

## 第一步：在 1e17 上网格搜索

报告先在 $10^{17}$ FLOPs 的小预算上，对一个 $M=1.77\times10^8$ FLOPs/token 的模型做了 batch size × 学习率的网格搜索（报告图 2(a)），发现在很宽的范围内，泛化误差都很稳定 [@dsllm]。

::: fig figures/l06-grid-1e17.svg | 图 6.11 1e17 FLOPs 预算下的 batch size × 学习率网格 | scroll
**看深绿色的 5 个格子：它们的损失都不超过最小值 3.685 的 1.0025 倍，这就是报告所说的“近优”。** 行是 batch size（$2^{15}$ 到 $2^{20}$ 个 token，注意行距不均匀），列是学习率 $2^{k}$。过了 $2^{17}$ 再往下（batch 越大），损失越来越高：$2^{19.5}$、$2^{20}$ 两行已经到 4 以上；最上面的 $2^{15}$ 行（batch 最小）也偏高，约 3.87–3.92。蓝色叉是 (6.12) 在 $C=10^{17}$ 处的预测，落在近优区域中间。格内数值按报告图 2(a) 印刷值转录 [@dsllm]；报告该图标题写的是“训练损失”，正文称“泛化误差”。颜色与阈值由脚本计算。
:::

::: ex 为什么 batch 太大就不行
这个网格里每个模型的训练量是 $D=C/M=10^{17}/(1.77\times10^8)\approx5.65\times10^8$ token。步数 $S=D/B$：

- $B=2^{15}=32{,}768$：约 17,242 步。
- $B=2^{17}=131{,}072$（最优格所在行）：约 4,310 步。
- $B=2^{20}=1{,}048{,}576$：只有约 539 步。

只走 539 步，每一步再准也走不到谷底；这正是最下面两行损失升到 4 以上（$2^{19.5}$ 行 4.08–4.76，$2^{20}$ 行 4.61–5.15）的原因。反过来，$B=2^{15}$ 的步数多但每步噪声大，损失约 3.87–3.92，也不如中间几行。最优 batch 是在“步数”和“每步的准确度”之间取的平衡，而这个平衡点随预算移动。
:::

**近优的定义。** 报告考虑到参数空间里的冗余，把“泛化误差比最小值高不超过 0.25%”的超参数都算作**近优**（near-optimal）[@dsllm]。对图 6.11：阈值 $3.685\times1.0025\approx3.6942$，恰好 5 个格子入选。放宽到 1% 有 19 格，放宽到 2% 有 41 格：最优区域是一片宽阔的盆地，而不是一个尖点。

## 第二步：跨预算找近优带，拟合幂律

在一个预算上网格搜索只得到一个点。要得到“随 $C$ 变化”的规律，需要在很多预算上重复。报告用 §4 的多步调度“复用第一阶段”，训练了许多 batch size、学习率和算力预算都不同的模型，正文称预算范围是 $10^{17}$ 到 $2\times10^{19}$；把每个预算下的近优点画在（算力，batch size）和（算力，学习率）两张图上，观察到**最优 batch size 随算力缓慢增大，最优学习率随算力缓慢减小** [@dsllm]，然后用幂律拟合。

::: deriv 在双对数坐标里拟合一条幂律（以 batch size 为例）
$B=k\,C^{\alpha}$ || 假设的函数形式：幂律，两个待定常数 $k$、$\alpha$
$\log B=\log k+\alpha\log C$ || 两边取对数：变成关于 $\log C$ 的直线
$\min_{u,\alpha}\ \textstyle\sum_i\bigl(y_i-u-\alpha x_i\bigr)^2$ || 对近优点 $(C_i,B_i)$ 做最小二乘；记 $x_i=\log C_i$、$y_i=\log B_i$、截距 $u=\log k$，这就是普通的一元线性回归
$u=\bar y-\alpha\,\bar x$ || 对 $u$ 求偏导令其为 0，得 $\sum_i(y_i-u-\alpha x_i)=0$；$\bar x$、$\bar y$ 是 $x_i$、$y_i$ 的平均。拟合直线必过点 $(\bar x,\bar y)$
$\textstyle\sum_i x_i\bigl[(y_i-\bar y)-\alpha(x_i-\bar x)\bigr]=0$ || 对 $\alpha$ 求偏导令其为 0，并代入上一行的 $u$
$\textstyle\sum_i(x_i-\bar x)(y_i-\bar y)=\alpha\sum_i(x_i-\bar x)^2$ || 方括号对 $i$ 求和为 0（偏离平均值的量加起来总是 0），所以上一行的 $x_i$ 换成 $x_i-\bar x$ 不改变结果（多减的是 $\bar x$ 乘以 0）；再把 $\alpha$ 项移到右边
$\alpha=\dfrac{\sum_i(x_i-\bar x)(y_i-\bar y)}{\sum_i(x_i-\bar x)^2}$ || 解出斜率；截距由第四行给出：$\log k=\bar y-\alpha\bar x$
:::

报告没有写明它具体用的是哪种拟合（例如是否对近优带取中心、各点如何加权），上面只是这类拟合的标准做法。报告给出的结果是：

::: eq 超参数的 scaling law（DeepSeek LLM 式 (1)） | (6.12)
$$\begin{aligned}\eta_{\mathrm{opt}}&=0.3118\cdot C^{\,-0.1250}\\ B_{\mathrm{opt}}&=0.2920\cdot C^{\,0.3271}\end{aligned}$$
$C$ 是用 $C=MD$ 计的训练算力（FLOPs），$B$ 以 token 计，$\eta$ 是峰值学习率。
:::

**读法。** 用 §1 的“倍数”读法：

$$\begin{aligned}\frac{B_{\mathrm{opt}}(10C)}{B_{\mathrm{opt}}(C)}&=10^{0.3271}\approx2.12\\[4pt] \frac{\eta_{\mathrm{opt}}(10C)}{\eta_{\mathrm{opt}}(C)}&=10^{-0.125}\approx0.75\end{aligned}$$

算力每增加 10 倍，最优 batch size 乘 2.12，最优学习率乘 0.75，与 $C$ 原来多大无关。算力增加 1000 倍，batch 大约乘 9.6，学习率大约乘 0.42。

报告又在 $10^{20}$ 的预算上验证：对一个 $M=2.94\times10^9$ FLOPs/token 的模型再做一次网格（报告图 2(b)），公式给出的点落在最优参数空间的中央 [@dsllm]。

::: ex 在 1e17 与 1e20 两处验算 (6.12)
- $C=10^{17}$：$\eta=0.3118\times10^{-17\times0.125}=0.3118\times10^{-2.125}\approx2.34\times10^{-3}=2^{-8.74}$；$B=0.2920\times10^{17\times0.3271}\approx1.06\times10^{5}=2^{16.70}$。在图 6.11 里，这一点落在 $2^{16.5}$ 与 $2^{17}$ 两行之间、$2^{-8.75}$ 那一列上，正是近优格聚集的地方。
- $C=10^{20}$：$\eta\approx9.86\times10^{-4}=2^{-9.99}$，$B\approx1.02\times10^{6}=2^{19.96}$。报告图 2(b) 中标着“拟合出的最优超参数”的星号，就在 $(B,\eta)=(2^{20},2^{-10})$ 这一格，损失 2.474，是该网格的最小值；按同样的 0.25% 阈值，这个网格有 20 个近优格。
:::

::: fig figures/l06-hparam-fit.svg | 图 6.12 两条超参数幂律，以及它们对 7B、67B 的外推 | scroll
**看绿色星号与空心圆几乎重合：公式对 7B、67B 的预测，和报告实际采用的值只差几个百分点。** 左图纵轴是 batch size（token，按 $\log_2$ 刻度），右图是学习率（按 $\log_{10}$ 刻度），横轴都是训练算力。灰色带是正文称的拟合范围 $10^{17}$–$2\times10^{19}$，两颗星在它右端之外约 3.6 与 4.6 个数量级。$10^{17}$ 处的绿色竖条是图 6.11 近优格覆盖的范围。直线按 (6.12) 计算，7B、67B 的 $C$ 用 §5 的真实结构 $M$ [@dsllm]。
:::

::: ex 用 (6.12) 为 7B 和 67B 选超参数
§5 算出 $C_{7B}=8.49\times10^{22}$，$C_{67B}=8.65\times10^{23}$。

| | 7B | 67B |
|---|---|---|
| 预测 $\eta_{opt}=0.3118\,C^{-0.125}$ | $4.24\times10^{-4}$ | $3.17\times10^{-4}$ |
| 实际 $\eta$（报告表 2） | $4.2\times10^{-4}$ | $3.2\times10^{-4}$ |
| 预测 $B_{opt}=0.2920\,C^{0.3271}$（token） | $9.24\times10^{6}$ | $1.974\times10^{7}$ |
| 换算成 4096 长的序列 | 2255 条 | 4818 条 |
| 实际 batch（报告表 2，序列） | 2304 条 $=9.44\times10^6$ token | 4608 条 $=1.887\times10^7$ token |

学习率几乎分毫不差；batch size 实际取了离预测值很近的整数（7B 多 2%，67B 少 4%）。报告图 3 在两颗星旁标注的 “9.2M”“19.7M”“4.2e-04”“3.2e-04”，就是上表的预测值 [@dsllm]。

**反过来的验证。** 如果把 67B 的 $M$ 按 (6.8) 算成 $4.97\times10^{11}$，$C=9.95\times10^{23}$，公式给出 $B=2.065\times10^7$、$\eta=3.12\times10^{-4}$，与图 3 标注的 19.7M 对不上。这就是 §5 断定“报告按真实结构计算 $M$”的依据之一。
:::

::: warn 单位陷阱：token 还是序列
(6.12) 和报告图 3 的 $B$ 以 **token** 计；报告表 2 的 2304、4608 以**序列**计（表头原文就是 “Sequence Batch Size”）。两者差 4096 倍。把 2304 直接代进 (6.12) 的反函数，会得到一个荒谬的算力。
:::

## 为什么 batch size 随算力增大、学习率随算力减小

报告只报告了趋势和拟合，没有给出理论解释。下面是常见的理解方式（笔者解释，不是报告的结论）。

::: ana 类比：民意调查
**映射。** 每一步训练像一次民意调查：batch size = 调查的样本量；梯度 = 调查得出的“民意方向”；学习率 = 每次根据调查结果调整政策的幅度。

**收益。** 训练早期（损失高），“往哪边走”非常明显，少量样本就能看清方向，可以大胆调整；训练到后期、算力更大的模型把损失压得更低，剩下的改进方向越来越微妙，需要更大的样本才能从噪声里分辨出来，调整也要更谨慎。这对应“$B$ 随 $C$ 增大、$\eta$ 随 $C$ 减小”。报告自己提到，McCandlish 等人（2018）与 Kaplan 等人（2020）的工作认为最优 batch size 可以只看作泛化误差 $L$ 的函数 [@dsllm]，这与“损失越低，需要的样本越多”的直觉是一致的。

**失效的地方。** 这个图景只解释了**方向**，解释不了 0.3271、$-0.125$ 这两个具体的指数，它们纯粹是拟合出来的。学习率变小还有另一个来源：算力大的最优模型通常也更大，大模型为了训练稳定往往需要更小的学习率，这和“噪声”无关。另外，调查样本之间是独立的，而同一个 batch 里的 token 来自同一批文档，并不完全独立。
:::

报告也坦白了这套公式的局限 [@dsllm]：它只考虑了算力 $C$，没有考虑其他因素；这与 McCandlish 等人、Kaplan 等人“最优 batch size 只与泛化误差 $L$ 有关”的建模不一致；而且报告观察到，**算力相同、但模型/数据分配不同**的模型，最优参数空间也略有不同。

::: warn 失败模式：外推几个数量级，指数的小误差会被放大
按正文，拟合范围最大到 $2\times10^{19}$，67B 在 $8.65\times10^{23}$，外推约 $4.3\times10^4$ 倍，即 $\log_{10}(4.3\times10^4)\approx4.64$ 个数量级。假如拟合直线在拟合范围的右端 $2\times10^{19}$ 处是准的，只是 batch 的指数有 $\pm0.02$ 的误差，预测值会差 $10^{0.02\times4.64}\approx1.24$ 倍：指数偏大 0.02 时预测偏大 24%，偏小 0.02 时偏小约 19%（$1/1.24\approx0.81$；笔者算例）。这还是偏乐观的估计：最小二乘直线最准的地方是数据中心 $(\bar x,\bar y)$（上面拟合推导的第四行），不是右端。若数据点在 $10^{17}$ 到 $2\times10^{19}$ 之间按对数大致均匀分布，中心约在 $1.4\times10^{18}$，离 67B 约 5.8 个数量级，同样 $\pm0.02$ 的指数误差会放大成 $10^{0.02\times5.8}\approx1.31$ 倍。好在图 6.11 显示最优区域很宽：近优的 batch 从 $2^{16.5}$ 到 $2^{18}$，跨了约 2.8 倍，差 20%–30% 多半仍在近优带里。报告能用一条直线外推这么远，多半也靠这一点（笔者推测）。
:::

::: key 本页要点
- 只重新研究 batch size 与学习率。$10^{17}$ 的网格显示最优区域很宽；损失比最小值高不超过 0.25% 的都算“近优”。
- 用多步调度复用第一阶段，在多个预算上找近优点并拟合：$\eta_{opt}=0.3118C^{-0.125}$，$B_{opt}=0.2920C^{0.3271}$（$B$ 按 token）。算力 ×10，batch ×2.12，学习率 ×0.75。
- 预测 7B：$\eta=4.24\times10^{-4}$、$B=9.24$M token；67B：$3.17\times10^{-4}$、19.7M token。实际用 $4.2\times10^{-4}$/2304 条与 $3.2\times10^{-4}$/4608 条。
- 公式只依赖 $C$；报告自认这与“$B$ 只依赖损失”的旧模型不一致，且同算力不同分配时最优区域会略有移动。
:::

# 最优分配与数据质量 | IsoFLOP、a + b = 1、67B 算不算“算力最优”、为什么数据越好越该给模型 | 25

现在可以回答问题三了。算力 $C$ 固定，$C=MD$，模型做大一点，数据就得少一点。哪种分法损失最低？算力增加时，模型和数据各该长多少？§1 看到，Kaplan 和 Chinchilla 对这个问题的回答差了 5 倍多。有了调好的超参数（§6）和一致的记账方式（§5），DeepSeek 把这个实验重做了一遍，并且找到了一个前人没注意到的变量：**数据质量**。

::: ana 类比：固定学时里，“长脑子”还是“多读书”
**映射。** 把训练想成一个学生在固定的总学时里读书：总学时 = 算力 $C$；学生的脑容量 = 模型规模 $M$；读过的页数 = 数据量 $D$。这个学生有个怪脾气：脑子越大，读一页花的时间越多（每 token 的计算量正是 $M$），所以学时固定时，$C=MD$ 把两者绑在一起，脑子大了，读的页数就少。

**收益。** 它让“最优分配”变成一个直观的权衡：脑子太小，书读得再多也装不下，容量成了瓶颈；脑子太大，学时全花在少数几页上，书没读够，数据成了瓶颈；最好的分法在两者之间，这就是下面 IsoFLOP 曲线呈 U 形、有一个谷底的原因。它也给本页后半的结论一个读法：书写得越清楚（数据质量越高），每一页越快被读懂，瓶颈更早落到脑容量上，新增的学时就该多花在“长脑子”上。

**失效的地方。** 第一，人脑的大小不改变读一页的时间；模型的规模却直接决定每读一个 token 要算多少，$C=MD$ 是算力记账的定义，不是学习规律。第二，“清楚的书读得快”只是把报告自己标为推测的解释搬进了类比，类比不能证明它。第三，真实的收益是幂律，类比说不出 0.5243 这样的具体指数。
:::

**数学。** 问题可以写成一个带约束的最小化：

::: eq 最优模型/数据分配（DeepSeek LLM 式 (3)） | (6.13)
$$M_{\mathrm{opt}}(C),\ D_{\mathrm{opt}}(C)=\underset{M,\,D\ \text{s.t.}\ C=MD}{\operatorname{argmin}}\ L(M,D)$$
$L$ 是验证集上的损失（这里用 bits-per-byte；本页的 $L$ 都是损失，不是层数）。报告印刷的是 $L(N,D)$，但优化变量是 $M$、$D$，应读作 $L(M,D)$。
:::

::: pre IsoFLOP 方法与 bits-per-byte | 学过第 2 课 Chinchilla 与 M05 的可以跳过
**IsoFLOP**（等算力）方法来自 Chinchilla [@chinchilla]：固定一个算力预算 $C$，训练一组大小不同的模型，每个模型的数据量取 $D=C/M$，使总算力相同；把它们的最终损失画成 $M$ 的函数，得到一条 U 形曲线，谷底就是这个预算下的最优分配。对多个预算重复，谷底连起来就是 $M_{opt}(C)$。

**bits-per-byte**（BPB，每字节比特数）把交叉熵换成与分词器无关的单位：把整个验证集上的负对数似然用以 2 为底的对数求和（单位：比特），再除以验证文本的 UTF-8 字节数。用每 token 的交叉熵比较时，分词器切得越粗，每个 token 的损失自然越高；BPB 按字节摊平，就没有这个问题（交叉熵与比特的关系见 [M05 §2](../math/m05-information-theory.html#p2)）。
:::

## IsoFLOP 实验

报告选了 8 个算力预算，从 $10^{17}$ 到 $3\times10^{20}$，每个预算设计约 10 种模型/数据分配；每个预算的超参数由 (6.12) 给出；在一个与训练集分布相似、含 1 亿 token 的独立验证集上计算 BPB [@dsllm]。

每个预算内部为什么会有一个谷底？沿着一条 IsoFLOP 曲线从左往右走，模型变大、数据变少。最左端模型太小，再多的数据也学不进去；最右端模型太大，$D=C/M$ 太少，没训够。两种损失此消彼长，中间就有一个最低点。本页后面的 (6.15) 会把这两头写成两个可以计算的项。

::: fig figures/l06-isoflop-allocation.svg | 图 6.13 IsoFLOP 曲线与最优分配（据 DeepSeek LLM 报告图 4 重绘） | scroll
**看 (b)(c) 两张图的虚线：它们就是 (6.14)，在双对数坐标里是直线，一直外推到 67B。** 原图里灰点是 8 个预算的实测最优点，虚线是报告对这些点的幂律拟合；本图的灰点是按 (6.14) 算出的位置，所以恰好落在线上，只标出实验覆盖的范围。(a) 是每个预算下的 U 形曲线：谷底的横坐标按 (6.14) 计算，谷底高度是研究笔记对原图的目测，曲线宽窄只是示意。(b)(c) 标出了 67B：它的 $M=4.3\times10^{11}$ 对应的最优算力是 $4.5\times10^{23}$，最优数据量是 $1.04\times10^{12}$ token；绿色星号是它实际训练的点（算力 $8.65\times10^{23}$、2T token），2T 是 $1.04\times10^{12}$ 的 1.92 倍。星号比同一横坐标处的虚线高出的倍数只有 $2/1.42\approx1.41$：同样 $8.65\times10^{23}$ 的算力，(6.14) 建议的是更大的模型、$1.42\times10^{12}$ token（练习 7）。据 DeepSeek LLM 报告图 4 重绘 [@dsllm]，直线与各点由脚本计算。
:::

拟合结果是两条幂律：

::: eq 最优模型规模与最优数据量（DeepSeek LLM 式 (4)） | (6.14)
$$\begin{aligned}M_{\mathrm{opt}}&=M_{\mathrm{base}}\,C^{a}=0.1715\,C^{0.5243}\\ D_{\mathrm{opt}}&=D_{\mathrm{base}}\,C^{b}=5.8316\,C^{0.4757}\end{aligned}$$
系数 $M_{\mathrm{base}}=0.1715$、$D_{\mathrm{base}}=5.8316$；指数 $a=0.5243$、$b=0.4757$。**模型规模指数** $a$ 与**数据规模指数** $b$ 说的是：算力每增加 10 倍，最优模型规模乘 $10^a$，最优数据量乘 $10^b$。
:::

这两组数不是彼此独立的。它们必须满足一个约束，可以当场验证：

::: deriv 为什么必须 $a+b=1$、$M_{\mathrm{base}}D_{\mathrm{base}}=1$
$M_{\mathrm{opt}}(C)\cdot D_{\mathrm{opt}}(C)=C$ || 最优分配也必须花完预算：(6.9) $C=MD$ 对每个 $C$ 都成立
$M_{\mathrm{base}}D_{\mathrm{base}}\cdot C^{a+b}=C$ || 代入 (6.14)，同底幂相乘指数相加
$a+b=1\ \text{且}\ M_{\mathrm{base}}D_{\mathrm{base}}=1$ || 对所有 $C$ 成立，两边的指数和系数必须分别相等
$0.5243+0.4757=1.0000$ || 代入报告的指数：满足
$0.1715\times5.8316=1.00012$ || 代入报告的系数：满足，差别来自四舍五入
:::

所以 $a$ 一个数就说清了分配。按数量级来算：$\log_{10}C=\log_{10}M+\log_{10}D$，算力每多一个数量级，最优模型长 $a$ 个数量级、最优数据长 $b=1-a$ 个。$a>0.5$ 表示模型长得比数据快，新增算力偏向模型；$a<0.5$ 表示偏向数据。DeepSeek 当前数据上 $a=0.5243$，略偏向模型。

::: ex 8 个预算的最优点
- $C=10^{17}$：$M_{opt}=0.1715\times10^{17\times0.5243}=1.40\times10^{8}$，$D_{opt}=5.8316\times10^{17\times0.4757}=7.12\times10^{8}$。核对：$1.40\times10^8\times7.12\times10^8\approx1.0\times10^{17}$。
- $C=10^{19}$：$M_{opt}=1.57\times10^9$，$D_{opt}=6.37\times10^9$。
- $C=3\times10^{20}$：$M_{opt}=9.34\times10^9$，$D_{opt}=3.21\times10^{10}$。

最大的一组实验的最优模型只有 $9.3\times10^9$ FLOPs/token，把它当成 $6N$，约合 $M/6\approx16$ 亿个参数（真实的非嵌入参数还要少，因为 $M$ 里含注意力项：表 3 中 $M=9.66\times10^9$ 的 $L=24$、$d=2048$ 模型只有 12.1 亿），比 7B 小得多；7B、67B 完全在外推区。
:::

## 67B 是“算力最优”的吗

**问题。** (6.14) 是从“算力给定，求最优模型”的方向写的。反过来：给定模型（它的 $M$），多少算力、多少数据对它才是最优的？

::: deriv 由模型规模反推最优算力与最优数据量
$M=0.1715\,C_{opt}^{0.5243}$ || (6.14) 的第一式，把 $M$ 当已知
$C_{opt}=\left(M/0.1715\right)^{1/0.5243}$ || 两边除以系数，再开 $1/0.5243$ 次方
$D_{opt}=C_{opt}/M$ || 由 $C=MD$；与用 (6.14) 第二式算的结果一致
:::

合起来，给定一个模型规模 $M$，对它“算力最优”的训练量是

$$D_{opt}(M)=\frac{1}{M}\left(\frac{M}{0.1715}\right)^{1/0.5243}\;\propto\;M^{\,1/0.5243-1}=M^{\,0.907}$$

模型大 10 倍，最优数据量大 $10^{0.907}\approx8.1$ 倍，比模型长得略慢。

::: ex 67B 与 7B 各训了“最优量”的几倍
- **67B**（$M=4.3273\times10^{11}$）：$C_{opt}=(4.3273\times10^{11}/0.1715)^{1/0.5243}\approx4.51\times10^{23}$，$D_{opt}=4.51\times10^{23}/4.3273\times10^{11}\approx1.04\times10^{12}$ token。报告图 4 标注的正是 “4.5e23” 和 “1.04e12 Tokens”。实际训了 2T，是最优量的 **1.92 倍**。
- **7B**（$M=4.2467\times10^{10}$）：$C_{opt}\approx5.39\times10^{21}$，$D_{opt}\approx1.27\times10^{11}$ token。实际 2T，是最优量的 **15.8 倍**。

所以 67B 大致接近算力最优，7B 则是一个“远远训过头”的小模型。报告没有解释为什么这样做。笔者推测有两个常见的理由：一是**推理成本**，模型越小，部署时每个 token 越便宜，多花训练算力把小模型训得更好，在大量推理中能赚回来；二是**工程上的简便**，两个模型共用同一份 2T 的数据和同一套流程。
:::

**每个参数分到多少 token？** 第 2 课讲过 Chinchilla 的经验值：大约每个参数 20 个 token。用 (6.14) 可以算出 DeepSeek 的对应量。$M/6$ 相当于 $6N$ 意义下的“等效参数”，所以看 $D_{opt}/(M_{opt}/6)$：$C=10^{17}$ 时约 30.4，$10^{21}$ 时约 19.5，$10^{23}$ 时约 15.6，$10^{25}$ 时约 12.4。因为 $b<a$，这个比值随算力缓慢下降，而不是一个常数。按同样的 $M/6$ 口径，实际的 7B 每个等效参数训了约 283 个 token（$2\times10^{12}/(4.2467\times10^{10}/6)$），67B 约 27.7 个；若按总参数量算，是 289 与 29.7。

## 数据质量改变最优分配

报告做了一件前人没做的事：在**三个不同的数据集**上各拟合一次 (6.14)。按报告的内部评估，当前的内部数据质量高于早期的内部数据；OpenWebText2 的质量又高于当前内部数据，因为它规模小，可以处理得更精细 [@dsllm]。

| 来源 | $a$（模型） | $b$（数据） | 算力 ×10：模型 × / 数据 × |
|---|---|---|---|
| Kaplan 等（报告表 4 标为 OpenAI (OpenWebText2)） | 0.73 | 0.27 | 5.37 / 1.86 |
| Chinchilla（MassiveText） | 0.49 | 0.51 | 3.09 / 3.24 |
| DeepSeek 早期内部数据 | 0.450 | 0.550 | 2.82 / 3.55 |
| DeepSeek 当前内部数据 | 0.524 | 0.476 | 3.34 / 2.99 |
| DeepSeek OpenWebText2 | 0.578 | 0.422 | 3.78 / 2.64 |

前两行是报告表 4 引用的前人结果，后三行是 DeepSeek 自己的拟合 [@dsllm]；最后一列是笔者按 $10^a$、$10^b$ 算的。

::: fig figures/l06-quality.svg | 图 6.14 数据越好，新增算力越该分给模型
**看下面三行蓝色部分的长度：从早期数据到当前数据再到 OpenWebText2，模型指数 $a$ 从 0.450 增到 0.524 再到 0.578。** 每一行是一个长度为 1 的条：按数量级计，算力每多一个数量级，蓝色 $a$ 是分给模型的份额，绿色 $b$ 是分给数据的份额，两者之和为 1。右边两列是算力增加 10 倍时模型与数据各乘多少。数据取自 DeepSeek LLM 报告表 4 [@dsllm]，倍数由脚本计算。
:::

报告的结论是：随着数据质量提高，模型规模指数 $a$ 逐渐增大，数据规模指数 $b$ 逐渐减小，说明增加的算力应当更多地分给模型而不是数据；这一发现也许还能解释前人研究中观察到的最优分配差异 [@dsllm]。

::: ex 算力从 1e22 增到 1e23，三种数据各怎么分
算力 ×10。按早期数据：模型 ×2.82，数据 ×3.55，数据长得比模型快；按当前数据：模型 ×3.34，数据 ×2.99；按 OpenWebText2：模型 ×3.78，数据 ×2.64。同一笔新增算力，在最好的数据上，最优模型的增长倍数是最差数据上的 $3.78/2.82\approx1.34$ 倍，数据的增长倍数只有后者的 $2.64/3.55\approx0.74$。拿 Kaplan（×5.37 / ×1.86）和 Chinchilla（×3.09 / ×3.24）对照：DeepSeek 当前数据与 OpenWebText2 的结果落在两者之间，早期数据（$a=0.450$）却比 Chinchilla 的 0.49 还偏向数据；三组按数据质量排成一条线。
:::

**为什么数据越好越该加大模型？** 报告明确把自己的解释标为**推测**：高质量数据通常意味着逻辑清晰，经过充分训练之后预测难度较低，因此增加算力时扩大模型更有利 [@dsllm]。下面用 Chinchilla 的参数化损失给这个推测一个可以计算的形式。这是笔者的解读，DeepSeek 没有拟合这种形式。

Chinchilla 把损失写成三项之和 [@chinchilla]：

::: eq Chinchilla 的参数化损失 | (6.15)
$$\hat L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B'}{D^{\beta}}$$
$E$ 是数据本身的熵（再好的模型也消不掉的部分）；$A/N^\alpha$ 是模型有限大造成的损失；$B'/D^\beta$ 是数据有限、没有训练到收敛造成的损失。为了不与 batch size 的 $B$ 混淆，这里把原文的 $B$ 写成 $B'$。
:::

::: deriv 在 $C=6ND$ 的约束下求最优 $N$
$\hat L(N)=E+A\,N^{-\alpha}+B'\,(C/6)^{-\beta}N^{\beta}$ || 用 $D=C/(6N)$ 消去 $D$
$\dfrac{d\hat L}{dN}=-\alpha A\,N^{-\alpha-1}+\beta B'(C/6)^{-\beta}N^{\beta-1}=0$ || 对 $N$ 求导，令导数为零
$\alpha A\,N^{-\alpha}=\beta B'(C/6)^{-\beta}N^{\beta}$ || 两边同乘 $N$
$N^{\alpha+\beta}=\dfrac{\alpha A}{\beta B'}\left(\dfrac C6\right)^{\beta}$ || 把 $N$ 的幂合到一边
$N_{opt}=G\left(\dfrac C6\right)^{\frac{\beta}{\alpha+\beta}},\quad G=\left(\dfrac{\alpha A}{\beta B'}\right)^{\frac1{\alpha+\beta}}$ || 两边开 $\alpha+\beta$ 次方；与 Chinchilla 式 (4) 相同
:::

::: eq 分配指数由两个“学习速度”的比值决定 | (6.16)
$$a=\frac{\beta}{\alpha+\beta},\qquad b=\frac{\alpha}{\alpha+\beta}$$
$\alpha$：模型变大时损失降得多快；$\beta$：数据变多时损失降得多快。$\beta$ 相对 $\alpha$ 越大，$a$ 越大。
:::

**读法。** (6.16) 说：如果数据项衰减得快（$\beta$ 大，多喂的数据很快就被“学完”），瓶颈就在模型，新增算力该给模型；反过来，若数据项衰减得慢，就该多给数据。DeepSeek 的推测“高质量数据在充分训练后预测难度低”，在这个模型里就对应“数据质量高 → $\beta/\alpha$ 大 → $a$ 大”。

::: ex 从 a 反推 β/α（玩具模型）
由 (6.16)，$\beta/\alpha=a/(1-a)$：

- 早期数据 $a=0.450$：$\beta/\alpha=0.450/0.550\approx0.82$。
- 当前数据 $a=0.524$：$\beta/\alpha\approx1.10$。
- OpenWebText2 $a=0.578$：$\beta/\alpha\approx1.37$。

在这个玩具模型的读法里，数据从早期换到 OpenWebText2，“数据项的衰减速度”相对“模型项的衰减速度”提高了约 $1.37/0.82\approx1.7$ 倍。注意 DeepSeek 用 $M$ 而不是 $N$，也没有拟合 (6.15)，这里的数字只用来帮助理解方向。
:::

::: warn 表 4 的三处细节
1. **第一行的数据集名字写错了。** Kaplan 等人用的是 OpenAI 内部的 WebText2 [@kaplan]；OpenWebText2 是 The Pile 新引入的开源数据集 [@pile]。报告把两者混为一谈；第五行 “Ours (OpenWebText2)” 才是 DeepSeek 在 OpenWebText2 上的结果。
2. **不同行的 $a$ 不是同一个量。** Kaplan、Chinchilla 的 $a$ 是 $N_{opt}\propto C^a$；DeepSeek 的 $a$ 是 $M_{opt}\propto C^a$。$M/N$ 随模型形状变化（§5），两者只能近似比较；报告表头写成 “$N_{opt}(M_{opt})\propto C^a$” 也暗示了这一点。Kaplan 的 0.73 还是对“最小算力” $C_{\min}$ 拟合的，数据侧的 0.27 是由 batch 与步数两个指数合成的 [@kaplan]。
3. **Chinchilla 有三个答案。** 它的三种方法分别得到 0.50/0.50、0.49/0.51（IsoFLOP）、0.46/0.54 [@chinchilla]。DeepSeek 引用的是第二种。
:::

报告在 §3 开头还加了一句：最优分配策略的差异，“也可以作为间接评估数据质量的一种方法” [@dsllm]。也就是说，$a$ 本身成了一个数据质量的指标：同样的实验流程，拟合出的 $a$ 越大，数据越“好”。

## 外推被证实了吗

报告图 5 把 8 个 IsoFLOP 预算的最优 BPB 画成算力的函数，用幂律拟合小模型的点，再把 7B、67B 的实际验证 BPB 放上去：两颗星落在拟合曲线上，报告的说法是它们的表现被 scaling 曲线“很好地预测了” [@dsllm]。报告没有给出这条曲线的拟合公式和系数，本课不编造。需要记住的是外推的距离：最大的 IsoFLOP 预算是 $3\times10^{20}$，7B 是它的 283 倍，67B 是 2885 倍；报告说的“1000 倍”是数量级上的概括。

::: key 本页要点
- IsoFLOP：8 个预算（$10^{17}$–$3\times10^{20}$），每个约 10 种分配，BPB 为指标。拟合得 $M_{opt}=0.1715\,C^{0.5243}$、$D_{opt}=5.8316\,C^{0.4757}$，且必然满足 $a+b=1$、$M_{base}D_{base}=1$。
- 反推：67B 的最优数据量约 1.04T，实际 2T（1.92 倍）；7B 的最优量约 0.127T，实际训了 15.8 倍。
- 数据质量越高，$a$ 越大（0.450 → 0.524 → 0.578），新增算力越该给模型；报告把原因标为推测。用 Chinchilla 的 $a=\beta/(\alpha+\beta)$ 可以把这个推测读成“数据项衰减更快”。
- 表 4 第一行的 “OpenWebText2” 应为 WebText2；不同行的 $a$ 分别对 $N$ 与 $M$ 定义，只能近似比较。
:::

# 对齐、DeepSeek-Coder 与总账 | SFT 与 DPO；同期的代码模型（仓库级数据、FIM）；本课所有设计的一张账单 | 30

预训练得到的 Base 模型只会“接着往下写”。要让它成为能对话的助手，还要对齐（[第 3 课](lesson-03-alignment-rlhf.html)）。DeepSeek LLM 的对齐只有两步：监督微调（SFT）和直接偏好优化（DPO），没有用 PPO 一类的强化学习（报告也没有提到奖励模型）。这一页先讲这两步和报告在其中发现的问题，再简要介绍同期发布的 DeepSeek-Coder，最后把全课的设计放进一张账单。

## SFT：150 万条数据，与“复读”问题

**数据。** 报告收集了约 150 万条中英文指令数据，覆盖“有用”与“无害”两类主题。有用数据 120 万条，其中通用语言任务占 31.2%，数学题 46.6%，编程练习 22.2%；安全数据 30 万条，覆盖各类敏感话题 [@dsllm]。

::: ex SFT 数据的构成
有用数据 $1{,}200{,}000$ 条：通用 $1{,}200{,}000\times0.312=374{,}400$ 条，数学 $559{,}200$ 条，代码 $266{,}400$ 条；加上安全数据 $300{,}000$ 条，共 150 万条。数学题占了有用数据的将近一半，这一点马上就会出问题。
:::

**训练。** SFT 的目标就是只在回答部分上做下一词预测（标准形式，见第 3 课；报告没有印公式）：

::: eq SFT 的目标 | (6.17)
$$\mathcal L_{\mathrm{SFT}}(\theta)=-\sum_{t=1}^{\lvert y\rvert}\log\pi_\theta\bigl(y_t\mid x,\,y_{<t}\bigr)$$
这是一条样本 $(x,y)$ 的损失，训练时对整个 SFT 数据集取平均。$x$ 是指令（prompt），$y$ 是参考回答，$y_t$ 是回答的第 $t$ 个 token；$\pi_\theta$ 是正在训练的模型。求和只覆盖回答部分，指令 $x$ 的 token 只作条件、不计损失。
:::

7B 训了 4 个 epoch，67B 只训 2 个，因为 67B 的过拟合问题很严重；学习率分别是 $10^{-5}$ 和 $5\times10^{-6}$ [@dsllm]。

**复读问题。** 报告用 3868 条中英文提示，统计回答“停不下来、无休止地重复一段文字”的比例，称为**复读率**（repetition ratio，在温度 0 下计算）。它发现数学 SFT 数据越多，复读率越高；报告的解释是数学数据里偶尔有相似的推理模式，较弱的模型抓不住这些模式，就会陷入重复 [@dsllm]。对策有两个：两阶段 SFT 和 DPO，两者都能在基本不损失基准分数的前提下显著降低复读。7B 的做法是：第一阶段用全部数据，第二阶段去掉数学和代码数据、只用对话数据；复读率从 2.0% 降到 1.4%。67B 第一阶段后复读率已经低于 1%，第二阶段反而损害基准分数，所以只做一阶段 [@dsllm]。报告还有一句值得记住的判断：它认为 SFT 阶段学到的不是推理能力，而是推理路径的正确**格式** [@dsllm]。

## DPO：一个 epoch 的偏好优化

::: pre DPO 的一句话回顾 | 学过第 3 课的可以跳过
DPO 由 Rafailov 等人提出，是一种不用强化学习、直接从偏好数据训练语言模型的算法 [@dpo]。给定提示 $x$ 与一对回答：被偏好的 $y_w$ 和不被偏好的 $y_l$（这里沿用 DPO 论文的字母；第 3 课写作 $q$、$o_w$、$o_l$）。它把 RLHF 里“奖励模型 + KL 约束下的策略优化”合并成一个分类损失，推导见[第 3 课 §7](lesson-03-alignment-rlhf.html#p7)。
:::

::: eq DPO 损失（Rafailov 等人式 (7)） | (6.18)
$$\mathcal L_{\mathrm{DPO}}(\pi_\theta;\pi_{\mathrm{ref}})=-\E_{(x,y_w,y_l)\sim\mathcal D}\left[\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right)\right]$$
$\pi_{\mathrm{ref}}$ 是参考模型（通常就是 SFT 模型），$\beta>0$ 控制偏离参考模型的程度，$\sigma$ 是 sigmoid 函数。
:::

::: ex DPO 损失的一个数值（$\beta$ 为示意值）
报告没有给出 $\beta$，这里取 $\beta=0.1$ 只为演示。训练开始时 $\pi_\theta=\pi_{\mathrm{ref}}$，两个对数比都是 0，括号内为 0，损失 $=-\log\sigma(0)=\ln2\approx0.693$。若训练后 $\log\frac{\pi_\theta(y_w)}{\pi_{\mathrm{ref}}(y_w)}=+2$、$\log\frac{\pi_\theta(y_l)}{\pi_{\mathrm{ref}}(y_l)}=-3$，括号内为 $0.1\times(2+3)=0.5$，$\sigma(0.5)\approx0.622$，损失 $\approx0.474$。损失下降，靠的是“拉高好回答、压低坏回答”相对于参考模型的概率。
:::

DeepSeek LLM 的 DPO 训一个 epoch，学习率 $5\times10^{-6}$，batch size 512，用 warmup 加 cosine 学习率调度；偏好数据按“有用”和“无害”两类构建，有用类的提示是多语言的，涵盖创意写作、问答、指令遵循等，回答候选由 DeepSeek Chat 模型自己生成 [@dsllm]。报告没有说明 chosen / rejected 由谁或由什么判定。报告的观察是：DPO 增强了开放式生成能力，而在标准基准上几乎没有差别。

::: ex DPO 的效果与“超过 GPT-3.5”的说法
MT-Bench（英文开放式评测，满分 10）：67B Chat 8.35，67B Chat DPO 8.76；GPT-3.5-turbo-0613 为 8.39，GPT-4-1106-preview 为 9.26 [@dsllm]。DPO 前比 GPT-3.5 低 0.04，DPO 后高 0.37。中文的 AlignBench（gpt-4-0613 打分）上，67B Chat 6.43、DPO 版 6.69，gpt-3.5-turbo-0613 为 6.08，DPO 前就已超过。所以摘要里“优于 GPT-3.5”的说法，在英文 MT-Bench 上只对 DPO 版成立；报告引言其实写明了前提：经过 SFT 和 DPO 之后，67B 对话模型在中英文开放式评测中都超过 GPT-3.5 [@dsllm]。
:::

**两个“不做”的决定。** 报告 §5.5 还讲了两个实验。第一，在对齐阶段给 7B Chat 加入 2000 万道中文选择题后，MMLU 从 49.4 升到 60.9、C-Eval 从 47.0 升到 71.3、CMMLU 从 49.7 升到 73.8，但生成式的 TriviaQA（57.9 不变）和内部中文问答（75.0 → 74.4）不涨；报告认为这是对基准的过拟合，不能带来真正的智能，于是**预训练和微调两个阶段都不用选择题数据** [@dsllm]。第二，在预训练最后 10% 加入 500 万条以选择题为主的指令数据，最终效果与在 SFT 阶段加入同样数据几乎相同 [@dsllm]。这两条都是实测结论。

## 同期旁支：DeepSeek-Coder

DeepSeek-Coder 是与 DeepSeek LLM 同期的代码模型系列：1.3B 到 33B，在 2T token 上**从头训练**，数据 87% 是源代码、10% 是与代码相关的英文自然语言、3% 是与代码无关的中文自然语言，覆盖 87 种编程语言（后来的 Coder-V2 论文说成 86 种，见[第 10 课 §8](lesson-10-v2-moe-training.html#p8)），用 16K 的窗口做“填空”训练 [@dscoder]。模型在 2023 年 11 月初前后公开（GitHub 仓库首个提交是 11 月 2 日）[@gh-coder]，报告 2024 年 1 月 25 日才发到 arXiv [@dscoder]。它有两处值得学的做法：仓库级的数据组织和 FIM 训练。

::: fig figures/l06-coder-data.svg | 图 6.15 DeepSeek-Coder 的数据管线与仓库级依赖排序 | scroll
**看右下角拼好的两条样本：同一个仓库的文件按“被依赖的在前”排好，每个文件前加一行路径注释，拼成一条训练序列。** 上排是五个步骤（据 DeepSeek-Coder 报告图 2 重绘）。下排是一个虚构的五文件仓库：箭头从被依赖的文件指向依赖它的文件；每次取入度最小的文件，环（a、b 互相 import）也不会让排序卡住；互不相连的两组文件各成一条样本。排序由脚本按报告算法 1 的规则计算 [@dscoder]。
:::

**仓库级数据。** 报告先爬取 2023 年 2 月前创建的 GitHub 公开仓库，只留 87 种语言，用规则过滤（例如平均行长超过 100 字符或最长一行超过 1000 字符的文件删除，字母字符少于 25% 的文件删除）后，数据量只剩原来的 32.8% [@dscoder]。接着做两件以**仓库**为单位的事：

- **依赖排序。** 先解析文件之间的依赖（只用正则表达式抽取，如 Python 的 `import`、C# 的 `using`、C 的 `include`），再按依赖排列文件，保证每个文件依赖的上下文出现在它之前 [@dscoder]。算法是改造过的拓扑排序：标准做法每次取入度为 0 的节点，这里取**入度最小**的节点，因此能处理环；每个连通子图排成一条序列，拼成一个训练样本，并在每个文件开头加一行注明路径的注释 [@dscoder]。
- **仓库级去重。** 按仓库而不是按文件去重，因为按文件去重可能删掉仓库里的某些文件，破坏仓库的结构 [@dscoder]。

最终代码语料 798 GB、6.03 亿个文件；去污染规则是：一段代码只要与测试数据有相同的 10-gram 字符串就被剔除，测试数据中短于 10-gram、但不短于 3-gram 的字符串用精确匹配过滤 [@dscoder]。报告的消融显示，只用文件级语料预训练时，Java、TypeScript、C# 的仓库级补全表现下降，说明仓库级预训练有效 [@dscoder]；不过 Python 列几乎没变（研究笔记据报告表 7 核对），收益不是全语言的。

## FIM：让模型学会“填中间”

**问题。** 代码补全最常见的场景是：光标停在一个函数中间，上面有代码，下面也有代码。普通的自回归模型只能看见光标**前面**的内容（前缀），看不见**后面**的（后缀）。

**含义。** **FIM**（fill-in-the-middle，中间填充）是一种数据变换：把一篇文档随机切成前缀、中段、后缀三段，重新排列后用特殊符号连起来，让模型在看过前缀和后缀之后生成中段。Bavarian 等人的表述是：对数据集做一个简单变换，把文档中间的一段挪到末尾，自回归语言模型就能学会填空 [@fim]。他们以概率 $p$（称为 **FIM 率**，主实验用 0.5）对每篇文档做这种切分，而且在分词**之前**按字符切 [@fim]。

**数学。** 按 PSM（prefix–suffix–middle）顺序，DeepSeek-Coder 的训练样本是 [@dscoder]：

::: eq PSM 格式的 FIM 训练样本 | (6.19)
$$\langle\texttt{fim\_begin}\rangle\; f_{pre}\;\langle\texttt{fim\_hole}\rangle\; f_{suf}\;\langle\texttt{fim\_end}\rangle\; f_{middle}\;\langle\texttt{eos}\rangle$$
$f_{pre}$、$f_{middle}$、$f_{suf}$ 是切出的三段；尖括号 $\langle\cdot\rangle$ 表示一个特殊 token（哨兵），如 $\langle\texttt{fim\_begin}\rangle$ 在分词器里写作 `<｜fim▁begin｜>`。报告 v2 把第一个哨兵写作 fim_start（v1 误印为 fim_hole）；发布的分词器里真实的名字是 fim▁begin、fim▁hole、fim▁end [@hf-coder-cfg]。
:::

::: fig figures/l06-fim-psm.svg | 图 6.16 一个 FIM 样本：把中段挪到最后 | scroll
**看第 ② 行：绿色的中段 “urn a ” 被挪到了序列末尾，前面是前缀和后缀。** 切点落在单词 return 的中间，这是故意的：Bavarian 等人建议按字符切，让模型对“token 被切断”的情况也有鲁棒性 [@fim]。第 ③ 行是推理时的用法：提示只给到 fim▁end，模型写出的就是中段。token 名称与编号取自发布的 DeepSeek-Coder 分词器 [@hf-coder-cfg]。
:::

DeepSeek-Coder 在打包成训练序列之前、在文档级实现 FIM，FIM 率 0.5，采用 PSM 模式 [@dscoder]。这个选择来自一个消融：用 1.3B 模型、只在 Python 子集上训练，比较 0%、50%、100% 的 FIM 率与 50% 的 MSP（masked span prediction，T5 式的遮盖片段预测）[@dscoder]。下表是研究笔记从报告图 3 的矢量坐标反解出的 9000 步读数（精度约 ±0.001，不是报告正文数字）：

| 9000 步时 | FIM 率 0 | FIM 率 0.5 | FIM 率 1.0 | MSP 0.5 |
|---|---|---|---|---|
| HumanEval pass@1（左到右补全） | 0.191 | 0.160 | 0.149 | 0.164 |
| HumanEval-FIM pass@1（填一行） | — | 0.626 | 0.604（5000 步时峰值 0.659） | 0.416 |
| MBPP pass@1（左到右补全） | 0.254 | 0.233 | 0.178 | 0.229 |

报告的结论是：100% FIM 率在 HumanEval-FIM 上达到峰值，但左到右的补全能力最弱，FIM 与补全之间存在权衡；50% 的 PSM 优于 MSP；最终选 50% PSM 作为平衡 [@dscoder]。

::: warn FIM 真的“免费”吗
Bavarian 等人报告了 **FIM-for-free** 性质：把 FIM 变换后的数据与普通数据混合训练，模型学会填空的同时，左到右的能力不受影响；FIM 率在 50% 到 90% 之间都是合理的选择 [@fim]。他们在 HumanEval 上也测过，各 FIM 率的表现相近。DeepSeek-Coder 的小消融却看到左到右补全下降：9000 步时 FIM 率 0.5 比 0 低约 3 个百分点（0.160 对 0.191）。两篇在同一指标上结论相反；可以列出的差异是模型规模（1.3B）、数据（只用 Python 子集）和训练长度（只到 9000 步）。本课并列两种结果，不判定谁对。另外，“100% FIM 率在 HumanEval-FIM 上最好”只在训练中途成立：到 9000 步时 0.5 的 0.626 已经反超 1.0 的 0.604。
:::

## Coder 复用了 DeepSeek LLM 的超参数规律

DeepSeek-Coder 报告明说：batch size 和学习率按 DeepSeek LLM 提出的 scaling law 设定；学习率用三阶段调度，2000 步 warmup，终值为初始值的 10%，每一阶段是前一阶段的 $\sqrt{1/10}$ [@dscoder]。可以拿 (6.12) 检验这句话。

::: ex 用 (6.12) 预测 DeepSeek-Coder 的超参数
按 2T token、4096 长的序列、真实结构的 $M$（研究笔记 R24）：

| 模型 | 结构（层 × $d$，注意力） | $M$（FLOPs/token） | 预测 $\eta$ / 实际 | 预测 batch（条）/ 实际 |
|---|---|---|---|---|
| 1.3B | 24 × 2048，MHA | $9.70\times10^{9}$ | $5.10\times10^{-4}$ / $5.3\times10^{-4}$ | 1391 / 1024 |
| 6.7B | 32 × 4096，MHA | $4.53\times10^{10}$ | $4.21\times10^{-4}$ / $4.2\times10^{-4}$ | 2303 / 2304 |
| 33B | 62 × 7168，GQA-8 | $2.19\times10^{11}$ | $3.46\times10^{-4}$ / $3.5\times10^{-4}$ | 3857 / 3840 |

6.7B 与 33B 几乎分毫不差，1.3B 的 batch 偏小。注意：Coder 报告表 2 的 batch size 没有写单位，“按 4096 长的序列”是研究笔记的解读，它与 6.7B、33B 的预测吻合，但与 1.3B 差得较多。以 6.7B 为例：$M=6\times32\times202{,}375{,}168+12\times32\times4096^2=4.53\times10^{10}$，$C=9.06\times10^{22}$，$\eta=0.3118\times C^{-0.125}\approx4.21\times10^{-4}$。
:::

**其余要点。**

- **长上下文。** 用线性 RoPE 缩放，缩放因子从 1 增到 4，基频从 10000 改为 100000，再训 1000 步，batch 512、序列长 16K [@dscoder]，即 $1000\times512\times16384\approx8.4\times10^9$ token。理论上可处理 64K（$16384\times4=65536$），但报告说实际最可靠的范围在 16K 以内。GitHub README 却说 16K 窗口的续训用了额外的 200B token [@gh-coder]，与报告相差约 24 倍，公开材料无法调和。按 (6.10)，6.7B 在 16K 序列上注意力约占 $M$ 的 40%。
- **分词器。** 报告说词表 32,000；发布的分词器是 32,000 个 BPE 条目加 22 个追加 token（含 FIM 哨兵与对话标记），嵌入矩阵 32,256 行 [@hf-coder-cfg]。33B 用 GQA-8，每 token KV cache 为 $2\times62\times8\times128\times2=253{,}952$ 字节 $=248$ KiB。
- **v1.5：从通用模型续训。** DeepSeek-Coder-v1.5 7B 从 DeepSeek LLM 7B Base 出发，再做 2T token 的预训练，只用下一词预测、4K 上下文 [@dscoder]（报告结论一节把这个量写成 “2 billion tokens”，与正文的 2 trillion 自相矛盾，以正文为准是笔者的判断）。报告据此得出结论：最有效的代码模型，是建立在强大的通用大模型之上的。后来的 DeepSeek-Coder-V2 也走了这条路：它从通用模型 DeepSeek-V2 的一个中间检查点出发续训（[第 10 课 §8](lesson-10-v2-moe-training.html#p8)）。

| 超参数 scaling law | 大训练无法网格搜索 | 67B：$\eta=3.17\times10^{-4}$、$B=19.7$M token | 只依赖 $C$；外推约 4.3 万倍 |
| 最优分配 (6.14) | 模型/数据怎么分 | $a=0.5243$；67B 最优 1.04T，实训 2T | 67B 与 7B 都不是算力最优 |
| 分配随数据质量变化 | 前人结论矛盾 | $a$：0.450 → 0.524 → 0.578 | 原因是推测；$a$ 的定义各家不同 |
| SFT + DPO | 对齐 | 150 万条 SFT；MT-Bench 8.35 → 8.76 | 数学数据导致复读；偏好标注方式未公开 |
| Coder：仓库级数据 + FIM | 跨文件上下文、中间填充 | FIM 率 0.5，PSM；798 GB 代码 | FIM 在小模型上并非完全免费 |

::: key 本页要点
- SFT：150 万条（数学占有用数据的 46.6%）；数学数据带来复读，7B 用两阶段 SFT 把复读率从 2.0% 降到 1.4%。DPO：一个 epoch，MT-Bench 从 8.35 到 8.76。
- 报告决定预训练和微调都不用选择题数据：它能刷高 MMLU 一类选择题基准，却不提高 TriviaQA 这类生成式评测。
- DeepSeek-Coder：仓库内按依赖排序（取入度最小者，可处理环）、按仓库去重、10-gram 去污染；FIM 以 0.5 的概率把中段挪到末尾（PSM）；超参数直接用 (6.12) 设定，6.7B、33B 的预测几乎分毫不差。
- DeepSeek LLM 留下的最重要的东西不是某个模型，而是一套“先在小预算上把规律测准，再放大”的方法。第 7 课的 DeepSeekMoE 会在这套方法之上改动 FFN 本身。
:::

## 概念题

:::: quiz 练习 1 · 为什么要换掉 6N
（a）用一句话分别说出 $6N_1$ 和 $6N_2$ 各错在哪里。（b）为什么“一个常数倍的误差”无害，而 $6N_1$ 的误差有害？（c）$M$ 本身还保留了哪些约定，使它也不是“精确 FLOPs”？
::: answer 看答案
（a）$6N_1=72Ld^2$ 没有计入注意力的打分与加权求和 $12LdT$，会低估；$6N_2=72Ld^2+6Vd$ 同样漏了注意力，又把输出头（词表）的计算算了进去，而词表对模型能力贡献较小，小模型上会高估（表 3 第一行 1.32）。

（b）若所有点的横坐标都乘同一个常数，双对数坐标里只是整体平移，拟合出的指数不变。但 $6N_1/M=6d/(6d+T)$ 随模型宽度变化（小模型 0.43，大模型 0.92），小模型的点被挪得远、大模型的点几乎不动，于是拟合的斜率与截距被扭曲，外推到几百倍以外误差被放大。报告附录的实测：$6N_1$ 高估、$6N_2$ 低估大模型的表现，$M$ 最准。

（c）注意力按“每个 token 与全部 $T$ 个位置打分”计，不打因果掩码的折扣；softmax、归一化、激活、残差加法等逐元素运算不计；反向按前向的 2 倍整齐计。它的价值是用同一条规则把随形状变化最大的注意力项算进去，而不是绝对精确；剩下的约定仍会随形状带来偏差（例如若实现省下因果掩码的一半，$M$ 多算 $T/(12d+T)$，小模型上可达 40%）。
:::

:::: quiz 练习 2 · 你的数据拟合出 a = 0.40
你用 DeepSeek 的流程在一批新数据上做 IsoFLOP 实验，拟合出 $M_{opt}\propto C^{0.40}$。（a）$b$ 是多少？算力增加 10 倍，模型和数据各该乘多少？（b）按 DeepSeek 报告的解读，这批数据的质量与 DeepSeek 的“早期内部数据”“当前内部数据”相比如何？（c）为什么这个结论只能当作“间接”的质量评估？
::: answer 看答案
（a）$C=M_{opt}D_{opt}$ 对所有 $C$ 成立，所以 $b=1-a=0.60$。算力 ×10：模型 $\times10^{0.40}\approx2.51$，数据 $\times10^{0.60}\approx3.98$，新增算力的大头应给数据。

（b）$a$ 比早期数据的 0.450 还小。按报告“数据质量越高，$a$ 越大”的观察，这批数据的质量很可能低于 DeepSeek 的早期内部数据。

（c）$a$ 同时受很多因素影响：超参数是否调到最优、预算范围、记账方式（$N$ 还是 $M$）、验证集的选择。报告对“为什么质量影响 $a$”的解释也明确标为推测。所以 $a$ 只能作为一个旁证，不能替代直接的质量评估。
:::

:::: quiz 练习 3 · GQA 省了什么
判断对错并说明理由：（a）67B 用 GQA-8，所以训练时每个 token 的注意力打分 FLOPs 是 MHA 的 1/8。（b）GQA 让每层注意力的参数少了 43.75%。（c）67B 每 token 的 KV cache 比 7B 小。（d）DeepSeek 把 GQA 省下的参数加到了 FFN 的中间维度上。

（b）对。MHA 注意力 $4d^2=268{,}435{,}456$，GQA-8 为 $2d^2+2d\times1024=150{,}994{,}944$，少了 $117{,}440{,}512$，即 43.75%。

## 推导题

:::: quiz 练习 11 · 什么时候可以放心用 6N₁
（a）由 (6.8) 推导：要让 $6N_1$ 的低估不超过 10%（即 $6N_1/M\ge0.9$），$d$ 至少是 $T$ 的多少倍？（b）$T=4096$ 与 $T=16384$ 时各需要多宽？DeepSeek LLM 7B、67B 分别满足吗？（c）这与 Kaplan 省略上下文项的条件 $d\gg n_{ctx}/12$ 有什么关系？
::: answer 看答案
（a）$\dfrac{6d}{6d+T}\ge0.9\iff6d\ge0.9(6d+T)\iff0.6d\ge0.9T\iff d\ge1.5T$。

（b）$T=4096$ 需要 $d\ge6144$；$T=16384$ 需要 $d\ge24576$。7B（$d=4096$）不满足，低估 14.3%；67B（$d=8192$）满足，按 (6.8) 低估 7.7%（按真实结构 (6.11) 是 $6N_1/M=3.945\times10^{11}/4.3273\times10^{11}\approx0.912$，低估 8.8%，仍满足）。

（c）Kaplan 的前向上下文项是 $2Ln_{ctx}d$，与参数项 $2N=24Ld^2$ 之比是 $n_{ctx}/(12d)$，所以 $d\gg n_{ctx}/12$ 时可以忽略。DeepSeek 的注意力项按不打折扣的方式计，是 Kaplan 的 2 倍，对应的比值是 $T/(6d)$，条件更严：同样要误差小于 10%，Kaplan 的记法下 $d\ge0.75\,n_{ctx}$ 即可，DeepSeek 的记法下要 $d\ge1.5T$。

:::: quiz 练习 12 · 在 C = MD 下推导分配指数
设损失 $L(M,D)=E+A\,M^{-\alpha}+B'\,D^{-\beta}$（$A,B',\alpha,\beta>0$），约束 $C=MD$。（a）求 $M_{opt}(C)$ 与 $D_{opt}(C)$，写出 $a$、$b$。（b）验证 $a+b=1$。（c）若数据质量提高使 $\beta$ 从 $0.8\alpha$ 变成 $1.2\alpha$，$a$ 从多少变到多少？
::: answer 看答案
（a）代入 $D=C/M$：$L(M)=E+AM^{-\alpha}+B'C^{-\beta}M^{\beta}$。求导令其为零：$-\alpha AM^{-\alpha-1}+\beta B'C^{-\beta}M^{\beta-1}=0$，两边乘 $M$ 得 $\alpha AM^{-\alpha}=\beta B'C^{-\beta}M^{\beta}$，即 $M^{\alpha+\beta}=\frac{\alpha A}{\beta B'}C^{\beta}$。所以

$$M_{opt}=\Bigl(\frac{\alpha A}{\beta B'}\Bigr)^{\frac1{\alpha+\beta}}C^{\frac{\beta}{\alpha+\beta}},\qquad D_{opt}=\frac{C}{M_{opt}}=\Bigl(\frac{\alpha A}{\beta B'}\Bigr)^{-\frac1{\alpha+\beta}}C^{\frac{\alpha}{\alpha+\beta}}.$$

$a=\beta/(\alpha+\beta)$，$b=\alpha/(\alpha+\beta)$。与 Chinchilla 在 $C=6ND$ 下的结果相比，只差把 $C$ 换成 $C/6$，指数相同。二阶导 $\alpha(\alpha+1)AM^{-\alpha-2}+\beta(\beta-1)B'C^{-\beta}M^{\beta-2}$ 在驻点处等于 $\alpha(\alpha+\beta)AM^{-\alpha-2}>0$（用驻点条件代换第二项），所以是最小值。

（b）$a+b=(\beta+\alpha)/(\alpha+\beta)=1$；系数相乘 $M_{base}D_{base}=1$，与 §7 的推导一致。

（c）$\beta=0.8\alpha$：$a=0.8/1.8\approx0.444$；$\beta=1.2\alpha$：$a=1.2/2.2\approx0.545$。$a$ 增大约 0.1，与 DeepSeek 从早期数据（0.450）到当前数据（0.524）再到 OpenWebText2（0.578）的变化同一量级。这只是玩具模型，用来理解方向。
:::
