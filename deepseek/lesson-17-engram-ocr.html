第 17 课 · 记忆的另外两种形态：Engram 与 DeepSeek-OCR

到第 16 课为止，模型只有两种方式记住东西：训练时写进权重，推理时写进 KV cache。前者要靠一层层计算才能“想起来”，后者要把每个 token 逐字保存到对话结束。这一课讲 DeepSeek 在 2025–2026 年提出的两种新形态：Engram 让模型用最近几个 token 的编号直接查表取回静态知识，表可以大到 196B 参数、放在主机内存里；DeepSeek-OCR 把一页文字拍成图片，用约十分之一的视觉 token 装下它，并由此设想一种会“遗忘”的上下文。

这一课回答什么问题

读一句 “Only Alexander the Great could tame the horse Bucephalus.” 时，你不会先把 “Alexander”“the”“Great” 三个词分别理解一遍，再推理出它们合起来指一位马其顿国王；你是直接“认出”这个名字的。Transformer 做不到“直接认出”：它没有查表这条指令，只能用前几层的注意力和前馈网络，把这几个 token 的信息一步步拼起来。另一方面，它对上下文又记得“太好”：一百轮之前说过的每个 token，都以完整的键和值留在 KV cache 里，占着显存，直到对话结束。这一课回答五个问题：

  • 模型为什么要花好几层的计算去“拼”一个固定搭配？能不能像老式的 N-gram 模型那样，用最近几个 token 的编号直接查一张表？表里的行数远远少于可能的 N-gram 数，怎么办？
  • 查到的东西可能是错的（哈希碰撞、一词多义），模型怎样决定信不信它？这个查表模块放在网络的哪一层、以什么方式加进残差流？
  • 参数总数固定时，多出来的“不激活参数”该给 MoE 的专家，还是给这张表？Engram 论文的 U 形曲线说了什么、没说什么？
  • 这张表为什么能放在主机内存里，而 MoE 的专家不方便这么做？DeepSeek-V4.1-Flash 真的用了它吗，用了多大？
  • 一页文字拍成图片之后，要多少个视觉 token 才能把它“读回来”？压缩 10 倍、20 倍时还剩多少精度？这对“长对话的记忆”意味着什么，又不意味着什么？

这一课在科技树上的位置

这一课属于主线 E（残差流与记忆），同时碰到主线 A（KV cache 经济学）和主线 B（稀疏化）。第 7 课的 MoE 是“条件计算”：参数很多，每个 token 只激活一部分，而激活哪一部分由隐藏状态决定。Engram 提出与它互补的第二条稀疏轴，“条件记忆”：参数也很多，每个 token 也只取一小部分，但取哪一部分只由 token 编号决定。Engram 论文的实验（除非另行注明）都建立在第 16 课的 mHC 多分支残差流上，它的门控正是按分支分别计算的。

另一半内容接着第 4 课、第 9 课与第 14 课的 KV cache 账单：MLA 把每个 token 的条目压小，DSA 让每个查询只读一部分条目，但它们都默认“每个 token 一份条目，永远保留”。DeepSeek-OCR 提出另一种可能：把旧的上下文整体换成一张图，用少得多的视觉 token 保存，代价是精度随压缩比下降。

下一课的 DeepSeek-V4 没有使用 Engram，只在结论里把探索“更多稀疏嵌入模块”（原文 “more sparse embedding modules”）列为未来方向 1；再下一课的 V4.1-Flash 把 196B 参数的 Engram 放进了生产模型 2。本课 §2 会从 V4.1 的配置文件逐位算出这个 196B，§5 讲它怎样放进生产系统。

本课的记号
  • Engram 论文用 \(K\) 表示每阶的哈希头数、\(N\) 表示最大 N-gram 阶、\(M\) 同时表示表大小、mHC 分支数和“槽数”。这些字母在本课程里另有用途，本课改写为：哈希头数 \(K_{\text{hash}}\)，最大阶 \(N_{\text{gram}}\)，第 \((n,k)\) 张表的大小（一个素数）\(p_{n,k}\)，mHC 分支数 \(n_{hc}\)（第 16 课把扩展率记作 \(n\)，这里 \(n\) 已用来表示 N-gram 的阶，所以改用 V4 论文的写法 \(n_{hc}\)），槽数 \(S\)。
  • 记忆的键、值投影写成 \(W^K_{\text{mem}},W^V_{\text{mem}}\)，记忆键、值写成 \(\mathbf k^{\text{mem}}_t,\mathbf v^{\text{mem}}_t\)，以免与注意力的 \(W^K,W^V\) 混淆。\(\mathbf h_t\in\R^d\) 仍是第 \(t\) 个 token 的隐藏状态，\(d\) 是骨干隐藏维度（Engram-27B：\(d=2560\)；V4.1-Flash：\(d=5120\)）。
  • 参数预算：论文的 \(P_{\text{tot}},P_{\text{act}},P_{\text{sparse}}\) 本课写 \(N_{\text{tot}},N_{\text{act}},N_{\text{sparse}}\)（课程里 \(N\) 表示参数量）。
  • DeepSeek-OCR：\(n_v\) 是视觉 token 数，\(n_t\) 是文本 token 数，压缩比 \(r=n_t/n_v\)；DeepSeek-OCR 2 的因果查询数记作 \(n_q\)（论文的 \(m,n\)）。
  • 层号统一“从 1 数”，除非注明“从 0 计”。Engram 论文有 arXiv 版（本课以 v2 的节号、式号、图号为准）和 ACL 2026 正式版，后者把模块改称 Deep Sparse Embedding（DSE）3,4；本课一律称 Engram。

两本记忆账

到第 16 课为止，一个 DeepSeek 模型“记住”东西只有两种办法。一种是训练时写进权重，所有请求共用，叫参数化记忆（parametric memory）；另一种是推理时写进 KV cache，每个请求一份，叫上下文记忆。这一页把两种记忆各自的账单算一遍：前者的账单付在“深度”上，后者的账单付在“字节”上。算完之后，本课的两个主角各自要解决什么问题就清楚了。

第一本账：用计算去模拟查表

含义。 语言里有大量“静态的局部搭配”：几个固定的 token 连在一起，意思就定了，和上下文几乎无关。人名（“Alexander the Great”“张仲景”）、专名（“the Milky Way”“四大发明”）、固定短语（“By the way”）都是。Engram 论文画门控热图时举的正是这些例子 3。

理解。 分词器会把 “Alexander the Great” 切成几个 token。模型读到 “Great” 这个位置时，需要知道“这三个词合起来是一位历史人物”。Transformer 没有“查表”这条原语，它只能计算：前几层的注意力把前面几个 token 的信息搬到当前位置，前馈网络再认出这个组合，把“历史人物、马其顿、征服者”一类特征写进残差流。Engram 论文把这件事概括为：解析一个常见的多 token 实体要消耗前面好几层的注意力和前馈网络，实质上是在运行时花大价钱重建一张静态查找表（原文 “an expensive runtime reconstruction of a static lookup table”）3。每读到一次 “Alexander the Great”，这个重建就要做一次。

数学。 把“重建”要产出的东西写成一个函数：它只依赖最近 \(n\) 个 token 的编号，不依赖更远的上下文。输入是有限个离散值的组合，这样的函数原则上可以存成一张表，“算”它只需要一次查找。这正是经典 N-gram 模型做的事。

N-gram（N 元组）

含义。 连续的 \(n\) 个 token。“the Great” 是一个 2-gram（二元组），“Alexander the Great” 是一个 3-gram。

理解。 深度学习之前的语言模型就是 N-gram 模型：数一数语料里 “Alexander the” 后面跟 “Great” 的次数，用频率来预测下一个词。它的记忆是一张以 N-gram 为键的大表，查起来极快，但没有泛化能力，也看不到 \(n\) 个 token 以外的东西。

数学。 第 \(t\) 个位置、阶为 \(n\) 的 N-gram 是最近 \(n\) 个 token 编号组成的元组：

\[g_{t,n}=(x_{t-n+1},\dots,x_{t-1},x_t),\qquad x_j\in\{0,1,\dots,V-1\}\]

\(x_j\) 是第 \(j\) 个 token 在词表里的编号，\(V\) 是词表大小。可能的 \(n\) 元组共有 \(V^n\) 个。

\(V^n\) 增长得极快。DeepSeek 的分词器有 129,280 个 token；按下一页的“分词器压缩”并掉大小写等差别之后，V4.1-Flash 的配置里还剩 99,092 个规范编号 5。于是可能的 2-gram 约 \(9.82\times10^{9}\) 个，3-gram 约 \(9.73\times10^{14}\) 个，4-gram 约 \(9.64\times10^{19}\) 个。没有任何一张表能给每个 N-gram 单独一行，这就是下一页要用“哈希”的原因。

条件计算与条件记忆

Engram 论文把它的想法放在一个更大的框架里：条件计算（conditional computation）与条件记忆（conditional memory）是两条互补的稀疏轴 3。条件计算你已经在第 7 课见过，就是 MoE：参数很多，每个 token 只用其中一部分，用哪一部分由当前的隐藏状态决定。回忆 DeepSeekMoE 的一层：

MoE：用哪些参数由隐藏状态决定\[\begin{aligned}\mathbf h_t'&=\mathbf h_t+\sum_{i=1}^{N_s}\FFN^{(s)}_i(\mathbf h_t)+\sum_{i=1}^{N_r}g_{i,t}\,\FFN^{(r)}_i(\mathbf h_t),\\ g_{i,t}\neq0&\iff s_{i,t}\in\TopK\big(\{s_{j,t}\}_{j=1}^{N_r},\,K_r\big)\end{aligned}\]\(N_s,N_r\)：共享专家、路由专家的个数；\(K_r\)：每个 token 激活的路由专家数；\(s_{i,t}\)：由 \(\mathbf h_t\) 算出的亲和度。选哪些专家要等 \(\mathbf h_t\) 算出来才知道。(17.1)

条件记忆换了一个选择依据：不看隐藏状态，只看 token 编号。

Engram：取哪几行只由 token 编号决定\[\mathbf e_t=\operatorname{Lookup}\big(g_{t,2},\,g_{t,3},\,\dots,\,g_{t,N_{\text{gram}}}\big)\in\R^{d_{\text{mem}}}\]\(\mathbf e_t\)：从表里取回并拼接好的记忆向量；\(N_{\text{gram}}\)：用到的最大阶。取哪几行在前向传播开始之前就能算出来。(17.2)

两者的差别用一张表放在一起看：

条件计算（MoE） 条件记忆（Engram）
选择依据 当前层的隐藏状态 \(\mathbf h_t\) 最近 2–4 个 token 的编号
什么时候知道选谁 算到这一层才知道 读入 token 时就知道
被选中的参数做什么 一个小 FFN，要做矩阵乘法 一行向量，直接取出
适合的知识 动态的、依赖上下文的推理 静态的、固定搭配式的知识
每 token 的主要代价 FLOPs 字节搬运（取行）

表中最后两行是论文的论点，不是定理：论文认为 MoE 负责“动态逻辑”、Engram 负责“固定知识”（原文 “retrieve static embeddings for fixed knowledge”）3。§3 的组件消融和 §4 的分配实验、关闭实验会检验这个说法到底成立到什么程度。

类比：医院里的会诊与速查手册

沿用第 7 课的类比：MoE = 医院。路由器是分诊台，专家是专科医生；分诊台要先看病人的情况（隐藏状态）才能决定请哪几位医生会诊，会诊本身要花时间（FLOPs）。

映射。 Engram 是挂在分诊台旁边的一本速查手册：按病名的前几个字（最近几个 token 的编号）编好了页码，翻到那一页就能读到标准处方（记忆向量）。不需要先诊断，看一眼病名就知道翻哪一页，所以可以在病人走到分诊台之前就把那一页准备好（§5 的预取）。

收益。 它说明了为什么两者互补：常见病照手册处理，省下专科医生的时间去看疑难杂症；而手册再厚也不会“推理”。

失效的地方。 真实的手册一页对应一种病；Engram 的“页码”是哈希出来的，许多不同的病名会翻到同一页（碰撞），所以读到的内容要先和病人的实际情况核对一遍再用（§3 的门控）。另外，手册的内容也是训练出来的，不是人写的。

第二本账：KV cache 按 token 线性增长

第二本账你在第 4 课就算过：每个 token 在每一层都留下它的键和值，后来的 token 每一步都要回头读它们。第 9、14 课以及后面的第 18、19 课，都在想办法让每个 token 的条目更小，或者让每一步读更少的条目。到 V4.1-Flash，每个 token 的全局 KV cache 被压到 890 字节 2，但它仍然是“每个 token 一份、会话不结束就不释放”。

上下文记忆的大小\[M_{\text{KV}}(T)=T\cdot b_{\text{KV}}\]\(T\)：上下文里的 token 数；\(b_{\text{KV}}\)：每个 token 的 KV 字节数（V4.1-Flash 全局 \(b_{\text{KV}}=890\) 字节）；\(M_{\text{KV}}\)：一个请求占用的 KV 字节。(17.3)
一个长对话要多少 KV

按 V4.1-Flash 的 \(b_{\text{KV}}=890\) 字节/token：

  • 一次 10 轮、每轮 1,000 token 的对话：\(T=10{,}000\)，\(M_{\text{KV}}=8.9\times10^{6}\) 字节 \(=8.9\) MB。
  • 一个一百万 token 的智能体会话：\(M_{\text{KV}}=890\times10^{6}\) 字节 \(\approx0.89\) GB，这还只是一个请求。

(17.3) 是一条过原点的直线：第一轮说过的一个语气词，和刚刚说出的关键数字，占用完全一样多的字节，而且都要保留到会话结束。

人不是这样记对话的。一小时前的讨论，你记得结论和几个关键词，细节已经模糊；刚才那句话你能逐字复述。这引出一个问题：旧的上下文能不能用更低的“分辨率”保存？ MLA、DSA 这些方法对每个 token 一视同仁，它们回答不了这个问题。DeepSeek-OCR 的回答是：把旧的文字渲染成图片，图片越旧就缩得越小、越模糊，用少得多的视觉 token 保存它 6。§6 和 §7 讲这个设想和它背后的真实实验。

两个回答，一个共同点

两种新记忆的共同点是分层：不是所有要记的东西都值得用最贵的方式记。静态的局部搭配不必每次用好几层计算去重建，可以查一张表，而这张表因为寻址方式简单，可以放在比 GPU 显存便宜得多的主机内存里；旧的上下文不必逐 token 全精度保存，可以压成少量视觉 token，代价是“记得不那么清楚”。

“Engram 也省了 KV cache”

不对。Engram 是参数化记忆：它用最近几个 token 的编号去查一张训练好的表，查到的向量加进残差流。它既不存储、也不压缩上下文的键和值；每个位置只需要最近 \(N_{\text{gram}}-1\) 个 token 的编号。课程地图给本课的主题是“不是所有上下文都需要以完整 KV 的形式记住”，这句话对 DeepSeek-OCR 是字面意义上成立的；对 Engram 应该改成“不是所有知识都需要靠逐层计算来重建”。Engram 对长上下文确实有帮助，但那是间接的：§4 会看到，论文认为它把局部搭配交给查表，让注意力腾出容量去处理全局上下文。

本页要点
  • 参数化记忆的账付在深度上：Transformer 没有查表原语，重建一个多 token 实体要消耗前几层的注意力和 FFN。
  • 上下文记忆的账付在字节上：KV cache 按 \(M_{\text{KV}}=T\,b_{\text{KV}}\) 线性增长，每个 token 一份、保留到底。
  • Engram（条件记忆）按 token 编号查表，与 MoE（条件计算，按隐藏状态选专家）互补；DeepSeek-OCR 把旧上下文压成视觉 token。前者不省 KV，后者才是在压上下文。

Engram（上）：把 N-gram 变成一张可查的表

Engram 来自 DeepSeek 与北京大学 2026 年 1 月的论文《Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models》，代码同日开源 3,7。论文说它以经典的 N-gram 结构为基础，加上四项“现代化改造”：分词器压缩、多头哈希、上下文门控、多分支集成 3。这一页讲前两项，外加把查到的东西拼成一个向量；下一页讲后两项。

读这一页时请记住一个数：Engram-27B 的记忆向量有 \(d_{\text{mem}}=1280\) 维，由 2 个阶 × 8 个头 × 每头 80 维拼成。它的每一步都会落到这个数上。

第一步：分词器压缩

含义。 把“写法不同、意思相同”的 token 并成同一个编号，再拿去查表。

理解。 BPE 分词器（第 1 课）会给 “ Great” 和 “ great”、“Great” 和 “ Great”（前面有没有空格）各自分配不同的编号。对预测下一个 token 来说，这些区别有用；对“这几个词合起来指什么”来说，它们大多是噪声。如果不合并，“the Great” 和 “the great” 就是两个 N-gram，各占一行、各自学习，统计量被拆散了，表的容量也被浪费了。

数学。 预先算好一个满射（surjective function）\(\mathcal P\)：从原词表 \(\mathcal V\) 到一个更小的规范词表 \(\mathcal V'\)，每个原编号映到一个规范编号，多个原编号可以映到同一个 3：

分词器压缩\[\mathcal P:\mathcal V\to\mathcal V',\qquad x'_t=\mathcal P(x_t)\]\(x_t\)：第 \(t\) 个 token 的原编号；\(x'_t\)：它的规范编号。“满射”的意思是 \(\mathcal V'\) 里每个编号都至少有一个原编号映过来，所以 \(\abs{\mathcal V'}\le\abs{\mathcal V}\)。(17.4)
Unicode 规范化与“去重音”熟悉 NFKC 的可以跳过

同一个字符在 Unicode 里常有多种写法：全角的“Ａ”和半角的“A”，连字“ﬁ”和两个字母“fi”，预先合成的“á”和“a + 一个组合重音符”。NFKC 是一种标准的规范化：把这类“兼容写法”统一成一种规范写法。NFD 则反过来，把“á”拆成“a”加一个重音符号；拆开以后再去掉重音（strip accents），“á”“ä”就都变成了“a”。Engram 用这些步骤判断两个 token 是否“文本上等价”。

论文正文只写了“NFKC、转小写等”；开源代码里的规范化链更长：NFKC → NFD → 去重音 → 转小写 → 把连续空白折叠成一个空格 7。论文附录的表 6 列出了合并最多的 5 个规范 token：空格 ' ' 吸收了 163 个原 token，'a' 吸收 54 个，'o' 40 个，'e' 35 个，'i' 30 个，其中 'á'、'ä' 并入 'a'，与代码的去重音一致 3。

规范词表有多大

论文说，对 128K 的分词器，压缩使有效词表大小减少 23%，附录给出的精确值是 23.43% 3。DeepSeek 的分词器有 \(V=129{,}280\) 个 token，按 23.43% 算，剩下

\[129{,}280\times(1-0.2343)=98{,}990\ \text{个规范编号}.\]

V4.1-Flash 的配置文件写的是 engram_compressed_vocab_size: 99092 5，即 \(99{,}092/129{,}280=76.65\%\)，减少 23.35%。两者差约 100 个编号，来源没有说明（可能是分词器版本不同），本课不做猜测。重要的是量级：约四分之一的编号被并掉了。

第二步：取出最近几个规范编号

对每个位置 \(t\) 和每个阶 \(n=2,\dots,N_{\text{gram}}\)，取出最近 \(n\) 个规范编号：

压缩后的 N-gram\[g_{t,n}=(x'_{t-n+1},\dots,x'_{t-1},x'_t),\qquad n=2,3,\dots,N_{\text{gram}}\]Engram-27B：\(N_{\text{gram}}=3\)，即阶 2 和 3；V4.1-Flash：\(N_{\text{gram}}=4\)，即阶 2、3、4 3,2。序列开头不足 \(n\) 个 token 的位置，开源代码用填充编号补齐 7。(17.5)

阶从 2 开始而不是 1。笔者的解读：1-gram 的查表就是输入层的词嵌入本身（按一个 token 的编号取一行），不需要再做一遍。

第三步：多头哈希

问题。 上一页算过，可能的 3-gram 约有 \(10^{15}\) 个，而 Engram-27B 的一张表只有约 226 万行。必须有一个函数，把巨大的 N-gram 空间确定地压进一个小得多的行号范围。这个函数就是哈希。

含义。 哈希函数（hash function）把任意输入确定地映射成一个固定范围内的整数。

理解。 像衣帽间的号码牌：同一件大衣每次都拿到同一个号（确定性），所以下次能按号取回；但号码只有几百个，大衣却可能有几万件，不同的大衣难免会分到同一个号，这叫碰撞（collision）。这个类比在一处要修正：衣帽间只有一套号码牌，撞号就拿错；Engram 给每个 N-gram 同时发 8 张来自 8 套不同号码系统的牌（8 个“头”），只要不是每一套都撞号，两个 N-gram 拿到的东西就不完全一样（本页最后一节会算这件事有多少把握）。

数学。 Engram 给每个阶 \(n\) 配 \(K_{\text{hash}}\) 个哈希“头”，第 \(k\) 个头有自己的哈希函数 \(\varphi_{n,k}\) 和自己的表 \(E_{n,k}\)，表的行数是一个素数 \(p_{n,k}\) 3：

多头哈希查表\[z_{t,n,k}=\varphi_{n,k}(g_{t,n})\in\{0,1,\dots,p_{n,k}-1\},\qquad \mathbf e_{t,n,k}=E_{n,k}[z_{t,n,k}]\in\R^{d_{\text{head}}}\]\(z_{t,n,k}\)：行号；\(E_{n,k}\in\R^{p_{n,k}\times d_{\text{head}}}\)：第 \((n,k)\) 张表，每行 \(d_{\text{head}}\) 维；\(\mathbf e_{t,n,k}\)：取回的那一行。原文式 (1)。Engram-27B：\(K_{\text{hash}}=8\)，\(d_{\text{head}}=80\)。(17.6)

论文只说 \(\varphi_{n,k}\) 是一个“轻量的乘法-异或哈希”（multiplicative-XOR hash）。开源的演示代码和 V4.1-Flash 的推理代码给出了具体写法 7,5，笔者把它整理成公式：

代码里的哈希：一个混合值，对不同素数取模\[\text{mix}_{t,n}=\bigoplus_{i=0}^{n-1}\big(x'_{t-i}\cdot c_i\big),\qquad z_{t,n,k}=\text{mix}_{t,n}\bmod p_{n,k}\]\(\oplus\)：按位异或；\(c_i\)：随机奇数乘子，每个 Engram 层一组、每个回看位置一个；\(p_{n,k}\)：全模型互不相同的素数。同一阶的 \(K_{\text{hash}}\) 个头共用同一个 \(\text{mix}_{t,n}\)，只是模数不同。（实际代码还给每张表加一个行偏移，把所有表拼成一张大表存放。）(17.7)
按位异或与取模会的可以跳过

按位异或（XOR，记作 \(\oplus\)）把两个整数写成二进制，逐位比较：相同得 0，不同得 1。例：\(12=1100_2\)，\(5=0101_2\)，\(12\oplus5=1001_2=9\)。它的好处是便宜（一条指令），而且每一位输入都会影响输出。取模 \(a\bmod p\) 是 \(a\) 除以 \(p\) 的余数，结果落在 \(0\) 到 \(p-1\) 之间，正好当作行号。例：\(23\bmod7=2\)，因为 \(23=3\times7+2\)。

乘子为什么要不同？如果每个位置的乘子都一样，异或又不分先后，(“the”, “Great”) 和 (“Great”, “the”) 就会得到同一个混合值；给每个回看位置配不同的乘子，顺序就被编码进去了。代码还把乘子的上界限制为“\(2^{63}\) 除以规范词表大小再除以 2”，保证 \(x'\cdot c_i\) 不会溢出 64 位整数 7。每个乘积都是小于 \(2^{63}\) 的非负整数，而按位异或不会产生比两个输入更高的二进制位，所以每个混合值都是一个小于 \(2^{63}\) 的非负整数，这个事实在后面的碰撞分析里会用到。

手算一个迷你哈希

为了能手算，取极小的数：乘子 \(c_0=3\)、\(c_1=5\)，两个头的表大小 \(p_1=7\)、\(p_2=11\)。

2-gram A = \((x'_{t-1},x'_t)=(1,4)\)：\(4\times3=12=1100_2\)，\(1\times5=5=0101_2\)，\(\text{mix}_A=1100_2\oplus0101_2=1001_2=9\)。头 1 行号 \(9\bmod7=2\)，头 2 行号 \(9\bmod11=9\)。

2-gram B = \((3,8)\)：\(8\times3=24=11000_2\)，\(3\times5=15=01111_2\)，\(\text{mix}_B=10111_2=23\)。头 1 行号 \(23\bmod7=2\)，头 2 行号 \(23\bmod11=1\)。

A 和 B 在头 1 里撞了（都是第 2 行），在头 2 里没撞（第 9 行与第 1 行）。拼接之后，A 得到“头 1 第 2 行 ‖ 头 2 第 9 行”，B 得到“头 1 第 2 行 ‖ 头 2 第 1 行”（‖ 是拼接，不是异或），两个向量仍然不同。还可以注意到：若这个迷你词表的规范编号只有 0 到 12，那么每个乘积 \(x'\cdot c_i\le12\times5=60<64\)，都是不超过 6 位的二进制数，异或之后仍然小于 64，即任何混合值都落在 \([0,64)\) 里；而 \(7\times11=77>64\)，所以两个不同的混合值不可能在两个头上同时相撞（若同时相撞，差值要被 77 整除，但差值的绝对值小于 64）。后面会把这个观察推广到真实的规模。

为什么表的大小取素数？论文只说“素数大小”，没有解释。笔者的解释：如果表大小有小的因子（比如是偶数），而混合值恰好带有某种规律（比如总是偶数），取模后就只会用到表的一部分行；素数没有这种公共因子。更要紧的一点来自 (17.7) 的结构：同一阶的 8 个头共用同一个混合值，如果两个头的模数相同，它们就完全重复了。所以模数不但要是素数，还必须两两不同。演示代码的做法是：从配置的起始值往上找素数，跳过全模型已经用过的 7。

第四步：拼接成记忆向量

把所有阶、所有头取回的行首尾相接，得到这个位置的记忆向量：

拼接\[\mathbf e_t=\mathop{\Big\|}_{n=2}^{N_{\text{gram}}}\ \mathop{\Big\|}_{k=1}^{K_{\text{hash}}}\ \mathbf e_{t,n,k}\in\R^{d_{\text{mem}}},\qquad d_{\text{mem}}=(N_{\text{gram}}-1)\,K_{\text{hash}}\,d_{\text{head}}\]\(\|\)：向量拼接。原文式 (2)。(17.8)
两个真实配置的维度与参数量

Engram-27B：\(N_{\text{gram}}=3\)，\(K_{\text{hash}}=8\)，\(d_{\text{mem}}=1280\) 3，所以 \(d_{\text{head}}=1280/(2\times8)=80\)。模块放在 2 层，每层 \(2\times8=16\) 张表，共 32 张。表的起始大小是 2,262,400（论文附录表 5 的 “Engram Vocab Size”），按“向上找未用过的素数”的规则，32 个素数之和是 72,404,232 行，参数量

\[72{,}404{,}232\times80=5{,}792{,}338{,}560\approx5.79\text{B}.\]

论文写 5.7B；两者差 1.6%，是截断还是另有口径，论文没说（笔者复算，按演示代码的布局规则）。同法算 Engram-40B（起始大小 7,239,680）得 18.53B，与论文的 18.5B 一致。

V4.1-Flash：2 个模块，阶 {2,3,4}，每阶 8 个头、总维度 2048，所以 \(d_{\text{head}}=256\)、\(d_{\text{mem}}=3\times2048=6144\)；每张表约 1,600 万行 2。粗算 \(2\times3\times8\times1.6\times10^{7}\times256=1.966\times10^{11}\)。精确地，从 16,000,000 往上找 48 个互不相同的素数，两个模块的行数之和分别是 384,006,168 和 384,016,682，与配置文件的 engram_num_embeddings 逐位相同 5，于是

\[(384{,}006{,}168+384{,}016{,}682)\times256=196{,}613{,}849{,}600\approx196.6\text{B}.\]

这就是 V4.1 报告里 “196B Engram parameters” 的来历。

“Engram-27B 有一张 27B 的记忆表”

不对。“27B”是整个模型的总参数（26.7B，含 token 嵌入），其中 Engram 表只有 5.7B；Engram-40B 的表是 18.5B 3。同理，V4.1-Flash 的“552B”是骨干参数，不含 196B 的 Engram，两者合计约 748.6B 2；这还不是全部，投机解码用的 DSpark 起草器与视觉编码器也不在 552B 里（见第 19 课）。

碰撞：几乎必然发生，但很少同时发生两次

问题。 表的行数远少于 N-gram 的个数，碰撞不可避免。那么查到的向量还有意义吗？要回答它，先量化“碰撞有多频繁”。

形式化。 设有 \(U\) 个不同的 N-gram 被均匀地散列进一张 \(p\) 行的表，定义负载（load）\(\lambda=U/p\)，即平均每行分到几个 N-gram。论文没有报告训练语料里有多少个不同的 N-gram，所以下面的 \(U\) 都是假设值。

一个 N-gram 的行被别人占用的概率
(1)\(\displaystyle \Pr[\text{某个别的 N-gram 落在同一行}]=1/p\)均匀散列：它落在 \(p\) 行中每一行的机会相等
(2)\(\displaystyle \Pr[\text{它不落在这一行}]=1-1/p\)取补
(3)\(\displaystyle \Pr[\text{其余 }U-1\text{ 个都不落在这一行}]=(1-1/p)^{U-1}\)把不同 N-gram 的落点当作相互独立
(4)\(\displaystyle (1-1/p)^{U-1}=e^{(U-1)\ln(1-1/p)}\approx e^{-U/p}\)\(p\) 很大时 \(\ln(1-1/p)\approx-1/p\)，且 \(U-1\approx U\)
(5)\(\displaystyle \Pr[\text{这一行被共享}]\approx1-e^{-\lambda}\)再取补，\(\lambda=U/p\)
单个头里的碰撞概率\[\Pr[\text{共享一行}]=1-\Big(1-\frac1p\Big)^{U-1}\approx1-e^{-\lambda},\qquad\lambda=\frac Up\](17.9)
真实表大小下的负载

Engram-27B 的一个 2-gram 头 \(p=2{,}262{,}409\)。若 \(U=10^7\)：\(\lambda=4.42\)，\(1-e^{-4.42}=0.988\)，几乎每个 N-gram 都和别人共享一行；8 个头全都被共享的概率（按独立近似）\(0.988^8=0.908\)。

V4.1-Flash 的表大 7 倍，\(p=16{,}000{,}057\)。同样 \(U=10^7\)：\(\lambda=0.625\)，单头共享概率 \(0.465\)，8 头全共享只有 \(0.465^8=0.0022\)。若 \(U=10^8\)，\(\lambda=6.25\)，单头共享概率又升到 \(0.998\)。

所以“有没有碰撞”不是好问题：负载一上去，每一行都被许多 N-gram 共享。好问题是：两个不同的 N-gram，拿到的 8 行组合会不会一样？ 只要组合不同，拼接出来的 \(\mathbf e_t\) 就不同，后面的网络就有机会区分它们。

对某个特定的“别的 N-gram”，它在头 \(i\) 和头 \(j\) 上同时与我相撞的概率约为 \(1/(p_ip_j)\approx1/p^2\)（把两个头的落点当作近似独立）。8 个头里任选 2 个有 \(\binom82=28\) 种选法，用并集上界（union bound：几个事件“至少发生一个”的概率，不超过各自概率之和）把 28 种情形的概率加起来，再对 \(U\) 个可能的伙伴求和：

在 ≥ 2 个头上同时相撞的期望伙伴数\[\E[\#\text{伙伴}]\approx U\cdot\binom{K_{\text{hash}}}{2}\cdot\frac1{p^2}\]对 \(U\) 个 N-gram 逐个累加“与我在某两个头上同时相撞”的概率。对混合值与我不同的伙伴，下面会证明 3 个头以上同时相撞不可能，所以 28 个“恰好在这两个头上相撞”的事件互不相容，并集上界在这里其实取等号，误差只来自“两个头近似独立”这一近似；混合值与我完全相同的伙伴会 8 个头全撞，但这要求两个落在 \([0,2^{63})\) 里的整数恰好相等，按同样的均匀近似，每个伙伴的概率只有约 \(2^{-63}\approx1.1\times10^{-19}\)，可以忽略。(17.10)

代入 \(K_{\text{hash}}=8\)：即使 \(U=10^{10}\)，Engram-27B 的期望伙伴数也只有 \(10^{10}\times28/2{,}262{,}409^2=0.055\)，V4.1-Flash 只有 \(0.0011\)。对绝大多数 N-gram，8 行的组合是独一无二的。

还有一个更强的结论，来自 (17.7) 的代码结构。它只用到两个事实：同一阶的 8 个头共用一个混合值；每个混合值都落在 \([0,2^{63})\) 里。

互素、整除与中国剩余定理熟悉初等数论的可以跳过

两个整数除了 1 没有别的公因数，就叫互素；两个不同的素数一定互素。下面要用的事实是：若 \(a,b\) 互素且都整除 \(\Delta\)，则 \(ab\) 也整除 \(\Delta\)。 理由：写 \(\Delta=ak\)；\(b\) 整除 \(ak\)，又与 \(a\) 没有公因数，所以 \(b\) 只能整除 \(k\)（欧几里得引理），于是 \(\Delta=ab\cdot(k/b)\)。三个两两互素的数同理，一个一个并进来即可。

中国剩余定理（Chinese remainder theorem）是同一件事的另一面：若 \(p_1,\dots,p_r\) 两两互素、乘积为 \(P\)，那么任意连续 \(P\) 个整数的“余数组” \((x\bmod p_1,\dots,x\bmod p_r)\) 两两不同。小例子：\(p=3,5\) 时，0 到 14 这 15 个数的余数对 \((x\bmod3,\ x\bmod5)\) 没有两个相同的。放到 Engram 里就是：任取 3 个头，它们的 3 个行号在长度为 \(p_ip_jp_l\) 的范围内唯一确定混合值。

两个不同的混合值最多在 2 个头上同时相撞
(1)\(\displaystyle \text{mix}\bmod p_i=\text{mix}'\bmod p_i\iff p_i\mid(\text{mix}-\text{mix}')\)余数相同 ⇔ 差能被模数整除
(2)\(\displaystyle \text{在头 }i,j,l\text{ 同时相撞}\Rightarrow p_i\mid\Delta,\ p_j\mid\Delta,\ p_l\mid\Delta\)记 \(\Delta=\text{mix}-\text{mix}'\)
(3)\(\displaystyle \Rightarrow p_ip_jp_l\mid\Delta\)不同素数两两互素（上面的前置知识）
(4)\(\displaystyle p_ip_jp_l\ge1.158\times10^{19}\)Engram-27B 全模型最小的三个表大小之积 \(2{,}262{,}409\times2{,}262{,}413\times2{,}262{,}437\)，任意三个头都不小于它
(5)\(\displaystyle \abs{\Delta}<2^{63}=9.22\times10^{18}<1.158\times10^{19}\)两个混合值都在 \([0,2^{63})\) 里
(6)\(\displaystyle \Rightarrow\Delta=0,\ \text{即 }\text{mix}=\text{mix}'\)\(p_ip_jp_l\) 的倍数里，绝对值小于 \(p_ip_jp_l\) 的只有 0

所以两个 N-gram 要么混合值完全相同（那样 8 个头全撞，多头也救不了），要么最多只在 2 个头上相撞。V4.1-Flash 的三素数之积约 \(4.10\times10^{21}\)，结论相同。这个推导有一个前提：27B 实验用的哈希代码没有公开，论文只写了“乘法-异或”；上面的结论对开源的演示代码和 V4.1-Flash 的推理代码成立，二者结构相同 7,5。

碰撞在实践中到底有多大害处，第三方做过一个对照实验：给高频 N-gram 换上完全无碰撞的“完美哈希”，在严格等参数的比较下，验证损失并没有稳定地变好，作者认为碰撞可能起了隐式正则化的作用 8。这是一篇未经评审的预印本，本课只读了摘要，只作为方向性的证据。Engram 自己的应对办法是下一页的门控：让模型根据上下文决定要不要相信查到的向量。

Engram（中）：查到的东西信多少

上一页结束时，每个位置 \(t\) 手里有了一个记忆向量 \(\mathbf e_t\in\R^{d_{\text{mem}}}\)。它是按编号查出来的，没有看过上下文，所以可能是错的。这一页回答三件事：模型怎样决定这个向量信多少（上下文门控）；信了之后怎样加回残差流（短卷积与多分支集成）；这个模块放在网络的哪一层。

问题：同一个 N-gram，不同的意思

查表出错有两种来源。第一种是上一页的碰撞：一行里混着许多不相干的 N-gram 的内容。第二种即使没有碰撞也会发生，那就是一词多义。2-gram (the, Great) 出现在 “Alexander the Great”“the Great Wall”“the Great Depression” 里，分别指一位国王、一道城墙、一场经济危机。这张表只有一行留给 (the, Great)，训练会把三种用法的平均写进去。3-gram 更具体，可它的行也可能与别的 3-gram 相撞。

所以模型需要在每个位置做一个判断：这次查到的东西，和我现在读到的上下文对不对得上？ 对得上就多用一点，对不上就少用一点。“现在读到的上下文”已经有现成的载体，就是隐藏状态 \(\mathbf h_t\)：只要前面至少有一层注意力，它就汇总了前文的信息。

类比：翻到那一页之后，先对一下病历

接着上一页的速查手册。映射：病人的病历是隐藏状态 \(\mathbf h_t\)；手册这一页上印着的“适用症状”栏是记忆的键 \(\mathbf k^{\text{mem}}_t\)；“处方”栏是记忆的值 \(\mathbf v^{\text{mem}}_t\)；把病历和适用症状对一对，吻合程度就是两者的点积；按吻合程度决定处方采纳几成，就是门控 \(\alpha_t\)。

收益：它说明了为什么门控要同时看 \(\mathbf h_t\) 和 \(\mathbf e_t\)：只看手册（\(\mathbf e_t\)）不知道这页适不适用，只看病历（\(\mathbf h_t\)）又不知道手册翻到了哪一页。

失效的地方：真医生可以只采纳处方里的某几味药；Engram 的 \(\alpha_t\) 是一个标量，整页处方同乘一个系数。“适用症状”栏也不是人写的，它和处方一样是从同一行 \(\mathbf e_t\) 用两个学出来的矩阵投影出来的。

形式化：记忆的键、值与标量门控

Engram 论文的原话是：把当前隐藏状态 \(\mathbf h_t\) 当作动态的 Query，而检索到的记忆 \(\mathbf e_t\) 同时作为 Key 和 Value 的来源（原文 “serves as the source for both Key and Value projections”）3。先把 \(\mathbf e_t\) 投影成与骨干同维的键和值：

记忆的键与值\[\mathbf k^{\text{mem}}_t=W^K_{\text{mem}}\,\mathbf e_t,\qquad \mathbf v^{\text{mem}}_t=W^V_{\text{mem}}\,\mathbf e_t,\qquad W^K_{\text{mem}},W^V_{\text{mem}}\in\R^{d\times d_{\text{mem}}}\]\(\mathbf k^{\text{mem}}_t,\mathbf v^{\text{mem}}_t\in\R^{d}\)：记忆的键和值，和 \(\mathbf h_t\) 同维。原文式 (3)。Engram-27B：\(d=2560\)，\(d_{\text{mem}}=1280\)，每个矩阵 \(2560\times1280=3{,}276{,}800\) 个权重。(17.11)

再用一个标量决定这个值加多少：

上下文门控（论文式 (4)）\[\alpha_t=\sigma\!\left(\frac{\RMSNorm(\mathbf h_t)^\top\RMSNorm(\mathbf k^{\text{mem}}_t)}{\sqrt d}\right),\qquad \tilde{\mathbf v}_t=\alpha_t\,\mathbf v^{\text{mem}}_t\]\(\alpha_t\in(0,1)\)：门控，一个数；\(\sigma\)：sigmoid；\(\tilde{\mathbf v}_t\in\R^d\)：门控后的记忆值。下文把括号里的缩放点积记作 \(s_t\)。(17.12)
RMSNorm 与 sigmoid熟悉的可以跳过

RMSNorm（第 5 课 §4）把一个向量除以它的均方根：\(\RMSNorm(\mathbf x)=\mathbf x\big/\sqrt{\tfrac1d\sum_i x_i^2+\epsilon}\)，再逐元素乘一个可学习的缩放 \(\boldsymbol\gamma\)。\(\boldsymbol\gamma=\mathbf 1\) 且忽略 \(\epsilon\)（一个防止除零的极小正数）时，输出 \(\mathbf y=\RMSNorm(\mathbf x)\) 的均方根恰好是 1，也就是 \(\sum_i y_i^2=d\)，长度 \(\norm{\mathbf y}=\sqrt d\)。它只改长度、不改方向。

sigmoid \(\sigma(x)=1/(1+e^{-x})\) 把任意实数压进 \((0,1)\)：\(\sigma(0)=0.5\)，\(\sigma(4)=0.982\)，\(\sigma(-4)=0.018\)，而且 \(\sigma(-x)=1-\sigma(x)\)。它是二分类里“是的概率”的标准写法。

这个式子长得很像注意力，但有一处必须不同。注意力给每个查询准备了很多个键，用 softmax 分配权重；这里每个位置只有一个候选（查到的那一个 \(\mathbf e_t\)）。对一个元素做 softmax，结果恒等于 \(e^{s}/e^{s}=1\)，什么也没判断。sigmoid 给出的是一个绝对的“信多少”，不需要和别的候选比较。这是笔者的解读，论文没有专门解释为什么用 sigmoid。

推导：点积为什么除以 \(\sqrt d\)，门控能取到多大

除以 \(\sqrt d\) 的理由和第 1 课 §4 缩放点积注意力里 \(\sqrt{d_k}\) 的理由一样：让训练开始时的点积大小与维度无关，sigmoid 不会一上来就饱和（“\(d\) 个不相关的数相加，方差放大 \(d\) 倍”的一般道理见 M04 §3）。推导要用一个建模假设（笔者的）：训练初期，两个归一化后的向量相互独立，各自的分量零均值、同分布、两两不相关。注意 RMSNorm 把平方和固定成了 \(d\)，所以分量不可能严格独立；下面只用到“不相关”，例如向量的方向在半径为 \(\sqrt d\) 的球面上均匀分布时，它就严格成立。

两个归一化后的随机向量的点积有多大
(1)\(\displaystyle \mathbf a=\RMSNorm(\mathbf h_t),\ \mathbf b=\RMSNorm(\mathbf k^{\text{mem}}_t)\)记号；取 \(\boldsymbol\gamma=\mathbf 1\)
(2)\(\displaystyle \textstyle\sum_i a_i^2=\sum_i b_i^2=d\)RMSNorm 的输出均方根为 1
(3)\(\displaystyle \E[a_i]=\E[b_i]=0,\ \E[a_ia_j]=\E[b_ib_j]=0\ (i\neq j)\)上面的建模假设
(4)\(\displaystyle \E[a_i^2]=\E[b_i^2]=1\)对第 2 行取期望得 \(\sum_i\E[a_i^2]=d\)；\(d\) 个分量同分布，每个分到 1
(5)\(\displaystyle \E[a_ib_i]=\E[a_i]\,\E[b_i]=0\)\(\mathbf a,\mathbf b\) 相互独立，乘积的期望可以拆开
(6)\(\displaystyle \Var(a_ib_i)=\E[a_i^2b_i^2]-0^2=\E[a_i^2]\,\E[b_i^2]=1\)方差 = 平方的期望 − 期望的平方；再按独立拆开
(7)\(\displaystyle \Cov(a_ib_i,\,a_jb_j)=\E[a_ia_j]\,\E[b_ib_j]-0=0\ (i\neq j)\)同样按独立拆开；第 3 行的不相关假设
(8)\(\displaystyle \Var(\mathbf a^\top\mathbf b)=\textstyle\sum_{i=1}^d\Var(a_ib_i)=d\)\(\mathbf a^\top\mathbf b=\sum_i a_ib_i\)，各项两两不相关，方差直接相加
(9)\(\displaystyle \Var\!\big(\mathbf a^\top\mathbf b/\sqrt d\big)=d/d=1\)乘常数 \(c\)，方差乘 \(c^2\)；这里 \(c=1/\sqrt d\)
(10)\(\displaystyle \abs{s_t}\sim1\ \Rightarrow\ \sigma(s_t)\ \text{多在}\ 0.27\ \text{到}\ 0.73\ \text{之间}\)标准差为 1（若 \(s_t\) 近似正态，约 68% 落在 \(\pm1\) 内）；\(\sigma(1)=0.731\)，\(\sigma(-1)=0.269\)

这是“典型”大小。训练之后，\(\mathbf h_t\) 和 \(\mathbf k^{\text{mem}}_t\) 可以对齐或反向，\(s_t\) 能走多远？

门控的取值范围（忽略可学习缩放）
(1)\(\displaystyle \abs{\mathbf a^\top\mathbf b}\le\norm{\mathbf a}\,\norm{\mathbf b}=\sqrt d\cdot\sqrt d=d\)柯西–施瓦茨不等式（M01 §1）；两个长度都是 \(\sqrt d\)
(2)\(\displaystyle \abs{s_t}=\abs{\mathbf a^\top\mathbf b}/\sqrt d\le\sqrt d\)除以 \(\sqrt d\)
(3)\(\displaystyle d=2560:\ \abs{s_t}\le50.60\)Engram-27B
(4)\(\displaystyle \alpha_t\in\big[\sigma(-50.6),\,\sigma(50.6)\big]\approx[10^{-22},\,1-10^{-22}]\)\(\sigma(-50.6)\approx1.1\times10^{-22}\)；\(\mathbf a,\mathbf b\) 同向或反向时取等号

所以按论文的式 (17.12)，门控可以几乎完全关上，也可以几乎完全打开。论文说的“语义对齐”就是这个机制：如果检索到的记忆和当前上下文矛盾，\(\alpha_t\) 趋向零，噪声被压掉（原文 “the gate \(\alpha_t\) tends toward zero, effectively suppressing the noise”）3。

论文与代码的差别：带符号平方根

开源的演示代码在 sigmoid 之前多做了一步：先对 \(s_t\) 取“带符号的平方根” 7。V4.1-Flash 的推理代码也这样做，注释写着这是为了与训练内核一致（原文 “matching the training kernel”）5。论文的式 (4) 没有这一步。

代码里的门控\[\alpha_t=\sigma\!\Big(\sign(s_t)\sqrt{\max(\abs{s_t},\,10^{-6})}\Big)\]\(\sign(s)\)：\(s\) 的正负号。\(10^{-6}\) 的下限让 \(\abs{s_t}<10^{-6}\) 时这一步输出常数 \(10^{-3}\)（带符号）、对 \(s_t\) 的梯度为零，从而避开 \(\sqrt{x}\) 的导数 \(1/(2\sqrt x)\) 在 \(x\to0\) 时趋于无穷（笔者的解读，代码没有注释）。(17.13)
平方根把门控的范围收窄了多少

\(\abs{s_t}\le\sqrt d\) 取平方根后变成 \(\le d^{1/4}\)：

Engram-27B（\(d=2560\)） V4.1-Flash（\(d=5120\)）
\(\abs{s_t}\) 上界 \(\sqrt d\) 50.60 71.55
平方根后上界 \(d^{1/4}\) 7.11 8.46
代码门控 \(\alpha_t\) 的范围 \([0.00081,\ 0.99919]\) \([0.00021,\ 0.99979]\)

逐点比较两种门控（\(\sigma(s)\) 对 \(\sigma(\sign(s)\sqrt{\abs s})\)）：\(s=0.25\) 时 \(0.562\) 对 \(0.622\)；\(s=1\) 时都是 \(0.731\)；\(s=4\) 时 \(0.982\) 对 \(0.881\)；\(s=16\) 时 \(1.000\) 对 \(0.982\)。

为什么要这样改，论文和代码都没有解释。笔者能说的只是它的效果：门控不会因为一个很大的点积就几乎恒等于 1，反向传播时门控对 \(s\) 的梯度不容易消失。以 \(s=4\) 为例，论文门控的梯度是 \(\sigma'(4)=\sigma(4)(1-\sigma(4))=0.018\)；代码门控先取平方根，由链式法则是 \(\sigma'(\sqrt4)\cdot\frac{1}{2\sqrt4}=0.105\times\frac14=0.026\)，约为前者的 1.5 倍；到 \(s=16\)，两者相差约两万倍（练习 12 会逐步算）。读论文时记住式 (17.12)，读代码时记住式 (17.13)，二者不一致是事实，不要自己脑补成同一个。

短卷积：让相邻位置的记忆互相补充

门控之后，Engram-27B 还有一个很轻的步骤：沿序列方向做一次短的因果卷积，再加上它自己 3。

膨胀因果卷积熟悉一维卷积的可以跳过

一维因果卷积（causal convolution）在每个位置 \(t\) 上，把当前和之前若干个位置的输入加权相加：\(y_t=\sum_{j=0}^{w-1}\mathbf w_j\odot\mathbf x_{t-j}\)，\(w\) 叫核宽（kernel size）。“因果”指只看过去、不看未来，所以不会泄露后面的 token。膨胀（dilation）\(\delta\) 让它隔着取：\(y_t=\sum_{j=0}^{w-1}\mathbf w_j\odot\mathbf x_{t-j\delta}\)。逐通道（depthwise）指每个维度有自己的一组权重，维度之间不混合，这里的 \(\odot\) 是逐元素相乘。

短卷积与残差（论文式 (5)）\[Y=\mathrm{SiLU}\big(\mathrm{Conv1D}(\RMSNorm(\tilde V))\big)+\tilde V,\qquad H^{(l)}\leftarrow H^{(l)}+Y\]\(\tilde V\in\R^{T\times d}\)：把 \(T\) 个位置的 \(\tilde{\mathbf v}_t\) 按行堆叠（每行一个 token）；\(\mathrm{Conv1D}\)：核宽 \(w=4\)、膨胀 \(\delta=N_{\text{gram}}\)（Engram-27B 为 3）的逐通道因果卷积；\(\mathrm{SiLU}(x)=x\,\sigma(x)\)；\(H^{(l)}\in\R^{T\times d}\)：第 \(l\) 层的隐藏状态。(17.14)
这个卷积能看多远
(1)\(\displaystyle \{t,\ t-\delta,\ t-2\delta,\ t-3\delta\}\)核宽 \(w=4\) 的膨胀卷积在位置 \(t\) 读取的位置
(2)\(\displaystyle \{t,\ t-3,\ t-6,\ t-9\}\)Engram-27B：\(\delta=N_{\text{gram}}=3\)
(3)\(\displaystyle (w-1)\delta+1=3\times3+1=10\)卷积的跨度：从 \(t-9\) 到 \(t\) 共 10 个位置
(4)\(\displaystyle \mathbf e_{t-9}\leftarrow(x'_{t-11},x'_{t-10},x'_{t-9})\)最早那个位置的记忆本身由一个 3-gram 查出
(5)\(\displaystyle \{t-11,\dots,t\}:\ 12\ \text{个 token}\)3-gram 的跨度与卷积的跨度首尾相接

膨胀取 \(N_{\text{gram}}\) 是有道理的：相邻两个被读取的位置正好相隔一个最长 N-gram 的长度，四段 3-gram 首尾相接、不重叠。论文还说卷积的参数初始化为零，以便训练开始时严格保持恒等映射 3。代进 (17.14)：卷积输出 0，\(\mathrm{SiLU}(0)=0\cdot\sigma(0)=0\)，于是 \(Y=\tilde V\)，一开始 Engram 就只是“门控后的查表值”，卷积从零开始慢慢学。

这个卷积后来被去掉了。论文自己的消融显示去掉它只让损失略差（原文 “only marginally degrades performance”）3；V4.1-Flash 就去掉了它，理由是它的收益抵不上推理系统里多出来的复杂度 2。

多分支集成：一张表、一个值投影、四个键投影

论文说，除非另行注明，它的实验都跑在第 16 课的 mHC 骨干上（原文 “Unless otherwise stated, all experiments utilize this integration”）：残差流被扩成 \(n_{hc}=4\) 条，第 \(m\) 条流在位置 \(t\) 的状态记作 \(\mathbf h^{(m)}_t\in\R^d\) 3。门控应该按哪一条流来算？论文的回答是每条流各算一个：

多分支门控（论文式 (6)）\[\begin{aligned}\alpha^{(m)}_t&=\sigma\!\left(\frac{\RMSNorm(\mathbf h^{(m)}_t)^\top\RMSNorm\big(W^{K,(m)}_{\text{mem}}\mathbf e_t\big)}{\sqrt d}\right),\\ \mathbf u^{(m)}_t&=\alpha^{(m)}_t\cdot W^V_{\text{mem}}\mathbf e_t,\qquad m=1,\dots,n_{hc}\end{aligned}\]一张嵌入表和一个值投影 \(W^V_{\text{mem}}\) 被所有分支共享，每条分支有自己的键投影 \(W^{K,(m)}_{\text{mem}}\)，从而有自己的门控 \(\alpha^{(m)}_t\)；\(\mathbf u^{(m)}_t\) 加回第 \(m\) 条流。(17.15)

共享与不共享的选择有一个工程上的好处：5 个投影矩阵（1 个 \(W^V\) 加 4 个 \(W^{K,(m)}\)）作用在同一个 \(\mathbf e_t\) 上，可以上下拼成一个大矩阵，一次 FP8 矩阵乘法算完（原文 “fused into a single dense FP8 matrix multiplication”）3。

多分支投影的参数与算力

Engram-27B：拼起来的矩阵是 \((5\times2560)\times1280=12{,}800\times1{,}280\)，共 \(16{,}384{,}000\) 个权重。每个 token 每层的乘加 \(2\times16{,}384{,}000=32.8\) M FLOPs（矩阵乘向量，每个权重一次乘一次加），两层共 \(65.5\) M FLOPs。对比激活参数 3.8B 的前向约 \(2\times3.8\times10^9=7.6\) G FLOPs，只占 \(0.86\%\)（笔者推算）。

V4.1-Flash：输入是 3 阶 × 2048 = 6144 维，输出 \(5\times5120=25{,}600\) 维，每个模块 \(6144\times25{,}600=157{,}286{,}400\approx157.3\) M 个权重，两个模块 314.6M，约为 decode 激活参数 16B 的 2.0%。这些投影是否计入官方的“552B 骨干参数”和“16B 激活参数”，报告没有说明（笔者推算，见研究笔记“未能核实”）。

一个副产品：Engram-27B 每个 token 有 4 条分支 × 2 个 Engram 层 = 8 个门控标量。论文画门控热图时只挑了与语义模式最相关的那一个，并说明不是每条分支都有可解释的模式 3。

论文的门控可视化给了一个直观的印象：门控在局部固定搭配的最后一个 token 上打开，例如英文的 “Alexander the Great”“the Milky Way”“By the way”，中文的“四大发明”“张仲景” 3。这正是上一页说的“静态的局部知识”：读到最后一个词时，整个搭配才完整，查表才有意义。

放在哪一层

论文强调 Engram 不是每层都放，放在哪里要同时满足两个互相拉扯的约束 3：

  • 建模希望早。 Engram 的用处是替骨干承担“把局部搭配拼起来”的活，这件事在底层做，所以越早接手，省下的深度越多。
  • 系统希望晚。 下一页会讲到，Engram 的表可以放在主机内存里，边算前面的层边预取；放得越深，前面可以用来掩盖预取延迟的计算越多。

建模这一侧有直接的实验。论文在一个 12 层、总参数 3B（激活 0.56B）的 MoE 上加 1.6B 参数的 Engram，训练 100B token，扫描插入的层号 3：纯 MoE 基线的验证损失是 1.808；只插一个模块时，第 2 层最好（1.770），比第 1 层好，再往深处逐渐变差；同样 1.6B 参数拆成第 2 层与第 6 层两块，达到 1.768。

为什么第 1 层不如第 2 层？论文的解释是：一轮注意力就足以给门控提供“有上下文的” \(\mathbf h_t\)，而第 2 层仍然足够早，能接手骨干底层的局部拼装工作（原文 “one round of attention is already sufficient to provide a meaningfully contextualized \(\mathbf h_t\) for gating”）3。放在第 1 层时，\(\mathbf h_t\) 就是 token 自己的词嵌入，还没看过任何前文，门控无从判断“对不对得上上下文”，只能按 token 自身来开关。

右侧那一列就是论文的组件消融，结论与正文一致：多分支集成、上下文门控、分词器压缩三项最重要；去掉短卷积只差一点；在固定 1.6B 预算下加入 4-gram 略差，论文推测是它稀释了更常见的 2/3-gram 的容量，但不排除表更大时高阶 N-gram 会变得有利 3。V4.1-Flash 用了 {2,3,4} 阶、每个模块约 980 亿参数，正好是“表更大”的情形 2。

两个真实配置的层号需要小心读。Engram 论文写“第 2 层和第 15 层”；V4.1-Flash 的报告写“从 0 计的第 1 层和第 14 层”，配置文件是 engram_layer_ids: [1, 14] 3,2,5。如果论文是从 1 数的（笔者推测），两者指的是同样的位置，即图 17.6 画的第 2、15 层。开源演示代码写的是 layer_ids=[1, 15]，与两者都差一层 7。另外，V4.1-Flash 给出的放置理由与论文不同：它说是为了平衡训练流水线各段的显存 2，不是论文所说的“建模与延迟的折中”。同一个位置，两份文献给了两个理由，不要张冠李戴。

本页要点
  • 门控 \(\alpha_t=\sigma\big(\RMSNorm(\mathbf h_t)^\top\RMSNorm(W^K_{\text{mem}}\mathbf e_t)/\sqrt d\big)\)：隐藏状态当 Query，记忆同时给出 Key 和 Value；只有一个候选，所以用 sigmoid 而不是 softmax。
  • 除以 \(\sqrt d\) 让初始点积的方差为 1；RMSNorm 之后 \(\abs{s_t}\le\sqrt d\)（27B 为 50.6）。开源代码在 sigmoid 前多了带符号平方根（范围变成 \(\le d^{1/4}\)），论文式 (4) 没有。
  • 短卷积（\(w=4\)，\(\delta=N_{\text{gram}}\)，零初始化）把相邻 N-gram 的记忆拼接起来，共覆盖 12 个 token；消融显示它作用很小，V4.1-Flash 去掉了它。
  • 多分支：共享表与 \(W^V_{\text{mem}}\)，每条 mHC 分支一个 \(W^{K,(m)}_{\text{mem}}\)，五个投影融合成一次 FP8 矩阵乘法（27B 每层 16.4M 权重，两层合计约占前向算力的 0.86%）。
  • 位置：建模要早、系统要晚；单模块第 2 层最好，第 1 层因为还没有注意力、门控看不到上下文而稍差。

Engram（下）：记忆该分多少参数

前两页讲了 Engram 是什么。这一页回答两个定量问题：参数总数固定时，该给这张表多少参数？给了之后，模型到底变好在哪里？

问题：一笔固定的“不激活预算”

MoE 模型里本来就有大量不激活的参数：每个 token 只用 \(K_r\) 个路由专家，其余专家的参数这一步没有参与计算。Engram 的表也是这样：Engram-27B 的表有 7,240 万行，每个 token 只读 32 行。两者都是“存着很多、每次只用一点”，于是可以放在同一个账本里比较。

类比：一笔固定的预算，多请医生还是多印手册

接着医院与速查手册的类比。映射：医院的总预算固定（\(N_{\text{tot}}\)），每位病人就诊时能同时占用的人手也固定（\(N_{\text{act}}\)）；剩下那笔“平时闲着、轮到才用”的预算（下面的 \(N_{\text{sparse}}\)），可以拿去多聘几位专科医生（路由专家），也可以拿去把速查手册印得更厚（Engram 表）。\(\rho\) 就是这笔预算里花在医生身上的比例。

收益：U 形曲线的两端都说得通。全聘医生（\(\rho=1\)）时，连常见病也要医生从头诊断一遍；全印手册（\(\rho\to0\)）时，疑难杂症没人会看。最好的分法在中间。

失效的地方：真医院里医生和手册的价钱由市场定；这里两者按参数个数一比一折算，一个专家权重和一个表格数字被当作同价，尽管前者每次被选中都要做矩阵乘法，后者只是被读出来。另外，“哪些病查手册、哪些病找医生”不是人分配的，是训练中自己分出来的。

稀疏参数预算与分配比 ρ

含义。 总参数减去激活参数，剩下的就是“不花计算、只花存储”的预算；\(\rho\) 是这笔预算里分给 MoE 专家的比例，其余给 Engram。

理解。 固定 \(N_{\text{tot}}\) 和 \(N_{\text{act}}\)，就是固定了模型的存储规模和每 token 的计算量。唯一能动的是这笔预算的分法：\(\rho=1\) 是纯 MoE，\(\rho=0\) 是把所有不激活参数都给 Engram。

数学。 论文的定义（论文记号 \(P\)，本课写 \(N\)）3：

稀疏预算与分配比（论文式 (7)）\[\begin{aligned}N_{\text{sparse}}&\triangleq N_{\text{tot}}-N_{\text{act}},\\ N^{\text{(sparse)}}_{\text{MoE}}&=\rho\,N_{\text{sparse}},\qquad N_{\text{Engram}}=(1-\rho)\,N_{\text{sparse}},\qquad\rho\in[0,1]\end{aligned}\]\(N_{\text{tot}}\) 不含词嵌入与输出头；\(N_{\text{act}}\)：每个 token 实际参与计算的参数；\(N^{\text{(sparse)}}_{\text{MoE}}\)：没被选中的路由专家的参数。ACL 版把 \(N_{\text{sparse}}\) 记作 \(P_{\text{free}}\) 4。(17.16)
从专家个数读出 ρ
(1)\(\displaystyle N^{\text{(sparse)}}_{\text{MoE}}=(N_r-K_r)\,L_{\text{MoE}}\,N_{\text{exp}}\)\(N_r\) 个路由专家激活 \(K_r\) 个，每层不激活 \(N_r-K_r\) 个；\(L_{\text{MoE}}\) 个 MoE 层，每个专家 \(N_{\text{exp}}\) 个参数
(2)\(\displaystyle N_r=72,\ K_r=6\Rightarrow N_{\text{sparse}}=66\,L_{\text{MoE}}N_{\text{exp}}\)MoE-27B：纯 MoE，\(\rho=1\)，整笔预算都是专家
(3)\(\displaystyle N_r=55\Rightarrow N^{\text{(sparse)}}_{\text{MoE}}=49\,L_{\text{MoE}}N_{\text{exp}}\)Engram-27B：拿掉 17 个专家，空出来的参数给 Engram
(4)\(\displaystyle \rho=49/66=0.742\)两个模型等总参数、等激活参数，所以 \(N_{\text{sparse}}\) 相同；若 Engram 恰好等于拿掉的参数，\(L_{\text{MoE}}N_{\text{exp}}\) 约掉
用真实参数核对 74.3%

论文没给专家的中间维。DeepSeek-VL2 的 27B 语言模型与 MoE-27B 规格一致（30 层、隐藏维 2560、72 路由 + 2 共享、top-6），它的配置给出专家中间维 1536 9；用它推算（笔者推断，论文未证实两者是同一骨干）：每个 SwiGLU 专家 \(3\times2560\times1536=11{,}796{,}480\) 个参数，首层稠密，所以有 29 个 MoE 层。

  • 留下的不激活专家：\(49\times29\times11{,}796{,}480=16{,}762{,}798{,}080\)。
  • Engram 表（§2 的素数布局）：\(5{,}792{,}338{,}560\)。
  • \(\rho=16.763/(16.763+5.792)=0.7432\)，与论文的 \(\rho=74.3\%\) 一致 3。

反过来，论文说 \(\rho\approx40\%\) 时 5.7B 模型剩 46 个专家、9.9B 模型剩 43 个，而这两个模型的纯 MoE 基线分别有 106 与 99 个路由专家 3。设它们每 token 也激活 6 个（笔者推断，论文没写），激活的 6 个不在预算里，不激活的份额按 \(\rho\) 缩：\(6+0.4\times(106-6)=46\)，\(6+0.4\times(99-6)=43.2\)，吻合。

“最优是把 75%–80% 的参数给 Engram”

反了。\(\rho\) 是给 MoE 的份额。论文的结论是把不激活预算的 20%–25% 给 Engram（原文 “reallocating roughly 20%–25% of the sparse parameter budget to Engram yields the best performance”）3。而且这是不激活预算的比例，不是总参数的比例。

U 形曲线：纯 MoE 不是最优

论文在两个算力点上扫描 \(\rho\)，两点都保持 \(N_{\text{tot}}/N_{\text{act}}\approx10\)：\(C=2\times10^{20}\) FLOPs 时总参数约 5.7B、激活 568M；\(C=6\times10^{20}\) 时约 9.9B、激活 993M 3。结果是一条 U 形曲线（图 17.7a）：

  • 右端（纯 MoE）不是最优。 在 \(6\times10^{20}\) 处，验证损失从 \(\rho=100\%\) 的 1.7248 降到 \(\rho\approx80\%\) 附近的 1.7109，\(\Delta=0.0139\) 3。
  • 左端也不好。 把太多预算给表，模型失去条件计算的容量。论文的解释是：记忆替代不了计算，需要动态推理的任务会受损。这是作者的解释，不是证明。
  • 曲线很平。 \(\rho\approx40\%\)（只剩 46 或 43 个专家）时仍与纯 MoE 持平。

最优点到底在哪？论文说“\(\rho\approx75\%\)–\(80\%\)，且两个算力点一致”。从图上读出的点看，两个算力点的最低观测点其实都在 \(\rho\approx85\%\)；用二次函数拟合，顶点在 0.72–0.74。

二次拟合的顶点
(1)\(\displaystyle \mathcal L(\rho)\approx a\rho^2+b\rho+c\)\(\mathcal L\) 是验证损失；最小二乘拟合读出的 10 个点（笔者的选择：U 形最简单的模型）
(2)\(\displaystyle \dfrac{d\mathcal L}{d\rho}=2a\rho+b=0\)极值点处导数为零
(3)\(\displaystyle \rho^\star=-\dfrac{b}{2a}\)\(a>0\) 时是最小值
(4)\(\displaystyle 6\times10^{20}:\ a=0.13496,\ b=-0.19913\Rightarrow\rho^\star=0.738\)numpy.polyfit 的系数；\(0.19913/0.26992=0.738\)
(5)\(\displaystyle 2\times10^{20}:\ a=0.11978,\ b=-0.17346\Rightarrow\rho^\star=0.724\)同法；\(0.17346/0.23956=0.724\)

所以稳妥的说法是：最优点在 70%–85% 一带，纯 MoE 明显更差；精确位置不稳，而且只在两个算力点、一种稀疏度下测过（论文自己加了限定 “under fixed sparsity”）3。“U 形 scaling law”是两条经验曲线，不是像第 2 课 Chinchilla 那样在许多个模型规模上拟合出的规律。

“无限内存”：只加大表会怎样

另一个实验不再固定总参数：骨干固定为 3B 总参数、568M 激活的 MoE，训练 100B token，只把 Engram 的槽数从 \(2.58\times10^5\) 加到 \(1.0\times10^7\)（最多约 13B 参数）3。槽（slot）是论文对表行数的叫法：每个槽对应一个 \(d_{\text{mem}}=1280\) 维的记忆条目（每张 \((n,k)\) 表各出一行、拼起来的那一份），所以参数量约为槽数 × 1280，\(1.0\times10^7\) 槽就是 12.8B（笔者由论文的 “up to ≈13 billion” 反推，见研究笔记 §4.2）。每个 token 读的行数不变，所以计算量不变。图 17.7b 的点排成一条直线：横轴是对数，纵轴是线性。

损失随槽数的经验关系\[\mathcal L(S)\approx\mathcal L_0-\beta\,\log_{10}S,\qquad \beta\approx0.0284\]\(\mathcal L\)：验证损失；\(S\)：槽数；\(\mathcal L_0\)：拟合的截距；\(\beta\)：槽数每增加 10 倍损失的下降量（笔者对图 3 读出的 8 个点做最小二乘拟合）。(17.17)

论文正文把这条线称为“严格的幂律（在对数空间里是直线）”（原文 “strict power law (linear in log-space)”），图的标题却写“对数线性趋势”，ACL 版改成“近似对数线性” 3,4。二者不是一回事：

对数线性与幂律，在窄范围内分不出来
(1)\(\displaystyle \text{幂律：}\mathcal L=A\,S^{-\kappa}\iff\ln\mathcal L=\ln A-\kappa\ln S\)\(\ln\mathcal L\) 对 \(\ln S\) 是直线（\(A>0\)，指数 \(\kappa\) 是常数）
(2)\(\displaystyle \text{对数线性：}\mathcal L=\mathcal L_0-\beta'\ln S\)\(\mathcal L\) 本身对 \(\ln S\) 是直线；\(\log_{10}S=\ln S/\ln10\)，所以 \(\beta'=\beta/\ln10\)
(3)\(\displaystyle \ln\mathcal L=\ln\mathcal L_0+\ln\!\big(1-\tfrac{\beta'}{\mathcal L_0}\ln S\big)\)提出 \(\mathcal L_0\)；这不是 \(\ln S\) 的一次函数，所以严格说不是幂律
(4)\(\displaystyle \dfrac{d\ln\mathcal L}{d\ln S}=\dfrac{1}{\mathcal L}\dfrac{d\mathcal L}{d\ln S}=-\dfrac{\beta'}{\mathcal L}\)链式法则；幂律时这个斜率恒等于 \(-\kappa\)，这里却随 \(\mathcal L\) 变
(5)\(\displaystyle \beta'=0.0284/2.303=0.0123\)把 (17.17) 的 \(\beta\) 换成自然对数的斜率，\(\ln10=2.303\)
(6)\(\displaystyle -\beta'/\mathcal L\approx-0.0123/1.765\approx-0.0070\)取图中范围的中间值 \(\mathcal L\approx1.765\)；\(\mathcal L\) 只从 1.788 变到 1.743，所以这个“等效指数”几乎是常数

在损失只变 0.045 的窄范围里，对数线性曲线看起来就像一条指数只有 0.007 的幂律（直接拟合双对数斜率是 \(-0.00698\)）。两种说法都能描述数据，但外推到更大的表时会给出不同的预测，这是一个不该忽略的措辞差别。

读一读这条线

从最左的点（\(2.586\times10^5\) 槽，0.33B 参数，损失 1.7883）到最右的点（\(1.034\times10^7\) 槽，13.2B 参数，损失 1.7432）：槽数增加 40 倍，即 \(\log_{10}40=1.60\) 个十倍，(17.17) 预测下降 \(1.60\times0.0284=0.045\)，实际 \(1.7883-1.7432=0.0451\)。纯 MoE 骨干是 1.8082，所以最小的表也已经降了 0.020。同样槽数下，对照方法 OverEncoding（在输入层把 N-gram 嵌入与词嵌入取平均，原文 “integrates \(N\)-gram embeddings via averaging with the vocabulary embedding”）始终在 Engram 之上（更差）3。

27B 规模：四个模型，同样的激活参数

主实验训练了四个模型，全部 262B token、激活参数都是 3.8B 3：

结果（图 17.9a）：Engram-27B 在表 1 的全部 27 项基准上都不低于 MoE-27B 3。论文特别指出，提升不只在知识类（MMLU +3.0、CMMLU +4.0），推理类更大（BBH +5.0、ARC-Challenge +3.7），代码和数学也有（HumanEval +3.0、GSM8K +2.2、MATH +2.4）。反过来，最像“查事实”的 TriviaQA 只有 +1.9、PopQA 只有 +0.2。

摘要里的 “MMLU +3.4” 与表对不上

论文摘要和引言写 MMLU +3.4，§4.2 写 +3.0。表 1 的 MMLU 是 57.4 → 60.4，即 +3.0；+3.4 是 MMLU-Redux（60.6 → 64.0）3。ACL 版同样如此 4。引用时请写“MMLU +3.0”或“MMLU-Redux +3.4”。另外，Engram-40B 并没有处处胜过 Engram-27B：C3、HumanEval、MBPP、MATH 四项更低，MBPP 甚至低于 MoE-27B；作者认为是训练不足（训练末期损失差距仍在扩大），这是推测 3。

为什么查表能帮推理？论文给的解释是“等效深度”：Engram 在底层直接交出局部搭配，骨干就不必花前几层去拼装。用 LogitLens（把中间层直接接到输出头上看预测）和 CKA（比较两个模型各层表示的相似度）去看，Engram-27B 第 5 层的表示与 MoE-27B 约第 12 层最相似（原文 “layer 5 of Engram-27B align most closely with those at approximately layer 12 of the MoE baseline”）3。论文据此说 Engram 在功能上等价于加深网络。这是对表示相似度的解读，不是定理：实测的只是相似度矩阵的对角线往上移了。

图 17.9b 从另一个角度支持“表里存的是事实性知识”：推理时把 Engram 关掉，事实类基准只剩 29%–44%，阅读理解保留 81%–93% 3。但作者自己提醒，这是事后消融，会引入训练与推理的不一致；它不能读成“有 56%–71% 的知识存在 Engram 里”。

最后是长上下文。论文把 Engram-27B 与 MoE-27B 都用 YaRN（第 10 课 §6）扩到 32K，发现长上下文能力与基座的整体损失高度耦合，所以比较架构要对齐基座损失而不是对齐训练步数 3。在损失对齐的比较下（Engram-27B 训练 46k 步 vs MoE-27B 训练 50k 步），多查询“大海捞针”从 84.2 升到 97.0，变量追踪从 77.0 升到 87.2（等步数的比较是 89.0，引用时要写明是哪一行）。论文的解释是局部搭配交给查表之后，注意力有更多容量处理全局上下文。注意这仍然不是“省 KV cache”：KV 一个字节都没少。

本页要点
  • \(N_{\text{sparse}}=N_{\text{tot}}-N_{\text{act}}\)，\(\rho\) 是其中给 MoE 专家的份额。Engram-27B 把 72 个专家减到 55 个：按专家数 \(\rho=49/66\approx74.2\%\)，按参数精确算是 \(74.3\%\)。
  • U 形曲线：纯 MoE 不是最优，最优在 \(\rho\approx70\%\)–85%（论文说 75%–80%），只在两个算力点、固定稀疏度下测过。
  • 只加大表时，损失对 \(\log S\) 近似直线（每十倍约 −0.028）；论文称“严格幂律”不准确，是对数线性。
  • Engram-27B 在 27 项基准上全部不低于等参数的 MoE-27B，推理类提升比知识类更大；摘要的 “MMLU +3.4” 实为 MMLU-Redux。
  • 关掉 Engram 时事实类性能跌到 29%–44%；“等效加深网络”是对表示相似度的解读。长上下文收益要在对齐基座损失后比较。

Engram 论文标题里的 “Scalable Lookup”（可扩展的查表）有两层意思：表可以做得很大，而且大了也不贵。前一页讲了“做大有用”；这一页讲“做大不贵”靠的是什么，以及 DeepSeek 怎样把它放进 V4.1-Flash。

问题：一张 200 GB 的表放在哪里

先算 V4.1-Flash 的表有多大。它的表按 FP8 存储：每个数 1 字节，每 32 维再配 1 字节的缩放因子 5。

FP8 与块缩放读过第 12 课或 M08 的可以跳过

FP8 是 8 位（1 字节）的浮点格式，能表示的数值很粗。为了不损失太多精度，把一段相邻的数（这里是 32 个）共用一个缩放因子：先除以它，让这段数落进 FP8 最精细的区间，用时再乘回来。V4.1 的缩放因子是 UE8M0 格式（只有 8 位指数、没有尾数，所以只能是 2 的整数次幂），也占 1 字节。于是一行 256 维占 \(256+256/32=264\) 字节。详见第 12 课 §2–§3、M08 §6–§7。

V4.1-Flash 的 Engram 表有多大

行数：两个模块 \(384{,}006{,}168+384{,}016{,}682=768{,}022{,}850\) 行（§2 从配置复算）。存储：

\[768{,}022{,}850\times264\ \text{字节}=2.028\times10^{11}\ \text{字节}\approx202.8\ \text{GB}\ (188.8\ \text{GiB}).\]

若用 BF16（每数 2 字节）则是 393.2 GB。换个参照：V4.1-Flash 的全局 KV cache 是 890 字节/token，202.8 GB 相当于约 2.28 亿个 token 的 KV 2（笔者换算）。

这么大的一张表如果放在 GPU 显存（HBM）里，就要占掉大量本来可以留给 KV cache 和批处理的空间。主机内存（host DRAM，CPU 那一侧的内存）容量大得多、每字节便宜得多，但离 GPU 远：数据要经过 PCIe 或网络（RDMA）才能送到 GPU，一次搬运要等。问题变成：能不能在 GPU 需要这些行之前，就把它们搬过来？

为什么 Engram 能预取而 MoE 专家不能

关键在于“取哪几行”由什么决定。对比 Engram 的行号和 MoE 的专家选择：

行号只依赖 token 编号；专家选择依赖隐藏状态\[z_{t,n,k}=\varphi_{n,k}\big(\mathcal P(x_{t-n+1}),\dots,\mathcal P(x_t)\big),\qquad \mathcal S^{(l)}_t=\TopK\big(\{s_{i,t}(\mathbf h^{(l)}_t)\}_{i=1}^{N_r},\ K_r\big)\]左：第 \((n,k)\) 张表的行号，是 token 编号的确定函数；右：第 \(l\) 层为 token \(t\) 选出的专家集合，依赖第 \(l\) 层的隐藏状态 \(\mathbf h^{(l)}_t\)。(17.18)

左边在 token 进入模型的那一刻就能算出来，右边必须等前 \(l-1\) 层都算完。论文的原话：因为记忆的索引在前向传播之前就已知，系统可以经 PCIe 从充裕的主机内存里异步取回嵌入；为了掩盖通信延迟，Engram 被放在特定的层，用前面各层的计算当缓冲 3。这就是 §3 说的“系统希望晚”：放在第 2 层，预取只能藏在第 1 层的计算后面；放得更深，能藏的时间更长。

每个 token 搬多少字节

预取的代价是搬运量。每个 token 在每个 Engram 层、每个阶、每个头上各取一行：

每 token 的取数量\[B_{\text{token}}=L_{\text{E}}\cdot(N_{\text{gram}}-1)\cdot K_{\text{hash}}\cdot b_{\text{row}}\]\(L_{\text{E}}\)：Engram 层数；\(N_{\text{gram}}-1\)：阶的个数；\(K_{\text{hash}}\)：每阶头数；\(b_{\text{row}}\)：每行字节数。式中没有表的行数 \(p\)。(17.19)
取数量与表的大小无关
  • V4.1-Flash：\(2\times3\times8=48\) 行，\(48\times264=12{,}672\) 字节/token。
  • Engram-27B 的配置（若按 BF16 取数，假设）：\(2\times2\times8=32\) 行 × 80 维 × 2 字节 \(=5{,}120\) 字节/token。
  • Engram-40B 的表是 Engram-27B 的 3 倍多（18.5B 对 5.7B），每个 token 取的仍然是 32 行。

论文的说法是：每步的有效通信量随被激活的槽数增长，而不是随整张表的大小增长（原文 “scales with the number of activated slots rather than the total embedding table size”）3。按论文表 4 中 Dense-4B 的吞吐 9,031.62 token/s 粗算，V4.1 式的取数约 114 MB/s，27B 式的约 46 MB/s（示意；论文没给测试平台的 PCIe 带宽，也没给 100B 卸载实验中 Engram 的阶数与维度，所以这不是该实验的真实流量）。

预取藏不住时会怎样

预取之所以“几乎免费”，是因为搬运和前面几层的计算同时进行。前提是一次前向要搬的字节，必须在 Engram 之前那几层算完之前到齐（笔者写成的不等式，论文没有给出）：

\[\frac{n_{\text{step}}\cdot B_{\text{token}}}{W_{\text{link}}}\ \le\ t_{\text{hide}}.\]

\(n_{\text{step}}\)：这一次前向处理的 token 数（decode 时约等于并发请求数，prefill 时是这批提示的总长度）；\(W_{\text{link}}\)：主机到 GPU 的有效带宽（字节/秒）；\(t_{\text{hide}}\)：Engram 之前那几层的计算时间。左边是“要搬多久”，右边是“能藏多久”。

一次前向要搬多少

按 V4.1 的配置（\(B_{\text{token}}=12{,}672\) 字节）：

  • decode 一步、512 个并发请求（论文吞吐实验的序列数）：\(512\times12{,}672=6.49\times10^{6}\) 字节，约 6.5 MB。
  • prefill 一条 10 万 token 的提示：\(10^{5}\times12{,}672=1.27\times10^{9}\) 字节，约 1.27 GB，是前者的 \(10^5/512\approx195\) 倍。

prefill 时右边的 \(t_{\text{hide}}\) 也大致随 token 数成比例变长（第 1 个块要算的 token 同样多了约 195 倍），两边一起涨。decode 时情况不同：第 4 课讲过，小批量的 decode 受读权重的带宽限制，第 1 个块的耗时几乎不随并发数增长，所以并发数越大，左边越容易追上右边（笔者推算）。

失败模式：不等式不成立时，GPU 算完前面的层就只能停下来等行向量到齐（stall），吞吐随之下降，下降多少取决于差了多少。能让它重新成立的办法，本课都已见过：把 Engram 放得更深（\(t_{\text{hide}}\) 变大，即 §3 说的“系统希望晚”）；把常用的行缓存在 HBM 里（论文设想的多级缓存，让 \(W_{\text{link}}\) 等效变大）；或者干脆把整张表放在 GPU 上，V4.1 在 RL 采样时就是这样做的（见本页最后一节）。

实测：100B 参数的表整个放在主机内存

论文做了一个极端的实验：在第 2 个 Transformer 块里插入一个 100B 参数的 Engram 层，整张表放在主机 DRAM 里，推理时异步预取，与第 1 个块的计算重叠 3。结果见图 17.10 右下：Dense-4B 的吞吐从 9,031.62 降到 8,858.28 token/s（−1.92%），Dense-8B 从 6,315.52 降到 6,140.02（−2.78%），论文称最大损失只有 2.8% 3，ACL 版补写了 4B 的 1.9% 4。

这个 “<3%” 要连同条件一起记。它是在 nano-vLLM 改的原型上、H800 上、稠密的 4B/8B 骨干上测的，512 条序列、长度在 100 到 1024 之间均匀分布，所有取数都走 PCIe 3。论文没有在 MoE 骨干上测。论文还设想了一个多级缓存：N-gram 的访问频率服从 Zipf 分布（少数搭配极常见，大量搭配很少出现），常用的行放 HBM 或 DRAM，长尾放 NVMe SSD；但论文明说它的实验强制所有取数都经 PCIe 从主机内存走，多级缓存没有实测 3。

训练时则是另一套办法：表按行切分到多张 GPU 上（标准的模型并行），前向时用 All-to-All 通信收集被用到的行，反向时把梯度发回去 3。这和 MoE 专家并行分发 token 用的是同一种通信（第 12 课 §7）。

动量、Nesterov 与 Muon读过 M07 的可以跳过

动量把过去各步的梯度按指数衰减累加起来，用累加值代替单步梯度，更新方向因此更平稳（M07 §3）。Nesterov 是动量的一个变体：决定这一步走多远时，先“按惯性再往前看一步”。Muon 是 V4 用在大多数权重矩阵上的优化器：先做动量，再把整个更新矩阵“正交化”（M07 §7，第 18 课）。这里只需要记住一点：Muon 和下面的更新都只存一个动量缓冲，不像 Adam 那样再存一份二阶矩。

把一张嵌入表记作 \(W\in\R^{m\times n}\)：\(m\) 行对应表的行（约 1,600 万），\(n\) 列是每行的维度（注意这里的 \(n\) 是列数，不是 N-gram 的阶）。一步更新分四个动作：

V4.1 嵌入表的一步更新（报告算法 1，记号按本课改写）
(1)\(\displaystyle M_t=\mu M_{t-1}+(1-\mu)\,G_t\)动量：\(G_t\in\R^{m\times n}\) 是这一步的梯度，\(\mu\) 是动量系数，\(M_t\) 按指数衰减累加过去的梯度
(2)\(\displaystyle \widehat G_t=\mu M_t+(1-\mu)\,G_t\)Nesterov 式的“再往前看一步”：用新的动量再混一次当前梯度
(3)\(\displaystyle \norm{\widehat G_{t,i,:}}_2\le\tau\,\bar g\ \Rightarrow\ \widehat G_{t,i,:}\leftarrow\mathbf 0\)\(\bar g\)：所有行 \(\ell_2\) 范数的平均；范数不超过它 \(\tau\) 倍的行置零，这一行这一步不更新
(4)\(\displaystyle U^{(0)}=\widehat G_t\)交替归一化的起点
(5)\(\displaystyle U^{(k)}_{i,:}=U^{(k-1)}_{i,:}\big/\big(\norm{U^{(k-1)}_{i,:}}_2+\varepsilon\big)\)\(k\) 为奇数：每一行除以自己的 \(\ell_2\) 范数；\(\varepsilon\) 防止除以零
(6)\(\displaystyle U^{(k)}_{:,j}=U^{(k-1)}_{:,j}\big/\big(\norm{U^{(k-1)}_{:,j}}_2+\varepsilon\big)\)\(k\) 为偶数：每一列除以自己的 \(\ell_2\) 范数；\(k=1,2,\dots,K_{\text{sk}}\) 交替进行
(7)\(\displaystyle \Delta_t=\sqrt n\,U^{(K_{\text{sk}})}\)乘 \(\sqrt n\) 调整整体尺度（为什么是 \(\sqrt n\)，见 (17.20) 后的说明）
(8)\(\displaystyle W\leftarrow W-\gamma\,\eta_t\,\Delta_t\)\(\eta_t\)：学习率；\(\gamma\)：与 Muon 相同的缩放常数

四个动作合起来，得到的更新量有一个简洁的描述 2：

V4.1 的 Sinkhorn 平衡更新\[\Delta_t=\sqrt n\,U^{(K_{\text{sk}})}=\sqrt n\,D_r\,\widehat G_t\,D_c,\qquad \frac1n\sum_{j=1}^{n}(\Delta_t)_{ij}^2\approx1,\qquad \frac1m\sum_{i=1}^{m}(\Delta_t)_{ij}^2\approx1\]\(U^{(K_{\text{sk}})}\)：交替归一化 \(K_{\text{sk}}\) 步之后的矩阵（与 §2 的 N-gram 个数 \(U\) 无关）；\(D_r,D_c\)：这些步骤累积成的行、列对角缩放（每一步都只是把某些行或列乘一个数）；两个约束的意思是更新的每一行、每一列的均方根都约为 1。\(K_{\text{sk}}=11\)、\(\tau=10^{-3}\)、\(\varepsilon=10^{-20}\)，动量系数 \(\mu\) 与缩放常数 \(\gamma\) 同 Muon（0.95 与 0.18）2。(17.20)

为什么行和列能同时约为 1（笔者的推导；忽略 \(\varepsilon\)，并先假设没有行被阈值置零）：\(K_{\text{sk}}=11\) 是奇数，最后一步按行归一，所以每一行恰好是单位长度，乘 \(\sqrt n\) 后每行的平方和是 \(n\)，除以 \(n\) 个元素，行均方根恰好是 1；此时全矩阵的平方和是 \(m\cdot n\)。倒数第二步（列）刚把各列拉成等长，最后这一步按行归一只把它们扰动一点，于是每列分到约 \(mn/n=m\)，除以 \(m\) 个元素，列均方根约为 1。“约”字就来自这一点扰动。被阈值置零的行在以后每一步都保持为零（\(0/(0+\varepsilon)=0\)），它们的行均方根是 0 而不是 1；若这样的行占比为 \(f\)，全矩阵的平方和只剩 \((1-f)mn\)，列均方根就约为 \(\sqrt{1-f}\)（笔者用随机矩阵模拟过：\(f=25\%\) 时列均方根 0.864，\(\sqrt{0.75}=0.866\)）。所以 (17.20) 里的列约束，要在被置零的行很少时才成立。

两步看懂交替归一化

取 \(m=n=2\)，\(\widehat G=\begin{pmatrix}3&4\\0.6&0.8\end{pmatrix}\)：第一行的梯度是第二行的 5 倍（例如一个常见 N-gram 的行和一个罕见 N-gram 的行）。

  • 第 1 步（行）：第一行除以 \(\sqrt{9+16}=5\)，第二行除以 \(\sqrt{0.36+0.64}=1\)，两行都变成 \((0.6,\ 0.8)\)。
  • 第 2 步（列）：第一列 \((0.6,0.6)\) 除以 \(0.849\)，第二列 \((0.8,0.8)\) 除以 \(1.131\)，四个数都变成 \(0.7071\)。
  • 此后行、列都已归一，继续迭代不再变化。乘以 \(\sqrt n=\sqrt2\)：\(\Delta=\begin{pmatrix}1&1\\1&1\end{pmatrix}\)，每行、每列的均方根都是 1。

两行原本相差 5 倍的更新幅度被拉平了。这与第 16 课的 Sinkhorn–Knopp 同名但用途不同：那里是把残差混合矩阵投影成双随机矩阵，这里是把更新量的行、列尺度拉平（M11 §7 把两者并排对照）。至于为什么这样更新比 Adam 更适合嵌入表，报告只说它像 Muon 一样只需要一个动量缓冲、而且实测优于 Adam 2，没有给出机制上的解释。

最后，V4.1 的报告没有给出“去掉 Engram”的消融，所以 Engram 在 V4.1-Flash 里具体贡献了多少，目前无法从公开材料量化。

本页要点
  • Engram 的行号只由 token 编号决定，前向开始前就能算出，所以表可以放在主机内存里、边算前面的层边预取；MoE 的专家选择依赖该层隐藏状态，做不到。
  • 每 token 取数 \(B_{\text{token}}=L_{\text{E}}(N_{\text{gram}}-1)K_{\text{hash}}b_{\text{row}}\)，与表的大小无关（V4.1：12,672 字节）。
  • 100B 参数的表整个放主机内存，稠密 4B/8B 骨干的吞吐只降 1.9%/2.8%；多级缓存是设想，MoE 骨干没有测。
  • V4.1-Flash：196B Engram（202.8 GB，FP8），{2,3,4}-gram，去掉卷积，第 1、14 层（从 0 计），RDMA 预取；嵌入表用“动量 + Sinkhorn 平衡”代替 Adam 以省下优化器状态。

DeepSeek-OCR：一页文字值多少视觉 token

现在换到本课的另一半：上下文记忆。§1 留下的问题是，旧的上下文能不能用更低的“分辨率”保存。DeepSeek-OCR（arXiv 2025-10-21）把这个问题落到一个可以测量的实验上：把一页文字拍成图片，最少要多少个视觉 token，模型才能把原文逐字读回来？ 论文开宗明义说，它是对“用光学二维映射压缩长上下文”可行性的一次初步探索（原文 “an initial investigation into the feasibility of compressing long contexts via optical 2D mapping”）6。

问题：文本 token 与视觉 token 的汇率

一页 A4 文档，分词后常在一千个文本 token 上下（下一页 Fox 实验挑的就是 600–1300 个 token 的页面）；放进上下文，就是一千个左右的 KV 条目。同一页拍成图片交给视觉语言模型，图片被切成小块、编码成若干个视觉 token（vision token），每个视觉 token 在语言模型里同样占一个位置、一份 KV。如果视觉 token 比文本 token 少，这页文字就被“压缩”了。

光学压缩比\[r=\frac{n_t}{n_v},\qquad f_{\text{dec}}:\ \R^{n_v\times d_{\text{latent}}}\to\R^{n_t\times d_{\text{text}}},\quad n_v\le n_t\]\(n_t\)：这页原文（标准答案）的文本 token 数；\(n_v\)：模型用的视觉 token 数；\(r\)：压缩比。右式是论文式 (2) 的解码器：把 \(n_v\) 个视觉潜向量（每个 \(d_{\text{latent}}\) 维，DeepSeek-OCR 投影后是 1280 维）还原成 \(n_t\) 个文本 token（每个用 \(d_{\text{text}}\) 维表示）6,10。(17.21)
类比：把旧纪要拍成缩微照片

沿用第 4 课的“会议纪要本”。映射：每个文本 token 是纪要本上逐字记下的一条；把旧的几页纪要拍成一张照片、贴回本子里，就是换成视觉 token；照片占的格子数就是 \(n_v\)；一格照片里装下几条纪要，就是压缩比 \(r\)；解码器是一位能看照片把原文念出来的秘书。

收益：它说明了为什么这件事可能成立：一张照片的一个“格子”可以同时拍下好几个字，而纪要本上一格只能写一个 token。

失效的地方：秘书能把照片念出来，不等于后来的人能直接看着照片开会。DeepSeek-OCR 测的只是前者（OCR 精度）；语言模型能不能在视觉 token 上直接做推理、检索，是另一个没被这篇论文证明的问题（§7）。另外，照片越小越模糊，念错的字就越多。

DeepEncoder：先看局部，再压缩，再看全局

编码器要同时满足三件互相矛盾的事：输入分辨率要高（否则小字看不清），输出 token 要少（否则谈不上压缩），中间的激活显存要可控（否则高分辨率跑不动）。

视觉 Transformer：切块、窗口注意力与全局注意力熟悉 ViT 的可以跳过

视觉 Transformer（ViT）把一张图当成一串 token：先把图切成 \(P\times P\) 像素的小块（patch），每块拉平后线性投影成一个向量，一块就是一个 token。边长 \(R\) 的方图切出 \((R/P)^2\) 块，\(R=1024\)、\(P=16\) 时是 \(64\times64=4096\) 个。之后就是普通的 Transformer 层。

全局注意力让每个 token 与所有 token 算分数，\(n\) 个 token 要算 \(n^2\) 个分数。窗口注意力把 token 网格切成互不重叠的小窗口，只在窗口内部算：每个窗口有 \(n_{\text{win}}\) 个 token 时，共 \(n/n_{\text{win}}\) 个窗口、每个 \(n_{\text{win}}^2\) 个分数，总数是 \(n\cdot n_{\text{win}}\)，在 \(n_{\text{win}}\ll n\) 时比 \(n^2\) 小得多，代价是看不到窗口以外。DeepEncoder 的两段都是现成的 ViT 编码器：SAM-base 原本为图像分割训练，以窗口注意力为主；CLIP-large 原本用图文配对训练，全部是全局注意力。

DeepSeek-OCR 的编码器 DeepEncoder 用三段串联来调和这三件事 6：

  1. SAM-base（80M 参数）：把 1024×1024 的图切成 16×16 像素的小块，得到 4096 个 token；以窗口注意力为主（12 层中只有 4 层做全局注意力 10），大多数层里每个 token 只和附近窗口里的 token 互相看，负责认清局部笔画。
  2. 卷积压缩器：两层卷积，核 3、步长 2、填充 1，通道从 256 升到 1024；每层把长宽各减半，两层合计 token 数除以 16，从 4096 变成 256。
  3. CLIP-large（300M 参数）：在这 256 个 token 上做全局注意力，负责版面与语义；因为输入已经不是图片，去掉了它原来的第一层 patch embedding。
每个模式的视觉 token 数
(1)\(\displaystyle \text{切块：}(R/16)\times(R/16)\ \text{个 token}\)边长 \(R\) 像素，每块 16×16
(2)\(\displaystyle s\ \to\ \Big\lfloor\dfrac{s+2-3}{2}\Big\rfloor+1=\dfrac s2\)每层卷积把边长 \(s\) 变成 \(\lfloor(s+2\times\text{填充}-\text{核})/\text{步长}\rfloor+1\)；\(s\) 为偶数时恰好减半，例 64 → 32
(3)\(\displaystyle n_v=\dfrac{(R/16)^2}{4\times4}=\Big(\dfrac{R}{64}\Big)^2\)两层共把长宽各缩 4 倍，token 数缩 16 倍；要求 \(R/16\) 是 4 的倍数，两次都是偶数边长
(4)\(\displaystyle R=1024:\ 64^2\to16^2=256\)Base 模式：4096 个块压成 256 个
(5)\(\displaystyle R=512,640,1280\Rightarrow64,100,400\)Tiny、Small、Large 模式的 \(n_v\)

为什么先 SAM、后压缩、再 CLIP，而不是反过来？看注意力分数矩阵的大小：全局注意力在 \(n\) 个 token 上要算 \(n^2\) 个分数。若让 CLIP 直接处理 4096 个 token，分数矩阵是 \(4096^2\)，比现在的 \(256^2\) 大 \(4096^2/256^2=256\) 倍。论文的说法是：前半段以窗口注意力为主、参数只有 80M，激活可以接受；进入全局注意力之前先压成 256 个 token，整体激活显存就可控了 6。

这条“拼接”旁路值得记住：DeepEncoder 并不是纯粹的“SAM → 压缩 → CLIP”串联，SAM 看到的局部细节有一路绕过 CLIP 直接送给解码器 10。这种“SAM 特征 + 语义编码器特征拼接”的做法在 DeepSeek-VL 里就有：它用 SAM-B 处理 1024² 的高分辨率图，经两层步长为 2 的卷积压缩后与 SigLIP 的特征拼接 11；DeepSeek-OCR 自己则说压缩模块借鉴自 Vary 6。

分辨率模式：同一个编码器，不同的预算

为了研究“多少 token 够用”，DeepSeek-OCR 训练了多种分辨率模式（图 17.12）6。四种原生模式：Tiny（512²，64 个 token）、Small（640²，100 个）、Base（1024²，256 个）、Large（1280²，400 个）。前两种把图直接缩放，后两种为了保持长宽比而补边。还有两种动态模式：Gundam 把大图切成 \(n\) 块 640² 的局部视图，再加一张 1024² 的全局视图，共 \(n\times100+256\) 个 token，\(n\) 在 2 到 9 之间；Gundam-M 用 1024² 的块加 1280² 的全局视图，是在训练好的模型上续训得到的，开源模型没有提供它 6,10。

补边会浪费一部分 token：竖长的一页补成正方形，两侧的空白也被编码了。论文用一个公式估计“有效”的视觉 token：

补边后的有效视觉 token（论文式 (1)）\[N_{\text{valid}}=\Big\lceil N_{\text{actual}}\times\Big[1-\frac{\max(w,h)-\min(w,h)}{\max(w,h)}\Big]\Big\rceil=\Big\lceil N_{\text{actual}}\cdot\frac{\min(w,h)}{\max(w,h)}\Big\rceil\]\(w,h\)：原图的宽和高（像素）；\(N_{\text{actual}}\)：该模式的视觉 token 数（Base 为 256）。第二个等号：\(1-(\max-\min)/\max=\big(\max-(\max-\min)\big)/\max=\min/\max\)。(17.22)
一张 A4 扫描页用 Base 模式

A4 纵向按 200dpi 扫描约 1654×2339 像素。\(N_{\text{valid}}=\lceil256\times1654/2339\rceil=\lceil181.03\rceil=182\)。巧的是，论文表 3 中 Base 模式在 OmniDocBench 上的平均有效 token 正好也写作 “256 (182)” 6。开源代码用向下取整（int），得 181 10。

同一页若有 1,000 个文本 token，各原生模式的压缩比是 \(1000/64=15.6\)、\(1000/100=10\)、\(1000/256=3.9\)、\(1000/400=2.5\)。

论文数的 token 与送进语言模型的 token 不一样多

64/100/256/400 是编码器输出的视觉 token。开源代码把它们排成 \(s\times s\) 的网格送进语言模型时，每一行末尾还多一个“换行” token，全局视图后多一个“分隔” token，所以实际占 \((s+1)s+1\) 个位置：Tiny 73、Small 111、Base 273、Large 421 10。按实际占位算，下一页表中 “10.5×” 的那一格约为 \(672/73=9.2\times\)。论文的压缩比用的是 64/100 这个分母。

解码器与训练

解码器是 DeepSeek-3B-MoE：12 层、隐藏维 1280，64 个路由专家每 token 激活 6 个，另有 2 个共享专家，激活参数约 570M；论文说它“有 3B 模型的表达力、500M 小模型的推理效率” 6。它与 DeepSeek-VL2-Tiny 的语言模型规格相同，VL2 报告其激活参数为 0.57B 13。按配置文件（隐藏维、专家宽度 896、首层稠密宽度 6848、词表 129,280）重建 10：总参数约 2.93B，非嵌入激活参数 407.7M，加上输出头 573.2M，与 “A570M” 吻合（笔者推算，未计归一化层与路由器）。

训练数据中 OCR 数据占 70%、通用视觉 20%、纯文本 10%，序列长度 8192 6。它没有经过 SFT，所以不是一个聊天模型，有些能力要用补全式的提示才能激活 6。论文还报告了生产用途：一张 A100-40G 每天可以为 LLM/VLM 生成 20 万页以上的训练数据，20 个节点（160 张卡）每天 3,300 万页 6；\(3.3\times10^7/160=206{,}250\) 页/卡/天，两个数字互相一致。

本页要点
  • 压缩比 \(r=n_t/n_v\)：原文文本 token 数除以视觉 token 数。DeepSeek-OCR 测的是在给定 \(r\) 下能否把原文逐字读回来。
  • DeepEncoder = SAM-base（80M，以窗口注意力为主，4096 token）→ 两层 stride-2 卷积（token ÷16）→ CLIP-large（300M，全局注意力，256 token）；开源代码还把 SAM 特征绕过 CLIP 拼接进来。
  • \(n_v=(R/64)^2\)：Tiny/Small/Base/Large = 64/100/256/400；Gundam \(=n\times100+256\)。补边时有效 token \(\lceil N\cdot\min(w,h)/\max(w,h)\rceil\)。代码实际占位多出换行与分隔 token。
  • 解码器 3B MoE、激活约 570M；它是 OCR 专用模型，不是聊天模型。

压缩比、精度与“光学遗忘”

DeepSeek-OCR 的头条数字是：压缩比低于 10 倍时 OCR 精度约 97%，压缩到 20 倍时仍有约 60% 6。这一页先把这两个数字还原到它们来自的那张表，再看作者由此提出的“光学遗忘”设想，最后看它的续作 DeepSeek-OCR 2。

Fox 实验：头条数字来自哪几格

实验用 Fox 基准的英文部分：把标准答案用 DeepSeek-OCR 的分词器（约 129K 词表）分词，挑出 600–1300 个文本 token 的页面，正好 100 页；因为文字不多，只测 Tiny（64 个视觉 token）和 Small（100 个）两种模式 6。论文表 2 按文本 token 数分成 7 档，每档给出两种模式的精度和压缩比，画出来就是图 17.13。

所以“<10× 约 97%”是 77 页的加权平均，站得住；“20× 约 60%”是 4 页的结果，只能当作一个方向。论文正文还有一句“10–12× 约 90%”，表里对应的格是 91.5%（10.6×）、89.8%（11.3×），但 Tiny 列的 10.5× 却有 96.5%，可见这是粗略的概括 6。论文还提醒，模型输出的格式与 Fox 的标准答案不完全一致，实际精度会更高一些 6。

超过 10 倍后精度为什么下降？论文给了两个可能的原因：长文档的版面更复杂；文字在 512² 或 640² 的分辨率下变模糊了。前者可以把文字渲染到单一版面来解决；对后者，作者的态度很特别：他们认为这会成为“遗忘机制”的一个特性（原文 “will become a feature of the forgetting mechanism”）6。

在真实文档上（OmniDocBench），DeepSeek-OCR 只用 100 个视觉 token 就超过了用 256 个 token 的 GOT-OCR2.0（比的是编辑距离）；Gundam 模式平均每页 795 个 token，超过了每页约 6,790 个 token 的 MinerU2.0，token 数只有它的约 1/8.5（\(795/6{,}790=11.7\%\)）6。但报纸这类每页有 4,000–5,000 个文本 token 的文档，必须用 Gundam 甚至 Gundam-M 才行，因为那已经远超其他模式 10 倍左右的压缩能力 6。

光学遗忘：让旧的上下文慢慢模糊

论文的讨论部分把上面的观察推成了一个关于记忆的设想：遗忘是人类记忆最基本的特征之一；上下文光学压缩可以模拟它，把之前各轮的历史文本渲染成图片做初步压缩，再把越旧的图片缩得越小，token 越来越少、文字越来越模糊，从而实现“文本的遗忘” 6。论文还设想，多轮对话中超过 \(k\) 轮的历史可以这样处理，达到 10 倍的压缩效率 6。

遗忘方案的 KV 账

10 轮、每轮 1,000 token。全部保留为文本：\(10{,}000\) 个 token，\(10{,}000\times890=8.90\) MB。按图 17.14 遗忘：

\[\begin{aligned}&2\times1000+2\times400+2\times256+2\times100+2\times64=3{,}640\ \text{个 token},\\ &3{,}640\times890=3.24\ \text{MB},\end{aligned}\]

整体压缩比 \(10{,}000/3{,}640=2.75\)，即 KV 只剩原来的 36.4%。代价看表 2：Small 那两轮（10×）对应约 91.5%–96.8% 的逐字精度，Tiny 那两轮（15.6×）对应约 79.3%–85.9%；Base 和 Large 在 Fox 上没有测过。对话越长，被压成小图的轮次占比越大，整体压缩比会继续上升，而这些最旧的轮次，也正是被读得最不准的。

这就是本课标题里“不是所有上下文都需要以完整 KV 的形式记住”在字面意义上的样子：旧的轮次不删除，只是降低分辨率，占用随之下降。

它证明了什么，没证明什么

证明了的（实测）：在 Fox 这类英文文档上，一个专门训练的 OCR 模型可以用约十分之一数量的视觉 token 把一页文字逐字读回来，精度约 97%；在真实文档解析上，用少得多的 token 达到当时的先进水平 6。

没有证明的：语言模型能否在这些视觉 token 上直接理解和推理，而不是先把它们念回文本。作者自己写得很清楚：只靠 OCR 不足以完全验证真正的上下文光学压缩，将来要做数字-光学文本交错的预训练、大海捞针测试等评测（原文 “OCR alone is insufficient to fully validate true context optical compression”）6。

还有一篇第三方预印本给出了反方向的证据：用句子级和词级的语义扰动去掉语言先验之后，DeepSeek-OCR 的表现从约 90% 跌到约 20%，并在约 1 万个文本 token 处全面崩溃 14。该文作者据此认为，高精度里有相当一部分来自语言模型“猜得出下一个词”（语言先验），而不全是视觉 token 装下了信息。这篇预印本未经评审，本课只读了摘要，只作方向性引用。

“视觉 token 能把上下文无损压缩 10 倍”

这不是已被证实的结论。已经测到的是：在 Fox 英文页、600–1300 个文本 token、只用 Tiny/Small 两种模式、提示为 “Free OCR.” 的条件下，压缩比低于 10 倍时逐字 OCR 精度约 97% 6。它衡量“能不能读回来”，不衡量“能不能在压缩后的上下文上推理”；而且去掉语言先验后精度会大幅下降 14。另外，DeepSeek 自己的 V4.1-Flash 也没有采用 DeepEncoder：它的视觉编码器是从头训练的 DeepSeek-ViT 2。

DeepSeek-OCR 2：从“压多少”到“按什么顺序读”

三个月后的 DeepSeek-OCR 2（arXiv 2026-01-28）换了一个问题 12。传统的视觉语言模型总是按光栅顺序（从左上到右下）把视觉 token 送进语言模型；而人读一页复杂版面（分栏、表格、图注）并不是这样读的。OCR 2 的编码器 DeepEncoder V2 做了两处改动 12：

  • 用一个 Qwen2-0.5B 结构的小型 LLM（500M 参数）替换原来的 CLIP；
  • 在视觉 token 后面接上同样数量的可学习因果流查询（causal flow queries）。视觉 token 之间是双向注意力，查询可以看到全部视觉 token、但查询之间是因果的；最后只把查询那一半的输出交给解码器。
DeepEncoder V2 的注意力掩码（OCR 2 式 (1)）\[\mathbf M=\begin{bmatrix}\mathbf 1_{n_v\times n_v}&\mathbf 0_{n_v\times n_q}\\ \mathbf 1_{n_q\times n_v}&\mathrm{LowerTri}(n_q)\end{bmatrix}\in\{0,1\}^{(n_v+n_q)\times(n_v+n_q)},\qquad n_q=n_v\]\(n_v\)：视觉 token 数（与 (17.21) 同一个符号；原文记作 \(m\)）；\(n_q\)：因果查询数（原文记作 \(n\)）；前 \(n_v\) 行、列是视觉 token，后 \(n_q\) 行、列是查询；\(\mathbf M_{ij}=1\) 表示第 \(i\) 个位置可以看第 \(j\) 个位置；\(\mathrm{LowerTri}(n_q)\)：\(n_q\times n_q\) 的含对角线的下三角全 1 矩阵。(17.23)

直观地说，查询一个接一个地“读”这页图：每个查询都能看到整页，但在查询之间只能看到自己和自己之前的查询，于是它们学会按某种语义顺序依次提取内容，这就是论文副标题里的 “Visual Causal Flow”。论文还报告，用 mBART 式的交叉注意力编码器-解码器结构代替这种“前缀拼接”的做法，训练无法收敛 12。

OCR 2 的 token 预算与结果

全局视图 1024² 给 256 个 token，每个局部视图 768² 给 \(768^2/(16^2\times16)=144\) 个，局部视图 0–6 个：送进解码器的 token 数是 \(k\times144+256\)，范围 \([256,1120]\)；上限 1120 低于 DeepSeek-OCR Gundam 模式的 1156 12。

结果（OmniDocBench v1.5）：总分从 87.36 升到 91.09，论文写作 “3.73% improvement”，其实是 3.73 个百分点（相对提升 4.3%）；阅读顺序的编辑距离从 0.085 降到 0.057 12。生产数据中的重复率：在线日志图片从 6.25% 降到 4.17%，PDF 从 3.69% 降到 2.88% 12。退步的地方也有：报纸类文本的编辑距离超过 0.13 12。

  • 光学遗忘：越旧的轮次渲染得越小越模糊，10 轮对话的算例把 KV 压缩到原来的 1/2.75（36.4%）；论文只提出设想，没做多轮实验。

共享的表与每个请求的 KV，哪个更贵

V4.1-Flash 的 Engram 表 202.8 GB，所有请求共用一份。一个一百万 token 的会话，KV 是 \(10^6\times890=0.89\) GB，每个请求一份。\(202.8/0.89\approx228\)：同时服务约 228 个百万 token 的会话，KV 就超过了整张 Engram 表。这就是两种记忆的根本差别：参数化记忆的成本按模型摊，上下文记忆的成本按请求和长度涨。

回到课程地图给本课的主题：“不是所有上下文都需要以完整 KV 的形式记住”。对 DeepSeek-OCR，这句话是字面意义上的：旧的轮次换成视觉 token，条目少了约 10 倍，代价是读回来的精度随压缩比下降。对 Engram，更准确的说法是“不是所有知识都需要靠逐层计算重建”：它一个字节的 KV 也没省，但它把局部搭配交给查表，让骨干的深度和注意力的容量去做别的事。两者的共同点是分层：按“值得用多贵的方式记住”来分配存储与计算。接下来的两课会在注意力内部继续这条线：V4 的 CSA/HCA 沿序列方向压缩 KV，V4.1-Flash 改用纯 CSA2，让多层共享同一份全局 KV，并把主 KV 存成 FP4（第 18 课、第 19 课）。

概念题

练习 1 · Engram 省了 KV cache 吗

有人说：“Engram 把静态知识放进一张表，所以 V4.1-Flash 的 KV cache 才这么小。”这句话对吗？Engram 对长上下文有没有帮助？如果有，是通过什么？

看答案

不对。Engram 是参数化记忆：它用最近几个 token 的编号作键去查一张训练好的表，查到的向量加进残差流；它不存储、也不压缩任何 token 的键和值。每个位置只需要最近 \(N_{\text{gram}}-1\) 个 token 的编号。V4.1-Flash 的 KV 小，是 CSA2（多层共享全局 KV）、FP4 主 KV 等注意力侧设计的功劳（第 19 课）。

Engram 对长上下文的帮助是间接的：论文认为它把局部搭配的重建交给查表，让注意力有更多容量处理全局上下文；在对齐基座损失的比较下，多查询大海捞针从 84.2 升到 97.0 3。真正“把上下文压小”的是 DeepSeek-OCR 的光学压缩设想。

练习 2 · 预取与放置

（a）为什么 Engram 的表可以放在主机内存里、提前预取，而 MoE 的专家不方便这样做？（b）既然放得越深、能用来掩盖预取的计算越多，为什么不把 Engram 放在第 20 层？（c）为什么放在第 1 层又不如第 2 层？

看答案

（a）Engram 的行号 \(z_{t,n,k}\) 只是 token 编号的确定函数 (17.18)，token 一进入模型就能算出，可以在前面各层计算的同时把行搬过来。MoE 第 \(l\) 层选哪些专家取决于 \(\mathbf h^{(l)}_t\)，必须等前 \(l-1\) 层算完才知道。

（b）建模上希望早：Engram 的作用是替骨干承担底层的局部拼装，放得越深，骨干已经用前面的层把这件事做完了，省下的深度就越少。层扫描显示单模块越深越差 3。实际的放置是建模与延迟的折中。

（c）第 1 层之前没有任何注意力，\(\mathbf h_t\) 只是 token 自己的嵌入，门控无法判断查到的记忆与上下文是否一致。论文的解释是一轮注意力就足以给门控提供有上下文的 \(\mathbf h_t\) 3。

练习 3 · 读 U 形曲线

（a）有人总结：“Engram 论文发现了一条 scaling law：应该把 75%–80% 的参数给 Engram。”指出其中的两处错误，并写出正确的说法。（b）Engram-40B 和 Engram-27B 一样保留 55 个路由专家（不激活的专家参数都是 16.76B），但表有 18.53B。按 (17.16) 算它的 \(\rho\)。能不能把这个 \(\rho\) 放到 U 形曲线上去判断 Engram-40B 分得好不好？

看答案

（a） 错误一：\(\rho\) 是不激活参数预算里给 MoE 专家的份额。\(\rho\approx75\%\)–80% 最优，意味着给 Engram 的是这笔预算的 20%–25%；而且是不激活参数的比例，不是总参数的比例。

错误二：“scaling law”言过其实。U 形曲线只在两个算力点（\(2\times10^{20}\)、\(6\times10^{20}\) FLOPs）、固定 \(N_{\text{tot}}/N_{\text{act}}\approx10\) 下测过，论文自己加了 “under fixed sparsity” 的限定；从图上读出的最低观测点在 \(\rho\approx85\%\)，二次拟合顶点 0.72–0.74，精确位置并不稳。

正确的说法：在所测的两个规模、固定稀疏度下，纯 MoE 不是最优；把约 20%–25% 的不激活参数挪给 Engram 时验证损失最低，\(\rho\) 在 40%–100% 之间曲线都比较平。

（b） \(\rho=\dfrac{16.763}{16.763+18.534}=\dfrac{16.763}{35.297}=0.475\)，约 47.5%（专家参数与表参数取 §2、§4 的复算值：\(16{,}762{,}798{,}080\) 与 \(18{,}534{,}311{,}360\)）。

不能拿它去对照 U 形曲线。U 形曲线的前提是 \(N_{\text{tot}}\) 和 \(N_{\text{act}}\) 都固定，只改分法；Engram-40B 的激活参数没变，总参数却从 26.7B 涨到 39.5B，多出来的全是表。它属于“只加大表”的那一类实验（图 17.7b），在那一类实验里表越大损失越低（每十倍槽数约 −0.028）。所以 \(\rho\) 低到 47.5% 并不意味着它落在 U 形左端、分得不好；两个 \(\rho\) 只有在总参数相同时才能比较。

计算题

练习 4 · V4.1-Flash 的 Engram 有多大

V4.1-Flash 有 2 个 Engram 模块，每个模块阶 {2,3,4}、每阶 8 个头、每头的表约 \(1.6\times10^7\) 行、每行 256 维；FP8 存储，每 32 维一个 1 字节缩放。（a）粗算参数量。（b）配置文件给出两模块行数 384,006,168 和 384,016,682，求精确参数量与存储。（c）若用 BF16 存，存储是多少？

看答案

（a）表的张数 \(2\times3\times8=48\)，参数 \(48\times1.6\times10^7\times256=1.966\times10^{11}\)，约 196.6B。

（b）行数 \(384{,}006{,}168+384{,}016{,}682=768{,}022{,}850\)，参数 \(768{,}022{,}850\times256=196{,}613{,}849{,}600\)。每行字节 \(256+256/32=264\)，存储 \(768{,}022{,}850\times264=2.028\times10^{11}\) 字节 \(\approx202.8\) GB（\(\div2^{30}\) 得 188.8 GiB）。

（c）BF16 每数 2 字节，不需要块缩放：\(196{,}613{,}849{,}600\times2=3.932\times10^{11}\) 字节 \(\approx393.2\) GB，约为 FP8 方案的 1.94 倍。

练习 5 · 每 token 搬多少字节

（a）按 (17.19) 算 V4.1-Flash 每个 token 要从主机内存取多少字节。（b）假想一个配置：3 个 Engram 层、阶 {2,3}、每阶 4 个头、每头 128 维、BF16 存储。每 token 取多少字节？（c）把（b）中每张表的行数翻倍，答案变不变？

看答案

（a）\(L_{\text{E}}(N_{\text{gram}}-1)K_{\text{hash}}=2\times3\times8=48\) 行，每行 264 字节：\(48\times264=12{,}672\) 字节。

（b）\(3\times2\times4=24\) 行，每行 \(128\times2=256\) 字节：\(24\times256=6{,}144\) 字节。

（c）不变。每 token 每张表只取一行，(17.19) 里没有表的行数 \(p\)；表变大只增加存储，不增加每 token 的搬运量。这正是论文说“通信量随激活的槽数增长，而不是随表的大小增长”的算术 3。

练习 6 · 哈希负载

假设训练语料里有 \(10^8\) 个不同的（压缩后的）3-gram，V4.1-Flash 一个头的表有 16,000,057 行。求（a）负载 \(\lambda\)；（b）一个 3-gram 在这个头里与别人共享一行的概率；（c）与某个特定 3-gram 在 8 个头中至少 2 个头上同时相撞的期望伙伴数。由此说明“碰撞几乎必然”与“拼接后的记忆向量几乎唯一”为什么不矛盾。

看答案

（a）\(\lambda=10^8/16{,}000{,}057=6.25\)。

（b）由 (17.9)：\(1-e^{-6.25}=0.998\)，几乎每一行都被共享。

（c）由 (17.10)：\(\binom82=28\)，\(16{,}000{,}057^2\approx2.56\times10^{14}\)，所以期望伙伴数 \(\approx(10^8-1)\times28/(2.56\times10^{14})\approx1.1\times10^{-5}\)。

不矛盾：单个头里的行几乎都被许多 3-gram 共享，但一个 3-gram 拿到的是 8 行的组合，另一个 3-gram 要在至少两个头上同时撞上的期望次数只有十万分之一。拼接后的 \(\mathbf e_t\) 对不同的 3-gram 几乎总是不同的，被共享的那部分由门控和后续网络去分辨。注意 \(U=10^8\) 是假设值，论文没有报告不同 N-gram 的个数。

练习 7 · 门控的取值范围

设骨干隐藏维 \(d=4096\)，忽略 RMSNorm 的可学习缩放。（a）\(s_t\) 的绝对值最大是多少？（b）按论文式 (17.12)，\(\alpha_t\) 的范围是什么？（c）按代码的 (17.13)，范围是什么？（d）\(s=9\) 时两种门控各是多少？

看答案

（a）RMSNorm 后两向量长度都是 \(\sqrt d=64\)，由柯西–施瓦茨不等式点积 \(\le64\times64=4096\)，除以 \(\sqrt d\) 得 \(\abs{s_t}\le64\)。

（b）\([\sigma(-64),\sigma(64)]\)（两个 RMSNorm 输出同向或反向时取到端点），下界 \(\approx e^{-64}\approx1.6\times10^{-28}\)，实际上就是 \((0,1)\)。

（c）平方根后 \(\le\sqrt{64}=8\)：\(\alpha_t\in[\sigma(-8),\sigma(8)]=[0.000335,\ 0.999665]\)。

（d）\(\sigma(9)=0.99988\)；代码 \(\sigma(\sqrt9)=\sigma(3)=0.9526\)。

练习 8 · DeepSeek-OCR 的 token 数

（a）Large 模式（1280×1280）输出多少视觉 token？开源代码里实际占多少个位置？（b）一张 1920×1080 的横向截图用 Base 模式，按 (17.22) 有效 token 是多少？（c）Gundam 模式最多多少 token？OCR 2 最多多少？

看答案

（a）\(1280/16=80\)，切出 \(80\times80=6400\) 块；两层卷积 token 数除以 16：\(400\)，即 \((1280/64)^2=20^2\)。网格 \(20\times20\)，每行加一个换行 token、最后加一个分隔 token：\(21\times20+1=421\)。

（b）\(\lceil256\times1080/1920\rceil=\lceil144\rceil=144\)。补边后有 \(256-144=112\) 个 token 编码的是空白。

（c）Gundam：瓦片数上限 9，\(9\times100+256=1156\)。OCR 2：局部视图上限 6，\(6\times144+256=1120\)。

练习 9 · 读 Fox 表

论文表 2 中，64 个视觉 token、文本 1200–1300 token 的一档，压缩比 19.7×、精度 59.1%，共 4 页。（a）这一档平均多少文本 token？用 100 个视觉 token 那一列的 12.6× 核对。（b）“<10× 时约 97%”按页加权是多少？（c）为什么“20× 约 60%”要谨慎引用？

看答案

（a）\(19.7\times64=1260.8\approx1261\)；另一列 \(12.6\times100=1260\)，一致。压缩比是按每档的平均文本 token 算的。

（b）<10× 的只有 100-token 列的前四档：\((98.5\times7+97.3\times28+96.8\times28+96.8\times14)/77=7479.5/77=97.14\%\)。

（c）只有 4 页，样本太小；而且同一列并不单调（13.2× 时 83.8%，15.1× 时反而 85.9%），说明每档的噪声不小。此外它衡量的是逐字 OCR 精度，精度的计算方式论文也没有定义。

练习 10 · 另一种遗忘方案

10 轮对话，每轮 1,000 文本 token。方案 A 全部保留为文本；方案 B 最近 2 轮保留文本，更早的 8 轮每轮渲染成一张 Small 模式（100 个视觉 token）的图。按 890 字节/token，并假设视觉 token 与文本 token 的 KV 成本相同，求两方案的 KV 和压缩倍数，并说出方案 B 的两个风险。

看答案

A：\(10{,}000\times890=8.90\) MB。B：\(2\times1000+8\times100=2{,}800\) 个 token，\(2{,}800\times890=2.49\) MB；整体压缩比 \(10{,}000/2{,}800=3.57\)（KV 只剩 28%）。

风险一：每张图的压缩比是 10×，按 Fox 表 2，这附近的逐字精度约 91.5%–96.8%，意味着每页有几个百分点的字读不准，而且最旧的 8 轮全都如此。风险二：这是 OCR 精度，不是“在这段历史上推理”的保真度；作者承认 OCR 不足以验证上下文光学压缩 6，第三方还报告去掉语言先验后精度大幅下降 14。另外“视觉 token 与文本同价”是假设。

推导题

练习 11 · V4.1-Flash 里最多几个头同时相撞

V4.1-Flash 第一个 Engram 模块的 2-gram 头，最小的三个表大小是 16,000,057、16,000,079、16,000,081。沿用 §2 的前提（同一阶的头共用一个混合值 \(\text{mix}\in[0,2^{63})\)，行号是 mix 对各自的素数取模）。（a）证明两个不同的混合值不可能在 3 个头上同时相撞。（b）在 2 个头上同时相撞可能吗？

看答案

（a）设 \(\Delta=\text{mix}-\text{mix}'\neq0\)。在头 \(i,j,l\) 同时相撞意味着 \(p_i\mid\Delta\)、\(p_j\mid\Delta\)、\(p_l\mid\Delta\)。三个不同的素数两两互素，所以 \(p_ip_jp_l\mid\Delta\)，从而 \(\abs\Delta\ge p_ip_jp_l\)。任意三个头的素数之积至少是最小三个之积：\(16{,}000{,}057\times16{,}000{,}079\times16{,}000{,}081\approx4.10\times10^{21}\)。但 \(\abs\Delta<2^{63}\approx9.22\times10^{18}\)，矛盾。所以 \(\Delta=0\)，即混合值相同。（快速估计：每个素数都大于 \(1.6\times10^7\)，乘积大于 \((1.6\times10^7)^3=4.096\times10^{21}\)。）

（b）可能。两个素数之积约 \(16{,}000{,}057\times16{,}000{,}079\approx2.56\times10^{14}<2^{63}\)，所以存在 \(\Delta=p_ip_j\) 这样的差，使两个混合值恰好在这两个头上相撞。这就是 (17.10) 只统计“至少 2 个头”的原因：更多头同时相撞的项为零。

练习 12 · 平方根让门控的梯度变大了吗

门控 \(\alpha=\sigma(g(s))\)。论文 \(g(s)=s\)，代码 \(g(s)=\sign(s)\sqrt{\abs s}\)。（a）用链式法则写出 \(d\alpha/ds\)，并利用 \(\sigma'(x)=\sigma(x)(1-\sigma(x))\)。（b）分别算 \(s=4\) 与 \(s=16\) 时两种门控的 \(d\alpha/ds\)。（c）为什么只有一个候选时不能用 softmax 当门控？

看答案

（a）链式法则：

\[\frac{d\alpha}{ds}=\sigma'\big(g(s)\big)\,g'(s),\qquad \sigma'(x)=\sigma(x)\big(1-\sigma(x)\big).\]

论文：\(g(s)=s\)，\(g'(s)=1\)。代码（\(s>0\)）：\(g(s)=s^{1/2}\)，\(g'(s)=\tfrac12s^{-1/2}=1/(2\sqrt s)\)。

（b）\(s=4\)：论文 \(\sigma(4)(1-\sigma(4))=0.9820\times0.0180=0.0177\)；代码 \(\sigma(2)(1-\sigma(2))\cdot\frac1{2\cdot2}=0.1050/4=0.0262\)，大约 1.5 倍。\(s=16\)：论文 \(\sigma'(16)\approx1.1\times10^{-7}\)，几乎为零；代码 \(\sigma'(4)\cdot\frac1{2\cdot4}=0.0177/8=0.0022\)，大了约两万倍。所以在点积很大时，代码的门控仍能收到可观的梯度，不容易“卡死”在全开（笔者推导；论文与代码都没有说明这样设计的理由）。

（c）对一个元素做 softmax：\(e^{s}/e^{s}=1\)，与 \(s\) 无关，门控恒为 1，梯度恒为 0，什么也没学到。softmax 只能在多个候选之间分配相对权重；这里要的是“这一个候选信多少”的绝对判断，所以用 sigmoid。
