# “黑板课”讲法（试行）

> 用户希望试一种更接近国内优秀科普老师的讲法：像站在黑板前给学生讲课，从一个生活里的问题开始，
> 用最小的例子在黑板上一步步算出来，边讲边问。本文件规定这种讲法的具体做法。它**叠加**在
> `style-guide.md` 与 professor 契约之上：事实、公式、符号、引用规则一条不变，变的是展开方式和语气。
> 页面上不出现任何真实人物的名字，也不自称某位老师；这是一种讲法，不是模仿某个人。

## 1. 开场：先抛一个大家见过的现象

- 每一课、每一页都从一个具体的、读者亲眼见过或能立刻想象的现象开始，而不是从定义开始。
  例：“大家用聊天机器人的时候有没有注意到，它的回答是一个字一个字往外蹦的，而你发过去的一大段话，
  它好像一下子就读完了。这是为什么？”
- 第二句就把现象变成一个可以回答的问题：“今天我们就来把这件事彻底讲清楚。”

## 2. 语气：站在黑板前跟大家聊

- 称呼读者一律用“大家”（或“我们”），**不用“同学们”**，也不用“各位”：语气是平等地聊，不是讲台上训话。
  讲的人自称“我”。短句为主，一句话只说一件事；可以像朋友聊天那样随意一点（“其实”“说白了”“你看”），
  但每个结论仍然要算出来、写出来。
- 多用设问和停顿，让读者先想再看答案：“那么问题来了——”“大家先想一想，这时候会发生什么？”
  “是不是这样？对，就是这样。”“好，我们来算一下。”
- 允许一点幽默和口头的节奏感，但不油滑，不用网络梗，不堆感叹号。
- 仍然禁用“显然”“易证”“不难看出”“众所周知”：黑板课的精神恰恰是“每一步都写出来”。

## 3. 板书：从最小的例子算起，再推广

- 每个机制先用最小、能手算的例子在“黑板”上演一遍（2 个 token、3 维向量、一张 4×4 的表），
  数字要真的算出来、写出来，读者拿笔能跟着算。然后才说“好，现在我们把 3 换成 $T$”，推广成一般公式。
- “板书”用 `::: ex 黑板上 · ……` 或 `::: deriv` 呈现，每一步一行、每行写理由；推导里的每一步都像老师
  一边写一边说“这一步为什么可以这样做”。
- 一般公式出来以后，立刻代回最初的小例子验算一次：“我们代进去看看，是不是 12？对，12。”

## 4. 算账：数量级和真实数字

- 讲到成本，一定落到真实模型的真实数字上，并且先让读者猜：“大家猜一猜，一个 token 要占多少显存？
  几十字节？几 KB？……答案是 128 KB。”猜测—揭晓的节奏只用在真正反直觉的数字上。
- 数字来自研究笔记；估算要写清楚用了什么假设。

## 5. 类比与误区

- 类比用生活里的东西，而且优先沿用 `style-guide.md` 第 5 节那 8 个全课类比（会议纪要、图书馆……），
  讲完类比一定说“但是这个比方有个地方不对——”把边界讲出来。
- 专门设一段“很多人以为……其实……”，用 `::: err` 呈现一个常见误解和它错在哪里。

## 6. 小故事

- 在合适的地方讲一个真实的小故事或历史细节（谁在哪一年、为了解决什么问题提出了什么），一两句话，
  带引用；不编故事，不加没来源的轶事。

## 7. 收尾：三句话总结 + 一个思考题

- 每页结尾用 `::: key` 写“今天这一页就讲了三件事：第一……第二……第三……”。
- 全课最后留一个开放的思考题（“最后给大家留个问题……下一课我们揭晓”），把读者引到下一课。

## 8. 不变的东西

- 公式、符号、数字、引用、图的颜色语义、页面结构（封面、分页、练习与答案、参考文献）与原规范一致。
- 五级阶梯仍然要走完：黑板课只是把“问题”和“数字”两级放大，把“形式化”和“推导”写成板书。
- 篇幅与原课相当；口语化不等于稀释内容，原课里的每个知识点都要保留。
