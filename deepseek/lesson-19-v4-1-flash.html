第 19 课 · DeepSeek-V4.1-Flash：把 KV cache 压到极限

V4-Flash 已经把每个 token 的全局 KV 压到 3,514 字节，1M 上下文下单 token 解码的计算也只有 V3.2 的约 10%。长程智能体却带来一种新的负载：每一轮都要把十几万 token 的上下文重新交给模型，模型只回几百个 token。账单于是从“算得动吗”变成了“存得下、搬得动吗”。DeepSeek-V4.1-Flash 用四个设计回答：让提示 token 只走一半的层（prefill 只激活 8B 参数），让 40 层只存 4 份全局 KV，把主 KV 存成 FP4，把 SWA 状态从 SSD 挪进主机内存、丢了就只回放 128 个 token。结果是每 token 全局 KV 890 字节，约为 V4-Flash 的 1/4；持久化 KV 约为 1/8。

这一课回答什么问题

第 18 课结束时，DeepSeek-V4-Flash 在 1M token 上下文里每个 token 只存 3,514 字节的全局 KV，是 V3.2 的 7%；1M 上下文下一个新 token 的解码计算也只有 V3.2 的约 10%。按“注意力贵不贵”的老标准，问题已经基本解决了。

可是 2026 年的主要负载变了。一个写代码的智能体会读一个仓库、调用几十次工具，每调用一次，都要把越来越长的上下文重新交给模型，而模型每次只回一小段动作。这样的负载输入远多于输出。这一课要回答的问题是：

  • 输入重的负载，账单落在哪里？为什么论文说瓶颈从“计算”转向了“存储与搬运”？全局 KV、SWA KV、持久化 KV 分别是什么，各存在哪里？
  • 因果编码器–解码器（CED）凭什么让 prefill 只激活 8B 参数、而解码仍激活 16B？它和 YOCO、和 T5 式的编码器–解码器有什么不同？“SWA 回放”又是为什么不可避免的？
  • CSA2 怎样让 40 层只存 4 份全局 KV？Full、Reindex、Reuse 三种模式各自共享了什么？“890 字节/token”怎样从配置文件一行一行算出来？
  • 主 KV 为什么敢存成 4 比特？它用的格式为什么和索引器用的 MXFP4 不一样？
  • SWA Bounded Replay 为什么只回放 128 个 token 就够用？它近似在哪里？“持久化 KV 约 1/8”里的 1/2 和 1/4 分别从哪来，哪一个是架构常数、哪一个是负载统计？
  • 从 GPT-3 到 V4.1-Flash，每个 token 的 KV 字节缩小了多少倍？每一级台阶是在哪个维度上省的？

这一课在科技树上的位置

这一课是主线 A（注意力与 KV cache 经济学）的最后一站。回顾一下这条线：第 4 课推导了 KV cache，又用 MQA/GQA 减少了头数；第 9 课的 MLA 把每个 token 的缓存压成一个 512 维的潜在向量加一个 64 维的 RoPE 键（共 576 维），减小的是每个条目的大小；第 14 课的 DSA 没有减少缓存，却让每个查询只读 2048 个条目；第 18 课的 V4 用 CSA/HCA 沿序列方向把每 4 个或每 128 个 token 压成一个条目，同时把缓存的大部分维度存成 FP8。

V4 留下三个问题。第一，每一层仍然各存一份全局 KV，43 层的 V4-Flash 存了 41 份，层维度一点没省。第二，prefill 时每个提示 token 仍要走完全部层，激活 13B 参数，而论文指出，智能体频繁调用工具，会产生大量 prefill 请求 1，输入量可以是输出的一两百倍（§1 的假设会话是 197 : 1）。第三，V4 线上的持久化缓存里，几乎一半的空间存的是只在几分钟内有用的 SWA 状态。V4.1-Flash（2026-09-10 发布权重与 API 2；论文 arXiv 2609.19969 于 2026-09-17 提交 1）就是对这三点的回答。下一课 第 20 课把六条主线放在一起复盘，本课最后一页的“KV 字节阶梯图”就是主线 A 的总结图。

新账单：输入重的智能体负载

先回顾前几课一直在打的那一仗。第 14 课的 DSA 让每个查询只精读 2048 个 token；第 18 课的 V4 又沿序列方向压缩，1M 上下文下 V4-Flash 的单 token 解码计算只有 V3.2 的约 10%。V4.1 论文在引言里这样概括局面：稀疏注意力的进展已经大幅降低了长序列处理的计算成本，于是持久化存储与数据搬运成了越来越突出的瓶颈 1。这一页先把这句话落到数字上：智能体的负载长什么样，钱花在哪里，哪些字节必须存、存在哪、存多久。

智能体会话：每一轮都重读全部上下文

含义。 一个负载叫输入重（input-heavy），是说每次请求交给模型的 token（输入）远多于模型生成的 token（输出）。

理解。 想一个写代码的智能体。开头，它拿到系统提示、任务描述和若干源文件，可能已经有两万 token。它想一想，输出一个工具调用（比如“运行测试”），只有几百 token。工具执行完，把几千 token 的结果贴回上下文。下一轮，模型要在全部这些 token 之上再决定下一步。于是每一轮的输入都是“之前的一切 + 新的工具结果”，越滚越长；每一轮的输出始终只有几百个。这不是某个产品的偶然，是“多轮调用工具”这种工作方式本身的形状。

数学。 设开头的上下文有 \(T_0\) 个 token，一共 \(K\) 轮，每轮模型输出 \(o\) 个 token、工具返回 \(a\) 个 token。第 \(k\) 轮请求的输入长度是前面积累的全部：

第 k 轮的输入长度与全会话输入总量\[T_k=T_0+(k-1)(a+o),\qquad \sum_{k=1}^{K}T_k=K\,T_0+\frac{K(K-1)}{2}\,(a+o)\]输入总量随轮数 \(K\) 平方增长，输出总量 \(Ko\) 只线性增长。(19.1)
输入总量的求和
(1)\(\displaystyle \sum_{k=1}^{K}T_k=\sum_{k=1}^{K}T_0+(a+o)\sum_{k=1}^{K}(k-1)\)把 \(T_k\) 的两项分开求和；\((a+o)\) 与 \(k\) 无关，提到求和号外
(2)\(\displaystyle =K\,T_0+(a+o)\sum_{j=0}^{K-1}j\)第一项是 \(K\) 个 \(T_0\)；第二项换元 \(j=k-1\)
(3)\(\displaystyle =K\,T_0+(a+o)\,\frac{K(K-1)}{2}\)等差数列 \(0+1+\cdots+(K-1)\) 的和
一次 50 轮的会话

取一个假设的会话（参数是笔者设的，只为看形状）：\(T_0=20{,}000\)，\(K=50\)，\(o=400\)，\(a=2{,}000\)。

  • 最后一轮的输入：\(T_{50}=20{,}000+49\times2{,}400=137{,}600\) token。
  • 输入总量：\(50\times20{,}000+\tfrac{50\times49}{2}\times2{,}400=1{,}000{,}000+2{,}940{,}000=3{,}940{,}000\) token。
  • 输出总量：\(50\times400=20{,}000\) token。输入 : 输出 \(=197:1\)。

哪怕每轮的工具结果只有 2,000 token，输入也是输出的近 200 倍。轮数翻倍（\(K=100\)），输入总量变成 \(100\times20{,}000+\tfrac{100\times99}{2}\times2{,}400=13{,}880{,}000\)，是原来的 3.5 倍（轮数越多，平方项越占主导，这个倍数越接近 4），输出只翻一倍。

前缀缓存：上一轮算过的，不要再算

含义。 第 \(k\) 轮的输入，前面一大段和第 \(k-1\) 轮一模一样。把上一轮已经算好的 KV 存起来，这一轮直接读，只对新增的部分做 prefill，这叫前缀复用（prefix reuse）；为此长期保存的那部分 KV，论文叫持久化 KV 缓存（persistent KV cache）1。

理解。 用第 4 课的类比：KV cache 是会议纪要本，后来的人只翻本子，不用重听录音。前缀缓存就是会开完了，纪要本不扔，存进档案室；明天接着开会，先把本子调出来，只补记今天的新发言。V4 部署时，这个档案室开在 SSD 上，按典型负载配得足够大，让缓存能保存 72 小时以上 1。

数学。 因果掩码保证：位置 \(j\) 的 K、V 只依赖位置 \(\le j\) 的 token。所以只要前缀逐 token 相同，它的 KV 就逐位相同，可以原样复用。在上面的会话里，第 1 轮要 prefill 全部 \(T_0\) 个 token；从第 2 轮起，上一轮的上下文和上一轮的输出都已有 KV（V4 部署会在“提示结尾”和“输出结尾”两处保存 SWA 状态，正是为了重新生成与多轮会话 1），新增的只有工具结果 \(a\) 个 token。

同一个会话，缓存命中率与账单

未命中（要 prefill）的 token：\(T_0+(K-1)a=20{,}000+49\times2{,}000=118{,}000\)。命中的：\(3{,}940{,}000-118{,}000=3{,}822{,}000\)，命中率 \(97.0\%\)。

按 V4.1-Flash 上线后的 API 标价（deepseek-flash，off-peak，每百万 token：缓存命中 $0.003、未命中 $0.15、输出 $0.60；峰时价格翻倍）2：

  • 有前缀缓存：\(3.822\times0.003+0.118\times0.15+0.02\times0.60=0.0115+0.0177+0.0120=0.041\) 美元。
  • 没有前缀缓存（全部按未命中计）：\(3.94\times0.15+0.02\times0.60=0.591+0.012=0.603\) 美元，是有缓存时的 14.6 倍。

命中价只有未命中价的 2%。这个价差本身就说明了厂商的成本结构：命中的 token 不用算，只要存着、读出来。

边界与失败模式。 纪要本的类比在一处会误导人：档案室里的纪要，只有在“前面的记录一字不差”时才能接着用。这是上面那条因果性论证的另一面：位置 \(j\) 的 KV 依赖位置 \(\le j\) 的全部 token，所以只要第 \(p\) 个位置的 token 变了，\(p\) 之后所有位置的 KV 都作废，哪怕后面的文字一个字也没改。前缀缓存命中的是“从头开始、逐 token 相同的最长前缀”，不是“内容相同的段落”。

一个会变的时间戳，让命中率归零

沿用上面的会话，假设系统提示的前 10 个 token 之后紧接着写着当前时间，每一轮都不同。那么每一轮至多前 10 个 token 能命中，其余都要 prefill：命中的 token 至多 \(49\times10=490\) 个（第 1 轮没有缓存），命中率从 97.0% 跌到约 0.01%，账单回到“没有前缀缓存”的约 0.603 美元。把会变的内容挪到提示末尾，命中率就回来了。这不是 V4.1 特有的问题，因果掩码下的任何前缀缓存都是这样。

两种 KV：全局 KV 与 SWA KV

从 V4 开始，每一层的注意力由两条分支组成（第 18 课 §3）：一条是压缩后的全局分支，能看到整段上下文；一条是只看最近 \(n_{\text{win}}=128\) 个 token 的滑动窗口注意力（sliding window attention，SWA）分支。两条分支各有各的缓存，它们的性质截然不同。这是本课最重要的术语区分。

含义。 V4.1 论文的定义：全局分支维护全局 KV（global KV），它由主 KV（main KV）和索引器键（indexer K）组成；SWA 分支维护局部 KV（local KV），本课叫 SWA KV 1。

理解。 全局 KV 像一本越记越厚的纪要本：每来一个 token（或每 \(m\) 个 token）就多一条，永不删除。SWA KV 像一块只写得下最近 128 条的白板：新的写上去，最旧的擦掉，所以不管会开多久，白板的大小不变。论文的原话是：窗口固定时，SWA 的存储与序列长度无关；序列足够长时，全局 KV 主导运行时的 KV 占用，而它受 HBM 容量限制 1。

数学。 设模型每 token 的全局 KV 为 \(s_{\text{glob}}\) 字节，每层 SWA 每个条目 \(b_{\text{swa}}\) 字节。一个长度为 \(T\) 的请求：

全局 KV 随长度线性增长，SWA 状态是常数\[S_{\text{glob}}(T)=s_{\text{glob}}\,T,\qquad S_{\text{swa}}=L\cdot n_{\text{win}}\cdot b_{\text{swa}}\quad(\text{与 }T\text{ 无关})\]\(L\) 是带 SWA 的层数。第一式忽略了还没凑满 \(m\) 个 token 的最后一组，第二式要求 \(T\ge n_{\text{win}}\)（更短时每层只有 \(T\) 个 SWA 条目），讨论长上下文时两者都成立。V4-Flash：\(s_{\text{glob}}=3{,}514.25\) B，\(S_{\text{swa}}=43\times128\times584=3{,}214{,}336\) B（3.07 MiB；第 18 课按 \(10^6\) 字节记作 3.21 MB）。(19.2)
V4-Flash：多长的上下文时，全局 KV 才比 SWA 状态大？

令 \(s_{\text{glob}}T=S_{\text{swa}}\)：\(T=3{,}214{,}336/3{,}514.25\approx915\) token。也就是说，只要上下文超过约 900 个 token，全局 KV 就更大；到 1M token 时，全局 KV 是 \(3{,}514.25\times2^{20}\) B \(=3.43\) GiB，SWA 状态仍是 3.07 MiB，只占 0.09%。这就是论文说“序列足够长时全局 KV 主导”的意思。

持久化 KV 是第三个口径，它不是一种新的张量，而是“为了前缀复用而长期保存的那部分 KV”。论文把两种口径对应到硬件：全局 KV 的占用说的是 HBM（“always in HBM”），持久化 KV 说的是 SSD 或主机内存（“always on SSD or in host memory”）1。

三张账单

把上面的概念拼起来，就得到论文摘要里的那句话：prefill 仍然昂贵，庞大的 KV cache 持续挤压 HBM 与 SSD 的容量和数据传输带宽 1。拆开是三张账单。

第一张：prefill 计算。 每个没命中缓存的输入 token 都要走一遍前向。除注意力外，每个 token 每经过一个参数大约做一次乘法和一次加法，所以

prefill 的主干计算量\[F_{\text{prefill}}\approx 2\,N_{\text{act}}^{\text{pre}}\;T_{\text{new}}\]\(N_{\text{act}}^{\text{pre}}\)：prefill 时每 token 激活的参数量；\(T_{\text{new}}\)：本次要 prefill 的 token 数。“2”来自一次乘加（M10 §1）。(19.3)

在输入重的负载里，\(T_{\text{new}}\) 远大于输出 token 数，所以哪怕命中率高达 97%，prefill 的计算仍然可以超过 decode（图 19.1 右）。要省这张账单，只有两条路：少 prefill 一些 token（前缀缓存），或者让每个 prefill 的 token 少激活一些参数。后者就是下一页的 CED。

第二张：容量。 活跃请求的全局 KV 必须待在 GPU 的 HBM 里，一张卡能同时服务多少个长请求，由 \(s_{\text{glob}}\) 决定；持久化 KV 存在 SSD 或主机内存里，能保存多少会话、保存多久，也由每 token 的字节数决定。

第三张：带宽。 缓存命中时，要把前缀的 KV 从 SSD 读回 HBM；prefill 和 decode 在不同机器上时（第 12 课 §8 的 PD 分离），prefill 算出的 KV 要经网络传给 decode 机器。搬运时间与字节数成正比。以图 19.1 的第 50 轮为例：命中的前缀有 \(137{,}600-2{,}000=135{,}600\) 个 token，V4-Flash 要读回 \(3{,}514.25\times135{,}600\approx4.77\times10^{8}\) 字节（454 MiB）的全局 KV，V4.1 只要 \(890\times135{,}600\approx1.21\times10^{8}\) 字节（115 MiB）。同一条链路上，这一轮的搬运时间也就差 3.95 倍。

因果编码器–解码器（CED）

第一张账单是 prefill 计算。前缀缓存已经让大部分输入 token 不必重算，剩下的每个新 token，按 (19.3) 要付 \(2N_{\text{act}}\) 次运算。V4.1 的回答是：让提示 token 只走前一半的层。这一页先弄清“为什么可以不走后一半”，再看 V4.1 为这个想法付出了什么代价（SWA 回放），最后从张量形状复算论文的“prefill 8B、decode 16B”。

问题：提示 token 在上半截的计算，是为谁算的？

先看普通的仅解码器（decoder-only）模型。一个提示 token（不是最后一个）在第 \(l\) 层算出的隐藏状态，只有两种用途：一是作为第 \(l+1\) 层的输入，继续往上走；二是在第 \(l\) 层投影出它的 K、V，供后面的 token做注意力。它自己在最顶层的输出，会被送进输出头预测“下一个 token”，但提示里的下一个 token 我们已经知道了，这个预测没人用。

为什么提示 token 必须走完所有层（在普通模型里）
(1)\(\displaystyle \operatorname{Head}\big(\mathbf h^{(L)}_j\big)\ \text{无人使用}\quad(j<T-1)\)提示里下一个 token 已知，prefill 只要最后一个位置的输出
(2)\(\displaystyle \mathbf u^{(l)}_t=\textstyle\sum_{j'\le t}a^{(l)}_{t,j'}\,\mathbf v^{(l)}_{j'},\qquad t>j\)后面的 token \(t\) 在第 \(l\) 层做注意力（\(a^{(l)}_{t,j'}\) 是它分给 \(j'\) 的注意力权重，由 \(\mathbf q^{(l)}_t\) 与 \(\mathbf k^{(l)}_{j'}\) 打分得到）；求和里含 \(j'=j\) 这一项，所以要读 \(j\) 在第 \(l\) 层的 K、V
(3)\(\displaystyle \mathbf k^{(l)}_j=W^K_l\,\mathbf h^{(l)}_j,\qquad \mathbf v^{(l)}_j=W^V_l\,\mathbf h^{(l)}_j\)普通模型里，每层的 KV 由本层自己的输入投影
(4)\(\displaystyle \mathbf h^{(l)}_j=f_{l-1}\big(\mathbf h^{(l-1)}_{0},\dots,\mathbf h^{(l-1)}_{j}\big)\)\(f_{l-1}\) 是第 \(l-1\) 层的整层计算；本层输入要等下面一层把 \(j\)（连同它看得见的位置）算完
(5)\(\displaystyle \{\mathbf k^{(l)}_j,\mathbf v^{(l)}_j\}_{l<L}\Rightarrow j\ \text{须走完层}\ 0,\dots,L-2\)对每一层重复上面三行：要最高层（层 \(L-1\)）的 KV，就得先有它的输入 \(\mathbf h^{(L-1)}_j\)；只有最顶层本身可以不跑，相差一层，下文按“走完 \(L\) 层”计

这条链里只有一环可以改：第 \(l\) 层的 KV 一定要由第 \(l\) 层自己的隐藏状态投影出来吗？如果上半截各层的 KV 改由某个中间层的隐藏状态投影，提示 token 走到中间层就可以停下。这正是 YOCO（You Only Cache Once）6 的想法，V4.1 的因果编码器–解码器（Causal Encoder-Decoder，CED）明确写着“受 YOCO 启发”1。

图景：二十楼的速记员

纪要本记在二十楼

映射。 把 40 层模型想成一栋 40 层的楼，每层楼有一位秘书（这一层的注意力），每个 token 是一位发言者。普通模型里，每位发言者要从一楼一路走到四十楼，每层楼的秘书都要当面听他讲一遍，才能在本层的纪要本（KV cache）上记下他的要点。CED 把楼分成两半：发言者只走到二十楼；二十楼有一位速记员，根据发言者走到这里时的样子（\(H_{L/2}\)），替上面二十层写好一份纪要（解码器的全局 KV）。二十一楼到四十楼的秘书不再见每一位发言者，只读这份纪要。

收益。 发言者少爬一半的楼，prefill 的计算就少一半；上半截的纪要只写一份，缓存也跟着省。

边界。 第一，二十楼的速记员只见过“走到一半”的发言者，写下的纪要比四十楼秘书当面记的“粗”：上半截能看到的上下文信息，全都来自中间层。这是一个容量上的限制，模型必须从预训练开始就学会在这种结构下工作（V4.1 就是从头这样训练的）。第二，每层楼除了厚厚的纪要本，还有一块只记最近 128 位发言者的小白板（SWA），白板必须由本层秘书当面听过才能写。这块白板让“只走到二十楼”不再那么干净，见本页后半的“回放”。

形式化：解码器的全局 KV 由编码器输出投影而来

论文的式 (1)（行向量写法，\(H_{L/2}\) 的每一行是一个 token 在层 19 输出处的隐藏状态）1：

CED：解码器层的 KV 条目直接由 \(H_{L/2}\) 投影\[C_{l}=H_{L/2}\,W_{l}^{KV},\qquad Z_{l}=H_{L/2}\,W_{l}^{Z},\qquad l>\frac{L}{2}\]\(C_l\)：第 \(l\) 层的 KV 条目（每行一个，既当键又当值）；\(Z_l\)：压缩时用的权重 logits（\(m=1\) 时不需要）。这个式子里的层号要按从 1 数起理解：\(l>\tfrac L2\) 指第 21–40 层，也就是本课（从 0 数）的层 20–39；\(H_{L/2}\) 是第 20 层的输出，即本课层 19 的输出（参考代码里，层 20 正是用它的输入算全局 KV）。形状：\(H_{L/2}\in\R^{T\times5120}\)，\(W_l^{KV},W_l^{Z}\in\R^{5120\times512}\)，所以 \(C_l,Z_l\in\R^{T\times512}\)（行向量写法把权重放在右边，它是 (19.5) 里列向量写法的权重的转置）。与普通模型的差别只在下标：右边是 \(H_{L/2}\)，不是 \(H_l\)。(19.4)

V4.1 实际的解码器全局 KV（\(m=1\)）\[\mathbf e_s=\RMSNorm\!\big(W^{KV}_{20}\,\mathbf h^{(20)}_s\big)\in\R^{512},\qquad W^{KV}_{20}\in\R^{512\times5120}\]对每个位置 \(s=0,\dots,T-1\) 各算一次。\(\mathbf h^{(20)}_s\in\R^{5120}\)：token \(s\) 进入层 20 时的隐藏状态，即编码器输出（经 mHC 的输入混合与注意力前的 RMSNorm）。之后最后 64 维按位置 \(s\) 加 RoPE，存成 FP4（§5）。这个形式按参考代码还原 4。(19.5)

对照 YOCO 的式 (2)(3) 6：它的上半截叫交叉解码器（cross-decoder），所有上层共用同一对 \(W_K,W_V\)，由第 \(L/2\) 层的输出一次性算出共享的 \(\hat K,\hat V\)；每个上层只有自己的查询 \(\hat Q^l=\operatorname{LN}(X^l)W_Q^l\)，对共享 KV 做因果交叉注意力，没有自注意力。

YOCO 的交叉解码器（对照）\[\hat K=\operatorname{LN}(X^{L/2})W_K,\quad \hat V=\operatorname{LN}(X^{L/2})W_V,\qquad Y^l=\operatorname{Attention}(\hat Q^l,\hat K,\hat V)+X^l\]\(X^{L/2}\)：下半截（自解码器，用滑动窗口等高效注意力）的输出。上半截每一层只读这一份 \(\hat K,\hat V\)，没有自己的 KV。(19.6)

两者放在一起看，V4.1 在“解码器只有一份全局 KV”这一点上回到了 YOCO；差别在于，V4.1 的每个解码层还保留着自己的 SWA 分支，而且那份全局 KV 是稀疏读取的（每个查询只选 512 条）。

CED 不是 T5 那样的编码器–解码器

T5 式模型的编码器读一段源序列（比如待翻译的句子），解码器生成另一段目标序列，并通过交叉注意力读编码器的输出。CED 的两半处理的是同一条 token 流，而且两半都是因果的：位置 \(t\) 只能看位置 \(\le t\)。名字里的“编码器”“解码器”只说明 prefill 时这一半跑不跑：编码器每个 token 都跑，解码器只为生成而跑。它是把一个仅解码器模型从中间切开，而不是换成另一种架构。

麻烦：解码器的每一层还有自己的 SWA

YOCO 的上半截只有交叉注意力，所以提示 token 可以在中间精确地“提前退出”：YOCO 摘要说，这种计算流让 prefill 提前退出而不改变最终输出 6。V4.1 的解码层却保留了 SWA。论文的说明是：对 SWA，CED 在所有层保持常规的逐层计算，这就需要一个 SWA 回放（replay）过程 1。

为什么？生成第一个输出 token 时，它在每个解码层 \(l\) 的 SWA 分支要读本层最近 128 个 token 的 SWA KV，也就是提示最后 128 个 token 在层 \(l\) 的 \(\mathbf k,\mathbf v\)。这些 KV 由它们在层 \(l\) 的隐藏状态 \(\mathbf h^{(l)}\) 投影而来，而 \(\mathbf h^{(l)}\) 只有真的把这些 token 送进解码器才算得出。更麻烦的是，SWA 的依赖会逐层向左扩散。

为什么截断是可以接受的？论文给了两条理由。一是全局信息不受影响：解码器的全局 KV (19.5) 来自编码器、对所有位置都是精确的，回放段里的每个 token 仍能通过稀疏的全局注意力看到整段上下文。二是 SWA 的有效感受野远小于理论上的 \(n_{\text{win}}\times L/2\)，论文引 PowerAttention 支持这一点 1,7。第二条需要打个折扣：PowerAttention 的结论是滑动窗口的感受野只随层数线性扩张、在远距离检索探针上表现很差，这和“有效感受野远小于理论值”方向一致，但不是同一个量；最直接的证据仍是 V4.1 自己的实验，而论文对此只给了定性描述。

代价与失败模式

解码更贵了一点。 decode 时每 token 激活 16B，比 V4-Flash 的 13B 多。上下文较短时，V4.1 的单 token 解码计算反而比 V4-Flash 高，§4 会算出交叉点约在 100K token。V4.1 的收益在 prefill、长上下文和存储，不在短对话的解码。

近似。 解码器的 SWA 状态是截断回放出来的，严格说它依赖“提示从哪里开始回放”。论文承认 SWA Bounded Replay 的近似状态重建可能在未测试的边界情形下造成能力退化 1；它给出的只有定性证据，没有公布消融数字。

容量。 解码器 20 层看到的全部远程信息都来自层 19 的输出。论文说 CED 在把 prefill 计算减少近一半的同时，保持了与基线相当的性能 1，但没有给出基线是什么、在多大规模上比较。

“prefill 只激活 8B，所以模型读提示时只用了一半的能力”

不准确。编码器 20 层完整处理每个提示 token；解码器通过 (19.5) 的全局 KV 看到提示的每个位置；提示最后 128 个 token 还会走完解码器。省掉的是“提示 token 在解码器里的计算”，而那部分计算的产物本来只有两样：它们自己的解码器 SWA KV（现在只为最后 128 个 token 回放），以及没人用的下一个 token 预测。

这一页的要点
  • 在普通模型里，提示 token 走完全部层，只是为了给高层提供 KV。CED 让解码器（层 20–39）的全局 KV 由编码器输出投影 (19.4)，在 V4.1 里实际只投影一份 (19.5)。
  • 与 YOCO 的差别：V4.1 的解码层保留自己的 SWA，所以要回放。精确回放需要约 \(\tfrac L2 n_{\text{win}}=2{,}560\) 个 token (19.7)；有界回放只要 128 个，代价是近似。
  • prefill 工作量 \(\rho(T)=\tfrac12+\tfrac{64}{T}\) (19.8)；按形状复算，prefill 激活约 8.2B、decode 约 16.5B (19.9)。

CSA2：跨层共享主 KV 与 top-k

第二张账单是 HBM 容量，也就是每个 token 的全局 KV 字节数 \(s_{\text{glob}}\)。V4-Flash 已经把它压到 3,514 字节，V4.1 还要再除以 4。这一页先把 3,514 拆成“哪几份、每份多大”，找出 V4 没碰过的那个维度；再看 CSA2 怎样在这个维度上动刀，以及它为此放弃了什么。

总公式：三个相乘的维度

含义。 V4.1 论文把 KV 的开销拆成三个相乘的维度 1：条目大小（GQA 减少 KV 头数、MLA 让各头共享一个小的潜在向量）、序列维（每 \(m\) 个 token 压成一个条目，如 V4 的 CSA 与 HCA）、层维（一些层复用别的层的缓存与选择，而不保留自己的一份，或者干脆被更省的层取代）。

理解。 想象一面墙上的书架。每本“书”是一个条目，书的厚度是条目字节数；每 \(m\) 个 token 才出一本书，所以书的数量是 \(T/m\)；而一共有几面这样的书架，取决于有多少层各自维护一份。总占地 = 厚度 × 本数 × 书架数。前几课省的都是前两项：MLA 让书变薄，CSA/HCA 让书变少。V4-Flash 却仍有 41 面书架。这个比喻在一处会误导人：41 面书架上的书并不是同一套书的 41 份复印件，每面书架是由不同的层、按各自的理解写的。拆掉书架不是删重复，而是让后面的层改读别人写的书，这笔代价在本页最后单独算。

数学。 设 \(\mathcal L_{\text{kv}}\) 是“自己存一份全局 KV”的层的集合（对应配置里的 kv_source_layer_ids），第 \(r\) 份的压缩比是 \(m_r\)，每个主 KV 条目 \(b_{\text{main}}\) 字节，每个索引器键条目 \(b_{\text{idx}}^{(r)}\) 字节（没有索引器的层为 0）。每 token 的全局 KV 字节数是

每 token 全局 KV 的总公式\[s_{\text{glob}}=\sum_{r\in\mathcal L_{\text{kv}}}\frac{b_{\text{main}}+b_{\text{idx}}^{(r)}}{m_r}\qquad\Big(\text{各份相同时}=\lvert\mathcal L_{\text{kv}}\rvert\times\frac1m\times(b_{\text{main}}+b_{\text{idx}})\Big)\]三个因子依次是层维（份数 \(\lvert\mathcal L_{\text{kv}}\rvert\)）、序列维（\(1/m\)）、条目大小（\(b\)，其中又包含维数与每个数的比特数）。(19.10)
第 18 课的 CSA，用到的部分读过第 18 课 §2–§4 的可以跳过

V4 的每个注意力层有两条分支。全局分支：先把相邻的 token 压成一个条目。CSA 每 \(m=4\) 个 token 出一个 \(c=512\) 维的条目 \(\mathbf e_i\)（它同时当键和值），做法是对这段 token 的投影按每个通道做 softmax 加权求和；V4 还让每个条目读 \(2m=8\) 个 token（与相邻条目重叠一半），并给块内位置加一个可学习的偏置。然后一个便宜的索引器（lightning indexer，第 14 课 §4）用自己的查询给每个压缩条目的索引器键打分，每个查询只取分数最高的 \(k_{\text{sel}}\) 个条目（V4-Flash 为 512）做注意力。HCA 则每 \(m=128\) 个 token 压一个条目，不打分、全部都看。局部分支：SWA，只看最近 \(n_{\text{win}}=128\) 个未压缩的 token。每个查询最终对“选中的全局条目 ∪ 窗口内的 SWA 条目”做一次注意力。V4-Flash 的 43 层是 2 层纯 SWA、21 层 CSA、20 层 HCA 3,5。细节见第 18 课 §2。

CSA2 相对 CSA 的三处简化

在动层维之前，V4.1 先把 CSA 本身改简单了。论文列出三处 1：

  1. 去掉重叠。 CSA 的每个条目由 \(2m\) 个原始 token 生成，相邻条目的来源重叠一半；CSA2 的每个条目只由自己那 \(m\) 个 token 生成。
  2. 去掉绝对位置嵌入。 CSA 在压缩时给块内的 \(2m\) 个位置各加一个可学习的偏置；CSA2 不加。
  3. 索引器键从主 KV 投影。 CSA 的索引器键有一条从隐藏状态出发的独立压缩路径；CSA2 直接把压缩好的主 KV 条目投影成索引器键。

论文说这两类改动都简化了实现、提高了训练效率 1。CSA2 还把“压缩比 \(m=1\)”（不压缩）当作一个特例包含进来：V4.1 解码器的 20 层全部是 \(m=1\)。论文没有写出 CSA2 的公式，下面两式按 V4.1 的参考代码还原 4。设第 \(l\) 层注意力的输入是 \(\mathbf h_j\in\R^{5120}\)（已做 RMSNorm），压缩比 \(m\in\{1,2\}\)：

CSA2 的压缩（按参考代码还原）\[\mathbf e_i=\RMSNorm\Big(\sum_{j=mi}^{m(i+1)-1}\mathbf s_j\odot W^{KV}\mathbf h_j\Big),\qquad [\mathbf s_j]_r=\frac{\exp([W^{Z}\mathbf h_j]_r)}{\sum_{j'=mi}^{m(i+1)-1}\exp([W^{Z}\mathbf h_{j'}]_r)}\]\(W^{KV},W^Z\in\R^{512\times5120}\)；softmax 对组内 \(m\) 个 token、每个通道 \(r\) 各做一次。\(m=1\) 时权重恒为 1，退化成 \(\mathbf e_i=\RMSNorm(W^{KV}\mathbf h_i)\)，即 (19.5)。之后最后 64 维按组内第一个 token 的位置 \(mi\) 加 RoPE。与 V4 的 CSA 相比，少了第二路候选（V4 用它让条目 \(i\) 还读前一块的 \(m\) 个 token，相邻条目因此重叠）和块内位置偏置。(19.11)
逐通道 softmax：两个 token 压成一个条目（\(m=2\)，只看 3 个通道）

为了能手算，只取 3 个通道，数是笔者设的。组内两个 token 的压缩权重 logits 与候选值：

通道 1 通道 2 通道 3
token 0：\(W^Z\mathbf h_0\) 2 0 −1
token 1：\(W^Z\mathbf h_1\) 0 0 1
token 0：\(W^{KV}\mathbf h_0\) 1 2 3
token 1：\(W^{KV}\mathbf h_1\) 3 −2 1

每个通道各做一次 softmax。 通道 1：token 0 得 \(e^2/(e^2+e^0)=0.881\)，token 1 得 0.119；通道 2：两个 logits 相等，各得 0.5；通道 3：token 0 得 \(e^{-1}/(e^{-1}+e^{1})=0.119\)，token 1 得 0.881。

加权求和。 通道 1：\(0.881\times1+0.119\times3=1.238\)；通道 2：\(0.5\times2+0.5\times(-2)=0\)；通道 3：\(0.119\times3+0.881\times1=1.238\)。

RMSNorm。 均方根 \(\sqrt{(1.238^2+0^2+1.238^2)/3}=1.011\)，除以它得 \(\mathbf e\approx(1.225,\,0,\,1.225)\)（这里取 \(\boldsymbol\gamma=\mathbf 1\)）。

看每个通道各自“听”谁：通道 1 主要听 token 0，通道 3 主要听 token 1，通道 2 两个各听一半。如果每个 token 只配一个标量权重，所有通道只能按同一个比例混合，做不到这一点。失败模式出在通道 2：两个 token 在这个通道上的值正好相反，一平均就成了 0，条目里再也看不出它们原来不同。每 \(m\) 个 token 只留一个条目，这类信息损失无法完全避免；\(m=1\) 时每个条目只来自一个 token，没有这种损失，V4.1 解码器那一份全局 KV 用的正是 \(m=1\)。

索引器键与索引分数\[\begin{aligned}\mathbf k^I_i&=\operatorname{RoPE}\big(\RMSNorm(W^{IK}\,\mathbf e_i)\big)\in\R^{128}\\ I_{t,s}&=\sum_{j=1}^{H^I}w^I_{t,j}\,\operatorname{ReLU}\big(\mathbf q^{I\top}_{t,j}\,\mathbf k^I_s\big),\qquad \mathcal S_t=\TopK_{k_{\text{sel}}}\big(I_{t,:}\big)\end{aligned}\]\(W^{IK}\in\R^{128\times512}\) 作用在加 RoPE 之前的 \(\mathbf e_i\) 上；\(H^I=32\) 个索引器头，\(\mathbf q^I_{t,j}\in\R^{128}\) 是查询 \(t\) 的第 \(j\) 个索引器查询，\(w^I_{t,j}\) 是它的头权重；\(k_{\text{sel}}=512\)。代码里 \(w^I_{t,j}\) 还乘了常数 \(1/(\sqrt{128}\sqrt{32})\)。(19.12)

索引器键现在只是主 KV 的一个“128 维摘要”，不再需要另一套压缩器，这也让下一节的跨层共享变得干净：共享主 KV 时，索引器键可以跟着一起共享。

三种模式：Full、Reindex、Reuse

CSA2 的每一层被静态地指定为三种模式之一 1：

  • Full：本层计算自己的主 KV 与索引器查询，由主 KV 投影出索引器键，运行索引器，得到新的 top-k。它就是一个完整的 CSA 层。
  • Reindex：复用前面最近一个 Full 层的主 KV 和对应的索引器键；本层的索引器计算自己的查询，给复用来的键重新打分，得到新的 top-k。
  • Reuse：复用最近可用的主 KV，以及前面最近一个 Full 或 Reindex 层算出的 top-k；本层不算索引器查询，也不打分，直接按这份选择做注意力。

三种模式里，每一层都保留自己的主查询和自己的 SWA KV 1。论文的小结一句话说清了分工：共享主 KV 和索引器键减少缓存存储，复用 top-k 索引省掉额外的索引器计算。

模式 主 KV + 索引键 索引器查询与打分 top-k 索引 主 Q、SWA KV
Full 本层算，写入缓存 本层算 本层产出 本层算
Reindex 借最近的 Full 层 本层算 本层产出 本层算
Reuse 借最近的 Full 层 不算 借最近的 Full/Reindex 层 本层算
目录与书架，接力着用

映射。 沿用第 14 课的类比：稀疏注意力是“先查目录再精读”。Full 层自己往书架上放书（主 KV），自己编目录（索引器键），再拿自己的问题（索引器查询）查目录、挑出 512 页。Reindex 层的书架和目录都是借前面 Full 层的，但它拿自己的问题重查一遍目录，所以可能挑出不同的页。Reuse 层连页码都借，直接去读前一位挑好的那 512 页。无论哪种，读的人都是本层自己（主 Q），手边还有一块只属于本层的小白板（SWA）。

收益。 书架只要四面（存储省在层维），查目录的次数也从 38 次降到 8 次（计算省在索引器）。

边界。 书架上的书是某一层根据它那一层的理解写下的；后面的层即使有了新的理解，也没法往共享的书架上补写，只能靠自己的查询和白板来弥补。Reuse 层失去了“按自己的问题挑页”的自由：如果它真正需要的内容不在前一位挑的 512 页里，它就读不到。论文在局限里明确提到 CSA2 可能的选择错误 1。

逐层配置：4 层写 KV，8 层打分

V4.1-Flash 有 40 层，隐藏维 \(d=5120\) 1。论文 §4.2.1 与配置文件给出的布局是：

  • 编码器：前两层是纯 SWA；其余 18 层是 \(m=2\) 的 CSA2，分成三组，每组 6 层：第一层 Full，其余 5 层 Reuse。
  • 解码器：20 层全是 \(m=1\) 的 CSA2，分成五组，每组 4 层。第一组：第一层 Full，其余 3 层 Reuse；后四组：第一层 Reindex，其余 3 层 Reuse。

配置文件里对应三个字段：kv_source_layer_ids: [2, 8, 14, 20]（写全局 KV 的层）、index_source_layer_ids: [2, 8, 14, 20, 24, 28, 32, 36]（跑索引器的层），以及 compress_ratios（逐层压缩比）4。数一数：纯 SWA 2 层、Full 4 层、Reindex 4 层、Reuse 30 层。论文说“绝大多数 Transformer 层（即 CSA2 处于 Reuse 模式的那些层）”在 prefill 时只需 15 个内核、decode 时 11 个 1，这里的“绝大多数”就是 30/40 = 75%。

数配置文件时的两个坑

compress_ratios 数组有 43 项，不是 40：最后 3 个 0 属于 DSpark 的三个草稿块，不是主干层（V4-Flash 的数组有 44 项，最后一项属于 MTP 层）。另外 num_key_value_heads: 1 说的是“所有查询头共享一份 KV”的 MQA 形态，不是“一个 GQA 组”。

890 字节是怎么来的

现在可以把 (19.10) 用在 V4.1 上了。主 KV 条目从 V4 的 584 字节换成了 FP4 的 288 字节（§5 细讲），索引器键仍是 68 字节；存 KV 的只有层 2、8、14、20 四份。

假设 38 个 CSA2 层（18 个 \(m=2\)、20 个 \(m=1\)）每层都存自己的主 KV 与索引器键：

这是 890 的 11.6 倍，甚至是 V4-Flash（3,514.25）的 2.9 倍。原因是 V4.1 的压缩比更小：V4 用 4 和 128，V4.1 用 2 和 1，每一份其实“压得更少”。V4.1 的全局 KV 之所以只有 890 字节，全靠层维共享把 29 份扳回到 2.5 份。

“CSA2 用某种模式取代了 HCA”

CSA2 没有“重压缩”模式，V4.1 的压缩比反而变小了。V4 里 HCA 承担的是“以很低的成本对整段上下文做稠密注意力”；在 V4.1 里，这个角色被“每层固定读 512 个选中条目 + 128 个 SWA 条目”的纯稀疏注意力取代了。论文原话是：V4 用 CSA–HCA 混合架构，V4.1-Flash 用纯 CSA2 1。

层维度的前人工作，以及 CSA2 多做的一步

“层与层共享缓存”不是 V4.1 首创。V4.1 论文自己列出了几条先例，并指出各自的不足 1：

  • CLA（Cross-Layer Attention）让相邻层共享同一份 KV 9，是 V4.1 论文为“层维度”举的先例。
  • IndexCache 让多数层复用前面层的 top-k 索引 10，省了索引器计算，但论文指出单纯复用索引不省主 KV 存储。
  • YOIO 全网只算一次稀疏路由、所有层共享 11，论文认为这种全网共享限制了性能。
  • HySparse 让稀疏层复用稠密层的 KV 12，但仍保留全注意力层。

论文的判断是：这些方法都没有同时覆盖三个维度。CSA2 的做法是把“共享 KV 存储”与“共享 top-k 选择”解耦：Reindex 层共享 KV 但重新选择，Reuse 层两样都共享。这样，存储由 Full 层的数目决定（4），打分次数由 Full + Reindex 层的数目决定（8），两件事可以分别调。

代价与失败模式

  • 选择错误。 Reuse 层用的是别人的 top-k。论文在局限里写明，CSA2 潜在的选择错误可能在未测试的边界情形下造成能力退化，今后会特别关注长上下文里的稀疏检索 1。
  • 共享的 KV 只有一种“视角”。 解码器 20 层读的是同一份由层 19 输出投影的 KV（§2）；编码器每 6 层读同一份。深层能看到的远程信息，受限于写 KV 那一层的表示。
  • 质量证据以整体结果为主。 论文用基座模型的整体评测说明没有掉点（§8），没有单独给出“每组 6 层 vs 每组 4 层”之类的消融。
这一页的要点
  • 每 token 全局 KV = 份数 × \(\frac1m\) × 每条目字节 (19.10)。V4-Flash 的 3,514.25 B 里 97% 来自 21 份 CSA，层维一点没省。
  • CSA2 先简化 CSA（去重叠、去位置偏置、索引器键从主 KV 投影，(19.11)(19.12)），再引入 Full / Reindex / Reuse 三种模式，把“共享 KV”与“共享 top-k”解耦。
  • V4.1：4 份全局 KV（层 2、8、14 的 \(m=2\)，层 20 的 \(m=1\)），\(2.5\times356=890\) B；不共享的话是 10,324 B。

分层稀疏索引器与解码计算

CSA2 让每层的核心注意力只读固定数量的条目，存储也只剩 4 份。那么解码一个新 token 时，还有什么随上下文长度 \(T\) 增长？答案是索引器打分：每个跑索引器的层都要给全部可见条目各打一次分。这一页讲 V4.1 怎样把后几个索引器的打分从“正比于 \(T\)”变成常数，并用论文图 2 的数字看解码计算到底有多平。

问题：8 个索引器，每个都要扫全部条目

解码一个新 token（位置 \(T\)）时，数一数每层要打多少分：

  • 层 2、8、14（编码器的 Full 层，\(m=2\)）：各扫 \(T/2\) 个条目，共 \(1.5T\)。
  • 层 20（解码器的 Full 层，\(m=1\)）：扫 \(T\) 个。
  • 层 24、28、32、36（Reindex）：如果也各扫全部，共 \(4T\)。

合计 \(6.5T\)。其中 Reindex 的 \(4T\) 占了六成，而它们打分的对象，正是层 20 刚刚打过一遍分的同一批键。能不能让后面的层只在“层 20 觉得有希望”的范围里找？

机制：先按块圈出候选池，再在池里选

含义。 分层稀疏索引器（Hierarchical Sparse Indexer）只用在解码器里：解码器的第一个 Full 层（层 20）为每个查询构造一个候选池，后面的 Reindex 层只在池里重新打分 1。

理解。 层 20 把所有位置按 8 个一组分块，每一块取块内最高的索引分数作为“块分”，挑出块分最高的 2,048 块，这 16,384 个位置就是候选池。后面每个 Reindex 层还是用自己的查询打分、自己选 top-512，只是只在这 16,384 个位置里选。用目录的比喻：层 20 先把整本目录粗翻一遍，把有希望的章节折角；后面的人只在折角的章节里细查。

数学。 记层 20 的索引分数为 \(I^{(20)}_{t,s}\)，块 \(b\) 包含位置 \(\mathcal B_b=\{8b,\dots,8b+7\}\)：

块分、候选池与池内选择\[\begin{aligned}\beta_{t,b}&=\max_{s\in\mathcal B_b}I^{(20)}_{t,s},\qquad \mathcal P_t=\bigcup_{b\in\TopK_{2048}(\beta_{t,:})\,\cup\,\{b_{\text{new}}\}}\mathcal B_b\\ \mathcal S^{(l)}_t&=\TopK_{512}\big(\{I^{(l)}_{t,s}:s\in\mathcal P_t\}\big)\end{aligned}\]\(l\in\{24,28,32,36\}\)；\(\lvert\mathcal P_t\rvert\le2{,}048\times8=16{,}384\)（再加一块）。\(b_{\text{new}}\) 是包含最新位置的那一块，参考代码把它强制放进池里，注释给的理由是：它装着最新的 token，却可能因为还没填满而被更老、更满的块比下去 4。(19.13)
候选池一定包含层 20 自己选中的 512 个位置
(1)\(\displaystyle s^\star\in\mathcal S^{(20)}_t,\quad s^\star\in\mathcal B_{b^\star},\quad \tau=\text{层 20 的第 512 高分}\)记号：\(s^\star\) 是层 20 自己选中的任一位置，落在块 \(b^\star\) 里
(2)\(\displaystyle \beta_{t,b^\star}\ge I^{(20)}_{t,s^\star}\ge\tau\)块分取块内最大值
(3)\(\displaystyle \#\{b:\beta_{t,b}\ge\tau\}\le512\)块分 \(\ge\tau\) 意味着块内至少有一个分数 \(\ge\tau\) 的位置，而这样的位置只有 512 个（不计并列）
(4)\(\displaystyle 512\le2{,}048\ \Rightarrow\ b^\star\in\TopK_{2048}(\beta_{t,:})\)所以每个被选位置所在的块都进了候选池

这条性质说明候选池不会“漏掉”层 20 自己认为最重要的内容；Reindex 层在池内可以换一批位置，但搜索范围是层 20 认可过的 1.56%（1M 上下文时）。

失败模式正是这条性质的反面。 候选池只保证层 20 的 top-512 在里面，不保证后面各层需要的位置在里面。如果层 36 真正需要的某个位置，所在的 8 个位置在层 20 眼里分数都不高（块分排不进前 2,048），层 36 无论怎样打分都选不到它。候选池有 16,384 个位置，是 top-512 的 32 倍，多出来的部分就是给“层 20 不看好、后面的层却需要”的内容留的余量；这个余量够不够，论文没有给出消融。“折角”的比喻在这里也到了边界：后面的人只能在折过角的章节里细查，没折角的那一章，他们连翻都不会翻。

这个机制有三点限定。第一，它是训练感知的，在后训练阶段引入，训练与推理用同样的候选限制；第二，层 20 自己仍然扫描全部因果可见的范围；第三，它只用在解码器里 1。编码器里 Full 层之后全是 Reuse 层，没有 Reindex 层可以省（这是笔者对“只用在解码器”的解释，论文没有展开）。先例是 HISA，它先用池化的块表示打分剪枝、再在保留的块里做 token 级索引 13；V4.1 的差别在于块分直接取上一层 token 级分数的最大值，不增加任何额外状态。

每个解码 token 要打多少分

1M 上下文（\(T=2^{20}=1{,}048{,}576\)）：

  • 有分层：\(1.5T+T+4\times16{,}384=1{,}572{,}864+1{,}048{,}576+65{,}536=2{,}686{,}976\) 次。
  • 没有分层（Reindex 也全扫）：\(6.5T=6{,}815{,}744\) 次，是前者的 2.54 倍。
  • V4-Flash：21 个 CSA 层各扫 \(T/4\)，共 \(5.25T=5{,}505{,}024\) 次；它的索引器有 64 个头，V4.1 只有 32 个。乘上头数：V4.1 \(2{,}686{,}976\times32=8.60\times10^7\)，V4-Flash \(5{,}505{,}024\times64=3.52\times10^8\)，V4.1 少 4.1 倍。

128K 上下文（\(T=131{,}072\)）：有分层 393,216 次，没有分层 851,968 次。

FP4 主 KV 缓存

到这里，结构已经省到头了：4 份全局 KV，每个 token 摊到 2.5 个条目。可如果每个主 KV 条目仍用 V4 的 584 字节格式，全局 KV 是 \(2.5\times(584+68)=1{,}630\) 字节，离 890 还差 1.83 倍。剩下的这一截，靠把主 KV 的每个数从 8 比特压到 4 比特。这一页讲 FP4 是什么、V4.1 为什么给主 KV 和索引器选了两种不同的 FP4、以及为什么敢省掉“全局缩放”。

出发点：V4 的 584 字节

V4 的主 KV 条目是 512 维：前 448 维存成 FP8（每维 1 字节），最后 64 维是带 RoPE 的位置分量，存成 BF16（每维 2 字节），再加 8 字节的缩放行（7 个 E8M0 缩放，每个管 64 个 FP8 数，外加 1 字节填充）3,8。V4 论文说这种混合表示比纯 BF16 存储把 KV cache 缩小了近一半 3：纯 BF16 是 \(512\times2=1{,}024\) 字节，\(584/1{,}024=57\%\)。

四种小浮点：FP8（E4M3）、FP4（E2M1）、E8M0、BF16读过数学课 M08 的可以跳过

一个浮点数由符号位、指数位、尾数位组成，写法 E\(x\)M\(y\) 表示 \(x\) 位指数、\(y\) 位尾数。

  • E4M3（FP8）：1 + 4 + 3 = 8 位。最大值 448，最小的非零值（次正规数）\(2^{-9}\approx0.00195\)。
  • E2M1（FP4）：1 + 2 + 1 = 4 位，一个字节装两个。非负值只有 8 个（7 个正值加 0）：\(\{0,\,0.5,\,1,\,1.5,\,2,\,3,\,4,\,6\}\)，加上负号共 15 个不同的值。
  • E8M0：8 位全是指数、没有尾数、没有符号，只能表示 2 的整数次幂。专门用来当缩放因子。
  • BF16：1 + 8 + 7 = 16 位，动态范围与 FP32 相同，精度只有 2 到 3 位十进制有效数字。 FP4 只有 15 个值，直接存一个任意实数是不可能的；实用的做法永远是“一小块数共用一个缩放因子”。各格式的全部取值见 M08 §3，MXFP4 与 NVFP4 见 M08 §7。

块量化：短尺子加分段放大镜

含义。 把 512 维的主 KV 条目切成 32 块，每块 16 个数。每块存 16 个 E2M1 编码和 1 个 E4M3 缩放因子；读的时候把编码乘回缩放因子，这叫反量化（dequantization）。

理解。 用本课程的第 8 个类比：低精度数值是一把刻度很少的短尺子，缩放因子是给每一小段配的放大镜。E2M1 这把尺子只有 0、0.5、1、1.5、2、3、4、6 这几道刻度；如果一块数的最大值是 2.2，就先配一个倍数 0.375 的放大镜，让 2.2 落在尺子的最末端 6 附近（\(2.2/0.375\approx5.87\)），这一块的其他数也就落在刻度比较密的区间里。块越小，放大镜配得越密，同一块里大小悬殊的数越少。边界：放大镜只能整体缩放一整块；同一块里如果一个数是 2.2、另一个是 0.015，后者除以 0.375 只有 0.04，会被量成 0。

数学。 V4.1 的参考代码是这样做的 4：

主 KV 的块量化与反量化（每块 16 个数）\[s=\operatorname{RNE}_{\text{E4M3}}\Big(\frac{\max_{i}\lvert x_i\rvert}{6}\Big),\qquad q_i=\operatorname{RNE}_{\text{E2M1}}\Big(\frac{x_i}{s}\Big),\qquad \hat x_i=s\,q_i\]\(i=1,\dots,16\) 是块内的编号。\(\operatorname{RNE}_{\mathcal F}\)：舍入到格式 \(\mathcal F\) 里最近的值（一样近时取尾数为偶数的那个）。除以 6 是为了让块内最大的数正好落在 E2M1 的最大值 6 附近。代码还把 \(\max_i\lvert x_i\rvert\) 的下限钳到 \(6\times2^{-9}\)，保证全零的块缩放因子也不为零。(19.15)
每个条目的字节数与每维比特数\[b_{\text{main}}=\underbrace{\frac{512\times4}{8}}_{\text{E2M1 编码}}+\underbrace{\frac{512}{16}\times1}_{\text{E4M3 缩放}}=256+32=288\ \text{字节},\qquad \frac{288\times8}{512}=4.5\ \text{比特/维}\]对比 V4：\(584\times8/512=9.125\) 比特/维。\(288/584=0.493\)，论文说“近乎减半”1。(19.16)
手算一个 16 维块

取一个 16 维块 \(\mathbf x\)，16 个分量依次是 0.089、−0.634、1.29、0.298、−2.2、0.052、0.492、−0.902、0.246、1.566、−0.358、0.679、−0.015、0.783、−1.223、0.433（也就是下表每组的第一行）。

两种 FP4：主 KV 用 E4M3 缩放，索引器用 MXFP4

V4.1 里有两处 FP4，格式不一样 1：

  • 索引器（V4 已经如此）：用 OCP 标准的 MXFP4，即 E2M1 元素 + 每 32 个数一个 E8M0 缩放 14。论文的理由是“尽可能支持更多的硬件平台”，并坦白说在他们的实验里别的格式其实更准。
  • 主 KV（V4.1 新增）：E2M1 + 每 16 个通道一个 E4M3 缩放，这是 NVFP4 的做法，但去掉了 NVFP4 的第二级全局缩放。

为什么两处要不一样？因为用途不一样。索引器的打分是真正的 FP4 矩阵乘法，缩放格式必须是硬件矩阵单元原生支持的，所以只能选标准格式。主 KV 只是存储：论文说，在注意力之前把缓存值反量化，就可以用更准的格式，而不需要这种格式有原生的矩阵乘支持 1。FlashMLA 的说明也是这样：内核把缓存解回 BF16，再用 BF16 做注意力计算 8。

E8M0 缩放为什么更粗？它只能取 2 的幂，参考代码把它向上取到 2 的幂，保证块内最大值除以缩放后不超过 6 4。上面那个块：\(2^{\lceil\log_2 0.3667\rceil}=2^{-1}=0.5\)，于是 \(2.2/0.5=4.4\)，块内最大的数只用到刻度 4，E2M1 最上面那一截（4 到 6）空着没用。缩放从 0.375 变成 0.5，尺子上每一道刻度对应的实际间距都放大了 \(0.5/0.375=1.33\) 倍，块里的每个数都被量得更粗。

同一块改用 MXFP4 的缩放

\(s=0.5\)：编码依次是 0、−1.5、3、0.5、−4、0、1、−2、0.5、3、−0.5、1.5、−0、1.5、−2、1，相对 RMSE \(12.09\%\)，最大单点误差 0.223（\(-1.223\to-1\)）。比 E4M3 缩放的 8.91% 差了约三分之一。

笔者用 2,000 个单位 RMS 的高斯向量（每个 512 维）做了同样的比较：E2M1 + 每 16 个一个 E4M3 缩放的相对 RMSE 约 9.5%，MXFP4（每 32 个一个 E8M0）约 11.5%，而 V4 的格式（448 维 FP8 + 每 64 个一个 E8M0 缩放，64 个 RoPE 维用 BF16，几乎无误差）约 2.5%。真实 KV 的分布不是高斯，这组数只说明几种格式的相对精度，方向与论文“别的格式更准”一致。

每个数错 9%，注意力分数错多少

8.91% 的逐元素误差听起来很大，自然要问：注意力还能用吗？主 KV 在注意力里只有两种用法，一是和查询做点积打分，二是按注意力权重对选中的条目加权求和。两者都是把很多个数加在一起，而互相独立的舍入误差在求和里会抵消掉一部分。下面用一个粗糙的模型估一估（笔者的推算，论文没有给）。

打分误差的粗估
(1)\(\displaystyle \hat{\mathbf e}=\mathbf e+\boldsymbol\delta,\quad \operatorname{rms}(\boldsymbol\delta)=\epsilon\,\operatorname{rms}(\mathbf e)\)\(\boldsymbol\delta\in\R^{512}\) 是量化误差，\(\epsilon\) 是上面例题里的相对 RMSE
(2)\(\displaystyle \mathbf q^\top\hat{\mathbf e}-\mathbf q^\top\mathbf e=\textstyle\sum_{r=1}^{512}q_r\delta_r\)\(\mathbf q\in\R^{512}\) 是某一个查询头；打分误差是 512 项之和
(3)\(\displaystyle \operatorname{std}\Big(\textstyle\sum_r q_r\delta_r\Big)=\lVert\mathbf q\rVert_2\,\operatorname{rms}(\boldsymbol\delta)\)假设各 \(\delta_r\) 零均值、方差相同（都是 \(\operatorname{rms}(\boldsymbol\delta)^2\)）、互相独立、与 \(\mathbf q\) 无关；独立项相加时方差相加，得 \(\sum_r q_r^2\operatorname{rms}(\boldsymbol\delta)^2\)
(4)\(\displaystyle =\epsilon\,\lVert\mathbf q\rVert_2\,\lVert\mathbf e\rVert_2/\sqrt{512}\)均方根等于长度除以 \(\sqrt{512}\)：\(\operatorname{rms}(\mathbf e)^2=\tfrac1{512}\sum_r e_r^2=\lVert\mathbf e\rVert_2^2/512\)
(5)\(\displaystyle \dfrac{\operatorname{std}}{\lVert\mathbf q\rVert_2\lVert\mathbf e\rVert_2}=\dfrac{\epsilon}{\sqrt{512}}\approx0.42\%\)分母 \(\lVert\mathbf q\rVert_2\lVert\mathbf e\rVert_2\) 是打分能达到的最大值（两者方向完全一致时）；代入 \(\epsilon\approx0.095\)、\(\sqrt{512}\approx22.6\)
用模拟核对粗估

笔者用 400 对随机高斯向量（每个 512 维）做了模拟：把 \(\mathbf e\) 按 (19.15) 量化，逐元素相对 RMSE 平均 9.5%，打分误差的均方根是 \(\lVert\mathbf q\rVert_2\lVert\mathbf e\rVert_2\) 的约 0.42%（换 6 个随机种子，落在 0.40%–0.43% 之间），与粗估的 0.42% 相符。

换成注意力的语言：一个与查询方向很接近、真正会分到大权重的条目（夹角余弦接近 1），分数只被扰动约 0.4%；夹角余弦只有 0.1 的条目，分数的相对扰动约 4%，但它的分数本来就小，softmax 之后分到的权重也小。加权求和那一步同理：输出是 640 个值向量的加权平均，各条目的误差也会部分抵消。

失败模式。 粗估依赖“误差独立”，而块量化的误差可能并不独立：误差和数值本身相关（一个小数被量成 0，误差恰好是它的相反数），一块里有离群值时，其余 15 个数都被量得很粗。如果某个查询恰好依赖这些小分量，误差就不会在求和里相消。所以这个粗估只说明“逐元素错 9% 不等于注意力错 9%”，不能代替实验；V4.1 的做法是在后训练里做量化感知训练，让模型适应这种误差 1。

为什么敢省掉全局缩放

NVFP4 在“每 16 个一个缩放”之上还有一个全张量的 FP32 缩放，用来扩大动态范围。V4.1 省掉了它，理由是主 KV 的数值被 RMSNorm 管住了，根本用不到那么大的范围 1。

下面的推导用到的三件向量小事熟悉范数与正交矩阵的可以跳过
  • 范数与均方根。 \(\lVert\mathbf x\rVert_2=\sqrt{\sum_r x_r^2}\) 是向量的长度（M01 §1）；均方根 \(\operatorname{rms}(\mathbf x)=\sqrt{\tfrac1d\sum_r x_r^2}=\lVert\mathbf x\rVert_2/\sqrt d\) 是“每个分量平均有多大”。两式相除就得到 \(\lVert\mathbf x/\operatorname{rms}(\mathbf x)\rVert_2=\sqrt d\)。
  • 单个分量不超过长度。 \(x_r^2\le\sum_{r'}x_{r'}^2\)，两边开方得 \(\lvert x_r\rvert\le\lVert\mathbf x\rVert_2\)；只有其余分量全为 0 时才取等号。
  • 旋转不改长度。 RoPE 是一串二维旋转，旋转矩阵是正交矩阵，正交矩阵保持长度（M03 §1）。
主 KV 的每个分量都不超过约 22.6
(1)\(\displaystyle \mathbf e=\boldsymbol\gamma\odot\dfrac{\mathbf y}{\operatorname{rms}(\mathbf y)},\quad \operatorname{rms}(\mathbf y)=\sqrt{\tfrac1{512}\textstyle\sum_r y_r^2}\)主 KV 在压缩后做 RMSNorm (19.11)，\(\boldsymbol\gamma\) 是可学习的逐通道权重
(2)\(\displaystyle \Big\lVert\dfrac{\mathbf y}{\operatorname{rms}(\mathbf y)}\Big\rVert_2=\sqrt{512}\)除以均方根后，512 个分量的平方和恰好是 512
(3)\(\displaystyle \lVert\mathbf e\rVert_2\le\max_r\lvert\gamma_r\rvert\cdot\sqrt{512}\approx\sqrt{512}\approx22.6\)每个分量至多被 \(\gamma_r\) 放大 \(\max_r\lvert\gamma_r\rvert\) 倍，长度也至多放大这么多；论文：训练出的 RMSNorm 权重最大约为 1
(4)\(\displaystyle \lVert\operatorname{RoPE}(\mathbf e)\rVert_2=\lVert\mathbf e\rVert_2\)RoPE 是一串二维旋转，旋转不改变长度（第 5 课）
(5)\(\displaystyle \max_r\lvert e_r\rvert\le\lVert\mathbf e\rVert_2\lesssim22.6\ll448\times6=2{,}688\)单个分量不会超过整个向量的长度；E4M3 缩放最大 448，乘 E2M1 最大 6

上界 22.6 离格式能表示的 2,688 还差两个数量级，论文还报告训练中观察到的最大幅值只有约 10 1。所以只靠每块的 E4M3 缩放就够了，二级全局缩放是多余的。下界那一侧，E4M3 最小的次正规数是 \(2^{-9}\)，代码把缩放钳在它之上（见 (19.15) 的说明）。

三个细节：RoPE 之后量化、RoPE 维也量化、SWA 仍用 FP8

  1. 先加 RoPE，再量化。 论文说，在 RoPE 之前量化只带来“边际的”精度提升，还会在解码时增加开销 1。论文没有展开这笔开销，笔者的理解是：如果缓存里存的是旋转之前的值，每次读出来都要再按位置旋转一遍。
  2. RoPE 维也量化。 V4 为了保护位置信息，把 64 个 RoPE 维单独用 BF16 存；V4.1 的主 KV 让非 RoPE 维和 RoPE 维用同一种格式 1。这 64 维原来要 128 字节，现在只要 \(32+4=36\) 字节。
  3. SWA KV 仍是 FP8。 论文说 SWA KV 对量化敏感，所以保留 FP8 1。V4.1 的 SWA 条目是 512 个 FP8（RoPE 维也量化）加 16 个 E8M0 缩放（每 32 个一个），共 528 字节 8。它是每请求的常数，不影响每 token 的 890。

FP4 不是一开始就训练的：主 KV 的量化感知训练（quantization-aware training，QAT）在后训练阶段引入 1。也就是说，预训练时主 KV 不经过 FP4 量化，后训练时才让模型适应 FP4 的舍入误差。

“FP4 KV 意味着注意力用 FP4 算”

不对。主 KV 只以 FP4 存储，进入注意力之前在片上反量化；FlashMLA 的说明是把缓存解回 BF16、以 BF16 计算 8。真正做 FP4 矩阵乘的只有索引器的打分，所以它才必须用硬件广泛支持的 MXFP4。V4.1 的稀疏解码内核目前只支持 SM100 架构的 GPU 8。

FP4 的代价说不清

论文对 FP4 主 KV 的质量影响只有定性描述，没有给出消融数字；“RoPE 前量化只有边际提升”也没有数字。块量化的典型失败是块内离群值：一块 16 个数里有一个特别大，缩放就被它拉大，其余 15 个数都被量得很粗，接近 0 的会直接变成 0。每 16 个一个缩放（而不是 32 个）正是为了减少这种情形。

这一页的要点
  • 主 KV 条目从 V4 的 584 字节（448 FP8 + 64 BF16 + 缩放）变成 288 字节（512 个 E2M1 + 32 个 E4M3 缩放）(19.16)，每维 4.5 比特。
  • 块量化 (19.15)：缩放 \(s=\text{E4M3}(\max\lvert x\rvert/6)\)，编码 \(q=\text{E2M1}(x/s)\)。一个 16 维块的例子相对误差 8.91%；换成 MXFP4 的 2 的幂缩放是 12.09%。
  • 逐元素约 9% 的误差在 512 维点积里会部分抵消：若误差独立，打分误差约为最大分数的 \(\epsilon/\sqrt{512}\approx0.4\%\)（笔者的粗估）。
  • 主 KV 只存储、先反量化再计算，所以可以选更准的非标准格式；索引器要直接做 FP4 矩阵乘，只能用 MXFP4。RMSNorm + RoPE 把每个分量限制在约 22.6 以内，二级全局缩放多余。
  • 结构把 3,514 降到 1,630，精度再把 1,630 降到 890。

持久化 KV 与 SWA Bounded Replay

前三页处理的是 HBM 里的全局 KV。这一页转向第三张账单：为了前缀复用而长期保存的持久化 KV，它占的是 SSD（或主机内存）的容量，读回来还要占传输带宽。V4.1 在这里做的不是新架构，而是一个部署上的决定：SWA 状态不再落盘。要让这个决定可行，需要一种便宜的办法在 SWA 状态丢失时把它补回来，这就是 SWA Bounded Replay（有界回放）。

V4 的做法：SWA 状态和全局 KV 一起存进 SSD

问题。 前缀命中时，全局 KV 可以从缓存里读回，但接着 prefill 新输入的第一个 token，每一层的 SWA 分支都要看前面 127 个 token 的 SWA KV。这些 SWA KV 也得从某个地方来。

V4 的线上做法是：在“提示结尾”和“输出结尾”两个点把 SWA KV 存下来，方便重新生成和多轮会话；SSD 上的持久化缓存配得足够大，典型负载下两种 KV 都能驻留 72 小时以上。结果是 SWA KV 占了持久化缓存将近一半的容量 1。V4 论文还讨论过另外两种策略：周期性地存检查点，或者干脆不存（Zero SWA Caching），需要时重算最后 \(n_{\text{win}}\cdot L\) 个 token 来恢复 SWA 状态 3。

为什么这笔存储不划算。 V4.1 论文说，SWA KV 只在一个活跃会话内部、分钟级的窄窗口里被复用，会话结束或下一轮开始，它就“死了”；而 Zero SWA Caching 的精确恢复要跑 \(L\times n_{\text{win}}\) 个 token 的完整前向，在线上代价高得无法接受 1。V4-Flash 的 \(L=43\)，那就是 \(43\times128=5{,}504\) 个 token，比很多轮次的新输入还长。

V4 的“约 8 倍”与 V4.1 的“将近一半”并不矛盾

V4 论文说 SWA 条目的体积约是压缩后 CSA/HCA 条目的 8 倍 3。这是“每个 token 都存 SWA”时按条目数比的：\(43/(21/4+20/128)=7.95\)。V4.1 说的“将近一半”，是 V4 实际部署只在两个点存 SWA 时，SWA 在持久化缓存里的容量占比，是一个线上负载的统计 1。

V4.1 的新分工

V4.1 把两种 KV 按寿命分开存放 1：

  1. SWA KV 不再进入持久化缓存，改存到一个分布式内存池里，这个池由每台机器 10% 的主机内存组成；因为它的寿命（TTL）只有几分钟，过期的条目可以立即回收。
  2. 全局 KV 留在持久化缓存里，保证至少保存 72 小时。
  3. 如果需要的 SWA 状态已经不在内存池里，就只重算 \(n_{\text{win}}\) 个 token，而不是 \(L\times n_{\text{win}}\) 个 token 的完整前向。论文把这种有界回放称为整个设计的基石。

论文在引言里的概括是：把长寿命的全局 KV 存储，与存在主机内存里的短寿命的编码器 SWA KV 分开 1。只提编码器，是因为解码器的 SWA 状态本来就在每次 prefill 时由 Decoder SWA Bounded Replay 重新生成、不进前缀缓存（§2）。部署层面，V4.1 采用 Encoder–Prefill–Decode（EPD）分离，让视觉编码、prefill、解码三部分各自独立扩容 1。

Encoder SWA Bounded Replay：规则与误差

含义。 前缀命中、但 SWA 状态已经不在内存池里时，只把命中位置之前最近 \(n_{\text{win}}\) 个 token 重新送进编码器，只为它们重建 SWA KV；回放时，SWA 的窗口在回放段的起点截断。

理解。 回到纪要本和白板的比喻：隔天接着开会，厚厚的纪要本（全局 KV）从档案室调回来了，但每层楼的小白板（SWA）早就被擦掉了。精确的做法是把前一天最后几千位发言者请回来，按顺序从一楼走一遍，把每块白板恢复原样。V4.1 的做法是只请最后 128 位回来重讲一遍，而且规定他们重讲时，只能参照这 128 人内部的发言，不能参照更早的人。这样恢复出来的白板和原来的“差不多”，但不完全一样。

数学。 设缓存命中在位置 \(h\)（前缀是位置 \(0,\dots,h-1\)），回放段从 \(s=h-n_{\text{win}}\) 开始。论文的规则是 1：

回放段内的 SWA 可见区间\[\mathcal W_i=\big[\max(s,\;i-n_{\text{win}}+1),\;i\big],\qquad s\le i<h\]正常情况下位置 \(i\) 看 \([i-n_{\text{win}}+1,\,i]\) 共 128 个位置；回放时，比 \(s\) 更早的部分被截掉。论文在这里把窗口写作 \(W\)，本课统一写 \(n_{\text{win}}\)。(19.17)

回放段里的 token 只重建 SWA KV；它们的全局分支直接读缓存里的全局 KV，既不重算、也不覆盖。命中位置之后的新输入则正常 prefill，同时写全局 KV 和 SWA KV 1。

误差从哪里来、到哪里为止
(1)\(\displaystyle \mathbf e_j\ (j<h)\ \text{精确}\)全局 KV 从持久化缓存读回，与原来逐位相同
(2)\(\displaystyle \mathcal W_i\subsetneq[i-n_{\text{win}}+1,\,i]\quad\text{当 }i<s+n_{\text{win}}-1\)回放段开头的位置看不到本该看到的更早邻居 (19.17)
(3)\(\displaystyle \hat{\mathbf h}^{(l)}_i\ne\mathbf h^{(l)}_i\quad(s\le i<h,\ l\ge2)\)截断先改变层 0 的 SWA 输出（\(i<h-1\) 从层 1 的输入起就不同；\(i=h-1\) 的窗口恰好完整，要从层 2 的输入起才被波及），误差随层数往上传
(4)\(\displaystyle \hat{\mathbf k}^{(l)}_i=W^K_l\,\hat{\mathbf h}^{(l)}_i\ne\mathbf k^{(l)}_i\)回放段重建的 SWA KV 由近似的隐藏状态投影而来（记号同 §2），所以也是近似的
(5)\(\displaystyle \text{后缀 }t\ge h\text{ 的 KV 依赖于 }h\)新输入的 SWA 分支读到了这些近似的 SWA KV，于是它们写出的全局 KV 与 SWA KV 都随命中位置而变

论文把最后一行说得很直白：按照设计，回放的前缀状态是近似的，所以为未缓存后缀算出的全局 KV 和 SWA KV 依赖于缓存命中的位置，在不同位置之间并不在数学上相同 1。它给出的质量证据是：实验表明这种有界回放几乎不损害回答质量。这句话没有附数字。

回放多少、省多少
  • V4-Flash 的 Zero SWA Caching 精确恢复：\(43\times128=5{,}504\) 个 token 3。
  • V4.1 若按论文“\(L\times n_{\text{win}}\)”的口径精确重建：\(40\times128=5{,}120\) 个 token。笔者按 (19.7) 的感受野推理：命中后续算的新输入只经过编码器（解码器另有自己的回放），所以真正要精确恢复的是编码器 20 层，约 \(20\times128=2{,}560\) 个 token。
  • Bounded Replay：128 个 token，比上面两种口径分别少 40 倍和 20 倍。

对照一次典型的新输入：上一轮工具结果只有 2,000 个 token（§1）。精确恢复要先重跑 2,560 到 5,120 个 token，比要处理的新内容还多；有界回放只多 128 个，占 6%。

“持久化 KV 约 1/8”：两个相乘的因子

论文的原话是：两个相乘的因子造成了这一降幅，其一是持久化缓存不再存 SWA KV，这几乎把它的大小减半；其二是其中保留的全局 KV 又被压到 V4 的 1/4 1。写成公式：

从 1/2 × 1/4 到 1/8
(1)\(\displaystyle P_{4}=G_{4}+S_{4}\)V4 持久化缓存 = 全局 KV 部分 + SWA 部分
(2)\(\displaystyle S_4\approx G_4\)线上统计：SWA 占“将近一半”
(3)\(\displaystyle P_{4.1}=G_{4.1}\)V4.1 不再持久化 SWA
(4)\(\displaystyle G_{4.1}=\tfrac{890}{3514.25}\,G_4=0.253\,G_4\)同样多的缓存 token，每个 token 的全局 KV 之比
(5)\(\displaystyle \dfrac{P_{4.1}}{P_4}=\dfrac{0.253\,G_4}{2\,G_4}=0.127\approx\dfrac18\)代入
持久化 KV 之比\[\frac{P_{4.1}}{P_{4}}=\frac{G_{4.1}}{G_{4}+S_{4}}=\underbrace{\frac{G_4}{G_4+S_4}}_{\approx\,1/2\ (\text{负载统计})}\times\underbrace{\frac{G_{4.1}}{G_4}}_{=\,1/3.95\ (\text{架构})}\approx\frac18\]第一个因子取决于负载：SWA 在 V4 持久化缓存里占多少，要看会话有多少轮、每轮多长。第二个因子由架构决定。(19.18)
换一种负载，“1/8”还成立吗？

设想一个以长文档为主、很少多轮的负载，SWA 快照只占 V4 持久化缓存的 10%，即 \(S_4=\tfrac19G_4\)。则

\[\frac{P_{4.1}}{P_4}=\frac{0.253\,G_4}{G_4+\tfrac19G_4}=0.228\approx\frac1{4.4}\]

反过来，会话越碎、轮数越多，SWA 占比越大，比值越接近甚至低于 1/8。所以“1/8”是 V4 线上负载下的数，“1/4”才是架构本身给的保证。

SWA 状态现在比全局 KV “更贵”

V4.1 的全局 KV 小到 890 字节/token 以后，一个请求在 HBM 里的 SWA 状态 \(40\times128\times528=2{,}703{,}360\) 字节（2.58 MiB）相当于 \(2{,}703{,}360/890\approx3{,}037\) 个 token 的全局 KV；只算编码器 20 层，\(1{,}351{,}680\) 字节也相当于约 1,519 个 token（笔者推算）。对短回合、多轮次的智能体会话，SWA 快照反而会成为持久化缓存的大头。这正是 V4.1 把它挪到寿命短、回收快的主机内存池、并用有界回放兜底的动机（笔者的解读，数字按配置复算）。

“SWA Bounded Replay 是精确的”

不是。论文明确说回放出来的前缀状态是近似的，同一段后缀从不同位置命中缓存，会得到不同的 KV (19.17)。它的局限一节也写明：SWA Bounded Replay 的近似状态重建可能在未测试的边界情形下造成能力退化，今后会特别关注缓存续接边界上的 SWA 状态重建 1。

这一页的要点
  • V4 的持久化缓存里，“提示结尾、输出结尾”两处保存的 SWA 快照占了将近一半，而它们几分钟后就没用了。
  • V4.1：SWA KV 放进由每台机器 10% 主机内存组成、寿命几分钟的池子；全局 KV 留在 SSD，至少 72 小时；池里没有时，只回放最近 128 个 token，窗口在回放起点截断 (19.17)。
  • 近似的代价：后缀的 KV 随命中位置而变；论文只给了定性的质量证据。
  • 持久化 KV \(\approx\tfrac12\times\tfrac1{3.95}\approx\tfrac18\) (19.18)：前一个因子是负载统计，后一个是架构。

扩展一：Single-Pass mHC，让残差流少读写一半

第 16 课的 mHC 把残差流扩成 \(n_{hc}=4\) 条，每层用三组系数混合：输入混合 \(A_l\)、残差映射 \(B_l\)、输出映射 \(C_l\)（第 16 课记作 \(H^{\rm pre}_l,H^{\rm res}_l,H^{\rm post}_l\)）15。V4 的写法是（论文式 (2)）

\[X_{l+1}=B_lX_l+C_l\,\mathcal F_l(A_lX_l),\qquad (A_l,B_l,C_l)=\mathcal H(X_l)\]

这里 \(X_l\in\R^{n_{hc}\times d}\) 是 4 条残差流（每行一条），\(\mathcal F_l\) 是本层的注意力或 MoE；\(A_l\in\R^{1\times n_{hc}}\) 把 4 条流混成送进 \(\mathcal F_l\) 的一条输入，\(B_l\in\R^{n_{hc}\times n_{hc}}\) 在流与流之间搬运，\(C_l\in\R^{n_{hc}\times1}\) 把 \(\mathcal F_l\) 的一条输出分回 4 条流；\(\mathcal H\) 是从 \(X_l\) 逐 token 预测这三组系数的函数（第 16 课式 (16.26)(16.27)）。注意这里的 \(C_l\) 与 (19.4) 里的 KV 条目 \(C_l\) 同名但毫无关系，两处都是论文原记号。问题在于依赖顺序：输入混合要用 \(A_l\)，而 \(A_l\) 要先对整个 \(X_l\)（\(n_{hc}d\) 个数）做一次归约才能预测出来。于是必须先把 \(X_l\) 完整读一遍算系数，再读一遍做混合，V4 的实现分成三个内核，残差被来回读写多次。

Single-Pass mHC 把输入混合的系数错后一层 1：

Single-Pass mHC\[X_{l+1}=B_lX_l+C_l\,\mathcal F_l\big(A_{l-1}X_l\big),\qquad (A_l,B_l,C_l)=\mathcal H(X_l)\]唯一的变化是 \(A_l\to A_{l-1}\)：本层的输入混合用上一层预测的系数，不再等本层的归约完成。\(X_l\) 的每一块读进来，可以同时用于输入混合和为下一层累积系数。(19.19)

这个“错后一层”在数据流上是什么样子，第 16 课 §7 的图 16.14 画出了多趟实现与单趟实现的对比，图 16.15 画出了各种实现每个子层的访存量。

每个 token、每次 mHC 的激活读写量（\(n_{hc}=4\)，\(d=5120\)，单位：元素）
  • 理想映射的下界：读 \((n_{hc}+1)d\)、写 \((n_{hc}+1)d\)，合计 \((2n_{hc}+2)d=10\times5120=51{,}200\)。笔者的拆解：读进 \(n_{hc}\) 条残差流和本层 \(\mathcal F_l\) 的 1 条输出，写出 \(n_{hc}\) 条新的残差流和送给下一层 \(\mathcal F_{l+1}\) 的 1 条输入，每样都只碰一次。
  • V4 的三内核实现（计入 pre-norm）：\((4n_{hc}+4)d=20\times5120=102{,}400\)，是下界的两倍。
  • 原 mHC 的两遍实现：\((3n_{hc}+2)d=14\times5120=71{,}680\)。\(A_l\) 要等对整个 \(X_l\) 的归约完成才能算出，所以输入混合必须把 \(X_l\) 再读一遍，比下界多一次读；Mega-mHC 内核跑原 mHC 时就是这个数 1。
  • Single-Pass mHC 的部署内核 Mega-mHC：残差只读一次、写一次，达到下界 51,200，比原实现减半 1。

论文说这个错位“在经验上”只带来可以忽略的性能下降，而且预训练时仍用原来的多内核实现 1。论文内部有个小矛盾：引言说 Mega-mHC 相对“原来的四内核实现”减半，§2.4.1 说 V4 是“三个内核”，加上 pre-norm 才是四步。

扩展二：Engram，196B 参数的条件记忆

第 17 课的 Engram 用 \(N\)-gram 哈希查表给模型加了一种“查字典”式的记忆 16。V4.1 放了两个 Engram 模块，在层 1 和层 14，一共 196B 参数；每个模块用 2、3、4 阶 \(N\)-gram，每阶 8 个哈希头、合计 2048 维，每个头查一张约 1,600 万行的表（表的大小取互不相同的素数），表和投影都用 FP8 1。

这些参数不算在“552B 主干”里，也不算在 8B / 16B 激活里。每个 token 在每个模块里只读 \(3\times8=24\) 行、每行 256 维，两个模块共 \(2\times24\times256=12{,}288\) 个数（外加 0.315B 的投影）。因为查哪几行只取决于 token 本身，推理时可以提前知道地址，把这些行从主机内存经后台 RDMA 预取过来，第一个模块的预取与第一个 Transformer 块的计算重叠 1。换句话说，Engram 的 196B 参数也被放到了 HBM 之外，这和本课“把不常用的字节赶出 HBM”的主题一致。

扩展三：DSpark，事后训练的投机解码

V4 在预训练里带一个 MTP 模块，推理时拿来做投机解码（MTP 模块见第 11 课 §6，投机解码见同课 §7）。V4.1 预训练时不带 MTP，改用 DSpark 17：一个由 3 个 Transformer 块（滑动窗口 128）组成的草稿模型，一次前向并行算出 5 个草稿位置的基础 logits，再用一个轻量的 Markov 头建模草稿 token 之间的依赖 1。它在预训练之后的专门阶段单独训练（主干冻结），后训练时继续和主干一起训练，但 DSpark 的损失不回传到主干。DSpark 论文报告，在 V4 的线上服务系统中，相对 MTP-1、在相同吞吐下单用户生成速度提升 60% 到 85%（V4-Flash；V4-Pro 为 57% 到 78%，摘要只写了 Flash 的区间）17；V4.1 论文没有给出 DSpark 在 V4.1 上的接受长度或加速比。

权重文件里的名字

DSpark 的权重放在 checkpoint 的 mtp.* 命名空间下，配置字段也仍叫 num_nextn_predict_layers: 3 4。看到这些名字，不要以为 V4.1 预训练里有 MTP。

多模态：视觉从预训练第一天就在

V4.1-Flash 是一个多模态 MoE 模型：一个视觉编码器加一个 MLP 投影把图像变成视觉嵌入，与文本嵌入一起送进语言主干；多模态数据从语言模型预训练的一开始就加入 1。

视觉编码器 DeepSeek-ViT。 32 层、隐藏维 1024、16 个头、图像块（patch）边长 14 像素；投影 MLP 2 层、隐藏维 5120 1。和常见的 ViT 相比有四处改动：用二维 RoPE 取代绝对位置嵌入；把 patch 嵌入层的卷积换成线性投影，以便与 Muon 优化器兼容（第 18 课 §5 的 Muon 是按二维权重矩阵定义的）；用 RMSNorm 和 SwiGLU。送进语言模型之前，做一次 \(3\times3\) 的 pixel-unshuffle：把每个 \(3\times3\) 邻域的 9 个特征沿通道维拼成一个，视觉 token 数减少 9 倍，从而能支持最大约 \(1344\times1344\) 像素的输入。

一张图变成多少个视觉 token（笔者按论文参数推算）\[n_{\text{vis}}=\Big\lceil\frac{H_{\text{px}}}{14\times3}\Big\rceil\times\Big\lceil\frac{W_{\text{px}}}{14\times3}\Big\rceil\]每 14 像素一个 patch，每 \(3\times3\) 个 patch 合成一个 token。\(1344\times1344\)：\(1344/14=96\) 个 patch，\(96/3=32\)，\(32\times32=1{,}024\) 个视觉 token。\(544\times544\)：\(\lceil544/14\rceil=39\)，\(\lceil39/3\rceil=13\)，169 个。实现里还有少量换行、起止标记，这里不计。(19.20)

视觉编码器单独预训练，分两阶段 1。第一阶段用 SigLIP 的 sigmoid 对比损失，在约 470 亿个图文对上训练，输入最大 \(224\times224\) 像素；论文说这一阶段用更高的分辨率虽有明显收益，但对最终模型帮助不大，因为后一阶段专门处理高分辨率。第二阶段把编码器接到一个 4B 的 MoE 语言模型上，用下一 token 预测在 2,360 亿 token 的图注、alt 文本、图表、OCR 数据上训练，分辨率限制在 \(544^2\) 到 \(1344^2\) 之间；训完丢掉这个语言模型，只留编码器。

并入主干之后。 预训练的大部分时间里视觉编码器是冻结的（它的最后一层归一化和视觉–语言投影仍然可训练）；学习率开始衰减时，才解冻编码器、用更小的学习率与语言模型联合训练 1。

按模态分开的负载均衡。 第 11 课 §4的无辅助损失均衡给每个专家一个偏置 \(b_i\)，只影响选专家、不影响门控值。V4.1 发现图像 token 和文本 token 的表示分布不同，可能偏好不同的专家；如果只平衡两者的总负载，会掩盖某一种模态内部的不均衡。所以它为文本和图像各维护一套偏置：每个 token 用自己模态的偏置选专家，原始路由分数仍用于加权，每步训练后两套偏置按各自模态的负载独立更新（更新速度都是 0.001），另留一个权重 \(10^{-4}\) 的序列级均衡损失 1。

数据。 多模态语料主要是三类：图文对、图文交错的网页与 PDF、以及领域数据（视觉定位与指点、OCR、长尾知识、图像–代码对、计算机操作轨迹）；论文说他们没有做大规模数据合成，而是尽量以原生形态清洗和使用网络数据。纯文本和多模态两条管线的数据取并集，重叠的样本用多模态版本替换纯文本版本，之后纯文本 : 多模态 = 7 : 1（按 token）1。

训练日程。 45T token，论文说训练中没有出现不稳定；batch 始终固定为 1.006 亿 token；前 2,000 步线性预热，学习率 \(2.6\times10^{-4}\) 保持到 28T，28T 到 40T 按余弦衰减到 \(2.6\times10^{-5}\)，之后保持到 45T；从头就用 64K 序列长度和稀疏注意力，34T 时把序列扩到 1M 1。

图像加载会不会拖慢训练？

百万 token 的序列里若塞满图像，一台主机的 IO、CPU 和内存可能在加载时就被耗尽。V4.1 把每条序列的图像按负载均衡分给各个上下文并行（CP）的进程，每张图只加载一次。论文给出一个判据：加载能藏在计算后面，当且仅当

\[\frac{N\times\rho}{B_{\mathrm{IO}}}<\frac{N\times C}{B_{\mathrm{GPU}}}\quad\Longleftrightarrow\quad \rho<\frac{B_{\mathrm{IO}}}{B_{\mathrm{GPU}}}\,C\]

其中 \(N\) 是 token 数（论文记号，这里不是参数量），\(\rho\) 是每个 token 的原始字节数，\(C\) 是每个 token 的计算量，\(B_{\mathrm{IO}}\)、\(B_{\mathrm{GPU}}\) 是文件系统和 GPU 的带宽 1。注意量纲：左边是字节 ÷（字节/秒）= 秒；右边的 \(N\times C\) 是运算次数，要同样得到秒，\(B_{\mathrm{GPU}}\) 只能理解成 GPU 每秒能做的运算次数（FLOP/s，算力吞吐），而不是显存带宽。\(N\) 在两边约掉了，所以判据只和“每个 token”的量有关，与序列长度、集群规模无关。\(C\) 与模型大小成正比：论文说，只有每 token 计算很少的小模型（比如做消融实验时）才会卡在存储吞吐上，生产规模的模型仍是计算受限。这和 §1 的“三张账单”是同一种算法：比较“搬字节的时间”和“做计算的时间”。

后训练：算法没有新东西

论文的原话是：后训练没有算法上的创新，沿用 SFT → RL → 在线策略蒸馏（OPD）的标准范式；观察到的提升几乎全部来自合成数据与环境在规模、多样性和可验证性上的系统改进 1。最后的全词表 OPD 用了 40 多个教师模型。一个值得一提的接口变化是推理强度：系统提示里写一个 1 到 100 的数，数越大要求推理越充分；API 的 max、high、low 三档分别对应 100、75、50。论文报告，把强度从 25 调到 100，八个推理密集型基准的平均 Pass@1 从 67.1% 升到 76.3%，代价是输出 token 约变成原来的 2.5 倍 1。这与本课的主题相呼应：输出变长会加重 decode 的账，而 V4.1 的设计重点放在输入侧。

这一页的要点

890 字节的两步：结构 2.16 倍，精度 1.83 倍

从 3,514.25 到 890 一共缩小 3.95 倍。中间插一个“假想模型”，就能把两类改动分开：它用 V4.1 的结构（4 份全局 KV、2.5 个条目/token），但条目仍用 V4 的 584 字节格式。

把 3.95 倍拆成两个因子
(1)\(\displaystyle s_{\text{mid}}=2.5\times(584+68)=1{,}630\)假想模型：V4.1 的结构、V4 的格式
(2)\(\displaystyle \dfrac{3{,}514.25}{1{,}630}=2.156\)结构这一步：41 份 → 4 份，同时 \(m\) 从 4/128 变成 2/1

主线 A 的总结：KV 字节的阶梯

第 4 课推出 KV cache 的时候，每个 token 的缓存是 \(2\,n_h d_h\,l\) 个数。回头看，这条主线上的每一次改进，都是在一个乘法因子上动手。把 (19.10) 再展开一层，每 token 的 KV 字节可以写成四个因子的乘积：

  • V4.1 的代价：模型更大、短上下文解码更贵、两处近似；它的收益集中在输入重负载的 prefill、HBM 与 SSD。

练习与答案

先自己做，再展开答案。需要的规格一律用 V4.1-Flash 与 V4-Flash 的真实配置：V4.1 为 40 层、\(n_{\text{win}}=128\)、KV 源层 [2, 8, 14, 20]（压缩比 2, 2, 2, 1）、索引器层 [2, 8, 14, 20, 24, 28, 32, 36]、索引器 32 头 × 128 维、主 KV 条目 288 B、索引器键 68 B、SWA 条目 528 B；V4-Flash 为 43 层、21 CSA（\(m=4\)）+ 20 HCA（\(m=128\)）、主 KV / SWA 条目 584 B、索引器 64 头。

概念题

练习 1 · CED、YOCO 与 T5

（a）CED 是不是 T5 那样的编码器–解码器？说出两点不同。（b）CED 与 YOCO 的关键差别是什么？这个差别带来了什么代价？（c）在发布的 V4.1 里，式 (19.4) 的“每层各有一组 \(W_l^{KV}\)”实际实例化了几次？为什么？

看答案

（a）不是。T5 的编码器读一段独立的源序列，解码器生成另一段目标序列，通过交叉注意力读编码器输出；编码器是双向的。CED 的两半处理同一条 token 流，而且两半都是因果的；“编码器”“解码器”只说明 prefill 时这一半跑不跑。

（b）YOCO 的上半截只有对共享 KV 的交叉注意力，没有自注意力，所以提示 token 可以在中间精确地提前退出。CED 的解码层保留了自己的 SWA，生成第一个输出 token 时需要解码器各层最近 128 个 token 的 SWA 状态，于是必须“回放”。精确回放约要 2,560 个 token，V4.1 改用只回放 128 个的 Decoder SWA Bounded Replay，代价是 SWA 状态变成近似的。

（c）一次。V4.1 同时用了 CSA2，解码器 20 层里只有层 20 是 Full 模式，自己由 \(H_{L/2}\) 投影出全局 KV；其余 19 层复用它（Reuse 或 Reindex）。所以整个解码器只有一份全局 KV，效果上又回到了 YOCO 的“只缓存一次”。

练习 2 · 两种 FP4

（a）V4.1 的主 KV 和索引器键都是 FP4，格式有什么不同？（b）为什么不统一成一种？（c）有人说“主 KV 是 FP4，所以注意力是用 FP4 算的”，错在哪里？（d）SWA KV 为什么没有改成 FP4？

看答案

（a）主 KV：E2M1 元素 + 每 16 个一个 E4M3 缩放（NVFP4 去掉二级全局缩放），每条目 \(256+32=288\) B；索引器键：OCP 标准 MXFP4，E2M1 + 每 32 个一个 E8M0 缩放，每条目 \(64+4=68\) B。

（b）用途不同。索引器的打分是真正的 FP4 矩阵乘，缩放格式必须是硬件矩阵单元原生支持的，论文为了支持尽可能多的硬件选了 MXFP4（尽管别的格式在他们的实验里更准）。主 KV 只用于存储，注意力之前先反量化，所以可以选更准的、没有原生矩阵乘支持的格式。

（c）主 KV 只以 FP4 存储。注意力内核在片上把它解回 BF16，再用 BF16 做打分和加权（FlashMLA 的说明）。只有索引器打分是 FP4 计算。

（d）论文说 SWA KV 对量化敏感，所以保留 FP8（528 B/条目）。它是每请求的常数（40 层 × 128 个条目），不影响每 token 的 890 字节。

练习 3 · 三种模式与前人工作

（a）CLA、IndexCache、YOIO 分别只共享了什么？对照 CSA2 的 Full / Reindex / Reuse，各自相当于哪一种（或哪一种组合）？（b）如果把 V4.1 的 4 个 Reindex 层都改成 Reuse，存储和计算各有什么变化？可能的风险是什么？（c）为什么每一层都要保留自己的主 Q 与 SWA KV，而不连它们也共享？

看答案

（a）CLA：相邻层共享 KV，但每层各自对 KV 做完整注意力，相当于“共享主 KV、不涉及稀疏选择”。IndexCache：复用 top-k 索引，但每层仍存自己的 KV，相当于只有“Reuse 的一半”（共享选择、不共享存储），所以论文说它不省主 KV 存储。YOIO：全网只算一次稀疏路由、所有层共用这一份选择，就选择这一半而言，相当于只有一个产出 top-k 的层、没有任何 Reindex 层（它是否也共享 KV，本课没有核实），论文认为这种全网共享会限制性能。CSA2 把两件事解耦：Reindex = 共享 KV、各自选择；Reuse = 两样都共享。

（b）存储不变（KV 份数仍是 4，由 Full 层决定）。计算上，每个解码 token 省掉 4 个 Reindex 层在候选池里的打分，即 \(4\times16{,}384\) 个条目 × 32 头，一个与 \(T\) 无关的常数。风险是解码器 20 层全部使用层 20 的一份 top-512；深层真正需要的内容若不在其中，就读不到，这正是 YOIO 式“全网共享路由”的问题。

（c）主 Q 决定“本层想找什么”，每层的需求不同；共享同一批条目时，各层用自己的 Q 仍能得到不同的注意力输出。SWA KV 来自本层自己的隐藏状态，携带本层对最近 128 个 token 的局部加工结果；论文的设计哲学是“以 SWA 做局部处理的主干 + 压缩的全局上下文”，只简化全局分支、基本保留局部注意力。

练习 4 · 分层稀疏索引器的范围

（a）为什么分层稀疏索引器只用在解码器？（b）1M 上下文时，解码一个 token，哪些层的索引器仍要扫描全部可见条目？一共多少个条目？（c）“分层索引器让解码的索引变成 \(O(1)\)”对吗？

看答案

（a）论文只说它“只用在解码器”。笔者的解释：编码器每组是 1 个 Full + 5 个 Reuse，没有 Reindex 层，后面没有人需要“在候选池里重新打分”；解码器有 4 个 Reindex 层，才有东西可省。另外候选池由层 20 的 token 级分数按块取最大值得到，不增加任何状态。

（b）层 2、8、14（编码器的 Full 层，\(m=2\)）各扫 \(T/2\) 个，层 20（解码器的 Full 层，\(m=1\)）扫 \(T\) 个，共 \(2.5T=2{,}621{,}440\) 个；层 24、28、32、36 各只在至多 16,384 个候选里打分。

（c）不对。只有 4 个 Reindex 层变成常数；4 个 Full 层每个解码 token 仍要全扫，所以单 token 解码 FLOPs 仍有一个 \(5{,}120\,T\) 的增长项 (19.14)，只是比 V4-Flash 的 \(41{,}984\,T\) 小得多。

计算题

练习 5 · 从配置算 890

（a）从主 KV 与索引器键的格式出发，算出每个条目的字节数。（b）用 KV 源层与压缩比算出每 token 全局 KV，并分出编码器与解码器各占多少。（c）如果主 KV 仍用 V4.1 的 FP8 格式（SWA 那种 528 B），全局 KV 是多少？（d）如果解码器那一份也用 \(m=2\)，是多少？

看答案

（a）主 KV：512 个 E2M1，每字节两个，256 B；每 16 个一个 E4M3 缩放，\(512/16=32\) B；合计 288 B。索引器键：128 个 E2M1 共 64 B，每 32 个一个 E8M0，4 B；合计 68 B。一个条目连索引器键 356 B。

（b）每 token 条目数 \(\tfrac12+\tfrac12+\tfrac12+1=2.5\)，全局 KV \(2.5\times356=890\) B。编码器三份 \(1.5\times356=534\) B（60%），解码器一份 \(356\) B（40%）。

（c）\(2.5\times(528+68)=1{,}490\) B，是 890 的 1.67 倍。

（d）每 token 条目数 \(4\times\tfrac12=2\)，全局 KV \(2\times356=712\) B。它更省，但解码器的全局注意力就只能看到“每 2 个 token 一条”的压缩条目；V4.1 选择让解码器保留逐 token 的全局 KV。

练习 6 · V4-Flash 的 3,514 与不共享的 V4.1

（a）写出 V4-Flash 每 token 全局 KV 的算式，并分出 CSA 主 KV、HCA 主 KV、索引器键三部分。（b）如果把 V4-Flash 的 20 个 HCA 层直接删掉，全局 KV 少多少？（c）如果 V4.1 的 38 个 CSA2 层每层都存自己的主 KV 与索引器键，全局 KV 是多少？是 V4-Flash 的几倍？这说明了什么？

看答案

（a）\((21/4+20/128)\times584+(21/4)\times68=3{,}066+91.25+357=3{,}514.25\) B。

（b）少 91.25 B，只有 2.6%。V4-Flash 的字节几乎全在 21 份 CSA 上，删 HCA 省不了什么；V4.1 删掉 HCA 的理由是简化架构，省字节靠的是层维共享。

（c）\((18\times\tfrac12+20\times1)\times356=29\times356=10{,}324\) B，是 V4-Flash 的 2.94 倍、V4.1 实际值的 11.6 倍。V4.1 的压缩比（2 和 1）比 V4（4 和 128）小，每一份其实“压得更少”；全局 KV 能降到 890，完全靠层维共享把 29 个“等效份数”降到 2.5。

练习 7 · 一个请求的 HBM

（a）1M（\(2^{20}\)）token 的一个请求，V4.1 与 V4-Flash 的全局 KV 各是多少 GiB？（b）128K（131,072）token 呢？用 MiB 表示。（c）V4.1 每个请求的 SWA 状态是多少字节？上下文多长时，全局 KV 才和它一样大？

看答案

（a）V4.1：\(890\times2^{20}=933{,}232{,}640\) B，除以 \(2^{30}\) 得 0.869 GiB。V4-Flash：\(3{,}514.25\times2^{20}/2^{30}=3.432\) GiB。

（b）V4.1：\(890\times131{,}072=116{,}654{,}080\) B \(=111.25\) MiB。V4-Flash：\(3{,}514.25\times131{,}072=460{,}619{,}776\) B \(=439.3\) MiB。

（c）\(40\times128\times528=2{,}703{,}360\) B（2.58 MiB）。令 \(890\,T=2{,}703{,}360\)，\(T\approx3{,}037\) token。上下文短于约 3,000 token 时，SWA 状态反而比全局 KV 大；V4-Flash 的这个交叉点只有约 915 token。

练习 8 · CED 省了多少 prefill

（a）一次请求要 prefill 2,000 个新 token。按“一个 token 过一层”计，CED 加有界回放的工作量是完整 40 层的多少？若解码器 SWA 要精确重建（回放约 2,560 个），又是多少？（b）同样问题，\(T=65{,}536\)。（c）用 (19.3) 估算 \(T=2{,}000\) 时 V4.1 的 prefill 主干计算量，并与“40 层全跑、每 token 16.48B”比较。

看答案

（a）有界回放：\(\rho=\tfrac12+\tfrac{64}{2000}=0.532\)。精确重建：\(T<2{,}560\)，整段提示都要进解码器，\(\rho_{\text{exact}}=\tfrac{20\times2000+20\times2000}{40\times2000}=1\)，CED 一点也不省。

（b）\(\rho=\tfrac12+\tfrac{64}{65{,}536}=0.50098\)；\(\rho_{\text{exact}}=\tfrac12+\tfrac{1280}{65{,}536}=0.5195\)。长提示时两者都接近 1/2，差别主要出现在几千 token 的短增量上，而智能体的每轮新输入恰好是这种长度。

（c）粗算：编码器侧 \(2\times8.24\times10^9\times2{,}000=3.30\times10^{13}\)；解码器回放 128 个 token，每个再走后 20 层，约 \(2\times(16.48-8.24)\times10^9\times128=2.1\times10^{12}\)；合计约 \(3.5\times10^{13}\)。40 层全跑：\(2\times16.48\times10^9\times2{,}000=6.59\times10^{13}\)。比值 0.53，与 (a) 一致。

练习 9 · 手算一个 FP4 块

一个 16 维块 \(\mathbf x\) 的分量依次是 0.12、−0.45、0.9、3.2、−0.05、0.33、−1.7、0.6、0.02、−0.28、1.15、−0.74、0.41、0、−2.6、0.19。（a）按主 KV 的格式（E4M3 缩放，(19.15)）量化并反量化。提示：E4M3 在 0.5 附近的值有 0.5 与 0.5625。（b）改用 MXFP4 的缩放（向上取到 2 的幂）。（c）比较两者的相对 RMSE（已知 \(\lVert\mathbf x\rVert_{\text{rms}}=1.213\)），说明差在哪里。

看答案

（a）\(\max\lvert x_i\rvert/6=3.2/6=0.5333\)；离它最近的 E4M3 值是 0.5625（差 0.029，比 0.5 的 0.033 更近），\(s=0.5625\)。\(x_i/s\) 依次为 0.213、−0.800、1.600、5.689、−0.089、0.587、−3.022、1.067、0.036、−0.498、2.044、−1.316、0.729、0、−4.622、0.338，舍入到 E2M1 得编码 0、−1、1.5、6、−0、0.5、−3、1、0、−0.5、2、−1.5、0.5、0、−4、0.5，反量化（乘 0.5625）为 0、−0.5625、0.8438、3.375、0、0.2813、−1.6875、0.5625、0、−0.2813、1.125、−0.8438、0.2813、0、−2.25、0.2813。最大误差 0.35（\(-2.6\to-2.25\)：\(-4.622\) 夹在 −4 与 −6 之间，离 −4 更近）。相对 RMSE 9.81%。

（b）\(s=2^{\lceil\log_2 0.5333\rceil}=2^0=1\)。编码就是把原值直接舍入到 E2M1：0、−0.5、1、3、−0、0.5、−1.5、0.5、0、−0.5、1、−0.5、0.5、0、−3、0。最大误差 0.4（\(-2.6\to-3\)），相对 RMSE 14.30%。

（c）E8M0 只能取 2 的幂，向上取整后缩放是 1，块内最大值 3.2 只用到 E2M1 的刻度 3，4 到 6 这一段完全浪费，小数值落在 0、0.5、1 这几道粗刻度上。E4M3 缩放 0.5625 让最大值落在 5.69，整个块用满了刻度。这正是主 KV 选“每 16 个一个 E4M3”的原因。

练习 10 · 解码 FLOPs 与交叉点

用 (19.14)。（a）128K（131,072）上下文时，V4.1 与 V4-Flash 的单 token 解码 FLOPs 各约多少？与论文图 2 的读数（20.8 与 22.0 G）对照。（b）若 V4.1 没有分层索引器（4 个 Reindex 层也全扫），增长项 \(g\) 变成多少？1M 时单 token 解码 FLOPs 约多少？与 V4-Flash 的交叉点移到哪里？

看答案

（a）V4.1：\(20.1\text{G}+5{,}120\times131{,}072=20.1+0.67=20.77\) G。V4-Flash：\(16.4\text{G}+41{,}984\times131{,}072=16.4+5.50=21.90\) G。与读数 20.8、22.0 吻合；128K 时 V4.1 已经略便宜（约 5%）。

（b）每个条目、每个索引器头的 FP4 加权 FLOPs 是 \(0.25\times2\times128=64\)，32 个头为 2,048。全扫的条目从 \(2.5T\) 变成 \(1.5T+T+4T=6.5T\)，\(g=2{,}048\times6.5=13{,}312\)。1M 时增长 \(13{,}312\times2^{20}=13.96\) G，总计约 \(20.1+14.0=34.1\) G（有分层时约 25.5 G）。交叉点

\[T=\frac{(20.1-16.4)\times10^9}{41{,}984-13{,}312}=\frac{3.7\times10^9}{28{,}672}\approx129{,}000\ \text{token},\]

比有分层时的约 100K 推后了约三成。严格说，去掉分层以后，\(F_0\) 里 4 个 Reindex 层在候选池里打分的常数（\(4\times16{,}384\times2{,}048\approx0.13\) G）也跟着消失，交叉点约 124,000 token；这个修正比图 2 读数本身的误差（约 ±3%，即 ±0.6 G）还小，结论不变。

推导题

练习 11 · 持久化 KV 的比值

设 V4 持久化缓存里 SWA 快照占的比例为 \(\sigma=S_4/(G_4+S_4)\)，V4.1 不持久化 SWA，且 \(G_{4.1}/G_4=890/3{,}514.25\)。（a）推导 \(P_{4.1}/P_4\) 关于 \(\sigma\) 的表达式。（b）分别求 \(\sigma=0.5\)、\(0.3\)、\(0.6\) 时的值。（c）解释为什么论文说“约 1/8”而架构只保证“约 1/4”。

看答案

（a）\(P_4=G_4+S_4=G_4/(1-\sigma)\)（因为 \(G_4=(1-\sigma)P_4\)）；\(P_{4.1}=G_{4.1}\)。所以

\[\frac{P_{4.1}}{P_4}=\frac{G_{4.1}}{G_4/(1-\sigma)}=(1-\sigma)\,\frac{G_{4.1}}{G_4}=0.2533\,(1-\sigma)\]

（b）\(\sigma=0.5\)：0.127（约 1/7.9）；\(\sigma=0.3\)：0.177（约 1/5.6）；\(\sigma=0.6\)：0.101（约 1/9.9）。

（c）\(G_{4.1}/G_4\approx1/3.95\) 由架构（份数、压缩比、条目格式）决定，与负载无关，所以“1/4”是保证。\((1-\sigma)\) 取决于 V4 线上的负载：会话多轮、每轮短时 SWA 快照占比大，\(\sigma\) 大；长文档单轮时 \(\sigma\) 小。论文用的是 V4 部署中“将近一半”的统计，\(\sigma\approx0.5\)，才得到约 1/8。

练习 12 · 回放的长度与截断

（a）一个有 \(L_d\) 层 SWA 的堆栈，窗口 \(n\)（含自己）。要精确重建最上层对最后 \(n\) 个位置的 SWA KV，最下层的输入要覆盖多少个位置？代入 V4.1 的解码器（\(L_d=20\)，\(n=128\)）与 V4-Flash 的全部 43 层，并与论文的 \(L\times n_{\text{win}}\) 比较。（b）在 Bounded Replay 里，回放段 \([s,h)\) 中有多少个位置的窗口被截断？被截得最多的那个位置看到几个 SWA 键？（c）为什么说全局分支不受截断影响？

看答案

（a）最上层要 \(n\) 个位置的输入。每往下一层，最左边的位置要看它左边 \(n-1\) 个邻居，覆盖范围向左多出 \(n-1\)。从最上层退到最下层的输入共退 \(L_d-1\) 次，所以要 \(n+(L_d-1)(n-1)\) 个位置。V4.1 解码器：\(128+19\times127=2{,}541\)，论文写成 \(\tfrac L2\times n_{\text{win}}=2{,}560\)。V4-Flash 43 层：\(128+42\times127=5{,}462\)，论文写成 \(43\times128=5{,}504\)。论文的写法是略大一点的整数近似。

（b）位置 \(i\) 的完整窗口是 \([i-127,\,i]\)，回放时变成 \([\max(s,i-127),\,i]\)。只要 \(i-127<s\)，即 \(i<s+127\)，就被截断；回放段有 128 个位置（\(s\) 到 \(s+127\)），只有最后一个 \(i=s+127=h-1\) 不被截断，其余 127 个都被截断。截得最多的是 \(i=s\)，只看到它自己，1 个键（本应 128 个）。

（c）全局分支读的是全局 KV。编码器侧命中时，前缀的全局 KV 从持久化缓存原样读回；回放段的 token 只重建 SWA KV，不重算、也不覆盖全局 KV。所以前缀部分的全局 KV 是精确的。误差只从截断的 SWA 进入，再经过后续层传给新输入，使新输入写出的 KV 随命中位置而变。
