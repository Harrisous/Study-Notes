第 11 课 · DeepSeek-V3（上）：无辅助损失负载均衡与多 token 预测

671B 参数，每个 token 只激活 37B。DeepSeek-V3 的骨架几乎原样继承 V2，真正新的是两件事：一个不产生任何梯度的偏置，负责让 256 个专家分到差不多的活；一个训练时“多看一步”的 MTP 模块，推理时可以扔掉，也可以拿来当草稿加速解码。这一课把这两件事的每个公式、每个超参数和背后的账单讲透。

这一课回答什么问题

一个混合专家（MoE）模型有 256 个路由专家，每个 token 只去其中 8 个。如果大部分 token 都挤向同几个专家，会发生两件坏事：冷门专家学不到东西，而放着热门专家的那张 GPU 成了整个集群的瓶颈。V2 的办法是在损失函数里加惩罚项（辅助损失），但惩罚项会把梯度送回模型的每一层，和“预测下一个词”这个本职目标抢方向。DeepSeek-V3 换了一个思路：不改损失，只改分诊规则。每个专家挂一个偏置 \(b_i\)，专家太忙就把它的“推荐分”调低一点，太闲就调高一点；偏置只决定 token 去哪里，不参与输出的加权，也不产生梯度。

这一课还讲 V3 的第二个新东西：多 token 预测（multi-token prediction, MTP）。训练时，模型除了预测下一个 token，还要借助一个小模块预测再下一个；推理时这个模块可以直接丢掉，也可以用来生成草稿，让解码快约 1.8 倍。

问题：V2 留下的均衡账单

DeepSeek-V3 的技术报告第一版发布于 2024 年 12 月 27 日，本课读的是 2025 年 2 月 18 日的第二版；两版在本课涉及的章节（架构、超参数、消融、MTP 评估）一字未改 1。报告对 MoE 部分的说法很克制：与 V2 相比，基本架构不变，唯一的例外是额外引入了一种无辅助损失的负载均衡策略；门控则“略有不同”：亲和度从 softmax 换成了 sigmoid，并在选中的亲和度之间归一化 1。这一页先摆出 V3 的全貌，再讲它要解决的问题：负载均衡为什么重要，V2 的做法代价在哪里。

从配置文件数出 671B 与 37B

发布的 config.json 给出全部尺寸 2。每个专家是一个 SwiGLU 前馈网络，有三个 \(7168\times2048\) 的矩阵：\(3\times7168\times2048=44{,}040{,}192\approx44.04\)M 个参数。一层 MLA（各投影矩阵加两个归一化向量）是 \(187{,}107{,}328\approx187.1\)M。前 3 层的稠密 FFN 各 \(3\times7168\times18432\approx396.4\)M。嵌入表和输出头各 \(129280\times7168\approx0.927\)B。

总参数。 注意力 \(61\times187.1\text{M}=11.41\)B；稠密 FFN \(3\times396.4\text{M}=1.19\)B；58 个 MoE 层各有 257 个专家（1 共享 + 256 路由），\(58\times257\times44.04\text{M}=656.5\)B；门控矩阵 \(58\times(256\times7168+256)\approx0.11\)B；嵌入与输出头 \(1.85\)B；再加上各层的归一化向量。合计 \(671.03\)B，与论文的 671B 一致。其中路由专家就占了 \(653.9\)B，即总参数的 97.4%。

激活参数。 每个 token 在每个 MoE 层只经过 1 个共享专家和 8 个路由专家，把上面的 257 换成 9，合计 \(37.55\)B（含嵌入与输出头），不含嵌入表是 \(36.63\)B。论文写 37B；仓库的权重说明写“36.7B（含 0.9B 嵌入与 0.9B 输出头）”，与按配置逐项累加的 37.55B 差约 0.85B，原因没有公开说明 4。

每 token 的前向算力。 按第 1 课“每 token 前向约 \(2N\) 次运算”的估算（\(N\) 取真正参与乘法的参数，嵌入查表不算），约 \(2\times36.6\text{B}\approx73\) GFLOPs。一个 671B 的模型，每个 token 的计算量只相当于一个 37B 的稠密模型。

负载为什么必须均衡

含义。 一个专家的负载（load），就是在一批 token 里，有多少个 token 被路由到了它那里。

理解。 可以借用这门课反复使用的医院类比（§4 会把它讲完整）：路由器是分诊台，路由专家是专科医生。如果分诊台把大部分病人都送进同一个科室，就会出两类问题。

第一类是学习上的：冷门专家很少收到 token，也就很少收到梯度，学不到东西；热门专家收到的梯度多，变得更好，于是更容易被选中。这种“富者愈富”的循环走到极端，就是路由坍缩（routing collapse）：少数专家包揽一切，其余专家形同虚设，模型的有效容量缩水。V3 报告把它列为负载不均的第一个后果 1。

第二类是系统上的：V3 训练时用 64 路专家并行（expert parallelism, EP），256 个路由专家平均分到 8 个节点的 64 张 GPU 上，每张卡 4 个专家 1。一个 MoE 层要等所有卡都算完才能进入下一步，所以这一步的耗时由最忙的那张卡决定。其余卡算完了只能干等。

数学。 衡量“最忙的比平均忙多少”，LossFree 论文定义了最大违背度（maximal violation, MaxVio）5：

最大违背度 MaxVio\[\mathrm{MaxVio}=\frac{\max_i \mathrm{Load}_i-\overline{\mathrm{Load}}}{\overline{\mathrm{Load}}}\]\(\mathrm{Load}_i\) 是专家 \(i\) 在统计范围内分到的 token 数，\(\overline{\mathrm{Load}}\) 是全体专家的平均。完全均衡时为 0；最忙的专家负载是平均的 \(1+\mathrm{MaxVio}\) 倍。(11.1)

LossFree 区分两种统计范围：在整个验证集上统计的 \(\mathrm{MaxVio}_{\rm global}\)，和在每个训练 batch 上统计的 \(\mathrm{MaxVio}_{\rm batch}\)；论文报告的 MaxVio 都是各 MoE 层取平均后的值 5。前者反映长期的偏好，后者才直接对应上面说的“每一步等最慢的卡”。

MaxVio 的两个读法

小例子。 4 个专家分到的 token 数是 \([5,2,1,4]\)，平均 \(12/4=3\)，最忙的是 5。\(\mathrm{MaxVio}=(5-3)/3\approx0.667\)：最忙的专家干了平均量的 1.667 倍。

V3 的尺度。 V3 预训练的大部分时间里，一个 batch 是 15360 条长 4096 的序列，也就是 \(15360\times4096=62{,}914{,}560\) 个 token 1。每个 token 选 8 个专家，一层一共要分派约 \(5.03\times10^8\) 次，平均每个专家 \(62{,}914{,}560\times8/256=1{,}966{,}080\) 次。若 MaxVio 为 0.72（下面 LossFree 实验里辅助损失基线的全局值），最忙的专家要处理约 338 万次，是平均的 1.72 倍。

对速度意味着什么。 如果每张卡的计算时间与它处理的 token 数成正比，这一层的耗时至多是完全均衡时的约 1.72 倍：一张卡放 4 个专家，卡的负载是 4 个专家之和，平均是 4 倍的专家均值，最忙的卡不会超过 \(4\times1.72\) 倍的专家均值；同卡的其他专家不那么忙时，差距会被摊薄一些。这是笔者为说明问题做的简化：真实耗时还取决于通信、专家在卡上的摆放，以及 MaxVio 在 batch 级而不是全局统计。

V2 的做法：三个辅助损失，外加丢 token

V2 用了两类手段（第 10 课 §3–§4 详讲）6。第一类是辅助损失（auxiliary loss）：在语言模型的交叉熵之外，再加三项惩罚——专家级均衡损失（系数 \(\alpha_1=0.003\)）、设备级均衡损失（\(\alpha_2=0.05\)）、通信均衡损失（\(\alpha_3=0.02\)）。它们都是 \(\alpha\sum_i f_iP_i\) 的形式，\(f_i\) 是“实际分到的比例”，\(P_i\) 是“路由器给的平均概率”，§3 会把它的定义和梯度逐项推出来。第二类是丢 token（token dropping）：给每台设备设一个计算预算（容量因子 1.0），超载的设备把亲和度最低的 token 丢掉，直到不超预算；为了不让训练与推理差太多，约 10% 的训练序列里的 token 永远不丢，评估时也不丢 6。

被丢掉的只是 token 在那台超载设备上的专家计算，它仍有残差、共享专家和其他设备上的路由专家（第 10 课 §4），这项代价是明摆着的。辅助损失的代价更隐蔽，LossFree 论文把它画成了一张图。

辅助损失的两难

这张图就是这一课要解决的问题。辅助损失的系数 \(\alpha\) 像一个旋钮：

  • 拧大（\(\alpha=0.01\)），负载几乎完全均衡（MaxVio 约 0.1），但困惑度最差（约 9.69）；
  • 拧到 \(0.001\)（与 V2-Lite 的专家级系数相同），MaxVio 是 0.72，困惑度 9.56；
  • 再拧小到 \(10^{-4}\)，困惑度降到约 9.53，负载却已明显失衡（MaxVio 约 2.2）；
  • 拧到 0，完全不管均衡，MaxVio 超过 5，困惑度反而回升到约 9.54——路由坍缩本身也伤害模型。

没有哪个 \(\alpha\) 能同时得到好的均衡和好的困惑度。而 LossFree 的做法（绿色星号）同时做到了 MaxVio 0.04、困惑度 9.50 5。两者的困惑度只差 \(9.56/9.50\approx1.0063\)，约 0.6%；在 3B 模型上是 7.97 对 7.92，比例也是 1.0063。差距不大，但它是在负载更均衡的同时得到的。

门控：从 softmax 到 sigmoid

在讲偏置之前，先要把 V3 的门控本身弄清楚，因为偏置是加在门控的某一个中间量上的。路由器对每个 token 要回答两个问题：去哪几个专家（选择），以及每个专家的输出占多大权重（加权）。V2 用同一个 softmax 分数回答这两个问题；V3 换成 sigmoid 分数，并且在选中的专家之间重新归一化。这一页说明这两处改动各自改变了什么。

三个量：中心向量、亲和度、门控值

专家中心向量（expert centroid）\(\mathbf e_i\)。含义：每个路由专家都有一个可学习的“标签向量”，形状与 token 的隐藏状态相同。理解：它像专科门口挂的牌子，写着“我擅长什么样的病人”；token 的隐藏状态与哪块牌子方向接近，就和哪个专家对口。数学：\(\mathbf e_i\in\R^{7168}\)，\(i=1,\dots,256\)；把 256 个 \(\mathbf e_i^\top\) 按行叠起来，就是路由器唯一的权重矩阵 \(W_g\in\R^{256\times7168}\)（发布的代码里它没有偏置项）2。

亲和度（affinity score）\(s_{i,t}\)。含义：token \(t\) 与专家 \(i\) 有多“对口”的分数。理解：先算点积 \(z_{i,t}=\mathbf u_t^\top\mathbf e_i\)（第 1 课：点积量的是同向程度），这是一个任意实数，叫逻辑值（logit，本课沿用英文）；再用一个函数把它压进 \((0,1)\)，变成分数。数学：V2 是 \(s_{i,t}=\softmax_i(\mathbf z_t)\)，依赖这个 token 的全部 \(N_r\) 个 logit（式 11.3）；V3 是 \(s_{i,t}=\sigma(z_{i,t})\)，只依赖自己的那一个（式 11.4）。\(\mathbf z_t\in\R^{N_r}\) 是把 \(z_{1,t},\dots,z_{N_r,t}\) 排成的列向量。

门控值（gating value）\(g_{i,t}\)。含义：专家 \(i\) 的输出在最终结果里占的权重。理解：像会诊时各科医生意见的分量；没被选中的专家门控值为 0。数学：式 (11.2) 中乘在 \(\FFN^{(r)}_i(\mathbf u_t)\) 前面的非负标量，每个 token 只有 \(K_r\) 个非零。V2 与 V3 的差别主要就在这个量怎么算。

有了这三个量，V3 的一个 MoE 层写成 1：

DeepSeekMoE 层的输出（V3 式 12）\[\mathbf h_t'=\mathbf u_t+\sum_{i=1}^{N_s}\FFN^{(s)}_i(\mathbf u_t)+\sum_{i=1}^{N_r}g_{i,t}\,\FFN^{(r)}_i(\mathbf u_t)\]\(\mathbf u_t\in\R^{d}\) 是进入这一层 FFN 的隐藏状态，\(\mathbf h_t'\in\R^{d}\) 是输出。注意第一项 \(\mathbf u_t\) 是残差连接，已经写在式子里了。V3 中 \(N_s=1\)、\(N_r=256\)，共享专家 \(\FFN^{(s)}\) 对每个 token 都算，没有门控。(11.2)
softmax 与 sigmoid熟悉这两个函数的可以跳过

softmax 把一组实数 \(z_1,\dots,z_N\) 变成一个概率分布：\(\softmax_i(\mathbf z)=e^{z_i}/\sum_{j=1}^{N}e^{z_j}\)。每个输出都在 \((0,1)\) 里，全部加起来等于 1；一个 \(z_j\) 变大，所有输出都会变（分母变了）。sigmoid 只处理一个数：\(\sigma(z)=1/(1+e^{-z})\)，也落在 \((0,1)\) 里，\(\sigma(0)=0.5\)，\(\sigma(z)\to1\) 当 \(z\to+\infty\)。对一组数逐个用 sigmoid，各输出互不相干，加起来也不必等于 1。两者的联系：只有两个数时 \(\softmax(z_1,z_2)_1=\sigma(z_1-z_2)\)。softmax 作为概率分布的性质见 M04 §4，它的导数（雅可比）见 M06 §5。

V2 的门控是 softmax 分数直接当门控值，选中的保留、其余置零 6：

V2 的门控（V2 式 21–22）\[s_{i,t}=\softmax_i\!\big(\mathbf u_t^\top\mathbf e_i\big),\qquad g_{i,t}=\begin{cases}s_{i,t},& s_{i,t}\in\TopK\big(\{s_{j,t}\mid 1\le j\le N_r\},K_r\big)\\0,&\text{其他}\end{cases}\]\(\TopK(\cdot,K)\) 是一个 token 对全体路由专家的亲和度中最大的 \(K\) 个组成的集合。V2 取 \(N_r=160\)、\(K_r=6\)。(11.3)

V3 把 softmax 换成 sigmoid，并多了一步归一化 1：

V3 的门控（V3 式 13–15）\[s_{i,t}=\sigma\!\big(\mathbf u_t^\top\mathbf e_i\big),\qquad g'_{i,t}=\begin{cases}s_{i,t},& s_{i,t}\in\TopK\big(\{s_{j,t}\},K_r\big)\\0,&\text{其他}\end{cases},\qquad g_{i,t}=\frac{g'_{i,t}}{\sum_{j=1}^{N_r}g'_{j,t}}\]分母只有被选中的 \(K_r=8\) 项非零，所以 \(g_{i,t}\) 就是“选中的 8 个亲和度各占总和的比例”，8 个门控值加起来恰好是 1。§4 会把 \(\TopK\) 里的 \(s\) 换成 \(s+b\)。(11.4)

一组数字：同样的 logit，两种门控

6 个专家，选 2 个

设某个 token 对 6 个专家的 logit 是 \(\mathbf z=(2.0,\ 1.5,\ 0.5,\ 0.0,\ -0.5,\ -1.0)\)，\(K=2\)。

V2（softmax）。 \(e^{z_i}\) 依次约为 \(7.389,\ 4.482,\ 1.649,\ 1,\ 0.607,\ 0.368\)，和为 \(15.494\)，除一下得 \(s=(0.477,\ 0.289,\ 0.106,\ 0.065,\ 0.039,\ 0.024)\)。选专家 1、2，门控值就是 \((0.477,\ 0.289)\)，两个加起来只有 \(0.766\)。

V3（sigmoid + 归一化）。 \(\sigma(z_i)\) 依次是 \(0.881,\ 0.818,\ 0.622,\ 0.500,\ 0.378,\ 0.269\)，六个加起来是 \(3.47\)，不是 1。仍选专家 1、2；归一化：\(0.881/(0.881+0.818)=0.519\)，\(0.818/1.699=0.481\)，加起来是 1。

动一下没被选中的专家。 把专家 3 的 logit 从 0.5 提到 1.4，它仍然排第三、仍然没被选中。V2：分母变成 \(15.494-1.649+4.055=17.900\)，专家 1、2 的门控值降到 \((0.413,\ 0.250)\)，这个 token 经过路由专家的那部分输出整体缩小了约 13%。V3：专家 1、2 的 sigmoid 值根本没变，门控值仍是 \((0.519,\ 0.481)\)。

推导：谁和谁耦合在一起

上面的数字现象有一个干净的解释：看每个亲和度对各个 logit 的导数。

softmax 与 sigmoid 的雅可比
(1)\(\displaystyle s_i=\dfrac{e^{z_i}}{Z},\quad Z=\sum_j e^{z_j}\)softmax 的定义，\(Z\) 叫配分函数（分母），它含有全部 logit
(2)\(\displaystyle \dfrac{\partial s_i}{\partial z_j}=\dfrac{\delta_{ij}e^{z_i}}{Z}-\dfrac{e^{z_i}e^{z_j}}{Z^2}\)商的求导法则；\(\partial Z/\partial z_j=e^{z_j}\)；\(\delta_{ij}\) 在 \(i=j\) 时为 1，否则为 0
(3)\(\displaystyle =s_i(\delta_{ij}-s_j)\)提出 \(e^{z_i}/Z=s_i\)；\(i\ne j\) 时是 \(-s_is_j\ne0\)：每个分数都被其他所有 logit 牵动
(4)\(\displaystyle \dfrac{\partial\sigma(z_i)}{\partial z_j}=\delta_{ij}\,\sigma(z_i)\big(1-\sigma(z_i)\big)\)sigmoid 只含自己的 \(z_i\)；\(i\ne j\) 时导数为 0，分数之间互不牵动
两种亲和度的雅可比\[\text{softmax：}\ \frac{\partial s_i}{\partial z_j}=s_i(\delta_{ij}-s_j),\qquad \text{sigmoid：}\ \frac{\partial s_i}{\partial z_j}=\delta_{ij}\,s_i(1-s_i)\]softmax 的雅可比是稠密矩阵（每个元素都不为 0；它并不满秩，每行之和为 0），sigmoid 的是对角矩阵。(11.5)

有意思的是，如果 V2 当初也在选中的专家之间归一化，softmax 的这种牵连在门控值里就会消失。设选中的集合为 \(\mathcal S\)：

归一化之后，softmax 的分母被约掉
(1)\(\displaystyle g_i=\dfrac{s_i}{\sum_{j\in\mathcal S}s_j}=\dfrac{e^{z_i}/Z}{\sum_{j\in\mathcal S}e^{z_j}/Z}\)代入 softmax 的定义
(2)\(\displaystyle =\dfrac{e^{z_i}}{\sum_{j\in\mathcal S}e^{z_j}}\)分子分母的 \(1/Z\) 约掉：结果只含被选中专家的 logit

所以图 11.3 Ⓒ 里 V2 门控值的变化，来自“softmax 的分母含全体专家”加上“不归一化”这两件事同时成立。V3 的门控值 \(g_i=\sigma(z_i)/\sum_{j\in\mathcal S}\sigma(z_j)\) 在选中集合 \(\mathcal S\) 给定时只依赖被选中的 8 个专家自己的 logit（其余 logit 只能通过改变排序、换掉 \(\mathcal S\) 的成员来影响它）。

这里要分清楚哪些是事实、哪些是解读。事实：V3 报告只说“使用 sigmoid 计算亲和度”“在选中的亲和度之间归一化”，没有给出理由 1。sigmoid 门控也不是 V3 首创：早四个月的 LossFree 论文主实验就用 sigmoid，并报告在它的设定下 sigmoid 基线的表现好于 softmax 基线（附录 C.1 称 softmax 门控在相近的均衡程度下困惑度更高、对不均衡更敏感）5。解读：上面的导数说明了 sigmoid 让各专家的分数彼此独立，这是笔者给出的机制性说明，不是论文的论证。

偏置眼中的耦合

LossFree 附录 C.2 还给了一个与偏置直接相关的理由：softmax 的归一化让偏置更难调，因为一个专家与另一个专家的分差会受到其余专家分数的影响 5。§4 才正式引入偏置，这里先看这句话在数学上指什么。假设比较专家 \(i\)、\(j\) 谁排在前面，给它们各加一个偏置：

加偏置后两个专家的排序\[s_i+b_i>s_j+b_j\iff s_i-s_j>b_j-b_i\]右边是偏置之差，对所有 token 都一样；左边是这个 token 上两个亲和度之差。sigmoid 时左边只取决于 \(z_i\)、\(z_j\)；softmax 时左边等于 \((e^{z_i}-e^{z_j})/Z\)，还取决于其余所有专家的 logit。(11.6)
同样的偏置，softmax 下效果因 token 而异

6 个专家，每个 token 只选 1 个（\(K=1\)）。偏置只给专家 2：\(b_2-b_1=0.05\)。两个 token 对专家 1、2 的 logit 相同（2.0 和 1.8），只是其余 4 个专家的 logit 不同：

  • token A：其余四个都是 0。softmax：\(Z=7.389+6.050+4\times1=17.439\)，\(s_1=0.4237\)，\(s_2=0.3469\)，差 \(0.0768>0.05\)，偏置扳不过来，仍选专家 1。
  • token B：其余四个都是 1.7（仍低于 1.8）。softmax：\(Z=7.389+6.050+4\times5.474=35.334\)，\(s_1=0.2091\)，\(s_2=0.1712\)，差 \(0.0379<0.05\)，偏置扳过来了，改选专家 2。
  • sigmoid：两个 token 的 \(\sigma(2.0)-\sigma(1.8)=0.8808-0.8581=0.0226\) 完全相同，偏置对两者的作用也相同，都改选专家 2（专家 3–6 的 \(\sigma(1.7)=0.8455\) 仍排在后面）。

同一个偏置，在 softmax 下对 A 无效、对 B 有效，取决于与这两个专家无关的其他四个专家。这就是“偏置更难调”的含义：你想挪动专家 1、2 之间的分流比例，却要看每个 token 上其他专家的脸色。

为什么要“选中后归一化”，以及代码里的 2.5

sigmoid 分数不是概率，8 个选中的分数之和可以在 0 到 8 之间任意变化。如果直接拿它们当门控值，同一层对不同 token 的路由输出会忽大忽小（sigmoid 分数普遍高的 token 输出就大）。归一化把 8 个门控值之和固定为 1，路由部分的输出尺度就只由专家本身决定。这是笔者从公式读出的作用，V3 报告没有解释为什么要归一化。

读发布的代码会发现一个论文里没有的常数。Hugging Face 上的 MoEGate 和 DeepSeek 官方推理仓库的 Gate 都在归一化之后再乘 routed_scaling_factor = 2.5 2,4：

代码中的门控值\[g_{i,t}=2.5\cdot\frac{s_{i,t}}{\sum_{j\in\mathcal S_t}s_{j,t}},\qquad i\in\mathcal S_t\]\(\mathcal S_t\) 是 token \(t\) 选中的 8 个专家。V3 报告的式 (13) 没有这个 2.5。作为对照，V2 的配置不归一化，乘的是 16.0 7。(11.7)

这个常数从哪来？V2 和 V3 的报告都提到，在“宽度瓶颈”处（包括路由专家的中间隐状态）会乘一个额外的缩放因子，但没有给数值 6,1。专家的下投影是线性的，把中间隐状态乘一个常数，等价于把门控值乘同一个常数；所以笔者推测代码里的 2.5 就是那个缩放因子的实现方式，只是论文没写数值。这是推测，不是论文的陈述。

还有一个工程细节：V3 用 FP8 训练，但报告专门把“MoE 门控模块”列在保持 BF16/FP32 高精度的组件清单里 1。门控决定 token 去哪里，一点数值误差就可能让排在第 8、第 9 的两个专家交换位置，第 12 课 §4 讲 FP8 时会再回到这份清单。

失败模式：sigmoid 的饱和

sigmoid 在 \(\abs{z}\) 较大时很平：\(\sigma(4)=0.982\)，\(\sigma(5)=0.993\)。如果很多专家的 logit 都很大，亲和度会挤在 1 附近，排序对微小扰动很敏感，归一化后的门控值也趋于平均。softmax 没有这个上限，logit 差 1 永远意味着概率比 \(e\approx2.72\) 倍。这是从函数形状读出的风险（笔者推理），论文没有报告 V3 训练中出现这种现象。

小练习：门控值之和

沿用上面的 6 个 logit，但改成 \(K=3\)。分别求 V2 与 V3 的门控值和它们的总和。

看答案

V2：选专家 1、2、3，门控值就是 softmax 分数，保留四位小数是 \((0.4769,\ 0.2893,\ 0.1064)\)，和为 \(0.8726\)。V3：sigmoid 分数 \((0.881,\ 0.818,\ 0.622)\)，和为 \(2.321\)，归一化得 \((0.380,\ 0.352,\ 0.268)\)，和为 1。V2 的和随 \(K\) 和 logit 的分布变化（\(K=2\) 时是 0.766），V3 的和恒为 1（乘 2.5 之后恒为 2.5）。

本页要点
  • V3 门控 = sigmoid 亲和度 + Top-8 选择 + 在选中的 8 个之间归一化（式 11.4），代码里再乘 2.5（式 11.7，论文未写数值）。
  • softmax 的雅可比是稠密的（每个分数被所有 logit 牵动），sigmoid 的是对角的；V2 又不归一化，所以一个没被选中的专家变热，也会改变 V2 的门控值。
  • 同一个偏置，在 softmax 下的作用因 token 而异（受无关专家的 logit 影响），在 sigmoid 下只取决于这两个专家自己。V3 没有说明为什么换 sigmoid；LossFree 报告了 sigmoid 基线更好的实验结果。

辅助损失为什么会伤害性能

LossFree 论文对辅助损失的指控归结起来是一句话（摘要和引言里反复出现）：辅助损失一大，就会往训练里引入“不可忽略的干扰梯度”，从而损害模型性能 5。这句话听起来有道理，但“干扰梯度”究竟是哪些梯度、流到了哪里，论文没有写出来。这一页先把均衡损失的定义讲透，再把它的梯度一行一行推出来，最后分清楚：这个论断里哪些是测出来的，哪些是推理。

均衡损失 \(f_iP_i\)：两个因子各管什么

含义。 经典的专家级均衡损失是两组数的内积：\(f_i\) 是专家 \(i\) 实际分到的 token 比例，\(P_i\) 是路由器打算分给专家 \(i\) 的平均概率。V3 报告和 LossFree 都把这种做法的出处追溯到 GShard 与 Switch Transformer 1,5,8，第 7 课 §3 讲过它的来历。

理解。 可以把 \(\sum_if_iP_i\) 读成“按拥挤程度加权的概率总和”：一个专家越拥挤（\(f_i\) 越大），路由器分给它的概率 \(P_i\) 就越受惩罚。\(f_i\) 来自计数，是离散的，没法求导，在反向传播中当作常数；真正传梯度的是 \(P_i\)。于是这个损失的作用是：把概率从拥挤的专家那里挪走。

数学。 V2 的专家级均衡损失写成（V2 式 23–25）6：

专家级均衡损失\[\mathcal L_{\rm ExpBal}=\alpha\sum_{i=1}^{N_r}f_iP_i,\qquad f_i=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb 1(\text{token } t \text{ 选中专家 } i),\qquad P_i=\frac1T\sum_{t=1}^{T}s_{i,t}\]\(T\) 是一条序列的 token 数（V2 的定义：这个损失按每条序列分别计算，再对 batch 求平均，见第 10 课 §3），\(\mathbb 1(\cdot)\) 条件成立时为 1、否则为 0，\(s_{i,t}\) 是 softmax 亲和度（式 11.3），\(\alpha\) 是平衡系数（V2 取 \(\alpha_1=0.003\)）。(11.8)

系数 \(N_r/(K_rT)\) 的作用是把 \(f_i\) 放大成“完全均衡时等于 1”。下面的推导把这件事和损失在两个极端情形下的取值一起算出来。

均衡损失的两个极端情形
(1)\(\displaystyle \sum_{i=1}^{N_r}\sum_{t=1}^{T}\mathbb 1(t\text{ 选中 }i)=K_rT\)每个 token 恰好选 \(K_r\) 个专家，交换求和次序后按 token 数
(2)\(\displaystyle \sum_{i}f_i=\dfrac{N_r}{K_rT}\cdot K_rT=N_r\)代入 \(f_i\) 的定义：不论路由如何，\(f_i\) 之和恒为 \(N_r\)
(3)\(\displaystyle \text{完全均衡：}f_i\equiv1\ \Rightarrow\ \mathcal L=\alpha\sum_iP_i=\alpha\)\(N_r\) 个 \(f_i\) 平分 \(N_r\)；softmax 的 \(s_{i,t}\) 对 \(i\) 求和为 1，所以 \(\sum_iP_i=1\)
(4)\(\displaystyle \text{完全坍缩：}f_i=\dfrac{N_r}{K_r}\ (i\in\mathcal C),\ P_i=\dfrac1{K_r}\ (i\in\mathcal C)\)所有 token 都选同一组 \(K_r\) 个专家 \(\mathcal C\)，概率也平均集中在它们身上
(5)\(\displaystyle \mathcal L=\alpha\cdot K_r\cdot\dfrac{N_r}{K_r}\cdot\dfrac1{K_r}=\alpha\,\dfrac{N_r}{K_r}\)\(\mathcal C\) 中 \(K_r\) 项求和，其余项 \(f_i=0\)

这两个值一个是上界，另一个却不是下界。上界：一个 token 至多选专家 \(i\) 一次，计数不超过 \(T\)，所以 \(f_i\le\frac{N_r}{K_rT}\cdot T=\frac{N_r}{K_r}\)，于是 \(\sum_if_iP_i\le\frac{N_r}{K_r}\sum_iP_i=\frac{N_r}{K_r}\)，坍缩时恰好取到。不是下界：取 \(N_r=3\)、\(K_r=1\)、\(T=2\)，两个 token 的 softmax 亲和度分别是 \((0.50,\ 0.02,\ 0.48)\) 与 \((0.02,\ 0.50,\ 0.48)\)，各自选专家 1、2。于是 \(f=(1.5,\ 1.5,\ 0)\)，\(P=(0.26,\ 0.26,\ 0.48)\)，\(\sum_if_iP_i=1.5\times0.52=0.78<1\)：专家 3 一个 token 都没分到，损失却比完全均衡时的 \(\alpha\) 还小。所以 \(\mathcal L_{\rm ExpBal}\) 的数值不是“离均衡有多远”的度量，它起作用靠的是梯度的方向（下面的式 11.9：这个例子里，梯度下降会抬高两个 token 对专家 3 的 logit）。

损失有多大

V2：\(\alpha_1=0.003\)、\(N_r=160\)、\(K_r=6\)。完全均衡时 \(\mathcal L_{\rm ExpBal}=0.003\)；完全坍缩时 \(0.003\times160/6=0.08\)。作为对照，语言模型的交叉熵大约是 2 nats 的量级：例如 V3 §4.5.3 里 1B、3B 两个 MoE 模型的验证损失约为 2.25 与 2.08（§5 会用到这组实验）1；nats 的含义见第 2 课 §2。

所以均衡损失在数值上始终很小。它的影响不在于损失值本身，而在于它的梯度指向哪里、推动了哪些参数。下面就来算这个梯度。

推导：梯度流向哪里

记第 \(t\) 个 token 对专家 \(k\) 的 logit 为 \(z_{k,t}=\mathbf u_t^\top\mathbf e_k\)，亲和度 \(s_{\cdot,t}=\softmax(z_{\cdot,t})\)。把 \(f_i\) 当作常数，对 logit 求导：

均衡损失对 logit 的梯度
(1)\(\displaystyle \dfrac{\partial\mathcal L}{\partial s_{i,t}}=\dfrac{\alpha f_i}{T}\)\(P_i=\frac1T\sum_ts_{i,t}\)，\(s_{i,t}\) 只出现在 \(P_i\) 这一项里
(2)\(\displaystyle \dfrac{\partial\mathcal L}{\partial z_{k,t}}=\sum_{i}\dfrac{\alpha f_i}{T}\,\dfrac{\partial s_{i,t}}{\partial z_{k,t}}\)链式法则：\(z_{k,t}\) 通过 softmax 影响这个 token 的全部 \(s_{i,t}\)
(3)\(\displaystyle =\dfrac{\alpha}{T}\sum_{i}f_i\,s_{i,t}(\delta_{ik}-s_{k,t})\)代入 softmax 的雅可比（式 11.5）
(4)\(\displaystyle =\dfrac{\alpha}{T}\,s_{k,t}\Big(f_k-\sum_i f_is_{i,t}\Big)\)\(\delta_{ik}\) 挑出 \(i=k\) 那一项；第二部分提出公因子 \(s_{k,t}\)

把 \(\bar f_t=\sum_if_is_{i,t}\) 叫作“这个 token 眼中的平均拥挤度”：它是各专家的 \(f_i\) 按这个 token 自己的路由概率加权的平均。于是

均衡损失对 logit 的梯度\[\frac{\partial\mathcal L_{\rm ExpBal}}{\partial z_{k,t}}=\frac{\alpha}{T}\,s_{k,t}\big(f_k-\bar f_t\big),\qquad \bar f_t=\sum_{i=1}^{N_r}f_i\,s_{i,t}\]专家 \(k\) 比这个 token 眼中的平均更拥挤（\(f_k>\bar f_t\)），梯度为正，梯度下降会压低 \(z_{k,t}\)；反之抬高。对 \(k\) 求和，\(\sum_ks_{k,t}(f_k-\bar f_t)=\bar f_t-\bar f_t=0\)：它只在专家之间“挪”分数。(11.9)

logit 是 \(\mathbf u_t\) 与 \(\mathbf e_k\) 的点积，所以 \(\partial z_{k,t}/\partial\mathbf u_t=\mathbf e_k\)，\(\partial z_{k,t}/\partial\mathbf e_k=\mathbf u_t\)。再用一次链式法则：

梯度的两个去处\[\frac{\partial\mathcal L_{\rm ExpBal}}{\partial\mathbf u_t}=\frac{\alpha}{T}\sum_{k=1}^{N_r}s_{k,t}\big(f_k-\bar f_t\big)\,\mathbf e_k,\qquad \frac{\partial\mathcal L_{\rm ExpBal}}{\partial\mathbf e_k}=\frac{\alpha}{T}\sum_{t=1}^{T}s_{k,t}\big(f_k-\bar f_t\big)\,\mathbf u_t\]第一个梯度落在 token 的隐藏状态上，第二个落在专家的中心向量（路由器的权重）上。(11.10)

第二个梯度是我们想要的：路由器调整自己的“门牌”，让拥挤专家的门牌与 token 不那么对口。第一个梯度才是麻烦所在。\(\mathbf u_t\) 不是路由器的参数，它是注意力层的输出加上残差，是模型对这个 token 在这一层的全部理解。它本身不是可训练的参数，但这个梯度会经反向传播落到产生 \(\mathbf u_t\) 的所有参数 \(\theta\) 上。记 \(\nabla_{\mathbf u}\mathcal L=\partial\mathcal L_{\rm ExpBal}/\partial\mathbf u_t\in\R^{d}\)（式 11.10 的第一项），雅可比 \(J=\partial\mathbf u_t/\partial\theta\in\R^{d\times n_\theta}\)（\(n_\theta\) 是这些参数的个数）。只看均衡损失经 \(\mathbf u_t\) 传来的这一份梯度，学习率 \(\eta\) 的一步梯度下降是 \(\Delta\theta=-\eta J^\top\nabla_{\mathbf u}\mathcal L\in\R^{n_\theta}\)，它让 \(\mathbf u_t\) 变化约

\[\begin{aligned}\Delta\mathbf u_t&\approx J\,\Delta\theta=-\eta\,JJ^\top\nabla_{\mathbf u}\mathcal L,\\ (\nabla_{\mathbf u}\mathcal L)^\top\Delta\mathbf u_t&\approx-\eta\,\norm{J^\top\nabla_{\mathbf u}\mathcal L}^2\le0 .\end{aligned}\]

也就是说，一阶近似下 \(\mathbf u_t\) 总是朝着让均衡损失下降的方向移动：改写 token 的表示本身，把它从拥挤专家的中心向量那里推开。这个梯度继续向下传，进入这一层的注意力、残差流，以及前面的每一层。这就是“干扰梯度”在数学上的具体形态：一个与“预测下一个词”无关的目标，在改动所有层的参数。

4 个专家、4 个 token 的梯度

取 \(N_r=4\)、\(K_r=1\)、\(T=4\)。这条序列里 3 个 token 选了专家 1，1 个选了专家 2，计数 \([3,1,0,0]\)，\(f_i=\frac{4}{1\times4}\times\) 计数 \(=[3,1,0,0]\)（和为 \(N_r=4\)，符合上面的推导）。

看其中一个 token，它的 logit 是 \((1.0,\ 0.5,\ 0.0,\ -0.5)\)，softmax 得 \(s=(0.4551,\ 0.2760,\ 0.1674,\ 0.1015)\)。它眼中的平均拥挤度 \(\bar f=3\times0.4551+1\times0.2760=1.6412\)。由式 (11.9)，\(\frac{T}{\alpha}\frac{\partial\mathcal L}{\partial z_k}=s_k(f_k-\bar f)\)：

  • 专家 1：\(0.4551\times(3-1.6412)=+0.6183\)；
  • 专家 2：\(0.2760\times(1-1.6412)=-0.1770\)；
  • 专家 3：\(0.1674\times(0-1.6412)=-0.2747\)；
  • 专家 4：\(0.1015\times(0-1.6412)=-0.1666\)。

四项之和为 0。梯度下降压低专家 1 的 logit，抬高其余三个。落到隐藏状态上：\(\frac{T}{\alpha}\frac{\partial\mathcal L}{\partial\mathbf u}=0.6183\,\mathbf e_1-0.1770\,\mathbf e_2-0.2747\,\mathbf e_3-0.1666\,\mathbf e_4\)，下降方向把 \(\mathbf u\) 从 \(\mathbf e_1\) 推开。笔者用有限差分核对过这组数，误差在 \(10^{-6}\) 以内。

图景：为了排队均衡而改写病历

用医院类比来说：辅助损失相当于为了让各科室排队均衡，去改写病人的病历，让病历读起来不那么像心内科的病人，分诊台自然就把他送去别处。可病历不只给分诊台看，后面每一位医生都要依据它治疗。偏置的做法则是只改分诊台的规则：病历原封不动，分诊台看到心内科排长队，就把心内科的推荐分临时调低一点。

这个类比的边界：模型里的“病历”\(\mathbf u_t\) 是连续向量，辅助损失对它的改动很小（系数 \(\alpha\) 小），而且与语言模型的梯度叠加在一起，并不是“另写一份”；改得多了才伤性能，这正是图 11.2 里 \(\alpha\) 越大困惑度越高的那一段。

证据有多强

把这个论断拆成三层，各自的证据强度不同。

  1. 实测：在 LossFree 的 1B / 3B 模型上，把辅助损失换成偏置，困惑度从 9.56 降到 9.50、从 7.97 降到 7.92，同时 \(\mathrm{MaxVio}_{\rm global}\) 从 0.72 / 0.52 降到 0.04 5；V3 在 15.7B 与 228.7B 两个规模上的消融也显示无辅助损失版本在多数基准上更好（§8 详列）1。
  2. 机制：上面的梯度推导说明辅助损失确实会把梯度送进 \(\mathbf u_t\) 和所有更早的层。但推导只证明了这条路径存在，没有测量它造成了多少性能损失。LossFree 没有把“干扰梯度”单独分离出来测量，它的证据是 \(\alpha\) 扫描（图 11.2）5。所以“性能损失来自干扰梯度”是一个合理的解释，不是被证明的结论。
  3. 反面的线索：V3 自己的实验显示，辅助损失只要把统计范围放宽到整个 batch，验证损失就与无辅助损失方法相同（1B 都是 2.253，3B 都是 2.080）1。关键因素可能是均衡约束的范围，而不只是“用不用损失函数”（§5）。

还有一个背景值得知道：LossFree 只是 arXiv 预印本，它投稿 ICLR 2025 的记录在 OpenReview 上标注为未录用；V3 是技术报告，也没有经过同行评审。支持这一方法的大规模证据，主要来自 DeepSeek 自己的实验。

常见误解：辅助损失只影响路由器

辅助损失确实定义在路由器的输出上，但式 (11.10) 说明它的梯度同时落在 \(\mathbf e_k\) 和 \(\mathbf u_t\) 上；后者再经反向传播进入注意力层和前面所有层的参数。只有当路由器的输入被截断梯度（stop-gradient）时，它才只影响路由器；本课读到的 V2、V3 报告相关章节都没有提到这样做。

小练习：均衡时的梯度

在上面的算例中，如果这条序列的计数是 \([1,1,1,1]\)（完全均衡），式 (11.9) 给出的梯度是多少？这说明辅助损失在什么时候“不出力”？

看答案

\(f_i=\frac{4}{1\times4}\times1=1\) 对所有 \(i\) 成立，\(\bar f=\sum_if_is_i=\sum_is_i=1\)，所以每一项 \(s_k(f_k-\bar f)=0\)，梯度为零。把 \(f\) 当常数时，只要负载完全均衡，\(\mathcal L=\alpha\sum_iP_i=\alpha\) 是常数，辅助损失对任何参数都没有梯度；它只在不均衡时出力。由式 (11.9)，对 logit 的推力大小是 \(\frac{\alpha}{T}s_{k,t}\abs{f_k-\bar f_t}\)：与 \(\alpha\) 成正比，并随专家 \(k\) 的拥挤度偏离这个 token 眼中平均值的程度增大。

本页要点
  • \(\mathcal L=\alpha\sum_if_iP_i\)：\(f_i\) 是实际比例（不可导，当常数），\(P_i\) 是平均概率（传梯度）；\(\sum_if_i=N_r\) 恒成立，均衡时 \(\mathcal L=\alpha\)，坍缩时 \(\alpha N_r/K_r\)（后者是上界；前者不是下界，损失值不能当均衡度量）。
  • 梯度 \(\partial\mathcal L/\partial z_{k,t}=\frac{\alpha}{T}s_{k,t}(f_k-\bar f_t)\) 同时落在路由器的 \(\mathbf e_k\) 和 token 表示 \(\mathbf u_t\) 上；后者一路传进更早的层，这就是“干扰梯度”的具体形态（笔者推导）。
  • 实测的是“换成偏置后困惑度更低、均衡更好”；“性能损失来自干扰梯度”是解释而非证明；V3 自己的实验还提示，均衡约束的范围可能同样关键。

无辅助损失均衡：只管分诊的偏置

上一页的结论是：辅助损失的问题在于它有梯度，而且梯度会改写 token 的表示。那么反过来问：能不能不产生任何梯度，也能把 token 引向空闲的专家？能。办法是在“选谁”这一步动手脚，而且只在这一步动手脚。

图景：分诊台的推荐分

类比：MoE = 医院，偏置 = 分诊台的推荐分

映射。 路由器 = 分诊台；路由专家 = 专科医生；共享专家 = 每个病人都要看的全科医生；细粒度切分（第 7 课）= 把“内科”拆成心内、消化、呼吸……，组合更灵活；负载均衡 = 别让所有病人都挤进一个科室；偏置 \(b_i\) = 分诊台看到某科排队太长，就把它的“推荐分”暂时调低，排队短的科室调高；门控值 = 各科医生的意见在最终诊断里占的分量。

收益。 这个类比说清了两件事。第一，推荐分只影响“去哪个科”，不影响“各科意见占多大分量”：病人被分到心内科以后，心内科医生的意见权重仍按病情（亲和度 \(s\)）决定，所以偏置不进入门控值。第二，调推荐分不需要“学习”，只需要看排队长度：分诊台不必改写病历（不产生梯度），也不必重新培训医生。

失效的地方。 分诊是逐个 token 进行的，同一句话里的不同词会去不同科室；各“专科”擅长什么是训练中自发形成的，不是人指定的。还有一点最容易被忽略：推荐分只在“两可”的病人身上起作用。一个 token 如果对某个专家的亲和度远高于其他专家，小小的偏置扳不动它；偏置改变的是那些第 8 名与第 9 名分数很接近的 token 的去向。

形式化：选择用 \(s+b\)，加权用 \(s\)

V3 给每个路由专家一个偏置 \(b_i\)（一个标量，每个 MoE 层各有 256 个），把它加在亲和度上，只用于 Top-K 选择 1：

带偏置的选择（V3 式 16）\[g'_{i,t}=\begin{cases}s_{i,t},& s_{i,t}+b_i\in\TopK\big(\{s_{j,t}+b_j\mid 1\le j\le N_r\},K_r\big)\\0,&\text{其他}\end{cases}\]它替换式 (11.4) 中的 \(g'_{i,t}\)；归一化 \(g_{i,t}=g'_{i,t}/\sum_jg'_{j,t}\) 不变。注意被选中之后，门控值仍取原始的 \(s_{i,t}\)，不是 \(s_{i,t}+b_i\)。V3 报告的原话是：偏置项只用于路由。(11.11)

偏置怎么变？V3 的描述是：每一步训练结束时，统计整个 batch 上每个专家的负载；过载的专家把偏置减小 \(\gamma\)，欠载的增大 \(\gamma\)；\(\gamma\) 叫作偏置更新速度（bias update speed）1。写成式子（式子是笔者按这段文字写的，与 LossFree 的算法 1 一致）：

偏置的 sign 更新\[b_i\leftarrow b_i-\gamma\,\sign\!\big(\mathrm{Load}_i-\overline{\mathrm{Load}}\big),\qquad \gamma=\begin{cases}0.001,&\text{前 14.3T tokens}\\0,&\text{最后 500B tokens}\end{cases}\]\(\mathrm{Load}_i\) 是专家 \(i\) 在这一步整个 batch 上分到的 token 数，\(\overline{\mathrm{Load}}\) 是平均。\(\sign(x)\) 在 \(x>0\) 时为 \(+1\)，\(x<0\) 时为 \(-1\)。\(\gamma\) 的取值出自 V3 §4.2。(11.12)

这里有两处论文没有说清的地方，必须照实交代。第一，V3 没有定义“过载”的阈值；用平均负载作阈值是 LossFree 的定义：它的算法 1 先算负载误差 \(\delta_i=\overline{c}-c_i\)（\(c_i\) 是专家 \(i\) 的计数），再令 \(b_i\leftarrow b_i+\gamma\,\sign(\delta_i)\)，与式 (11.12) 相同 5。负载恰好等于平均时怎么处理，两篇论文都没说。第二，“整个 batch”的负载在多机训练中如何跨数据并行组汇总，V3 也没有说明。训练代码没有公开，这两点无法核实。

三条性质

性质一：偏置没有梯度。 \(b_i\) 只出现在 \(\TopK\) 的比较里。\(\TopK\) 的结果是离散的集合：让 \(b_i\) 变动一个很小的量，只要没有改变排序，选出的集合就完全不变；一旦改变排序，结果就跳变。所以损失对 \(b_i\) 的导数在几乎所有地方都是 0，在跳变处不存在。偏置不是靠反向传播训练的参数，由计数规则 (11.12) 更新；门控值用的是 \(s_{i,t}\)，其余参数的梯度也不经过 \(b_i\)。

性质二：只有偏置之差有意义。

给全部偏置加同一个常数，Top-K 不变
(1)\(\displaystyle s_{i,t}+(b_i+c)>s_{j,t}+(b_j+c)\)设给所有专家的偏置都加上同一个常数 \(c\)，比较任意两个专家
(2)\(\displaystyle \iff s_{i,t}+b_i>s_{j,t}+b_j\)不等式两边同时减去 \(c\)
(3)\(\displaystyle \TopK\big(\{s_{j,t}+b_j+c\}\big)=\TopK\big(\{s_{j,t}+b_j\}\big)\)Top-K 只取决于两两比较的结果，而所有比较都不变

一个推论：sign 规则并不保持 \(\sum_ib_i\) 不变。过载专家与欠载专家的个数一旦不相等，总和就会漂移；但漂移只是给全体偏置加了一个常数，不影响任何选择。发布的 V3 权重印证了这一点：直接读取 Hugging Face 上的权重文件，全部 58 个 MoE 层的偏置张量（名为 e_score_correction_bias，另有一份属于 MTP 层，共 59 份）都是正数，落在 \([2.03,\ 8.05]\) 之间，各层的均值从约 2.23 到约 8.04 不等；而同一层之内的极差只有 0.013 到 0.221，中位数 0.045 2。整体漂移比层内差值大一到两个数量级，真正起作用的只是那一点层内差值。

性质三：每一步最多挪 \(\gamma\)。 由 (11.12)，每一步每个偏置恰好变化 \(\gamma\)（或不变），所以 \(n\) 步之后

偏置的移动速度上限\[\big|b_i^{(n)}-b_i^{(0)}\big|\le n\gamma\]\(b_i^{(n)}\) 是第 \(n\) 步后的偏置。V3 的 \(\gamma=0.001\)：100 步最多挪 0.1。(11.13)

这个上限决定了控制器的“反应速度”。V3 满 batch 时一步是 62,914,560 个 token，100 步就是约 63 亿 token；整个预训练估计约 24 万步（batch 爬坡阶段按线性增长估算，属于近似）。所以偏置对单步的随机波动反应迟钝，对跨越几十亿 token 的缓慢漂移（比如数据分布变化、专家逐渐特化）却跟得上。

LossFree 还比较过两种变体：把 \(\sign(\delta_i)\) 换成 \(\delta_i\) 本身（按误差大小成比例调整），均衡略好但困惑度没有更好，所以保留 sign 版；把加性偏置换成乘性偏置 \(s_{i,t}\cdot b_i\)，效果略差 5。

为什么只能用上一步的负载

偏置在第 \(n\) 步使用的值，是根据第 \(n-1\) 步及更早的负载算出来的。能不能更“及时”一点，直接按当前序列的负载来调？LossFree 指出不行：用当前序列的负载信息做路由，会破坏语言模型的因果约束，让未来 token 的信息泄漏进过去 token 的计算里 5。

失败模式：Expert Choice 路由的信息泄漏

专家选择（Expert Choice）路由反过来让每个专家在一批 token 里挑自己要的，均衡是天然的，但一个 token 被不被选中，取决于同一批里其他（包括它后面的）token。LossFree 附录 D 给出泄漏量的下界：稀疏率 \(R=K_r/N_r\) 时，每个 token 每层能泄漏超过 \(K_r\log_2\frac{1-R}{R}\) 比特（论文写作 \(K/N\)，这里换成课程记号，\(N\) 在课程里是参数量）。取 \(K_r=2\)、\(N_r=16\)，\(R=1/8\)，每层 \(2\log_27\approx5.61\) 比特，9 层合计约 50.5 比特；论文在块大小 512 的实验中观察到约 10% 的异常损失下降，说明模型确实在“偷看” 5。偏置方法只用已经过去的 batch 的统计量，不存在这个问题。

一次玩具训练

一步更新看不出控制器的动态。下面是笔者的模拟（脚本 figures/gen/l11_sim_balance.py）：16 个专家、每个 token 选 2 个、每步 4096 个随机 token；每个专家有固定的“热度”偏移 \(c_i\)（从 \(-1\) 均匀排到 \(+1\)），亲和度 \(s=\sigma(\mathbf u^\top\mathbf e_i+c_i)\)。除了偏置什么都不学，所以它只检验偏置这个控制器本身。

从图上可以读出几组数（全部由脚本算出）：

  • \(\gamma=10^{-4}\)：MaxVio 在第 100 步仍是 1.576，第 1000 步 0.615，第 3000 步才降到 0.051。平衡时最高与最低的偏置要相差约 0.39（3000 步后是 0.218 与 \(-0.175\)）；每步两者最多相向各挪 \(10^{-4}\)，差距每步最多拉开 \(2\times10^{-4}\)，所以至少要约 1960 步。

  • \(\gamma=10^{-2}\)：第 30 步就降到 0.113，但此后不再往下走，而是在 0.1–0.2 一带来回抖动（最后 100 步约八成落在 0.11–0.20 之间，平均 0.153），比 \(10^{-3}\) 差。原因是每一步 \(\pm0.01\) 的调整已经大到会整批地改变“两可” token 的去向，控制器在目标附近来回过冲。

数值精度：偏置为什么要用 FP32

BF16 的间隔熟悉浮点格式的可以跳过

BF16 用 16 位存一个数：1 位符号、8 位指数、7 位尾数。在 \([2^e,2^{e+1})\) 这一段里，相邻两个可表示的数相差 \(2^{e-7}\)。例如 \([0.5,1)\) 里的间隔是 \(2^{-8}\approx0.0039\)，\([4,8)\) 里是 \(2^{-5}=0.03125\)。加法的结果要舍入到最近的可表示数，所以一个小于半个间隔的增量会被舍掉，这叫吞没（swamping）。各种格式的位布局见 M08 §3，就近舍入与吞没见 M08 §4–§5。

0.001 加不上去

若某个偏置用 BF16 存储，当前值 \(b_i=0.625\)（\(=1.01_2\times2^{-1}\)，BF16 能精确表示）：它落在 \([0.5,1)\)，间隔 \(2^{-8}=0.00390625\)，下一个可表示数是 \(0.62890625\)，半个间隔约 \(0.00195\)。每步加 \(\gamma=0.001\)，结果 \(0.626\) 离 \(0.625\) 比离 \(0.62890625\) 更近，舍入回 \(0.625\)。偏置永远不动，控制器失效。（换成 \(b_i=0.6\) 也一样，只是 \(0.6\) 本身不能用 BF16 精确表示，实际存的是离它最近的 \(0.6015625\)；加 \(0.001\) 后又舍回这个数。）

发布的 V3 偏置在 \([2.03,\ 8.05]\)，BF16 在这一段的间隔是 \(2^{-6}\approx0.0156\)（\([2,4)\)）到 \(2^{-4}=0.0625\)（\([8,16)\)），是 \(\gamma\) 的 15.6 到 62.5 倍，半个间隔也至少是 \(\gamma\) 的 7.8 倍。所以偏置必须用 FP32 存储和累加。发布的检查点里偏置确实以 F32 存储（而门控权重是 BF16）2；官方推理代码也在 2025-08-26 的一次提交里把 Gate.bias 改成了 FP32 4。训练时偏置用什么精度，论文没有说明。

V3 的实际设定

V3 的 \(\gamma\) 在前 14.3T tokens 取 0.001，在最后 500B tokens 取 0，也就是偏置冻结 1。按满 batch 算，500B tokens 约是 \(500\times10^9/62{,}914{,}560\approx7{,}947\) 步。论文没有解释为什么最后要冻结。笔者注意到，这 500B 恰好是学习率的最后两个恒定低值段（333B 用 \(2.2\times10^{-5}\)，167B 用 \(7.3\times10^{-6}\)）；一个可能的理由是让专家在固定的分配下收尾，但这是推测，论文没有这样说。

笔者的解读：偏置是一个“价格”

sign 规则看起来只是一条凭经验定的规则，其实它和一个经典的优化方法同源。把负载均衡写成一个带容量约束的分配问题，再用拉格朗日乘子处理容量约束，就能推出式 (11.12) 的形状。下面的推导是笔者给出的解释，V3 与 LossFree 都没有这样表述。

拉格朗日乘子、对偶函数与次梯度学过约束优化的可以跳过

问题。 想让 \(F(x)\) 尽量大，但有一条约束 \(G(x)\le C\)（比如“一个专家最多收 \(C\) 个 token”）。办法：不再死守约束，而是给“超出的部分”标一个单价 \(\lambda\ge0\)，改成最大化 \(\mathcal J(x,\lambda)=F(x)-\lambda\,(G(x)-C)\)。\(\lambda\) 就叫拉格朗日乘子（Lagrange multiplier）：价格越高，越不划算去占用这份资源。

对偶函数 \(\Phi(\lambda)=\max_x\mathcal J(x,\lambda)\) 是“在价格 \(\lambda\) 下，你能拿到的最好成绩”（这里不用字母 \(g\)，它在本课是门控值）。对任何满足约束的 \(x\)，\(\mathcal J(x,\lambda)\ge F(x)\)（因为减去的 \(\lambda\,(G(x)-C)\) 是非正数），所以 \(\Phi(\lambda)\) 永远不低于原问题的最优值；于是去找让 \(\Phi\) 最小的价格，就是在从上方逼近原问题的答案（两者是否恰好相等要看具体问题，下面的分配问题是相等的）。

怎么调价。 \(x\) 只有有限种取法时，\(\Phi\) 是一族关于 \(\lambda\) 的直线（每个 \(x\) 一条）的上包络，所以是凸的，但在折点处不可导。在某个 \(\lambda\) 处取到最大值的那个 \(x^\star\)，它那条直线的斜率 \(-(G(x^\star)-C)\) 就是 \(\Phi\) 在这里的一个次梯度（subgradient，“折点处也能用的斜率”）；这是“逐点取最大的函数的次梯度”规则，Danskin 定理是它的一般形式。于是调价规则是：用了超过 \(C\)，涨价；用了不到 \(C\)，降价。偏导数与链式法则的基础见 M06 §2–§3，步长太大为什么会来回振荡见 M07 §1。

从容量约束到偏置更新
(1)\(\displaystyle \max_{x}\ \sum_{t,i}x_{t,i}\,s_{i,t}\quad\text{s.t.}\ \sum_ix_{t,i}=K,\ \ \sum_tx_{t,i}\le C\)原问题：\(x_{t,i}\in\{0,1\}\) 表示 token \(t\) 是否选专家 \(i\)；每个 token 选 \(K\) 个，使总亲和度最大，每个专家至多 \(C\) 个 token
(2)\(\displaystyle \mathcal J(x,\lambda)=\sum_{t,i}x_{t,i}\,s_{i,t}-\sum_i\lambda_i\Big(\sum_tx_{t,i}-C\Big)\)给第 \(i\) 个容量约束配一个拉格朗日乘子 \(\lambda_i\ge0\)
(3)\(\displaystyle =\sum_t\sum_ix_{t,i}\big(s_{i,t}-\lambda_i\big)+C\sum_i\lambda_i\)按 token 重新整理：固定 \(\lambda\) 后，各 token 的选择互不耦合
(4)\(\displaystyle x^\star_t(\lambda)=\TopK\big(\{s_{i,t}-\lambda_i\}_i,\,K\big)\)每个 token 独立地对 \(s-\lambda\) 取 Top-K；令 \(b_i=-\lambda_i\)，这正是式 (11.11) 的选择规则
(5)\(\displaystyle \big(C-\mathrm{Load}_i(\lambda)\big)_{i=1}^{N_r}\in\partial\Phi(\lambda)\)\(\Phi(\lambda)=\max_x\mathcal J(x,\lambda)\) 的一个次梯度（\(\partial\Phi\) 是全体次梯度）：\(\mathcal J(x^\star,\lambda)\) 对 \(\lambda_i\) 的导数，\(\mathrm{Load}_i=\sum_tx^\star_{t,i}\)
(6)\(\displaystyle \lambda_i\leftarrow\lambda_i+\eta\big(\mathrm{Load}_i-C\big)\)对偶问题是把 \(\Phi\) 最小化，沿负次梯度方向走一步，步长 \(\eta>0\)
(7)\(\displaystyle b_i\leftarrow b_i-\gamma\,\sign\big(\mathrm{Load}_i-\overline{\mathrm{Load}}\big)\)令 \(b_i=-\lambda_i\)、\(C=\overline{\mathrm{Load}}\)，把步长换成固定幅度的 sign：得到式 (11.12)

所以偏置可以理解为专家的“价格”（取了负号）：越抢手的专家，价格越高、\(b_i\) 越低，直到供需平衡。这个视角顺带解释了两件事：只有偏置之差有意义（价格整体加一个常数，谁买什么不变）；以及为什么步长 \(\gamma\) 太大会在平衡点附近来回过冲（次梯度法用固定步长时的通病）。

还有两个细节要交代清楚。第一，为什么可以不管 \(\lambda_i\ge0\)：取 \(C=\overline{\mathrm{Load}}\)（设它是整数）时，每个 token 恰好选 \(K\) 个，负载之和恒为 \(N_r\overline{\mathrm{Load}}=N_rC\)，而每个负载又都不超过 \(C\)，所以约束只能全部取等号；等式约束的乘子可正可负，这与 \(b_i\) 可正可负一致，更新时不需要把 \(\lambda_i\) 截到 0 以上。第二，价格法找到的是不是真正的最优分配：这个分配问题（token 与专家构成二部图，每个 token 连出 \(K\) 条边、每个专家至多收 \(C\) 条）的约束矩阵是全单模的，把 \(x_{t,i}\in\{0,1\}\) 放宽成 \(0\le x_{t,i}\le1\) 不改变最优值。另一方面，固定 \(\lambda\) 后每个 token 的子问题“\(N_r\) 个里选 \(K\) 个”放宽成 \(0\le x\le1\)、\(\sum_ix_{t,i}=K\) 之后，最优解仍然是取前 \(K\) 名的 0/1 解，所以 \(\Phi\) 不因放宽而改变，\(\min_\lambda\Phi(\lambda)\) 就是放宽后线性规划的对偶最优值，等于它的原始最优值。两步合起来，\(\min_\lambda\Phi(\lambda)\) 恰好等于原问题的最优值，没有对偶间隙（线性规划的标准结论，笔者补充）。真正的近似在别处：用固定幅度的 sign 代替与误差成比例的步长，以及用上一个 batch 的负载代替当前的负载。

两个专家、四个 token：价格把谁挪走

2 个专家，每个 token 选 1 个（\(K=1\)），4 个 token 的亲和度 \((s_1,s_2)\) 是 \(t_1:(0.9,0.2)\)、\(t_2:(0.8,0.5)\)、\(t_3:(0.7,0.6)\)、\(t_4:(0.6,0.4)\)。四个 token 都更喜欢专家 1，“对专家 1 的偏爱差” \(s_1-s_2\) 依次是 \(0.7,\ 0.3,\ 0.1,\ 0.2\)。token 改去专家 2 的条件是 \(s_1+b_1<s_2+b_2\)，即偏爱差 \(<b_2-b_1\)。用式 (11.12)，\(\gamma=0.04\)，偏置从 0 开始，并设 \(\sign(0)=0\)：

步 \(b_2-b_1\) 改去专家 2 的 token 负载 \((c_1,c_2)\) 更新
1 0 无 (4, 0) \(b_1-0.04\)，\(b_2+0.04\)
2 0.08 无（最小偏爱差 0.1） (4, 0) 同上
3 0.16 \(t_3\) (3, 1) 同上
4 0.24 \(t_3,\ t_4\) (2, 2) 负载等于平均，不再变

价格挪走的正好是“最不在乎”的两个 token。 容量 \(C=2\) 时，从 4 个 token 里挑 2 个给专家 2 有 \(\binom42=6\) 种分法。每种分法的总亲和度，等于全部 \(s_1\) 之和 \(3.0\)，减去被挪走的两个 token 的偏爱差之和。偏爱差最小的两个是 \(t_3,t_4\)（\(0.1+0.2=0.3\)），所以最优值是 \(3.0-0.3=2.7\)，恰好就是第 4 步的分配。这就是对偶推导说的：价格机制在满足容量的前提下，让总亲和度损失最小。

步子太大的失败模式。 改用 \(\gamma=0.2\)：第 1 步后 \(b_2-b_1=0.4\)，第 2 步里偏爱差小于 0.4 的 \(t_2,t_3,t_4\) 一起涌向专家 2，负载变成 \((1,3)\)；专家 2 过载，偏置又各退 0.2，差值回到 0，第 3 步又是 \((4,0)\)。负载在 \((4,0)\) 与 \((1,3)\) 之间来回跳，永远到不了 \((2,2)\)。这就是图 11.7 Ⓑ 中 \(\gamma=10^{-2}\) 在稳态抖得更厉害的缩小版（笔者构造的例子）。

常见误解两则

“偏置会改变专家输出的权重。” 错。偏置只用于 Top-K 选择，门控值取原始 \(s_{i,t}\) 再归一化（式 11.11）；发布的代码里也是先用加了偏置的分数选下标，再从未加偏置的分数里按下标取值 1,2。

“V3 完全没有辅助损失。” 不对。“无辅助损失”说的是主要机制；V3 还保留了一个系数极小的序列级均衡损失，下一页讲。

小练习：总和的漂移

某一步 256 个专家中有 100 个过载、150 个欠载、6 个恰好等于平均（设 \(\sign(0)=0\)）。按式 (11.12)，这一步之后 \(\sum_ib_i\) 变化多少？这会影响路由吗？

看答案

过载的 100 个各减 \(\gamma\)，欠载的 150 个各加 \(\gamma\)：总和变化 \((150-100)\gamma=50\times0.001=+0.05\)。不影响路由：由性质二，整体平移不改变任何 Top-K。长期累积下来偏置可以整体漂得很远（发布权重的偏置都在 2 以上）。

本页要点
  • V3 式 (16)：选择用 \(s+b\)，加权用 \(s\)。偏置只改变“两可” token 的去向，不改门控值，不产生梯度。
  • 更新规则：过载减 \(\gamma\)，欠载加 \(\gamma\)（\(\gamma=0.001\)，最后 500B tokens 冻结为 0）；每步最多挪 \(\gamma\)，只有偏置之差有意义，总和会漂移但无害。
  • 必须用过去 batch 的负载，否则泄漏未来信息；必须用 FP32 存偏置，否则 0.001 的增量会被 BF16 舍掉。玩具模拟复现了 LossFree 的结论：\(\gamma\) 太小收敛慢，太大稳态抖，\(10^{-3}\) 合适。
  • 笔者的解读：\(-b_i\) 是容量约束的拉格朗日乘子，也就是专家的“价格”；sign 更新是固定步长的对偶次梯度法。价格挪走的是偏爱差最小的 token，所以满足容量时总亲和度损失最小。

护栏与边界：序列级损失与节点受限路由

偏置解决了主要问题，但 V3 的路由还有三处细节：一个系数极小的序列级均衡损失，一条“每个 token 最多去 4 个节点”的节点限制，以及不丢 token。这一页逐个讲清，最后把论文的描述和发布的代码逐行对齐，手算一次完整的路由。

为什么还留一个损失：单个序列里的极端情况

偏置按整个 batch 的负载调节。一个 batch 有 6291 万个 token，每个专家每步平均分到约 197 万次；而一条 4096 个 token 的序列总共只有 \(4096\times8=32{,}768\) 次分派，不到整批的万分之一。batch 级均衡对单个序列几乎没有约束：一条序列完全可以把所有 token 都送进同样 8 个专家，只要别的序列把负载补回来。V3 报告说，为了防止任何单个序列内部出现极端不均衡，额外加了一个序列级均衡损失，并给它一个极小的系数 1：

互补的序列级均衡损失（V3 式 17–20）\[\begin{aligned}\mathcal L_{\rm Bal}&=\alpha\sum_{i=1}^{N_r}f_iP_i,\qquad P_i=\frac1T\sum_{t=1}^{T}s'_{i,t},\qquad s'_{i,t}=\frac{s_{i,t}}{\sum_{j=1}^{N_r}s_{j,t}}\\ f_i&=\frac{N_r}{K_rT}\sum_{t=1}^{T}\mathbb 1\Big(s_{i,t}\in\TopK\big(\{s_{j,t}\mid1\le j\le N_r\},K_r\big)\Big)\end{aligned}\]这里的 \(T\) 是一个序列的 token 数，\(\alpha=0.0001\)（V3 §4.2）。\(s'_{i,t}\) 把 sigmoid 亲和度在全部 256 个专家上归一化，使 \(\sum_iP_i=1\)，结构与 V2 的式 (11.8) 相同。(11.14)

对照式 (11.8)，这个损失的结构完全相同，统计范围也一样是一条序列（V2 的 \(T\) 同样是一条序列的 token 数）。不同之处有三：亲和度是 sigmoid 再在全体专家上归一化，而不是 softmax；系数从 \(0.003\) 降到 \(10^{-4}\)；\(f_i\) 的指示函数按不带偏置的 Top-K 统计（见下面的警告框）。§3 的推导几乎原样适用：\(\sum_if_i=N_r\) 仍然成立，完全均衡时 \(\mathcal L_{\rm Bal}=\alpha\)，一条序列的所有 token 都挤进同样 8 个专家（且概率平均集中在它们身上）时 \(\mathcal L_{\rm Bal}=\alpha N_r/K_r\)。它的梯度也仍然会流进 \(\mathbf u_t\)（练习 11 会推出具体形式），只是系数小到 \(10^{-4}\)。

护栏有多软

\(\alpha=10^{-4}\)，\(N_r=256\)，\(K_r=8\)。完全均衡：\(\mathcal L_{\rm Bal}=10^{-4}\)。极端坍缩：\(10^{-4}\times256/8=3.2\times10^{-3}\)。和约 2 nats 的语言模型损失相比，最坏情况也只占约 0.16%；V2 的专家级系数 \(\alpha_1=0.003\) 是它的 30 倍。所以它不是在“做均衡”，只是在极端情况下拉一把。V3 报告的原话是：设成 0.0001，只是为了避免任何单个序列内的极端不均衡 1。

论文公式的一处细节：\(f_i\) 用的 Top-K 不带偏置

式 (11.14) 中 \(f_i\) 的指示函数用的是 \(\TopK(\{s_{j,t}\})\)，不带偏置；而实际路由用的是带偏置的式 (11.11)。LaTeX 源码里式 (18) 上方有一行被注释掉的旧写法，只说“专家 \(i\) 属于 token \(t\) 的 Top-\(K_r\) 集合”，没说带不带偏置。这可能是有意的（统计“如果没有偏置会怎么分”），也可能是笔误；训练代码没有公开，无法确定。本课照抄论文的写法。

batch 级还是序列级：均衡的“范围”

V3 认为，无辅助损失方法与序列级辅助损失的关键区别在于均衡的范围：一个管整个 batch，一个管每条序列。batch 级的约束更灵活，它不要求每条序列都均匀地使用所有专家，于是专家可以按领域特化 1。

这组实验在 1B 和 3B 两个 MoE 模型上做：序列级辅助损失、无辅助损失、batch 级辅助损失三种训练方式，验证损失分别是 2.258 / 2.253 / 2.253（1B）与 2.085 / 2.080 / 2.080（3B）1。换算成困惑度，1B 上是 \(e^{2.258}\approx9.564\) 对 \(e^{2.253}\approx9.516\)，比值约 1.005。V3 还画了专家负载的热图：在 Pile 测试集的 Wikipedia、Github、DM Mathematics 三个领域上，无辅助损失模型的专家负载呈现出更明显的领域特化 1。热图只能读颜色，这里不引具体数值。

batch 级均衡也不是免费的。V3 自己指出了两个效率风险：一是某些序列或小 batch 内部仍可能不均衡；二是推理时的数据领域和训练不同，负载也会随之偏移。前者靠大规模的专家并行与数据并行保证每个 micro-batch 足够大，后者靠推理部署中的冗余专家（把高负载的专家多复制几份，第 12 课 §8）1。

节点受限路由：每个 token 至多去 4 个节点

问题。 V3 训练时把 256 个路由专家分到 8 个节点、64 张 GPU 上，每个节点 32 个专家 1。一个 token 选中 8 个专家后，要把自己的隐藏状态发到这些专家所在的 GPU，这叫全对全通信（all-to-all，通信代价见 M10 §6；NVLink 与 InfiniBand 在存储与互联层级中的位置见 M10 §2）。节点之间走 InfiniBand（IB），V3 报告给的带宽约 50 GB/s；节点内部走 NVLink，约 160 GB/s，是 IB 的约 3.2 倍 1。如果 8 个专家散在 8 个节点上，同一个 token 要跨 IB 发出 7 份（只有落在它自己节点上的那个专家不用走 IB）；IB 是瓶颈。

图景。 同一个 token 发往同一个远端节点的多个专家时，只需跨 IB 发一份，到达后在节点内部用 NVLink 转发给各张 GPU。所以 IB 流量正比于目标节点数，而不是专家数。限制节点数，就限制了 IB 流量。DeepSeek 在另一篇回顾 V3 硬件设计的论文里把这笔账写得更直白：每个 token 的 IB 通信量从最多 \(8\tau\) 降到 \(M\tau\)（\(\tau\) 是跨节点发送一个 token 的代价；原文记作 \(t\)，这里换个字母，以免与位置下标 \(t\) 混淆）9。这个 \(8\tau\) 把 token 所在的本节点也算了进去；只数真正走 IB 的份数，是上面说的最多 7 份（图 11.9 按这种数法），两种数法差的只是这一份。

形式化。 设路由专家按节点分成 \(\mathcal E_1,\dots,\mathcal E_8\)，每组 32 个。V3 的文字描述是：每个 token 至多发往 \(M\) 个节点，节点按“分布在该节点上的专家中最高的 \(K_r/M\) 个亲和度之和”挑选 1。写成式子（笔者形式化）：

节点受限的两级选择\[\begin{aligned}\mathcal T_n(t)&=\TopK\big(\{s_{j,t}+b_j\mid j\in\mathcal E_n\},\,K_r/M\big)\\ \mathrm{NodeScore}_n(t)&=\sum_{i\in\mathcal T_n(t)}\big(s_{i,t}+b_i\big)\\ \mathcal N_t&=\TopK\big(\{\mathrm{NodeScore}_n(t)\}_{n=1}^{8},\,M\big)\end{aligned}\]\(\mathcal T_n(t)\) 是节点 \(n\) 内加偏置后最高的 \(K_r/M\) 个专家。然后只在 \(\bigcup_{n\in\mathcal N_t}\mathcal E_n\) 这 \(32M\) 个专家里做式 (11.11) 的 Top-\(K_r\)。V3 取 \(M=4\)、\(K_r/M=2\)。论文没说节点打分用 \(s\) 还是 \(s+b\)；发布的推理代码用 \(s+b\)，式中照代码写。(11.15)

这和 V2 的设备受限路由不同（第 10 课 §2）：V2 限制的是设备（单张 GPU）数，\(M=3\)，每台设备的分数是它上面最高的一个亲和度；V3 限制的是节点数，\(M=4\)，节点分是最高两个之和 6,1。用“前两个之和”而不是“最大的一个”，笔者的理解是：每个节点平均要贡献 \(K_r/M=2\) 个专家，按前两名打分更能反映这个节点能否提供两个好专家；论文没有解释这个选择。

V3 报告还算了一笔“顺便”的账：NVLink 带宽是 IB 的 3.2 倍，一个远端节点收到一份数据后，在节点内用 NVLink 转发 3.2 份所需的时间（\(3.2/160\)）恰好等于跨节点用 IB 发这一份的时间（\(1/50\)），所以每个节点平均可以用约 3.2 个专家，而 NVLink 一侧不会成为比 IB 更慢的一环。4 个节点 × 3.2 = 12.8，论文写成“至多 13 个专家”：在同样的通信代价下，激活专家数可以扩到 13 个 1。V3 实际只激活 8 个，这是余量。DeepSeek 在 ISCA 2025 的回顾论文里给的是“约 4:1”：NVLink 名义 200 GB/s、实际约 160；每块 IB 网卡名义 50 GB/s，考虑小消息与延迟按有效 40 GB/s 计 9。名义对名义、实际对有效都是 4:1，而 V3 报告的 3.2 倍是 NVLink 的实际值对 IB 的名义值；两种说法口径不同，可以同时成立。

随机选 8 个专家会跨几个节点？这是一个计数问题，用容斥原理可以精确算出。

恰好跨 j 个节点的组合数
(1)\(\displaystyle A_j=\binom{32j}{8}\)固定某 \(j\) 个节点，8 个专家都从这 \(32j\) 个专家里选；这里允许其中某些节点一个都没被选中
(2)\(\displaystyle E_j=\sum_{i=0}^{j}(-1)^i\binom ji\binom{32(j-i)}{8}\)容斥原理：减去“至少空出 1 个节点”的情形，加回“至少空出 2 个”的，依此类推，剩下的是这 \(j\) 个节点都被用到的组合数
(3)\(\displaystyle \#\{\text{恰好 }j\text{ 个节点}\}=\binom8j\,E_j\)再乘以从 8 个节点中选出这 \(j\) 个的方式数
(4)\(\displaystyle \Pr(\le4\text{ 个节点})=\sum_{j=1}^{4}\binom8jE_j\Big/\binom{256}{8}\)对 \(j=1,\dots,4\) 求和，除以全部组合数
(5)\(\displaystyle \E[\text{节点数}]=8\Big(1-\binom{224}{8}\Big/\binom{256}{8}\Big)\)期望的线性：某个节点“一个专家都没被选中”的概率是 \(\binom{224}{8}/\binom{256}{8}\)，8 个节点各自“被用到”的概率相加
节点限制丢掉了多少种组合

不加限制时，从 256 个专家里选 8 个有 \(\binom{256}{8}=409{,}663{,}695{,}276{,}000\approx4.10\times10^{14}\) 种组合（V2 的 \(\binom{160}{6}\approx2.12\times10^{10}\)，V3 多了四个数量级）。

限制在至多 4 个节点内：按上面的推导，恰好跨 1、2、3、4 个节点的组合分别占 0.00002%、0.030%、1.632%、15.820%，合计约 \(7.16\times10^{13}\) 种，占全部组合的 17.48%。换句话说，如果专家是随机选的，82.5% 的组合会被禁止，平均每个 token 要跨 \(8\big(1-\binom{224}{8}/\binom{256}{8}\big)\approx5.29\) 个节点。

这个数字看起来吓人，但它只是组合计数。真实的路由远非随机：亲和度高的专家往往集中在少数几个节点上，节点限制只在那些“第 8 名散落在第 5 个节点”的 token 上起作用。V2 报告过，设备受限路由在 \(M\ge3\) 时与不受限的 top-K 性能大致持平 6；V3 的节点限制比 V2 更宽松：可选的专家占全体的 4/8，而 V2 的配置是 8 组里选 3 组（3/8）；按同样的随机组合计数，V2（160 个专家分 8 组、选 6 个、至多 3 组）只有约 10.7% 的组合满足限制，V3 是 17.48%（笔者计算）。

不丢 token。 由于负载控制得足够好，V3 训练时不丢弃任何 token；推理时也通过部署策略（冗余专家等）保证不丢 1。V2 训练时是要按设备容量丢 token 的。

多 token 预测：模块、对齐与损失

前五页讲的是 V3 怎样把 token 分给专家。从这一页起换一个话题：V3 的训练目标。标准的语言模型在每个位置只做一件事，预测下一个 token（第 2 课）。V3 在此之外加了一个多 token 预测（MTP）目标：每个位置还要再往后多预测一个 token。这一页讲 MTP 模块的结构、每个位置预测哪个 token、损失怎么算、权重怎么安排，以及它花了多少代价。

问题：一个位置只有一个监督信号

在下一词预测里，长为 \(T\) 的序列提供 \(T\) 个监督信号，每个位置一个。V3 报告给出了加 MTP 的两个理由，措辞都很谨慎（原文用的是“may”）：第一，MTP 让训练信号更稠密，可能提高数据效率；第二，MTP 可能让模型在表示里提前为后面的 token 做规划 1。这两条是作者的假设，不是被证明的结论；能拿来检验它们的，只有后面 §8 的消融实验。

这个想法的直接来源是 Gloeckle 等人 2024 年的工作：在共享主干上接 \(n\) 个独立的输出头，同时预测后面 \(n\) 个 token 10。V3 借了这个思路，但改成了顺序预测，并在每一个预测深度上都保持完整的因果链 1。“因果链”是什么意思，下一页和 Gloeckle 的做法对照着讲；这一页先把 V3 的结构弄清楚。

图景：老师揭晓答案之后的接龙

想象一个接龙练习：学生读到第 \(i\) 个字，先猜第 \(i+1\) 个字（这是主模型的下一词预测）；然后老师揭晓第 \(i+1\) 个字的正确答案，学生再猜第 \(i+2\) 个字（这是 MTP 深度 1）。第二次猜的时候，学生手里有两样东西：自己读到第 \(i\) 个字时的理解，以及刚揭晓的正确的第 \(i+1\) 个字。

这个图景说明了两件事：MTP 模块永远拿到的是真实的下一个 token（训练时的教师强制，第 2 课），而不是自己猜的；它的第二次猜测建立在第一次的“理解”之上，所以会反过来要求这份理解里提前装着对后面有用的东西。边界：真正的学生只有一个脑子，而 MTP 模块是一个单独的小网络（一层 Transformer），它与主模型共享的只有嵌入层、输出头，以及从主模型传过来的隐藏状态。推理时这个“第二次猜测”可以直接不做。

形式化：一个 MTP 模块由什么组成

含义。 V3 用 \(D_{\rm MTP}\) 个顺序排列的模块预测额外的 \(D_{\rm MTP}\) 个 token，第 \(k\) 个模块叫深度 \(k\)。V3 实际只用了 \(D_{\rm MTP}=1\) 1。

组成。 第 \(k\) 个 MTP 模块包含四样东西 1：与主模型共享的嵌入层 \(\operatorname{Emb}(\cdot)\)；与主模型共享的输出头 \(\operatorname{OutHead}(\cdot)\)（线性层映射到 logit，再接 softmax）；一个 Transformer 块 \(\operatorname{TRM}_k(\cdot)\)；一个投影矩阵 \(W^{\rm MTP}_k\in\R^{d\times2d}\)。

数学。 设 \(x_1,\dots,x_T\) 是输入 token，\(\mathbf h_i^{(k-1)}\in\R^{d}\) 是位置 \(i\) 在深度 \(k-1\) 的表示；\(k=1\) 时 \(\mathbf h_i^{(0)}\) 就是主模型在位置 \(i\) 给出的表示。第一步，把“前一深度的表示”和“真实的第 \(i+k\) 个 token 的嵌入”各自归一化后拼起来，再投影回 \(d\) 维：

MTP 深度 k 的输入组合（V3 式 21）\[\tilde{\mathbf h}_i^{(k)}=W^{\rm MTP}_k\big[\RMSNorm(\mathbf h_i^{(k-1)});\ \RMSNorm(\operatorname{Emb}(x_{i+k}))\big]\]\([\cdot;\cdot]\) 是拼接，得到 \(2d\) 维向量；\(W^{\rm MTP}_k\) 把它压回 \(d\) 维。V3 的 \(d=7168\)，拼接后 14336 维，\(W^{\rm MTP}_1\) 是 \(7168\times14336\)，约 1.03 亿个参数。(11.17)

第二步，把位置 \(1\) 到 \(T-k\) 的组合向量作为一个序列送进这一深度的 Transformer 块；第三步，用共享的输出头给出预测：

Transformer 块与预测（V3 式 22–23）\[\mathbf h^{(k)}_{1:T-k}=\operatorname{TRM}_k\big(\tilde{\mathbf h}^{(k)}_{1:T-k}\big),\qquad \mathbf p^{(k)}_{i+k+1}=\operatorname{OutHead}\big(\mathbf h^{(k)}_i\big)\in\R^{V}\]下标 \(1{:}T-k\) 表示位置 1 到 \(T-k\)（含两端）；\(\mathbf p^{(k)}_{i+k+1}\) 是深度 \(k\) 在位置 \(i\) 给出的、关于第 \(i+k+1\) 个 token 的概率分布，\(V\) 是词表大小（V3 配置为 129280）。\(\operatorname{TRM}_k\) 在序列维上仍然是因果的：位置 \(i\) 只看得到位置 \(\le i\) 的组合向量。(11.18)

最后是这一深度的交叉熵：

深度 k 的 MTP 损失（V3 式 24）\[\mathcal L^{(k)}_{\rm MTP}=-\frac1T\sum_{i=2+k}^{T+1}\log\mathbf p^{(k)}_i[x_i]\]\(\mathbf p^{(k)}_i[x_i]\) 是分布 \(\mathbf p^{(k)}_i\) 在正确 token \(x_i\) 上的概率。共 \(T-k\) 项却除以 \(T\)；\(T=4096\)、\(k=1\) 时只差 \(4095/4096\)，照抄论文即可。(11.19)
本课的记号与论文的对应

论文的 \(\mathbf h_i^{k}\)、\(\mathbf h_i^{\prime k}\)、\(P^k_i\) 在本课写作 \(\mathbf h_i^{(k)}\)、\(\tilde{\mathbf h}_i^{(k)}\)、\(\mathbf p^{(k)}_i\)：上标不加括号像幂，\(P_i\) 在 §3、§5 已表示平均亲和度。其余改写（\(x_i\)、\(D_{\rm MTP}\)、\(W^{\rm MTP}_k\)）见封面的记号说明。

三个系数的量级对比

主损失大约是 2 nats 的量级。\(\lambda=0.3\) 时，MTP 项的系数是主损失的 30%，不是可以忽略的小项；10T tokens 之后 \(\lambda\) 降到 0.1，系数只剩主损失的十分之一。相比之下，序列级护栏损失的系数只有 \(10^{-4}\)。

为什么在 10T 处把 \(\lambda\) 调低？论文没有解释。10T 恰好是学习率转入余弦衰减的起点（§8）；让训练后期的主目标占更大比重是一个自然的猜想，但只是推测。

代价：参数、算力与存储

参数。 MTP 模块的 Transformer 块和主模型的 MoE 层一样大：一个 MLA 注意力层加一个有 1 个共享专家、256 个路由专家的 MoE 层。按配置逐项累加，MTP 模块独有的参数约 11.61B（含 \(W^{\rm MTP}_1\) 的 1.03 亿），仓库的权重说明写 11.5B；是主模型 671B 的 1.7% 4。

MTP 模块的额外算力

每个 token 在 MTP 模块里激活的参数：一层 MLA 约 187.1M；1 个共享专家加 8 个路由专家，\(9\times44.04\text{M}\approx396.4\)M；投影 \(W^{\rm MTP}_1\) 约 102.8M；再加门控（约 1.8M）与几个归一化向量，合计约 0.688B。输出头（0.927B）虽然与主模型共享参数，这里也要再算一遍。按“每个参数前向 2 次运算”，MTP 模块的前向约 \(2\times(0.688+0.927)\text{B}\approx3.2\) GFLOPs，约为主模型 73.3 GFLOPs 的 4.4%。

这是笔者按参数量做的估算，不含注意力分数那部分。反向传播大约再乘 2，比例不变。再加上 11.6B 参数的优化器状态（AdamW 每个参数还要存两个动量），MTP 在训练端的开销是实打实的；推理时丢掉它，这些开销就全部消失。

存储。 Hugging Face 上 V3 的权重总量是 685B，而不是 671B：多出来的是 MTP 模块独有的约 11.6B，再加上 MTP 层（层号 61）里又存了一份嵌入表和输出头，各 0.93B。\(671.03+11.61+2\times0.927\approx684.5\text{B}\approx685\text{B}\) 2,4。训练时二者并不重复：V3 借助 DualPipe 把最浅的几层（含嵌入）和最深的几层（含输出头）放在同一个流水线并行 rank 上，MTP 模块与主模型在物理上共享这两块参数和它们的梯度 1（第 12 课 §6）。

推理。 默认情况下，推理时直接丢掉 MTP 模块，主模型可以独立工作 1；MTP 只增加训练成本，不增加推理成本。另一种用法是把它当作投机解码的草稿，下一页讲。

论文与代码对照：拼接的顺序

因果链与并行头，以及投机解码

上一页说 V3 的 MTP 是“顺序的、保持完整因果链的”，而 Gloeckle 等人的 MTP 是“并行的独立头”。这一页先把这个区别落到一个具体的条件概率上，再看两种做法各自的证据，最后讲 MTP 在推理时的第二种用途：投机解码。

Gloeckle 等人的并行头

Gloeckle 等人把下一词预测的损失推广成一次预测后面 \(n\) 个 token 10：

多 token 预测损失（Gloeckle 式 2）\[L_n=-\sum_t\log P_\theta\big(x_{t+n:t+1}\mid x_{t:1}\big)\]\(x_{t:1}\) 是到位置 \(t\) 为止的全部 token，\(x_{t+n:t+1}\) 是后面 \(n\) 个 token。\(n=1\) 就是普通的下一词预测。(11.22)

他们的实现是：一个共享主干 \(f_s\) 读入 \(x_{t:1}\)，得到表示 \(\mathbf z_t\)；\(n\) 个独立的头 \(f_{h_i}\)（每个是一层 Transformer）各自从 \(\mathbf z_t\) 出发；共享的反嵌入 \(f_u\) 把结果变成 logit 10：

第 i 个并行头\[P_\theta(x_{t+i}\mid x_{t:1})=\softmax\Big(f_u\big(f_{h_i}(f_s(x_{t:1}))\big)\Big),\qquad i=1,\dots,n\]第 \(i\) 个头只看 \(\mathbf z_t=f_s(x_{t:1})\)，看不到 \(x_{t+1},\dots,x_{t+i-1}\)。(11.23)

他们的主要发现（全部是实测）：参数匹配时（头多加 \(n-1\) 层，主干就减 \(n-1\) 层），多 token 预测对小模型反而有害，对大模型有益；13B 模型在代码基准上，MBPP 从 26.0 提到 30.5（+17%），HumanEval 从 14.1 提到 15.8（+12%）；在 7B、200B tokens 的代码数据上，\(n=4\) 最好 10。他们还用了一个节省显存的技巧：主干前向之后，逐个头做前向和反向，把峰值显存从 \(O(nV+d)\) 降到 \(O(V+d)\)。

推导：差别在哪一个条件上

问题。 并行头和 V3 的 MTP 都在“预测第 \(t+2\) 个 token”，差别到底在哪？在于条件：并行头预测 \(x_{t+2}\) 时不知道 \(x_{t+1}\)；V3 的深度 1 知道真实的 \(x_{t+1}\)。

推导。 并行头的第 2 个头要拟合的是给定 \(x_{\le t}\) 时 \(x_{t+2}\) 的分布。它等于对未知的 \(x_{t+1}\) 求和：

边缘分布 = 条件分布的混合\[p(x_{t+2}\mid x_{\le t})=\sum_{v\in\mathcal V}p(x_{t+1}=v\mid x_{\le t})\;p(x_{t+2}\mid x_{\le t},\,x_{t+1}=v)\]这是全概率公式：把 \(x_{t+1}\) 的每一种可能按其概率加权。V3 的深度 1 要拟合的是右边的第二个因子 \(p(x_{t+2}\mid x_{\le t+1})\)，一个条件分布；并行头要拟合的是左边的边缘分布，它是许多条件分布的混合。(11.24)
熵、条件熵与互信息读过 M05 的可以跳过

熵 \(H(X)=-\sum_xp(x)\log p(x)\) 是“猜 \(X\) 之前平均有多不确定”，单位用自然对数时是 nats（M05 §1）。条件熵 \(H(Y\mid X)=\sum_xp(x)\,H(Y\mid X=x)\) 是“先告诉你 \(X\)，再猜 \(Y\) 时平均还剩多少不确定”：对 \(X\) 的每个取值算一次 \(Y\) 的熵，再按 \(p(x)\) 加权平均。互信息 \(I(X;Y)=H(Y)-H(Y\mid X)\) 是“知道 \(X\) 让 \(Y\) 的不确定减少了多少”；它等于 \(\KL\big(p(x,y)\,\|\,p(x)p(y)\big)\)，而 KL 散度非负（M05 §4），所以 \(I\ge0\)，也就是 \(H(Y\mid X)\le H(Y)\)：多知道一点，平均不会更糊涂。它对称，\(I(X;Y)=H(X)-H(X\mid Y)\) 也成立。最后，用交叉熵训练时，模型能达到的最低期望损失就是目标分布的熵（交叉熵 = 熵 + KL，M05 §2）。

用交叉熵训练，一个模型能达到的最低期望损失就是目标分布的熵。于是两种目标的“最好成绩”之间有一个确定的大小关系：

条件化不增加熵\[H\big(X_{t+2}\mid X_{\le t+1}\big)\le H\big(X_{t+2}\mid X_{\le t}\big)\]左边是 V3 深度 1 的理论最低损失，右边是并行头的理论最低损失。多知道一个变量，不确定性不会增加：两边之差是条件互信息 \(I(X_{t+2};X_{t+1}\mid X_{\le t})\)，它是 KL 散度的加权平均，非负。(11.25)
一个构造的例子：“他来自”

假设语料里“他来自”之后只有两种说法，各占一半：“北京”和“上海”。按字切分，\(x_{t+1}\in\{\text{北},\text{上}\}\)，\(x_{t+2}\) 在“北”之后必是“京”，在“上”之后必是“海”。

  • 并行头预测 \(x_{t+2}\)：它不知道 \(x_{t+1}\) 是哪个，最好的预测是“京 0.5、海 0.5”，交叉熵 \(\ln2\approx0.693\) nats。
  • V3 深度 1 预测 \(x_{t+2}\)：它拿到了真实的 \(x_{t+1}\)，可以做到“北”之后预测“京”的概率为 1，交叉熵为 0。

用式 (11.25) 的语言：右边 \(H(X_{t+2}\mid X_{\le t})=\ln2\)，左边 \(H(X_{t+2}\mid X_{\le t+1})=0\)，两者之差 \(\ln2\) 就是 \(x_{t+1}\) 为 \(x_{t+2}\) 提供的互信息：知道第一个字，第二个字就没有悬念了。

这个例子是笔者构造的，只用来说明式 (11.24)–(11.25)：并行头学到的是一个“两边押注”的混合分布，V3 的模块学到的是确定的条件分布。

哪一个对训练主干更有用？ 这是一个选择，不是推论，而且目前没有定论。Gloeckle 等人的论证站在并行头一边：记 \(X=x_{t+1}\)、\(Y=x_{t+2}\)（都以前文为条件），他们指出下一词预测与 2-token 并行预测的损失可以分解为：

Gloeckle 的信息论分解
(1)\(\displaystyle H(X)=H(X\mid Y)+I(X;Y)\)互信息的定义
(2)\(\displaystyle H(Y)=H(Y\mid X)+I(X;Y)\)同理，交换 \(X\)、\(Y\)
(3)\(\displaystyle H(X)+H(Y\mid X)=H(X\mid Y)+I+H(Y\mid X)\)下一词预测：位置 \(t\) 预测 \(X\)，位置 \(t+1\) 已知 \(X\) 再预测 \(Y\)；把第一行代入 \(H(X)\)，\(I\) 即 \(I(X;Y)\)
(4)\(\displaystyle H(X)+H(Y)=H(X\mid Y)+2I+H(Y\mid X)\)2-token 并行：在位置 \(t\) 同时预测 \(X\) 与 \(Y\)；把第一、二行分别代入 \(H(X)\)、\(H(Y)\)

对比最后两行：并行头把互信息 \(I(X;Y)\) 的权重加倍了，也就是更强调“后两个 token 之间相互关联的那部分信息”，迫使主干在位置 \(t\) 就把它编码进 \(\mathbf z_t\) 10。他们还论证，这样的损失会给“选择点”（决定后文走向的 token）更大的隐式权重。

V3 的深度 1 损失在形式上是 \(H(Y\mid X)\) 这一类条件熵，和主模型在下一个位置的损失同类。那它额外施加了什么压力？笔者的理解是：压力在信息的来源上。MTP 模块只有一层 Transformer，它预测 \(x_{i+2}\) 主要只能依靠两样东西：主模型在位置 \(i\) 的表示 \(\mathbf h^{(0)}_i\)（此时主模型还没看到 \(x_{i+1}\)），和 \(x_{i+1}\) 的嵌入。要让这一层就能预测准，\(\mathbf h^{(0)}_i\) 里必须预先装好“与后面第二个 token 相关”的信息。这与 V3 所说的“让模型提前规划它的表示”是一致的，但这是笔者的解读，V3 没有做这样的分析，也没有和并行头做正面比较。

还要纠正一个常见的说法：“把预测头串成因果链是 DeepSeek 首创”。不准确。Gloeckle 等人的附录 B 已经试过把头串起来的“因果”变体（后面的头叠在前面的头上），在 \(n=4\)、7B 的设定下 MBPP 31.9、HumanEval 20.9，不如并行头的 33.8、24.0 10；投机解码的 EAGLE 也采用了保持因果链的思路，V3 报告自己也说原则与 EAGLE 相似，只是 EAGLE 的主要目标是投机解码，而 V3 用 MTP 改进训练 1,12。EAGLE 的草稿模型和 V3 的 MTP 模块在结构上非常接近：它把目标模型的特征序列和“提前一步”的 token 序列的嵌入拼接成 \(2d\) 维，用一个全连接层压回 \(d\) 维，过一个解码层，再用目标模型的输出头出分布；嵌入层和输出头直接沿用目标模型的参数 12。所以“喂入下一个真实 token 的嵌入”并不是 V3 的发明。V3 与两者真正不同的地方在于：

  • 与 Gloeckle 的因果变体相比：V3 的每个深度额外输入真实第 \(i+k\) 个 token 的嵌入，Gloeckle 的变体只把头串起来，不喂真实 token。
  • 与 EAGLE 相比：EAGLE 是在冻结的目标模型上事后训练的一个草稿头，损失是特征回归（Smooth L1）加 token 分类 12；V3 的 MTP 模块从头与主模型联合训练，它的交叉熵梯度流回主模型，嵌入与输出头与主模型共享并一起更新，目的首先是改进主模型本身。

推理时的第二种用途：投机解码

投机解码读过第 4 课的可以跳过

自回归解码每一步只产出一个 token，而大模型在小 batch 下解码时主要受显存带宽限制：读一遍权重，只算一个 token（第 4 课 §4 的 roofline）。完整的推导见 第 4 课 §7。投机解码（speculative decoding）的办法是：先用一个便宜的“草稿”机制猜后面几个 token，再让大模型用一次前向同时验证这几个位置。贪心解码时，草稿与大模型自己的选择一致就接受；采样解码时，以 \(\min\big(1,\,P(x)/Q(x)\big)\) 的概率接受草稿 token \(x\)（\(P\) 是大模型的分布，\(Q\) 是草稿的分布；Leviathan 等人写作小写 \(p\)、\(q\)，本页的小写 \(p\) 留给接受率），被拒绝时从归一化的 \(\max(0,\,P-Q)\) 中重新采样。这样得到的输出分布与大模型自己逐个生成完全相同 13；接受规则的推导见 M04 §5，下面要用的尾和公式见 M04 §2。验证时，被接受的前缀之后，大模型在第一个被拒绝的位置上本来就给出了自己的 token，所以每一步至少产出 1 个 token。

V3 的 MTP 模块天然就是一个草稿器：它读主模型的隐藏状态和刚生成的 token，预测再下一个。V3 报告说，用 MTP 预测后面第 2 个 token，在不同生成主题上的接受率在 85% 到 90% 之间，带来 1.8 倍的每秒生成 token 数（TPS）1。DeepSeek 在 ISCA 2025 的回顾论文里给的是 80% 到 90%，同样 1.8 倍，并补充说这种做法“略微损害吞吐”，但显著改善端到端延迟 9。两个一手来源的区间不一致，本课两个都引，不把任何一个当定论。

每一步能产出多少个 token？设每个草稿 token 被接受的概率为 \(p\)，且各草稿之间独立（这是简化假设）。

每步期望产出的 token 数
(1)\(\displaystyle N=1+A\)每步产出 = 主模型自己的 1 个 + 被接受的草稿数 \(A\)
(2)\(\displaystyle A\ge j\iff\text{前 }j\text{ 个草稿都被接受}\)草稿按顺序验证，第一个被拒绝的位置之后全部作废
(3)\(\displaystyle \Pr(A\ge j)=p^{\,j},\quad j=1,\dots,k\)各草稿独立、接受率同为 \(p\)
(4)\(\displaystyle \E[A]=\sum_{j=1}^{k}\Pr(A\ge j)=\sum_{j=1}^{k}p^{\,j}\)非负整数随机变量的尾和公式 \(\E[A]=\sum_{j\ge1}\Pr(A\ge j)\)（推导见 M04 §2）
(5)\(\displaystyle \E[N]=\sum_{j=0}^{k}p^{\,j}=\dfrac{1-p^{k+1}}{1-p}\)加上主模型的 1 个，等比数列求和
投机解码的每步期望产出\[\E[N]=\frac{1-p^{k+1}}{1-p},\qquad k=1\ \Rightarrow\ \E[N]=1+p\]\(k\) 是每步的草稿数。这正是 Leviathan 等人投机解码论文 §3.1 的式 (1)，他们同样假设各位置的接受独立同分布 13。V3 的 \(D_{\rm MTP}=1\)，每步一个草稿，\(\E[N]=1+p\)。(11.26)
从接受率到 1.8 倍

\(p=0.85\)：\(\E[N]=1.85\)；\(p=0.90\)：\(\E[N]=1.90\)；按 Insights 的下限 \(p=0.80\)：\(\E[N]=1.80\)。

如果起草和验证都不花时间，TPS 就会提高到 \(\E[N]\) 倍。实测是 1.8 倍：对 \(p=0.85\) 是理论值的 \(1.8/1.85\approx97.3\%\)，对 \(p=0.90\) 是 \(94.7\%\)。差距可能来自 MTP 模块自己的前向、验证多一个位置的开销等。这只是笔者的粗算：论文没有给出测量时的采样温度、batch 大小与硬件，也没有定义接受率是怎么统计的，不能据此反推真实开销。

作为对照，Gloeckle 等人的 7B 代码模型用 2、3、4 个头自投机解码，每次前向平均产出 1.94、2.78、3.50 个 token（表 S2，含主模型自己的那 1 个；他们对 4 个头的描述是 3 个草稿里平均接受 2.5 个，\(1+2.5=3.5\)）10。2 个头相当于每步一个草稿，\(1+p=1.94\) 对应 \(p\approx0.94\)；若 3、4 个头的草稿也都以 0.94 独立被接受，式 (11.26) 给出 2.82 与 3.65，比实测的 2.78、3.50 略高，说明越靠后的头越不准（笔者换算）。

为什么主要是延迟收益？ 小 batch 解码受显存带宽限制，验证 2 个位置和验证 1 个位置几乎一样快，所以每一步多产出的 token 几乎是白赚的，延迟明显下降。大 batch 服务时，GPU 已经接近算力上限，起草与验证多出来的计算要与别的请求争用算力，总吞吐可能略降，这与 Insights 所说的“略微损害吞吐”一致。这段机制解释是笔者结合第 4 课的 roofline 给出的。

本页要点
  • 并行头学的是边缘分布 \(p(x_{t+2}\mid x_{\le t})\)，V3 的深度 1 学的是条件分布 \(p(x_{t+2}\mid x_{\le t+1})\)；前者是后者的混合，理论最低损失更高（条件化不增加熵）。
  • 哪一种更有利于训练主干没有定论：Gloeckle 论证并行头加倍了互信息的权重；V3 的压力在于要求 \(\mathbf h^{(0)}_i\) 预先装好后面的信息（笔者解读）。“因果链式 MTP”并非 DeepSeek 首创，喂入下一个真实 token 的嵌入也是 EAGLE 已有的做法；V3 的新意在于把这种模块与主模型从头联合训练，当作改进主模型的训练目标。
  • 投机解码：每步期望产出 \(\E[N]=(1-p^{k+1})/(1-p)\)，\(k=1\) 时为 \(1+p\)。接受率 85%–90%（V3）或 80%–90%（Insights），实测 1.8 倍 TPS，收益主要在延迟。

概念题

练习 1 · 偏置能不能也进门控值

有人提议：既然偏置 \(b_i\) 能把 token 引向空闲的专家，干脆让门控值也用 \(s_{i,t}+b_i\)，这样“偏置调低的专家，意见权重也更低”，岂不更一致？分析这样做的后果。

看答案

这样做会让偏置改变前向计算的函数本身，而不只是改变“选谁”。

  1. 门控值决定专家输出的加权（式 11.2）。若用 \(s+b\)，偏置每调一步，同一个 token 经过同样专家时得到的输出就变了。偏置是按负载规则变化的，与语言模型目标无关，这等于每一步都在往模型里注入一个与预测无关的扰动。
  2. 偏置本身仍无梯度，但进入了前向计算，模型不得不去“适应”一个不断漂移的门控。
  3. 由性质二，偏置整体漂移本来无害；进入门控值后，整体漂移会改变归一化后的权重（例如全体偏置加 2，每个 \(s+b\) 都变大，归一化后的比例趋于平均），“只有差值有意义”就不再成立。发布的 V3 偏置在 2 以上，如果进入门控值，路由部分的加权会被严重抹平。

V3 与 LossFree 都明确偏置只进入 Top-K 选择 1,5。

练习 2 · 为什么不能看当前序列的负载

（a）为什么偏置只能用已经过去的 batch 的负载来更新？（b）对 Expert Choice 路由，LossFree 给出的每 token 每层泄漏下界是 \(K_r\log_2\frac{1-R}{R}\)，\(R=K_r/N_r\)。在 V3 的规模 \(N_r=256\)、\(K_r=8\) 下算出这个下界，并与正文 \(N_r=16\)、\(K_r=2\) 的例子比较。

看答案

（a）语言模型在位置 \(t\) 的计算只能依赖位置 \(\le t\) 的 token。若路由决策依赖当前序列的负载，而负载是整条序列（包括 \(t\) 之后的 token）统计出来的，未来 token 的信息就通过“谁被分到哪里”泄漏进了过去位置的计算。用过去 batch 的统计量，偏置对当前序列而言是一个常数，不带任何未来信息。

（b）\(R=8/256=1/32\)，\(\frac{1-R}{R}=31\)，下界 \(8\log_231\approx8\times4.954=39.6\) 比特/层。正文例子 \(N_r=16\)、\(K_r=2\)：\(2\log_27\approx5.61\) 比特/层。固定 \(K_r\) 时，稀疏率越低（\(R\) 越小），能泄漏的信息越多；在 \(R\) 固定时，每 token 选的专家越多（\(K_r\) 越大）也越多。但固定 \(N_r\) 只增大 \(K_r\) 时未必：\(R\) 跟着变大，\(N_r=256\)、\(K_r=128\) 时 \(R=1/2\)，下界降为 0。V3 若用 Expert Choice，58 个 MoE 层的下界合计超过 2000 比特。

练习 3 · MTP 消融公平吗

V3 表 4 中“加 MTP”的模型与基线推理成本完全相同。（a）训练成本相同吗？（b）这张表支持什么结论，不支持什么结论？（c）Gloeckle 等人是怎样做公平比较的？

看答案

（a）不同。加 MTP 的模型多训练了一个 MTP 模块：在 V3 的尺寸下约 11.6B 参数（外加它们的优化器状态），每 token 前向多约 3.2 GFLOPs，约为主模型的 4.4%（笔者按参数量估算）。表 4 用的模型比 V3 小，额外开销的具体比例论文没有给出，但方向相同：训练算力更多。

（b）支持：“在推理成本不变的前提下，训练时加一个 MTP 目标，多数基准会变好。”不支持：“在同样的训练算力下，MTP 比把这部分算力花在别处（更大的主干、更多数据）更好”，因为表 4 没有做算力匹配；也不支持“顺序 MTP 优于并行头”，因为没有与并行头比较。

（c）参数匹配：给预测头多加 \(n-1\) 层，就从共享主干中减掉 \(n-1\) 层，保证总参数相同 10。

练习 4 · 只准去一个节点

沿用图 11.10 的 16 个专家、4 个节点、\(K_r=4\)，但改成 \(M=1\)。（a）按论文的定义，节点分取“节点内最高 \(K_r/M\) 个 \(s+b\) 之和”，此时 \(K_r/M\) 是多少？算出四个节点分，选哪个节点？（b）发布的代码把“取最高 2 个”写死了，按代码算选哪个节点？（c）选中的 4 个专家与门控值（乘 2.5 前后）各是多少？

看答案

（a）\(K_r/M=4\)，即节点内全部 4 个 \(\tilde s=s+b\) 之和。节点 0：\(0.7185+0.4256+0.6187+0.2689=2.0317\)；节点 1：\(0.7409+0.6900+0.3775+0.4502=2.2586\)；节点 2：\(0.3318+0.5250+0.7176+0.2315\approx1.8058\)（用未舍入的值相加；四个四位小数直接相加得 1.8059）；节点 3：\(0.5400+0.4013+0.5744+0.7057=2.2214\)。选节点 1。

（b）按代码（最高 2 个之和），节点分就是正文算过的 \((1.3372,\ 1.4309,\ 1.2426,\ 1.2801)\)，也选节点 1。两种定义在这里结论相同；但当 \(K_r/M\ne2\) 时它们可能不同，这正是“论文定义”与“写死的代码”在 V3 配置（\(K_r/M=8/4=2\)）之外不一致的地方。

（c）节点 1 只有 4 个专家，全部选中：\(\{4,5,6,7\}\)，\(s=(0.7109,\ 0.6900,\ 0.3775,\ 0.4502)\)，和 \(2.2286\)，\(g=(0.3190,\ 0.3096,\ 0.1694,\ 0.2020)\)，乘 2.5 得 \((0.7975,\ 0.7740,\ 0.4235,\ 0.5050)\)。注意专家 6 的亲和度只有 0.3775，也被迫入选：\(M\) 太小时，节点限制会强迫 token 去它并不对口的专家。

练习 5 · 偏置更新几步

4 个专家，\(\gamma=0.001\)，偏置初始全为 0。某一步的负载是 \([7,3,4,2]\)。（a）这一步的 MaxVio 是多少？（b）按式 (11.12) 更新后的偏置是多少（设 \(\sign(0)=0\)）？\(\sum_ib_i\) 变成多少？（c）若专家 1 持续过载，它的偏置至少要多少步才能下降 0.05？在 V3 满 batch 下这对应多少 token？

看答案

（a）平均 \(16/4=4\)，\(\mathrm{MaxVio}=(7-4)/4=0.75\)。

（b）\(\mathrm{Load}-\overline{\mathrm{Load}}=(+3,\ -1,\ 0,\ -2)\)，符号 \((+,-,0,-)\)。\(b=(-0.001,\ +0.001,\ 0,\ +0.001)\)，\(\sum_ib_i=+0.001\)：一个过载、两个欠载，总和漂移了 \(+\gamma\)。

（c）每步最多挪 \(\gamma\)（式 11.13），\(0.05/0.001=50\) 步。V3 满 batch 一步 62,914,560 个 token，50 步约 \(3.15\times10^9\) 个 token。

练习 6 · 护栏损失的量级

V3 的 \(\mathcal L_{\rm Bal}\)（式 11.14），\(\alpha=10^{-4}\)、\(N_r=256\)、\(K_r=8\)，一条序列 \(T=4096\)。设这条序列的所有 token 都只在同一组 16 个专家中选 8 个，且这 16 个专家被选中的次数相同，\(P_i\) 也平均集中在这 16 个专家上。（a）求 \(f_i\) 与 \(\mathcal L_{\rm Bal}\)。（b）推广：若集中在 \(m\) 个专家上（\(K_r\le m\le N_r\)），\(\mathcal L_{\rm Bal}\) 是多少？

看答案

（a）总分派次数 \(4096\times8=32{,}768\)，平均到 16 个专家各 2048 次。\(f_i=\frac{256}{8\times4096}\times2048=16\)（这 16 个），其余为 0；核对 \(\sum_if_i=16\times16=256=N_r\)。\(P_i=1/16\)。\(\mathcal L_{\rm Bal}=10^{-4}\times16\times16\times\frac1{16}=16\times10^{-4}=1.6\times10^{-3}\)。

（b）\(f_i=N_r/m\)，\(P_i=1/m\)，\(m\) 项求和：\(\mathcal L_{\rm Bal}=\alpha\cdot m\cdot\frac{N_r}{m}\cdot\frac1m=\alpha\frac{N_r}{m}\)。\(m=N_r\) 时为 \(\alpha\)（完全均衡），\(m=K_r\) 时为 \(\alpha N_r/K_r=3.2\times10^{-3}\)（完全坍缩），与 §5 一致。

练习 7 · 小规模的组合数

4 个节点、每个节点 4 个专家，每个 token 选 4 个。（a）不受限时有多少种组合？（b）至多跨 2 个节点的组合有多少种，占多少？（c）与正文 V3 规模的 17.48% 相比，说明节点限制的“松紧”取决于什么。

看答案

（a）\(\binom{16}{4}=1820\)。

（b）恰好 1 个节点：4 个专家全在同一节点，\(4\times\binom44=4\) 种。恰好 2 个节点：先选 2 个节点 \(\binom42=6\) 种，再从这 8 个专家中选 4 个、但不能全在其中一个节点：\(\binom84-2=68\)；合计 \(6\times68=408\)。至多 2 个节点共 \(4+408=412\) 种，占 \(412/1820\approx22.6\%\)。

（c）两例都允许一半的节点，但 V3 要把更多的专家（8 个）放进更多节点中的一半，随机组合更容易散开，所以比例更低（17.48%）。松紧取决于 \(M\) 占总节点数的比例、\(K_r\) 与每节点的专家数。真实路由的亲和度是集中的，实际被扳动的 token 远少于这些比例所暗示的。

练习 8 · 偏置的精度

（a）若某个偏置 \(b=3.0\) 用 BF16 存储，加一次 \(\gamma=0.001\) 的结果是多少？（b）在 \(b=3.0\) 附近，BF16 至少要多大的增量才不会被舍掉？（c）FP32（23 位尾数）在 3.0 附近的间隔是多少？

看答案

（a）3.0 落在 \([2,4)\)，BF16 的间隔是 \(2^{1-7}=2^{-6}=0.015625\)，半个间隔 \(0.0078\)。\(3.001\) 离 3.0 更近，舍入回 3.0：偏置不动。

（b）增量要超过半个间隔约 \(0.0078\)，才会被舍入到下一个可表示数 3.015625（恰好等于半个间隔 \(0.0078125\) 时按“舍入到偶数”处理：3.0 的尾数末位是 0，所以仍回到 3.0）。这是 \(\gamma\) 的约 8 倍。

（c）FP32 在 \([2,4)\) 的间隔是 \(2^{1-23}\approx2.38\times10^{-7}\)，约为 \(\gamma=0.001\) 的 \(1/4200\)。每加一次 \(0.001\)，舍入误差不超过半个间隔 \(1.19\times10^{-7}\)，约为增量本身的万分之一，所以增量几乎原样保留下来（不是分毫不差：\(0.001\) 本身就不能用二进制精确表示）。这就是偏置要用 FP32 的数值理由；发布的检查点里偏置确实是 F32 2。

练习 9 · 两个草稿

（a）V3 用一个草稿、接受率 \(p=0.85\)，每步期望产出多少个 token？（b）若改用 \(D_{\rm MTP}=2\)、每步两个草稿，两个草稿都以 0.85 独立被接受，期望产出多少？（c）更现实的情形是第二个草稿更难猜：设第一个草稿接受率 0.85，在第一个被接受的条件下第二个的接受率只有 0.6，期望产出多少？

看答案

（a）\(1+p=1.85\)。

（b）式 (11.26)，\(k=2\)：\(1+0.85+0.85^2=1+0.85+0.7225=2.5725\)。

（c）第二个草稿被计入的前提是第一个被接受，所以 \(\E[N]=1+0.85+0.85\times0.6=1+0.85+0.51=2.36\)。比 (b) 少 0.21 个。练习 12 把这个算法推广成一般公式。多一个草稿还要多跑一个 MTP 模块、多验证一个位置，实际加速要扣除这些开销。

练习 10 · MTP 模块的参数，以及稠密层的宽度

（a）按配置逐项累加 MTP 模块独有的参数：两个输入归一化（各 7168）、投影 \(7168\times14336\)、一层 MLA（187,107,328）、这一层的两个归一化（各 7168）、257 个专家（各 44,040,192）、门控（\(256\times7168+256\)）、输出前的归一化（7168）。（b）为什么 Hugging Face 上的权重是 685B 而不是 671B？（c）前 3 层稠密 FFN 的中间维是 18432，V2 的稠密层是 12288。各自与 MoE 层有什么算术关系？

看答案

（a）\(14{,}336+102{,}760{,}448+187{,}107{,}328+14{,}336+11{,}318{,}329{,}344+1{,}835{,}264+7{,}168=11{,}610{,}068{,}224\approx11.61\)B。仓库的权重说明写 11.5B。

（b）\(671.03+11.61=682.64\)B，再加上 MTP 层（层号 61）里又单独存了一份嵌入表和输出头，各 \(129280\times7168\approx0.927\)B：\(682.64+1.85\approx684.5\text{B}\approx685\)B。训练时这两份与主模型共享，只是文件里存了两份。

（c）\(18432=9\times2048\)：恰好等于 MoE 层中每个 token 实际经过的 1 个共享专家加 8 个路由专家的中间维之和，所以稠密层与 MoE 层每 token 的 FFN 计算量相同。V2 的 \(12288=8\times1536\)，同样等于 2 个共享专家加 6 个路由专家（专家中间维 1536）。算术是事实，设计意图是推测。

练习 11 · 序列级护栏损失的梯度

V3 的 \(\mathcal L_{\rm Bal}\)（式 11.14）用 sigmoid 亲和度再在全体专家上归一化：\(z_{k,t}=\mathbf u_t^\top\mathbf e_k\)，\(s_{k,t}=\sigma(z_{k,t})\)，\(S_t=\sum_js_{j,t}\)，\(s'_{i,t}=s_{i,t}/S_t\)。把 \(f_i\) 当作常数，证明

\[\frac{\partial\mathcal L_{\rm Bal}}{\partial\mathbf u_t}=\frac{\alpha}{T}\sum_{k=1}^{N_r}\frac{f_k-\sum_if_is'_{i,t}}{S_t}\,s_{k,t}(1-s_{k,t})\,\mathbf e_k,\]

并与 V2 的式 (11.10) 比较：两者的结构有什么相同与不同？

看答案

逐层用链式法则。

  1. \(\mathcal L_{\rm Bal}=\alpha\sum_if_iP_i\)，\(P_i=\frac1T\sum_ts'_{i,t}\)，所以 \(\partial\mathcal L/\partial s'_{i,t}=\alpha f_i/T\)。
  2. 归一化的导数：\(s'_{i,t}=s_{i,t}/S_t\)，\(\partial S_t/\partial s_{k,t}=1\)，商的求导法则给 \(\dfrac{\partial s'_{i,t}}{\partial s_{k,t}}=\dfrac{\delta_{ik}S_t-s_{i,t}}{S_t^2}=\dfrac{\delta_{ik}-s'_{i,t}}{S_t}\)。
  3. 合并：\(\dfrac{\partial\mathcal L}{\partial s_{k,t}}=\sum_i\dfrac{\alpha f_i}{T}\cdot\dfrac{\delta_{ik}-s'_{i,t}}{S_t}=\dfrac{\alpha}{T}\cdot\dfrac{f_k-\sum_if_is'_{i,t}}{S_t}\)。
  4. sigmoid 的导数（式 11.5）：\(\partial s_{k,t}/\partial z_{k,t}=s_{k,t}(1-s_{k,t})\)，且 \(s_{k,t}\) 只依赖 \(z_{k,t}\)。
  5. \(\partial z_{k,t}/\partial\mathbf u_t=\mathbf e_k\)，对 \(k\) 求和即得所证。

比较。 相同之处：都是“专家 \(k\) 的拥挤度 \(f_k\) 减去这个 token 眼中的平均拥挤度（按 \(s'\) 或 \(s\) 加权）”乘上专家中心向量 \(\mathbf e_k\) 再求和；梯度都落在 \(\mathbf u_t\) 上，所以同样会传进更早的层。不同之处：V2（softmax）的权重是 \(s_{k,t}\)；V3（sigmoid + 归一化）的权重是 \(s_{k,t}(1-s_{k,t})/S_t\)，sigmoid 饱和（\(s_k\to1\)）的专家几乎不受推动。系数 \(\alpha\) 从 V2 的 0.003 降到 \(10^{-4}\)，小了 30 倍（两者的 \(T\) 都是一条序列的 token 数，所以系数可以直接比；梯度的实际大小还取决于上面那两种不同的权重）。可以用有限差分做数值检验：笔者用随机取的向量核对过，两边一致到 \(10^{-10}\) 以内。

练习 12 · 接受率各不相同时的期望产出

每步有 \(k\) 个草稿，按顺序验证；设第 \(j\) 个草稿在前 \(j-1\) 个都被接受的条件下被接受的概率为 \(p_j\)。（a）证明 \(\E[N]=1+p_1+p_1p_2+\dots+p_1p_2\cdots p_k\)，并说明 \(p_j\equiv p\) 时它退化为式 (11.26)。（b）Gloeckle 等人 7B 代码模型用 2、3、4 个头自投机解码时，每次前向平均产出 1.94、2.78、3.50 个 token（含主模型自己的 1 个）。假设多一个头只是在末尾多一个草稿、前面各草稿的接受率不变，反推 \(p_1,p_2,p_3\)。

看答案

（a）\(N=1+A\)，\(A\) 是被接受的草稿数。\(A\ge j\) 当且仅当前 \(j\) 个草稿都被接受，由条件概率的乘法公式 \(\Pr(A\ge j)=p_1p_2\cdots p_j\)。非负整数随机变量的尾和公式 \(\E[A]=\sum_{j=1}^{k}\Pr(A\ge j)\)，所以 \(\E[N]=1+\sum_{j=1}^{k}\prod_{m=1}^{j}p_m\)。\(p_j\equiv p\) 时是 \(\sum_{j=0}^{k}p^j=(1-p^{k+1})/(1-p)\)，即式 (11.26)。

（b）2 个头即 1 个草稿：\(1+p_1=1.94\)，\(p_1=0.94\)。3 个头：\(1.94+p_1p_2=2.78\)，\(p_1p_2=0.84\)，\(p_2=0.84/0.94\approx0.894\)。4 个头：\(2.78+p_1p_2p_3=3.50\)，\(p_1p_2p_3=0.72\)，\(p_3=0.72/0.84\approx0.857\)。越靠后的草稿越难被接受，这与“头离当前位置越远、预测越难”的直觉一致。这是在“增加头不改变前面草稿的接受率”这一假设下的换算（笔者），Gloeckle 等人没有直接报告逐位置的接受率 10。
