一张科技树

这一页先说清楚为什么要把这段历史画成“树”，再给出整张图和读图的三种方法，最后用一张表把六条主线各自对付的账单说完。后面六页（§2–§7）每页放大一条主线。

问题：3,377 天里发生了什么

先把时间摆出来。GPT 这一侧的六个日子都有一手来源：Transformer 的论文在 2017-06-12 提交 arXiv 3；GPT-1 在 2018-06-11 公告，没有 arXiv 版 4；GPT-2 在 2019-02-14 公告 5；GPT-3 的论文在 2020-05-28 提交 6；InstructGPT 的公告与论文 PDF 在 2022-01-27 发出，arXiv 版晚到 2022-03-04 7；ChatGPT 在 2022-11-30 上线 8。从 Transformer 到 ChatGPT 是 1,997 天。

DeepSeek 这一侧，最早公开的语言模型是代码模型 DeepSeek-Coder：它没有官方公告页，GitHub 仓库的第一次提交是 2023-11-02，本课就用这一天作代理日期 9,10。第一代通用模型 DeepSeek LLM 7B/67B 在 2023-11-29 发布，离 ChatGPT 上线 364 天 11。从它到 2026-09-10 发布的 V4.1-Flash 是 1,016 天 12,13。研究笔记的发布总表从 DeepSeek-Coder 一直记到 2026-09-19 的 DSec 论文，一共 50 个条目：主线模型、旁支模型、论文和开源制品。

这么多条目，按时间排成一串，看到的只是一份清单。把它们按要压低的那一笔账分组，清单就变成了几条线：同一条线上，后一个节点几乎总是在前一个节点的账单上再打一个折。这就是“科技树”的意思：节点是一次改进，枝干是“在它的基础上”。

主线 A：注意力与 KV cache

这一页把主线 A 的七步改进放进一个公式里：每 token 的 KV 字节是四个因子的乘积，每一步改进都在其中一个因子上动手。然后用这个公式复算五个数，最后说清每一步省下的字节由什么来付。

问题：解码的每一步都要把缓存读一遍

第 4 课推导过：生成第 \(t\) 个 token 时，每一层都要用当前的查询去和前面全部 \(t-1\) 个 token 的键打分、再按权重读它们的值。这些键和值不必重算，可以缓存下来，这就是 KV cache；代价是它每个 token 占一份空间，而且解码的每一步都要把整份缓存从显存里读一遍。于是解码的速度主要由读多少字节决定，而不是算多少次乘法（第 4 课 §4 的“带宽墙”）。

这笔账有多大？DeepSeek LLM 67B 每个 token 缓存 389,120 字节。一个 \(2^{20}\) token（1M）的请求，缓存就是 \(389{,}120\times2^{20}\approx4.08\times10^{11}\) 字节，也就是 408 GB：一张 80 GB 的显卡只放得下 0.2 个这样的请求。主线 A 的全部工作，就是把这个数压下去。

KV cache = 会议纪要本

映射。 每个发言者（token）说完，秘书把他的“标签 + 要点”（键 K、值 V）记在本子上；后来的人只翻本子，不必重听录音。主线 A 的每一步都在让本子变薄或少翻几页：MQA/GQA 让几位发言者共用一栏；MLA 改记速记符号（潜向量），要用时再展开；DSA 先查目录，只精读得分最高的 2048 条；CSA/HCA 把每 4 句或每 128 句合写成一条；CSA2 让 40 层共用 4 本；FP4 用更短的字来写。

收益。 它让“省空间”和“省阅读量”分开：DSA 并没有让本子变薄（反而多了一栏目录），只是每次少翻。

边界。 真正的纪要是逐字副本，所以 KV cache 本身只省重复计算、不省空间，空间随发言人数线性增长；MLA 的速记、CSA 的合写却是训练出来的有损压缩，压缩用的矩阵是学出来的，模型必须在训练中学会读它，不能事后套在一个现成模型上。

形式化：每 token 字节的四个因子

把每 token 的缓存拆成四个问题：一共存几份？每几个 token 存一条？每条几个数？每个数几个字节？第 19 课把这四个问题写成一个乘积（第 19 课 §8）：

每 token 全局 KV 字节\[B_{kv}=\underbrace{n_{\text{copy}}}_{\text{存几份}}\times\underbrace{\frac1m}_{\text{每几个 token 一条}}\times\underbrace{n_{\text{dim}}}_{\text{每条几个数}}\times\underbrace{b}_{\text{每个数几字节}}\]\(B_{kv}\) 只计随上下文线性增长的全局 KV；滑动窗口（SWA）状态是每个请求的一个常数，不计入。\(b\) 要把摊到每个数上的缩放因子也算进去。(0.1)

四个符号的含义：\(n_{\text{copy}}\) 是整模型一共存几份缓存（普通模型每层一份，\(n_{\text{copy}}=l\)）；\(m\) 是压缩率，每 \(m\) 个 token 合成一条（不压缩时 \(m=1\)）；\(n_{\text{dim}}\) 是一条缓存里有多少个数；\(b\) 是每个数占几个字节（BF16 是 2）。把前几代模型代进去：

稠密注意力与 MLA\[\begin{aligned}\text{MHA / GQA：}\quad B_{kv}&=2\,n_g\,d_h\,l\,b\\ \text{MLA：}\quad B_{kv}&=(d_c+d_h^R)\,l\,b\end{aligned}\]MHA 取 \(n_g=n_h\)，MQA 取 \(n_g=1\)。系数 2 是键和值各一份；MLA 每层只存一个 \(d_c\) 维潜向量和一个 \(d_h^R\) 维的 RoPE 键，所有头共用 1。(0.2)

V3.2 以后的缓存用低精度存储，并多了一个给 indexer 用的“索引键”；V4 起还沿序列方向压缩。它们的通式是：

V3.2：每层一条 FP8 MLA 条目加一个索引键\[B_{kv}=l\times(656+132)\]656 字节 = 512 个 FP8 潜向量分量 + 4 个 FP32 缩放因子（16 字节）+ 64 个 BF16 的 RoPE 分量（128 字节）；132 字节 = 128 维 FP8 索引键 + 4 字节缩放 19。(0.3)
V4：CSA 层与 HCA 层分别压缩\[B_{kv}=\sum_{\ell\in\text{CSA}}\frac{584+68}{m}+\sum_{\ell\in\text{HCA}}\frac{584}{m'},\qquad m=4,\ m'=128\]584 字节 = 448 维 FP8 + 64 维 BF16 的 RoPE + 8 字节缩放 19；68 字节是 FP4 的索引键（128 维 × 4 bit + 4 字节缩放），这是笔者由论文与代码推算的值，原文没有直接印出 12,20。(0.4)
V4.1：只有 Full 层自己存\[B_{kv}=\sum_{\ell\in\text{Full}}\frac{288+68}{m_\ell}\]288 字节 = 512 维 FP4（E2M1）+ 每 16 维一个 E4M3 缩放（32 字节）12,19。40 层里只有 4 层是 Full 层（三层 \(m=2\)、一层 \(m=1\)），其余层借用它们的缓存（第 19 课 §3）。(0.5)

这五个数里有四个恰好是 V4.1 论文图 1(b) 印出的柱长（389,120、48,068、3,514、890），由此也复现了图上的三段倍数 8.1×、13.7×、3.9× 和总倍数“437 倍”12。V4-Pro 按同一公式是 \(30\times\tfrac{652}{4}+31\times\tfrac{584}{128}=5{,}031\) 字节，论文没有印这个数，只说约为 V3.2 的 10%，与之吻合（笔者推算）。

年化看：从 DeepSeek LLM（2023-11-29）到 V4.1-Flash（2026-09-10）共 1,016 天，缩小 437.2 倍，相当于每年 \(437.2^{365/1016}\approx8.9\) 倍（笔者口径）。

代价：省下的字节由什么来付

主线 A 上没有免费的一步。把每一步的代价列在一起，才能看懂为什么它们要按这个顺序出现：

  • GQA / MQA 付质量。 让一组查询头共用一对键值：MQA 在原论文的翻译实验里略降（WMT14 BLEU 26.7 → 26.5），还可能训练不稳；GQA-8 在 T5-XXL 上几乎追平 MHA（47.1 对 47.2）（第 4 课 §5）21,22。
  • MLA 付计算，还要绕开 RoPE。 推理时把上投影“吸收”进查询，缓存从不展开；代价是每个缓存 token 多做约 3.4 倍运算，换来少读几十倍字节（第 9 课 §3）。旋转位置编码 RoPE 夹在中间会破坏吸收，于是位置信息另存一个 64 维的共享键，这就是 \(d_h^R\) 23。
  • DSA 付存储，省的是读取与计算。 V3.2 在 MLA 之外多存一个 132 字节的索引键，缓存相对 FP8 的 MLA 反而多了约 20%；它省的是长上下文下每一步要读的条目数和要算的打分。在 128K 处，按 H800 租价折算，预填充约便宜 3.56 倍、解码约 8.65 倍（第 14 课 §7）16。DeepSeek 在它之前提出的 NSA 走的是另一条稀疏路线（压缩、选块、滑窗三个分支），获 ACL 2025 最佳论文 24,25。
  • CSA/HCA 付细节。 把 4 个或 128 个 token 合写成一条，条目就记不住“哪个数是哪个 token 的”，逐字细节要靠最近 128 个 token 的滑动窗口。1M 上下文“装得下”不等于“用得好”：多针检索 MRCR 在 1M 处明显下降（第 18 课 §7）。
  • CSA2 付近似。 多数层借用别人的 top-k，可能选错；持久化缓存的 SWA 状态靠有界回放近似恢复；短上下文下解码反而比 V4-Flash 贵（第 19 课 §8）。
“93.3%”和“27% / 10%”各自在比什么
  • V2 论文说 KV cache 比 DeepSeek 67B 降了 93.3%，比较的是部署态：V2 的缓存平均量化到 6 bit，67B 按 BF16。\(1-25{,}920/389{,}120=93.3\%\)；两边都按 BF16 只有 \(1-69{,}120/389{,}120=82.2\%\) 1。
  • V4 论文说 1M 上下文下 V4-Pro 只需 V3.2 的 27% 单 token FLOPs 和 10% KV，这只在 1M、以外推到 1M 的 V3.2 为基线、按“等效 FP8 FLOPs”计时成立 2。V4.1 论文的 FLOPs 图改用 BF16 当量（BF16、FP8、FP4 按 1、0.5、0.25 加权），同一个 V3.2 在两张图上相差约 2 倍，两图不能直接比 12。
主线 A 小结
  • 每 token KV = 份数 × \(\tfrac1m\) × 每条维数 × 每维字节 (0.1)。GQA 动头数，MLA 动条目维，V3.2 动精度，V4 动序列维，V4.1 同时动层维与精度；DSA 不减字节，减的是每步的读取。
  • 五个数 389,120 → 69,120 → 48,068 → 3,514 → 890 都能由架构复算，其中四个与 V4.1 论文图 1(b) 一致；67B 到 V4.1-Flash 共 437 倍。
  • 每一步都有代价：质量（GQA）、计算（MLA）、存储反增（DSA）、细节（CSA/HCA）、近似（CSA2）。

主线 B：前馈层的稀疏化

这一页讲混合专家（mixture of experts，MoE）这条线：它要拆开的是“模型越大、每个 token 越贵”这个绑定。先给出 DeepSeek 用了三年的 MoE 层公式，再沿时间看它的每一次改动各自在对付什么，最后用一张图看激活比例怎样一代代变小。

问题：参数量和计算量绑在一起

稠密模型处理每个 token 时，每个参数都要参与一次乘加，所以每 token 的前向计算约是 \(2N\) 次运算（第 1 课 §8）。想让模型知道更多，就要加参数；加了参数，每个 token 就更贵。前馈网络（FFN）是这笔账的大头：DeepSeek LLM 7B 有 58.7% 的参数在 FFN 里（第 7 课 §1）。

条件计算（conditional computation）的想法是：把一个大 FFN 换成许多个小 FFN（“专家”），每个 token 只经过其中几个。于是总参数 \(N_{\text{total}}\) 可以很大，每个 token 真正参与计算的激活参数 \(N_{\text{act}}\) 却很小。要付的是另一笔账：全部专家都得放在显存里，而且专家分在不同的卡上，token 要在卡与卡之间来回搬。

MoE = 医院

映射。 路由器是分诊台；路由专家是各个专科医生；共享专家是每个病人都要看的全科医生；细粒度切分是把“内科”拆成心内、消化、呼吸……，组合更灵活；负载均衡是别让病人都挤到一个科室；V3 的偏置 \(b_i\) 是分诊台看到某科排队太长，就把它的“推荐分”暂时调低。

收益。 它让“总参数大、每个病人只看几个医生”变得直观，也让“排队”（负载不均）成为一个自然的问题。

边界。 分诊按 token 进行，同一句话里的不同词会去不同科室；“专科”是训练中自发形成的，不是人为指定的，所以没有哪个专家叫“数学专家”。

形式化：一层 DeepSeekMoE

从 DeepSeekMoE 到 V4.1，MoE 层一直是“共享专家 + 路由专家”的结构。以 V3 的写法为例（第 11 课 §2），第 \(t\) 个 token 进入 FFN 位置的隐藏状态是 \(\mathbf u_t\in\R^{d}\)，输出为

共享专家加路由专家\[\mathbf h'_t=\mathbf u_t+\sum_{i=1}^{N_s}\FFN^{(s)}_i(\mathbf u_t)+\sum_{i=1}^{N_r}g_{i,t}\,\FFN^{(r)}_i(\mathbf u_t)\]\(N_s\) 个共享专家每个 token 必经；\(N_r\) 个路由专家里只有 \(K_r\) 个的门控值 \(g_{i,t}\) 不为 0。V3 取 \(N_s=1\)、\(N_r=256\)、\(K_r=8\) 26。(0.6)

门控值怎么来，是这条线后半段反复修改的地方。V3 先算亲和度 \(s_{i,t}=\sigma(\mathbf u_t^\top\mathbf e_i)\)（\(\mathbf e_i\in\R^d\) 是第 \(i\) 个专家的中心向量，\(\sigma\) 是 sigmoid），再用一个只管“选谁”的偏置 \(b_i\) 做 top-\(K_r\) 选择：

选择用 \(s+b\)，加权用 \(s\)\[g'_{i,t}=\begin{cases}s_{i,t}, & s_{i,t}+b_i\in\TopK\big(\{s_{j,t}+b_j\}_{j=1}^{N_r},K_r\big)\\ 0, & \text{否则}\end{cases}\qquad g_{i,t}=\frac{g'_{i,t}}{\sum_{j}g'_{j,t}}\]每一步训练之后，过载的专家 \(b_i\) 减 \(\gamma\)，欠载的加 \(\gamma\)（V3 取 \(\gamma=0.001\)）；\(b_i\) 不进入门控值，也不产生梯度 26,27。(0.7)

数字：激活比例一代代变小

细粒度切分换来了什么，又没有换来什么

组合数。 16 个专家里选 2 个，有 \(\binom{16}{2}=120\) 种组合；每个专家切成 4 份（64 个专家选 8 个），组合数变成 \(\binom{64}{8}=4{,}426{,}165{,}368\)。总参数和每 token 的计算量都没有变（第 7 课 §5）。

激活比例。 V3 是 \(37/671=5.5\%\)，V4-Pro 是 \(49/1600=3.1\%\)，V4.1-Flash 解码 \(16/552=2.9\%\)、预填充 \(8/552=1.45\%\)。

没有换来的。 显存里仍要放下全部 671B 或 1.6T 参数；专家分散在许多卡上，每个 token 的 all-to-all 通信随它要去的设备数增长。这正是设备受限路由、节点受限路由和第 12 课那些通信内核要解决的问题。

“DeepSeekMoE 16B 只用了 40% 的计算量”

论文里的“40%”是每 4K token 的前向 FLOPs 之比（74.4T 对 183.5T），对照的是 DeepSeek LLM 7B，不是激活参数之比；16B 的激活参数 2.8B 包含嵌入与输出头（第 7 课 §8）31。引用这类比例时，先问分子分母各是什么。

代价与失败模式

  • 路由坍缩。 被偏爱的专家学得更快、被选得更多，这是自我强化的；不加约束时最忙的专家负载可达平均的 17.8 倍（第 7 课 §3）28。
  • 辅助损失的两难。 系数大了伤性能，小了不均衡。无辅助损失论文的 1B 实验里，偏置法同时得到更好的均衡与更低的困惑度（第 11 课 §1）；“伤性能是因为干扰梯度”是解释，不是证明。
  • 通信与等待。 专家分到多张卡后，最忙的卡决定整步的时间；token 要去的设备越多，all-to-all 越贵。
主线 B 小结
  • MoE 层 = 共享专家 + 路由专家 (0.6)；DeepSeek 的两招是细粒度切分和共享专家隔离（第 7 课）。
  • 均衡的办法从辅助损失（V2 三种）换成了只管选择、不产生梯度的偏置 (0.7)（V3 起）；路由的约束从设备受限（V2，至多 3 台）到节点受限（V3，至多 4 个节点）再到取消（V4）。
  • 激活比例从 16B 的约 1/6 降到 V4.1-Flash 预填充的约 1/69；代价是显存要装下全部参数，以及跨卡通信。

主线 C：数值与系统

这一页讲“同样的模型，怎样算得更便宜”。主线 C 有两半：数值（每个数用几位存、几位算）与系统（算、传、存怎样重叠与分工）。数值这一半有一个统一的形式：一小组数共用一个缩放因子。

问题：一次训练的账单

V3 的技术报告给出了全部正式训练的 GPU 小时：预训练 2,664K、上下文扩展 119K、后训练 5K，合计 2,788K H800 GPU 小时，按每小时 2 美元折算是 557.6 万美元；报告明确说这不包括此前的研究与消融实验（第 12 课 §1）26。要让这个数小下去，只有两条路：让每次矩阵乘法更便宜（更短的数），让不算的时间更少（把通信藏到计算后面）。推理时还有第三笔：显存装得下多少、每一步要读多少字节，这又回到主线 A。

低精度数值 = 短尺子 + 分段放大镜

映射。 FP8 是一把刻度很少的尺子（一共只有 256 个码）；缩放因子是给每一小段配一个放大镜，让这一段的数正好落在尺子最精细的区间里；细粒度量化是放大镜配得更密（每 128 个数一个，而不是整个张量一个）。

收益。 它解释了为什么“一个离群值”在整张量缩放下是灾难：放大镜只能照顾最大的那个数，其余的数都被挤到尺子的粗刻度上。

边界。 放大镜只能整体缩放，同一小段里大小悬殊的数，仍然会有一个被量得很粗；而且缩放因子本身也要存、要乘，配得越密，额外的字节和运算越多。

形式化：一组数共用一个缩放因子

把一组数 \(\{x_j\}_{j\in G}\) 存成低精度时，先按组里的最大绝对值定一个缩放因子 \(s\)，再把每个数除以 \(s\) 后舍入到格式里最近的可表示值：

分组缩放量化\[s=\frac{\max_{j\in G}\abs{x_j}}{q_{\max}},\qquad \hat x_j=s\cdot\operatorname{round}_{\text{fmt}}\!\Big(\frac{x_j}{s}\Big)\]\(q_{\max}\) 是格式能表示的最大值：FP8 的 E4M3 是 448，FP4 的 E2M1 是 6。V3 的训练里，激活按 \(1\times128\)、权重按 \(128\times128\) 分组，缩放因子存成 FP32（第 12 课 §3）26,33。(0.8)

V3.1 把缩放因子本身也限制成 2 的整数次幂（UE8M0 格式，8 位全是指数），并向上取整，保证不溢出（第 15 课 §3）：

UE8M0：只取 2 的幂的缩放因子\[s=2^{\lceil\log_2(a/448)\rceil},\qquad a=\max_{j\in G}\abs{x_j}\]好处是缩放因子只占 1 字节、乘 \(2^n\) 精确且便宜；代价是组里最大的数只能用到 E4M3 范围的一半到全部，在对数均匀的假设下平均约 72%。(0.9)

数字：一个 KV 条目里的字节

主线 C 与主线 A 在 KV 缓存上相遇：同一个“每 token 缓存多少字节”，A 管的是存几份、每几个 token 一条，C 管的是每个数几位。

557.6 万美元，与“每维几位”

训练账单。 \((2{,}664+119+5)\text{K}\times\$2=\$5.576\text{M}\)。报告另给出每万亿 token 需要 180K GPU 小时，在 2,048 张卡上是 \(180{,}000/2{,}048/24=3.66\) 天（原文写约 3.7 天）26。

每维几位。 V2/V3：\(1{,}152\times8/576=16\) 位；V3.2：\(656\times8/576=9.1\) 位；V4：\(584\times8/512=9.1\) 位；V4.1：\(288\times8/512=4.5\) 位。

代价与失败模式

  • 范围与精度。 E4M3 只有 256 个码，相对舍入误差可达 6.25%；比组内最大值小约 3 万倍的数开始失真（第 12 课 §3）。离群值决定整组的缩放，这就是“细粒度”存在的理由。
  • 累加误差。 H800 的 FP8 张量核心累加只有约 14 位有效位，误差随内维线性变大，所以 V3 每 128 个元素把部分和搬到 FP32（第 12 课 §4）。
  • 假设。 V4.1 省掉 FP4 的第二级全局缩放，前提是训练出的 RMSNorm 权重大约为 1，于是 512 维向量的每个分量不超过约 \(\sqrt{512}\approx22.6\)，远小于 \(448\times6=2{,}688\)；这个前提不成立时论证就不成立（第 19 课 §5）12。
  • 理论值与实际值。 开源周 Day 6 公布的“成本利润率 545%”是按 R1 价格算的理论值，不是实际收入 36。

主线 D：训练目标与后训练

这一页讲模型学什么。预训练让模型模仿语料；后训练想让它帮得上忙、做得对。这条线上 DeepSeek 最重要的贡献是 GRPO，以及用它在 R1 上证明的一件事：只看最后答案对不对，也能教会模型一步一步地想。

问题：“让人满意”写不成一个可以求导的损失

预训练的目标是下一词预测：在语料上最小化交叉熵（第 2 课 §2）。

下一词预测\[\mathcal L(\theta)=-\frac1T\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t})\]\(x_t\) 是第 \(t\) 个 token，\(p_\theta\) 是参数为 \(\theta\) 的模型给出的条件概率。它让模型像语料，但语料里的“像”不等于“对”或“有用”。(0.10)

我们真正想要的东西（回答有没有帮上忙、数学题做没做对）只能事后打分，写不成对 \(\theta\) 可导的式子。于是有了强化学习：让模型自己写回答、按奖励 \(r\) 打分、把高分回答的概率推高，同时用 KL 散度把它拴在参考模型 \(\pi_{ref}\) 附近，免得它跑到奖励打分不可靠的地方去（第 3 课 §3）：

带 KL 约束的强化学习目标\[\max_{\pi_\theta}\ \E_{q\sim\mathcal D,\ o\sim\pi_\theta(\cdot\mid q)}\big[r(q,o)\big]-\beta\,\KL\big[\pi_\theta\,\Vert\,\pi_{ref}\big]\]\(q\) 是题目（提示），\(o\) 是模型写的回答，\(\beta\) 是 KL 系数。(0.11)

InstructGPT 用 PPO 优化它，要同时放四个模型：策略、参考模型、奖励模型、价值网络。按每个训练参数 16 字节、冻结参数 2 字节估算，7B 规模下 SFT 约 112 GB，PPO 约 252 GB（第 3 课 §6）7,40。

GRPO = 同题多答、组内排名

映射。 同一道题让学生写 \(G\) 份答卷，每份按“比这组平均分高多少个标准差”给分，不用另请一位“预测分数的老师”（价值网络）。

收益。 它说明了 GRPO 为什么能省掉价值网络：基线直接用同题其他答卷的平均分。

边界。 只有同一道题内比较才有意义；如果一组全对或全错，优势全为零，这道题就不提供学习信号。

形式化：组内标准化的优势

GRPO 对每道题 \(q\) 采 \(G\) 个回答，得到奖励 \(r_1,\dots,r_G\)，第 \(i\) 个回答的每个 token 共用同一个优势（第 8 课 §4）：

GRPO 的优势\[\hat A_i=\frac{r_i-\operatorname{mean}(r_1,\dots,r_G)}{\operatorname{std}(r_1,\dots,r_G)}\]DeepSeekMath 与 R1 都除以标准差；V3.2 改成只减均值、不除标准差（第 15 课 §4）15,16。(0.12)

训练目标这一侧还有一处改动：V3 在下一词预测之外加了多 token 预测（MTP），用 \(D\) 个顺序模块，第 \(k\) 个模块预测再往后第 \(k\) 个 token，损失取平均再乘一个权重 \(\lambda\)（第 11 课 §6）：

多 token 预测的附加损失\[\mathcal L_{\text{MTP}}=\frac{\lambda}{D}\sum_{k=1}^{D}\mathcal L^{(k)}\]V3 取 \(D=1\)，\(\lambda\) 在前 10T tokens 为 0.3、之后为 0.1 26；它的思路来自 Meta 的并行多 token 预测 41。(0.13)

一组四个回答的优势

一道题采 \(G=4\) 个回答，只有第一个答对：\(r=(1,0,0,0)\)。均值 0.25，总体标准差 \(\sqrt{0.25\times0.75}=0.433\)，所以

\[\hat A=\Big(\frac{0.75}{0.433},\ \frac{-0.25}{0.433},\ \frac{-0.25}{0.433},\ \frac{-0.25}{0.433}\Big)=(1.732,\ -0.577,\ -0.577,\ -0.577)\]

四个优势之和为 0：答对的那一份被推高，另外三份被压低，而且答对越稀有，推得越狠（这正是 \(\sqrt{(1-p)/p}\)，\(p=0.25\) 时为 1.732，第 13 课 §3）。如果四份都答对或都答错，优势全是 0，这道题这一步不提供任何信号。若按 V3.2 的写法只减均值，答对的优势是 0.75，不再除以 0.433。

代价与失败模式

  • 奖励被钻空子。 神经网络奖励模型会被“讨好”，R1 因此在推理题上只用规则奖励，神经奖励只用在一般题目、且只在最后 400 步（第 13 课 §5）。
  • 两条没走通的路。 R1 试过过程奖励模型（PRM）和蒙特卡洛树搜索（MCTS），都没用上；论文也说明这不代表它们做不出好的推理模型（第 13 课 §7）。
  • RL 改变了什么。 DeepSeekMath 的实测是 RL 提升 Maj@K（多数投票）而不提升 Pass@K（\(K\) 次里对一次），更像把已有的正确答案“磨尖”，而不是教会新本事（第 8 课 §8）。
  • 规模化的不稳定。 后训练放大 50 多倍之后，“采样的模型”与“训练的模型”不再一致，V3.2 为此加了无偏 KL、离策略序列掩码、固定路由、固定采样掩码四项修补（第 15 课 §5）。
  • 更长的思考，更贵的推理。 R1 平均每题写 8,793 个思考 token，约为 GPT-4o 的 12 倍（第 13 课 §1）；长输出的注意力账单又回到了主线 A。

主线 E：残差流与记忆

这一页有两个话题，放在同一条线上，是因为它们都在问“信息怎样在模型里保存和传递”。前一半是残差流：每一层把结果加回一条贯穿全程的向量流，这条流上的系数为什么必须是 1，又怎样在保住 1 的前提下把一条流变成四条。后一半是记忆：除了权重和 KV cache，还有没有别的地方可以记东西。

问题一：捷径上的系数

残差连接让每一层只学一个增量：\(\mathbf x_{l+1}=\mathbf x_l+\mathcal F_l(\mathbf x_l)\)，\(\mathbf x_l\in\R^d\) 是第 \(l\) 层之前的残差流（第 1 课 §6）。展开 \(L\) 层后，最初的 \(\mathbf x_l\) 以系数 1 出现在任意深处，梯度也原样传回来。如果捷径上乘的不是 1 而是 \(\lambda\)，从第 \(l\) 层走到第 \(L\) 层，直通项就变成 \(\lambda^{L-l}\)：

捷径系数的连乘\[\mathbf x_{L}=\lambda^{L-l}\,\mathbf x_l+\cdots,\qquad 1.05^{60}=18.7,\quad 0.95^{60}=0.046\]偏离 1 的代价随深度指数增长（第 16 课 §1）。(0.14)

图景：传送带

残差流 = 传送带

映射。 每层是传送带旁的一个工位，从带上取件、加工、把增量放回带上；恒等映射就是没人动的件原样往下走。Hyper-Connections 是多条并行传送带，再加上带与带之间的调度；mHC 要求调度必须“守恒”：每条带送出去的总量和收进来的总量都是 1（双随机矩阵），所以件既不会越传越多，也不会凭空消失。

收益。 它让“守恒”这个约束一目了然，也让“为什么单独约束每行（只管送出）不够”变得可以想象：只管送出不管收进，某条带仍可能被挤爆。

边界。 真实的残差流是连续向量空间里的加法，“件”的比喻不表达方向，也不表达正负抵消。

形式化：从一条流到四条守恒的流

Hyper-Connections 把残差流复制成 \(n\) 条，\(X_l\in\R^{n\times d}\)；每个子层 \(\mathcal F_l\) 用 \(H^{\rm pre}_l\in\R^{1\times n}\) 从 \(n\) 条流里读出一个输入，用 \(H^{\rm post}_l\in\R^{1\times n}\) 把输出写回各条流，再用 \(H^{\rm res}_l\in\R^{n\times n}\) 混合各条流（第 16 课 §2）17：

超连接的一层\[X_{l+1}=H^{\rm res}_l\,X_l+H^{\rm post\,\top}_l\,\mathcal F_l\big(H^{\rm pre}_l\,X_l\big)\]\(n=1\)、三个映射都取 1 时，它退回普通残差。mHC 要求 \(H^{\rm res}_l\) 是双随机矩阵：元素非负，每行、每列的和都是 1；它的谱范数恰为 1，而且两个双随机矩阵的乘积仍是双随机矩阵，所以多少层连乘都不会放大 44。(0.15)

问题二：记在哪里

到第 16 课为止，模型只有两种记法：训练时写进权重，要靠一层层计算才能“想起来”（付的是深度）；推理时写进 KV cache，每个 token 一份、保留到对话结束（付的是字节）。第 17 课讲两种新形态（第 17 课 §1）：

  • Engram 条件记忆。 用最近几个 token 的编号做哈希、直接查一张大表，取回静态的局部知识。行号只由 token 编号决定，前向开始前就能算出，所以表可以放在主机内存里边算边预取 18。
  • DeepSeek-OCR 视觉压缩。 把一页文字渲染成图片，用少得多的视觉 token 装下它：文本 token 不超过视觉 token 10 倍时，逐字读回的精度约 97% 45。

两个 2×2 的双随机矩阵

\(A=\begin{pmatrix}0.7&0.3\\0.3&0.7\end{pmatrix}\) 每行、每列的和都是 1。它的平方是

\[A^2=\begin{pmatrix}0.7\cdot0.7+0.3\cdot0.3&0.7\cdot0.3+0.3\cdot0.7\\0.3\cdot0.7+0.7\cdot0.3&0.3\cdot0.3+0.7\cdot0.7\end{pmatrix}=\begin{pmatrix}0.58&0.42\\0.42&0.58\end{pmatrix}\]

仍是双随机矩阵，所以两条流的总量 \(x_1+x_2\) 经过任意多层都不变。反过来，只约束行和的 \(\begin{pmatrix}1&0\\1&0\end{pmatrix}\) 前向安全，反向却能把梯度放大 2 倍（列和是 2）；这就是 mHC 要同时约束行与列的原因（第 16 课 §4）。代价也看得见：\(A^2\) 比 \(A\) 更接近“全取平均”的 \(\begin{pmatrix}0.5&0.5\\0.5&0.5\end{pmatrix}\)，流与流之间的差别只减不增。

代价与失败模式

  • 访存。 按 V4-Flash 计，mHC 的参数只占约 0.012%，算术约 0.33%，瓶颈在读写：不做核融合时每个 token 每个子层要读写约 \(34d\) 个元素，是普通残差 \(3d\) 的约 11 倍（第 16 课 §6）。
  • 证据的范围。 Engram 的 U 形曲线只在两个算力点、固定稀疏度下测过；DeepSeek-OCR 测的是逐字 OCR 精度，不是在压缩后的上下文上推理的能力，V4.1-Flash 也没有采用它的编码器（第 17 课 §7）。

主线 F：规模化规律与优化器

这一页讲怎样“下注”。一次大训练只能跑一遍，学习率、batch 大小、模型与数据怎么分，全要在开跑之前定下来。主线 F 的办法是：在小预算上把规律测准，拟合成幂律，再外推到大预算；优化器则决定每一步怎样走。

问题：一次训练，没有第二次机会

训练一个稠密 Transformer 的算力约为 \(C\approx6ND\)：每个 token、每个参数，前向 2 次、反向 4 次运算（第 2 课 §6）。给定 \(C\)，模型该多大（\(N\)）、数据该多少（\(D\)）？Kaplan 2020 的拟合说主要加大模型，\(N_{\text{opt}}\propto C^{0.73}\) 48；Chinchilla 2022 用三种方法得到参数与数据同比例增长，由此流传出“每个参数约 20 个 token”的经验法则 34。两家的结论互相矛盾，超参数怎么随规模变也交代不全。

形式化：DeepSeek LLM 的三条幂律

DeepSeek LLM 的回答分三步（第 6 课）。先换一个记账方式：用每 token 的非嵌入 FLOPs \(M\) 代替 \(6N\)，训练算力写成 \(C=MD\)；\(M=72\,l\,d^2+12\,l\,d\,T\) 把注意力的打分与加权求和也算了进去（\(T\) 是序列长度）11。再在小预算上找出近优的学习率与 batch：

超参数的规模化规律\[\eta_{\text{opt}}=0.3118\,C^{-0.125},\qquad B_{\text{opt}}=0.2920\,C^{0.3271}\]\(\eta\) 是学习率，\(B\) 按 token 计。算力每乘 10，batch 约乘 2.12，学习率约乘 0.75（第 6 课 §6）。(0.16)

最后拟合模型与数据的最优分配：

最优分配\[M_{\text{opt}}=0.1715\,C^{0.5243},\qquad D_{\text{opt}}=5.8316\,C^{0.4757}\]两个指数之和为 1，因为 \(M_{\text{opt}}D_{\text{opt}}=C\)。报告还发现，数据质量越高，模型那一侧的指数越大（0.450、0.524、0.578），并把原因标为推测（第 6 课 §7）。(0.17)

优化器这一侧，DeepSeek 从 DeepSeek LLM 到 V3 一直用 AdamW 49；V4 把大部分矩阵参数换成 Muon：先按动量求出更新方向，再用牛顿–舒尔茨迭代把它近似正交化（所有奇异值推向 1），然后重新缩放（第 18 课 §5）：

V4 的 Muon 一步（算法 1 第 4–8 行）\[\begin{aligned}M_t&=\mu M_{t-1}+G_t\\ O_t&=\operatorname{NS}(\mu M_t+G_t)\cdot\sqrt{\max(n,m)}\cdot\gamma\\ W_t&=W_{t-1}(1-\eta\lambda)-\eta\,O_t\end{aligned}\]\(G_t\) 是梯度，\(W\in\R^{n\times m}\) 是一个权重矩阵，\(\mu=0.95\) 是动量，\(\lambda=0.1\) 是权重衰减，\(\gamma\) 把更新的均方根缩放到 0.18；NS 是 8 步快速迭代加 2 步精修的牛顿–舒尔茨 2,50。(0.18)

数字：每个参数分到多少 token

MoE 让“每个参数分到多少 token”有了两种算法：按总参数算，还是按激活参数算。

用规律给 7B 与 67B 定超参数

把两个模型的训练算力代进 (0.16)，预测 7B 的学习率为 \(4.24\times10^{-4}\)、batch 为 9.24M token，67B 为 \(3.17\times10^{-4}\)、19.7M token（报告图 3 标作 4.2e-04、9.2M 与 3.2e-04、19.7M）；实际用的是 \(4.2\times10^{-4}\) 配 2,304 条序列、\(3.2\times10^{-4}\) 配 4,608 条序列（每条 4,096 个 token，即约 9.4M 与 18.9M token）（第 6 课 §6）11。

再看图 0.7 的两个数：V3 是 \(14.8\text{T}/671\text{B}=22.1\) 与 \(14.8\text{T}/37\text{B}=400\)；V4.1-Flash 是 \(45\text{T}/552\text{B}=81.5\) 与 \(45\text{T}/16\text{B}=2{,}812.5\)。

代价与失败模式

  • 外推是下注。 幂律是在小预算上拟合的，7B 与 67B 的训练算力分别是最大一组 IsoFLOP 实验的 283 倍与 2,885 倍（第 6 课 §1）；拟合只依赖 \(C\)，同算力下不同的模型形状，最优区域会略有移动。
  • 口径。 在最小的实验模型上，只数非嵌入参数的 \(6N_1\) 只有 \(M\) 的 0.43，把输出头也算进去的 \(6N_2\) 又高估 32%（第 6 课 §5）；MoE 再让“\(N\)”分成总参数与激活参数两个数。
  • Muon 不是“全部参数都换”。 V4 的嵌入、预测头、RMSNorm 权重和 mHC 的静态偏置、门控仍用 AdamW；牛顿–舒尔茨只把奇异值近似推到 1（第 18 课 §5）。
主线 F 小结
  • 算力 \(C\approx6ND\)；DeepSeek LLM 改用 \(C=MD\)，并拟合出学习率与 batch (0.16)、模型与数据 (0.17) 的幂律，最优分配随数据质量而变。
  • 优化器从 AdamW 到 Muon (0.18)（V4），V4.1 再给嵌入表与 Engram 表换上更省状态的更新。
  • MoE 让“每个参数多少 token”有两种算法：按总参数多在 20–120（V2-Lite 例外，363），按激活参数几百到近三千。

这门课是怎么做出来的

每一课都先有一份研究笔记，再有课文。研究笔记放在 deepseek/reference-docs/lesson-NN-doc.md，数学课的在 math/reference-docs/。它记下四样东西：每个事实的一手来源与读的是哪一版（arXiv 的哪一版、哪个配置文件、哪一页模型卡）；承载事实的那一句原文（短引文）；每个派生数字的计算式（都在 Python 里复算过）；以及勘误和“未能核实”的清单。课文里的数字只能来自研究笔记，研究笔记里标“未能核实”的内容不进课文，进了也要写明。

笔记写完之后还有一轮对抗式复核：复核人不沿用原来的结论，而是回到一手来源逐条重查。以本课的研究笔记为例，复核记下了 25 项核对无误的论断和 8 处修改，比如 API 更新日志的条目数原先数错了、V4 技术报告在 HF 上的“更新”其实是删除、若干论文的作者人数把团体名也算成了人、DSpark 的提速区间原先把 V4-Flash 的数推广到了整个 V4。

图也遵守同样的规矩：凡是由数据决定形状的图（曲线、柱子、刻度），都由 figures/gen/ 下的脚本从数据表计算生成，不手画；本课的九张图对应 l00_*.py 九个生成脚本（外加一个共用的绘图工具 l00_svg.py）。每一课构建后都要通过检查脚本（公式能否渲染、图的颜色是否都用主题变量、引用是否都能对上），再逐页截图检查。

五个贯穿全课的问题

这门课的每一课都在讲一个具体的设计，但读多了会发现，能帮你真正读懂一个设计的，总是同样几个问题。这里把它们写下来，读后面任何一课、任何一篇技术报告时都可以拿出来问。每个问题后面列几处课里的例子。

一、账单在哪一行？

先问这个设计省下的是什么：显存容量、每一步读的字节、每个 token 的运算、跨卡通信、训练算力，还是训练信号的质量。同一个“省”字，指的可能是完全不同的资源。

  • MLA 省的是缓存字节，付的是每个缓存 token 约 3.4 倍的运算（第 9 课 §3）。
  • DSA 不省字节（反而多 20%），省的是长上下文下每一步要读的条目和要算的打分（第 14 课 §7）。
  • GRPO 省的是一个和策略一样大的价值网络的显存（第 8 课 §4）。
  • V4.1 的因果编码器–解码器省的是预填充的计算，解码反而多激活一些参数（第 19 课 §2）。

二、这个数在跟谁比，按什么口径？

头条数字几乎都有一个没写在标题里的分母。读到“省了 X%”，先找到比较对象、单位和条件。

  • “KV 降 93.3%”是 6 bit 部署的 V2 对 BF16 的 67B；两边同为 BF16 是 82.2%（§2）。
  • “27% FLOPs、10% KV”只在 1M 上下文、以外推的 V3.2 为基线、按等效 FP8 计时成立（第 18 课 §7）。
  • DeepSeekMoE 16B 的“40%”是 FLOPs 之比，不是参数之比（§3）。
  • “557.6 万美元”不含研究与消融（§4）；“1/4 激活参数”对不上任何一个口径（§8）。

三、证据有多硬：证明、实测，还是推测？

同一篇论文里，三种强度的说法常常并排出现，课文会逐一标明。

  • 证明：双随机矩阵的谱范数恰为 1，所以 mHC 的复合映射不会放大（第 16 课 §4）；KV cache 的精确性由因果掩码保证（第 4 课 §2）。
  • 实测：Engram 的 U 形曲线只在两个算力点上测过（第 17 课 §4）；RL 提升 Maj@K 而不提升 Pass@K，是 \(K\le64\) 下的实测，不是定理（第 8 课 §8）。
  • 推测或解释：“辅助损失伤性能是因为干扰梯度”（第 11 课 §3）；“光学遗忘”只是设想，没有做多轮实验（第 17 课 §7）；“aha moment”要和长度设置的改动一起读（第 13 课 §4）。

四、代价转移到了哪里？

主线上几乎没有免费的改进；省下的东西通常是换成了另一样东西，由另一个部件或另一个场景来付。

  • MoE 用显存和通信换计算（§3）；mHC 的参数与算术几乎为零，代价在访存（§6）。
  • CSA/HCA 用逐 token 的细节换缓存，1M 上下文“装得下”不等于“用得好”（第 18 课 §7）。
  • V4.1-Flash 用更大的模型、短上下文下更贵的解码和两处近似，换来输入重负载下的存储与搬运（第 19 课 §8）。
  • R1 用更长的思考换正确率，推理成本随输出长度线性甚至平方增长（第 13 课 §8）。

五、下一个瓶颈在哪里？

每解决一个瓶颈，账单就落到下一行。把整棵科技树连起来看，瓶颈大致是这样移动的：参数与计算绑在一起（MoE 拆开）→ 解码时读 KV 的字节（MLA）→ 长上下文的注意力计算（DSA）→ 百万 token 的缓存与计算（CSA/HCA）→ 智能体负载下缓存的存储与搬运（V4.1）。训练一侧则是：价值网络的显存（GRPO）→ 训练信号的来源（R1 的规则奖励）→ 规模化 RL 的稳定性（V3.2）。

有些设计在瓶颈移动之后被放弃了：V2 的 token 丢弃、V3 的节点受限路由、V4 的哈希路由与 HCA、预训练里的 MTP、稠密注意力热身，以及 R1 试过却没用上的过程奖励模型和蒙特卡洛树搜索。它们为什么被放弃，是第 20 课的主题。

练习与答案

先自己做，再展开答案。需要的数字都在本课前几页和规格总表里；计算题用计算器即可，每一步都可以用几行 Python 核对。这些题检验的正是封面“读完你能……”里的几条：认日期、问口径、分证据、用式 (0.1) 复算。

概念题

练习 1 · 同一个模型，该写哪一天

（a）InstructGPT 在时间线上应该标 2022 年 1 月还是 3 月？（b）V4 论文的编号是 2606.19348，为什么本课把 V4 的日期写成 2026-04-24？（c）DeepSeek-Coder 的 2023-11-02 是什么日期，为什么说它是代理值？（d）主线 F 的改进链里 DeepSeek LLM 写的是 2024-01-05（论文），时间线上却是 2023-11-29，两者矛盾吗？

看答案

（a）标 1 月。OpenAI 的公告页与论文 PDF 在 2022-01-27 发出，arXiv v1 晚到 2022-03-04；“3 月”只对 arXiv 成立。本课的规则是模型写第一次公开的日子，所以时间线用 01-27，并注明 arXiv 日期（§1）7。

（b）模型写公开发布日：权重与技术报告在 2026-04-24 已在 Hugging Face 公开，arXiv v1 的提交日是 04-26。编号前缀 2606 与提交月份对不上，原因没有从 arXiv 得到确认（“编号按公告月份分配”只是研究笔记的推测），所以引用时写发布日、再注编号最稳妥 2。

（c）它是 GitHub 仓库最早一次提交的日期。DeepSeek-Coder 没有官方公告页，能找到的一手证据只有这次提交和 HF 仓库的创建时间；创建时间只是发布日的下界（仓库常常先私有创建、后公开），所以本课用最早提交作代理，并明确标出 9,10。

（d）不矛盾。2023-11-29 是 7B / 67B 权重公开的日子，2024-01-05 是报告 arXiv v1 的日子；超参数规模化规律是报告里的贡献，所以主线 F 的表按论文日期记，时间线按模型发布日记。

练习 2 · 这个数在跟谁比

对下面四句话，各写出比较的对象、单位和成立的条件：（a）“V2 把 KV cache 降了 93.3%”；（b）“1M 上下文下 V4-Pro 只要 V3.2 的 27% FLOPs 和 10% KV”；（c）“DeepSeekMoE 16B 只用了 40% 的计算量”；（d）“V4.1-Flash 只用了 V4-Pro 1/4 的激活参数”。

看答案

（a）对象是 DeepSeek LLM 67B；单位是每 token 的 KV 字节；条件是部署态：V2 的 KV 平均量化到 6 bit，67B 按 BF16。\(1-25{,}920/389{,}120=93.3\%\)；两边同为 BF16 只有 \(1-69{,}120/389{,}120=82.2\%\)（§2）。

（b）对象是 V3.2，可 V3.2 官方只支持 128K，1M 处的 V3.2 是按架构外推的假想点；FLOPs 按“等效 FP8 FLOPs”计，而且只在 1M 这一点上比。按式 (0.4) 推算，KV 是 \(5{,}031/48{,}068=10.5\%\)，与论文的 10% 吻合（§2、第 18 课 §7）。

（c）对象是 DeepSeek LLM 7B；单位是每 4K token 的前向 FLOPs（74.4T 对 183.5T，40.5%），不是激活参数之比（§3）。

（d）对象是 V4-Pro 的 49B 激活参数。V4.1 的激活参数要分口径：解码 16B 是 \(16/49=0.33\)，预填充 8B 是 \(8/49=0.16\)，都不是 1/4；只有两者的平均 12B 才有 \(12/49=0.245\)。直接写 8B、16B、49B 最稳妥（§8）。

练习 3 · 证据有多硬

把下面六句话分成“已证明”“实测”“推算或推断”三类，并说明各自的适用范围：（a）两个双随机矩阵的乘积仍是双随机矩阵；（b）Engram 的最优分配在 75%–80%；（c）辅助损失伤性能，是因为它干扰了主目标的梯度；（d）V4 与 V4.1 的索引键每条 68 字节；（e）V4.1 取消了哈希路由；（f）在 DeepSeekMath 上，RL 提升 Maj@K 而不提升 Pass@K。

看答案

（a）已证明，对任意两个同阶的双随机矩阵都成立：若 \(A\mathbf 1=\mathbf 1\)、\(\mathbf 1^\top A=\mathbf 1^\top\)，\(B\) 也一样，则 \(AB\mathbf 1=A\mathbf 1=\mathbf 1\)，\(\mathbf 1^\top AB=\mathbf 1^\top B=\mathbf 1^\top\)，非负数相乘相加也仍非负（第 16 课 §4）。

（b）实测，而且范围很窄：只在两个算力点、固定稀疏度下扫过。论文说 75%–80%，从图上读出的最低观测点在 85% 左右；稳妥的说法是“70%–85% 一带，纯 MoE 明显更差”（第 17 课 §4）。

（c）推断（一种解释）。实测到的是“系数大了困惑度变差、系数小了负载不均”；“因为干扰梯度”是对这个现象的解释，没有被单独验证（第 11 课 §3）。

（d）推算。依据是论文说索引器用 OCP 标准的 MXFP4、代码注释说每 32 个数一个 E8M0 缩放：\(128\times4/8+128/32=64+4=68\)。它让 3,514 与 890 两个论文数字同时复现，是很强的旁证，但“68”本身没有印在论文或 FlashMLA 说明里（式 (0.4)）20。

（e）推断，证据是间接的：V4.1 论文图 3 的图注说全部前馈层都是标准 DeepSeekMoE，配置文件里也没有 V4 那样的哈希层字段；正文没有明说“取消”（§3）。

（f）实测：从 Instruct 模型做 RL，在 GSM8K 与 MATH 上、\(K\le64\) 的范围内观察到；它描述的是这篇论文里的现象，不是关于 RL 的定理（第 8 课 §8）。

计算题

练习 4 · 两个 16B 级 MoE 的缓存

DeepSeekMoE 16B（16.4B / 2.8B）用 MHA，28 层、16 头 × 128 维；V2-Lite（15.7B / 2.4B）用 MLA，27 层、\(d_c=512\)、\(d_h^R=64\)；都按 BF16 存。（a）用式 (0.2) 算两者每 token 的 KV 字节。（b）两者相差几倍？差在哪里？（c）和激活 21B 的 V2（69,120 字节）比，DeepSeekMoE 16B 大几倍？这说明了什么？

看答案

（a）DeepSeekMoE 16B：\(2\times16\times128\times28\times2=229{,}376\) 字节。V2-Lite：\((512+64)\times27\times2=31{,}104\) 字节。

（b）\(229{,}376/31{,}104=7.37\) 倍。两个模型的参数量几乎一样，差别几乎全在注意力：MHA 每层每 token 存 \(2\times16\times128=4{,}096\) 个数，MLA 只存 576 个（层数 28 对 27 只差 4%）。

（c）\(229{,}376/69{,}120=3.32\) 倍。每 token 的 KV 由注意力的结构、层数和每个数的字节决定，与总参数、激活参数都没有直接关系：激活参数只有 V2 的 \(2.8/21\approx13\%\) 的模型，缓存反而是它的 3.3 倍。误读表里 7B 与 67B 的例子是同一个道理（§8）。

练习 5 · 一个请求要多少显存

只算全局 KV（不算权重和 SWA 状态），\(1\text{M}=2^{20}\) token，\(128\text{K}=2^{17}\) token，1 GB 取 \(10^9\) 字节。（a）V4-Pro（每 token 约 5,031 字节）一个 1M 请求多少 GB？一张 80 GB 的卡放得下几个？（b）V3.2 一个 128K 请求呢？把它和（a）比较。（c）DeepSeek LLM 67B 的 KV 在上下文多长时就会填满 80 GB？

看答案

（a）\(5{,}031.44\times2^{20}=5.28\times10^{9}\) 字节，即 5.28 GB（4.91 GiB）；\(80/5.28\approx15.2\) 个。

（b）\(48{,}068\times2^{17}=6.30\times10^{9}\) 字节，即 6.30 GB（5.87 GiB），一张卡约放 12.7 个。V4-Pro 装一个 1M 请求（5.28 GB）比 V3.2 装一个 128K 请求（6.30 GB）还少：上下文长了 8 倍，缓存反而少了 16%。

（c）令 \(389{,}120\times T=80\times10^{9}\)，得 \(T\approx205{,}592\) token，约 200K。67B 实际只支持 4,096 token，一个满长请求只要 \(389{,}120\times4{,}096=1.59\times10^{9}\) 字节（1.59 GB）；§2 的“0.2 个 1M 请求”是把它外推到 1M 的假想。

练习 6 · 3.95 倍的两种拆法

V4-Flash 每 token 3,514.25 字节，V4.1-Flash 890 字节。V4.1 的 4 个 Full 层每 token 共摊到 2.5 条缓存，每条再加 68 字节的索引键。（a）如果条目仍用 V4 的 584 字节格式，全局 KV 是多少？把 3.95 倍拆成“结构 × 精度”。（b）如果改用 V4.1 自己的 FP8 格式（FlashMLA 说明里每条 528 字节），又是多少、怎么拆？（c）两种拆法为什么不同？哪一个“对”？

看答案

（a）\(2.5\times(584+68)=1{,}630\) 字节；结构 \(3{,}514.25/1{,}630=2.16\) 倍，精度 \(1{,}630/890=1.83\) 倍，乘积 3.95（第 19 课的拆法，第 19 课 §8）。

（b）\(2.5\times(528+68)=1{,}490\) 字节；结构 \(3{,}514.25/1{,}490=2.36\) 倍，精度 \(1{,}490/890=1.67\) 倍，乘积仍是 3.95（研究笔记的拆法）。

（c）两种拆法用了不同的“中间模型”：（a）的中间模型保留 V4 的条目（448 维 FP8 + 64 维 BF16 的 RoPE + 缩放），（b）的中间模型已经把 RoPE 维也换成 FP8、缩放改成每 32 个数一个 E8M0。先换哪一部分，哪一步就分到那部分的功劳，所以没有唯一“对”的拆法；只要写清中间模型是什么，两种都对。它们的共同结论是：结构（份数与压缩率）这一步比格式那一步省得多。

练习 7 · 缩小的速度

用规格总表里的发布日与每 token KV：DeepSeek LLM 67B（2023-11-29，389,120 字节）、V3（2024-12-26，70,272 字节）、V4.1-Flash（2026-09-10，890 字节）。（a）两段各隔多少天？（b）按“每年缩小几倍”\(r^{365/\Delta t}\)（\(r\) 是这一段缩小的倍数，\(\Delta t\) 是天数）算，两段各是多少？和全程的 8.9 倍 / 年比，说明了什么？

看答案

（a）67B → V3：393 天；V3 → V4.1-Flash：623 天；合计 1,016 天，与 §1 一致。

（b）67B → V3：\(r=389{,}120/70{,}272=5.54\)，\(5.54^{365/393}=4.9\) 倍 / 年。V3 → V4.1-Flash：\(r=70{,}272/890=79.0\)，\(79.0^{365/623}=12.9\) 倍 / 年。全程的 \(437.2^{365/1016}=8.9\) 倍 / 年落在两者之间：缩小在 V3 之后明显加快，主要来自 V3.2 → V4-Flash 的序列方向压缩（÷13.7）和 V4.1 的跨层共享与 FP4（÷3.95）。这只是按发布日做的年化，是笔者的口径，不是什么规律，不能拿来外推下一代。

练习 8 · 从四个因子到“2.25 组 GQA”

（a）从式 (0.1) 出发，写出 MHA、GQA、MQA、MLA 四种注意力的 \(n_{\text{copy}}\)、\(m\)、\(n_{\text{dim}}\)，推出式 (0.2)。（b）V2 取 \(d_c=4d_h\)、\(d_h^R=d_h/2\)。证明 MLA 的缓存等于只有 2.25 组的 GQA。（c）GQA 的组数只能是整数，MLA 却“相当于” 2.25 组，这说明两者的缓存在结构上有什么不同？

看答案

（a）四种注意力都是每层存一份、每个 token 一条：\(n_{\text{copy}}=l\)，\(m=1\)。每条的数：MHA 每个头存一个键、一个值，\(n_{\text{dim}}=2n_hd_h\)；GQA 每组共用一对，\(n_{\text{dim}}=2n_gd_h\)；MQA 是 \(n_g=1\)，\(n_{\text{dim}}=2d_h\)；MLA 存一个潜向量加一个所有头共用的 RoPE 键，\(n_{\text{dim}}=d_c+d_h^R\)。代入 \(B_{kv}=n_{\text{copy}}\cdot\frac1m\cdot n_{\text{dim}}\cdot b\)，就得到 (0.2) 的 \(2n_gd_hlb\) 与 \((d_c+d_h^R)lb\)。

（b）\(d_c+d_h^R=4d_h+\tfrac12d_h=\tfrac92d_h=2\times2.25\times d_h\)。与 GQA 的 \(2n_gd_h\) 对照，就是 \(n_g=2.25\)。代入 V2 的 \(d_h=128\)：\((512+64)/(2\times128)=2.25\) 1。

（c）GQA 的条目是若干对完整的键和值，每个查询头直接拿来用，所以只能按整组计数。MLA 的条目是一个 512 维的潜向量，128 个头的键和值都由它经上投影展开（推理时把上投影吸收进查询），它本身不是任何一个头的键或值；“2.25 组”只是等字节的换算，不代表 MLA 有 2.25 组头。这种共享的代价见 §2：每个缓存 token 约多 3.4 倍运算，RoPE 还得另存一栏。

练习 9 · UE8M0 为什么不溢出，平均用到多少

一组数的最大绝对值是 \(a\)，E4M3 能表示的最大值是 448，UE8M0 缩放取 \(s=2^{\lceil\log_2(a/448)\rceil}\)（式 (0.9)）。（a）证明缩放后组里每个数的绝对值都不超过 448。（b）证明组里最大的数缩放后落在 \((224,448]\)，也就是只用到 E4M3 范围的一半到全部。（c）设 \(\log_2(a/448)\) 的小数部分在 \([0,1)\) 上均匀分布，求利用率 \(u=a/(448s)\) 的期望。（d）\(a=1{,}000\) 时 \(s\) 与 \(u\) 各是多少？如果改成向下取整呢？

看答案

（a）记 \(y=\log_2(a/448)\)。因为 \(\lceil y\rceil\ge y\)，\(s=2^{\lceil y\rceil}\ge2^{y}=a/448\)，所以 \(a/s\le448\)；组里其余数的绝对值都不超过 \(a\)，缩放后也都不超过 448。

（b）又因为 \(\lceil y\rceil<y+1\)，\(s<2^{y+1}=2a/448\)，所以 \(a/s>224\)。于是 \(a/s\in(224,448]\)，利用率 \(u\in(\tfrac12,1]\)。

（c）令 \(v=\lceil y\rceil-y\)，则 \(u=2^{-v}\)，\(v\) 在 \([0,1)\) 上均匀分布。\(\E[u]=\int_0^12^{-v}\,dv=(1-2^{-1})/\ln2=1/(2\ln2)\approx0.721\)，这就是式 (0.9) 下面说的“约 72%”。

（d）\(a/448=2.232\)，\(\log_2 2.232=1.158\)，向上取整为 2，\(s=4\)；\(a/s=250\)，\(u=250/448=0.558\)。若向下取整，\(s=2\)，\(a/s=500>448\)，就溢出了。所以规则规定向上取整：\(2^{\lceil y\rceil}\) 是所有不溢出的 2 的幂里最小的一个，也就是精度最好的一档（第 15 课 §3）。
