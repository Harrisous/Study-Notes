Lesson 01The problem with sequences

You get to keep notes, or you get to re-read everything. Pick one.

A sequence model reads things one at a time, whether those things are words, audio samples or sensor readings, and after each one it has to produce an answer. The whole field is organised around a single awkward question: when you are at item number 900, what do you still know about item number 3?

There are exactly two honest answers, and for thirty years they have been the only two.

Answer 1: keep a summary (the RNN)

Carry a small notebook. After each item, cross out what is written and rewrite it. The notebook is always the same size, say 100 numbers, no matter how long the sequence gets.

Good: processing item 900 costs exactly what processing item 3 cost. Memory never grows.
Bad: everything you know about the past has to be squeezed into those 100 numbers. Item 3 has been overwritten 897 times. It is almost certainly gone.

Answer 2: keep everything (the Transformer)

Don't summarise. Keep a full transcript, and when you process item 900, look back at all 899 previous items and decide which ones matter. That "looking back and deciding" is attention.

Good: item 3 is still perfectly intact. Nothing is lost.
Bad: item 900 requires 899 comparisons. Item 9000 requires 8999. The work grows with position, and the transcript you have to store, called the KV cache, grows without limit.

The one-sentence version of this course

Mamba is an RNN whose notebook is large and whose update rule is fast on a GPU. The genuinely new idea is a third property: it decides, for each incoming item, how hard to write that item down. Everything else in these eleven lessons exists to make that third property work.

Check yourself: one question

easyWhy does a Transformer get slower with every token it generates, while an RNN does not?

Because a Transformer re-reads. To produce token 900 it compares against all 899 previous tokens, so the work at each step grows with how far in it already is. An RNN never re-reads. It only looks at its notebook, which is the same size at token 900 as at token 3. That is the whole difference, and every other trade-off in this course follows from it.

Lesson 02The state

A notebook with exactly one rule for updating it

Forget neural networks for a moment. Suppose you are tracking the temperature in a room and you want a running sense of how warm it has been lately. You get one reading per minute, and you are allowed to remember exactly one number.

Here is a rule that works. Call your remembered number h and the new reading x. At every minute:

The entire idea, in one line ht = a · ht−1 + b · xt New notebook = (a fraction a of the old notebook) + (a portion b of the new reading). That is it. That is a recurrent state.

Two knobs. a controls forgetting: if a = 0.9, you keep 90% of what you knew each minute. b controls listening, meaning how much of the new reading gets mixed in.

Let us actually run it. Take a = 0.9, b = 0.1, start at h0 = 0, and feed in a single spike of 10 followed by silence:

The spike gets written in, then decays geometrically. After k further steps, what remains of it is ak times what went in. This is the single most important behaviour in the whole course, so it is worth staring at: the past is not deleted, it is multiplied by a number smaller than one, over and over.

Lesson 03Continuous time

The same rule, written for a world without discrete steps

State space models do not start from ht = a ht−1 + b xt. They start one level further back, in continuous time, and then derive that rule. The detour looks like pointless mathematical formality. It is not. It is where Δ comes from, and Δ is the entire Mamba paper.

Picture a bucket with a hole in the bottom. Water pours in from a tap and leaks out through the hole. The water level is h. Then:

  • Water leaks out at a rate proportional to how full the bucket is. That is a term A h, with A negative, because the fuller it is, the faster it drains. This is forgetting.
  • Water pours in proportional to the tap setting x. That is a term B x. This is listening.
  • You read the level off a measuring stick, which might be calibrated in different units. That is y = C h. This is reporting.
Continuous-time state space model, paper Eq. (1) h′(t) = Ah(t) + Bx(t)      y(t) = Ch(t) h′ means "rate of change of h". Read it as: the level changes at a rate given by (leak) + (inflow), and what you report is a readout of the level. Three matrices, three jobs: A forgets, B listens, C reports.
A detail worth flagging now

The paper defines the SSM with four parameters (Δ, A, B, C) and no skip term. The released code does add a per-channel skip, yt = Cht + Dxt, initialised to 1. It is a small thing, but it means the SSM only has to learn the correction to passing the input straight through. Paper and code differ here, and there is a full errata box at the end.

Check yourself: one question

easyWhy must A be negative?

Because Ā = exp(ΔA) and Δ > 0. If A were positive, Ā > 1 and every step would amplify the state, so it explodes. Negative A puts Ā in (0, 1), which is decay. Mamba enforces this structurally by storing A = −exp(A_log), so no optimizer step can ever make it positive.

Lesson 04Discretization and Δ

The most important lesson in this course

Continuous time is nice mathematics, but your data is a list. You have word number 1, word number 2, word number 3, not a smooth function of t. So you have to convert the continuous rule into a step-by-step rule. That conversion needs one new quantity, and that quantity turns out to be the whole ballgame.

The new quantity: Δ

Δ ("delta") is how much continuous time passes between one item and the next. It is a step size. If you sample the bucket every second, Δ = 1. If you sample it every 0.01 seconds, Δ = 0.01 and almost nothing has changed between samples.

Given Δ, you can solve the differential equation exactly over one step. Assume the input holds constant across the step, an assumption called a zero-order hold or ZOH, and out comes:

ZOH discretization, paper Eq. (4) A = exp(ΔA)       B = (ΔA)−1(exp(ΔA) − I) · ΔB The bar means "discretized". Read A = exp(ΔA) as: the fraction of the state that survives one step. Since A is negative and Δ is positive, this is always between 0 and 1, which is exactly the a from Lesson 2.

And now the discrete rule falls out, and it is the rule you already know:

Discrete recurrence, paper Eq. (2) ht = Aht−1 + Bxt      yt = Cht Compare to Lesson 2: ht = a ht−1 + b xt. Identical. All the discretization did was tell you where a and b come from. They are not free knobs; they are determined by A, B and Δ. Note C gets no bar; only A and B are discretized.

Worked example: do this one by hand

Take the simplest possible case: one state, A = −1, B = 1, C = 1, and Δ = 0.5.

A = exp(0.5 × −1) = exp(−0.5) = 0.6065     B = 1−0.5(0.6065 − 1) × 0.5 = 0.3935

Notice that 0.6065 + 0.3935 = 1 exactly. For this scalar case the ZOH formula gives B = 1 − A, a perfect convex blend: keep 60.65% of the old state, mix in 39.35% of the new input. Remember this one, because it is Theorem 1 in disguise and it comes back in Lesson 8.

The intuition to carry for the rest of the course

Δ is a focus dial. Large Δ means "this input matters, so clear the notebook and write it down". Small Δ means "this input is noise, so hold what you have and let it pass". A model whose Δ is fixed applies the same focus to every item in the sequence. A model that can choose Δ per item can decide what to pay attention to. That choice is Mamba.

Useful rule of thumb, exact to two decimals: memory horizon ≈ 2.303 / (Δ·|A|) steps before a memory has faded to 10% of its original strength.

Check yourself: one question

easyA model uses Δ = 0.02 for every token, with A = −1. Is it better at remembering, or at reacting to what just happened?

Remembering, at the cost of reacting. Ā = exp(−0.02) = 0.980, so its memory horizon is 2.303/0.02 ≈ 115 steps. But B̄ = 0.020, meaning each new input enters with only 2% weight. It is a very long, very sluggish averager, and it will not notice anything happening now. This is precisely the trade a fixed Δ forces you into.

Lesson 05Going wide

One number is not a memory. Sixteen numbers at sixteen speeds is.

Everything so far used a single number for the state. That single number can only decay at one rate, so it is either a fast memory or a slow memory, never both. Real sequences need both at once. The fix is embarrassingly simple: run several of these in parallel at different speeds.

N: the state dimension

Instead of one h, keep a vector of N of them, each with its own A value. Mamba's default is N = 16. Because A is diagonal, a design choice inherited from S4D, these 16 states never talk to each other. They are 16 independent leaky buckets with 16 different hole sizes.

Concretely, with A = [−1, −0.1] and Δ = 1:

stateAĀt=0t=1t=2t=4t=9
fast−1.00.36790.63210.23250.08550.01160.0001
slow−0.10.90480.95160.86110.77910.63790.3869

Same spike, same Δ. Nine steps later the fast state has forgotten it completely (0.0001) and the slow state still holds 39% of it. Together they encode both "what just happened" and "what happened a while ago". Scale that to 16 and you have a small spectrum of timescales.

D: the channels

Meanwhile your input is not one number per timestep either. A token embedding is a vector of D numbers (Mamba-2.8B uses D = 2560, doubled to 5120 inside the block). Mamba runs a completely separate SSM on each channel. Channel 7 has its own 16 states and its own 16 decay rates, independent of channel 8.

So the parameter A has shape (D, N): one decay rate for every (channel, state) pair. That is the whole reason the state is bigger than a classical RNN's. It holds D × N numbers, not D.

Where HiPPO comes in, briefly

HiPPO ("High-order Polynomial Projection Operator") is the 2020 result that made this line of work possible. It asks: if you must compress an entire history into N numbers, what is the optimal way? The answer is a specific matrix that keeps a running projection of the history onto Legendre polynomials. For HiPPO-LegS its entries are Ank = −(2n+1)½(2k+1)½ above the diagonal and −(n+1) on it. That matrix is triangular, so its eigenvalues are just its diagonal: −1, −2, −3, …

S4D's insight was that you can throw away the off-diagonal part and keep only that diagonal, An = −(n+1), with almost no loss. That is what Mamba uses. So the practical takeaway is small and concrete: initialise your decay rates to −1, −2, −3, … rather than to random numbers, and the theory behind why is HiPPO.

Check yourself: one question

mediumAn SSM has N = 16 states initialised HiPPO-style at A = −1, −2, …, −16, with Δ = 0.1. Which state holds a memory longest, and for roughly how many steps?

The state with A = −1, since horizon ≈ 2.303/(Δ|A|). That gives 2.303/(0.1 × 1) ≈ 23 steps. The shortest is A = −16 at 2.303/(0.1 × 16) ≈ 1.4 steps. That 16× spread is the point of the HiPPO initialisation: you get a bank of memories covering many timescales at once rather than 16 copies of the same one.

Lesson 06S4 and the convolution trick

The same model, computed two completely different ways

There is a serious practical problem with everything built so far. ht depends on ht−1, which depends on ht−2. To train on a sequence of 4,000 tokens you must do 4,000 steps one after another. A GPU with 10,000 cores sits nearly idle. This is exactly why RNNs lost to Transformers.

S4's escape hatch: if A, B, C are the same at every timestep, a property called linear time-invariant or LTI, then unroll the recurrence and watch what happens.

Unrolling, starting from h₋₁ = 0 h0 = Bx0
h1 = ABx0 + Bx1
h2 = A2Bx0 + ABx1 + Bx2
…and so, multiplying by C:
yt = CBxt + CABxt−1 + CA2Bxt−2 + … Every output is a fixed weighted sum of past inputs. The weights never change. That is the definition of a convolution.
Convolutional form, paper Eq. (3) K = (CB, CAB, … , CAkB, …)       y = x ∗ K Recall the Lesson 4 table where two rows matched exactly. The state values were the kernel, so you had already computed K without knowing it.

Why this matters: a convolution over the whole sequence can be computed in parallel, all L positions at once, or via FFT in O(L log L). So S4 gets to have it both ways:

The convolution trick works if and only if A, B, C are the same at every timestep. The instant any of them depends on the input, the unrolled sums stop collapsing into one fixed kernel and the trick dies. Lesson 8 breaks exactly this condition on purpose, and Lesson 9 is the bill that comes due.

Check yourself: one question

mediumWhy does making Δ input-dependent destroy the convolution trick?

The convolution form comes from unrolling the recurrence and noticing that yt = Σk CĀkB̄xt−k uses the same coefficients CĀkB̄ at every t. That is only true if Ā and B̄ are constant. Once Δt varies, position 5 accumulates Ā5Ā4Ā3…, a different product from the one position 6 accumulates. There is no single kernel to convolve with, so no FFT.

Lesson 07Why S4 is not enough

A fixed kernel cannot notice what it is looking at

S4 is fast and it holds long memory. But it has a flaw so basic it is easy to miss: the kernel K is computed from the parameters alone. It does not depend on the input at all. S4 applies the identical weighting pattern to every sequence it will ever see.

Think about what that means. The model weights "5 steps ago" by some fixed amount. Always. Whether the token 5 steps ago was a critical password or the word "um", it gets the same weight, because the weight was decided at training time by position rather than by content.

The task that exposes it: Selective Copying

Show the model a sequence of mostly-noise tokens with a few coloured tokens hidden at random positions. Ask it to output the coloured tokens in order.

The second task: Induction Heads

If you have seen the bigram "Harry Potter" earlier, then the next time "Harry" appears you should predict "Potter". This requires reaching back an arbitrary, content-determined distance, which is the defining capability behind in-context learning.

The headline result here is the one worth memorising, because it is not a small improvement over a baseline; it is a different kind of behaviour. Two-layer models, 74K parameters for Mamba, trained on sequences of length 256:

The extrapolation result

Mamba solves induction heads perfectly at sequence length 220 = 1,048,576. The paper states it "generalizes perfectly to million-length sequences, or 4000× longer than it saw during training, while no other method goes beyond 2×." The attention baselines could not even be evaluated past 16,384 without running out of memory.

The diagnosis, in one line

S4's problem is not that its memory is too short. Its problem is that its memory is content-blind. It compresses on a fixed schedule instead of compressing based on what it just read. Fixing that means letting the input change the dynamics, which is Lesson 8.

Check yourself: one question

mediumPlain Copying is solved perfectly by S4, but Selective Copying is not. What single change to the task causes that, and why is it fatal to S4?

The change is random spacing between the tokens to be copied. In Plain Copying the gap is constant, so a fixed kernel with a spike at exactly the right lag solves it without ever looking at the content. In Selective Copying the gap is different on every example, and a fixed kernel is indexed by position, not by content, so no single kernel can be right for all of them. S4 scores 18.3%; the same architecture with an S6 layer scores 99.8%.

Lesson 08Selection

Mamba's one idea: let the input choose Δ, B and C

Everything so far has been setup. Here is the actual contribution, and it fits in a sentence: make Δ, B and C functions of the current input instead of fixed parameters. The layer that results is called S6, which is S4 plus Selection.

In S4, B is a learned matrix. Same matrix for every token, forever. In S6, B is computed from the token by a small linear layer. Feed in a different token, get a different B.

The selection functions, paper §3.2, verbatim sB(x) = LinearN(x)    sC(x) = LinearN(x)    sΔ(x) = BroadcastD(Linear1(x))    τΔ = softplus Three tiny linear layers. That is the entire mechanism. τΔ = softplus just forces Δ to be positive, since a negative timestep is meaningless. In the real implementation the Δ projection is low-rank, LinearD(LinearR(x)) with R = ⌈D/16⌉, and there is a learned bias inside the softplus.

Why B and C, and why not A

  • B selective: the model can decide whether this token gets written into memory at all.
  • C selective: the model can decide which parts of memory to read out right now.
  • Δ selective: the focus dial from Lesson 4, now under the model's control per token. This is the important one.
  • A stays fixed. The paper's reasoning: A only ever reaches the model through A = exp(ΔA), so making Δ selective already makes A selective. Selecting A too would be redundant. They "leave it out for simplicity".

The Broadcast_D on Δ is a deliberate design choice with a clean justification: if a token should be ignored, all D channels should ignore it. So the input is projected down to a single number and then copied out to all channels.

Theorem 1: the sanity check

Strip the model to its bones: N = 1, A = −1, B = 1. Then the selective SSM becomes something you may already recognise:

Check yourself: 4 questions

easyIn S4, what is the shape of B? In S6?

S4: (D, N), a learned parameter, the same for every position and every sequence. S6: (B, L, N), computed from the input, so it differs at every position of every sequence in the batch. The appearance of the L axis is literally what "time-varying" means, and it is what kills the convolution.

mediumIf selection is so useful, why doesn't Mamba make A input-dependent too?

Because it would be redundant. A only reaches the computation through Ā = exp(ΔA), and Δ is already input-dependent, so Ā is already input-dependent. The paper says selectivity in Δ "is enough to ensure selectivity in (Ā, B̄)", hypothesises that a selective A would perform similarly, and leaves it out for simplicity.

mediumΔ is projected down to one number and broadcast to all D channels, rather than computed per channel. What is the argument for that?

The paper's reasoning: Δ answers the question "should this token be paid attention to at all?", and that is a property of the token, not of any individual channel. If a token should be ignored, all D channels should ignore it. So the decision is made once and shared. Note this is a deliberate asymmetry: B and C lose the D axis (shared across channels), while Δ keeps it via broadcasting.

mediumGiven Theorem 1, what does an LSTM's forget gate correspond to in Mamba's vocabulary?

It corresponds to Ā = exp(ΔtA), the input-dependent decay. Theorem 1 shows that with N = 1, A = −1, B = 1 the recurrence becomes exactly ht = (1 − gt)ht−1 + gtxt with gt = σ(Linear(xt)). So forget gate = Ā, input gate = B̄, and the identity that makes it work is exp(−softplus(z)) = σ(−z). Mamba is a gated RNN that arrived at its gate by derivation rather than by design, then generalised the scalar state to 16 dimensions per channel and wrote a kernel fast enough to train it.

Lesson 09Making it fast

Selection costs you the convolution. Here is how Mamba pays.

Selection broke LTI, and LTI was the thing that made the convolution trick work. So Mamba is back to a sequential recurrence, which is the exact problem that killed RNNs. Two engineering ideas rescue it, and neither changes the mathematics at all.

Idea 1: the recurrence is a parallel scan

The recurrence looks hopelessly sequential, but it has a property that saves it. Write each step as a pair (A, b). Composing two steps gives:

(A2, b2) ∘ (A1, b1) = (A2A1,  A2b1 + b2) This operation is associative: (a∘b)∘c = a∘(b∘c). Anything associative can be computed by a prefix scan, the same trick that parallelises a cumulative sum.

A prefix scan does O(L) total work but only O(log L) sequential depth. For L = 4096 that is 12 dependent rounds instead of 4096. The GPU is busy again.

Idea 2: never write Ā and B̄ to main memory

This is the part people skip, and it is where the speed actually comes from. A modern GPU has two kinds of memory, and the gap between them is brutal:

Idea 3: recompute instead of remembering

Backpropagation normally requires storing every intermediate state from the forward pass. Here that is the enormous (B,L,D,N) tensor again. Mamba throws it away and recomputes it during the backward pass. That sounds wasteful, since it is extra arithmetic, but reading the tensor back from HBM costs more than recomputing it in SRAM. This is the same insight as FlashAttention, and it is why the paper can say Mamba has the same memory footprint as an optimised Transformer.

Why this lesson is not optional

Selective SSMs had been mathematically possible for years. What Mamba added was the kernel: a fused, IO-aware, recomputing parallel scan that made the idea trainable at scale. If you take one engineering lesson from this course, take this one. The algorithm and the memory hierarchy are not separable concerns.

Check yourself: one question

mediumMamba's kernel recomputes intermediate states in the backward pass rather than storing them. That is strictly more arithmetic. Why is it faster?

Because the bottleneck is memory bandwidth, not arithmetic. The intermediate states are a (B, L, D, N) tensor; storing and re-reading them means moving O(BLND) elements across the slow HBM bus. Recomputing them needs only the small inputs, already in fast SRAM. On modern GPUs, arithmetic is nearly free and memory movement is the cost, which is the same insight FlashAttention is built on.

Lesson 10The Mamba block

Assembling the whole thing

The S6 layer is the engine. The block is the car around it. Mamba's block design merges two things that architectures normally alternate, the H3-style SSM block and the gated MLP block, into one homogeneous unit you simply stack.

The whole course in five lines

1. A state is a fixed-size notebook updated by h ← ah + bx.
2. Derive a and b from a continuous system, and a step size Δ appears: Ā = exp(ΔA).
3. Δ is a focus dial: large means "record this", small means "ignore this".
4. Let the input set Δ (and B, C). That is selection, and it costs you the convolution trick.
5. Win it back with a fused parallel scan that never spills the big tensor to slow memory.

Check yourself: one question

mediumMamba's inference state is 13.1 MB whether the sequence is 10 tokens or a million. Name precisely what was given up to get that.

Exact lookup of an arbitrary past token. The Transformer's KV cache is a perfect record, so any past token can be retrieved exactly, because nothing was thrown away. Mamba's 13.1 MB is a summary, and a summary of a million tokens has necessarily discarded something. Selection makes the discarding intelligent, since the model chooses what to keep rather than losing things on a fixed schedule, but it does not make the loss zero. This is exactly why hybrid architectures, which interleave a few real attention layers among many Mamba layers, beat either pure design.

AppendixWhere the paper and the code disagree

Four things to know before you read the source

1. B̄ is not the ZOH formula in the released code

The paper's Eq. (4) gives B̄ = (ΔA)−1(exp(ΔA) − I)·ΔB. The shipped CUDA kernel and the PyTorch reference both compute B̄ = ΔB, a first-order Euler step, while keeping the exact ZOH for Ā. The author's explanation, given in a GitHub issue rather than the paper: it is simpler and does not affect empirical performance. Think of it as ZOH for A mixed with Euler for B. The two agree as ΔA → 0, and the difference is a per-channel rescaling that B's projection can partly absorb.

Consequence worth noting: Theorem 1's clean convex combination (1 − g)h + gx relies on the full ZOH B̄. Under the shipped kernel you get (1 − gt)ht−1 + softplus(·)xt instead. So "Mamba is a gated RNN" is a statement about the paper's mathematics, not exactly about the released implementation.

2. The D skip term is in the code, not in the paper's equations

The paper defines the SSM with four parameters and no feedthrough. The code has self.D = nn.Parameter(torch.ones(d_inner)) and computes yt = Cht + Dxt, excluded from weight decay and kept in fp32.

3. The "optional normalization layer" is absent from Mamba-1

§3.4 mentions an optional LayerNorm inside the block, motivated by RetNet. There is no such layer anywhere in mamba_simple.py. Mamba-2 does add a gated RMSNorm before out_proj. If you see a block diagram with an internal norm, it is Mamba-2.

4. Small numeric slips

dt_rank = ceil(d_model/16) is a code default the paper never states (it only says "a small fraction of D"), though an appendix ablation is consistent with it. The paper writes S4D-Lin as An = −½ + ni, dropping the π from the S4D paper's −½ + iπn. And the fused-kernel IO is quoted as O(BLD + DN) in the forward and O(BLN + DN) in the backward, a D/N swap that looks like a typo in one of the two.

ReviewSix synthesis questions

These span several lessons at once

The per-lesson questions checked one idea at a time. These deliberately do not. Each one needs pieces from two or three different lessons, which is the only real test of whether the course stuck. Answer out loud first.

mediumWalk the whole chain. A model with A = −1 sets Δ = 2 on a token. State what happens to Ā, to B̄, and to the state, then say in plain English what the model just decided.

Ā = exp(2 × −1) = 0.135, so 86.5% of the existing state is erased in one step. B̄ = 1 − 0.135 = 0.865, so the incoming token is written in at almost full strength. The state is therefore replaced rather than updated.

In plain English: "this token matters, so clear the notebook and write it down." The memory horizon collapses to 2.303/2 ≈ 1.2 steps, which is the price: right after doing this, the model has forgotten nearly everything that came before.

mediumSomeone says "Mamba is just an RNN with a bigger hidden state." What is right about that, and what is wrong?

Right: it is a recurrent model with a fixed-size state, it processes tokens sequentially at inference, and Theorem 1 shows the update rule reduces to an ordinary gated RNN in the scalar case. The state genuinely is bigger: D × N rather than D.

Wrong, in two ways. First, size is not the contribution; selection is. A classical RNN's gate is a design choice bolted on to fix vanishing gradients, while Mamba's gate falls out of discretising a continuous system, which is what gives Δ its interpretation as a timescale rather than an arbitrary number. Second, an RNN with a state this large would be untrainable: the whole reason Mamba works at scale is the fused parallel scan, which is an engineering result, not an architectural one. A bigger state with a gate had been possible for years. The kernel is what made it real.

mediumYou need to run a model over 500,000-token documents on a fixed GPU budget. Give the argument for Mamba, then give the honest argument against it.

For: at 500K tokens a 2.8B-class Transformer is carrying roughly 328 GB of KV cache, which does not fit on any single accelerator you can buy. Mamba carries 13.1 MB, the same as it carries at 500 tokens. Training is linear rather than quadratic in length, and per-token generation is constant-time. On a fixed budget this is not an optimisation, it is the difference between possible and impossible.

Against: if the task is "find the one clause on page 340 and quote it exactly", you are asking for precise retrieval from a compressed summary, and that is the operation Mamba is structurally worst at. A Transformer keeps that clause verbatim. The right question is not "which architecture is better" but "does my task need exact recall or good summarisation?", and if it needs both, that is the argument for a hybrid rather than for either pure model.

mediumRank these four changes from "breaks the model entirely" to "barely matters": (a) making A positive, (b) deleting the depthwise convolution, (c) using Euler instead of ZOH for B̄, (d) freezing Δ to a constant.

(a) → (d) → (b) → (c).

(a) catastrophic. Ā = exp(ΔA) > 1, so every step amplifies the state and it diverges. This is not a degradation but a numerical failure, and it is why the code stores A = −exp(A_log).

(d) severe but survivable. You have reverted S6 to S4. The model still trains and still works; it has simply lost content-awareness. Concretely, 99.8% → 18.3% on Selective Copying.

(b) a real but bounded loss. The conv supplies short-range temporal detail that an exponentially decaying state handles poorly. Measurable degradation, not collapse.

(c) no measurable effect. This is what the released code actually does, and the author's stated reason is that it is simpler with no empirical cost.

mediumThe SSM already mixes information over time. So why does the Mamba block also need a depthwise convolution in front of it?

Two reasons, and it is worth being precise here, since the convolution is depthwise and so does not mix channels either (that job belongs to in_proj and out_proj).

First, the diagonal SSM's memory is a sum of decaying exponentials. That shape is good at "roughly how much of this have I seen recently" and bad at "exactly two tokens ago". A width-4 causal convolution gives sharp, exact, short-range structure that the decay profile cannot represent at all.

Second, it is cheap: ED(d_conv + 1) parameters against 3ED² for the projections, a rounding error in the parameter budget for a capability the SSM genuinely lacks.

easyOne sentence each: what do A, B, C and Δ do?

A forgets: it sets how fast each state decays.
B listens: it sets how much of the new input enters the state.
C reports: it selects which part of the state becomes the output.
Δ focuses: it scales A and B together, trading memory against listening, and it is the one the input gets to choose.

If you can say those four from memory, you can reconstruct the rest of the course.
